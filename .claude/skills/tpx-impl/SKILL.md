# /tpx-impl

체인 [5]. 할 일을 하위 작업자에게 나눠 준다. **TDD 강제 (RED → GREEN → REFACTOR).**

0·1등급은 여기 들어오지 않는다 — `/tpx` 가 직접 고치고 규율만 같게 따른다.

## 선행 읽기 — 컨트롤러가 1회 읽고 하위에는 위치를 넘긴다

**하위 작업자에게 본문을 붙이지 않는다.** 아래는 `파일:줄` 과 **절 제목**으로 넘긴다.
앞 묶음이 문서를 고치면 줄이 밀리므로, 받는 쪽은 절 제목을 `grep -nF '<절 제목>'` 로 찾아(고정 문자열 — 제목의 `[` · `*` · `(` 가 정규식으로 읽히지 않게) 위치를 다시 잡고 그 줄 범위만 연다. 장 · 파일 전체를 다시 읽지 않는다.

- `/tpx-spec` 이 읽은 SPEC 절 — 장 · 절 제목 · 줄 범위
- LEARNINGS 발췌 — 이번 작업 키워드 + 최근 5건의 헤딩
- 계획 파일의 해당 할 일 — 계획 파일 경로 + 할 일 번호

**환경 값은 위치로 바꾸지 않고 프롬프트에 그대로 싣는다** — 검사용 `DATABASE_URL` · 작업방 절대경로.
이 값은 문서 어디에도 없어서, 프롬프트에 안 실으면 작업자가 기본 DB 에서 돈다(LEARNINGS 2026-09-26).
코드 규칙(루트 `CLAUDE.md`)은 싣지 않는다 — 보조 에이전트가 자동으로 받는다.

## Step 1. 묶음을 계산한다

계획의 메타 세 칸을 읽는다.

- **간선 둘** — 명시 `depends-on`, 그리고 **`files` 교집합이 있으면 자동 직렬화**(번호 작은 쪽 → 큰 쪽)
- **묶음** — 진입 차수 0 인 할 일이 묶음 1, 그것을 뺀 뒤 다시 0 인 것이 묶음 2 …
- **`검증` 칸을 함께 읽는다.** 그 명령을 ① 하위 작업자 프롬프트에 싣고 ② Step 4 범위에 넘긴다
- 메타 누락 · 파싱 실패 · 순환 → **BLOCKED**, `/tpx-plan` 으로 되돌린다

**`검증` 칸이 비었으면 BLOCKED.** 조용히 전량으로 대체하지 않는다.

## Step 2. 묶음마다 세 박자

### 2-A. 구현자 병렬 발행

- 묶음의 모든 할 일을 **한 응답 안에 여러 `Agent()` 호출**로 동시에 낸다.
  응답이 갈리면 직렬화돼 병렬 이점이 사라진다
- **구현자는 `subagent_type: "tpx-implementer"`**(Sonnet · effort high — `.claude/agents/tpx-implementer.md`, 2026-10-06 사용자 · 토큰이 빨리 닳는다).
  **보안 · 비밀값 · 권한을 고치는 할 일만 `subagent_type: "general-purpose"` 에 `model: "opus"`** 로 낸다 — 그 자리에서 아끼면 품질이 떨어진다(PR #163 의 비밀번호 노출을 Opus 렌즈가 찾았다).
  ponytail 규칙은 `tpx-implementer` · `author-write` 에만 자동으로 붙으므로(`.claude/settings.json` `env`) 이 프롬프트는 첫 줄에서 `ponytail:ponytail` 스킬을 부르라고 적는다
- **정의를 못 찾으면**(「없는 에이전트」 오류 — 정의는 세션을 띄울 때 읽혀서, 그 뒤 병합되거나 받아 온 정의는 그 세션이 못 본다)
  `subagent_type: "general-purpose"` 에 `model: "sonnet"` 으로 대신 내고 게이트 2 요약에 적는다. effort 는 정하지 못한다 — 새 세션부터는 정의가 잡힌다.
  이 프롬프트도 첫 줄에서 `ponytail:ponytail` 스킬을 부르라고 적는다 — 규칙이 `tpx-implementer` · `author-write` 에만 자동으로 붙는다(`.claude/settings.json` `env`)
- 프롬프트에는 **계획 파일 경로 + 할 일 번호**를 넘겨 구현자가 원문을 읽게 한다 — 컨트롤러가 풀어 쓰지 않는다(LEARNINGS 2026-10-08)
- 프롬프트에 반드시 넣을 것 — 계획 파일 경로 + 할 일 번호(작업방 기준 **절대경로**로) · `files` 목록 · `검증` 명령 ·
  환경 값(DB 를 건드리면 검사용 `DATABASE_URL` · 작업방 절대경로) ·
  **「선언된 `files` 밖을 고치면 BLOCKED 로 보고하라」**

### 2-B. 응답 처리

| 응답 | 다음 |
|---|---|
| `DONE` | 2-C 검증 대상 |
| `DONE_WITH_CONCERNS` | 우려를 검증자 프롬프트에 실어 대상 포함 |
| `NEEDS_CONTEXT` | 빠진 것을 보강해 그 할 일만 다시 발행 |
| `BLOCKED` | 아래 복구 규율로 다시 발행 |

**BLOCKED 복구 규율** — 다시 던지는 프롬프트에 **시도한 것 · 관찰한 것 · 가설 둘 · 필요한 정보**
네 항목을 반드시 채운다. 이것 없이 다시 던지면 같은 실패가 반복된다.

**같은 실패 3회면 멈추고** CLAUDE.md §6 형식으로 보고한다.

### 2-C. 계획 대조 검증

`subagent_type: "tpx-verifier"` 로 발행한다(Sonnet · effort medium). **읽기 전용 — 정의의 `tools` 가 읽기 셋뿐이라 Bash · 고치기를 못 한다.**
차이가 길면 **작업방 밖**에 파일로 떨궈 그 경로를 넘긴다 — 배경 세션이면 `$CLAUDE_JOB_DIR/tmp/tpx-<할 일>.diff`, 아니면 `/tmp/tpx-<할 일>.diff`.
작업방 안에 두면 추적 안 된 파일이 커밋 · 차선 판정에 섞인다. 검증자는 Read 로 읽는다(2026-10-06 PR #163 에서 배경 세션 자리로 읽힌 것을 확인)
정의를 못 찾으면 위 2-A 처럼 `general-purpose` 에 `model: "sonnet"` 으로 내되 프롬프트에 「Bash · 고치기 금지」를 적는다

- **컨트롤러가 할 일별 `git log` 와 `git diff` 를 먼저 직접 모아 프롬프트에 붙인다.**
  검증자가 추측으로 거짓 PASS 를 내는 경로를 막는다
- **판정 기준은 계획 파일 경로 + 할 일 번호로 넘긴다.** 검증자가 원문 블록을 읽고 대조한다 — 컨트롤러가 요약해 옮기면 요약이 기준이 된다(LEARNINGS 2026-10-08)
- PASS 응답에 **실제 커밋 해시가 인용돼 있지 않으면 거절**하고 다시 발행한다
- `PASS` → 졸업 / `DRIFT` → 항목을 전달해 재발행 / `TDD_VIOLATION` → 복구 규율

묶음의 모든 할 일이 PASS 면 다음 묶음으로.

## Step 3. 화면을 건드렸으면 눈으로 본다

`apps/admin/src/web/**` 가 `files` 에 있으면 브라우저로 직접 확인한다 — **밝게·어둡게 양쪽.**
`docs/DESIGN.md` 가 기준이다. 결과를 PR 코멘트에 적는다.

**넘침 0 은 통과가 아니다** (2026-10-08 승격 — PR #165 · #175 두 번). 칸이 그릇 안에서 쪼그라들면 문서 폭은 그대로라 넘침이 0 으로 나온다.
실측 스크립트가 아래 넷을 같이 재고, 폭마다 사진을 한 장씩 눈으로 연다.

| 무엇 | 어떻게 재나 |
|---|---|
| 글 칸이 꺾이지 않는가 | 글이 든 칸마다 「높이 > 줄 높이 × 2 이고 폭 < 글자 넷」이면 한 글자씩 세로로 쌓인 것이다 — 배지 · 숫자 칸 · 라벨을 특히 |
| 주요 칸 최소 폭 | 이름 · 문장 칸이 정한 최소(예 120px) 아래인가 |
| 버튼이 제 그릇 안인가 | 버튼 · 링크의 상자가 카드 · 줄 상자 밖으로 나갔나 |
| 제목 · 버튼 줄이 한 줄인가 | 머리 제목 높이 / 줄 높이 |

**폭은 1440 · 1280 · 1180 · 1024 · 900 · 768 · 390 과 상자 폭(창 1440 · 1024)** — 그릇 질의(`@container`)는 창 폭이 아니라 그릇 폭으로 갈려서,
사이드바를 편 1024~1180 창이 따로 깨진다(PR #175 요약 띠 — 1024 를 찍고도 넘침만 재서 놓쳤다).

화면을 안 건드리면 건너뛴다.

## Step 4. 푸시 전 최종 점검

**종료 코드로 판정한다. 통과 건수로 하지 않는다.**

```bash
npm run check:deps      > /tmp/c.log 2>&1; echo "EXIT=$?"
npm run typecheck       > /tmp/c.log 2>&1; echo "EXIT=$?"
npm run check:workflow  > /tmp/c.log 2>&1; echo "EXIT=$?"
npm run check:spec      > /tmp/c.log 2>&1; echo "EXIT=$?"
npm run check:tests     > /tmp/c.log 2>&1; echo "EXIT=$?"
```

단위 테스트는 **바뀐 것과 이어진 것 + 늘 도는 목록을 1회** 돈다 (2026-09-25 — 서비스 전이라 전체 3회를 걷었다).
DB 를 건드렸으면 `DATABASE_URL` 을 붙인다. 없으면 DB 검사가 조용히 건너뛴다.

```bash
npm run test:changed -- origin/main > /tmp/c.log 2>&1; echo "EXIT=$?"
npm run test:always                 > /tmp/c.log 2>&1; echo "EXIT=$?"
```

migration·`package.json`·설정을 바꿨으면 `vitest run` 전체다 — 작업방 경로의 `.claude/` 때문에
vitest 의 전체 재실행 트리거가 여기서는 안 걸린다 (`vitest.config.ts` 주석).

**파이프로 넘기지 않는다.** `cmd 2>&1 | tail` 은 셸이 보고하는 종료 코드를 `tail` 의 것으로 바꾼다.
파일로 받고 `$?` 를 읽는다.

**「Tests N passed」와 「EXIT=1」은 같은 실행에서 동시에 참일 수 있다.**

## 구현 중 게이트 결정 · RED 와 달라지면 (2026-10-05 — #157 · #158 두 번)

- **그 자리에서 계획 파일 `## 구현 중 바뀐 것` 절에 한 줄씩 적는다** — 무엇이 · 왜 · 명세 문장이 걸리는지. 임시 메모에 두지 않는다. 게이트 2 요약은 이 절을 그대로 싣는다
- **명세 문장은 고치지 않고 그 절에 「명세 승인 필요」로 적는다** — 게이트 2 에서 받은 뒤에 고친다. 승인 없이 바꾼 명세 문장이 두 번 `spec-review` 중대로 걸렸다
- **화면 모양을 약속하는 명세 문장(한 줄 · px)은 브라우저로 잰 뒤에 쓴다** — #158 「도구 줄 한 줄 유지」는 재기 전에 적었다가 넓은 창에서도 두 줄이었다

## PR 갱신

묶음마다 코멘트를 단다. 여기가 가장 오래 걸려서, 한 시간 넘게 소식이 없으면
멈춘 건지 도는 건지 알 수 없다.

```bash
node .claude/scripts/pr-update.mjs --pr <번호> --tier <등급> --step 5 --note "<n>/<전체>" --next "게이트 2"
node .claude/scripts/pr-update.mjs --pr <번호> --comment "### [5/7] 묶음 <n> 완료 (<n>/<전체>)
...
**다음.** <무엇>"
```

## 출력

```
🔄 [5/7] tpx-impl (할 일 N개, 묶음 N개)
   ├─ 묶음 1  할 일1 ✅ · 할 일2 ⚠️ DRIFT 1회 → 재발행 ✅
   ├─ 묶음 2  할 일3~5 전부 ✅
   └─ 최종 점검 ✅ (테스트 N개, 종료코드 0, 타입검사 깨끗)
```

## 실패 / 엣지

- **같은 실패 3회** — 멈추고 보고. 등급 재판정 제안을 붙인다
- **추측성 대규모 수정 금지** — 원인을 못 짚었으면 범위를 넓히지 말고 BLOCKED 로 보고
- **검사가 빨간데 내 변경 같지 않다** — `git diff origin/main...HEAD` 로 실제 바뀐 것부터 본다.
  환경 문제면 **고치지 말고** 게이트 2 요약에 싣는다
- **도메인 모델이 틀렸다는 결론** — `/tpx-spec` 으로 되돌린다 (드물다)
