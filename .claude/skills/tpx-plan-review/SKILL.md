# /tpx-plan-review

체인 [4]. 계획을 **검토만** 한다. 고치지 않는다. 0·1등급은 진입하지 않는다.

## 선행 읽기

**없음.** `/tpx` 가 이미 실었다. **재로드 금지.**

## 하지 않는 것

- **계획을 고치지 않는다.** 지적만 한다 — 고치는 것은 게이트 1 뒤의 일이다
- **사용자에게 묻지 않는다.** 판단이 갈리는 것도 지적으로 적는다. 결정은 게이트 1 이 받는다
- **두 번 돌지 않는다.** 아래 §루프 금지

## Step 1. 등급으로 렌즈를 고른다

| 등급 | 렌즈 |
|---|---|
| **2** | `gstack:/plan-eng-review` (+ 화면을 건드리면 `gstack:/plan-design-review`) |
| **3** | 위 + `gstack:/plan-ceo-review` |

두 렌즈가 걸리면 **한 응답에 함께 발행한다.** 순차로 나누면 왕복만 2배가 된다.

## Step 2. 호출 — 이 세 마디를 반드시 넣는다

gstack 렌즈는 **자체 스코프 게이트 · 대화형 질문 · 자체 telemetry** 를 들고 온다.
그대로 부르면 이 체인의 게이트와 겹쳐 사용자가 같은 것을 두 번 답하게 된다.

**2026-09-18 실측** — 아래 세 마디를 넣으면 한 번에 끝난다. 빼면 대화형으로 빠진다.

```
Skill({
  skill: "plan-eng-review",
  args: "<계획 파일 경로> — <한 줄 요약>. 작업 디렉터리는 <작업방 절대경로> 다. " +
        "비대화형으로 한 번만 검토하고 지적만 내라 — 계획을 고치지 말고, 질문하지 말고, " +
        "재검토 루프를 돌리지 마라. 판정은 통과 / 주의 N건 / BLOCKER N건 중 하나로 끝내라."
})
```

세 마디의 몫.

| 마디 | 막는 것 |
|---|---|
| `비대화형으로 한 번만` | 렌즈가 자체 `AskUserQuestion` 을 띄우는 것 |
| `계획을 고치지 말고` | 검토자가 계획을 다시 쓰는 것 |
| `재검토 루프를 돌리지 마라` | `계획 → 검토 → 계획` 왕복 |

**작업 디렉터리를 절대경로로 준다.** 안 주면 렌즈가 공유 체크아웃을 본다.

## Step 3. 결과를 계획 파일에 적는다

`## 리뷰 결과` 절에 **append** 한다. 덮어쓰지 않는다.

```markdown
## 리뷰 결과

**렌즈**: <이름> (<등급>등급 = N종) · <날짜>
**판정**: BLOCKER N건 · 주의 N건

### BLOCKER 1 — <한 줄>
<무엇이 · 왜 문제 · 고칠 것>

### 주의 1 — <한 줄>

### 통과한 것
- <항목>
```

**`왜 문제` 는 나중에 무엇이 잘못되는지를 적는다.** 코드 설명이 아니다.

## 루프 금지 (이 스킬의 존재 이유 절반)

**한 번만 돈다.** BLOCKER 가 나와도 계획을 고쳐 다시 부르지 않는다.

```
계획 → 검토 ─┐
             ▼
   🛑 게이트 1 (계획 + 지적을 나란히)
             │
   ┌─────────┼─────────┐
지적 반영   그대로     중단
하고 진행    승인
← 재검토 안 함
```

**2026-09-18 실측 근거.** 옛 오케스트레이터는 `계획 → 검토 → 계획 → 계획 → 계획 → 검토 → 계획`
일곱 턴을 돌고 **구현에 도달하지 못했다.** contracts 단위가 $12.22 를 계획에만 썼다.
상한이 없는 것이 원인이었다.

판별식 `plan-review-loop-guard` 가 이 본문에 `tpx-plan` 을 다시 부르는 문장이 생기면 빨간불을 낸다.

## PR 갱신

```bash
node .claude/scripts/pr-update.mjs --pr <번호> --tier <등급> --step 4 --next "게이트 1"
node .claude/scripts/pr-update.mjs --pr <번호> --comment "### [4/7] 계획 검토 — <판정>

<지적을 쉬운 말로. 약어는 괄호로 푼다>

**계획을 고치지 않았습니다.** 검토자는 지적만 합니다.

**다음.** 🛑 게이트 1"
```

## 출력

```
🔄 [4/7] tpx-plan-review
   ├─ 렌즈: <이름> N종 (<등급>등급)
   ├─ 판정: BLOCKER N · 주의 N
   └─ 다음. 🛑 게이트 1
```

## 실패 / 엣지

- **렌즈 호출이 실패한다** — 조용히 0종으로 줄이지 않는다. 부재를 게이트 1 요약에 적고
  진행 여부를 사용자가 정하게 한다
- **렌즈가 그래도 질문을 띄운다** — 그 질문을 게이트 1 요약에 지적으로 옮겨 싣고,
  렌즈에는 답하지 않는다. 사용자는 한 번만 답한다
- **BLOCKER 가 계획 자체를 부정한다** — 게이트 1 선택지에 `중단` 이 있다. 거기서 받는다
- **두 렌즈 결과가 충돌한다** — BLOCKER 가 항상 우선. 충돌 사실을 요약에 그대로 적는다
