# /tpx

이 저장소 코드 작업의 **단일 진입점**. 등급을 판정하고 일곱 단계를 컨트롤한다.

**하위 일곱은 이 컨트롤러만 호출한다.** 각 단계 응답을 받은 뒤 명시적으로 다음 `Skill()` 을 부른다 — 「자동으로 호출된 셈」 가정 금지.

## 체인 일곱 단계

```
[1] tpx-start        분류 · 작업방 · 초안 PR
[2] tpx-spec         읽을 장 선택 · 계약 변경 판정            (2등급+)
🛑 게이트 0 — 계약 변경 승인                                  (계약을 건드릴 때만)
[3] tpx-plan         할 일 쪼개기 · §2.7 동반 수정을 할 일로   (2등급+)
[4] tpx-plan-review  계획 검토 — 한 번만                      (2등급+)
🛑 게이트 1 — 계획과 지적을 나란히                            (2등급+)
[5] tpx-impl         구현 (TDD). 0·1등급은 여기서 인라인
[6] tpx-review       검사 2종 병렬 · 게이트 2 요약
🛑 게이트 2 — 전 등급 필수
[7] tpx-merge        초안 해제 → 병합 → 정리 → 기록
```

## A-0. 중단된 작업 감지 (모든 입력에 선행, 필수)

파일을 하나라도 만들거나 고치기 전에 먼저 본다.

```bash
git worktree list
gh pr list --draft --author @me --json number,title,headRefName
```

둘 중 하나라도 비어 있지 않으면 **사용자 확인 없이 진행하지 않는다.** `AskUserQuestion` 으로
① 이어가기 ② 새 작업 추가 ③ 이전 폐기.

**「이어가기」의 재개 지점은 추정하지 않는다.** `gh pr view <번호> --comments` 의 마지막 코멘트가
재개 지점이다. 코멘트가 없으면 `AskUserQuestion` 으로 묻는다.

## A-1. 순서 강제 — 이 표를 어기지 않는다

**2026-09-18 실측.** 같은 세션 안에서 계획을 먼저 쓰고 PR 을 나중에 열었다.
한 세션 안에서도 드리프트가 난다. 기억에 맡기지 않는다.

| 순서 | 무엇 | 이걸 안 하고 다음으로 가지 않는다 |
|---|---|---|
| 1 | 등급 판정 (`detect-tier.mjs`) | 등급 없이는 어느 단계를 도는지 모른다 |
| 2 | 작업방 생성 | 공유 체크아웃에서 고치지 않는다 |
| 3 | **초안 PR 개설** | **파일을 하나라도 고치기 전에 연다** |
| 4 | 그 뒤에 단계 진입 | |

**3번을 건너뛰면 그 자리에서 멈추고 PR 부터 만든다.** 계획 파일도 PR 이 생긴 뒤에 쓴다.

## 등급 판정

```bash
node .claude/scripts/detect-tier.mjs <바꿀 경로들>
```

**선언과 실측을 둘 다 잰다.**

| 언제 | 무엇을 재나 | 어디에 적나 |
|---|---|---|
| **[1] 착수 시점** | 이번에 건드릴 경로 → **선언 등급** | PR 본문 · `tpx-start` 가 잰다 |
| **게이트 0 직후** | SPEC 변경이 확정된다 → **선언 등급을 다시 잰다** | PR 본문을 갱신한다 |
| **[6] 검사 시점** | `git diff --name-only origin/main...HEAD` → **실측 등급** | 게이트 2 요약 |

**둘을 나란히 적는다.** 실측이 선언보다 높아도 **자동 승격하지 않는다** — 게이트 2 에서 사람이 정한다.
미분류(`미분류: <경로>`)가 나오면 조용히 넘기지 않고 게이트 2 요약에 그대로 싣는다.

**★게이트 0 이 통과하면 그 자리에서 다시 잰다.** 착수 시점에는 SPEC 을 고칠지 모르는 것이 보통이고,
**게이트 0 이 바로 그것을 확정하는 자리**다. 여기서 안 올리면 3등급 렌즈를 빠뜨린 채 게이트 2 까지 간다.

```bash
node .claude/scripts/detect-tier.mjs docs/spec/<고칠 파일> <그 밖에 건드릴 경로들>
```

**이건 「자동 승격」이 아니다.** 승격의 근거인 SPEC 변경을 사람이 방금 게이트 0 에서 승인했다 —
다시 물을 것이 없다. 자동 승격을 금지한 윗줄은 **아무도 승인한 적 없는 실측**을 두고 한 말이다.

2026-09-19 실측 — WS-E ② 가 선언 2 로 출발해 게이트 0 에서 `docs/spec/**` 가 확정됐는데
다시 재지 않았다. 실측 3 을 [6] 이 잡을 때까지 `/security-review` 가 안 돌았다.

표면→등급 정본은 `.claude/scripts/surfaces.mjs` 다. **이 문서에 사본을 두지 않는다.**

## 등급별 절차 (이 표가 정본)

| | **0등급** | **1등급** | **2등급** | **3등급** |
|---|---|---|---|---|
| 표면 | `DOC` | `WEB` `TESTS` `HARNESS` | `ADMIN` `RUNNER` `AUTH` `GUARD` | `MIGRATION` `KIT` `SPEC` `COMPOSE` |
| 계획 파일 | 없음 | 없음 | 1장 | 1장 + §1.2 절차 |
| 도는 단계 | 1 · **5 인라인** · 6 · 7 | 〃 | 1~7 전량 | 1~7 전량 + 게이트 0 |
| 계획 검토 | — | — | `/plan-eng-review` | 위 + `/plan-ceo-review` |
| 코드 검사 | `/code-review` | 위 + 화면이면 `/qa-only` | 위 + `spec-review` | 위 + `/security-review` |
| 게이트 | 2만 | 2만 | 1+2 | **0+1+2** |

- **0·1등급의 「5 인라인」** — `tpx-impl` 을 부르지 않고 이 컨트롤러가 직접 고친다. 규율은 같다
- **[5] 가 기획서에서 케이스를 만드는 일이면 인라인 대신 `tpx-cases` 를 부른다** —
  입력이 기획서 파일이고 산출물이 `tests/**` 인 경우다. 초안 PR·게이트 2 규율은 그대로다
- **`tpx-review` 는 전 등급 호출**한다. 자기 구현을 자기가 검사하면 독립이 아니다
- **`tpx-start` 와 `tpx-merge` 도 전 등급 호출**한다. 두 스킬에 사고 방어 절차가 걸려 있다

## 게이트

**★세 게이트 모두 `AskUserQuestion` 으로 낸다. 산문 3지선다 금지.**

본문에 「1. 승인 2. 수정 3. 보류」를 적고 숫자를 타이핑하게 하지 않는다.
**요약을 다 쓴 것이 질문을 낸 것이 아니다.** 요약은 질문의 재료다 — 요약 뒤에 반드시 도구 호출이 온다.

**기계적 판정** — 답을 사람이 골라야 하는 문장(「~할까요」「~아니면」「어느 쪽」)을 쓰려는 순간,
그 문장을 쓰지 말고 도구를 부른다.

| 게이트 | 언제 | 선택지 |
|---|---|---|
| 🛑 **0** 계약 변경 | `tpx-spec` 이 계약을 건드린다고 판정 | `승인 — SPEC 먼저 고친다` / `다른 방법을 찾는다` / `중단` |
| 🛑 **1** 계획 | 2등급 이상 | `지적 반영하고 진행` / `그대로 승인` / `중단` |
| 🛑 **2** 병합 | **전 등급** | `승인하고 병합` / `고치고 재검사` / `보류` |

**게이트 0 에서 「승인」이 나오면 다음 단계로 가기 전에 등급부터 다시 잰다** (위 §등급 판정).
`docs/spec/**` 를 고치기로 한 것이 바로 여기서 확정되고, 그 표면은 3등급이다.

**게이트 1 의 「지적 반영하고 진행」은 재검토로 돌아가지 않는다.** 계획만 고치고 곧장 [5] 로 간다 —
사용자가 계획과 지적을 둘 다 보고 고른 것이므로 한 번 더 돌릴 이유가 없다. 결과는 게이트 2 가 본다.
`계획 → 검토 → 계획 → 계획` 루프가 2026-09-18 실측으로 $12 를 태웠다. 그 루프를 여기서 끊는다.

게이트 2 요약에는 **선언 등급 · 실측 등급 · `미분류` 줄 · 건너뛴 단계**를 반드시 싣는다.

## 선행 읽기 — 여기서 한 번만 읽는다

**이 컨트롤러가 세션당 1회 읽고, 하위 스킬과 하위 작업자 프롬프트에 본문을 붙여 보낸다.**
하위는 다시 읽지 않는다. 단계마다 새로 읽는 것이 옛 오케스트레이터가 턴당 명령 20~30개를 쓴 원인이다.

1. `CLAUDE.md` — 작업 규칙
2. `docs/SPEC.md` 색인의 **「갈래를 맡았을 때」 표**에서 이번 갈래 행만 — 그 장들만 읽는다.
   갈래가 없는 작업이면 「기능을 더하거나 고칠 때」 라우터 표에서 찾는다
3. `docs/LEARNINGS.md` — **전량 금지.** `grep -n '^## '` 로 헤딩만 뽑아 이번 작업 키워드와
   맞는 것 + 최근 5건만 부분 읽기
4. `docs/progress/<갈래>.md` — 있으면

## PR 이 진행 상황판이다

**단계마다 갱신한다.** 한 단계라도 빠뜨리면 `pr-update-wiring` 판별식이 빨간불을 낸다.

```bash
node .claude/scripts/pr-update.mjs --pr <번호> --tier <등급> --step <N> --next "<다음 멈춤>"
node .claude/scripts/pr-update.mjs --pr <번호> --comment "### [N/7] <무엇> 완료 ... **다음.** <무엇>"
```

- **본문** = 지금 어느 단계인가 (덮어쓴다) · **코멘트** = 그 단계에서 뭘 했나 (쌓인다)
- 코멘트 맨 끝은 **항상 `다음.` 한 줄**이다. 읽는 사람이 「내가 뭘 해야 하나」를 찾아 헤매지 않게
- 비용은 적지 않는다

## 진행 출력

단계마다 1줄 출력해 깜깜이를 피한다. 보고 서식은 아래를 따른다.

- **첫 줄은 사용자가 할 수 있는 것.** 배경도 계획도 아니다
- 여러 단계는 번호. 한 단계에 「그리고」가 두 번 들어가지 않는다
- 마지막은 2분 안에 할 수 있는 행동 하나
- 서두·요약·마무리 인사 금지
- 처음 나온 약어는 괄호로 푼다
- **코드를 보여주고 「확인해보세요」 하지 않는다** (CLAUDE.md §4). 눌러볼 명령을 준다

게이트 요약은 세 줄로 시작한다.

```
✅ 한 줄   <비전문가 한 문장 — 무엇이 됐나>
💡 의미   <무슨 뜻인지 + 판단 재료>
🔧 기술 상세 (안 봐도 됨)
```

## 막혔을 때

같은 문제를 **3번 시도해서 안 되면 멈추고** CLAUDE.md §6 형식으로 보고한다.
하려던 것 · 시도한 것 셋 · 에러 원문 · 가설 한 줄 · 필요한 것.

- **작업방 충돌** — 같은 이름이 있으면 `-2` 접미사
- **검사가 빨강인데 내 변경 때문이 아닌 것 같다** — 추측하지 말고 `git diff origin/main...HEAD` 로
  실제 바뀐 것을 먼저 본다. 환경 문제면 **고치지 말고 게이트 요약에 싣는다**
- **계획 검토 BLOCKER** — 게이트 1 로 간다. 계획을 되돌리지 않는다
