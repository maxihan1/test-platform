# tpx-author — 이어하기 (멈춘 자리부터)

프롬프트에 `--- 이어하기 ---` 절이 있으면 이 파일을 따른다. 없으면 상관없다.
**정본은 `docs/spec/도메인/작성.md` §7 「이어하기」다.** 여기는 자식이 할 일만 적는다.

이 작업방은 앞 실행이 **멈춘 자리 그대로**다. 앞 실행이 쓴 요구사항 표 · 케이스 · 차이 파일 · 본 화면 기록이 남아 있다.
앞 실행의 대화는 없다 — **파일이 전부다.** 대화에서 정한 것이 파일에 없으면 없는 것이다.

## 1. 먼저 멈춘 까닭을 본다

절의 「멈춘 까닭」에 따라 첫 할 일이 다르다.

| 까닭 | 첫 할 일 |
|---|---|
| **올리기 거절** | **거절 글이 가리키는 것부터 고친다.** 다른 일보다 먼저다 — 그대로 두면 다시 거절된다 |
| · 비밀번호가 들어 있다 · 가린 표시가 남았다 | 에이전트가 자식을 띄우기 전에 원문을 `••••••` 로 가려 둔다(2026-09-29). **케이스의 `••••••` 가 거절된 자리다** — 그 자리를 **비밀값 자리(`process.env.TARGET_LOGIN_PASSWORD` · 비밀값 꼬리표)** 로 바꾼다. 표 · 차이의 `••••••` 는 기획서 문장이라 그대로 둔다. 역방향이면 `references/reverse.md` §2 |
| · 브랜치 마지막 커밋이 에이전트 것이 아니다(사람이 올린 커밋) | **자식은 고칠 수 없다** — 사람이 PR 에서 그 커밋을 병합하거나 뺀다(도메인/작성 §7 「실행 기록」). 파일은 손대지 말고 관문만 다시 돌린 뒤 결과 요약에 `사람 커밋이 브랜치에 있어 올리지 못함` 을 적는다 |
| · 테스트 밖 파일을 고쳤다 | 그 파일을 원래대로 되돌린다. 쓸 수 있는 것은 `tests/<폴더>/*.spec.ts` 와 `docs/cases/<접두사>.md` 뿐이다 |
| · push · PR 을 못 만들었다 | 고칠 것이 없다. 관문만 다시 돌리고 끝낸다 — 올리기는 에이전트가 다시 한다 |
| 시간초과 · 작성 중 끊김 · 재시작 · 응답 없음 · 사용자 · 한도 | 아래 2 부터 |

## 2. 남은 것을 읽는다

1. `docs/cases/<접두사>.md` — 요구사항 표. **있으면 새로 쓰지 않는다.** 빈 줄 · `케이스` 칸이 빈 요구만 남은 일이다
2. `tests/<폴더>/*.spec.ts` — 이미 만든 케이스. **지우고 다시 쓰지 않는다.** 표의 줄과 맞춰 본다
3. 역방향이면 산출물 폴더의 `diffs.json` 과 `screens/*.md` — 본 화면은 다시 훑지 않는다. 한 칸 규칙(`reverse.md`)으로 **아직 안 본 화면만** 본다
4. 자료(기획서)는 앞 실행과 같다 — 다시 읽되 표와 어긋나지 않게 한다

## 3. 남은 것만 하고, 관문은 넷 다 다시

- 표에서 케이스가 없는 요구만 케이스로 만든다. tcId 는 이미 쓴 번호 다음부터
- **관문 넷(형식 · 표 대조 · 3회 실행 · 일부러 부수기)은 이어받은 케이스까지 전부 다시 돌린다.** 앞 실행이 관문을 통과했는지는 파일로 남지 않는다
- 결과 요약(`SKILL.md` 「결과 요약」)에 한 줄을 더한다 — `이어받음: 작성 요청 <번호> · 이어받은 케이스 N건 · 새로 만든 케이스 M건`
