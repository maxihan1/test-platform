# tpx-author — 이어하기 (멈춘 자리부터)

프롬프트에 `--- 이어하기 ---` 절이 있으면 이 파일을 따른다. 없으면 상관없다.
**정본은 `docs/spec/도메인/작성.md` §7 「이어하기」다.** 여기는 자식이 할 일만 적는다.

이 작업방은 앞 실행이 **멈춘 자리 그대로**다. 앞 실행이 쓴 요구사항 표 · 케이스 · 차이 파일 · 본 화면 기록이 남아 있다.
앞 실행의 대화는 없다 — **파일과 진행 메모가 전부다.** 대화에서 정한 것이 그 둘에 없으면 없는 것이다. 메모의 칸은 `SKILL.md` 「진행 메모」가 정본이다(2026-10-04).

## 1. 먼저 멈춘 까닭을 본다

절의 「멈춘 까닭」에 따라 첫 할 일이 다르다.

| 까닭 | 첫 할 일 |
|---|---|
| **올리기 거절** | **거절 글이 가리키는 것부터 고친다.** 다른 일보다 먼저다 — 그대로 두면 다시 거절된다 |
| · 비밀번호가 들어 있다 · 가린 표시가 남았다 | 에이전트가 자식을 띄우기 전에 원문을 `••••••` 로 가려 둔다(2026-09-29). **케이스의 `••••••` 가 거절된 자리다** — 그 자리를 **비밀값 자리(`process.env.TARGET_LOGIN_PASSWORD` · 비밀값 꼬리표)** 로 바꾼다. 표 · 차이의 `••••••` 는 기획서 문장이라 그대로 둔다. 역방향이면 `references/reverse.md` §2 |
| · 브랜치 마지막 커밋이 에이전트 것이 아니다(사람이 올린 커밋) | **자식은 고칠 수 없다** — 사람이 PR 에서 그 커밋을 병합하거나 뺀다(도메인/작성 §7 「실행 기록」). 파일은 손대지 말고 관문만 다시 돌린 뒤 결과 요약에 `사람 커밋이 브랜치에 있어 올리지 못함` 을 적는다 |
| · 테스트 밖 파일을 고쳤다 | 그 파일을 원래대로 되돌린다. 쓸 수 있는 것은 `tests/<폴더>/*.spec.ts` · `pages/*.page.ts` · `components/*.component.ts` 와 `docs/cases/<접두사>.md` 뿐이다. **Page Object · Component 는 되돌리지 않는다** — 되돌리면 케이스가 쓰는 Page Object 가 지워진다 |
| · push · PR 을 못 만들었다 | 고칠 것이 없다. 관문만 다시 돌리고 끝낸다 — 올리기는 에이전트가 다시 한다 |
| · 표준 기획서를 못 올렸다 · 결과 파일이 없다 · 깨졌다 · 비밀값이 들었다 | 결과 파일(`out/prd.json`)을 고치거나 쓴 뒤 `npm run prd:ledger` 로 원장 사본을 다시 만든다(`prd.md`). 서버가 거절한 까닭(상한 · 번호)이면 그 항목을 고친다. 그 사이 판이 바뀌어 번호를 못 맞췄으면 고칠 것이 없다 — 관문만 다시 돈다 |
| 시간초과 · 작성 중 끊김 · 재시작 · 응답 없음 · 사용자 · 한도 | 아래 2 부터 |

**거절 까닭이 메모보다 앞선다** — 올리기 거절이면 위 표대로 그것부터 고친 뒤 메모를 본다.

## 2. 남은 것을 읽는다

0. **진행 메모**(프롬프트의 이어하기 절이 준 경로 — 없을 수 있다) — 「다음 할 일」이 어디서 이어갈지 알려 준다. 「정한 것과 이유」를 따른다. 「끝낸 것」은 진도일 뿐 관문 통과 기록이 아니다(아래 3). 메모를 읽었으면 `진행 메모를 읽었다 — <지금 단계>부터 이어간다` 한 줄을 말한다
1. `docs/cases/<접두사>.md` — 요구사항 표. **있으면 새로 쓰지 않는다.** 빈 줄 · `케이스` 칸이 빈 요구만 남은 일이다
2. `tests/<폴더>/*.spec.ts` · `tests/<폴더>/pages/*.page.ts` · `tests/<폴더>/components/*.component.ts` — 이미 만든 케이스와 Page Object · Component. **지우고 다시 쓰지 않는다.** 표의 줄과 맞춰 본다
3. 역방향이면 산출물 폴더의 `diffs.json` 과 `screens/*.md` — 본 화면은 다시 훑지 않는다. 자료 폴더에 `crawl/list.json` 이 있으면 **크롤러를 다시 돌리지 않는다**(번호가 바뀌어 기록 이름 · 저장본 맞추기가 어긋난다). 이어서 작성은 앞 실행의 크롤 목록을 쓴다 — 설정의 뺄 경로가 바뀌었으면 새 실행부터 먹는다. `reverse.md` 「훑는 범위」의 갈래 규칙(대조는 한 칸 · 화면만은 모든 화면)으로 **아직 안 본 화면만** 본다
4. 표준 기획서 절이 있으면 자료 폴더의 결과 파일(`out/prd.json`) — 있으면 새로 쓰지 않고 이어서 고친다(`prd.md` §1). 원장 사본은 에이전트가 그 파일을 넣어 다시 만들어 두었다 — 앞 실행이 올렸으면 임시 번호가 받은 번호로 바뀌어 있고 표도 그렇다
5. 자료(기획서)는 앞 실행과 같다 — 결과 파일이 없을 때만 다시 읽어 옮긴다. 표는 표준 기획서로 쓴다(`prd.md` §5)

## 3. 남은 것만 하고, 관문은 전부 다시

- **관문 0 의 `빠짐:` 줄부터 채운다.** 원장 대조는 2026-09-30 게이트 1 부터 올리기를 거절하지 않는다 — 빠진 채 올라가면 셈에 「빠짐」으로만 남는다. `다음 요청` 을 새로 적지 않는다(관문 0 이 형식 오류로 잡는다)
- 표에서 케이스가 없는 요구만 케이스로 만든다. tcId 는 `npm run ledger:number` 를 다시 돌려 매긴다 — 이미 매긴 번호는 안 바뀐다(종료 코드 2 면 종류별로 이미 쓴 번호 다음부터 — `two-kinds.md` R17)
- **관문 다섯(원장 대조 · 형식 · 표 대조 · 3회 실행 · 일부러 부수기)은 이어받은 케이스까지 전부 다시 돌린다.** 앞 실행이 관문을 통과했는지는 파일로 남지 않는다 — 진행 메모에 「통과」라고 적혀 있어도 다시 돈다(관문 3 결과 파일은 넘겨받을 때 지워진다)
- 결과 요약(`SKILL.md` 「결과 요약」)에 한 줄을 더한다 — `이어받음: 작성 요청 <번호> · 이어받은 케이스 N건 · 새로 만든 케이스 M건`
