# 게임 배우기 — 플레이어처럼 해 보고 테스터처럼 의심한다 (2026-11-25 · GAME-F6-03)

게임 학습 세션 · 시험 세션만 이 파일을 연다(케이스를 쓰는 세션은 열지 않는다). 프롬프트가 「직접 플레이하며 배운다」이면 §1 ~ §9, 「지도만 보고 시험 본다」이면 §10 만 한다.
정본은 명세 `docs/spec/도메인/게임.md` §3.10 「게임 배우기」 · 「게임에 대해 배운 것」이다.

## 1. 무엇을 하나

**배우는 것은 게임이다. 조작은 배우는 수단이다.** 이 게임이 어떻게 이기고 지나, 무엇이 무엇을 바꾸나, 숫자는 얼마인가를 알아내 게임 지도(세컨드 브레인)에 쌓는다.
버튼 목록 · 창 목록을 만드는 일이 아니다 — 그것은 창 훑기가 한다. 메뉴와 설정 화면만 돌고 끝내면 아무것도 안 배운 것이다.

지도는 다음 세션의 너만 본다. 사람이 읽기 좋게 꾸미지 않는다. 대신 **대화를 못 보는 세션이 이 줄만 보고 다시 해 볼 수 있게** 조건 · 앞뒤 값 · 횟수를 적는다.

## 2. 시간과 컨텍스트 — 배울 때마다 적는다

- 세션은 프롬프트에 적힌 시간(30분)이고 컨텍스트가 20만 토큰이면 먼저 끊긴다. **에이전트가 말없이 끊는다 — 적은 것만 남는다.** 한 가지를 알아낼 때마다 바로 적는다
- 명령이 `※` 줄을 찍으면 하던 시험을 멈추고 → 지금까지 안 것을 적고 → 못 끝낸 것을 `ASK` 로 남기고 → 「학습 끝」 한 줄로 끝낸다
- 큰 트리 · 긴 로그를 대화에 통째로 올리지 않는다. 파일에서 필요한 줄만 `grep` 한다. 스크린샷은 꼭 봐야 할 때만 연다
- 다음 세션은 이 대화를 못 본다. 지도 · 조작 맵 · `tests/<폴더>/helpers/` · 자료 폴더의 기록만 남는다

## 3. 한 바퀴

**처음(지도가 비었을 때)**

1. 게임을 켜고 **게임 안 글을 다 읽는다** — 공지 · 도움말 · 튜토리얼 · 설명 창 · 아이템 설명. 읽은 문장을 `<자료 폴더>/game-guide.txt` 에 한 줄에 한 문장씩 옮긴다(`# <어느 창>` 줄로 자리를 적는다). 프로그램이 **문장마다 지도에 들었는지 본다** — 그 문장을 `learned.data` 의 `글` 칸에 그대로 넣은 줄이 있어야 든 것이다. 게임이 한 말이면 `belief` 는 `GAME_TEXT`, 정말인지 재 볼 것이면 `ASK` 줄을 하나 더한다. **재 보니 글과 다르면** 그 줄을 `CONFIRMED` 로 바꾸고 `data` 에 `글`(원문 그대로)과 `글다름`(무엇을 했고 무엇이 나왔나 한 문장)을 같이 적는다 — 사람이 어느 쪽이 맞나 고른다. `ODD` 줄도 하나 남긴다
2. **튜토리얼을 끝까지 한다.** 중간에 나가지 않는다
3. **한 판 해 본다.** 목표는 이기기다. 지면 왜 졌는지 `FAIL` 에 적고 다음 판은 방법을 **하나만** 바꾼다(§6)

**그다음부터는 궁금한 것을 푼다**

1. **고른다** — 빈 종류 · 얇은 종류 · 남은 `ASK` · 빌드가 다른 줄 · 게임 안 글 · 화면 숫자 · SDK 로 읽은 값 이름 · 진 까닭에서. 차례는 승패 → 성장 → 재화 → 그 밖이다
2. **시험한다** — 예상을 먼저 적고(`TRIAL` · `belief: GUESS`), **조건 하나만** 바꾸고, 앞뒤 값을 잰다. 횟수는 §7
3. **테스터처럼 의심한다** — 경계(0 · 최대 · 모자람) · 동시에 · 도중에 그만두기 · 창을 연 채 · 글과 다른 값. 이상하면 `ODD`(버그 후보)에 앞뒤 값과 조건을 적는다
4. **정리한다** — 답을 얻은 `ASK` 는 답 줄(`RULE` · `CALC` …)에 적고 `learned: null` 로 지운다. 새 궁금증을 `ASK` 로 더한다. 틀린 것으로 드러난 줄은 지우지 말고 `OVERTURNED` 로 바꿔 무엇이 뒤집었나 적는다
5. **되는 동작은 남긴다** — 조작 도우미(`tests/<폴더>/helpers/`)로 쓰고 부를 수 있게 둔다. 가는 길은 조작 맵 행(`game.md` §8.3)이다. 케이스 · 미션과 다음 학습이 그대로 쓴다. 시험하다 만 함수는 지운다

## 4. 보는 길 넷을 다 쓴다

화면만 보면 반밖에 못 본다. 시험마다 넷을 다 본다.

| 길 | 명령 | 무엇을 |
|---|---|---|
| 화면 | `snapshot` · `find` · 스크린샷 | 숫자 · 표시 · 색 |
| 게임 안 값 | `get <주소> <칸>` · `members <주소>` | 위치 · 체력 · 재화 — 화면보다 먼저 바뀌기도 한다 |
| 게임 로그 | `logs`(최근 500줄) | 판정 · 데미지. **앞 번호를 적어 두고 뒤 줄만 본다** |
| 오류 · 장면 | `errors` · `events` | 조용히 난 오류 · 장면 바뀜 |

- 조작 도우미로 돌리면 그 사이 로그 · 오류 · 알림이 `<자료 폴더>/game-play/` 에 같이 남는다
- 로그에 아무것도 안 찍히는 게임도 있다 — 그러면 그렇다고 `PROBE` 에 적고 값과 화면으로 잰다
- 값을 읽은 자리(오브젝트 · 칸)와 **믿으면 안 되는 자리**(값이 늦게 바뀐다 · 복제본이 여럿이다)를 `PROBE` 에 적는다
- 서버가 있는 게임은 가이드에 적힌 서버 로그 · API 도 본다. GM · 어드민 API 는 **시작 조건을 맞출 때만** 쓴다. 캐릭터는 이름이 `qacrawl` 로 시작하는 것만 만들어 쓰고 서버 전체 초기화는 하지 않는다. 만든 캐릭터는 세션 사이에 지우지 않는다 — 다음 세션이 잇고, 케이스를 쓰는 세션이 작성 끝에 지운다(`game.md` §4)

## 5. 지도에 적기

```bash
npx tsx scripts/authoring-learn-note.ts <자료 폴더> <<'JSON'
[{ "kind": "RULE", "key": "rule:심기", "name": "심기",
   "learned": { "text": "빈 칸에 심으면 고기 5 를 쓴다(고기 5 미만이면 안 심긴다)", "belief": "CONFIRMED", "seen": 2, "build": "59",
                "shape": "FIXED", "data": { "고기": -5, "본것": ["20→15", "15→10"] }, "related": ["item:고기"] } },
 { "kind": "ASK", "key": "ask:심은 뒤 바로 공격하나", "name": "심은 뒤 바로 공격하나", "learned": { "text": "심고 몇 초 뒤에 첫 공격을 하나", "belief": "GUESS" } }]
JSON
```

- 같은 열쇠를 다시 적으면 통째로 바뀐다 — 앞에 잰 것(`data` · `seen`)을 같이 옮겨 적는다(`data.요구` 는 에이전트가 단 요구 번호다 — 빼지 않는다). 지우려면 `"learned": null`
- `value`(기획서 값)는 싣지 않는다. 잰 값은 `data` 에 적고, 기획서 값과 견줄 것은 `value` 와 **같은 칸 이름**을 쓴다
- **규칙 하나에 한 줄이다** — 뒤 세션이 `CONFIRMED` · `GAME_TEXT` 줄을 하나씩 PRD 항목으로 옮긴다(`GUESS` · `SEEN` · 치트로 본 것 · `shape: UNKNOWN` 은 안 옮긴다). 잰 조건을 `text` 에 적는다. 무엇의 규칙인지 `SYSTEM` 줄과 `related` 로 잇는다 — 그 이름이 PRD 기능 묶음이 된다
- 종류는 그 줄이 답하는 질문으로 고른다 — 표는 명세 「게임에 대해 배운 것」. 기본 종류에 안 맞는 줄이 **셋** 모였을 때만 `KIND` 줄로 새 종류를 만든다(스무 개까지). 세션 끝에 겹치는 종류는 합치고 줄이 셋 밑인 종류는 되돌린다
- **시험에서 틀린 줄만 다시 배우는 세션**이면 그 줄만 조건을 바꿔 다시 잰다 — 다른 궁금한 것은 다음 작성이 잇는다
- 빈 종류는 배우거나, 이 게임에 없으면 `<앞머리>:없음` 줄에 까닭을 적는다(`multi:없음` — 「혼자 하는 게임이다」). 안 해 보고 「없음」이라고 적지 않는다

| `belief` | 언제 |
|---|---|
| `GUESS` 추측 | 아직 안 쟀다 |
| `SEEN` 덜 봄 | 쟀지만 횟수가 모자라다 |
| `CONFIRMED` 확인 | §7 횟수를 채웠고 **원래 속도**로 다시 되는 것을 봤다. 잰 값 · 횟수 · 빌드를 꼭 적는다 |
| `GAME_TEXT` 게임 글 | 게임 안 글이 그렇게 말한다(아직 안 쟀다) |
| `OVERTURNED` 뒤집힘 | 틀린 것으로 드러났다 |

- 끝내기 전에 `npx tsx scripts/authoring-game-find.ts <자료 폴더> --check <지금 빌드>` 로 고칠 줄을 본다(근거 없음 · 값 다름 · 빌드 다름 · 없는 관련 열쇠)
- 원본(로그 · 스크린샷)은 자료 폴더에 두고 지도에는 앞뒤 값과 횟수만 적는다
- **기대값의 근거가 아니다.** 어느 쪽이 맞는지 정하지 않는다. 기획서와 다르면 잰 값을 적고 `ODD` 를 더한다. 사람이 쓴 서비스 가이드와 다르면 가이드를 따르고 그 줄에 `marks: ["HUMAN"]` 을 단다 — 다시 재도 계속 다르면 `ODD` 다
- 표준 기획서 지금 판이 있으면 그 요구를 확인한 줄에 `reqIds` 로 번호를 적는다 — 다음 이어 작성 · 반영이 그 번호의 줄부터 본다. 기획서에서 온 다섯 종류(`item:` · `zone:` 들)의 이미 있는 줄에는 안 적는다(명령이 뗀다)

## 6. 이기는 실력 — 생각은 AI, 손은 스크립트, 실력은 복습

1. **판을 시작하기 전에 작전 하나** — 무엇을 언제 어디에. 판 도중에 명령을 하나씩 생각해 보내지 않는다(그동안 게임은 흐른다)
2. **반사 스크립트** — 되풀이 규칙을 조작 도우미 함수로 쓴다(「체력이 줄면 기지로 · 자원이 되면 심기 · 떨어진 것 줍기 · 가까운 적이면 공격」). 위에서부터 보고 맞는 것 하나를 한다. 쓰는 법은 `game-control.md` §3
3. **판 기록** — 1초마다 한 줄(체력 · 자원 · 처치 · 웨이브 · 내 위치)을 함수가 돌려준다
   한 판을 다 하는 함수는 **어디서 불려도 그 판의 시작 조건부터 맞추고 끝에 `{ 이김: true | false }` 를 돌려주게** 쓴다 — 이긴 함수는 뒤 세션이 원래 속도로 10판을 돌려 확인하고 미션의 할 일로 쓴다(`game-control.md` §5)
4. **복습** — 언제부터 기울었나 → 까닭 하나 → 다음 판에 바꿀 것 하나. 판마다 버틴 시간 · 넘긴 웨이브 · 처치 · 승패를 `PLAY` · `FAIL` 에 남긴다. 그 숫자가 느는지가 배우고 있는지다
5. **쉬운 것부터** — 튜토리얼 → 첫 맵 쉬움 → 다음 맵. 세 판 이어 안 좋아지면 막힌 것이다
6. **멈추고 생각하기는 배울 때만** — 부르기 전에 `npx control-cli -s=g timescale-set 0.25` 로 늦추거나 0 으로 멈춘다(함수 안에서 바꾸지 않는다). 익힌 뒤 **원래 속도로 다시 해서 되는 것만 `CONFIRMED`** 다. 시간 값(쿨타임 · 카운트다운)은 원래 속도로만 잰다
7. 판 사이 되풀이(돈 모으기)는 스크립트만 돌린다. 이때만 배율을 올려도 된다 — 그때 본 시간 · 값은 근거로 쓰지 않는다

**막히면** — 방법을 바꿔 세 번 → 치트로 뒤쪽을 본다(`marks: ["CHEAT"]` — 승패 · 수치 근거가 아니다) → `ASK` 줄 `data` 에 `"막힘": "<까닭 — 사람에게 물을 말>"` 을 적고 다른 것으로 간다. 막힌 줄은 빌드가 바뀔 때까지 다시 배울 것으로 세지 않고 PR 머리에 「사람에게 물을 것」으로 실린다.

## 7. 랜덤

같은 조건인데 결과가 다르면 **바로 「뒤집힘」이나 버그로 적지 않는다.** ① 잰 실수(시점 · 지연) ② 아직 모르는 조건 ③ 남(봇 · 사람이 PC 를 만짐)을 먼저 찾고, 남은 것이 랜덤이다.

- **꼴을 적는다**(`shape`) — 고정 `FIXED` · 폭 `RANGE`(본 최소~최대) · 확률 `RATE`(k/n) · 목록 `LIST`(나온 것마다 횟수) · 앞에 매임 `DEPENDS`(천장 · 셔플 — 나온 순서도) · 모름 `UNKNOWN`
- **횟수** — 정해진 값은 조건을 바꿔 **두 번**. 랜덤일 만한 것(글에 확률 · % · 드랍 · 치명 · 랜덤, 전투 결과 · 등장 · 보상 · 선택지)은 **10번부터**, 확률을 말하려면 **30번부터**. 모자라면 「n번 중 k번」만 적고 `SEEN` 이다
- **표본은 더한다** — 앞 세션이 같은 빌드 · 같은 조건으로 잰 것이 있으면 그 수에 이어 센다
- **작전 비교** — 이겼다 졌다만 보지 않고 버틴 시간 · 웨이브 · 처치로 본다. 3판에 크게 다르면 끝, 애매하면 10판까지 간 뒤 되돌린다
- **줄인다** — 대상 하나 · 자리 고정 · 같은 시작 조건. 서버 게임은 결과 고정 명령이 있으면 쓴다. 난수 씨앗 고정은 배울 때만이고 그렇게 본 것은 `marks: ["SEED"]` 다(분포 근거가 아니다)
- 본 범위를 한도로, 본 비율을 확률로 적지 않는다

## 8. 오래 걸리는 것 · 여럿이 하는 것

- 성장표는 다 채우지 않고 몇 점만 잰다(처음 · 초반 둘 · 중간 · 끝). 중간부터는 시작 조건(GM · 시험 기능)으로 맞춘다
- 날짜가 바뀌어야 보이는 것은 시계를 바꾸지 않는다. `ASK` 줄 `data` 에 `"볼날": "YYYY-MM-DD"` 를 적으면 그날부터 배울 것이 된다
- **다시 잡은 디바이스에는 저장 데이터가 없다.** 배운 조작 도우미로 그 자리까지 다시 간다. 다시 못 가면 그 도우미 · 그 줄이 틀린 것이다 — 지도의 믿음을 내린다
- 여럿이 — 한 명으로 먼저 배우고, 둘이면 무엇이 달라지나(참가 · 화면 나눔 · 재화 나눔 · 적 수 · 승패 · 한 명 나가기)를 `ASK` 로 둔다. 두 명은 한 함수에서 키보드(1P)와 가상 패드(2P)를 번갈아 돈다 — 2P 는 서 있기부터. 세 명부터와 다른 사람의 계정이 있어야 하는 것은 `"막힘": "아직 안 해 봄 — <까닭>"` 이다

## 9. 디바이스

- 놓지 않는다(`release` 금지) — 놓으면 저장 데이터가 지워진다. 에이전트가 늘리고 놓는다. 앞 세션이 끊긴 채라면 `npx control-cli -s=g input-reset` 으로 눌린 입력부터 놓는다
- `open` 이 「이미 열려 있습니다」면 `snapshot` 을 먼저 해 본다. 안 되면 `close` 뒤 `open` 이다. 잡은 것이 풀렸으면(409 · 잡은 폰이 아님) `close` 뒤 다시 잡고 켠다
- 못 잡으면 같은 거절로 세 번 넘게 다시 걸지 않는다. 글로 된 자료에서 궁금한 것(`ASK`)만 적고 끝낸다
- 폰 게임은 키 대신 터치(`touchDown` · `drag`)다

## 10. 시험 — 지도만 보고

`game-exam.json` 의 줄(확인된 것)이 정말인지 본다. 기획서 · 가이드 · `game-play/` · `game-guide.txt` 를 열지 않는다. 지도는 찾기 명령으로 읽는다.

1. **첫 판을 끝까지** — 지도와 조작 도우미만으로 첫 스테이지를 시작부터 판이 끝날 때까지 한다(이기든 지든). 조작 도우미 부르기 명령이 찍은 기록 파일 이름을 적는다
   ```bash
   echo '{"끝":true,"이김":false,"까닭":"2웨이브에서 기지 체력 0","기록":"20261125120000000-한판.json"}' | npx tsx scripts/authoring-learn-exam.ts <자료 폴더> 판
   ```
2. **예측** — 시험감마다 `잰것` 에 **없는 조건**을 하나 정하고 값을 먼저 적는다. 적은 예측은 못 고친다
   ```bash
   echo '[{"열쇠":"rule:심기","조건":"고기 10 에서 두 번째 칸에 심는다","예측":{"값":5}},{"열쇠":"calc:처치 보상","조건":"둘째 웨이브 악마 다섯","예측":{"최소":3,"최대":8}}]' | npx tsx scripts/authoring-learn-exam.ts <자료 폴더> 예측
   ```
   고정 줄은 값, 재는 값이 흔들리는 시간 · 위치와 랜덤 줄은 범위, 나올 것이 정해진 줄은 `{"목록":[…]}` 이다
3. **재기** — 원래 속도로 잰다. 랜덤 줄은 세 번 이상 재서 다 적는다. 잰 것은 지도 줄의 표본에도 더해 적는다(§5 명령)
   ```bash
   echo '[{"열쇠":"rule:심기","잰값":[5]},{"열쇠":"calc:처치 보상","못잼":"둘째 웨이브까지 못 감"}]' | npx tsx scripts/authoring-learn-exam.ts <자료 폴더> 결과
   ```
4. 맞혔나는 프로그램이 매긴다 — 틀린 줄은 프로그램이 「덜 봄」으로 내린다. 스스로 믿음을 고치지 않는다. 다 했으면 「시험 끝」 한 줄로 끝낸다
