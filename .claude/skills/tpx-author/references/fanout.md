# tpx-author — 팬아웃 (화면 묶음별 서브에이전트)

`SKILL.md` 절차 4(§4 selector → §5 케이스 작성)에서 연다. 사용자 결정(2026-09-30): **A안 — 화면 묶음별로 나누고 동시 3.**

**왜** — 케이스 작성이 한 줄로 돌아 오래 걸린다. 표를 얼린 뒤의 일(§4 · §5)은 결정적이라 나눠도 결과가 흔들리지 않는다.
나누는 것은 **표를 얼린 뒤**뿐이다. 표를 쓰는 §2 는 비결정이라 한 곳(자식)에만 둔다 (`tpx-cases` 「척추」).
사람 세션의 `/tpx-cases` 도 같은 규칙을 쓴다 — 거기서는 「자식」을 「그 세션」으로, 뼈대의 「에이전트가 한다」를 「그 세션이 한다」로 읽는다.

## 1. 언제

셋 다일 때만 나눈다. 아니면 자식이 혼자 한다.

- 표를 확정했고 **tcId 를 전부 매겼다** — 묶음끼리 번호가 겹치지 않게 자식이 먼저 정한다
- **화면 묶음이 둘 이상**
- **케이스가 8건 이상**(서로 다른 tcId)

## 2. 묶음을 가른다

표의 줄을 **화면 · 절** 단위로 묶는다 — `출처` 칸의 절과 `조작` 이 여는 화면을 본다.
같은 tcId 를 가리키는 줄(규칙 R15 로 합친 줄)은 **반드시 한 묶음**이다. 한 화면을 두 묶음이 나눠 갖지 않는다 — 탐침과 용어가 겹친다.

- **동시에 셋까지.** 묶음이 넷 이상이면 셋씩 차례로 띄운다. 앞 셋이 다 끝나야 다음 셋이다
- **Agent 도구를 앞에서 띄우고 끝날 때까지 기다린다. 백그라운드로 띄우지 않는다** —
  2026-09-23 자식이 백그라운드 작업을 남기고 턴을 먼저 끝내 에이전트가 멈췄다. Agent 도구도 같다
- 셋을 한꺼번에 띄울 때는 한 응답에 Agent 호출 셋을 나란히 둔다 — 그래야 동시에 돈다

## 3. 누가 무엇을 쓰나 — 표는 자식 혼자 쓴다

| 누구 | 쓰는 것 |
|---|---|
| 자식 | `docs/cases/<접두사>.md` 전부 — 표 · 제외 · 용어 사전 · `tcId` · `작성 시점` 칸 |
| 서브에이전트 | 자기 tcId 의 `tests/<폴더>/<tcId>.spec.ts` · 용어 조각 `<자리>/glossary/<묶음>.md` · (역방향이면) 평소처럼 `screens/*.md` |

`<자리>` 는 프롬프트가 준 산출물 폴더, 없으면 `$TMPDIR`. **표 파일을 둘 이상이 고치면 늦게 쓴 쪽이 앞 것을 지운다.**
서브에이전트는 표에서 고칠 것을 찾으면 고치지 않고 돌려주는 요약에 적는다. 자식이 표를 고친다.

## 4. 서브에이전트 프롬프트 — 이 뼈대를 채워 그대로 넘긴다

서브에이전트는 이 대화도 스킬 규칙도 모른다. **읽을 파일과 금지를 프롬프트에 다 적는다.**

> `<접두사>` 서비스의 테스트케이스 가운데 「<묶음 이름>」 묶음을 만든다.
>
> **맡은 줄** — 아래는 `docs/cases/<접두사>.md` 요구사항 표에서 옮긴 줄이다. 이 줄의 칸을 글자 그대로 코드에 옮긴다(규칙 R11).
> `<표 머리 줄과 맡은 줄을 그대로 붙인다>`
>
> - tcId: `<목록>` — 이 번호 말고는 만들지 않는다
> - 테스트 폴더: `tests/<폴더>` · 본보기 `tests/demo/DEMO-011.spec.ts`
> - 대상 서버: 환경 변수 `<이름들 — 값은 적지 않는다>`
> - 먼저 Read 로 연다: `.claude/skills/tpx-cases/references/4-selector.md` · `5-writing.md` · `korean-ai-tells.md`
> - 용어 조각은 `<자리>/glossary/<묶음>.md` 에 `4-selector.md` 「용어 사전」 모양으로. 탐침 세션 이름은 `probe-<묶음>` — 다른 묶음과 겹치지 않게
>
> **지킬 것**
> 1. 버전 관리 명령과 PR 도구를 부르지 않는다. 커밋 · 올리기는 에이전트가 한다
> 2. AskUserQuestion 을 부르지 않는다 — 답할 사람이 없다
> 3. 명령과 도구를 백그라운드로 돌리지 않는다. 전부 끝까지 기다린다
> 4. 계정 값은 환경 변수와 `params` 비밀값 칸(`.meta({ secret: true })`)으로만 쓴다. 파일 · 명령줄에 값을 적지 않는다
> 5. 맡은 tcId 파일과 용어 조각 말고는 고치지 않는다. `docs/cases/<접두사>.md` 도 고치지 않는다
> 6. 관문은 아래 둘만 돈다. 다른 묶음 파일에서 난 오류는 고치지 않고 적어만 온다
>
> **관문** — 파이프로 넘기지 않는다.
> `npm run typecheck > <자리>/tc-<묶음>.log 2>&1; echo "EXIT=$?"` · `npm run check:tests > <자리>/ct-<묶음>.log 2>&1; echo "EXIT=$?"`
> `PLATFORM_ARTIFACTS_DIR=<자리>/pw-<묶음> npx playwright test <맡은 파일들> --project=desktop --reporter=line > <자리>/pw-<묶음>.log 2>&1; echo "EXIT=$?"`
>
> **돌려줄 것**(짧게) — 만든 파일 · 관문 결과(`EXIT` 와 요약 줄) · held 로 둔 케이스와 사유 · 표에서 고칠 것 · 막힌 것

**`PLATFORM_ARTIFACTS_DIR` 를 묶음마다 가른다** — Playwright 는 시작할 때 산출물 폴더를 비운다. 셋이 한 폴더를 쓰면 서로의 산출물을 지운다.

## 5. 관문 분담

| 누가 | 관문 |
|---|---|
| 서브에이전트 | 관문 1(형식) · 자기 파일 실행 1회 |
| 자식 | 조각을 합친 뒤 관문 0 · 2 · 3(폴더 전체 3회) · 4 를 한 번씩 |

**왜** — 관문 3 을 서브에이전트와 자식이 둘 다 3회씩 돌리면 120분 예산을 두 번 쓴다. 서브에이전트는 제 파일이 한 번 도는지만 보고,
불안정은 자식이 폴더 전체 3회로 한 번에 본다. 관문 1 은 싸서 양쪽에서 돈다.

**자식이 합칠 때** — ① `<자리>/glossary/*.md` 를 표 파일의 「용어 사전」 한 절로 합친다. 같은 용어가 다른 locator 로 두 번 오면 탐침으로 다시 보고 하나를 고른다
② 서브에이전트가 적어 온 「표에서 고칠 것」을 표에 반영한다 — 반영했으면 그 케이스의 글자가 표와 같은지 관문 2 가 본다
③ `SKILL.md` 의 관문 명령을 차례로 돈다

## 6. 서브에이전트가 실패하거나 막혔을 때

- **그 묶음은 자식이 이어받아 직접 쓴다.** 이미 만든 파일은 지우지 않고 이어서 쓴다
- **다시 띄우는 것은 한 번까지다.** 두 번째도 막히면 자식이 맡는다 — 같은 자리에서 서브에이전트를 거듭 띄우면 예산만 쓴다
- 막힌 사유는 결과 요약의 해당 칸(판정 불가·보류 · 못 읽은 자료)에 싣는다
