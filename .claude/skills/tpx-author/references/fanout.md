# tpx-author — 팬아웃 (화면 묶음별 서브에이전트)

`SKILL.md` 절차 4(§4 selector → §5 케이스 작성)에서 연다. 사용자 결정(2026-09-30): **A안 — 화면 묶음별로 나눈다.** 2026-10-03 게이트 0 · 1: **동시 넷 · 한 차례 · 서브에이전트가 자기 파일 3회 · 자식은 끝에 전체 3회 한 번.**
역방향 훑기를 나누는 것은 `references/scan-fanout.md` 다.

**왜** — 케이스 작성이 한 줄로 돌아 오래 걸린다. 표를 얼린 뒤의 일(§4 · §5)은 결정적이라 나눠도 결과가 흔들리지 않는다.
나누는 것은 **표를 얼린 뒤**뿐이다. 표를 쓰는 §2 는 비결정이라 한 곳(자식)에만 둔다 (`tpx-cases` 「척추」).
얼린 뒤 표에 더하는 줄은 §4 에서 본 화면 입력 규칙 하나뿐이고, 그것도 자식만 더한다 (아래 「자식이 합칠 때」 ③).
사람 세션의 `/tpx-cases` 도 같은 규칙을 쓴다 — 거기서는 「자식」을 「그 세션」으로, 뼈대의 「에이전트가 한다」를 「그 세션이 한다」로 읽는다.
**단 §5 관문 분담은 작성 에이전트에만 쓴다**(2026-10-03 게이트 1 — 근거 실측이 에이전트뿐이다). 사람 세션은 서브에이전트가 자기 파일 1회, 그 세션이 폴더 전체 3회를 돈다(`tpx-cases` §6).

## 1. 언제

셋 다일 때만 나눈다. 아니면 자식이 혼자 한다.

- 표를 확정했고 **tcId 를 전부 매겼다** — 묶음끼리 번호가 겹치지 않게 자식이 먼저 정한다. 묶음마다 UI 번호(`<접두사>-UI-NNN`)와 기능 번호(`<접두사>-FN-NNN`)를 종류별로 나눠 준다(`two-kinds.md` R17)
- **화면 묶음이 둘 이상**
- **케이스가 8건 이상**(서로 다른 tcId)

## 2. 묶음을 가른다

표의 줄을 **화면 · 절** 단위로 묶는다 — `출처` 칸의 절과 `조작` 이 여는 화면을 본다.
같은 tcId 를 가리키는 줄(규칙 R15 로 합친 줄)은 **반드시 한 묶음**이다. 한 화면을 두 묶음이 나눠 갖지 않는다 — 탐침과 용어가 겹친다.

- **가르기 전에 공용 Component 를 자식이 먼저 만든다.** 두 화면 이상에 나오는 부품(머리 메뉴 · 로그인 상자 등)만 `tests/<폴더>/components/<이름>.component.ts` 로 둔다. 서브에이전트는 읽기만 한다
- **동시에 넷까지 · 한 차례에 다 띄운다.** 묶음이 넷을 넘으면 이웃 묶음(같은 메뉴 · 이어지는 흐름)을 합쳐 넷으로 만든다. 차례를 나누지 않는다 —
  CDY 는 셋 + 하나 두 차례로 팬아웃만 34분이 걸렸다(2026-10-03)
- **묶음 크기를 케이스 수로 고르게 한다** — 화면 수가 아니라 묶음마다 서로 다른 tcId 수를 센다. 한 차례는 가장 큰 묶음이 끝나야 끝난다.
  한 화면에 케이스가 몰려 고르게 안 되면 그대로 두고 결과 요약 `팬아웃:` 줄에 묶음별 건수를 적는다
- **물러서기** — 서브에이전트가 로그인이 끊겼다거나 메모리 오류(`out of memory` · 브라우저가 갑자기 닫힘)를 돌려주면 남은 묶음을 **동시 둘**로 다시 띄운다
- **Agent 도구를 앞에서 띄우고 끝날 때까지 기다린다. 백그라운드로 띄우지 않는다** —
  2026-09-23 자식이 백그라운드 작업을 남기고 턴을 먼저 끝내 에이전트가 멈췄다. Agent 도구도 같다
- 넷을 한꺼번에 띄울 때는 한 응답에 Agent 호출 넷을 나란히 둔다 — 그래야 동시에 돈다

## 3. 누가 무엇을 쓰나 — 표는 자식 혼자 쓴다

| 누구 | 쓰는 것 |
|---|---|
| 자식 | `docs/cases/<접두사>.md` 전부 — 표 · 제외 · 용어 사전 · `tcId` · `작성 시점` 칸 · 팬아웃 전에 공용 `tests/<폴더>/components/<이름>.component.ts` |
| 서브에이전트 | 자기 tcId 의 `tests/<폴더>/<tcId>.spec.ts` · 자기 화면의 `tests/<폴더>/pages/<화면>.page.ts` · 용어 조각 `<자리>/glossary/<묶음>.md` · 실행 결과 `<자리>/gate3-<묶음>.json` |

**Page Object 의 주인은 하나다** — 한 화면을 두 묶음이 나눠 갖지 않으므로 그 화면 묶음의 서브에이전트만 `pages/<화면>.page.ts` 를 쓴다. 이미 있는 파일은 **더하기만** 한다(고치거나 이름을 바꾸지 않는다). `components/*` 는 자식이 팬아웃 전에 만들고 서브에이전트는 읽기만 한다.

`<자리>` 는 프롬프트가 준 산출물 폴더, 없으면 `$TMPDIR`. **표 파일을 둘 이상이 고치면 늦게 쓴 쪽이 앞 것을 지운다.**
서브에이전트는 표에서 고칠 것을 찾으면 고치지 않고 돌려주는 요약에 적는다. 자식이 표를 고친다.

> (사람 세션은 이 줄에서 `PLAYWRIGHT_JSON_OUTPUT_FILE=…` · `--repeat-each=3` · `,json` 을 빼고 1회 돈다 — 맨 위 「단 §5」)
>
> **돌려줄 것**(짧게) — 만든 파일 · 관문 결과(`EXIT` 와 요약 줄 · 결과 파일 경로) · 3회에서 빨간 케이스와 첫 실패 문장(held 를 달지 않는다) · held 로 둔 케이스와 사유 · 표에서 고칠 것 · 막힌 것 ·
> **화면 입력 규칙**(탐침에서 본, 기획서에 없는 필수 표시 · 글자 수 제한 · 형식 안내 — `요소 · 규칙 · 그 칸을 다루는 요구 번호`. 케이스는 만들지 않는다) ·
> **CSS · XPath 를 쓴 까닭**(쓴 요소와 까닭 한 줄 — 케이스 파일에는 주석을 못 쓴다)

**`PLATFORM_ARTIFACTS_DIR` 를 묶음마다 가른다** — Playwright 는 시작할 때 산출물 폴더를 비운다. 넷이 한 폴더를 쓰면 서로의 산출물을 지운다.

## 5. 관문 분담

| 누가 | 관문 |
|---|---|
| 서브에이전트 | 관문 1(형식) · **자기 파일 3회**(결과 파일 `gate3-<묶음>.json`) |
| 자식 | 조각을 합친 뒤 관문 0 · 1 · 2 → **폴더 전체 3회를 끝에 한 번** → 관문 4. 그 뒤 고친 것은 고친 파일 + 그 Page Object · Component 를 쓰는 케이스만 3회 |

**왜** (2026-10-03 게이트 1 — B) — MKT 는 자식이 고칠 때마다 전체 3회(한 번 약 20분)를 다시 돌아 약 100분을 썼다. 고치는 일은 서브에이전트가 자기 파일 3회로 끝내 두고,
자식의 전체 3회는 파일끼리 얽힌 불안정(앞 케이스가 남긴 자료)을 보려고 끝에 한 번만 돈다. 전체 1회로 줄이는 안은 그것을 놓쳐 뺐다. 관문 1 은 싸서 양쪽에서 돈다.

- **숫자는 결과 파일에서 센다** — `gate3-*.json` 의 `stats`(`expected` · `unexpected` · `flaky` · `skipped` — `expected` 는 케이스 수 × 3 이다)를 묶음마다 읽어 결과 요약 `관문 3` 줄에 싣는다. 서브에이전트가 말로 돌려준 숫자를 옮기지 않는다 — 그것이 사람이 누르는 병합의 근거다
- **서브에이전트 3회에서 빨간 케이스** — held 를 달기 전에 자식이 합친 뒤 그 파일만 혼자 3회 다시 돈다. 묶음 넷이 같은 계정 · 서버를 동시에 써서 난 빨강일 수 있다. 혼자서도 같은 이유로 3회 빨강일 때만 held(`tpx-cases` §6 종료 조건)
- **결과 파일이 없거나 못 읽으면** 그 묶음 파일을 자식이 3회 다시 돌린다

**단계 표지** — 서브에이전트를 띄우기 직전에 `[단계] 팬아웃 시작 — 묶음 <N>`, 모두 돌아온 직후 `[단계] 팬아웃 뒤 합치기` 를 말한다(`SKILL.md` 「단계 표지」).
위 프롬프트 뼈대에는 표지를 넣지 않는다 — 시각은 자식 줄로만 잰다.

**자식이 합칠 때** — ① `<자리>/glossary/*.md` 를 표 파일의 「용어 사전」 한 절로 합친다. 같은 용어가 다른 뜻 · 다른 요소로 두 번 오면 탐침으로 다시 보고 하나를 고른다(locator 는 Page Object 에 있다)
② 서브에이전트가 적어 온 「표에서 고칠 것」을 표에 반영한다 — 반영했으면 그 케이스의 글자가 표와 같은지 관문 2 가 본다
③ 적어 온 **화면 입력 규칙**을 모아 같은 것은 하나로 합치고, 표에 미확정 줄을 더해 번호를 이어 매긴 뒤 그 케이스를 자식이 직접 쓴다 (`tpx-cases` `two-kinds.md` 「화면에만 있는 입력 규칙」).
   **CSS · XPath 까닭**은 용어 사전의 그 요소 줄에 붙인다
④ 차이 목록에 새 차이를 더했으면 `diffs.json` 도 같이 고친다 — **합친 뒤 관문 0 을 연 다음에는 표 · 차이에 줄을 더하지 않는다**(표를 쓴 직후의 「관문 0 일찍」은 세지 않는다 — 명세 §3.6 「★ 원장」 팬아웃)(11204 는 관문 뒤에 미확정 6건을 더해 전체 3회를 다시 돌았다)
⑤ `SKILL.md` 의 관문 명령을 차례로 돈다

## 6. 서브에이전트가 실패하거나 막혔을 때

- **그 묶음은 자식이 이어받아 직접 쓴다.** 이미 만든 파일은 지우지 않고 이어서 쓴다
- **다시 띄우는 것은 한 번까지다.** 두 번째도 막히면 자식이 맡는다 — 같은 자리에서 서브에이전트를 거듭 띄우면 예산만 쓴다
- 막힌 사유는 결과 요약의 해당 칸(판정 불가·보류 · 못 읽은 자료)에 싣는다
