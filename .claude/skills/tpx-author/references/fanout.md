# tpx-author — 팬아웃 (화면 묶음별 서브에이전트)

`SKILL.md` 절차 4(§4 selector → §5 케이스 작성)에서 연다. 사용자 결정(2026-09-30): **A안 — 화면 묶음별로 나눈다.** 2026-10-03 게이트 0 · 1: **동시 넷 · 한 차례 · 서브에이전트가 자기 파일 3회 · 자식은 끝에 전체 3회 한 번.**
역방향 훑기를 나누는 것은 `references/scan-fanout.md` 다.

**왜** — 케이스 작성이 한 줄로 돌아 오래 걸린다. 표를 얼린 뒤의 일(§4 · §5)은 결정적이라 나눠도 결과가 흔들리지 않는다.
나누는 것은 **표를 얼린 뒤**뿐이다. 표를 쓰는 §2 는 비결정이라 한 곳(자식)에만 둔다 (`tpx-cases` 「척추」).
얼린 뒤 표에 더하는 줄은 §4 에서 본 화면 입력 규칙 하나뿐이고, 그것도 자식만 더한다 (아래 「자식이 합칠 때」 ③).
사람 세션의 `/tpx-cases` 도 같은 규칙을 쓴다 — 거기서는 「자식」을 「그 세션」으로, 뼈대의 「에이전트가 한다」를 「그 세션이 한다」로 읽는다.
**단 §5 관문 분담은 작성 에이전트에만 쓴다**(2026-10-03 게이트 1 — 근거 실측이 에이전트뿐이다). 사람 세션은 서브에이전트가 자기 파일 1회, 그 세션이 폴더 전체 3회를 돈다(`tpx-cases` §6).

## 1. 언제

셋 다일 때만 나눈다. 아니면 자식이 혼자 한다.

- 표를 확정했고 **`npm run ledger:number` 로 tcId 를 전부 매겼다**(`SKILL.md` 2단계 — 2026-10-04 부터 칸마다 명령이 매긴다). 묶음마다 UI 번호(`<접두사>-UI-NNN`)와 기능 번호(`<접두사>-FN-NNN`)를 종류별로 나눠 준다(`two-kinds.md` R17)
- **화면 묶음이 둘 이상**
- **케이스가 8건 이상**(서로 다른 tcId)

## 2. 묶음을 가른다

표의 줄을 **화면 · 절** 단위로 묶는다 — `출처` 칸의 절과 `조작` 이 여는 화면을 본다.
같은 tcId 를 가리키는 줄(한 칸의 줄 — 도메인/작성 §3.6 「칸과 번호」)은 **반드시 한 묶음**이다. 한 화면을 두 묶음이 나눠 갖지 않는다 — 탐침과 용어가 겹친다.

- **가르기 전에 공용 Component 를 자식이 먼저 만든다.** 두 화면 이상에 나오는 부품(머리 메뉴 · 로그인 상자 · 토스트 · 모달 등)과
  **가입 · 탈퇴 · 로그인 · 자료 만들고 지우기 같은 공용 도우미**를 `tests/<폴더>/components/<이름>.component.ts` 로 둔다. 서브에이전트는 가져다 쓰기만 하고 고치지 않는다 (2026-10-03 —
  MKT 11208 은 묶음마다 가입 · 탈퇴 도우미를 다른 이름으로 55개 파일에 따로 만들고, 있는 토스트 · 모달을 CSS 로 다시 만들었다).
  **표의 `전제` 칸을 훑어 두 케이스 이상에 나오는 준비 · 정리마다 도우미를 하나씩 만든다** — API 로그인 · 장바구니 비우기 · 글 만들고 지우기 · 주문 만들기 같은 것. 화면 부품만 만들고 끝내지 않는다
  (2026-10-04 — MKT 11211 은 부품 다섯만 만들어 `기본장바구니로되돌리기` 29 · `장바구니비우기` 21 · `지난글치우기` 17 파일에 복사됐다).
  만든 뒤 `grep -n "^export" tests/<폴더>/components/*.ts` 로 경로와 이름 목록을 뽑아 §4 뼈대에 그대로 붙인다
- **묶음마다 영문 slug 를 정한다** — 영문 소문자로 시작하고 소문자 · 숫자 · `-` 만, 35자까지(예 `cart` · `order-1`). 임시 도우미 파일 이름에 쓴다 — 부품 파일 이름 꼴이 그것만 받아 한글이면 관문 1 과 올리기가 거절한다
- **동시에 넷까지 · 한 차례에 다 띄운다.** 묶음이 넷을 넘으면 이웃 묶음(같은 메뉴 · 이어지는 흐름)을 합쳐 넷으로 만든다. 차례를 나누지 않는다 —
  CDY 는 셋 + 하나 두 차례로 팬아웃만 34분이 걸렸다(2026-10-03). **작성 에이전트에서는 훅이 지킨다**(2026-10-04 · 사람 세션은 훅이 꺼져 있어 이 규칙을 스스로 지킨다) — 다섯 번째 묶음 · 같은 묶음 세 번째 띄우기는 거절되고, 남은 묶음은 자식이 직접 쓴다. 다시 띄울 때 묶음 이름을 바꾸지 않는다
- **묶음 크기를 케이스 수로 고르게 한다** — 화면 수가 아니라 묶음마다 서로 다른 tcId 수를 센다. 한 차례는 가장 큰 묶음이 끝나야 끝난다.
  한 화면에 케이스가 몰려 고르게 안 되면 그대로 두고 결과 요약 `팬아웃:` 줄에 묶음별 건수를 적는다
- **물러서기** — 서브에이전트가 로그인이 끊겼다거나 메모리 오류(`out of memory` · 브라우저가 갑자기 닫힘)를 돌려주면 남은 묶음을 **동시 둘**로 다시 띄운다. 이것이 그 묶음의 「다시 띄우기 한 번」이다(§6)
- **Agent 도구를 앞에서 띄우고 끝날 때까지 기다린다. 백그라운드로 띄우지 않는다** —
  2026-09-23 자식이 백그라운드 작업을 남기고 턴을 먼저 끝내 에이전트가 멈췄다. Agent 도구도 같다
- 넷을 한꺼번에 띄울 때는 한 응답에 Agent 호출 넷을 나란히 둔다 — 그래야 동시에 돈다
- **작성 에이전트(자식)는 `subagent_type: author-write` 로 띄운다**(Sonnet · high — 작성.md §3.6 「모델」 줄 · 2026-10-04). **사람 세션의 `/tpx-cases` 는 고르지 않는다** — 그 모델은 승인 범위 밖이라 지금처럼 그 세션의 모델을 물려받는다

## 3. 누가 무엇을 쓰나 — 표는 자식 혼자 쓴다

| 누구 | 쓰는 것 |
|---|---|
| 자식 | `docs/cases/<접두사>.md` 전부 — 표 · 제외 · 용어 사전 · `tcId` · `작성 시점` 칸 · 팬아웃 전에 공용 `tests/<폴더>/components/<이름>.component.ts` |
| 서브에이전트 | 자기 tcId 의 `tests/<폴더>/<tcId>.spec.ts` · 자기 화면의 `tests/<폴더>/pages/<화면>.page.ts` · 용어 조각 `<자리>/glossary/<묶음>.md` · 실행 결과 `<자리>/gate3-<묶음>.json` · 모자란 도우미 `tests/<폴더>/components/draft-<slug>.component.ts` 한 파일 |

**Page Object 의 주인은 하나다** — 한 화면을 두 묶음이 나눠 갖지 않으므로 그 화면 묶음의 서브에이전트만 `pages/<화면>.page.ts` 를 쓴다. 이미 있는 파일은 **더하기만** 한다(고치거나 이름을 바꾸지 않는다). `components/*` 는 자식이 팬아웃 전에 만들고 서브에이전트는 읽기만 한다 — 단 자기 묶음의 `draft-<slug>.component.ts` 한 파일은 서브에이전트가 쓴다(자식이 합칠 때 공용으로 옮긴다).

`<자리>` 는 프롬프트가 준 산출물 폴더, 없으면 `$TMPDIR`. **표 파일을 둘 이상이 고치면 늦게 쓴 쪽이 앞 것을 지운다.**
서브에이전트는 표에서 고칠 것을 찾으면 고치지 않고 돌려주는 요약에 적는다. 자식이 표를 고친다.

> - 맡은 줄의 `축` 칸이 `UI` 면 UI Test, `정상` · `예외` · `경계` 면 Functional Test 다 (`two-kinds.md` R17)
> - 역방향이면: 맡은 줄 가운데 미확정 줄은 미확정 케이스로 쓴다(꼬리표 사유의 차이 번호는 줄에 있다). 화면 기록 `<화면 기록 폴더>/*.md` 를 다시 읽고 화면을 다시 훑지 않는다. 로그인 상태는 `state-load <로그인 상태 파일>`
> - 용어 조각은 `<자리>/glossary/<묶음>.md` 에 `4-selector.md` 「용어 사전」 모양으로. 탐침 세션 이름은 `probe-<묶음>` — 다른 묶음과 겹치지 않게
>
> **지킬 것**
> 1. 버전 관리 명령과 PR 도구를 부르지 않는다. 커밋 · 올리기는 에이전트가 한다
> 2. AskUserQuestion 을 부르지 않는다 — 답할 사람이 없다
> 3. 명령과 도구를 백그라운드로 돌리지 않는다. 전부 끝까지 기다린다
> 4. 계정 값은 환경 변수와 `params` 비밀값 칸(`.meta({ secret: true })`)으로만 쓴다. 파일 · 명령줄에 값을 적지 않는다
> 5. 맡은 tcId 파일 · 맡은 화면의 Page Object · 용어 조각 · `components/draft-<slug>.component.ts` 말고는 고치지 않는다. 다른 `components/*` 와 `docs/cases/<접두사>.md` 도 고치지 않는다
> 6. 관문은 아래 둘만 돈다. 다른 묶음 파일에서 난 오류는 고치지 않고 적어만 온다
> 7. 위 공용 부품 · 도우미 목록에 있는 일은 그것을 쓴다 — 같은 일을 하는 함수 · locator 를 케이스나 Page Object 에 다시 만들지 않는다.
>    **목록에 없는 준비 · 정리 도우미가 필요하면 케이스 파일마다 복사하지 말고** `draft-<slug>.component.ts` 에 한 번만 만들어 가져다 쓰고, 돌려주는 요약 「필요한 도우미」에 적는다
> 8. locator 는 testid → 역할(getByRole) → 라벨 → placeholder → 글자 → CSS → XPath 순으로 고른다. CSS · XPath 를 쓰면 까닭을 돌려준다
> 9. 준비 단계(전제)마다 그 화면이 맞는지 보는 판정을 `{ blocker: true }` 로 하나 둔다 — 준비가 틀어지면 뒤 판정이 엉뚱한 화면에서 실패한다
> 10. 맡은 줄의 경계 요구에서 입력 칸이 한도를 넘는 글자를 막으면 「한도 + 1 을 넣으면 한도까지만 들어간다」로 쓴다. 케이스를 빼지 않는다(도메인/작성 §3.6 「★ 테스트 두 갈래」). 표에 없는 새 입력 규칙은 쓰지 말고 아래 「화면 입력 규칙」으로 돌려준다
> 11. 경계 줄은 설계 목록의 값(표에 적힌 시험 값)을 그대로 쓴다. 맡은 줄의 설계 칸(경계 · 예외)을 빼지 않는다 — 못 쓰겠으면 「표에서 고칠 것」으로 돌려준다
> 12. 기능 케이스의 `defineCase` 에 `techniques` 를 `test-design.md` 「기법 표시」 표대로 적는다 — 경계 줄은 `['경계값 분석']`, 예외 줄은 위 「설계 목록」이 그 요구에 낸 예외 기법, 오류 추정 줄은 `['오류 추정']`, 정상 · UI 줄은 안 적는다
> 13. 오류 추정 줄(출처 `오류 추정 —`)은 화면에서 해 보고 `two-kinds.md` 「오류 추정 점검 목록」대로 쓴다. 화면이 기준을 어겨 빨간 것은 held 를 달지 않는다. 해 볼 수 없으면 쓰지 말고 「표에서 고칠 것」으로 돌려준다
>
> **관문** — 파이프로 넘기지 않는다.
> `npm run typecheck > <자리>/tc-<묶음>.log 2>&1; echo "EXIT=$?"` · `npm run check:tests > <자리>/ct-<묶음>.log 2>&1; echo "EXIT=$?"`
> `PLATFORM_ARTIFACTS_DIR=<자리>/pw-<묶음> PLAYWRIGHT_JSON_OUTPUT_FILE=<자리>/gate3-<묶음>.json npx playwright test <맡은 파일들> --project=desktop --repeat-each=3 --reporter=line,json > <자리>/pw-<묶음>.log 2>&1; echo "EXIT=$?"`
> 환경 변수 둘은 한 줄 안에 그대로 둔다 — 따로 치면 결과 파일이 안 생긴다. 자식이 그 파일로 숫자를 센다. 마지막 3회는 **고칠 것이 다 끝난 판으로** 돈다
> (사람 세션은 이 줄에서 `PLAYWRIGHT_JSON_OUTPUT_FILE=…` · `--repeat-each=3` · `,json` 을 빼고 1회 돈다 — 맨 위 「단 §5」)
>
> **돌려줄 것**(짧게) — 만든 파일 · 관문 결과(`EXIT` 와 요약 줄 · 결과 파일 경로) · 3회에서 빨간 케이스와 첫 실패 문장(held 를 달지 않는다) · held 로 둔 케이스와 사유 · 표에서 고칠 것 · 막힌 것 ·
> **필요한 도우미**(draft 에 만든 것 — `이름 · 하는 일 · 쓰는 tcId`) ·
> **화면 입력 규칙**(탐침에서 본, 기획서에 없는 필수 표시 · 글자 수 제한 · 형식 안내와 오류 문구 — `요소 · 규칙 · 그 칸을 다루는 요구 번호 · 화면 주소 · 화면에 보인 글 그대로`. 케이스는 만들지 않는다) ·
> **오류 추정 결과**(맡은 오류 추정 줄마다 `tcId · 항목 · 요구 번호 · 화면 주소 · 화면에 보인 글 그대로 · 기준 어김 여부`) ·
> **CSS · XPath 를 쓴 까닭**(쓴 요소와 까닭 한 줄 — 케이스 파일에는 주석을 못 쓴다)

**`PLATFORM_ARTIFACTS_DIR` 를 묶음마다 가른다** — Playwright 는 시작할 때 산출물 폴더를 비운다. 넷이 한 폴더를 쓰면 서로의 산출물을 지운다.

| 자식 | 조각을 합친 뒤 관문 0 · 1 · 2 → **폴더 전체 3회를 끝에 한 번**(`$AUTHORING_GATE3_DIR/gate3-final-<번호>.json` · `SKILL.md` 관문 명령 — 에이전트가 확인한다) → 관문 4. 그 뒤 고친 것은 고친 파일 + 그 Page Object · Component 를 쓰는 케이스만 3회 |

**왜** (2026-10-03 게이트 1 — B) — MKT 는 자식이 고칠 때마다 전체 3회(한 번 약 20분)를 다시 돌아 약 100분을 썼다. 고치는 일은 서브에이전트가 자기 파일 3회로 끝내 두고,
자식의 전체 3회는 파일끼리 얽힌 불안정(앞 케이스가 남긴 자료)을 보려고 끝에 한 번만 돈다. 전체 1회로 줄이는 안은 그것을 놓쳐 뺐다. 관문 1 은 싸서 양쪽에서 돈다.

- **숫자는 결과 파일에서 센다** — `gate3-*.json` 의 `stats`(`expected` · `unexpected` · `flaky` · `skipped` — `expected` 는 케이스 수 × 3 이다)를 묶음마다 읽어 결과 요약 `관문 3` 줄에 싣는다. 서브에이전트가 말로 돌려준 숫자를 옮기지 않는다 — 그것이 사람이 누르는 병합의 근거다
- **서브에이전트 3회에서 빨간 케이스** — held 를 달기 전에 자식이 합친 뒤 그 파일만 혼자 3회 다시 돈다. 묶음 넷이 같은 계정 · 서버를 동시에 써서 난 빨강일 수 있다. 혼자서도 같은 이유로 3회 빨강일 때만 held(`tpx-cases` §6 종료 조건). 화면이 오류 추정 기준을 어겨 빨간 것은 held 없이 둔다(같은 곳 4)
- **결과 파일이 없거나 못 읽으면** 그 묶음 파일을 자식이 3회 다시 돌린다

**단계 표지** — 서브에이전트를 띄우기 직전에 `[단계] 팬아웃 시작 — 묶음 <N>`, 모두 돌아온 직후 `[단계] 팬아웃 뒤 합치기` 를 말한다(`SKILL.md` 「단계 표지」).
위 프롬프트 뼈대에는 표지를 넣지 않는다 — 시각은 자식 줄로만 잰다.

**자식이 합칠 때** — ① `<자리>/glossary/*.md` 를 표 파일의 「용어 사전」 한 절로 합친다. 같은 용어가 다른 뜻 · 다른 요소로 두 번 오면 탐침으로 다시 보고 하나를 고른다(locator 는 Page Object 에 있다)
② 서브에이전트가 적어 온 「표에서 고칠 것」을 표에 반영한다 — 반영했으면 그 케이스의 글자가 표와 같은지 관문 2 가 본다
③ 적어 온 **화면 입력 규칙**을 모아 같은 것은 하나로 합치고, 표에 미확정 줄(출처에 `화면 검사 —`)을 더해 `npm run ledger:number` 를 다시 돌린 뒤(이미 매긴 번호는 안 바뀐다) 그 케이스를 자식이 직접 쓴다 (`tpx-cases` `two-kinds.md` 「화면에만 있는 입력 규칙」).
   오류 문구는 표 · 케이스에 더하지 않는다. 표준 기획서 절이 있으면 입력 규칙과 오류 문구, 그리고 돌려받은 **오류 추정 결과**를 결과 파일에 `확인 필요` 항목으로 더한다(`prd.md` §4)
   **CSS · XPath 까닭**은 용어 사전의 그 요소 줄에 붙인다
④ 차이 목록에 새 차이를 더했으면 `diffs.json` 도 같이 고친다 — **합친 뒤 관문 0 을 연 다음에는 표 · 차이에 줄을 더하지 않는다**(표를 쓴 직후의 「관문 0 일찍」은 세지 않는다 — 명세 §3.6 「★ 원장」 팬아웃)(11204 는 관문 뒤에 미확정 6건을 더해 전체 3회를 다시 돌았다)
⑤ **임시 도우미를 공용으로 옮긴다** — `components/draft-*.component.ts` 와 요약의 「필요한 도우미」를 모아 같은 일을 하는 것은 하나로 합쳐 공용 Component 파일로 옮기고, 케이스 · Page Object 의 import 를 고친 뒤 draft 파일을 지운다(남으면 끝 검사 ⚠️)
⑥ `SKILL.md` 의 관문 명령을 차례로 돈다

## 6. 서브에이전트가 실패하거나 막혔을 때

- **그 묶음은 자식이 이어받아 직접 쓴다.** 이미 만든 파일은 지우지 않고 이어서 쓴다
- **다시 띄우는 것은 한 번까지다**(물러서기 포함 · 훅이 지킨다). 두 번째도 막히거나 훅이 거절하면 자식이 맡는다 — 같은 자리에서 서브에이전트를 거듭 띄우면 예산만 쓴다
- 막힌 사유는 결과 요약의 해당 칸(판정 불가·보류 · 못 읽은 자료)에 싣는다
