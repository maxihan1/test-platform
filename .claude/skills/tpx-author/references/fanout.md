# tpx-author — 팬아웃 (화면 묶음별 서브에이전트)

`SKILL.md` 절차 4(§4 selector → §5 케이스 작성)에서 연다. 사용자 결정(2026-09-30): **A안 — 화면 묶음별로 나눈다.** 2026-10-03 게이트 0 · 1: **동시 넷 · 한 차례.** 2026-10-26 사용자(PRD-F15-01): **서브에이전트는 다 쓴 뒤 자기 파일 한 판(1회 · 빨강만 다시) · 3회는 자식의 마지막 전체 돌려 보기(이번 작성이 닿은 케이스) 한 번**(§5).
역방향 훑기를 나누는 것은 `references/scan-fanout.md` 다.

**왜** — 케이스 작성이 한 줄로 돌아 오래 걸린다. 표를 얼린 뒤의 일(§4 · §5)은 결정적이라 나눠도 결과가 흔들리지 않는다.
나누는 것은 **표를 얼린 뒤**뿐이다. 표를 쓰는 §2 는 비결정이라 한 곳(자식)에만 둔다 (`tpx-cases` 「척추」).
얼린 뒤 표에 더하는 줄은 §4 에서 본 화면 입력 규칙과 버튼 반응뿐이고, 그것도 자식만 더한다 (아래 「자식이 합칠 때」 ③ · ④).
사람 세션의 `/tpx-cases` 도 같은 규칙을 쓴다 — 거기서는 「자식」을 「그 세션」으로, 뼈대의 「에이전트가 한다」를 「그 세션이 한다」로 읽는다. 표준 기획서 절이 없으니 아래 ③ 의 미확정 줄은 더하지 않는다.
**단 §5 관문 분담은 작성 에이전트에만 쓴다**(2026-10-03 게이트 1 — 근거 실측이 에이전트뿐이다). 사람 세션은 서브에이전트가 자기 파일 1회, 그 세션이 폴더 전체 3회를 돈다(`tpx-cases` §6).

## 1. 언제

셋 다일 때만 나눈다. 아니면 자식이 혼자 한다.

- 표를 확정했고 **`npm run ledger:number` 로 tcId 를 전부 매겼다**(`SKILL.md` 2단계 — 2026-10-04 부터 칸마다 명령이 매긴다). 묶음마다 UI 번호(`<접두사>-UI-NNN`)와 기능 번호(`<접두사>-FN-NNN`)를 종류별로 나눠 준다(`two-kinds.md` R17)
- **화면 묶음이 둘 이상**
- **케이스가 8건 이상**(서로 다른 tcId)

## 2. 묶음을 가른다

표의 줄을 **화면 · 절** 단위로 묶는다 — `출처` 칸의 절과 `조작` 이 여는 화면을 본다.
같은 tcId 를 가리키는 줄(한 칸의 줄 — 도메인/작성 §3.6 「칸과 번호」)은 **반드시 한 묶음**이다. 한 화면을 두 묶음이 나눠 갖지 않는다 — 탐침과 용어가 겹친다.

- **가르기 전에 공용 Component · 도우미를 자식이 먼저 만든다.** 두 화면 이상에 나오는 화면 조각(머리 메뉴 · 로그인 상자 · 토스트 · 모달 등)은 `tests/<폴더>/components/<이름>.component.ts`,
  **가입 · 탈퇴 · 로그인 · 자료 만들고 지우기 같은 공용 도우미**는 `tests/<폴더>/helpers/<이름>.helper.ts` 로 둔다 — 도우미를 `components/` 에 두면 「케이스 ↔ 화면」 지도에서 모든 케이스가 그 조각에 닿는다(`tpx-cases` `two-kinds.md` 「Page Object」). 서브에이전트는 가져다 쓰기만 하고 고치지 않는다 (2026-10-03 —
  MKT 11208 은 묶음마다 가입 · 탈퇴 도우미를 다른 이름으로 55개 파일에 따로 만들고, 있는 토스트 · 모달을 CSS 로 다시 만들었다).
  **표의 `전제` 칸을 훑어 두 케이스 이상에 나오는 준비 · 정리마다 도우미를 하나씩 만든다** — API 로그인 · 장바구니 비우기 · 글 만들고 지우기 · 주문 만들기 같은 것. 화면 부품만 만들고 끝내지 않는다
  (2026-10-04 — MKT 11211 은 부품 다섯만 만들어 `기본장바구니로되돌리기` 29 · `장바구니비우기` 21 · `지난글치우기` 17 파일에 복사됐다).
  만든 뒤 `grep -n "^export" tests/<폴더>/components/*.ts tests/<폴더>/helpers/*.ts` 로 경로와 이름 목록을 뽑아 §4 뼈대에 그대로 붙인다
- **만든 공용 부품은 표본 케이스로 거른다** (2026-10-26 사용자 · PRD-F15-01) — 그 부품을 쓰는 표의 케이스 한두 건을 자식이 직접 써서 `npm run -s authoring:run -- 한번 main <파일들>` 로 PC 에서,
  반응형 · 적응형이면 `--mobile-only` 를 붙여 휴대폰에서도 1번씩 돌린다(기록 `once-*` 는 3번 판정에 안 섞인다). 빨가면 부품을 고친 뒤 띄운다. 그 tcId 는 자식 몫이라 서브에이전트에 안 넘긴다 —
  서브에이전트는 쓰는 동안 돌리지 않아(§5) 넷이 같이 쓰는 부품이 깨져 있으면 넷 다 한 판에서야 안다
- **묶음마다 영문 slug 를 정한다** — 영문 소문자로 시작하고 소문자 · 숫자 · `-` 만, 35자까지(예 `cart` · `order-1`). 임시 도우미 파일 이름에 쓴다 — 도우미 파일 이름 꼴이 그것만 받아 한글이면 관문 1 과 올리기가 거절한다
- **동시에 넷까지 · 한 차례에 다 띄운다.** 묶음이 넷을 넘으면 이웃 묶음(같은 메뉴 · 이어지는 흐름)을 합쳐 넷으로 만든다. 차례를 나누지 않는다 —
  CDY 는 셋 + 하나 두 차례로 팬아웃만 34분이 걸렸다(2026-10-03). **작성 에이전트에서는 훅이 지킨다**(2026-10-04 · 사람 세션은 훅이 꺼져 있어 이 규칙을 스스로 지킨다) — 다섯 번째 묶음 · 같은 묶음 세 번째 띄우기는 거절되고, 남은 묶음은 자식이 직접 쓴다. 다시 띄울 때 묶음 이름을 바꾸지 않는다
- **묶음 크기를 케이스 수로 고르게 한다** — 화면 수가 아니라 묶음마다 서로 다른 tcId 수를 센다. 한 차례는 가장 큰 묶음이 끝나야 끝난다.
  한 화면에 케이스가 몰려 고르게 안 되면 그대로 두고 결과 요약 `보조 AI 나눠 맡기기:` 줄에 사람마다 건수를 적는다
- **물러서기** — 서브에이전트가 로그인이 끊겼다거나 메모리 오류(`out of memory` · 브라우저가 갑자기 닫힘)를 돌려주면 남은 묶음을 **동시 둘**로 다시 띄운다. 이것이 그 묶음의 「다시 띄우기 한 번」이다(§6)
- **Agent 도구를 앞에서 띄우고 끝날 때까지 기다린다. 백그라운드로 띄우지 않는다** —
  2026-09-23 자식이 백그라운드 작업을 남기고 턴을 먼저 끝내 에이전트가 멈췄다. Agent 도구도 같다
- 넷을 한꺼번에 띄울 때는 한 응답에 Agent 호출 넷을 나란히 둔다 — 그래야 동시에 돈다
- **작성 에이전트(자식)는 `subagent_type: author-write` 로 띄운다**(Sonnet · high — 작성.md §3.6 「모델」 줄 · 2026-10-04). **사람 세션의 `/tpx-cases` 는 고르지 않는다** — 그 모델은 승인 범위 밖이라 지금처럼 그 세션의 모델을 물려받는다

## 3. 누가 무엇을 쓰나 — 표는 자식 혼자 쓴다

| 누구 | 쓰는 것 |
|---|---|
| 자식 | `docs/cases/<접두사>.md` 전부 — 표 · 제외 · 용어 사전 · `tcId` · `작성 시점` 칸 · 팬아웃 전에 공용 `tests/<폴더>/components/<이름>.component.ts` · `tests/<폴더>/helpers/<이름>.helper.ts` |
| 서브에이전트 | 자기 tcId 의 `tests/<폴더>/<tcId>.spec.ts` · 자기 화면의 `tests/<폴더>/pages/<화면>.page.ts` · 용어 조각 `<자리>/glossary/<묶음>.md` · 보고 `<자리>/summary-<slug>.md` · 실행 기록 `$AUTHORING_GATE3_DIR/gate3-part-<slug>-<번호>.json`(돌려 보기 명령이 쓴다) · 모자란 도우미 `tests/<폴더>/helpers/draft-<slug>.helper.ts` 한 파일 |

**Page Object 의 주인은 하나다** — 한 화면을 두 묶음이 나눠 갖지 않으므로 그 화면 묶음의 서브에이전트만 `pages/<화면>.page.ts` 를 쓴다. 이미 있는 파일은 **더하기만** 한다(고치거나 이름을 바꾸지 않는다). `components/*` · `helpers/*` 는 자식이 팬아웃 전에 만들고 서브에이전트는 읽기만 한다 — 단 자기 묶음의 `helpers/draft-<slug>.helper.ts` 한 파일은 서브에이전트가 쓴다(자식이 합칠 때 공용으로 옮긴다).

`<자리>` 는 프롬프트가 준 산출물 폴더, 없으면 `$AUTHORING_GATE3_DIR`(사람 세션은 `$TMPDIR`). 맡은 줄을 파일로 넘기려면 그것도 `<자리>` 에 둔다 —
`/tmp` 는 서브에이전트가 못 읽는다(R1 에서 셋이 그래서 다시 떴다 · 2026-10-13 PRD-F9-14). **표 파일을 둘 이상이 고치면 늦게 쓴 쪽이 앞 것을 지운다.**
서브에이전트는 표에서 고칠 것을 찾으면 고치지 않고 돌려주는 요약에 적는다. 자식이 표를 고친다.

> - 맡은 줄의 `축` 칸이 `UI` 면 UI Test, `정상` · `예외` · `경계` 면 Functional Test 다 (`two-kinds.md` R17)

> - 용어 조각은 `<자리>/glossary/<묶음>.md` 에 `4-selector.md` 「용어 사전」 모양으로. 탐침 세션 이름은 `probe-<묶음>` — 다른 묶음과 겹치지 않게

> 2. AskUserQuestion 을 부르지 않는다 — 답할 사람이 없다
> 3. 명령과 도구를 백그라운드로 돌리지 않는다. 전부 끝까지 기다린다
> 4. 계정 값은 환경 변수와 `params` 비밀값 칸(`.meta({ secret: true })` · 역할 계정은 `account: '<역할>'` 도)으로만 쓴다. 파일 · 명령줄에 값을 적지 않는다 — `PLATFORM_ACCOUNTS` 가 있으면 kit 이 채운다
> 5. 맡은 tcId 파일 · 맡은 화면의 Page Object · 용어 조각 · 보고 파일 · `helpers/draft-<slug>.helper.ts` 말고는 고치지 않는다. 다른 `components/*` · `helpers/*` 와 `docs/cases/<접두사>.md` 도 고치지 않는다
> 6. 관문은 아래 「관문」에 적힌 것만 돈다. 다른 묶음 파일에서 난 오류는 고치지 않고 적어만 온다
> 7. 위 공용 부품 · 도우미 목록에 있는 일은 그것을 쓴다 — 같은 일을 하는 함수 · locator 를 케이스나 Page Object 에 다시 만들지 않는다.
>    **목록에 없는 준비 · 정리 도우미가 필요하면 케이스 파일마다 복사하지 말고** `helpers/draft-<slug>.helper.ts` 에 한 번만 만들어 가져다 쓰고, 돌려주는 요약 「필요한 도우미」에 적는다.
>    다른 서비스 테스트 폴더(`tests/<폴더>` 와 본보기 `tests/demo` · `tests/todo` 말고)의 부품은 열지도 베끼지도 않는다 — 같은 앱처럼 보여도 다른 제품이다
> 8. locator 는 testid → 역할(getByRole) → 라벨 → placeholder → 글자 → CSS → XPath 순으로 고른다. CSS · XPath 를 쓰면 까닭을 돌려준다
> 9. 준비 단계(전제)마다 그 화면이 맞는지 보는 판정을 `{ blocker: true }` 로 하나 둔다 — 준비가 틀어지면 뒤 판정이 엉뚱한 화면에서 실패한다
> 10. 맡은 줄에 입력 칸 글자 수 경계가 있으면 **쓰기 전에** `4-selector.md` 「입력 칸 한도」대로 잰다 — 그 칸에 쓸 입력 방법(Page Object 도 그 방법으로 쓴다)으로 한도 + 1 을 넣고 남은 길이를 읽는다. 칸이 막는데 맡은 줄이 오류 문구 · 등록 안 됨을 기대하면 **그 tcId 는 쓰지 않고**(기대값을 화면에 맞춰 바꾸지 않는다) 아래 「화면 입력 규칙」으로 `<칸> · 한도 N 에서 막음(<입력 방법>)` 을 돌려준다 — 자식이 표를 고쳐 직접 쓴다(도메인/작성 §3.6 「★ 테스트 두 갈래」). 한 판에서 이렇게 빨개져도 같다. 표에 없는 새 입력 규칙은 쓰지 말고 아래 「화면 입력 규칙」으로 돌려준다
> 11. 경계 줄은 설계 목록의 값(표에 적힌 시험 값)을 그대로 쓴다. 맡은 줄의 설계 칸(경계 · 예외)을 빼지 않는다 — 못 쓰겠으면 「표에서 고칠 것」으로 돌려준다
> 12. 기능 케이스의 `defineCase` 에 `techniques` 를 `test-design.md` 「기법 표시」 표대로 적는다 — 경계 줄은 `['경계값 분석']`, 예외 줄은 위 「설계 목록」이 그 요구에 낸 예외 기법, 오류 추정 줄은 `['오류 추정']`, 정상 · UI 줄은 안 적는다
> 13. 오류 추정 줄(출처 `오류 추정 —`)은 화면에서 해 보고 `two-kinds.md` 「오류 추정 점검 목록」대로 쓴다. 화면이 기준을 어겨 빨간 것은 held 를 달지 않는다. 해 볼 수 없으면 쓰지 말고 「표에서 고칠 것」으로 돌려준다
>
> **관문** — 맡은 케이스를 다 쓴 뒤 차례로 돈다. 파이프로 넘기지 않는다.
> `npm run -s authoring:check -- 보조 <맡은 파일들>; echo "EXIT=$?"` — 맡은 파일만 타입 검사(저장소 전체는 한 번에 1.2GB 라 넷이 겹치면 Docker 상자가 넘친다) · 맡은 파일만 케이스 형식 검사(tcId 겹침은 나머지 케이스와도 본다 · 화면 파일만 맡아도 돈다) · 맡은 tcId 의 케이스와 요구 목록 맞춰 보기 · 확인 하나에 값 하나를 돌리고 틀린 것만 찍는다. `EXIT` 0 이면 통과
> (사람 세션은 이 명령 대신 `npm run typecheck` · `npm run check:tests` 를 돈다)
> **1번 돌려 보기** — 입력값 두 번과 빨간 케이스의 까닭 가르기에만 쓴다. `npm run -s authoring:run -- 한번 <묶음 slug> <파일들>; echo "EXIT=$?"`. 응답을 안 늦추고 한 번 돌려 빨간 케이스의 첫 오류 줄만 찍는다. **기기 하나만 돈다** — 기본은 PC, 휴대폰만 빨간 케이스는 끝에 `--mobile-only` 를 붙여 휴대폰 하나로 돈다(`--trace` 도 된다). PC · 휴대폰을 같이 보는 것은 아래 한 판과 마지막이다. 앞에 붙인 환경 변수(`PLATFORM_PARAMS` · `PLATFORM_SLOW_API=1`)는 그대로 간다 — 입력값 두 번은 `PLATFORM_PARAMS='…'` 를 붙여, trace 로 까닭을 가를 때는 `PLATFORM_SLOW_API=1` 과 끝에 `--trace` 를 붙여 찍힌 trace 폴더를 `npm run trace:summary -- <폴더>` 로 본다. `EXIT` 0 초록 · 1 빨강(끝까지 못 돈 케이스도 빨강 줄로 찍힌다) · 2 잘못 불렀거나 주소가 없거나 끝난 케이스가 없다(찍힌 로그를 본다) · 3 브라우저 자리가 안 났다(같은 명령을 바로 다시 부른다)
> **한 판** — `npm run -s authoring:run -- 보조 <묶음 slug> <맡은 파일들>; echo "EXIT=$?"` — 크롤러 판정이 반응형이면 끝에 `--mobile` 을 붙인다(PC · 휴대폰 나란히 — `two-kinds.md` 「화면 크기 판정」. 적응형의 PC 서브에이전트는 안 붙인다 — 아래 「적응형」)
> **한 판 바로 앞에 입력값 두 번**(작성 에이전트만 — 사람 세션은 빼고, 그 세션의 관문 4 가 한다) — 입력값 칸이 있는 맡은 케이스를 `6-gates.md` 「입력값 칸은 기본값 말고 다른 값으로 두 번」대로 돈다. 서버 응답을 늦추지 않는다(`PLATFORM_SLOW_API` 없이). 기본 계정으로 로그인 실패를 내지 않는다(일회용 회원). ① 이 빨갛거나 ② 가 초록이면 고친 뒤 한 판을 돈다
> 한 판은 돌려 보기 명령이 서버 응답을 일부러 늦추고(0.1~1.5초) 맡은 파일을 1회 돌려 기록을 남긴 뒤 빨간 케이스의 첫 오류 줄만 찍는다. `EXIT` 3 이면 `남은 것 N건` — 같은 명령을 바로 다시 부른다(브라우저 자리를 기다린 시간도 한 번 부를 때의 7분 30초 안이라 덜 돌았을 수 있다). 1 이면 빨간 케이스가 있다 — 빨간 것만 고쳐 같은 명령을 다시 부르면 고친 파일과 그것을 쓰는 케이스만 다시 1회 돈다(안 고친 빨강은 다시 안 돈다).
> **같은 이유로 3번 빨간 케이스는 더 고치지 않는다** — held 를 달지 않고 빨강과 첫 실패 문장을 돌려준다(에이전트가 합친 뒤 3회를 보고 정한다). 묶음 끝 3회는 없다
> (사람 세션은 이 명령 대신 `PLATFORM_ARTIFACTS_DIR=<자리>/pw-<묶음> npx playwright test <맡은 파일들> --project=desktop` 로 1회 돈다 — 반응형 · 적응형이면 `--project=desktop --project=mobile --workers=2`. 맨 위 「단 §5」)
>
> **돌려줄 것**(짧게) — 같은 글을 `<자리>/summary-<slug>.md` 에도 쓴다(실행이 끊기면 대화로 돌려준 것은 사라지고 이 파일만 남는다 — 2026-10-19 · #303) · 만든 파일 · 관문 결과(`EXIT` 와 명령이 찍은 「[돌려 보기] …」 줄) · 한 판에서 빨간 채 남은 케이스와 첫 실패 문장(held 를 달지 않는다) · held 로 둔 케이스와 사유 · 표에서 고칠 것 · 막힌 것 ·
> **필요한 도우미**(draft 에 만든 것 — `이름 · 하는 일 · 쓰는 tcId`) ·
> **화면 입력 규칙**(탐침에서 본, 기획서에 없는 필수 표시 · 글자 수 제한 · 형식 안내와 오류 문구 — `요소 · 규칙 · 그 칸을 다루는 요구 번호 · 화면 주소 · 화면에 보인 글 그대로`. 케이스는 만들지 않는다) ·
> **버튼 반응**(맡은 화면마다 누를 수 있는 것을 하나씩 눌러 본 직후 반응 — `화면 이름 · 화면 주소 · 버튼 이름 → 반응 · 기획서가 그 반응을 적은 요구 번호(없으면 없음)`. 위험 버튼은 확인 창까지, 입력이 있어야 도는 제출 버튼은 안 누른다 — `tpx-cases` `two-kinds.md` 「버튼 반응 케이스」. 케이스는 만들지 않는다) ·
> **입력값 두 번 결과**(`입력값 ① N건 초록 · ② N건 빨강 · 뺀 칸 <이름들 / 없음>` / `입력값 칸 없음`) ·
> **오류 추정 결과**(맡은 오류 추정 줄마다 `tcId · 항목 · 요구 번호 · 화면 주소 · 화면에 보인 글 그대로 · 기준 어김 여부`) ·

### 적응형 — 화면 파일을 기기마다 나눈다 (2026-10-16 PRD-F10-07 · 사용자 D3 · 「가」)

크롤러 판정이 적응형이면(모바일이 다른 주소로 간다) 묶음 하나를 **서브에이전트 둘이 나란히** 쓴다 — PC 쪽과 모바일 쪽. 차례로 쓰면 시간이 두 배다(D2). 동시 넷 상한은 그대로라 묶음은 둘까지다(둘을 넘으면 이웃 묶음을 합친다).
케이스는 하나다(칸 하나 = 번호 하나 — 「칸과 번호」 그대로). 기기마다 다른 것은 화면 파일뿐이다(`two-kinds.md` 「화면 크기 판정」).

- **띄우기 전에 자식이 정한다** — 묶음의 화면마다 메서드 목록(이름 · 인자 · 하는 일 한 줄)을 표의 `조작` 칸에서 뽑아 두 프롬프트에 똑같이 싣는다. 공용 도우미 `helpers/device.helper.ts`(`모바일인가(page)` — 화면 폭 768 미만)도 팬아웃 전에 만든다
- **PC 서브에이전트** — 위 §4 뼈대 그대로(케이스 파일 · PC 화면 파일 `pages/<화면>.page.ts` · 용어 조각). 케이스는 `모바일인가` 로 PC · 모바일 화면 파일을 고른다 — 모바일 파일 클래스 이름 · 경로도 프롬프트에 적어 둔다. 한 판은 돌려 보기 명령에 `--mobile` 없이
- **모바일 서브에이전트** — 프롬프트 첫 줄은 `<접두사> 서비스의 테스트케이스 가운데 「<묶음 이름> 모바일」 묶음을 만든다.` 다(훅이 이 줄의 묶음 이름으로 넷 상한 · 다시 띄우기를 센다). 모바일 화면 파일 `pages/m-<화면>.page.ts` 만 쓴다(케이스 · 표 · 용어 조각은 안 쓴다). `<크롤 폴더>/viewport.json` 의 `모바일주소` 를 `주소` 값으로 두고 메서드 목록의 이름 · 인자를 그대로 지킨다. 탐침은 `--browser=webkit --device="iPhone 14"` 로 연다(`--mobile` 은 chromium 이라 안 쓴다). 관문은 관문 1 만 — `npm run -s authoring:check -- 보조 <맡은 화면 파일들>`(케이스 파일은 PC 쪽이 쓰는 중이다)
- **자식이 합친 뒤** — 마지막 전체 돌려 보기를 `--mobile` 로 돌아 PC · 휴대폰 3회를 본다(그 묶음 케이스는 휴대폰에서 처음 돈다). 휴대폰에서 빨개진 것은 모바일 화면 파일만 고친다
- 다른 묶음 파일 · 남의 화면 파일은 고치지 않는다(§4 「지킬 것」 5) — 모바일 서브에이전트의 맡은 파일은 `pages/m-<화면>.page.ts` 다

가끔만 빨개지는 케이스는 이제 마지막 3회가 잡는다. 휴대폰도 3회다 — 명령이 기기마다 자리를 하나씩 나란히 잡아 휴대폰을 1회로 줄여도 시간이 안 준다. 까닭 전체는 명세 도메인/작성 §3.6 「관문 분담」 인용 블록.

- **숫자는 명령이 찍은 줄에서 옮긴다** — 모두 돌아온 직후 **합치기(아래 ①) 전에** 자식이 묶음마다 `npm run -s authoring:run -- 보조 <slug> <그 묶음 파일들>` 을 한 번 더 부르면 돌릴 것 없이 그 묶음 기록의 「[돌려 보기] …」 줄과 빨강 줄을 찍는다. 합친 뒤에 부르면 합치기가 고친 파일을 다시 돈다.
  그것을 결과 요약 `3번 돌려 보기:` 줄의 보조 AI 별 칸에 싣는다. 서브에이전트가 말로 돌려준 숫자를 옮기지 않는다
- **서브에이전트 한 판에서 빨갛고 못 고친 케이스** — 따로 다시 돌리지 않는다. 마지막 전체 돌려 보기가 그 파일을 혼자(하나씩) 3회로 돈다. 응답 늦추기도 그대로라 기다림이 빠진 케이스는 거기서도 빨갛다. 묶음 넷이 같은 계정 · 서버를 동시에 써서 난 빨강이면 거기서 초록이 된다. 거기서 같은 이유로 3회 빨강일 때만 held(`tpx-cases` §6 종료 조건) — 서브에이전트는 한 판 빨강으로 held 를 달지 않는다. 값 다름과 화면이 오류 추정 기준을 어겨 빨간 것은 held 없이 둔다(같은 곳 1 · 4)

**단계 표지** — 서브에이전트를 띄우기 직전에 `[단계] 보조 AI 에게 나눠 맡기기 — <N>명`, 모두 돌아온 직후 `[단계] 보조 AI 결과 합치기` 를 말한다(`SKILL.md` 「단계 표지」).
위 프롬프트 뼈대에는 표지를 넣지 않는다 — 시각은 자식 줄로만 잰다.

**자식이 합칠 때** — ① `<자리>/glossary/*.md` 를 표 파일의 「용어 사전」 한 절로 합친다. 같은 용어가 다른 뜻 · 다른 요소로 두 번 오면 탐침으로 다시 보고 하나를 고른다(locator 는 Page Object 에 있다)
② 서브에이전트가 적어 온 「표에서 고칠 것」을 표에 반영한다 — 반영했으면 그 케이스의 글자가 표와 같은지 관문 2 가 본다
③ 적어 온 **화면 입력 규칙**을 모아 같은 것은 하나로 합친다. 표준 기획서 절이 있으면 입력 규칙과 오류 문구, 그리고 돌려받은 **오류 추정 결과**를 결과 파일에 `확인 필요` 항목으로 먼저 더하고 `npm run prd:ledger` 로 원장 사본을 다시 만든다(`prd.md` §4 · §5).
   그다음 표에 미확정 줄(출처에 입력 규칙 항목의 임시 번호 · `화면 검사 —`)을 더해 `npm run ledger:number` 를 다시 돌린 뒤(이미 매긴 번호는 안 바뀐다) 그 케이스를 자식이 직접 쓴다 (`tpx-cases` `two-kinds.md` 「화면에만 있는 입력 규칙」).
   **결과 파일을 안 쓰는 작성(이어 작성 · 사람 세션)은 미확정 줄을 더하지 않고** 본 규칙을 결과 요약(끝 보고)에 적는다 — `확인 필요` 항목 없이 더하면 화면 값 케이스가 확정으로 돈다(2026-10-11 PRD-F4-05)
   오류 문구 항목과 오류 추정 결과 항목은 새 줄을 만들지 않고 그것을 확인하는 줄의 출처에 번호를 더한다(`prd.md` §5) — 출처만 고치므로 tcId 는 그대로다
④ 돌려받은 **버튼 반응**을 화면마다 모은다(같은 화면이 두 묶음에 걸렸으면 하나로 · 머리 메뉴 · 바닥 링크는 `공통` 하나로). 기획서가 적지 않은 반응이 있는 화면은 「<화면> 버튼 반응」 `확인 필요` 항목 하나를 결과 파일에 더하고 원장 사본을 다시 만든 뒤,
   버튼마다 줄(`버튼 반응 — <화면>`)을 더해 `npm run ledger:number` 를 다시 돌리고 그 화면의 버튼 반응 케이스를 자식이 직접 쓴다(`tpx-cases` `two-kinds.md` 「버튼 반응 케이스」). 결과 파일을 안 쓰는 작성은 기획서가 적은 반응 줄만 더한다
   **CSS · XPath 까닭**은 용어 사전의 그 요소 줄에 붙인다
⑤ 차이 목록에 새 차이를 더했으면 `diffs.json` 도 같이 고친다 — **합친 뒤 관문 0 을 연 다음에는 표 · 차이에 줄을 더하지 않는다**(표를 쓴 직후의 「관문 0 일찍」은 세지 않는다 — 명세 §3.6 「★ 원장」 팬아웃)(11204 는 관문 뒤에 미확정 6건을 더해 전체 3회를 다시 돌았다)

## 6. 서브에이전트가 실패하거나 막혔을 때

- **그 묶음은 자식이 이어받아 직접 쓴다.** 이미 만든 파일은 지우지 않고 이어서 쓴다
- **다시 띄우는 것은 한 번까지다**(물러서기 포함 · 훅이 지킨다). 두 번째도 막히거나 훅이 거절하면 자식이 맡는다 — 같은 자리에서 서브에이전트를 거듭 띄우면 예산만 쓴다
- 막힌 사유는 결과 요약의 해당 칸(판정 불가·보류 · 못 읽은 자료)에 싣는다

## 7. 게임 애플리케이션 — 폰은 자식만, 서브에이전트는 찍어 둔 파일로 (2026-10-23 · GAME-F1-11)

종류 「게임」(프롬프트에 `--- 게임 화면 ---` 절)이면 위 규칙에 이것만 바꾼다. 폰이 한 대라 눌러 보기는 자식 하나만 한다(명세 도메인/게임 §3.10 「작성 — 한 바퀴」 5).

- **띄우기 전에 자식이 셋을 한다** — ① 상태 도우미 `helpers/game-state.helper.ts` 를 만든다(§2 공용 도우미와 같다 — `tpx-cases` `game.md` §3) ② 묶음마다 쓸 창을 `game.md` §6 대로 눌러 보고 `<자료 폴더>/game-probe/<창>.yml` 로 찍어 둔다 ③ 창 화면 객체 `pages/<창>.page.ts` 의 주인을 정한다 — 한 창은 한 묶음이다
- **묶음은 창으로 가른다** — §2 의 「화면」 자리가 창이다
- **§4 뼈대에서 바꾸는 줄**
  - 「먼저 Read 로 연다」에 `tpx-cases` 의 `game.md` · `5-stable.md` 를 더하고 `4-selector.md` 는 뺀다(웹 locator 규칙이다)
  - 화면은 `<자료 폴더>/game-probe/<맡은 창>.yml` · `game-crawl/` · `game-kept/` 다. **폰과 `control-cli` 를 부르지 않는다** — 탐침 세션 줄은 지운다. 이 파일들에 없는 주소가 필요하면 그 케이스는 쓰지 말고 「눌러 볼 것」(`창 · 찾는 오브젝트 · tcId`)으로 돌려준다
  - 지킬 것 8(locator 차례) 대신 — 주소는 오브젝트 이름, 겹치면 `/` 경로이고 찍어 둔 파일에서만 옮긴다. 좌표는 쓰지 않는다
  - 지킬 것 10 · 13 — 화면을 못 보므로 칸 한도는 재지 않고, 오류 추정 줄은 표의 「~해야 한다」대로 쓰고 결과는 `화면 안 봄` 으로 돌려준다
  - 지킬 것에 한 줄 — `smoke` 는 달지 않는다(자식이 합친 뒤 고른다)
  - 관문 — `authoring:check -- 보조` 는 그대로 돈다. **1번 돌려 보기 · 한 판과 입력값 두 번은 돌지 않는다** — 게임 케이스는 폰에서 돌고 폰은 메인만 만진다. 관문 결과에 `안 돌림(게임 케이스 — 메인이 폰에서 돌림)` 을 적는다. **보조는 상태 도우미 부르기(`authoring-game-state.ts`)도 하지 않는다** — 게임 서버 상태를 바꿔 메인의 눌러 보기와 겹치고, 부를 수 있는 것은 공용 `helpers/game-state.helper.ts` 뿐이다. draft 도우미는 메인이 합친 뒤 불러 본다. 「화면 입력 규칙」 · 「버튼 반응」은 「없음」이다
- **합칠 때** — 돌아온 「눌러 볼 것」을 모아 폰을 한 번 잡고 눌러 본 뒤(`game.md` §3 · §6) 그 주소로 해당 케이스를 자식이 직접 마무리한다. 못 찾은 주소는 보류다. 다 합친 뒤 폰에서 케이스마다 1번 돌린다(`tpx-cases` `game.md` §7 — `authoring:run -- 게임`)
