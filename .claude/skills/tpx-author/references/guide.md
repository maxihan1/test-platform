# 서비스 가이드 — 요약을 읽거나 새로 쓴다 (2026-10-17 · PRD-F11-04)

프롬프트의 `--- 서비스 가이드 ---` 절을 보면 이 파일을 따른다. 정본은 명세 `docs/spec/도메인/작성.md` §3.6 「★ 서비스 가이드」다.
가이드는 사람이 적은 서비스 소개 · 정책 · 프로젝트 규칙이다. 에이전트가 자료 폴더 `guide/` 에 받아 두었다 — 글 셋은 `guide/guide.md`, 첨부는 그 파일에 적힌 자리다.

## 1. 판 번호를 먼저 견준다

저장소 `docs/cases/<접두사>.guide.md` 의 첫 줄 `<!-- guide-version: N -->` 과 프롬프트의 판 번호를 견준다.

- **절이 「서비스 가이드가 없다(판 0)」이면 이 줄만 따르고 아래 둘은 건너뛴다** — 원본이 없다. 요약이 있으면 읽기만 하고 본문을 새로 쓰지 않는다(받지 못한 것일 수도 있다. 앞 판 요약을 지우면 안 된다). 요약이 없으면 만들지 않는다 — §5 「배운 것」을 쌓을 때만 만든다
- **같으면 요약만 읽는다** — `guide/` 원본을 열지 않는다(토큰을 아낀다). 요약 파일은 §5 「배운 것」 쌓기 말고는 고치지 않는다
- **다르거나 요약이 없으면** `guide/guide.md` 와 거기 적힌 첨부를 다 읽고 아래 2 대로 요약을 새로 쓴다

## 2. 요약을 새로 쓸 때

```
<!-- guide-version: <프롬프트의 판 번호> -->
# <접두사> 서비스 가이드 요약

## 서비스
<무슨 서비스인지 두세 줄>

## 테스트할 때 지킬 것
- <데이터 이름 규칙 · 결제 수단 · 열면 안 되는 화면 · 환경 · 계정 다루기처럼 케이스를 쓰고 돌릴 때 쓰는 것만, 한 줄에 하나>

## 배운 것
<앞 요약의 이 구획 그대로 — 줄 꼴은 §5>
```

- **「배운 것」 구획은 앞 요약에서 글자 하나 안 바꾸고 옮긴다** — 가이드 글자 하나를 고쳐도 판이 바뀐다. 그때마다 쌓은 줄이 지워지면 안 된다. 앞 요약이 없으면 빈 구획으로 둔다
- 원문을 베끼지 않는다. 케이스를 쓸 때 쓰일 것만 짧게 적는다
- **비밀번호를 옮기지 않는다** — `••••••` 는 에이전트가 가린 자리다. 계정 값도 적지 않는다. 역방향의 비밀번호 점검(`reverse.md` §2 「끝내기 직전」)을 돌릴 때 경로에 이 요약을 더한다. 에이전트도 올리기 전에 요약을 본다

## 3. 어떻게 쓰나 — 기대값의 근거가 아니다

- 무엇이 맞는 동작인지는 표준 기획서에서만 온다(`tpx-cases` R10). 가이드에 「주문 취소는 30분 안에만」이 있어도 표준 기획서에 없으면 기대값으로 쓰지 않는다 — 기대값이 어느 요구 번호에서 왔는지 거슬러 볼 수 없게 된다
- 가이드 · 「배운 것」은 서비스를 알고 테스트를 어떻게 돌릴지(데이터 이름 · 결제 수단 · 열 수 없는 화면 · 고르기 · 기다리기)에만 쓴다
- 표준 기획서 결과 파일 · 요구사항 표 · 케이스의 근거 칸에 가이드 문장을 적지 않는다
- **케이스를 쓰기 전에 「배운 것」 줄을 다 읽는다** — `RUN` 줄은 앞 작성이 사람에게 「화면이 맞음」 판정을 받은 까닭, `요령` 줄은 앞 작성이 알아낸 이 서비스 테스트 요령이다(§5). 같은 화면 · 같은 조작을 쓰면 그 줄대로 고르고 기다리고 데이터를 다루고 되돌린다. 보조에게 나눠 맡기면 그 줄을 보조 프롬프트에 싣는다(`fanout.md` §4)

## 4. 못 읽은 첨부

`guide/guide.md` 에 「못 읽었다」로 적힌 첨부는 결과 요약 「못 읽은 자료」에 `가이드 「<이름>」 — <까닭>` 으로 적는다.

## 5. 「배운 것」 쌓기 — 「화면이 맞음」 까닭과 테스트 요령

「배운 것」 구획에는 두 가지 줄이 쌓인다. 둘 다 **기대값 · 화면 글자 · 숫자 조건 · 비밀번호 · 계정 값을 적지 않는다** — 기대값은 표준 기획서 번호에서 온다(§3).
앞 줄은 고치거나 지우거나 차례를 바꾸지 않는다. 새 줄은 구획 끝에 더한다.

### 5.1 「화면이 맞음」 까닭 — 그 요청만 (2026-10-17 · PRD-F11-05)

`apply.md` §5 「화면이 맞음」을 끝낸 뒤 **건마다 한 줄**을 더한다.

```
- RUN <runId> · <tcId> — <케이스가 왜 틀렸나, 다음 작성이 피할 것 한 줄>
```

- **까닭은 케이스를 어떻게 썼나로 적는다** — 요소 고르기 · 기다리기 · 데이터 다루기. 「결제 완료 문구는 토스트로 3초만 뜬다 — 토스트가 사라지기 전에 본다」처럼
- 요구 문장만 틀렸고 케이스 쓰는 법에 배울 것이 없으면 `— 요구 <번호> 문장을 화면대로 고쳤다(케이스 쓰는 법은 그대로)` 로 적는다
- 같은 `RUN <runId> · <tcId>` 줄이 이미 있으면 더하지 않는다(다시 작성 · 이어하기)

### 5.2 테스트 요령 — 모든 작성 (2026-10-23 · PRD-F14-06)

작성 중에 이 서비스를 테스트하는 법을 새로 알아냈으면 **한 줄씩** 더한다. 같은 것을 다음 작성이 다시 부딪혀 알아내지 않게 하려는 것이다
(14638 메인이 보조에게 공용 서버 · 일회용 회원 · 되돌리기 · 토스트 안내를 손수 썼는데 남지 않아 다음 실행이 다시 알아냈다).

```
- 요령 · <데이터 | 기다리기 | 공용 서버 | 되돌리기> — <다음 작성이 그대로 따를 것 한 줄>
```

- **데이터** — 케이스가 쓸 자료를 어떻게 만들고 고르나. 「회원 정보를 바꾸는 케이스는 가입 도우미로 일회용 회원을 만들어 쓴다 — 기본 계정을 바꾸면 다른 케이스가 깨진다」
- **기다리기** — 무엇을 기다려야 화면이 준비되나. 「저장 뒤 목록은 다시 불러온 응답을 기다린 뒤 본다 — 바로 보면 앞 목록이 남아 있다」
- **공용 서버** — 남도 같이 쓰는 서버라 생기는 일. 「대상 서버 자료가 가끔 처음 상태로 돌아간다 — 앞 케이스가 만든 자료에 기대지 않는다」
- **되돌리기** — 바꾼 값을 어떻게 원래대로 두나. 「설정을 바꾼 케이스는 끝에 원래 값으로 돌려놓는다 — 실패해도 돌도록 정리 단계에 둔다」
- **쓰는 사람은 메인(자식)뿐이다** — 보조는 돌려주는 요약 「테스트 요령」에 적고(`fanout.md` §4), 메인이 합칠 때 골라 더한다
- **알아낸 그 자리에서 더한다** — 보조에게 줄 공통 안내를 쓸 때 · 보조 결과를 합칠 때 · 3회 빨강을 고치며 까닭을 알았을 때. 끝까지 미루면 도중에 멈춘 실행(한도 · 시간 초과)은 남기지 못한다. 이어하기는 같은 작업 폴더를 받아 그 줄을 물려받는다
- **끝내기 전에 한 번 더 본다** — 스스로 멈출 때(`SKILL.md` 「멈출 때」)도 같다. 이번 작성에서 두 번 이상 부딪혔거나 보조에게 일러 준 것 가운데 아직 안 적은 것을 더한다
- **한 작성에 많아야 다섯 줄** — 이 서비스에만 해당하고 다음에도 쓰일 것만 고른다. 도구 사용법(탐침 · 돌려 보기 명령 · 훅)은 적지 않는다 — 서비스가 아니라 하네스 문제다
- 뜻이 같은 `요령` 줄이 이미 있으면 더하지 않는다
- 요구 문장이 틀렸다고 본 것은 적지 않는다 — 그것은 「화면이 맞음」 판정(§5.1)이나 표준 기획서 몫이다

### 5.3 요약이 없을 때

판이 있으면 §2 대로 요약을 새로 쓰고 거기 더한다. 판 0 이면 아래 꼴로 만든다. 가이드가 생기면 판이 달라 §2 가 본문을 채우고 이 구획은 그대로 옮긴다

```
<!-- guide-version: 0 -->
# <접두사> 서비스 가이드 요약

## 배운 것
- 요령 · <갈래> — <한 줄>
```
