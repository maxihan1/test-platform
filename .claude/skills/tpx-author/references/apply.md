# tpx-author — 고친 요구만 다시 작성(반영)

프롬프트에 `--- 반영 ---` 절이 있으면 이 파일을 따른다. 없으면 상관없다.
**정본은 `docs/spec/도메인/작성.md` §3.6 「★ 표준 기획서」 「사람이 고칠 때」 「고친 요구만 다시 작성」이다.** 여기는 자식이 할 일만 적는다.

사람이 「PRD 관리」에서 요구를 고치고 「바뀐 요구 N건 테스트에 반영」을 눌렀다. **자료(기획서)는 없다** — 표준 기획서가 입력이다.
작업방은 main 판이라 **표 · 케이스가 이미 들어 있다.** 이 요청은 그중 바뀐 요구에 닿는 것만 고친다. 다른 줄 · 케이스는 손대지 않는다.

## 1. 맡을 것 — `apply.json`

절에 적힌 `apply.json` 이 이번 일 전부다. 에이전트가 기준 판(마지막 반영 때 판)과 지금 판을 견주고, main 표(지도 ①)에서 덮던 케이스를 찾아 적었다.

| 칸 | 뜻 |
|---|---|
| `다시씀[]` | 문장이 바뀐 요구. `옛문장` · `새문장` · `다시쓸종류`(정상 · 경계 · 예외 · UI 가운데) · `케이스`(그 번호를 덮던 tcId 와 축) |
| `새항목[]` | 덮는 케이스가 없는 번호 — 새로 더했거나, 바뀌었는데 표가 아직 안 덮었다 |
| `지움[]` | 지운 번호. `지울케이스` 는 그 번호만 덮던 것 · `남길케이스` 는 다른 요구도 덮는 것 |

요구 문장은 원장 사본의 `문장` 에서 읽는다(`prd.md` §5). `옛문장` 이 `null` 이면 기준 판에 없던 번호인데 표가 이미 덮고 있다(기준 판이 없거나 새로 더한 번호) — 그 번호의 케이스를 네 종류 모두 새 문장으로 고쳐 쓴다.

## 2. 다시씀 — 종류별로 고쳐 쓴다

- **`다시쓸종류` 에 든 축의 줄 · 케이스만 새 문장대로 다시 쓴다.** 정상 · UI 는 문장이 바뀌면 늘 든다. 경계 · 예외는 설계(경계 값 · 예외 기법)가 바뀌었을 때만 든다 — `npm run ledger:design -- <원장 사본>` 이 새 칸과 시험 값을 준다
- **덮던 케이스가 있으면 새로 만들지 않고 그 파일을 고친다.** 표 줄의 tcId 는 그대로 둔다 — 같은 칸이면 번호 명령이 같은 번호를 준다
- 새 설계에 칸이 생기면(예: 한도가 생겨 경계 칸) 표에 줄을 더하고 `npm run ledger:number` 로 번호를 받는다. 칸이 없어지면 그 줄을 지우고 케이스를 「지움」과 같은 방법으로 지운다(아래 3)
- **`다시쓸종류` 에 없는 축은 그대로 둔다.** 다만 그 케이스의 기대값(숫자 · 문구)이 새 문장과 정면으로 어긋나면 그 기대값만 고친다 — 고친 것은 결과 요약에 tcId 로 적는다
- 표 줄의 결과 칸 · 조작 칸은 새 문장대로 고친다. 케이스의 `verify` 는 표 결과 칸 그대로다(R11)

## 3. 새 항목 · 지움

- **새 항목** — 보통 작성처럼 표에 줄을 더하고 케이스를 쓴다(`SKILL.md` 2 · 4단계). 출처 칸은 그 번호다
- **지움** — `지울케이스` 는 케이스 파일을 지우고 표의 그 tcId 칸을 「제거함(<tcId>)」로 바꾼다(보류 케이스 제거와 같은 꼴). 다른 칸은 그대로 둔다
- `남길케이스` 는 파일을 남기고 **지운 번호만 출처로 단 표 줄**을 지운다. 그 줄의 확인(`verify` 단계)도 케이스에서 뺀다. 출처에 다른 번호도 적힌 줄은 지운 번호만 출처 칸에서 뺀다
- 지울 케이스를 쓰는 Page Object · Component 는 다른 케이스가 안 쓰면 같이 지운다
- 에이전트가 끝난 뒤 `지울케이스` 파일이 남았는지 보고 PR 본문 머리에 경고로 띄운다 — 못 지운 까닭이 있으면 결과 요약에 적는다

## 4. 관문은 전부

- 관문 0 은 원장 절의 명령 그대로다 — **전체 원장**을 main 표 + 이번에 고친 줄로 맞댄다. 맡지 않은 번호도 그대로 덮여 있어야 초록이다
- 관문 1~4 는 `SKILL.md` 그대로다 — 폴더 전체를 돈다
- 결과 요약(`SKILL.md` 「결과 요약」)에 한 줄을 더한다 — `반영: 다시 씀 a(고친 케이스 b) · 새 항목 c(새 케이스 d) · 지움 e(지운 케이스 f · 남긴 케이스 g)`

## 5. 화면이 맞음 — `apply.json` 에 `화면이맞음` 칸이 있을 때

**정본은 `docs/spec/도메인/작성.md` §3.6 「화면이 맞음」이다.** 여기는 자식이 할 일만 적는다.
사람이 실행 결과의 실패 카드를 보고 「화면이 맞음」을 눌렀다 — 케이스가 기대한 요구가 틀렸고 화면이 맞다는 판정이다.
칸은 `runId`(그 실행) · `tcId`(실패한 케이스) · `env`(그 실행의 대상 서버) · `번호들[]`(그 케이스가 덮는 번호마다 지금 판 `문장` 과 그 번호를 덮던 `케이스`)이다.
§1~§3 의 다시씀 · 새 항목 · 지움이 같이 있으면 그것도 한다 — 반영과 한 요청이다.

1. **그 케이스를 `env` 서버에서 다시 돌려 실패한 확인과 화면을 본다.** 주소는 프롬프트 대상 서버 목록의 `env` 줄이다. 목록에 없으면 절의 ⚠️ 줄대로 요구를 고치지 않는다.
   케이스 파일은 `tests/<폴더>` 아래 `<tcId>.spec.ts` 다. 관문 3 꼴로 한 번만 돈다.

   ```bash
   PLATFORM_BASE_URL=<env 주소> npx playwright test <케이스 파일> --project=desktop --workers=1 --reporter=line > /tmp/sr.log 2>&1; echo "EXIT=$?"
   ```

   로그인 같은 앞 단계에서 먼저 멈춰 그 확인까지 못 가면 `tpx-cases` §4 화면 탐침으로 그 화면을 직접 연다.
   그 실행 뒤 배포로 화면이 바뀌었을 수 있다 — 지금 화면을 기준으로 하고 다르면 결과 요약에 적는다
2. **화면과 어긋난 번호만 결과 파일(`out/prd.json` — 폴더가 없으면 만든다)에 그 번호로 적는다.** 꼴은 `prd.md` §2 그대로다(`items` 만 · 그 번호의 `reqId` 를 단다). `번호들` 밖의 번호 · 새 항목 · `removed` 는 적지 않는다 — 에이전트가 버린다.
   `text` 는 화면대로 고치고 숫자 · 조건 낱말은 화면 글자 그대로다(`prd.md` §3 의 2). `feature` 는 지금 판 것을 그대로 둔다.
   근거는 화면 근거 하나로 바꾼다 — `{ "from": "화면", "ref": "<화면 주소>", "quote": "실행 RUN <runId> 실패 — 사람이 화면이 맞다고 판정" }`. `status` 는 `CONFIRMED` 로 적는다
3. **`npm run prd:ledger -- <자료 폴더>` 로 원장 사본을 다시 만든다** — 자료 폴더는 절의 결과 파일 경로에서 `out/prd.json` 을 뗀 곳이다.
   근거가 화면뿐이라 사본에는 그 번호가 `확인필요` 로 보인다. **그래도 미확정 표시 · `unconfirmed` 를 달지 않는다** — 사람이 판정했고 올리면 서버가 `확정` 으로 단다
4. **고친 번호를 덮는 케이스를 §2 「다시씀」 규칙대로 고쳐 쓴다.** 덮던 케이스는 `번호들[].케이스` 다. 옛 문장은 지금 판 `문장`, 새 문장은 결과 파일에 적은 `text` 다.
   다시 쓸 종류는 `npm run ledger:design -- <원장 사본>` 을 결과 파일을 쓰기 전과 원장을 다시 만든 뒤 한 번씩 돌려 그 번호의 설계(경계 값 · 예외 기법)를 견줘 정한다 — 정상 · UI 는 늘, 경계 · 예외는 설계가 바뀌었을 때만. 표 줄의 tcId 는 그대로다
5. **요구는 맞고 케이스만 틀렸으면**(요소 주소 · 기다리기 · 데이터 같은) 결과 파일에 적지 않고 케이스만 고친다. 에이전트는 고친 번호가 없으면 표준 기획서를 올리지 않는다
6. **결과 요약에 한 줄을 더한다** — `화면이 맞음: RUN <runId> · <tcId> · 다시 돌림 <EXIT 값> · 고친 요구 <번호들 또는 없음> · 고친 케이스 <tcId 들>`. 화면이 실행 때와 달랐으면 그 사실도 적는다

관문 0~4 는 §4 「관문은 전부」 그대로 돈다. 에이전트는 결과 파일에서 `번호들` 의 항목만 골라 지금 판에 합쳐 올린다 — 못 올리거나 비밀값이 들면 올리기 거절이다.
