# /tpx-author

작성 에이전트 전용 체인. 에이전트는 서버의 `author` 컨테이너가 기본이고 맥은 대체다.
**`/tpx` 네 단계를 타지 않는다** — 끝 검사는 관문 넷과 겹치고
병합은 사람이 화면에서 누르므로 자식이 할 일이 없다 (2026-09-23 첫 한 바퀴 실측,
`docs/archive/plans/2026-09-23-작성-전용체인.md`).

**에이전트 스크립트가 작업방을 만들고, 자식은 파일만 남기고, 에이전트 스크립트가 commit·push·PR 을 한다.**
정본 흐름은 `docs/spec/도메인/작성.md` §3.6 「작성 에이전트는 전용 체인이다」다.

## 입력 — 에이전트가 프롬프트로 준다

- **자료 목록** — 파일 경로와 원래 이름, 피그마 주소
- **tcId 접두사** — 서비스 단위 (`tpx-cases` §1 의 2)
- **테스트 폴더** — `tests/<폴더>`. 서비스 설정 `testsDir` 에서 온다.
  새 서비스면 폴더가 아직 없을 수 있다 — 그때는 만든다. 새 tcId 는 종류별로 매긴다. UI 는 `<접두사>-UI-NNN` · 기능은 `<접두사>-FN-NNN` 이다 (`two-kinds.md` R17)
- **대상 화면 주소** — 없으면 아래 「멈출 때」를 따른다
- **역방향 절**(`--- 역방향 ---`) — 있으면 **`references/reverse.md` 를 Read 로 열고 그대로 따른다.**
  실제 화면과 대조 · 화면만 · 계정 다루기 · 훑기 허용 목록 · `diffs.json` 이 거기 있다 (2026-09-26).
  훑을 화면이 넷 이상이면 `references/scan-fanout.md` 대로 나눠 훑는다 (2026-10-03)
- **이어하기 절**(`--- 이어하기 ---`) — 있으면 **`references/resume.md` 를 Read 로 열고 그대로 따른다.**
  앞 실행이 멈춘 작업방이다. 남은 표·케이스를 버리지 않고 남은 것만 한다 (2026-09-28)
- **이어 작성 절**(`--- 이어 작성 ---`) — 있으면 **`references/continue.md` 를 Read 로 열고 그대로 따른다.**
  반영된 앞 요청이 남긴 요구(「다음 요청」 · 「빠짐」)만 맡는 새 요청이다. 남은 번호 전체는 절에 적힌 `continue.json` 에 있다 (2026-09-30)
- **원장 절**(`--- 원장 ---`) — 표준 기획서 항목으로 만든 요구 목록의 사본 경로 · 수 · 관문 0 명령. **케이스는 표준 기획서만 읽는다** —
  출처 칸에는 표준 기획서 번호(새 항목은 임시 번호)를 적는다(`references/prd.md` §5 · 2026-10-10 PRD-F3-02). 항목이 없으면 `원장 없음 — <까닭>` 한 줄이다
- **표준 기획서 절**(`--- 표준 기획서 ---`) — 있으면 **`references/prd.md` 를 Read 로 열고 그대로 따른다.**
  지금 판 파일 · 결과를 쓸 곳 · 원본 원장 · 원장 다시 만들기 명령이 있다. 자료를 표준 기획서 항목으로 옮겨 결과 파일에 쓰고 원장 사본을 다시 만든다 — 대조 · 올리기 · 임시 번호 바꿔 적기는 에이전트가 한다 (2026-10-10)

## 선행 읽기

**없음.** `tpx-cases` 를 따라 읽는 것 말고는 여는 것이 없다. `/tpx` 컨트롤러와 명세 장을 싣지 않는다.

## 하지 않는 것

에이전트 스크립트가 전부 한다. 자식이 하면 그 commit·push 와 부딪히거나 턴이 먼저 끝나 멈춘다.

- **git 명령 전부** — commit·branch·checkout·stash·push 포함
- **gh 명령 전부** — PR 만들기·ready·병합
- **`/tpx` 와 다른 체인 스킬 호출**
- **Bash 의 `run_in_background`** — 모든 명령은 앞에서 끝까지 기다린다. **Agent 도구도 같다** — 서브에이전트는 앞에서 띄우고 끝날 때까지 기다린다
- **AskUserQuestion** — 답할 사람이 없다. 사람은 PR 본문에서 표를 본다
- **작업 폴더 밖 파일 수정** — 바꾸는 것은 `tests/<폴더>/*.spec.ts` · `tests/<폴더>/pages/*.page.ts` · `tests/<폴더>/components/*.component.ts` 와 `docs/cases/<접두사>.md` 뿐이다.
  표준 기획서 절이 있으면 자료 폴더의 결과 파일(`out/prd.json`)과 원장 사본(`npm run prd:ledger` 가 쓰는 `ledger.json`)도 바뀐다 — 저장소 밖이라 커밋되지 않는다.
  다른 파일이 바뀌면 에이전트 스크립트가 push 를 거부한다. `tests/` · `docs/` 밖에 **새로** 만든 파일(실행 로그 등)은 에이전트가 지우고 올린다 —
  필요한 출력은 `$TMPDIR` 에 둔다 (2026-10-03, 11203 이 `$로그` 파일 하나로 멈췄다)

## 절차 — `tpx-cases` 를 이 순서로 따른다

`tpx-cases` 의 규칙(R1~R16 · §6 관문 전부(관문 0 포함) · 종료 조건)을 **그대로** 쓴다. 이 스킬이 덮어쓰는 것은
아래 적은 자리뿐이다. `tpx-cases` 가 git·초안 PR·끝 검사를 전제로 적은 문장은 **이 스킬이 이긴다.**

**각 단계에 들어가기 전에 적힌 파일을 Read 로 연다** — 경로는 `.claude/skills/tpx-cases/` 아래다.

**단계 표지 (2026-10-03 · AUT-F3-21)** — 단계에 들어갈 때 글 한 줄로 `[단계] <이름>` 을 말한다. 에이전트가 그 줄을 본 순간의 시각으로
단계마다 걸린 시간을 재 로그와 PR 본문에 남긴다 — 어느 단계가 가장 긴지 보고 다음에 나눌 곳을 정한다.
이름은 아래 그대로 쓴다(다른 이름은 다른 단계로 잡힌다). 해당 없는 단계는 건너뛴다. **결과 요약과 같은 메시지에 넣지 않는다** — 요약 앞 메시지로 먼저 말한다.
`자료 읽기` · `표준 기획서` · `요구사항 표` · `관문 0 일찍` · `selector` · `케이스 작성` · `팬아웃 시작 — 묶음 <N>` · `팬아웃 뒤 합치기` · `관문 0` · `관문 1` · `관문 2` · `관문 3` · `관문 4` · `표 되채우기` · `결과 요약`.
역방향은 여기에 `화면 크롤링` · `화면 훑기` · `훑기 나누기 — 묶음 <N>` · `차이 목록` · `비밀번호 점검` 을 더한다(`references/reverse.md`). 서브에이전트는 표지를 말하지 않는다

**진행 메모 (2026-10-04 · 이 절이 정본)** — 프롬프트가 메모 경로를 주면 단계 표지를 말할 때마다 그 파일을 **통째로 고쳐 쓴다.** 멈췄다 이어받는 자식은 대화 없이 이 파일과 남은 파일만 받는다.
칸 넷 — `## 지금 단계` · `## 끝낸 것`(표 · 케이스 · 묶음별 진도) · `## 정한 것과 이유`(파일에 안 남는 판단 — 묶음 가르기 · 제외 까닭 · 고른 locator 방식) · `## 다음 할 일`(바로 다음 한두 가지 · 이미 읽은 문서). 짧게 — 다시 읽는 비용이 곧 한도다. 경로는 트리나 자료 폴더 기준 **상대 경로**로 적는다 — 넘겨받으면 작업 폴더 이름(`author-<번호>`)이 바뀐다.
**비밀번호 · 토큰 값을 적지 않는다.** 관문 통과 여부는 적어도 이어받는 쪽이 믿지 않는다(`references/resume.md`). 서브에이전트는 메모를 쓰지 않는다

1. **§1 입력 확인** — `references/1-input.md`. 「입력은 자료 목록이다」대로 자료를 전부 읽는다.
   프롬프트에 표준 기획서 절이 있으면 다 읽은 뒤 이 스킬의 `references/prd.md` 대로 표준 기획서로 옮기고 원장 사본을 다시 만든 뒤 2 로 간다.
   **2 부터는 표준 기획서만 읽는다** — 원본 자료를 다시 열어 표를 쓰지 않는다(`references/prd.md` §5)
2. **§2 요구사항 표** — `references/2-requirements.md`. `docs/cases/<접두사>.md` 에 쓴다. **중간에 멈추지 않는다**
   프롬프트의 원장 절을 먼저 읽고 사본을 연다. 원장의 번호(표준 기획서 번호)마다 케이스 줄 또는 「제외」 한 줄을 둔다(같은 파일 「원장」). 표를 다 쓰면 관문 0 을 `--tests` 없이 한 번 돌려 빠짐을 일찍 본다
   **경계 · 예외 칸은 설계 목록이 정한다** (2026-10-05 · 정본 도메인/작성 §3.6 「설계 기법」) — 표를 쓰기 전에 `npm run ledger:design -- <원장 사본>` 으로 요구마다 칸과 시험 값을 보고 그 칸을 다 쓴다.
   목록의 칸은 빼지 않는다. 기법별로 줄 쓰는 법 · 0건 · 「설계 거절」은 `references/test-design.md`. 기능 케이스의 `techniques` 도 같은 파일 「기법 표시」대로 적는다
   **오류 추정 점검 목록 줄도 이때 더한다** (2026-10-10) — 기획서가 결과를 안 적은 빈 값 · 공백만 · 두 번 누르기 · 남의 것 · 없는 주소 · 서버 실패. 꼴은 `two-kinds.md` 「오류 추정 점검 목록」
   **tcId 칸은 손으로 정하지 않는다** (2026-10-04 · 정본 도메인/작성 §3.6 「칸과 번호」) — 케이스 하나는 칸(요구 × 갈래 × 축 × 상태) 하나이고 번호는 명령이 매긴다.
   표를 다 쓰면 관문 0 일찍보다 먼저 `npm run ledger:number -- <원장 사본> docs/cases/<접두사>.md` 를 돌린다. 줄을 더하면 다시 돌린다 — 이미 매긴 번호는 안 바뀐다.
   미확정 · 보류 · 모킹 · 오류 추정 줄은 출처 칸에 표시를 단다(`wording.md` 「출처 칸의 상태 표시」) — 안 달면 정식 줄과 한 케이스로 묶인다. main 표에 원래 있던 줄은 고치지 않는다(명령도 안 건드린다).
   종료 코드 2(칸 재료 없음 — 기준 표를 못 읽었다)면 지금처럼 종류별로 가장 큰 번호 다음부터 매긴다
   쓰기 전에 `references/korean-ai-tells.md` 를 읽는다 — 표 문장부터 AI 티 없이 쓴다. 케이스 코드의 한글(절차 제목 · 칸 설명 · 판정 문장)도 같다
3. **§3 내부 게이트는 건너뛴다** — 표를 그대로 확정한다. 게이트가 물었을 것
   (합친 줄의 `name` · 자료 어긋남으로 `판정 불가` 가 된 줄)은 **결과 요약에 싣는다.** 사람이 PR 본문에서 본다.
   자료 어긋남 줄은 어긋난 값을 기본값 없는 칸으로 비운 `held: '판정 불가 — 자료 어긋남: <둘>'` 케이스로 쓴다 — 사람이 작성 화면에서 고른다
   무엇을 실을지는 `references/3-gate.md` 를 읽고 정한다
4. **§4 selector 확정 → §5 케이스 작성** — `references/4-selector.md` → `references/5-writing.md`.
   케이스는 UI Test 와 Functional Test 두 갈래다(R17). 예외 · 경계는 근거 넷에 적힌 것만 만들고(R18) 설계 목록의 칸은 빼지 않는다(2단계). 동작 요구는 Functional 케이스로 덮는다(R19).
   UI Test · Functional Test 둘 다 Page Object 를 쓴다(`two-kinds.md` 「Page Object」).
   §4 에서 기획서에 없는 화면 입력 규칙을 보면 표에 미확정 줄을 더해 케이스로 쓴다(`two-kinds.md` 「화면에만 있는 입력 규칙」).
   표준 기획서 절이 있으면 같은 규칙과 화면 오류 문구를 결과 파일에 `확인 필요` 항목으로 먼저 더하고 원장 사본을 다시 만든 뒤, 그 줄의 출처 칸에 새 항목의 임시 번호를 적는다(`references/prd.md` §4 · §5)
   **화면 묶음이 둘 이상이고 케이스가 8건 이상이면** 이 스킬의 `references/fanout.md` 대로 서브에이전트에게 나눠 맡긴다 (2026-09-30)
5. **§6 관문** — `references/6-gates.md`. 원장 대조(관문 0) · 형식 · 표 대조 · 3회 실행 · 일부러 부수기.
   **팬아웃했으면 관문 3 은 `references/fanout.md` §5 의 분담이다** — 서브에이전트가 자기 파일 3회를 결과 파일로 남기고, 자식은 끝에 폴더 전체 3회를 **한 번**만 돈다. 그 뒤 고친 것은 그 파일과 그 Page Object · Component 를 쓰는 케이스만 3회
6. **§7 표 되채우기** — `references/7-finish.md`. 1~3 만. **4 커밋은 하지 않는다** (에이전트 스크립트가 한다)

관문 0·1 명령은 `tpx-cases` §6 과 같다. **관문 3 은 다르다** — 결과 파일을 에이전트가 확인한다(아래). 파이프로 넘기지 않는다. 관문 0 의 원장 사본 경로는 원장 절에 있다.

```bash
npm run check:ledger -- <원장 사본> docs/cases/<접두사>.md --tests tests/<폴더> --agent > /tmp/cl.log 2>&1; echo "EXIT=$?"
npm run typecheck   > /tmp/tc.log 2>&1; echo "EXIT=$?"
npm run check:tests > /tmp/ct.log 2>&1; echo "EXIT=$?"
PLAYWRIGHT_JSON_OUTPUT_FILE="$AUTHORING_GATE3_DIR/gate3-final-1.json" npx playwright test tests/<폴더> --project=desktop --workers=1 --repeat-each=3 --reporter=line,json > /tmp/pw.log 2>&1; echo "EXIT=$?"
```

**끝의 전체 3회 — 에이전트가 결과 파일로 확인한다** (2026-10-03 · 도메인/작성 §3.6).
- 환경 변수 `AUTHORING_GATE3_DIR` 에 `gate3-final-<번호>.json` 으로 남긴다. 에이전트가 하나씩(`--workers=1`) · 파일마다 데스크톱 3회 · 실패 0 · 마지막 수정 뒤 실행인지 보고, 어기면 PR 본문에 ⚠️ 경고를 싣는다
- **명령 하나는 최대 10분이다.** 케이스가 많아 넘을 것 같으면 파일을 나눠 **하나씩 차례로** 돈다 — 덩어리마다 `-1` · `-2` … 번호를 올리고 모든 파일을 한 번씩 덮는다. `--workers` 를 올리거나 일부만 돌리지 않는다(MKT 11208 이 그래서 케이스끼리 얽힌 실패를 못 봤다)
- 그 뒤 케이스나 Page Object 를 고쳤으면 고친 파일과 그것을 쓰는 케이스를 다시 돌려 새 번호로 남긴다 — 에이전트는 파일마다 그 파일이 든 가장 늦은 결과로 본다
- **관문 4(일부러 부수기)는 끝의 전체 3회 앞에 돈다.** 부수려고 파일을 고쳤다 되돌리면 수정 시각이 바뀐다 — 끝의 전체 3회가 마지막이어야 되돌린 판을 확인하고 경고도 안 붙는다.
  기대값만 바꿀 때는 파일을 고치지 말고 `PLATFORM_PARAMS` 로 주입한다

## 멈출 때

`tpx-cases` 가 「멈추고 묻는다」고 적은 자리에서는 **묻지 않고 거기서 끝낸 뒤 결과 요약에 사유를 싣는다.**

- **피그마를 못 읽었다** — `tpx-cases` §1 의 3 대로 표에 `못 읽음: <주소> — <에러 첫 줄>` 을 적고 **§3 이후로 가지 않는다**
- **대상 화면 주소가 없다** — selector 를 확정할 수 없으므로 표까지만 쓰고 멈춘다
- **역방향인데 로그인 직전 출처가 대상 서버와 다르다** — 입력하지 않고 그 화면을 멈춘다 (`references/reverse.md` §2)
- **판정 불가 · 보류 · 모킹 필요로 빼려 한다** — 먼저 `tpx-cases` §5 「보류 · 모킹 필요로 빼기 전에」 표를 위에서부터 대 본다.
  화면 크기 · 늦춘 응답 · 가짜 응답 · 권한 · 계정 · 만들고 지우기로 풀리면 정식 케이스다. 결과 요약에 모킹한 케이스를 적는다
- **관문 0 이 빨강** — 로그의 `빠짐:` · `형식 오류:` 대로 **표를 고친다.** 케이스를 만들거나, §5 「빼기 전에」 표로도 안 풀리면 맞는 종류로 「제외」 한 줄.
  **`다음 요청` · `사람이 뺌` 은 자식이 새로 못 쓴다**(`다음 요청` 은 2026-10-04 부터 — 1차 MKT 가 「필수를 먼저 덮었다」며 9개를 뺐다. 범위는 AI 가 줄이지 않는다). 관문 0 이 형식 오류로 잡는다.
  main 표에 이미 있던 줄은 에이전트도 인정한다 — 지우거나 고치지 않는다. 다른 제외 종류로 옮겨 적지도 않는다 — 에이전트가 종류별 개수를 PR 본문 머리에 싣고 사람이 본다.
  다 못 덮으면 빠진 채 끝낸다. 관문 0 을 넘기지 못한 채 끝내도 올라가지만(2026-09-30 게이트 1 — 거절하지 않는다) 셈 · PR 본문 머리 · 요청 화면에 「빠짐」으로 남고 남은 요구로 이어 작성이 맡는다.
  `칸 번호 어긋남:` 줄은 `npm run ledger:number` 를 다시 돌리고 케이스 파일 이름 · `tcId` 를 표에 맞춘다.
  `설계 칸 빠짐:` · `설계 거절 형식 오류:` 줄은 `tpx-cases` `references/test-design.md` 「관문 0 의 설계 줄과 대처」대로 표를 고친다.
  `기법 어긋남:` 줄은 같은 파일 「기법 표시」대로 케이스 파일의 `techniques` 를 고친다
- **케이스가 같은 이유로 3회 빨강** — `tpx-cases` §6 종료 조건대로 그 케이스에 `held: '보류 — <에러 첫 줄>'` 을 달고 나머지는 계속 간다. 화면이 오류 추정 기준을 어겨 빨간 것은 빼고(§6 종료 조건 4)
- **같은 관문이 같은 이유로 3번 실패** — 더 고치지 않는다. 그 관문을 결과 요약에 `실패 — <이유 한 줄> (같은 이유 3번)` 으로 적고 남은 단계로 가서 끝낸다 (2026-10-03 사용자).
  전체 시간 제한은 없다 — 출력이 20분 없을 때만 멈춘다(도메인/작성 §7 TIMEOUT). 그래서 헛도는 것을 이 규칙이 막는다. 시간에 쫓긴다고 관문을 줄이지 않는다

## 끝내기 전에

**띄운 명령이 전부 끝났는지 확인하고 끝낸다.** 첫 한 바퀴에서 자식이 background 검사를 기다린다며
턴을 먼저 끝내 에이전트(그때는 맥)가 멈췄다 (2026-09-23).

**역방향이면 비밀번호 점검을 돌린다** — `references/reverse.md` §2 「끝내기 직전」. 찾으면 고치고 깨끗할 때까지 다시 돈다.
안 하면 다 만든 뒤 올리기에서 걸려 요청이 멈춘다 (2026-09-28, 5873).

## 결과 요약 — 마지막에 표준출력에 찍는다

에이전트 스크립트가 이것을 PR 본문에 싣는다. **관문 3 의 3회 실행 결과가 병합 근거다** — CI 가벼운 길은 케이스를 돌리지 않는다.

```
요구사항 N줄 → 케이스 M건 · 합친 것 J건 · 보류 K건(케이스로 씀) · 표만 L건
원장: <관문 0 로그의 `원장:` 줄 그대로 / 원장 없음 — <까닭>>
관문 0 원장 대조: EXIT=<값>
관문 1 형식: EXIT=<값>
관문 2 표 대조: <일치 / 어긋난 줄>
관문 3 3회 실행: <pw.log 의 마지막 요약 줄 그대로 — 예: 9 passed> · EXIT=<값>[ · 묶음별 <묶음: gate3 결과 파일의 expected/unexpected/flaky> · 끝 뒤 다시 돈 파일 <N건 · 요약 줄>]
팬아웃: <안 함 / 훑기 묶음 N · 케이스 묶음 N(묶음별 tcId 수) · 물러섬 <없음 / 동시 둘로>>
관문 4 부수기: <무엇을 바꿨나 · 어느 문장이 빨개졌나>
합친 것: <tcId · 합친 name 한 문장 · 어느 요구 줄들인지>
판정 불가·보류: <tcId — held 사유 한 줄씩 · 표만은 요구 번호 — 사유>
오류 추정: <줄 N · 케이스 M건 · 뺀 줄 K(해 볼 수 없음) · 기준 어김(빨간 채로 둠) tcId — 무엇을 어겼나 / 없음>
못 읽은 자료: <주소나 파일 — 에러 첫 줄 / 없음>
표: docs/cases/<접두사>.md
```

멈춘 경우에도 이 모양으로 찍고, 못 간 관문은 `안 돌림(<사유>)` 으로 적는다.
**`원장:` 줄은 참고용이다** — PR 본문 머리의 셈은 에이전트가 메모리의 원장과 올릴 트리로 직접 센다. 자식의 요약을 안 믿는다 (2026-09-30).
