# /tpx-author

작성 에이전트 전용 체인. 에이전트는 서버의 `author` 컨테이너가 기본이고 맥은 대체다.
**`/tpx` 네 단계를 타지 않는다** — 끝 검사는 관문 넷과 겹치고
병합은 사람이 화면에서 누르므로 자식이 할 일이 없다 (2026-09-23 첫 한 바퀴 실측,
`docs/archive/plans/2026-09-23-작성-전용체인.md`).

**에이전트 스크립트가 작업방을 만들고, 자식은 파일만 남기고, 에이전트 스크립트가 commit·push·PR 을 한다.**
정본 흐름은 `docs/spec/도메인/작성.md` §3.6 「작성 에이전트는 전용 체인이다」다.

## 입력 — 에이전트가 프롬프트로 준다

- **자료 목록** — 파일 경로와 원래 이름, 피그마 주소
- **tcId 접두사** — 서비스 단위 (`tpx-cases` §1 의 2)
- **테스트 폴더** — `tests/<폴더>`. 서비스 설정 `testsDir` 에서 온다.
  새 서비스면 폴더가 아직 없을 수 있다 — 그때는 만든다. 새 tcId 는 종류별로 매긴다. UI 는 `<접두사>-UI-NNN` · 기능은 `<접두사>-FN-NNN` 이다 (`two-kinds.md` R17)
- **대상 화면 주소** — 없으면 아래 「멈출 때」를 따른다
- **역방향 절**(`--- 역방향 ---`) — 있으면 **`references/reverse.md` 를 Read 로 열고 그대로 따른다.**
  실제 화면과 대조 · 화면만 · 계정 다루기 · 훑기 허용 목록 · `diffs.json` 이 거기 있다 (2026-09-26).
  훑을 화면이 넷 이상이면 `references/scan-fanout.md` 대로 나눠 훑는다 (2026-10-03)
- **이어하기 절**(`--- 이어하기 ---`) — 있으면 **`references/resume.md` 를 Read 로 열고 그대로 따른다.**
  앞 실행이 멈춘 작업방이다. 남은 표·케이스를 버리지 않고 남은 것만 한다 (2026-09-28)
- **이어 작성 절**(`--- 이어 작성 ---`) — 있으면 **`references/continue.md` 를 Read 로 열고 그대로 따른다.**
  반영된 앞 요청이 남긴 요구(「다음 요청」 · 「빠짐」)만 맡는 새 요청이다. 남은 번호 전체는 절에 적힌 `continue.json` 에 있다 (2026-09-30)
- **반영 절**(`--- 반영 ---`) — 있으면 **`references/apply.md` 를 Read 로 열고 그대로 따른다.**
  「PRD 관리」에서 고친 요구만 테스트에 넣는 요청이다. 자료가 없고 바뀐 번호 · 덮던 케이스 · 다시 쓸 종류 · 지울 케이스는 절에 적힌 `apply.json` 에 있다 (2026-10-11)
- **원장 절**(`--- 원장 ---`) — 표준 기획서 항목으로 만든 요구 목록의 사본 경로 · 수 · 관문 0 명령. **케이스는 표준 기획서만 읽는다** —
  출처 칸에는 표준 기획서 번호(새 항목은 임시 번호)를 적는다(`references/prd.md` §5 · 2026-10-10 PRD-F3-02). 항목이 없으면 `원장 없음 — <까닭>` 한 줄이다
- **표준 기획서 절**(`--- 표준 기획서 ---`) — 있으면 **`references/prd.md` 를 Read 로 열고 그대로 따른다.**
  지금 판 파일 · 결과를 쓸 곳 · 원본 원장 · 원장 다시 만들기 명령이 있다. 자료를 표준 기획서 항목으로 옮겨 결과 파일에 쓰고 원장 사본을 다시 만든다 — 대조 · 올리기 · 임시 번호 바꿔 적기는 에이전트가 한다 (2026-10-10)
- **서비스 가이드 절**(`--- 서비스 가이드 ---`) — 늘 온다. **`references/guide.md` 를 Read 로 열고 그대로 따른다.**
  사람이 적은 서비스 사정이다. 요약 `docs/cases/<접두사>.guide.md` 의 판이 같으면 요약만 읽고, 다르면 원본을 읽고 요약을 새로 쓴다(판 0 은 빼고 — `guide.md` §1). 요약의 「배운 것」은 판 0(가이드 없음)이어도 읽는다. 작성 중 알아낸 테스트 요령은 그 구획에 쌓는다(`guide.md` §5.2 · 2026-10-23). **기대값의 근거가 아니다** (2026-10-17)

- **API 문서 절**(`--- API 문서 ---`) — 있으면 **`tpx-cases` 의 `references/api.md` 를 Read 로 열고 그대로 따른다.**
  종류 「API」 애플리케이션이다. 화면 훑기 · 요소 찾기를 건너뛰고 판 원문(`api-doc.json`)과 표준 기획서로 기능 케이스만 쓴다. 원장 사본의 `API <메서드> <경로> <코드>` 줄도 덮는다 (2026-10-21)
- **앱 화면 절**(`--- 앱 화면 ---`)은 **`references/app.md`**, **게임 화면 절**(`--- 게임 화면 ---`)은 **`references/game.md`** 를 Read 로 열고 그대로 따른다.
  폰에서 켠 직후 첫 화면 하나, 또는 읽지 못한 까닭이다. 팜이 붙었으면 앱은 `appium-cli`(`app.md` §5), 게임은 `control-cli` 로 눌러 가며 읽고 창을 훑는다 — 잡은 폰은 꼭 놓는다. 게임은 게임 지도도 쓴다(`game.md` §5). 주소를 고르는 데만 쓴다. **기대값의 근거가 아니다** (2026-10-19 · 2026-10-20 · 게임 2026-10-23)

## 선행 읽기

**없음.** `tpx-cases` 를 따라 읽는 것 말고는 여는 것이 없다. `/tpx` 컨트롤러와 명세 장을 싣지 않는다.

## 하지 않는 것

에이전트 스크립트가 전부 한다. 자식이 하면 그 commit·push 와 부딪히거나 턴이 먼저 끝나 멈춘다.

- **git 명령 전부** — commit·branch·checkout·stash·push 포함
- **gh 명령 전부** — PR 만들기·ready·병합
- **`/tpx` 와 다른 체인 스킬 호출**
- **Bash 의 `run_in_background`** — 모든 명령은 앞에서 끝까지 기다린다. **Agent 도구도 같다** — 서브에이전트는 앞에서 띄우고 끝날 때까지 기다린다
- **AskUserQuestion** — 답할 사람이 없다. 사람은 PR 본문에서 표를 본다
- **다른 서비스의 테스트 폴더 읽기 · 베끼기** — 프롬프트의 테스트 폴더 말고 `tests/<다른 폴더>` 의 Page Object · 부품 · 도우미를 열거나 복사해 출발하지 않는다.
  같은 앱처럼 보여도 고객사 서비스끼리는 다른 제품이라 틀린 부품이 섞인다(R8 MKF 가 `tests/mku` 를 복사했다 · PRD-F9-32). 부품은 이번 서비스 화면에서 새로 만든다. 본보기 `tests/demo` · `tests/todo` 는 읽어도 된다
- **작업 폴더 밖 파일 수정** — 바꾸는 것은 `tests/<폴더>/*.spec.ts` · `tests/<폴더>/pages/*.page.ts` · `tests/<폴더>/components/*.component.ts` · `tests/<폴더>/helpers/*.helper.ts` 와 `docs/cases/<접두사>.md` · 가이드 요약 `docs/cases/<접두사>.guide.md` 뿐이다.
  표준 기획서 절이 있으면 자료 폴더의 결과 파일(`out/prd.json`)과 원장 사본(`npm run prd:ledger` 가 쓰는 `ledger.json`)도 바뀐다 — 저장소 밖이라 커밋되지 않는다.
  다른 파일이 바뀌면 에이전트 스크립트가 push 를 거부한다. `tests/` · `docs/` 밖에 **새로** 만든 파일(실행 로그 등)은 에이전트가 지우고 올린다 —
  필요한 출력은 `$TMPDIR` 에 둔다 (2026-10-03, 11203 이 `$로그` 파일 하나로 멈췄다)

## 절차 — `tpx-cases` 를 이 순서로 따른다

`tpx-cases` 의 규칙(R1~R16 · §6 관문 전부(관문 0 포함) · 종료 조건)을 **그대로** 쓴다. 이 스킬이 덮어쓰는 것은
아래 적은 자리뿐이다. `tpx-cases` 가 git·초안 PR·끝 검사를 전제로 적은 문장은 **이 스킬이 이긴다.**

**각 단계에 들어가기 전에 적힌 파일을 Read 로 연다** — 경로는 `.claude/skills/tpx-cases/` 아래다.

**단계 표지 (2026-10-03 · AUT-F3-21)** — 단계에 들어갈 때 글 한 줄로 `[단계] <이름>` 을 말한다. 에이전트가 그 줄을 본 순간의 시각으로
단계마다 걸린 시간을 재 로그와 PR 본문에 남긴다 — 어느 단계가 가장 긴지 보고 다음에 나눌 곳을 정한다.
이름은 아래 그대로 쓴다(다른 이름은 다른 단계로 잡힌다). 해당 없는 단계는 건너뛴다. **결과 요약과 같은 메시지에 넣지 않는다** — 요약 앞 메시지로 먼저 말한다.
**이 이름은 PR 본문 「단계 시각」과 작성 화면에 그대로 나가 사람이 읽는다** — 저장소 안에서만 쓰는 말(관문 · 팬아웃 · 원장 · 표)을 쓰지 않는다 (2026-10-19 사용자).
`자료 읽기` · `표준 기획서로 옮기기` · `요구별 케이스 목록 쓰기` · `빠진 요구 미리 검사` · `화면 요소 찾기` · `케이스 쓰기` · `보조 AI 에게 나눠 맡기기 — <N>명` · `보조 AI 결과 합치기` · `빠른 검사` · `마지막 전체 돌려 보기` · `일부러 고장 내 보기` · `케이스 목록에 결과 채우기` · `결과 요약`.
옛 이름과의 짝 — 요구사항 표 → 요구별 케이스 목록 쓰기 · 관문 0 일찍 → 빠진 요구 미리 검사 · selector → 화면 요소 찾기 · 팬아웃 시작 / 뒤 합치기 → 보조 AI 에게 나눠 맡기기 / 결과 합치기 · 관문 0 · 1 · 2 → 빠른 검사(명령 하나가 셋을 돈다) · 관문 3 → 마지막 전체 돌려 보기 · 관문 4 → 일부러 고장 내 보기 · 표 되채우기 → 케이스 목록에 결과 채우기. 다른 절이 「관문 3」처럼 옛 이름으로 단계를 가리키면 이 짝으로 읽는다.
역방향은 여기에 `화면 모으기`(크롤러) · `화면 살펴보기` · `화면 살펴보기 나눠 맡기기 — <N>명` · `바뀐 화면 케이스 고치기` · `기획서와 화면 차이 정리` · `비밀번호 노출 점검` 을 더한다(`references/reverse.md`). 서브에이전트는 표지를 말하지 않는다

**진행 메모 (2026-10-04 · 이 절이 정본)** — 프롬프트가 메모 경로를 주면 단계 표지를 말할 때마다 그 파일을 **통째로 고쳐 쓴다.** 멈췄다 이어받는 자식은 대화 없이 이 파일과 남은 파일만 받는다.
칸 넷 — `## 지금 단계` · `## 끝낸 것`(표 · 케이스 · 묶음별 진도) · `## 정한 것과 이유`(파일에 안 남는 판단 — 묶음 가르기 · 제외 까닭 · 고른 locator 방식) · `## 다음 할 일`(바로 다음 한두 가지 · 이미 읽은 문서). 짧게 — 다시 읽는 비용이 곧 한도다. 경로는 트리나 자료 폴더 기준 **상대 경로**로 적는다 — 넘겨받으면 작업 폴더 이름(`author-<번호>`)이 바뀐다.
**비밀번호 · 토큰 값을 적지 않는다.** 관문 통과 여부는 적어도 이어받는 쪽이 믿지 않는다(`references/resume.md`). 서브에이전트는 메모를 쓰지 않는다

1. **§1 입력 확인** — `references/1-input.md`. 「입력은 자료 목록이다」대로 자료를 전부 읽는다.
   프롬프트에 표준 기획서 절이 있으면 다 읽은 뒤 이 스킬의 `references/prd.md` 대로 표준 기획서로 옮기고 원장 사본을 다시 만든 뒤 2 로 간다.
   **2 부터는 표준 기획서만 읽는다** — 원본 자료를 다시 열어 표를 쓰지 않는다(`references/prd.md` §5)
2. **§2 요구사항 표** — `references/2-requirements.md`. `docs/cases/<접두사>.md` 에 쓴다. **중간에 멈추지 않는다**
   프롬프트의 원장 절을 먼저 읽고 사본을 연다. 원장의 번호(표준 기획서 번호)마다 케이스 줄 또는 「제외」 한 줄을 둔다(같은 파일 「원장」). 표를 다 쓰면 관문 0 을 `--tests` 없이 한 번 돌려 빠짐을 일찍 본다
   **경계 · 예외 칸은 설계 목록이 정한다** (2026-10-05 · 정본 도메인/작성 §3.6 「설계 기법」) — 표를 쓰기 전에 `npm run ledger:design -- <원장 사본>` 으로 요구마다 칸과 시험 값을 보고 그 칸을 다 쓴다.
   목록의 칸은 빼지 않는다. 기법별로 줄 쓰는 법 · 0건 · 「설계 거절」은 `references/test-design.md`. 기능 케이스의 `techniques` 도 같은 파일 「기법 표시」대로 적는다
   **오류 추정 점검 목록 줄도 이때 더한다** (2026-10-10) — 기획서가 결과를 안 적은 빈 값 · 공백만 · 두 번 누르기 · 남의 것 · 없는 주소 · 서버 실패. 꼴은 `two-kinds.md` 「오류 추정 점검 목록」.
   **이어 작성은 더하지 않는다** — 결과 파일을 안 써서 `확인 필요` 항목을 못 올린다(`references/prd.md` §5 · 2026-10-11 PRD-F4-05)
   **tcId 칸은 손으로 정하지 않는다** (2026-10-04 · 정본 도메인/작성 §3.6 「칸과 번호」) — 케이스 하나는 칸(요구 × 갈래 × 축 × 상태) 하나이고 번호는 명령이 매긴다.
   **정식 줄 출처에는 요구 번호를 하나만 적는다** (2026-10-13 PRD-F9-10) — 같은 화면 · 같은 조작이어도 요구가 다르면 줄을 나눈다. 앞 요구 번호를 붙여 한 케이스로 묶지 않는다(번호 명령 · 관문 0 이 어긋남으로 잡는다). 확인 필요 항목 번호는 세지 않는다.
   표를 다 쓰면 관문 0 일찍보다 먼저 `npm run ledger:number -- <원장 사본> docs/cases/<접두사>.md` 를 돌린다. 줄을 더하면 다시 돌린다 — 이미 매긴 번호는 안 바뀐다.
   미확정 · 보류 · 모킹 · 오류 추정 줄은 출처 칸에 표시를 단다(`wording.md` 「출처 칸의 상태 표시」) — 안 달면 정식 줄과 한 케이스로 묶인다. main 표에 원래 있던 줄은 고치지 않는다(명령도 안 건드린다) — 원장 절이 「옛 표다」라고 하면 예외다(`references/prd.md` §6 — 표를 표준 기획서 번호로 갈아쓴다).
   종료 코드 2(칸 재료 없음 — 기준 표를 못 읽었다)면 지금처럼 종류별로 가장 큰 번호 다음부터 매긴다
   쓰기 전에 `references/korean-ai-tells.md` 를 읽는다 — 표 문장부터 AI 티 없이 쓴다. 케이스 코드의 한글(절차 제목 · 칸 설명 · 판정 문장)도 같다
3. **§3 내부 게이트는 건너뛴다** — 표를 그대로 확정한다. 게이트가 물었을 것
   (합친 줄의 `name` · 자료 어긋남으로 `판정 불가` 가 된 줄)은 **결과 요약에 싣는다.** 사람이 PR 본문에서 본다.
   자료 어긋남 줄은 어긋난 값을 기본값 없는 칸으로 비운 `held: '판정 불가 — 자료 어긋남: <둘>'` 케이스로 쓴다 — 사람이 작성 화면에서 고른다
   무엇을 실을지는 `references/3-gate.md` 를 읽고 정한다
4. **§4 selector 확정 → §5 케이스 작성** — `references/4-selector.md` → `references/5-writing.md`.
   케이스는 UI Test 와 Functional Test 두 갈래다(R17). 예외 · 경계는 근거 넷에 적힌 것만 만들고(R18) 설계 목록의 칸은 빼지 않는다(2단계). 동작 요구는 Functional 케이스로 덮는다(R19).
   UI Test · Functional Test 둘 다 Page Object 를 쓴다(`two-kinds.md` 「Page Object」).
   §4 에서 기획서에 없는 화면 입력 규칙을 보면 표에 미확정 줄을 더해 케이스로 쓴다(`two-kinds.md` 「화면에만 있는 입력 규칙」) — **이어 작성은 더하지 않고 결과 요약에 적는다**(`references/prd.md` §5).
   §4 에서 기획서가 다루는 화면마다 누를 수 있는 것을 눌러 보고 버튼 반응 줄을 더해 화면마다 UI 케이스 하나로 쓴다(`two-kinds.md` 「버튼 반응 케이스」) — 이어 작성은 기획서가 적은 반응 줄만 더한다.
   표준 기획서 절이 있으면 같은 규칙과 화면 오류 문구를 결과 파일에 `확인 필요` 항목으로 먼저 더하고 원장 사본을 다시 만든 뒤, 그 줄의 출처 칸에 새 항목의 임시 번호를 적는다(`references/prd.md` §4 · §5)
   **화면 묶음이 둘 이상이고 케이스가 8건 이상이면** 이 스킬의 `references/fanout.md` 대로 서브에이전트에게 나눠 맡긴다 (2026-09-30)
5. **§6 관문** — `references/6-gates.md`. 원장 대조(관문 0) · 형식 · 표 대조 · 3회 실행 · 일부러 부수기.
   **팬아웃했으면 관문 3 은 `references/fanout.md` §5 의 분담이다** — 서브에이전트가 자기 파일을 3회 돌려 기록을 남기고, 자식은 끝에 마지막 전체 돌려 보기(아래)를 돈다. 보조 3회가 다 초록이고 그 뒤 안 고친 케이스는 1회, 합친 뒤 고친 케이스와 그 Page Object · Component 를 쓰는 케이스는 3회 — 돌려 보기 명령이 고른다
6. **§7 표 되채우기** — `references/7-finish.md`. 1~3 만. **4 커밋은 하지 않는다** (에이전트 스크립트가 한다)

**관문 0 · 1 · 2 와 비밀번호 노출 점검은 빠른 검사 명령 하나로, 관문 3 은 돌려 보기 명령으로 돈다** — 둘 다 틀린 것만 짧게 찍어 로그로 돌리지 않는다. 관문 0 의 원장 사본 경로는 원장 절에 있다.

```bash
npm run -s authoring:check -- 마지막 <원장 사본 | 없음> <접두사> <폴더>[ <산출물 폴더>]; echo "EXIT=$?"
npm run -s authoring:run -- 마지막 <폴더>; echo "EXIT=$?"
```

**돌려 보기 명령 앞에는 대상 서버 주소를 붙인다** — `PLATFORM_BASE_URL=<프롬프트 대상 서버 목록의 운영 아닌 주소> npm run -s authoring:run -- …`. 역방향 · API 는 에이전트가 이미 넣어 두어 붙이지 않는다. 주소가 없으면 명령이 「PLATFORM_BASE_URL 이 없다」를 찍고 `EXIT` 2 로 멈춘다(2026-10-22 PRD-F14-02 — 명령이 서버를 저절로 고르지 않는다. 목록에 운영 서버가 섞일 수 있다)

**빠른 검사 명령** (`scripts/authoring-check.ts` · 2026-10-19) — 빠진 요구 검사(`check:ledger --tests --agent`) · 타입 검사 · 케이스 형식 검사 · 케이스와 요구 목록 맞춰 보기(관문 2 — 프로그램이 글자로 견준다. 눈으로 하지 않는다) · 확인 하나에 값 하나(`tpx-cases` `5-writing.md` R12 아래 — 이번에 바꾼 케이스만) · 비밀번호 노출 점검(`tests/<폴더>` · 목록 · 가이드 요약 · 더 준 경로)을 차례로 돌린다.
첫 줄이 여섯의 통과 / 어긋남이고, 어긋난 것만 줄마다 찍는다. 원장 줄(`원장: …`)도 찍는다. `EXIT` 0 = 다 통과 · 1 = 어긋남 있음 · 2 = 잘못 불렀다. 긴 로그는 기록 자리의 `check-*.log`. 「관문 0 일찍」은 지금처럼 `check:ledger` 를 `--tests` 없이 돈다. 원장이 없으면(프롬프트 원장 절이 「원장 없음」) 원장 자리에 `없음` 을 넣는다 — 빠진 요구 검사가 「건너뜀」으로 찍힌다

**돌려 보기 명령** (`scripts/authoring-run3.ts` · 2026-10-19) — 돌릴 케이스를 고르고, 한 번 부를 때 7분 30초 안쪽만 돌고, 빨간 케이스의 첫 오류 줄만 찍는다. 출력이 짧아 로그로 돌리지 않는다.
`EXIT` 0 = 다 돌았고 빨강 없음 · 1 = 다 돌았고 빨강 있음(목록이 찍힌다) · 3 = `남은 것 N건` — **같은 명령을 바로 다시 부른다**(3분 안이면 브라우저 자리 줄의 앞 차례를 잇는다) · 2 = 잘못 불렀다. 긴 오류 글은 같은 이름의 `.log`(기록 자리)에 있다.
**크롤러 판정이 반응형 · 적응형이면 `--mobile` 을 붙인다**(`tpx-cases` `two-kinds.md` 「화면 크기 판정」 · 2026-10-16 PRD-F10-07) — PC · 휴대폰을 나란히 돈다. 에이전트의 확인은 PC 만 센다 — 휴대폰 빨강은 명령이 찍은 `휴대폰` 줄로 보고 고치거나 결과 요약에 적는다. 1번 돌려 보기는 기기 하나라 휴대폰만 빨간 케이스는 `--mobile-only` 로 돈다

**계정 칸은 kit 이 채운다** (2026-10-12) — 환경 변수 `PLATFORM_ACCOUNTS` 가 있으면 playwright 를 대상 서버 주소(`PLATFORM_BASE_URL=<주소>`)로 돌릴 때 kit 이 그 주소와 출처가 같은 줄의 계정으로 비밀값 칸(역할은 `.meta({ account })`)을 채운다. `PLATFORM_PARAMS` 로 계정을 손으로 만들지 않는다. 필요한 역할이 그 목록에 없으면 원장 「제외」 `계정 미등록`(`tpx-cases` `2-requirements.md` §2)

**마지막 전체 돌려 보기 — 에이전트가 기록으로 확인한다** (2026-10-03 · 2026-10-19 · 도메인/작성 §3.6).
- 기록은 `AUTHORING_GATE3_DIR` 에 남는다 — 마지막은 `gate3-final-<번호>.json`, 서브에이전트는 `gate3-part-<묶음>-<번호>.json`. 번호는 명령이 붙인다.
  에이전트가 파일마다(PC) 마지막 수정 뒤 ① 서버 응답을 늦춰 3회 다 초록인 기록(서브에이전트 것이든 마지막 것이든) ② 하나씩(`--workers=1`) 돈 마지막 기록이 있는지, 마지막 기록의 실패 수를 보고, 어기면 PR 본문에 ⚠️ 경고를 싣는다
- **마지막은 1회면 된다** (2026-10-19 사용자) — 가끔만 빨개지는 케이스는 서브에이전트의 3회가 잡는다(14632 보조 기록 177건 × PC · 휴대폰에서 「3번 중 일부만 빨강」 44개, 1회였으면 31개를 놓쳤다). 메인의 3회는 #221 · #246 에서 「3번 다 빨강」만 냈다.
  앞 케이스가 남긴 자료로 뒤 케이스가 깨지는 것은 한 줄로 이어 도는 1회가 본다. 서브에이전트 기록이 없거나 빨강이 섞였거나 그 뒤 고친 케이스는 명령이 3회로 돌린다
- **느린 망으로 돈다** (2026-10-13 PRD-F9-35) — 명령이 `PLATFORM_SLOW_API=1` 을 붙인다. kit 이 화면이 부르는 API 응답을 0.1~1.5초씩 늦춘다. 데모는 응답이 빨라 기다림이 빠진 케이스도 초록이다 — 여기서 빨개지면 기다림을 고친다(`tpx-cases` `references/5-stable.md`). 쓰는 중의 1회 실행에는 붙이지 않는다
- **도는 파일은 이번에 새로 쓰거나 고친 케이스와, 고친 Page Object · Component · 도우미를 쓰는 케이스다** (2026-10-13 PRD-F9-13) — 명령이 에이전트가 둔 기준 tests 목록과 지금 파일을 견줘 바뀐 파일을 보고(도메인/작성 §3.6 「돌려 보기 명령」) 에이전트와 같은 코드(`살필케이스`)로 고른다. 처음 작성이면 다 새것이라 폴더 전체다
- **명령 하나는 최대 10분이다** — 그래서 명령이 7분 30초 안쪽만 돌고 `남은 것 N건` 을 찍는다. 「다 돌았다」가 나올 때까지 같은 명령을 다시 부른다. `--workers` 를 올리거나 직접 playwright 로 일부만 돌리지 않는다(MKT 11208 이 그래서 케이스끼리 얽힌 실패를 못 봤다)
- 그 뒤 케이스나 Page Object 를 고쳤으면 같은 명령을 다시 부른다 — 고친 파일과 그것을 쓰는 케이스가 3회로 다시 돈다. **마지막 기록이 생긴 뒤에는 빨간 케이스가 고치기 전에는 다시 돌지 않는다** — 기획서와 화면이 달라 늘 빨간 케이스를 끝없이 돌리지 않게(서브에이전트 3회에서 빨갛던 케이스는 마지막 3회로 한 번 돈다). EXIT 2 에 「돌렸지만 끝난 케이스가 없다」면 다시 부르지 말고 찍힌 로그를 본다
- **관문 4(일부러 부수기)는 마지막 전체 돌려 보기 앞에 돈다.** 부수려고 파일을 고쳤다 되돌리면 수정 시각이 바뀐다 — 마지막 돌려 보기가 마지막이어야 되돌린 판을 확인하고 경고도 안 붙는다.
  기대값만 바꿀 때는 파일을 고치지 말고 `PLATFORM_PARAMS` 로 주입한다

## 멈출 때

`tpx-cases` 가 「멈추고 묻는다」고 적은 자리에서는 **묻지 않고 거기서 끝낸 뒤 결과 요약에 사유를 싣는다.** 끝낼 때는 아래 「끝내기 전에」를 거친다(요령 줄 · 비밀번호 점검).

- **피그마를 못 읽었다** — `tpx-cases` §1 의 3 대로 표에 `못 읽음: <주소> — <에러 첫 줄>` 을 적고 **§3 이후로 가지 않는다**
- **대상 화면 주소가 없다** — selector 를 확정할 수 없으므로 표까지만 쓰고 멈춘다
- **역방향인데 로그인 직전 출처가 대상 서버와 다르다** — 입력하지 않고 그 화면을 멈춘다 (`references/reverse.md` §2)
- **판정 불가 · 보류 · 모킹 필요로 빼려 한다** — 먼저 `tpx-cases` §5 「보류 · 모킹 필요로 빼기 전에」 표를 위에서부터 대 본다.
  화면 크기 · 늦춘 응답 · 가짜 응답 · 권한 · 계정 · 만들고 지우기로 풀리면 정식 케이스다. 결과 요약에 모킹한 케이스를 적는다
- **관문 0 이 빨강** — 로그의 `빠짐:` · `형식 오류:` 대로 **표를 고친다.** 케이스를 만들거나, §5 「빼기 전에」 표로도 안 풀리면 맞는 종류로 「제외」 한 줄.
  **`다음 요청` · `사람이 뺌` 은 자식이 새로 못 쓴다**(`다음 요청` 은 2026-10-04 부터 — 1차 MKT 가 「필수를 먼저 덮었다」며 9개를 뺐다. 범위는 AI 가 줄이지 않는다). 관문 0 이 형식 오류로 잡는다.
  main 표에 이미 있던 줄은 에이전트도 인정한다 — 지우거나 고치지 않는다(원장 절이 「옛 표다」면 예외 — `references/prd.md` §6). 다른 제외 종류로 옮겨 적지도 않는다 — 에이전트가 종류별 개수를 PR 본문 머리에 싣고 사람이 본다.
  다 못 덮으면 빠진 채 끝낸다. 관문 0 을 넘기지 못한 채 끝내도 올라가지만(2026-09-30 게이트 1 — 거절하지 않는다) 셈 · PR 본문 머리 · 요청 화면에 「빠짐」으로 남고 남은 요구로 이어 작성이 맡는다.
  `칸 번호 어긋남:` 줄은 `npm run ledger:number` 를 다시 돌리고 케이스 파일 이름 · `tcId` 를 표에 맞춘다. 「출처에 요구 번호가 둘 이상」이면 그 줄을 번호마다 나눈 뒤 돌린다.
  `설계 칸 빠짐:` · `설계 거절 형식 오류:` 줄은 `tpx-cases` `references/test-design.md` 「관문 0 의 설계 줄과 대처」대로 표를 고친다.
  `기법 어긋남:` 줄은 같은 파일 「기법 표시」대로 케이스 파일의 `techniques` 를 고친다
- **케이스가 같은 이유로 3회 빨강** — `tpx-cases` §6 종료 조건대로 그 케이스에 `held: '보류 — <에러 첫 줄>'` 을 달고 나머지는 계속 간다. 화면이 오류 추정 기준을 어겨 빨간 것과 역방향의 바뀐 화면 케이스(`references/reverse.md` §3.5 — 기존 케이스라 그대로 둔다)는 빼고(§6 종료 조건 4)
- **같은 관문이 같은 이유로 3번 실패** — 더 고치지 않는다. 그 관문을 결과 요약에 `실패 — <이유 한 줄> (같은 이유 3번)` 으로 적고 남은 단계로 가서 끝낸다 (2026-10-03 사용자).
  전체 시간 제한은 없다 — 출력이 20분 없을 때만 멈춘다(도메인/작성 §7 TIMEOUT). 그래서 헛도는 것을 이 규칙이 막는다. 시간에 쫓긴다고 관문을 줄이지 않는다

## 끝내기 전에

**띄운 명령이 전부 끝났는지 확인하고 끝낸다.** 첫 한 바퀴에서 자식이 background 검사를 기다린다며
턴을 먼저 끝내 에이전트(그때는 맥)가 멈췄다 (2026-09-23).

**알아낸 테스트 요령을 「배운 것」에 더했는지 본다** — 데이터 · 기다리기 · 공용 서버 · 되돌리기 가운데 이번에 새로 알아낸 것을 가이드 요약에 한 줄씩(`references/guide.md` §5.2 — 구획 전체 20줄까지 · 낡은 요령 줄은 고친다 · 기대값은 안 넣는다). 스스로 멈출 때도 한다 (2026-10-23 PRD-F14-06)

**역방향이면 비밀번호 점검을 돌린다** — `references/reverse.md` §2 「끝내기 직전」(`npm run -s authoring:check -- 비밀번호 <경로…>`). 찾으면 고치고 깨끗할 때까지 다시 돈다.
안 하면 다 만든 뒤 올리기에서 걸려 요청이 멈춘다 (2026-09-28, 5873).

## 결과 요약 — 마지막에 표준출력에 찍는다

에이전트 스크립트가 이것을 PR 본문에 싣는다. **3번 돌려 본 기록이 병합 근거다** — CI 가벼운 길은 케이스를 돌리지 않는다.
**줄 이름은 아래 그대로 쓴다** — 사람이 PR 에서 읽는다(2026-10-19 사용자 — 관문 · 팬아웃 · 표 같은 말을 안 쓴다). `원장:` 줄만 관문 0 로그를 그대로 옮긴다.

```
요구사항 N줄 → 케이스 M건 · 합친 것 J건 · 보류 K건(케이스로 씀) · 목록만 L건
원장: <관문 0 로그의 `원장:` 줄 그대로 / 원장 없음 — <까닭>>
빠진 요구 검사: <빠른 검사 첫 줄의 그 칸 — 통과 / 어긋남 N줄>
코드 형식 검사: <타입 검사 · 케이스 형식 검사 칸>
케이스와 요구 목록 맞춰 보기: <통과 / 어긋난 줄>
3번 돌려 보기: <돌려 보기 명령이 마지막에 찍은 「[돌려 보기] …」 줄 그대로 · 빨강 N줄> · EXIT=<값>[ · 보조 AI 별 <slug: 그 묶음 명령의 「[돌려 보기] …」 줄 · 빨강 N줄>]
보조 AI 나눠 맡기기: <안 함 / 화면 살펴보기 N명 · 케이스 쓰기 N명(사람마다 tcId 수) · 물러섬 <없음 / 동시 둘로>>
일부러 고장 내 보기: <무엇을 바꿨나 · 어느 문장이 빨개졌나>
입력값 바꿔 돌려 보기: <허용 범위 안 값 N건 초록 · 범위 밖 값 N건 빨강 · 뺀 칸 <이름들 / 없음> — 보조 AI 에게 나눠 맡겼으면 보고와 메인 몫을 더한다 / 입력값 칸 없음>
합친 것: <tcId · 합친 name 한 문장 · 어느 요구 줄들인지>
판정 불가·보류: <tcId — held 사유 한 줄씩 · 표만은 요구 번호 — 사유>
오류 추정: <줄 N · 케이스 M건 · 뺀 줄 K(해 볼 수 없음) · 기준 어김(빨간 채로 둠) tcId — 무엇을 어겼나 / 없음>
못 읽은 자료: <주소나 파일 — 에러 첫 줄 / 없음>
표: docs/cases/<접두사>.md
```

멈춘 경우에도 이 모양으로 찍고, 못 간 관문은 `안 돌림(<사유>)` 으로 적는다.
**`원장:` 줄은 참고용이다** — PR 본문 머리의 셈은 에이전트가 메모리의 원장과 올릴 트리로 직접 센다. 자식의 요약을 안 믿는다 (2026-09-30).
