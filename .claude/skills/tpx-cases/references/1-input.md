## §1. 입력 확인

1. **기획서가 텍스트로 읽히는가.** 사람이 `.docx` 를 직접 주면 **변환하지 말고** 붙여넣어 달라고 하고 멈춘다.
   **자료 목록**으로 왔으면 아래 「입력은 자료 목록이다」를 따른다 — 거기서는 작성 에이전트가 이미 바꿔 뒀다
2. **tcId 접두사를 정한다.** 접두사는 **기획서 단위가 아니라 서비스 단위**다 —
   `apps/admin/src/catalog/routes.ts` 가 `tcId.startsWith(prefix + '-')` 로 남의 것을 걸러 낸다.
   정규식은 `^[A-Z][A-Z0-9]{0,11}$`
3. **대상 화면 주소를 받는다.** 없으면 selector 를 확정할 수 없으므로 멈추고 묻는다
4. **`docs/cases/<접두사>.md` 가 이미 있으면 먼저 읽는다** — 요구사항 표(→ R9)와
   **용어 사전(→ §4 캐시)** 둘 다 재사용한다

### 입력은 자료 목록이다

기획서는 한 덩어리로 오지 않는다. 화면의 작성 요청은 **문서 파일 여럿과 피그마 주소 여럿**을
한 세트로 넘기고, 작성 에이전트(`scripts/authoring-agent.ts`)가 그 목록을 프롬프트에 싣는다.
사람이 `/tpx` 로 기획서 파일 하나나 본문을 주는 경우는 **자료가 하나인 목록**으로 본다 — 절차는 같다.
단 사람이 `.doc`·`.docx` 를 직접 주면 바꿔 줄 에이전트가 없으므로 위 1번대로 멈춘다.

| 자료 | 어떻게 읽나 |
|---|---|
| `.pdf` · `.md` · `.txt` | 받은 경로를 **Read 로 그대로** 연다 |
| `.doc` · `.docx` | 에이전트가 글자로 바꿔 둔 `.txt` 경로가 온다(맥은 `textutil`, 서버는 `pandoc` — 서버는 옛 `.doc` 을 미리 실패시킨다). 그것을 Read 로 연다 |
| 피그마 주소 | `npx --yes figma-reader@0.4.0 inspect --refresh '<주소>'` |

**피그마 도구** — 저장소 이름은 `figma-reader-cli` 지만 **npm 패키지와 명령 이름은 `figma-reader`** 다
(2026-09-23 실측 — `npm view figma-reader-cli` 는 404). 판을 **못박아** 부른다. 전역 설치(`npm i -g`)와
그 도구의 스킬 설치(`install`)는 **하지 않는다** — §4 의 Playwright 와 같은 이유로, 부를 때마다 같은 판이어야 한다.
토큰은 환경변수 `FIGMA_TOKEN` 으로만 받는다. 작성 에이전트가 **이 세션의 환경에만** 넣어 준다 — 명령줄이나 파일에 적지 않는다.
`--refresh` 는 그 도구가 응답을 **만료 없이** 디스크에 캐시하기 때문이다. 빼면 지난주 디자인으로 케이스를 만든다.

**셋을 지킨다.**

1. **자료 여럿을 요구사항 표 하나로 합친다.** 파일마다 표를 따로 만들지 않는다.
   **각 줄의 `출처` 칸에 어느 자료인지 적는다** — 파일 이름(`결제-기획.pdf §2`) 또는 피그마 주소.
   한 요구가 두 자료에 걸치면 둘 다 적는다
2. **자료끼리 어긋나면 표에 그대로 적는다.** 문서는 「최대 5개」, 피그마는 「최대 3개」면
   **둘 중 하나를 고르지도, 중간값을 지어내지도 않는다** — `결과` 칸에 `판정 불가(자료 어긋남: <둘>)` 로 남기고
   §3 게이트에서 사람이 정한다. 이것도 기획서의 구멍을 드러내는 부수 가치다
3. **피그마를 못 읽었으면 표에 「못 읽음」을 적고 멈춘다.** 토큰 없음 · 명령 거부 · 오류 셋 다 같다.
   표 맨 위 「덮는 범위」 줄 아래에 `못 읽음: <주소> — <에러 첫 줄>` 을 싣고 **§3 로 넘어가지 않는다.**
   **피그마를 빼고 만든 케이스를 끝난 것으로 올리지 않는다** — 사람은 피그마까지 넣었다고 믿고 머지를 누른다.
   답할 사람이 없는 실행(작성 에이전트)에서도 같다 — 초안 PR 에 그 표를 싣고 거기서 멈춘 사유를 보고한다

**피그마에서 가져오는 것은 요소 주소와 구조뿐이다** (규칙 R10 과 같은 논리). 화면 이름·버튼 이름·
배치처럼 **무엇이 있나**는 가져오되, 피그마에 적힌 글자를 **기대값으로 박지 않는다.**
시안의 글자는 자리표시이거나 이미 낡았을 수 있고, 그대로 박으면 **틀린 시안이 회귀 세트에 영원히 남는다.**
기대값은 문서나 사람의 결정에서 온다.
**피그마 글자는 예외가 없다.** 실제 화면에서 본 값을 기대값으로 쓰는 예외는 역방향의 미확정 케이스뿐이다(`unconfirmed` 꼬리표 필수 · 정본 `docs/spec/도메인/작성.md` §3.6 「★ 역방향」).
