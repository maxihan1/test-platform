## §2 · §5 문구 틀 — 표 문장과 케이스 코드의 한글 (2026-10-02 사용자)

**왜** — 2026-10-02 조사에서 케이스 111건의 뼈대(이름 = 판정 문장 하나 · 절차 「~한다」 · 화면 글자 「」)는 지켜졌지만
서비스마다 이름 꼴 · 전제 문장 꼴(일곱 가지) · 같은 대상의 이름(버튼/단추 · 완료분 지우기/Clear completed) · 칸 설명(「~여부」 57건) · 미확정 사유 꼴이 갈렸다.
증적 문서와 케이스 목록 엑셀이 이 글자를 그대로 싣는다. 그래서 꼴을 여기 하나로 둔다.
AI 티를 피하는 규칙은 `korean-ai-tells.md`, 표 칸과 코드 자리의 대응은 `5-writing.md` R11 이다. 이 파일은 **문장의 모양**만 정한다.

### 자리마다 꼴

| 자리 | 꼴 | 예 | 하지 않는 것 |
|---|---|---|---|
| 표 `결과` · 대표 판정 문장 · `name` (R11 로 셋이 같은 글자) | Functional: 「<조작>하면 <결과>」 · UI: 「<화면>에 <무엇>이 <어떻게> 보인다」 | 「맞는 아이디와 비밀번호로 로그인하면 머리글에 「로그아웃」이 보인다」 · 「로그인 화면에 「로그인」 버튼이 보인다」 | 결과 둘을 「~하며 · ~하고」로 잇기(R1 — 줄을 나눈다) · 과거형(「~됐다」) |
| 그 밖의 판정 문장(전제 판정 · 덧붙인 판정 · R15 로 합친 케이스의 둘째 결과 줄부터) | 결과만, 현재형 | 「목록에 할 일이 두 건 보인다」 | 조작을 다시 적기 |
| 기대값 | 고정값이면 문장 안에 「」로 · `expected` 칸에서 오면 「<무엇>이 기대값과 같다」 | 「「2 items left」가 보인다」 · 「응답 코드가 기대값과 같다」 | 「기대와 같다」(→ 기대값과) |
| 절차 제목 `test.step` | 「<어디서> <무엇을> <동사>한다」 하나 · 확인만 하는 절차는 「<무엇>을 확인한다」 | 「로그인 화면에서 「로그인」을 누른다」 · 「장바구니 개수를 확인한다」 | 「~을 본다」 · 끝이 잘린 꼴(「…적고 Enter」) |
| `precondition` | 한 칸에 한 문장 · 상태형 「<대상>이 <상태>다」 | 「비회원이다」 · 「관리자 계정으로 로그인해 있다」 · 「할 일 목록이 비어 있다」 · 「로그인 응답은 가짜 응답(모킹)이다」 | 지시형(「~으로 준다」) · 케이스를 설명하는 말(「~하려고 둔 것이다」) · 한 칸에 여러 문장 — 모킹 설명이 길면 칸을 나눈다 |
| `describe` (칸 설명 — 증적의 칸 이름) | 짧은 명사구 · 참/거짓 칸은 「<무엇>이 보이는지」 | 「검색어」 · 「「로그아웃」이 보이는지」 | 「~여부」 · 목록을 「 \| 」로 잇기(쉼표로) |

R15 로 여러 줄을 한 케이스로 합치면 **첫 결과 줄만** 「<조작>하면 <결과>」 꼴이고 그 줄이 `name` 이다. 나머지 결과 줄은 결과만 쓴다.
작성 에이전트에서는 한 칸(도메인/작성 §3.6 「칸과 번호」)의 줄이 한 케이스다 — 꼴은 같다.

### 사유 머리 — `unconfirmed` · `held`

머리를 고정하고 그 뒤에 한 문장을 둔다. 요청 번호는 프롬프트가 준 것이다.

| 언제 | 꼴 |
|---|---|
| 역방향 — 화면에만 있다 · 기획서끼리 다르다(표준 기획서 `확인 필요` 항목) | `기획서와 다름 — 차이 D3: <무엇이 어떻게 다른가> (작성 요청 5870)` |
| 역방향 — 화면만 요청 | `화면만 — 기획서 없음 (작성 요청 5870)` |
| 정방향 — 화면에만 있는 입력 규칙(`two-kinds.md`) | `화면 입력 검사 — <요소>: <규칙>, 기획서에 없음 (작성 요청 5870)` |
| 정방향 — 오류 추정 점검 목록(`two-kinds.md`) | `오류 추정 — <항목>: <화면이 보인 것>, 기획서에 없음 (작성 요청 5870)` |
| 정방향 — 기획서끼리 달라 화면 기준으로 적은 표준 기획서 `확인 필요` 항목(작성 에이전트 · `tpx-author` `prd.md` §4) | `기획서끼리 다름 — <무엇이 어떻게 다른가>, 화면 기준 (작성 요청 5870)` |
| 기대값 기준이 없다 | `판정 불가 — <무엇이 없는가>` · 자료 어긋남이면 `판정 불가 — 자료 어긋남: <둘>` |
| 전제 값이 없다 | `보류 — <무엇이 없는가>` |

### 출처 칸의 상태 표시 — 미확정 · 보류 · 모킹 줄 (2026-10-04)

꼬리표(`unconfirmed` · `held`)와 모킹은 케이스에 붙는다. 그래서 그런 줄은 정식 줄과 다른 케이스여야 한다.
작성 에이전트의 번호 명령은 **출처 칸 표시**로 줄을 가른다(정본 도메인/작성 §3.6 「칸과 번호」). 요구 번호 뒤에 붙인다.

| 줄 | 출처 칸에 붙이는 것 | 예 |
|---|---|---|
| 역방향 — 기획서끼리 다름(표준 기획서 확인 필요) | `차이 D<번호>` | `MKT-REQ-020 · 차이 D5` |
| 역방향 — 화면에만 있음 | `화면에만 — <요소>` | `MKT-NEW-002 · 화면에만 — 배송 요청 「선택 안 함」` |
| 정방향 — 화면에만 있는 입력 규칙 · 기획서끼리 다름(화면 기준) | `화면 검사 — <요소>` (R18 근거 칸과 같다) | `기획.md §4 REQ-MEM-001 · 화면 검사 — 아이디 칸 글자 수 제한` |
| 오류 추정 점검 목록 줄 — 항목은 빈 값 · 공백만 · 두 번 누르기 · 남의 것 · 없는 주소 · 서버 실패 | `오류 추정 — <항목>` (서버 실패도 `모킹 —` 을 따로 안 단다) | `기획.md §5 REQ-ORD-003 · 오류 추정 — 두 번 누르기` |
| 표를 쓸 때 이미 보류로 정한 줄(계정 · 권한 없음 등) | `보류 — <무엇이 없는가>` | `기획.docx §5 REQ-BRD-025 · 보류 — 관리자 비밀번호` |
| 가짜 응답(모킹)으로 만드는 줄 | `모킹 — <무엇을>` | `기획.md §3 REQ-LOGIN-004 · 모킹 — 로그인 401` |

쓰는 도중에 3회 빨강으로 보류가 된 케이스는 표시를 안 단다 — 케이스 통째로 보류다.

### 낱말 — 같은 것은 같은 말로

- **서비스 안의 이름은 용어 사전이 정한다.** 사전에 있는 대상은 사전의 `도메인 용어` 를 글자 그대로 쓴다. 없으면 사전에 먼저 더한다
- **화면 글자는 「」 안에 원문 그대로** — 영어 버튼이면 영어로(「Clear completed」). 「」 밖에 화면 글자를 맨글자로 두지 않는다. '' · "" 를 쓰지 않는다
- 요소: 버튼(단추 ×) · 입력칸 · 링크 · 체크박스 · 선택 상자 · 탭 · 팝업 · 목록 · 머리글 · 바닥글 · 화면
- 동작: 누른다(클릭한다 ×) · 적는다(입력칸에 글자) · 고른다(선택 상자 · 목록) · 켠다 / 끈다(체크박스) · 연다(화면 · 주소 · 팝업) · 친다(키 — 「Enter 를 친다」)
- 결과: 보인다 / 보이지 않는다 · <무엇>으로 바뀐다 · <화면>으로 간다 · N건이다
- 사람: 비회원 · 회원 · 관리자 — 서비스가 따로 부르면 그 말을 사전에 적고 쓴다

### 길이

글자 수 상한은 두지 않는다. 대신 **이름이 60자를 넘으면 결과가 둘 이상 묶였는지 본다** — 묶였으면 R1 대로 줄을 나눈다.
2026-10-02 에 145자짜리 이름(결과 다섯을 「~하며」로 이음)이 있었다.
