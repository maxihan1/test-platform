## 게임 조작 — 끊기지 않게 움직이기 (2026-11-25 · GAME-F6-02)

움직이거나 싸우는 게임을 직접 해 보거나(탐색 플레이 · 학습) 그 조작을 케이스 · 미션에 쓸 때 연다. 정본은 명세 `docs/spec/도메인/게임.md` §3.10 「조작 도우미」다.

### 1. 메뉴는 CLI, 판은 조작 도우미

| 무엇을 하나 | 어떻게 |
|---|---|
| 창을 열고 닫기 · 글자 넣기 · 한 번 눌러 결과 보기 | `npx control-cli` 하나씩 — 명령마다 트리와 화면이 남는다 |
| 걷기 · 싸우기 · 줍기 · 시간 안에 여러 번 누르기 | 조작 도우미 — 함수 하나를 한 번에 돌린다(§2) |

CLI 는 명령마다 화면이 멎기를 최대 3초 기다렸다 찍는다. 게임 시간은 그동안에도 흘러 걷다 서고 맞다 진다. 같은 조작을 한 프로세스에서 보내면 명령 하나가 0.04초쯤이다(2026-11-25 Cats Go! PC 실측 — 눌러 둔 채 위치를 2.5초에 57번 읽었다. 폰은 아직 안 쟀다). 1초 안쪽을 다투는 판정은 그래도 `game.md` §1 규칙대로 쓴다.
**처음 해 보는 것은 손으로 한 번 하고 눈으로 본다** — 판에 들어가자마자 `timescale-set 0` 으로 멈추고 `snapshot` 이 남긴 스크린샷을 Read 로 연다. 미니맵의 적 길 · 바닥에 떨어진 것 · 심을 수 있는 자리 · 벽은 트리에 안 나온다. 본 뒤에 함수로 쓰고, 함수를 돌린 뒤에는 끝 화면(`game-play/…jpg`)을 열어 하려던 대로 됐나 본다.
**AI 는 작전을 정하고 손은 스크립트가 움직인다** — 판을 시작하기 전에 무엇을 언제 할지 정해 함수로 쓰고, 판이 끝난 뒤 기록을 보고 하나만 고친다. 판 도중에 명령을 하나씩 생각해 보내지 않는다.

### 2. 조작 도우미 — 쓰고 부르기

`tests/<폴더>/helpers/<이름>.helper.ts` (이름은 영문 소문자 · 숫자 · `-`)에 첫 인자가 `game` 인 함수를 쓰고 이 명령으로 돌린다. `game` 은 케이스 몸통이 받는 것과 같은 드라이버다 — 여기서 된 함수를 케이스 · 미션이 그대로 부른다.

```bash
npx tsx scripts/authoring-game-play.ts <폴더> <이름> <함수> '<인자 JSON 배열>' --max 180
```

- 디바이스를 잡고(`npx control-cli hold` — PC 게임은 `--pc`) 게임을 켜 둔 채 부른다. 한 번에 420초까지(기본 90초)다. **셸 명령의 제한 시간(timeout)을 `--max` 보다 100초 길게 준다** — 셸이 먼저 끊으면 기록이 없다. 더 긴 판은 함수를 나눠 이어 부른다 — 게임은 그대로 돈다
- 함수가 어떻게 끝나도 눌러 둔 키 · 손가락 · 가짜 마우스를 놓는다. 함수가 바꾼 시간 배율도 되돌린다
- 케이스와 다른 것 둘 — 패드는 부르기 전에 `npx control-cli -s=g pad <종류>` 로 정해 두고, `game.restart()` 는 못 쓴다
- 돌려준 값 · 그 사이 게임 로그 · 오류 · 장면 알림을 찍고, 원본과 끝 화면은 `<자료 폴더>/game-play/` 에 남긴다. **돌려주는 값은 필요한 것만 짧게** — 8,000자에서 잘린다
- 첫 인자가 `game` 인 GM 명령 도우미도 이 명령으로 부른다(`authoring-game-state.ts` 는 첫 인자가 `admin` 인 것만)

### 3. 쓰는 꼴

```ts
import type { GameDriver } from '@platform/kit';

type 자리 = [number, number, number];
const 위치 = (game: GameDriver) => game.get('/Player(Clone)', 'Transform.position') as Promise<자리>;

export async function 누른채로<T>(game: GameDriver, 키: string, 읽기: () => Promise<T>, 됐나: (값: T) => boolean, 한도초: number): Promise<T> {
  const 끝 = Date.now() + 한도초 * 1000;
  await game.keyDown(키);
  try {
    for (;;) {
      const 값 = await 읽기();
      if (됐나(값) || Date.now() >= 끝) return 값;
    }
  } finally {
    await game.keyUp(키);
  }
}

/** 0.6초 동안 0.3칸도 못 가면 막힌 것이다 — 같은 쪽을 더 밀지 않고 돌려준다 */
export async function 오른쪽으로(game: GameDriver, 목표x: number): Promise<{ 닿음: boolean; 막힘: boolean; x: number }> {
  let 본자리 = (await 위치(game))[0];
  let 본때 = Date.now();
  let 막힘 = false;
  const 뒤 = await 누른채로(game, 'RightArrow', () => 위치(game), (p) => {
    if (Math.abs(p[0] - 본자리) >= 0.3) [본자리, 본때] = [p[0], Date.now()];
    막힘 = Date.now() - 본때 > 600;
    return p[0] >= 목표x || 막힘;
  }, 10);
  return { 닿음: 뒤[0] >= 목표x, 막힘, x: 뒤[0] };
}
```

- **누르고 → 읽고 → 떼기** — 얼마나 눌러야 하는지 시간으로 어림하지 않는다. 눌러 둔 채 값(위치 · 체력 · 개수)을 읽다가 되면 뗀다. `key(이름, { duration })` 은 그 시간 동안 아무것도 못 읽는다 — 짧은 누르기 · 길이가 정해진 누르기에만 쓴다
- **누를 차례를 시간으로 맞추지 않는다** — 키 하나를 누르면 장면 · 창 · 값이 바뀐 것을 보고 다음 키를 누른다(`find` · `get`). 앞 판에서 고른 것을 게임이 기억해 한 번에 들어가기도 한다 — 이미 들어갔으면 거기서 멈춘다. 들어간 뒤에 메뉴 키가 더 눌리면 캐릭터가 엉뚱한 데로 가고 준비 시간이 지나간다(2026-11-25 Cats Go! — 일곱 판을 이렇게 17초씩 버렸다)
- **판 하나는 함수 하나** — 들어가기부터 첫 행동까지 한 함수로 잇는다. 명령을 나눠 부르면 사이에 2초쯤 비고, 준비 시간(카운트다운)에 할 일을 놓친다. 들어간 때(`events` 장면 열림)부터 첫 행동까지 몇 초인지 돌려준다
- **막히면 바로 안다** — 걷는 함수는 늘 자리가 바뀌는지 같이 본다(위 예). 막혔으면 옆 축으로 한두 칸 비켜 다시 가고, 세 번 비켜도 안 되면 그 자리를 버리고 막힌 자리를 돌려준다. 제한 시간이 찰 때까지 벽을 밀면 판을 그냥 버린다(2026-11-25 Cats Go! — 네 자리 가는 데 36초를 쓰고 졌다)
- **가기 전에 물어본다** — 판을 멈춰 두고(`timescale-set 0`) `npx control-cli -s=g static-call UnityEngine.Physics.Linecast '[x,y,z]' '[x,y,z]'` 를 부르면 두 자리 사이에 충돌체가 있을 때 `true` 다(y 는 캐릭터 허리 높이). 막힌 것을 아는 두 자리와 뚫린 것을 아는 두 자리로 먼저 맞는지 본다. 안 맞으면 길을 충돌체로 안 막는 게임이니 화면과 걸어 본 기록으로 안다. 막힌 곳 · 지나갈 수 있는 길목을 지도 `WORLD` 줄에 적는다
- **두 방향 · 조합** — `keyDown('W')` 뒤 `keyDown('D')`, 방향을 바꿀 때는 놓을 것만 `keyUp`. 한 번에 누르는 조합은 `key('A+LeftShift')`
- **되풀이 규칙** — 「체력이 줄면 기지로 · 자원이 되면 심기 · 떨어진 것 줍기 · 가까운 적이면 공격」을 위에서부터 보고 맞는 것 하나를 하는 반복으로 쓴다. 판마다 규칙 하나만 고친다
- **판 기록** — 반복 안에서 1초쯤마다 한 줄(지난 시간 · 체력 · 자원 · 처치 · 내 위치)을 배열에 모아 돌려준다. 오래 도는 함수는 같은 줄을 `console.log` 로도 찍는다(가려지지 않으니 계정 값은 찍지 않는다). 케이스에서 부를 함수에는 남기지 않는다
- **폰 터치** — 버튼 하나는 `touchDown(주소)` → 읽기 → `touchUp(번호)`, 끌기는 `drag(주소, 닿을 주소, { duration })`. 화면 좌표는 쓰지 않는다. 게임 안 위치 값은 쓴다
- **끝에 다 놓는다** — `finally` 에서 `keyUp` · `touchUp` 을 부른다. 케이스에서 눌린 채 끝나면 다음 단계까지 남는다
- **누르는 시간은 실제 시간이다** — 시간 배율을 0.25 로 낮추면 1초를 눌러도 게임에서는 0.25초만 간다(같은 실측 — 원래 속도 5.99칸 · 0.25배 1.56칸). 늦춰서 익힌 조작은 원래 속도로 다시 해 본다. 케이스는 늘 원래 속도다 — 케이스와 도우미에서 시간 배율을 바꾸지 않는다

### 4. 안 될 때 볼 차례

1. 기록의 끝 화면 — 다른 창이 떠 있나(공지 · 일시정지)
2. 읽은 값이 안 바뀐다 — 주소가 다른 복제본이다(`(Clone)` · 여러 명). `control-cli find` 로 다시 찾는다
3. 자리가 안 바뀐다 — 벽인가(위 「막히면 바로 안다」), 시간 배율이 0 인가, 다른 창이 입력을 쥐었나
4. 키가 안 먹는다 — 게임이 읽는 입력이 무엇인지 본다(`ping` 의 `input`). 메뉴가 포커스를 쥐고 있으면 먼저 닫는다
5. 같은 자리에서 세 번 안 되면 방법을 바꾼다 — 같은 명령을 되풀이하지 않는다

### 5. 10판 확인 — 이기는 미션에 쓸 작전 (2026-11-25 · GAME-F6-04)

이기는 미션(판을 이긴다 · 스테이지를 깬다)은 원래 속도로 **10판을 다 이긴 작전만** 쓴다. 케이스를 쓰는 세션의 메인이 돌려 보기 앞에서 한다(보조는 안 부른다) — AI 없이 스크립트만 돈다.

```bash
npx tsx scripts/authoring-game-wins.ts <폴더> <이름> <함수> '<인자 JSON 배열>' --max 180   # 셸 제한 시간은 10분(600000)
```

- 함수는 판 하나다 — 시작 조건 맞추기(다시 시작 · 맵 고르기)부터 판이 끝날 때까지 하고 `{ 이김: true | false }` 를 돌려준다. 판 하나는 420초까지다
- 0 다 이김 · 1 졌다 · 2 판을 안 셈(못 붙음 · 팜 거절 · 원래 속도가 아님) · 3 남음 — 같은 명령을 다시 부른다. 이긴 판은 이어 센다. 잡기 30분이 모자라면 놓고 다시 잡는다(저장 데이터가 지워지니 그 자리까지 가는 도우미부터)
- **한 판이라도 지면 그 작전은 못 쓴다.** 같은 작전을 이길 때까지 다시 돌리지 않는다(명령이 막는다). 작전을 고치거나 시작 조건(레벨 · 장비 — 인자)을 쉽게 맞춰 다시 한다. 그래도 안 되면 그 미션은 쓰지 않고 결과 요약 「못 쓴 미션」 칸에 `10판을 다 못 이김(<이긴 판>/10)` 을 적는다 — 다음 작성이 다시 해 본다
- 도우미 글이나 빌드가 바뀌면 처음부터 센다 — 확인한 뒤에 그 파일을 고치지 않는다(보조가 쓴 도우미를 다 합친 뒤에 확인한다)
- **싸우는 중의 규칙은 이기지 않아도 쓴다** — 10판은 「이긴다」를 확인하는 미션에만 건다
- 10판을 다 이겨도 실제 승률은 72% 까지 낮을 수 있다 — 가끔 빨개지는 것은 남는다. 빨개진 것을 몰래 다시 돌려 초록으로 만들지 않는다
