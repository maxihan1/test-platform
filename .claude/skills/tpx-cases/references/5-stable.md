## §5. 흔들리지 않게 쓰기 (2026-10-12 PRD-F9-25 · 26)

⑧ 시험에서 MKT 472건을 응답이 늦고 가끔 실패하는 데모(`DEMO_UNSTABLE=1`)에 5번씩 돌렸더니 기준선 모드에서는 안 나던 실패가 9건 나왔다. MKU · MKF · MKS 920건을 같은 데모에 한 번 돌리니 12건이 더 나왔다.
원인은 세 갈래였다. 기다릴 것을 잘못 골랐고, 남이 만든 데이터를 집었고, 날짜로 만들어지는 값을 코드에 적었다. 실행은 두 건씩 같이 돌고 반복 실행은 같은 케이스의 회차가 나란히 돈다(실행 동시 수 2).

### 기다린 뒤 누르고 읽는다

- **화면이 API 로 채우는 내용은 그 내용으로 기다린다.** HTML 에 처음부터 있는 제목은 앵커가 못 된다 — MKT 주문 상세는 「주문 상세」 제목이 바로 뜨고 주문 내용은 API 뒤에 그려져, 제목만 기다리고 주문 번호를 읽은 FN-231 이 늘 실패했다
- **Page Object 의 `열기` 는 그 화면이 다 그려질 때까지 기다린다.** 「다 그려짐」 앵커는 화면마다 한 번 정해 Page Object 에 둔다(성공 화면과 오류 화면이 다르면 `.or()` 로 둘 다). 케이스마다 따로 기다리지 않는다
- **로그인 확인 뒤에 그려지는 공통 영역(머리글 · 바닥글)에 기대는 조작은 그 영역이 그려진 뒤에 한다.** 공통 영역 부품에 `그려질때까지()` 를 두고 화면 Page Object 의 기다리기가 부른다 —
  MKT 「장바구니 담기」는 로그인 확인 전에 누르면 아무 일도 안 하고(FN-180), 「맨 위로」 버튼은 바닥글이 그려지기 전에 내리면 끝내 안 나타났다(FN-017 · 018)
- **자리(`boundingBox`)를 견주는 판정은 위쪽에 늦게 그려지는 머리글이 그려진 뒤에 잰다** — 두 요소를 재는 사이에 화면이 밀린다(MKT-UI-424 「0/1000」이 내용 칸 아래인가)
- **「사라질 때까지」(`state: 'detached'`)는 그 요소가 먼저 그려진 뒤에만 앵커가 된다.** 아직 안 그려졌으면 바로 통과한다 — MKS-FN-402 는 로그인 화면 머리글이 그려지기 전에 「로그인」을 눌러 「머리글 로그인 링크가 사라졌다」가 곧장 참이 됐다
- **숨은 요소는 역할로 못 기다린다.** `getByRole(...).waitFor({ state: 'attached' })` 도 숨은 요소는 잡지 않는다 — 숨은 요소는 역할 트리에 없다. 숨은 버튼이 생겼는지를 기다려야 하면 그 버튼을 그리는 영역을 기다린다

### 정해 둔 시간을 기다리지 않는다 (2026-10-16 PRD-F10-02 · K15)

`waitForTimeout` 과 `networkidle` 은 `check:tests` 가 K15 로 막는다 — 케이스 · Page Object · 도우미 모두. 정해 둔 시간은 느린 망에서는 모자라고 빠른 망에서는 시간만 버린다. `networkidle` 은 늘 열린 연결(알림 · 상담 창 · 주기 요청)이 있으면 안 오고, 와도 「다 그려졌다」는 뜻이 아니다. 무엇을 기다리는지 이름을 대고 그것을 기다린다.

| 기다리던 것 | 이렇게 |
|---|---|
| 조작이 부르는 요청의 응답 | `const 응답 = page.waitForResponse(...)` 를 **조작 전에** 걸고 조작 뒤에 `await 응답`. 조작 뒤에 걸면 이미 온 응답을 놓쳐 시간 초과가 난다 |
| 몇 개 나갈지 모르는 요청(두 번 누르기) | 조작하는 동안 나간 요청을 모아 응답이 다 올 때까지 — 묶음마다 `helpers/common-tools.helper.ts` 의 `보낸요청끝날때까지` |
| 화면 타이머(토스트 3초 · 5초마다 바뀌는 수 · 15초 뒤 설문) | 화면을 열기 **전에** `page.clock.install()`, 그 뒤 `page.clock.runFor(밀리초)` |
| 부드러운 스크롤 · CSS 전환 | `스크롤멈출때까지기다리기` · 요소의 `getAnimations()` 가 다 `finished` 일 때까지 · 전환이 닿는 값(불투명도 1)을 `waitForFunction` 으로 |
| 화면이 늦게 붙이는 것(배지 숫자 · 쿠키 띠) | 같은 스크립트가 그 일 **바로 뒤에** 붙이는 다른 것 — 판정과 다른 것으로 고른다(R13) |
| 「아무 일도 안 일어난다」 | 그 일을 일으킬 요청을 듣는다. 나갔으면 그 결과가 화면에 닿을 때까지 기다린다. 안 나갔다고 보려면 **요청이 나갔을 시점을 지난 뒤**여야 한다 — 그 조작을 처리한 화면이 다시 그려진 뒤(두 프레임)에 본다. 타이머 · 늦은 요청으로 나가는 일이면 `page.clock` 으로 그 시각을 지난다 |
| 시간 초과를 일부러 내는 케이스 | 끝내 안 나타나는 것을 `waitFor({ timeout: 0 })` 로 — 테스트 제한 시간에 실패한다 |

`route` 안에서 응답을 늦추는 `setTimeout` 과 데드라인(`Promise.race`)은 된다 — 기다리는 것이 아니라 상황을 만드는 것이다.

### 남이 만든 데이터를 집지 않는다

- **목록의 「첫 줄」 · 「아무 상품」처럼 다른 케이스가 만들고 지울 수 있는 것을 집지 않는다.** 케이스가 만든 것을 이름 · 번호로 집는다 —
  MKT-UI-124 는 목록 첫 글을 열었다가 같이 돈 회차가 지운 임시 글을 열어 「삭제된 글」을 만났다
- **수가 적은 공용 데이터(재고 1개뿐인 상품)에 기대면 같은 케이스 회차끼리 부딪힌다.** 넉넉한 데이터가 있으면 그것을 쓴다(MKT-FN-228 은 데모에 재고 1~10 상품이 하나뿐이라 남은 한계다)
- **서버 전체를 초기화하는 요청은 같이 도는 케이스를 깨뜨린다**(MKT-FN-281 `POST /api/reset`) — 케이스 쪽에서 막을 길이 없어 끝 보고에 적는다
- **시드 데이터는 가이드 「테스트 데이터」 목록의 이름으로 집고 바꾸지 않는다** — 번호는 준비가 다시 만들 때 바뀐다(`5-data.md` · 2026-11-11 SEED-F1-04)
- **기본 상품은 다른 케이스 주문으로 재고가 바닥날 수 있다** — 실행 때 품절인지 보고 살 수 있는 상품을 고른다(DMA-UI-078 · FN-154 · 157 · 162 · 397, DMA `살수있는옵션상품`)

### 날짜 · 순번으로 만들어지는 값은 찾아 쓴다

- **서버가 날짜 · 순번으로 만드는 값(주문 번호 `DM20260614-0003` 꼴)을 코드에 적지 않는다.** 데모를 다른 날 켜면 없는 값이다(MKS-FN-390 ~ 393)
- 조건(상태 · 기간 · 내가 만든 것)으로 화면이나 API 에서 찾아 쓴다 — 도우미 하나로 둔다(MKS `상태별주문번호` · `석달넘은주문번호`, MKF `배송중주문번호`). 표의 `조작` · `결과` 칸에도 그 값을 적지 않는다
- 가짜 응답(모킹) 안에 넣는 값은 서버 데이터가 아니라 상관없다
- 찾아 쓰는 값은 입력값 칸으로 열지 않는다. 서버에 늘 있고 케이스가 바꾸지 않는 데이터(상품 번호 하나)는 칸으로 연다 — `5-inputs.md`

### 게임 — 기다림 (2026-10-23 · GAME-F1-11)

게임 케이스(`game.md`)는 위 웹 규칙의 뜻을 게임 드라이버로 지킨다. 명세는 도메인/게임 §3.10 「케이스 꼴」 기다림, 메서드 꼴은 공통/3 「게임 테스트 타입」이다.

| 기다리던 것 | 이렇게 |
|---|---|
| 창 · 오브젝트가 뜰 때까지 · 글자가 들 때까지 · 사라질 때까지 | `game.waitFor(주소, { text, gone, timeoutMs })` — 기본 10초 · 0.3초마다 찾는다 |
| 게임 안 값이 될 때까지(골드 · 위치 · 상태) | `game.waitForValue(주소, '컴포넌트.칸', 값, { timeoutMs })` — 깊은 비교다. 오브젝트가 아직 없어 읽기가 실패해도 한도까지 다시 본다 |
| 앱을 다시 켠 뒤 | 위 `waitForValue` 를 첫 확인으로 쓰고 `timeoutMs: 120000` — 게임이 켜지는 동안의 오류도 「아직」으로 본다. `waitFor` 는 연결 오류에서 바로 실패한다 |
| 누른 뒤 서버 값 | 화면이 그 결과를 그린 뒤(`waitFor` 로 글자) 서버를 읽는다. 화면보다 먼저 읽으면 요청이 아직 안 갔을 수 있다 |
| 시간 경계(리젠 20초) | 쉬지 않는다 — 시작 시각을 적고 `waitFor(…, { timeoutMs })` 로 뜰 때까지 기다린 뒤 걸린 시간을 견준다 |

- **정해 둔 시간을 쉬지 않는다** — `new Promise((r) => setTimeout(r, …))` 도 같다. 무엇을 기다리는지 이름을 대고 그것을 기다린다
- 명령 하나는 15초 안에 끝나야 한다(디바이스 팜이 끊는다). 오래 기다릴 것은 `timeoutMs` 를 늘린다 — 짧은 찾기를 되풀이하는 꼴이라 괜찮다
- 「사라질 때까지」(`gone: true`)는 그것이 먼저 뜬 것을 본 뒤에만 앵커다 — 웹과 같다
- **여럿 생기는 것(몬스터 · 드랍 · 다른 캐릭터)을 「첫 번째」로 집지 않는다** — 상태 도우미로 정해진 자리에 하나만 두고 그 이름 · 경로로 찾는다(위 「남이 만든 데이터를 집지 않는다」와 같다). 자리를 못 박으면 바로 아래 줄이다
- **폰이 움직이는 것(봇 · 몬스터)에 기대지 않는다** (2026-10-25 GAME-F2-13) — 이동은 폰이 정해 서버가 자리를 못 박는다. 화면에 보이는 봇 하나를 골라 서버 상태를 바꾸고 이름표를 읽는 사이에 그 봇이 멀어지면 이름표가 사라진다(ASH-UI-106 — 보라 이름이 화면에 닿기까지 약 14초 동안 봇이 걸어가 RUN 20926 통과 · 20929 실패)
  - 상태 도우미로 캐릭터 곁에 둘 수 있으면 그렇게 한다(몬스터는 스폰 자리 · 봇은 가이드에 그런 API 가 있을 때만)
  - 없으면 **읽는 동안 사라졌을 때 보이는 다른 것을 골라 처음부터 다시 한다** — 고르기 · 상태 바꾸기 · 읽기를 한 묶음으로 세 번까지. 다시 고를 때는 이미 고른 것을 뺀다. 잠깐 안 보이는 것은 다시 그리는 중일 수 있어 3초 넘게 안 보일 때 사라진 것으로 본다. 게임 케이스 상한이 120초라 한도를 끝까지 기다리지 않는다
  - 상태를 바꾼 서버 값이 기대와 다르면 화면을 기다리지 않고 바로 그 판정으로 간다
  - 찾은 뒤 읽는 사이에도 사라질 수 있다 — `find` 로 본 뒤 `get` · `text` 가 던지면 다시 `find` 해서 없을 때만 「사라짐」으로 본다. 있는데 던졌으면 그대로 던진다

### 웹 — 뜨는 창 · 화면 밖 요소 (2026-11-15 · 정본 SPEC 도메인/러너 §5.2 「웹 공용 부품」)

- **뜻밖에 뜨는 창은 서비스 도우미 한 곳에 등록한다** — 쿠키 띠 · 공지 · 설문처럼 아무 때나 화면을 덮는 창을 케이스 중간에 「떠 있으면 닫기」(`if (await 창.isVisible()) …`)로 흩어 쓰지 않는다. 그 화면을 여는 도우미(`helpers/page-setup.helper.ts`)에 두 가지를 모은다.
  - 안 뜨게 할 수 있으면 미리 막는다 — `page.addInitScript` 로 「이미 봤다」 값을 넣는다(지금 `방해막기` · `안내창막기` 가 하는 일)
  - 막을 수 없으면 떴을 때 닫게 등록한다 — `await page.addLocatorHandler(page.getByRole('dialog', { name: '공지' }), async (창) => { await 창.getByRole('button', { name: '닫기' }).click(); })`. Playwright 가 누르기 · 기다리기 직전에 그 창이 덮고 있으면 알아서 닫는다
  - **그 창 자체를 시험하는 케이스는 등록하지 않는다** — 도우미가 인자로 켜고 끄게 한다(`방해막기(page, { 공지팝업: false })` 꼴)
- **화면 밖 · 접힌 요소는 끌어온 뒤 읽는다** — 긴 메뉴 아래 · 접힌 구획의 요소는 `await 요소.scrollIntoViewIfNeeded()` 뒤에 읽고 누른다. 누르기(`click`)는 Playwright 가 알아서 끌어오지만 `isVisible` · `boundingBox` · 글 읽기는 안 끌어온다(MTW-UI-224)
- **가상 목록은 보이는 것만 DOM 에 있다** — 길게 굴리는 목록(타임라인 · 무한 스크롤)은 화면 밖 줄이 빈 껍데기이거나 아예 없다. 개수를 한 번에 세지 않는다 — 줄을 하나씩 `scrollIntoViewIfNeeded` 로 끌어와 내용이 채워진 것을 확인하며 센다(MTW-FN-422 — 펼친 고정 글 5개를 4개로 셌다 · UI-134)
- **누르는 자리에 다른 링크가 있으면 자리를 정한다** — 카드 · 글 본문은 가운데가 해시태그 · 멘션 링크일 수 있다. 본문을 누르는 케이스는 `click({ position: { x: 5, y: 5 } })` 처럼 빈 자리를 고른다(MTW-UI-034 — 해시태그 메뉴가 떴다)

### 앱(Appium) — 공용 부품을 쓴다 (2026-11-15 · 정본 SPEC 도메인/러너 §5.2 「앱 공용 부품」)

기다리기 · 지금 화면 가르기 · 적기 · 토스트 · 권한 창은 kit 이 준다 — `import { 뜰때까지, 먼저뜨는것, … } from '@platform/kit/parts'`. 도우미 · 화면 객체가 kit 에서 값으로 가져올 수 있는 곳은 이 입구뿐이다(그 밖은 K7). 케이스도 부품은 여기서 가져온다 — `defineCase` · `test` · `verify` 는 지금처럼 `@platform/kit` 에서. **같은 일을 서비스 도우미에 다시 짜지 않는다.** 서비스 도우미에는 그 앱의 주소(id)와 화면 흐름(로그인 · 서버 고르기)만 둔다.

| 하려는 일 | 부품 |
|---|---|
| 요소가 뜨기 · 사라지기를 기다린다 | `뜰때까지(driver, 주소, 시간)` · `사라질때까지` — 됐는지를 돌려준다(던지지 않는다). 판정은 `verify` 로 |
| 조건이 될 때까지 기다린다 | `될때까지(driver, async () => …, 시간)` — 고정 시간 쉬기(`pause` · `setTimeout`) 대신 |
| 지금 보이나(기다리지 않고) | `보이나(driver, 주소)` |
| 지금 화면이 어느 것인가 | `먼저뜨는것(driver, { 시작: 주소, 홈: 주소 }, 시간)` — 먼저 보이는 것의 이름, 안 뜨면 `undefined` |
| 굴려야 보이는 요소 | `스크롤해서찾기(driver, 글자)` |
| 칸에 적는다 · 키보드를 내린다 | `칸에적기(칸, 값)` · `키보드완료(driver)` — 아래 「입력 칸」 줄 |
| 토스트 글 | `토스트글(driver, 상자 주소)` — 아래 「토스트 글은 한 번에」 줄. 시스템 토스트는 `//android.widget.Toast` |
| 권한 창 | `권한창답하기(driver, '허용' \| '거부')` — 뜨면 답하고 `true`, 안 뜨면 `false` |
| 빠르게 두 번 · 길게 누르기 · 앱 다시 켜기 | `두번누르기(칸)` · `길게누르기(driver, 주소)` · `앱다시켜기(driver, 꾸러미)` |
| 여러 요소의 글 | `글자들(driver, 주소)` |

- **계속 움직이는 화면에서만 `움직이는화면에서(driver, async () => { … })` 로 감싼다** — 자동으로 넘어가는 배너 · 재생 중인 영상처럼 멈추지 않는 화면은 명령마다 10초를 꽉 채워 기다린다(폰 기록 「Waiting up to 10000ms for the device to idle」). 감싼 구간만 1초로 낮추고 끝나면 kit 이 되돌린다. **`updateSettings` 로 직접 낮추고 두지 않는다** — 그 10초가 다음 화면의 로딩을 기다려 주던 것이라, 낮춘 채로 넘어가면 로딩 중인 화면에서 요소를 못 찾는다. 구간 안에서 화면이 바뀌면 `뜰때까지` 로 직접 기다린다

### 앱(Appium) — 누르기 · 읽기 (2026-11-04 · 실행 21003 · 21004)

- **입력 칸은 누르지 않고 값만 넣는다**(`clearValue` · `setValue`) — 누르면 키보드가 뜬다. 내리려고 보낸 ESC 는 대화창을 닫고(UI-114 등 14건), 뒤로 가기는 키보드가 늦게 뜨는 안드로이드 13 에서 화면을 닫는다(FN-305 · 404). kit `칸에적기`
- **목록 끝에 잘린 칸은 읽지 않는다** — 안쪽 글 칸이 화면 구조에 없다. 다 보이는 칸만 읽고 나머지는 밀어서 다 보이게 한 뒤 읽는다(UI-089 · FN-325 · FN-345)
- **대화창이 떠 있으면 그 뒤 토스트 · 화면 글은 못 읽는다**(안드로이드 13) — 모든 창 보기(`enableMultiWindows`)도 안 잡혔다. 누른 뒤 곧바로 창을 닫고 읽는다. 토스트는 4초라 창을 닫기 전에 다른 확인을 하면 놓친다. 창이 남는지도 봐야 하면 그것을 먼저 보고 한 번 더 누른 뒤 닫는다(FN-260 · 357 · 360, DMA `취소하기눌러보기`)
- **토스트 글은 한 번에 찾아 읽는다** — 「떴나」와 「글」을 따로 물으면 느린 폰에서 그 사이에 사라진다. 상자 · 글 칸을 기다림 없이 찾아 글이 나올 때까지 되풀이한다(FN-260, kit `토스트글`)
- **빠르게 두 번 누르기는 하나만 들어가도 넘어간다** — 첫 누름으로 화면이 바뀌면 둘째는 「없음」 오류다. 판정은 결과(주문 수)로 한다(FN-404, kit `두번누르기`)
- **화면 글의 띄어쓰기 개수는 따지지 않는다** — 공백을 하나로 접은 뒤 견준다(UI-079 · 078)
- **줄을 이름표 낱말로 찾지 않는다** — 그 낱말이 화면에 없을 수 있다. 화면에서 읽은 꼴로 찾는다(UI-113 주소 줄은 「[06236] 서울 …」)
