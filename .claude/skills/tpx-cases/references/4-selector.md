## §4. selector 확정 — 화면을 실제로 연다

**기획서에 없는 단 하나의 정보다.** 추측해 쓰면 문법은 통과하고 실행은 전부 실패한다.

**도구는 Playwright 의 `cli` 다** (Microsoft). 설명은 `.claude/skills/playwright-cli/` 에 같이 있다.

```bash
npx playwright cli -s=probe open '<대상 주소>'      # 열고 **켜 둔 채로 둔다**
npx playwright cli -s=probe snapshot                # 스냅샷을 **파일로** 떨군다. 경로만 돌아온다
npx playwright cli -s=probe find '<찾는 글자>'       # 그 스냅샷에서 찾는다
npx playwright cli -s=probe fill e8 '<값>' --submit  # 상호작용. 세션이 그대로 이어진다
npx playwright cli -s=probe close
```

**★ 전역으로 깔지 않는다.** 벤더 안내는 「로컬 버전이 없을 때만 전역 설치」인데
**이 저장소에는 로컬이 있다** — `package.json` 이 `@playwright/test` 를 **한 버전으로 못박아** 두고
러너가 그 버전으로 케이스를 돌린다. 전역에 `@latest` 를 깔면
**탐침이 읽은 화면과 러너가 실행하는 화면이 다른 Playwright 를 타게 된다** —
「탐침으로 확정한 locator 가 러너에서 그대로 돈다」는 이 저장소의 전제가 거기서 깨진다.
`npx playwright cli` 는 `npm ci` 만 돌린 기계에서 바로 돈다 (2026-09-22 실측).

**왜 바꿨나** (2026-09-22 실측). 옛 탐침은 `node -e` 한 줄로 브라우저를 띄워 첫 화면을 찍고 **바로 닫았다.**

- 클릭한 뒤 상태를 보려면 **명령을 새로 써서 처음부터 다시 밟아야** 했다
- **로그인을 못 했다.** 이 절이 「로그인 뒤는 크롬으로 보고 **탐침으로 재확인**」이라 적어 뒀는데
  탐침에 로그인할 방법이 없었다 — **그 재확인은 성립한 적이 없다**
- `ariaSnapshot` 전문이 **컨텍스트에 통째로** 들어왔다

`-s=<이름>` 세션이 유지되므로 **한 번 로그인하고 여러 번 찍는다.**

### 메뉴로 닿지 않는 화면 — 딥 링크·메일 링크

대상 주소에서 메뉴를 눌러 못 가는 화면이 있다. **셋으로 가른다** (2026-09-25).

| 상황 | 어떻게 |
|---|---|
| 자료(기획서·피그마)에 경로가 있다 | **자료에 적힌 경로**로 바로 간다 — `page.goto('/<경로>')`. 탐침도 같은 경로로 연다 |
| 자료에 경로가 없고 메뉴로도 못 닿는다 | **경로를 지어내지 않는다.** 표 `결과` 칸에 `판정 불가(화면 경로 없음)` 을 적고 케이스로 안 만든다 |
| 메일·문자 링크처럼 화면 조작으로 못 만드는 진입 (토큰이 든 링크 등) | R4 와 같이 `모킹 필요` 로 남긴다 |

**★ 경로는 상대로만 쓴다.** 주소를 박지 않는다 — `baseURL` 기준이고 러너가 실행마다 `PLATFORM_BASE_URL` 을 준다.
둘째 줄은 사람이 경로를 자료에 적어 다시 넣으면 첫째 줄로 올라간다.

**왜** — 추측한 경로는 문법은 통과하고 실행에서 404 로 전부 빨개진다.
더 나쁘면 **비슷한 딴 화면이 열려 틀린 화면을 판정한다.**

### ★ CLI 가 뱉는 코드를 그대로 베끼지 않는다

명령마다 「Ran Playwright code」로 **방금 실행한 Playwright 코드**를 같이 뱉는다.
대개 `getByRole` 이라 아래 우선순위와 맞는다 — 이 도구를 쓰는 가장 큰 값이다.

**그런데 같은 것이 둘이면 `.nth(1)` 을 뱉는다** (2026-09-22 실측 — 같은 이름의 할 일 둘에서
`getByRole('checkbox', { name: 'Toggle Todo' }).nth(1)`).
**`nth()` 가 나온 것은 쓸 locator 가 아니라 「이 화면에 같은 것이 둘」이라는 신호다.**
다른 앵커를 찾고, 못 찾으면 표에 `보류` 로 남긴다.

### ★ 벤더 스킬의 **생성 절차**를 따르지 않는다

`.claude/skills/playwright-cli/references/test-generation.md` 가 plan → generate → heal 한 벌을 들고 있다.
**탐침만 가져온다. 생성 절차는 이 저장소의 규칙과 정면으로 부딪힌다.**

| 그 문서 | 여기 |
|---|---|
| 기대값을 **화면에서 읽어** 담는다 (`eval "el => el.textContent"`) | **R10 이 금지한다.** 화면이 버그를 갖고 있으면 그 버그가 회귀 세트에 영원히 박힌다 |
| `expect` 로 단언 | `tests/**` 는 `verify` 만 쓴다. **훅이 `expect` 를 막는다** |
| `// N. <단계>` 주석을 단다 | `tests/**` 는 **주석 금지** (CLAUDE.md §3) |

| 상황 | 무엇을 쓰나 |
|---|---|
| 주소가 열려 있다 | **탐침** (기본) |
| **로그인 뒤 화면** | **탐침으로 직접 로그인해서 본다** (2026-09-22 부터. 그전에는 길이 없었다) |
| 그 요소가 화면에 없다 | **케이스를 만들지 않는다.** 표에 `보류(<사유>)` 로 남긴다 |

**locator 우선순위** `getByRole` > `getByPlaceholder` > `getByTestId` > `getByText`.
CSS 선택자·`nth()`·XPath 금지.

**이 금지는 「무엇을 판정할지 고르는 자리」에만 건다.** 대기 앵커(R13)는 다르다 —
목록의 몇째가 붙었나 사라졌나를 기다리는 `nth(N).waitFor()` 와, 값이 바뀌기를 기다리는
`getByText('<값>').waitFor()` 는 쓴다. **판정 대상을 자리나 글자로 고르는 것**이 위험한 것이지
**기다리는 것**은 아니다 (2026-09-21 실측 — 이 예외가 없어서 같은 커밋이 산문과 반대로 갔다).

**「일단 쓰고 실패하면 고친다」가 기본이 아닌 이유** — Playwright 는 「그 locator 를 기다리다
시간 초과」라고만 말한다. **무엇이 있는지는 안 알려 준다.** 탐침 없이 루프를 돌면 3회 규칙에 그냥 걸린다.

### 용어 사전은 **다음 실행이 읽는 캐시**다

표 아래에 붙인다. **값이 나오는 자리는 유지보수가 아니라 생성 비용이다** —
케이스 파일들은 각자 locator 를 들고 있으므로 화면이 바뀌면 케이스마다 고쳐야 한다.
사전이 아끼는 것은 **AI 가 화면을 해석하는 일**이다.

```markdown
## 용어 사전

- 화면 스냅샷 해시: `<12자>` (**요소 번호를 뺀 뒤 sha256 앞 12자** · 2026-09-22)

| 도메인 용어 | 화면에서 무엇 | locator |
|---|---|---|
| 할 일 입력칸 | 맨 위 텍스트 상자 | `getByPlaceholder('What needs to be done?')` |
```

**★ 해시는 이 명령으로만 낸다.** 눈대중으로 옮겨 적지 않는다.

```bash
npx playwright cli -s=probe --raw snapshot | sed 's/\[ref=[^]]*\]//g' | shasum -a 256 | cut -c1-12
```

**`sed` 로 요소 번호를 빼는 것이 핵심이다** (2026-09-22 실측). 같은 화면인데
**한 번 이동하고 나면 번호에 `f1` 접두사가 붙는다** — `[ref=e1]` 이 `[ref=f1e1]` 이 된다.
번호를 넣은 채로 해시하면 같은 화면이 `2fa423bc2749` 와 `3d3636c4ccdf` 로 갈리고,
번호를 빼면 **둘 다 `4735b99cebbb`** 다.

**★ 알고리즘을 반드시 적는다.** 「해시 앞 12자」라고만 적으면 다음 세션이 md5 를 고를 수 있고,
그러면 **캐시가 영영 안 맞는데 그 사실이 「화면이 바뀌었나 보다」로 읽힌다** (2026-09-21 실측 —
같은 화면이 sha256 `73d937f42658` · md5 `cf65d97043d9` · sha1 `e54141fa349e` 였다).
**번호를 안 뺀 것도 같은 병이다** — 캐시가 매번 안 맞고 그것이 「화면이 자주 바뀐다」로 읽힌다.

**두 번째 실행부터의 절차**

1. 위 명령으로 해시를 낸다
2. **해시가 같으면 사전에 이미 있는 줄을 그대로 쓴다** — 그 요소들을 다시 해석하지 않는다
3. 다르면 **바뀐 부분만** 보고 사전을 갱신한다

> **★ 해시가 같아도 「탐침을 더 안 돌린다」는 뜻이 아니다.** 해시는 **첫 화면**만 덮는다.
> 새 요구사항이 **사전에 없는 요소**를 부르거나(필터·편집 같은 새 기능),
> **상호작용 뒤에만 생기는 상태**를 보려면 그 상태를 새로 탐침한다.
> 캐시는 **이미 확정한 것을 다시 해석하지 않는 것**이지 **없는 것을 지어내도 된다는 허가가 아니다** (규칙 R10).
> 새로 얻은 줄은 사전에 「N차에서 늘어난 것」으로 **덧붙인다** (2026-09-21 실측).

**표 아래에 「이 화면에서 걸린 것」 절도 쌓는다** — 관문 3 에서 고친 대기 문제 같은 것.
같은 화면은 같은 데서 걸리므로 다음 케이스가 그걸 처음부터 안다.

> **R9.** 기존 표가 있으면 **먼저 읽는다.** 새 요구사항마다 **더하기·바꾸기·없애기** 중 무엇인지
> 판정하고, **바꾸기면 기존 `tcId` 를 유지한 채** 케이스를 고친다. 번호를 새로 따면
> 「3개월째 초록이었는데 이번에 빨강」이라는 회귀 이력이 끊긴다.
>
> **R10. 기대값은 「사람이 판정한 것」에서만 온다.** 근거는 기획서일 수도 PO 의 결정일 수도 있다.
> **화면에서 자동으로 오지 않는다** — 화면에서 읽는 것은 selector 와 「무엇이 있나」뿐이다.
> 현재 화면이 버그를 갖고 있으면 그 버그가 기대값으로 박히고, 회귀 세트라 **영원히 지킨다.**
> **피그마도 같다** — 피그마에서 읽는 것은 요소 주소와 구조뿐이고, 시안의 글자를 기대값으로 박지 않는다 (§1 「입력은 자료 목록이다」).
>
> **예외 — 역방향의 미확정 케이스**만 화면 값을 기대값으로 쓴다. `unconfirmed` 꼬리표 필수, 없으면 R10 그대로 금지.
> 정본은 `docs/spec/도메인/작성.md` §3.6 「★ 역방향」 (2026-09-25).
