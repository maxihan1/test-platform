## §4. selector 확정 — 화면을 실제로 연다

**기획서에 없는 단 하나의 정보다.** 추측해 쓰면 문법은 통과하고 실행은 전부 실패한다.

**도구는 Playwright 의 `cli` 다** (Microsoft). 설명은 `.claude/skills/playwright-cli/` 에 같이 있다.

```bash
npx playwright cli -s=probe open '<대상 주소>'      # 열고 **켜 둔 채로 둔다**
npx playwright cli -s=probe snapshot                # 스냅샷을 **파일로** 떨군다. 경로만 돌아온다
npx playwright cli -s=probe find '<찾는 글자>'       # 그 스냅샷에서 찾는다
npx playwright cli -s=probe fill e8 '<값>' --submit  # 상호작용. 세션이 그대로 이어진다
npx playwright cli -s=probe close
```

**★ 전역으로 깔지 않는다.** 벤더 안내는 「로컬 버전이 없을 때만 전역 설치」인데
**이 저장소에는 로컬이 있다** — `package.json` 이 `@playwright/test` 를 **한 버전으로 못박아** 두고
러너가 그 버전으로 케이스를 돌린다. 전역에 `@latest` 를 깔면
**탐침이 읽은 화면과 러너가 실행하는 화면이 다른 Playwright 를 타게 된다** —
「탐침으로 확정한 locator 가 러너에서 그대로 돈다」는 이 저장소의 전제가 거기서 깨진다.
`npx playwright cli` 는 `npm ci` 만 돌린 기계에서 바로 돈다 (2026-09-22 실측).

`-s=<이름>` 세션이 유지되므로 **한 번 로그인하고 여러 번 찍는다** — 클릭 뒤 상태와 로그인 뒤 화면을
같은 세션에서 이어 보고, 스냅샷은 파일로 떨어져 컨텍스트에 통째로 안 들어온다.

### 명령을 아끼고 정확하게 (2026-10-16)

도구 호출 한 번이 모델 한 바퀴라 **명령 수가 곧 시간 · 토큰이다.** `--raw` 는 세션 뒤 · 명령 앞에 둔다(`-s=probe --raw click e8`).

| 할 일 | 명령 | 까닭 |
|---|---|---|
| 누르기 · 채우기 · 이동 | `--raw click e8` · `--raw fill e8 '<값>'` | 명령마다 붙는 화면 상태 · 생성 코드 · 스냅샷 링크가 빠진다 |
| 요소 주소 받기 | `--raw generate-locator e8` | Playwright 생성기가 testid 부터 고른다 — 스냅샷에는 `data-testid` 가 안 보인다. 아래 testid · `nth()` 규칙은 그대로 |
| 폼 하나만 읽기 | `snapshot e34` · `snapshot --depth=4` | 화면 전체를 다시 찍지 않는다 |
| 이름 여럿 찾기 | `find --regex` — 아래 명령 | 한 번에 찾는다 |
| 조작이 부른 API | `requests` → `--raw response-body <번호>` · `--raw request-body <번호>` | 무엇을 기다릴지(R13) · 모킹 응답 모양(§5)을 짐작하지 않는다. `request <번호>` 는 헤더까지 다 뱉는다. **본 응답 값은 기대값의 근거가 아니다**(R10) |
| 화면 오류 | `console error` | JS 오류가 나면 케이스보다 화면 버그를 먼저 의심한다 |

**서비스 지도** (2026-10-16) — 자료 폴더에 `api-map.txt` 가 있으면 `requests` 전에 `grep` 으로 그 화면 틀 · 비슷한 케이스 줄만 본다(`GET 호스트/api/goods/:n · 케이스 … · 화면 …`, 한 줄에 API 하나).
역방향 화면 기록의 `## 부르는 API` 절(크롤러가 그 화면을 열고 누를 때 들은 API · 본 상태)도 같은 쓰임이다(2026-10-23 PRD-F14-05).
그 화면이 늘 부르는 API 를 알면 `requests` 를 안 쳐도 기다릴 응답(R13)이 정해진다. 지도에 없거나 조작이 다르면 지금처럼 `requests` 로 본다. **지도도 기대값의 근거가 아니다**(R10) — 기다릴 것 · 가르기에만 쓴다. 정본은 명세 작성 §3.6 「서비스 지도」

입력 칸 속성은 `eval` 한 번으로 다 읽는다 — 스냅샷 글로 필수 · 글자 수를 짐작하지 않는다. 한도가 없으면 `null` 이다(크롤러 `# 입력칸:` 줄과 같은 뜻).

```bash
npx playwright cli -s=probe find --regex "가입|취소|확인"
npx playwright cli -s=probe --raw eval "JSON.stringify([...document.querySelectorAll('input,textarea,select')].map(e => ({ 이름: (e.labels?.[0]?.innerText || e.placeholder || e.name || '').trim(), type: e.type, 최대: e.maxLength > 0 ? e.maxLength : null, 최소: e.minLength > 0 ? e.minLength : null, 필수: e.required, 형식: e.pattern || null })))"
```

### ★ 입력 칸 한도 — 막는지 재고 쓴다 (2026-10-16)

글자 수 경계 줄의 칸은 **케이스를 쓰기 전에** 한도 + 1 글자를 넣고 남은 길이를 읽는다. 스냅샷에는 `maxlength` 가 안 보이고, `maxlength` 없이 JS 로 자르는 칸도 있다(데모마켓 주문서 연락처 — 12자를 넣으면 11자만 남는다).
2026-10-12 MKT 8건은 재지 않고 「한도 + 1 → 오류 문구」로 써서 늘 실패했다(PRD-F9-12).

1. 넣는 값은 그 경계 줄의 시험 값 그대로다. 칸이 걸러 내는 글자(숫자 칸에 영문)를 섞지 않는다
2. **그 칸에 쓸 입력 방법으로** 넣는다(Page Object 도 그 방법으로 쓴다 — 이미 있으면 그 메서드의 방법) — `fill` 이면 `--raw fill e8 '<값>'`, `pressSequentially` 면 `--raw fill e8 ''` → `--raw click e8` → `--raw type '<값>'`.
   걸러지는 글자가 섞인 값(형식 케이스)은 방법에 따라 남는 길이가 갈린다(2026-10-16 실측 — `maxlength` 11 에 숫자만 남기는 칸에 `010-12ab-5678` 을 넣으면 `fill` 7자 · 한 글자씩 9자. MKT-061 · MKU-063 꼴)
3. `--raw eval "el => el.value.length" e8` 로 읽는다

| 남은 길이 | 케이스 꼴 |
|---|---|
| 한도 — 막음 | 「한도 + 1 을 넣으면 한도까지만 들어간다」 경계 케이스. 기획서가 넘었을 때의 오류를 말하면 차이 · 미확정(`two-kinds.md` 「화면에만 있는 입력 규칙」) |
| 한도 + 1 — 안 막음 | 지금처럼 기획서가 적은 결과(오류 문구 · 등록 안 됨) |
| 그 밖 | 칸이 받는 글자로 다시 넣는다. 그래도 다르면 「표에서 고칠 것」으로 돌려준다 |

- 잰 길이는 **케이스 꼴을 고르는 데만** 쓴다. 기대값의 한도 숫자는 기획서에서 온다(R10) — 기획서에 숫자가 없으면 「화면에만 있는 입력 규칙」(아래 예외 ②)이다
- **화면 해시가 같아도 다시 잰다** — 해시(아래 「용어 사전」)는 스냅샷으로 내는데 스냅샷에 `maxlength` · JS 자르기가 안 보여 한도가 바뀌어도 해시가 그대로다. 칸 하나에 명령 셋이다
- 역방향 화면 기록의 「입력 칸 한도」 표(크롤러가 읽은 `maxlength`)는 출발점이다 — JS 로 자르는 칸 · 직접 연 팝업의 칸은 거기 없을 수 있어서 표에 없어도 잰다

### 메뉴로 닿지 않는 화면 — 딥 링크·메일 링크

대상 주소에서 메뉴를 눌러 못 가는 화면이 있다. **셋으로 가른다** (2026-09-25).

| 상황 | 어떻게 |
|---|---|
| 자료(기획서·피그마)에 경로가 있다 | **자료에 적힌 경로**로 바로 간다 — `page.goto('/<경로>')`. 탐침도 같은 경로로 연다 |
| 자료에 경로가 없고 메뉴로도 못 닿는다 | **경로를 지어내지 않는다.** 경로를 `params` 칸(`.describe('대상 화면 경로')`, 기본값 없음)으로 두고 `held: '보류 — 화면 경로가 자료에 없다'` 케이스로 쓴다 (§5). 화면을 못 봐 절차조차 못 적으면 **표만** — `결과` 칸에 `판정 불가(화면 경로 없음)` (표만). 그 요구 번호는 「제외」 표에도 `자료 없음` 한 줄을 둔다(관문 0 — `2-requirements.md` 「원장」) |
| 메일·문자 링크처럼 화면 조작으로 못 만드는 진입 (토큰이 든 링크 등) | 토큰을 만드는 응답을 가짜로 주고 **그 응답이 준 토큰으로만** `page.goto` 한다(§5 「보류 · 모킹 필요로 빼기 전에」). 토큰 값을 지어내지 않는다. 안 되면 `모킹 필요` 로 남긴다 |

**★ 경로는 상대로만 쓴다.** 주소를 박지 않는다 — `baseURL` 기준이고 러너가 실행마다 `PLATFORM_BASE_URL` 을 준다.
둘째 줄은 사람이 경로를 자료에 적어 다시 넣으면 첫째 줄로 올라간다.

**왜** — 추측한 경로는 문법은 통과하고 실행에서 404 로 전부 빨개진다.
더 나쁘면 **비슷한 딴 화면이 열려 틀린 화면을 판정한다.**

### ★ CLI 가 뱉는 코드를 그대로 베끼지 않는다

`--raw` 없이 부르면 명령마다 「Ran Playwright code」로 **방금 실행한 Playwright 코드**를 같이 뱉는다. `--raw` 로 부를 때는 `--raw generate-locator <ref>` 가 같은 생성기로 주소 하나만 준다.
`getByRole` 이 많아 아래 우선순위의 둘째와 맞는다 — 이 도구를 쓰는 가장 큰 값이다. 그 요소에 뜻 있는 testid 가 있으면 그쪽으로 바꾼다.

**그런데 같은 것이 둘이면 `.nth(1)` 을 뱉는다** (2026-09-22 실측 — 같은 이름의 할 일 둘에서
`getByRole('checkbox', { name: 'Toggle Todo' }).nth(1)`).
**`nth()` 가 나온 것은 쓸 locator 가 아니라 「이 화면에 같은 것이 둘」이라는 신호다.**
다른 앵커를 찾고(아래 우선순위대로 CSS · XPath 까지), 못 찾으면 표에 `보류(앵커 없음 · 표만)` 로 남기고 그 번호는 「제외」 표에 `자료 없음` 한 줄을 둔다 — 사람이 값을 넣어도 누를 곳이 안 정해지므로 케이스로 쓰지 않는다.

### ★ 벤더 스킬의 **생성 절차**를 따르지 않는다

`.claude/skills/playwright-cli/references/test-generation.md` 가 plan → generate → heal 한 벌을 들고 있다.
**탐침만 가져온다. 생성 절차는 이 저장소의 규칙과 정면으로 부딪힌다.**

| 그 문서 | 여기 |
|---|---|
| 기대값을 **화면에서 읽어** 담는다 (`eval "el => el.textContent"`) | **R10 이 금지한다.** 화면이 버그를 갖고 있으면 그 버그가 회귀 세트에 영원히 박힌다 |
| `expect` 로 단언 | `tests/**` 는 `verify` 만 쓴다. **훅이 `expect` 를 막는다** |
| `// N. <단계>` 주석을 단다 | `tests/**` 는 **주석 금지** (CLAUDE.md §3) |

| 상황 | 무엇을 쓰나 |
|---|---|
| 주소가 열려 있다 | **탐침** (기본) |
| **로그인 뒤 화면** | **탐침으로 직접 로그인해서 본다** |
| 그 요소가 화면에 없다 | 자료에 적힌 이름으로 locator 를 쓰고 `held: '보류 — <요소>가 화면에 없다'` 케이스로 쓴다 (§5). 반영 때 3회 실행이 그 locator 를 가린다. 자료에도 이름이 없으면 **표만** — `보류(<사유> · 표만)` + 「제외」 표에 `자료 없음` 한 줄 |

**locator 우선순위** (2026-10-02 사용자 — UI · Functional 같은 순서 하나)
`getByTestId` > `getByRole` > `getByLabel` > `getByPlaceholder` > `getByText` > CSS 선택자 > XPath.

- **testid 는 이름에 뜻이 있을 때만 맨 앞이다** — `login-button` 은 쓰고 `a8f3x` 처럼 빌드마다 바뀔 수 있는 생성값은 건너뛴다
- **CSS · XPath 는 위 다섯으로 못 집을 때만 쓴다.** 쓴 까닭을 용어 사전의 그 요소 줄 끝에 ` — 까닭: <한 줄>` 로 남긴다(locator 자체는 Page Object 에 둔다). 케이스 파일에는 주석을 못 쓴다
- **`nth()` 로 판정 대상을 고르지 않는다** — 자리로 고른 것은 순서가 바뀌면 다른 것을 판정한다
- 확정한 locator 는 Page Object 에 담는다 — UI Test · Functional Test 둘 다 (`references/two-kinds.md` 「Page Object」)

**`nth()` 금지는 「무엇을 판정할지 고르는 자리」에만 건다.** 대기 앵커(R13)는 다르다 —
목록의 몇째가 붙었나 사라졌나를 기다리는 `nth(N).waitFor()` 와, 값이 바뀌기를 기다리는
`getByText('<값>').waitFor()` 는 쓴다. **판정 대상을 자리나 글자로 고르는 것**이 위험한 것이지
**기다리는 것**은 아니다.

**「일단 쓰고 실패하면 고친다」가 기본이 아닌 이유** — Playwright 는 「그 locator 를 기다리다
시간 초과」라고만 말한다. **무엇이 있는지는 안 알려 준다.** 탐침 없이 루프를 돌면 3회 규칙에 그냥 걸린다.

### 용어 사전은 **다음 실행이 읽는 캐시**다

표 아래에 붙인다. **값이 나오는 자리는 유지보수가 아니라 생성 비용이다** —
케이스 파일들은 각자 locator 를 들고 있으므로 화면이 바뀌면 케이스마다 고쳐야 한다.
사전이 아끼는 것은 **AI 가 화면을 해석하는 일**이다.

**찾는 법의 정본은 Page Object 다** — 두 갈래 다. 사전에는 이름과 뜻(과 CSS · XPath 까닭)만 둔다.

```markdown
## 용어 사전

- 화면 스냅샷 해시: `<12자>` (**요소 번호를 뺀 뒤 sha256 앞 12자** · 2026-09-22)

| 도메인 용어 | 화면에서 무엇 | locator |
|---|---|---|
| 할 일 입력칸 | 맨 위 텍스트 상자 | `getByPlaceholder('What needs to be done?')` |
```

**★ 해시는 이 명령으로만 낸다.** 눈대중으로 옮겨 적지 않는다.

```bash
npx playwright cli -s=probe --raw snapshot | sed 's/\[ref=[^]]*\]//g' | shasum -a 256 | cut -c1-12
```

**`sed` 로 요소 번호를 빼는 것이 핵심이다** (2026-09-22 실측). 같은 화면인데
**한 번 이동하고 나면 번호에 `f1` 접두사가 붙는다** — `[ref=e1]` 이 `[ref=f1e1]` 이 된다.
번호를 넣은 채로 해시하면 같은 화면이 `2fa423bc2749` 와 `3d3636c4ccdf` 로 갈리고,
번호를 빼면 **둘 다 `4735b99cebbb`** 다.

**★ 알고리즘을 반드시 적는다.** 「해시 앞 12자」라고만 적으면 다음 세션이 md5 를 고를 수 있고,
그러면 **캐시가 영영 안 맞는데 그 사실이 「화면이 바뀌었나 보다」로 읽힌다** (2026-09-21 실측 —
같은 화면이 sha256 `73d937f42658` · md5 `cf65d97043d9` · sha1 `e54141fa349e` 였다).
**번호를 안 뺀 것도 같은 병이다** — 캐시가 매번 안 맞고 그것이 「화면이 자주 바뀐다」로 읽힌다.

**두 번째 실행부터의 절차**

1. 위 명령으로 해시를 낸다
2. **해시가 같으면 사전에 이미 있는 줄을 그대로 쓴다** — 그 요소들을 다시 해석하지 않는다
3. 다르면 **바뀐 부분만** 보고 사전을 갱신한다

> **★ 해시가 같아도 「탐침을 더 안 돌린다」는 뜻이 아니다.** 해시는 **첫 화면**만 덮는다.
> 새 요구사항이 **사전에 없는 요소**를 부르거나(필터·편집 같은 새 기능),
> **상호작용 뒤에만 생기는 상태**를 보려면 그 상태를 새로 탐침한다.
> 캐시는 **이미 확정한 것을 다시 해석하지 않는 것**이지 **없는 것을 지어내도 된다는 허가가 아니다** (규칙 R10).
> 새로 얻은 줄은 사전에 「N차에서 늘어난 것」으로 **덧붙인다** (2026-09-21 실측).

**표 아래에 「이 화면에서 걸린 것」 절도 쌓는다** — 관문 3 에서 고친 대기 문제 같은 것.
같은 화면은 같은 데서 걸리므로 다음 케이스가 그걸 처음부터 안다.

> **R9.** 기존 표가 있으면 **먼저 읽는다.** 새 요구사항마다 **더하기·바꾸기·없애기** 중 무엇인지
> 판정하고, **바꾸기면 기존 `tcId` 를 유지한 채** 케이스를 고친다. 번호를 새로 따면
> 「3개월째 초록이었는데 이번에 빨강」이라는 회귀 이력이 끊긴다.
>
> **R10. 기대값은 「사람이 판정한 것」에서만 온다.** 근거는 기획서일 수도 PO 의 결정일 수도 있다.
> **화면에서 자동으로 오지 않는다** — 화면에서 읽는 것은 selector 와 「무엇이 있나」뿐이다.
> 현재 화면이 버그를 갖고 있으면 그 버그가 기대값으로 박히고, 회귀 세트라 **영원히 지킨다.**
> **피그마도 같다** — 피그마에서 읽는 것은 요소 주소와 구조뿐이고, 시안의 글자를 기대값으로 박지 않는다 (§1 「입력은 자료 목록이다」).
> **서비스 가이드와 그 요약의 「배운 것」도 같다** — 데이터 이름 · 결제 수단 · 고르기 · 기다리기 · 되돌리기에만 쓴다. 가이드에 규칙처럼 적힌 문장도 표준 기획서에 없으면 기대값이 아니다 (`tpx-author` `references/guide.md` · 2026-10-17).
>
> **예외 — 미확정 케이스**만 화면 값을 기대값으로 쓴다. 그 줄 출처에 표준 기획서 `확인 필요` 항목 번호가 있어야 하고, 없으면 R10 그대로 금지다(케이스 파일 `unconfirmed` 꼬리표는 2026-10-11 PRD-F4-05 에서 없앴다).
> **표준 기획서 절이 없는 작성(사람 세션 · 이어 작성)은 이 줄을 쓰지 않는다** — 항목을 올릴 길이 없어 쓰면 확정으로 돈다. 본 것은 끝 보고(작성 에이전트는 결과 요약)에 적는다. 아래가 전부다(정본 목록은 명세 작성 §3.6 「★ 역방향」 「화면 기준 케이스는 `확인 필요` 항목을 덮어야 한다」).
> ① 역방향의 미확정 케이스 — 정본은 `docs/spec/도메인/작성.md` §3.6 「★ 역방향」 (2026-09-25)
> ② 정방향에서 본, 기획서에 없는 화면 입력 규칙(필수 표시 · 글자 수 제한 · 형식 안내) — `references/two-kinds.md` 「화면에만 있는 입력 규칙」 (2026-10-02)
> ③ 오류 추정 점검 목록 케이스의 문구 · 요소 — 「~해야 한다」는 점검 목록이 정한다. `references/two-kinds.md` 「오류 추정 점검 목록」 (2026-10-10)
> ④ 기획서가 적지 않은 버튼의 누른 직후 반응 — 그 화면의 「버튼 반응」 `확인 필요` 항목 하나를 덮는다. `references/two-kinds.md` 「버튼 반응 케이스」 (2026-10-16)
