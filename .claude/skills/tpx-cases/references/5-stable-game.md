### 게임 — 기다림 (2026-10-23 · GAME-F1-11)

게임 케이스(`game.md`)는 위 웹 규칙의 뜻을 게임 드라이버로 지킨다. 명세는 도메인/게임 §3.10 「케이스 꼴」 기다림, 메서드 꼴은 공통/3 「게임 테스트 타입」이다.

| 기다리던 것 | 이렇게 |
|---|---|
| 창 · 오브젝트가 뜰 때까지 · 글자가 들 때까지 · 사라질 때까지 | `game.waitFor(주소, { text, gone, timeoutMs })` — 기본 10초 · 0.3초마다 찾는다 |
| 게임 안 값이 될 때까지(골드 · 위치 · 상태) | `game.waitForValue(주소, '컴포넌트.칸', 값, { timeoutMs })` — 깊은 비교다. 오브젝트가 아직 없어 읽기가 실패해도 한도까지 다시 본다 |
| 앱을 다시 켠 뒤 | 위 `waitForValue` 를 첫 확인으로 쓰고 `timeoutMs: 120000` — 게임이 켜지는 동안의 오류도 「아직」으로 본다. `waitFor` 는 연결 오류에서 바로 실패한다 |
| 누른 뒤 서버 값 | 화면이 그 결과를 그린 뒤(`waitFor` 로 글자) 서버를 읽는다. 화면보다 먼저 읽으면 요청이 아직 안 갔을 수 있다. 게임이 바뀐 값을 모아 몇 초마다 저장하면(가이드의 저장 주기) 운영 API 값은 화면보다 늦게 바뀐다 — 기대값이 될 때까지 저장 주기의 두 배 동안 다시 읽고 마지막 값으로 판정한다(BRM 은 10초 — 상점 · 판매 케이스 7건이 저장 전 값을 읽었다) |
| 고른 뒤 누르기 | 고르기(적 · 물건 · 동료 누르기)가 반영된 것을 본 뒤 다음 버튼을 누른다 — 행동 버튼 그림이 바뀌는 게임이면 그 그림이 될 때까지 기다리는 blocker 확인을 둔다. 바로 누르면 고르기 전 동작(기본 공격)이 나간다(BRM-FN-093) |
| 시간 경계(리젠 20초) | 쉬지 않는다 — 시작 시각을 적고 `waitFor(…, { timeoutMs })` 로 뜰 때까지 기다린 뒤 걸린 시간을 견준다 |

- **기다림 한도는 조작 맵의 소요 시간을 참고한다** (2026-11-20 GAME-F5-08) — 경로 검색이 찍은 행의 `소요 <n>ms` 는 탐색 플레이가 그 동작에서 다음 화면 · 결과가 뜰 때까지 잰 시간이다. 그 동작 뒤 `waitFor` · `waitForValue` 의 `timeoutMs` 를 소요의 세 배쯤으로 적고, 기본 10초보다 짧게 줄이지 않는다. 소요만큼 쉬는 데 쓰지 않는다(아래 「정해 둔 시간을 쉬지 않는다」). 돌려 보기에서 소요보다 한참 길게 걸렸으면 한도를 늘리지 말고 먼저 그 창 · 상태가 맞는지 본다
- **게임 시나리오(`-GS-`)에는 케이스 전체 한도가 없다** (2026-11-18 · 명세 결정 21) — 기능 케이스는 지금처럼 120초다. 게임 시나리오는 한 번의 기다림(`waitFor` · `waitForValue` 한도)과 미션 멈춤(`repeatUntil` 의 `stallMs`)만 잡는다. 던전 입장처럼 오래 걸리는 기다림은 그 자리에 `timeoutMs` 를 넉넉히 적는다(`game-scenario.md` §3)
- **기능 케이스 120초 안에 준비 · 확인이 다 들어가야 한다** — 상태 도우미가 없어 준비를 플레이로 하는 케이스(퀘스트 진행 · 보스 처치)는 준비만으로 90초 넘게 걸린다. 그 뒤 단계는 알림이 사라지길 기다리지 말고 결과가 바로 보이는 것(그 줄이 「받음」으로 바뀜)을 기다린다(BRM-FN-458 — 준비 96초 + 보상 셋마다 알림 사라짐 기다림으로 두 번 시간 초과)
- **정해 둔 시간을 쉬지 않는다** — `new Promise((r) => setTimeout(r, …))` 도 같다. 무엇을 기다리는지 이름을 대고 그것을 기다린다
- 명령 하나는 15초 안에 끝나야 한다(디바이스 팜이 끊는다 — 게임 시나리오도 같다. kit 이 게임 시나리오에서 끄는 것은 명령 사이 쉬는 시간 한도다). 오래 기다릴 것은 `timeoutMs` 를 늘린다 — 짧은 찾기를 되풀이하는 꼴이라 괜찮다
- 「사라질 때까지」(`gone: true`)는 그것이 먼저 뜬 것을 본 뒤에만 앵커다 — 웹과 같다
- **여럿 생기는 것(몬스터 · 드랍 · 다른 캐릭터)을 「첫 번째」로 집지 않는다** — 상태 도우미로 정해진 자리에 하나만 두고 그 이름 · 경로로 찾는다(위 「남이 만든 데이터를 집지 않는다」와 같다). 자리를 못 박으면 바로 아래 줄이다
- **폰이 움직이는 것(봇 · 몬스터)에 기대지 않는다** (2026-10-25 GAME-F2-13) — 이동은 폰이 정해 서버가 자리를 못 박는다. 화면에 보이는 봇 하나를 골라 서버 상태를 바꾸고 이름표를 읽는 사이에 그 봇이 멀어지면 이름표가 사라진다(ASH-UI-106 — 보라 이름이 화면에 닿기까지 약 14초 동안 봇이 걸어가 RUN 20926 통과 · 20929 실패)
  - 상태 도우미로 캐릭터 곁에 둘 수 있으면 그렇게 한다(몬스터는 스폰 자리 · 봇은 가이드에 그런 API 가 있을 때만)
  - 없으면 **읽는 동안 사라졌을 때 보이는 다른 것을 골라 처음부터 다시 한다** — 고르기 · 상태 바꾸기 · 읽기를 한 묶음으로 세 번까지. 다시 고를 때는 이미 고른 것을 뺀다. 잠깐 안 보이는 것은 다시 그리는 중일 수 있어 3초 넘게 안 보일 때 사라진 것으로 본다. 기능 케이스 상한이 120초라 한도를 끝까지 기다리지 않는다
  - 상태를 바꾼 서버 값이 기대와 다르면 화면을 기다리지 않고 바로 그 판정으로 간다
  - 찾은 뒤 읽는 사이에도 사라질 수 있다 — `find` 로 본 뒤 `get` · `text` 가 던지면 다시 `find` 해서 없을 때만 「사라짐」으로 본다. 있는데 던졌으면 그대로 던진다
