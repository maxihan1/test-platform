## §5. 입력값 칸 — 실행 때 바꿀 수 있게 (2026-10-12 사용자 · PRD-F9-24)

⑧ 시험까지 케이스는 데이터를 안에서 만들고 계정만 입력값으로 받았다. MKT 472건 가운데 입력값 칸은 로그인 계정 38건뿐이라
사람이 실행 화면에서 아이디 · 검색어 · 상품 번호를 바꿔 돌려 볼 수 없었다. 실행 화면은 `params` 칸을 입력 폼으로 그리고(`.describe()` 가 라벨)
바꾼 값은 저장값 · 시나리오 부품에도 그대로 쓴다 — 케이스가 칸만 열면 된다.

### 무엇을 칸으로 여나

| 입력 | 칸 | 기본값 |
|---|---|---|
| 사람이 적는 글자 · 검색어 · 수량 | 연다 | 기획서 값, 없으면 데모 값 |
| 서버에 늘 있는 데이터 하나(상품 번호 · 게시글 번호 · 이름) | 연다 | 데모 값 — 서버마다 데이터가 달라 다른 서버에서는 사람이 바꾼다 |
| 경계값 분석의 시험 값 | 연다 | 설계 목록의 시험 값 그대로(`test-design.md`) |
| 사람이 적는 날짜 | `.optional()` 로 연다 | 두지 않는다 — 고정 날짜는 다른 날 틀린다. 비었으면 코드가 오늘 기준으로 만들고 그 규칙을 `.describe()` 에 적는다(「비우면 오늘부터 7일 뒤」) |
| 계정 | 지금처럼 비밀값 칸 | 없음(`5-writing.md` 「빼기 전에」 표) |

**열지 않는 것** — 조건으로 찾아 쓰는 값(날짜 · 순번으로 만들어지는 번호 · 다른 회차가 바꾸는 재고 — `5-stable.md`) · 케이스가 만들고 지우는 데이터의 번호 · 가짜 응답(모킹) 안의 값.
기획서가 범위를 안 정해 「바꿔도 같은 결과」를 못 적는 입력도 열지 않는다 — 범위를 지어내면 사람이 그 글을 믿고 엉뚱한 값을 넣는다

### 칸 쓰는 법

- **`.describe()` 에 칸 이름과 바꿔도 같은 결과가 나오는 범위를 적는다** — `z.string().describe('가입할 아이디 — 3자 이하 · 영문 소문자와 숫자').default('abc')`. 사람은 이 글만 보고 값을 고른다(꼴은 `wording.md`)
- **본문은 칸 값을 쓴다.** 기본값을 본문에 글자로 다시 적지 않는다. 화면 파일의 `열기(번호)` 에 기본 인자를 두지 않는다 — `열기()` 가 조용히 데모 번호를 연다
- **기대값은 코드에 그대로 둔다**(R10 — 사람이 판정한 값). 입력에 따라 결과가 바뀌면 기획서 규칙대로 코드에서 계산한다 — 「총 금액 = 단가 × 수량」이면 단가는 API 로 읽고 수량은 칸에서 받는다
- **입력값을 그대로 기대값에 넣지 않는다**(항등식 — `6-gates.md` 관문 4 ★★). 기획서가 「쓴 제목이 목록에 보인다」처럼 결과가 곧 입력이라고 정한 판정만 칸 값과 견주고, 그 판정은 관문 4 에서 조작을 바꿔 부순다
- 표의 `조작` · `결과` 칸에 「」 로 적은 값은 기본값이다. 절차 제목은 표 글자 그대로 둔다(R11) — 사람이 실행 때 값을 바꾸면 증적의 입력값 칸이 실제로 넣은 값을 보인다
- 칸 타입은 `string` · `number` · `boolean` · `enum` 만 쓴다. 실행 화면이 그것만 받는다
- 고칠 수 있는 칸이 생겼다고 케이스를 쪼개거나 합치지 않는다. 칸은 그 케이스 절차가 이미 쓰는 값에만 연다
