# /tpx-cases

체인 [5] 의 한 갈래. **1등급 인라인 구현 자리를 이 스킬이 대신한다.**
규율은 같다 — 초안 PR 은 [1] 이 이미 열었고, 게이트 2 는 [6] 이 받는다.

## 선행 읽기

**없음.** `/tpx` 가 이미 실었다. 이 스킬이 추가로 여는 것은 **본보기 케이스 한 건**뿐이다
(`tests/demo/DEMO-011.spec.ts` — `params`·`expected`·비밀값·`getByTestId` 가 한 파일에 다 있다).

---

## 척추 — 왜 이 순서인가

LLM 출력은 비결정적이다. 같은 기획서를 두 번 넣으면 두 번 다른 목록이 나온다.
**그래서 비결정성을 맨 앞 한 곳에 몰고 거기서 사람이 한 번 얼린다.**

```
기획서            ← 비결정. 여기서만 해석한다
   ↓
요구사항 정본 표   🛑 사람이 승인 → 이 표가 정본이 된다
   ↓
케이스 명세        ← 결정적. 표의 줄 하나 = 케이스 하나
   ↓
용어 사전          ← selector 를 한 곳에 모은다
   ↓
.spec.ts           ← 표의 칸이 코드 자리와 일대일
```

**§4 이후는 기획서를 다시 읽지 않는다.** 읽으면 비결정성이 뒤쪽까지 샌다.

## §1. 입력 확인

1. **기획서가 텍스트로 읽히는가.** `.md`·`.txt` 면 읽는다. `.docx`·`.pdf` 면 **변환하지 말고**
   「본문을 붙여넣어 달라」고 한 줄 요청하고 멈춘다
2. **tcId 접두사를 정한다.** 접두사는 **기획서 단위가 아니라 서비스 단위**다 —
   `apps/admin/src/catalog/routes.ts` 가 `tcId.startsWith(prefix + '-')` 로 남의 것을 걸러 낸다.
   정규식은 `^[A-Z][A-Z0-9]{0,11}$`
3. **대상 화면 주소를 받는다.** 없으면 selector 를 확정할 수 없으므로 멈추고 묻는다
4. **`docs/cases/<접두사>.md` 가 이미 있으면 먼저 읽는다** (→ R12)

## §2. 요구사항 표 — 분해 규칙

기획서 산문을 표로 옮긴다. **「한 문단이 1건인지 5건인지」를 두 번에 나눠 끊는다** —
R1 이 문단을 요구사항으로, R2~R4 가 요구사항을 축으로.

> **R1.** 요구사항 한 줄은 「누가 무엇을 하면 무엇이 된다」 하나다.
> 「그리고」·「또는」·「~하며」·「~되며」가 들어가면 **그 자리에서 줄을 나눈다.**
>
> **R2.** 케이스 1건 = 요구사항 1건 × 축 1개. 축은 셋뿐이다 —
> **정상**(적힌 대로 했을 때) · **경계**(0건·최대·마지막 하나) · **예외**(적힌 것을 어겼을 때).
>
> **R3.** 경계 축은 **기획서가 값의 범위·개수·상한을 적었을 때만** 만든다.
> 안 적혀 있으면 만들지 않는다.
>
> **R4.** 예외 축은 기획서가 실패·오류 화면을 적었을 때, 그중 **화면 조작만으로 일으킬 수 있는 것**만
> 만든다. 서버 응답을 바꿔야 일으킬 수 있는 것(500·타임아웃·외부 API 실패)은
> 표에 `모킹 필요` 로 남기고 **케이스를 만들지 않는다.**
>
> **R5. 상한** — 케이스 1건은 `test.step` 5개, `verify` 10문장, 화면 전환 3회를 넘지 않는다.
> 넘으면 두 건으로 쪼갠다.
>
> **R6. 하한** — 그 케이스에만 있는 판정이 하나는 있어야 한다.
> 앞 케이스가 이미 확인한 것을 다시 보기만 하는 케이스는 만들지 않는다.
>
> **R7.** 로그인·데이터 준비 같은 앞작업은 **그 케이스의 첫 스텝이 직접 한다.**
> `precondition` 에는 그 앞작업을 사람 말로 한 줄 적는다 —
> **증적 문서에 인쇄될 설명이지 실행되는 코드가 아니다.**
>
> **R8.** 한 요구사항에서 케이스가 4건을 넘으면 쪼개기가 덜 된 것이다. R1 로 돌아간다.
>
> **R9.** `platforms` 에 `mobile` 은 기획서가 모바일을 명시한 요구사항만. 아니면 생략한다(기본 `['desktop']`).
>
> **R10.** 한 번에 20건까지. 넘으면 기획서 절 단위로 나눠 여러 번 돌린다.
>
> **R11.** **케이스는 스스로 준비한다.** 다른 케이스가 남긴 상태에 기대지 않는다 —
> `apps/admin/src/execution/dispatcher.ts` 가 `Promise.all` 로 동시에 둘씩 돌리고,
> 사용자가 목록에서 **일부만 골라 실행**할 수 있다(SPEC §8.10). 순서 보장이 없다.

### 워딩 통일 — 자의적이지 않은 규칙 하나

「등록된다」·「반영된다」·「생성된다」·「추가된다」는 전부 같은 말이다. 하나로 모은다.

> **결과 칸은 「화면에서 눈으로 확인할 수 있는 문장」으로 적는다.**

「등록된다」는 눈에 안 보이고 「목록에 ~이 보인다」는 보인다.
이건 편의가 아니라 **필연**이다 — `verify()` 가 어차피 실제 값을 봐야 한다.

**바꿀 수 없는 문장은 판정 불가다.** 「적절히 처리한다」·「빠르게 응답한다」는
화면에서 확인할 문장으로 못 바꾼다. **지어내지 말고** 표에 `판정 불가` 와 사유를 남긴다.
그게 이 도구의 부수 가치다 — 기획서의 구멍을 드러낸다.

### 표 형식 — `docs/cases/<접두사>.md`

```markdown
# <접두사> — <서비스 이름> 요구사항

- 덮는 범위: <기획서 이름>(§1~§4). **그 밖의 기존 기능은 안 덮음**
- 케이스: `tests/<폴더>/`

| id | 축 | 전제 | 조작 | 결과 | 출처 | tcId | 상태 |
|----|----|------|------|------|------|------|------|
| R1 | 정상 | 목록이 비어 있다 | 입력칸에 「우유 사기」를 적고 Enter | 목록에 「우유 사기」 한 건이 보인다 | §2 첫문단 | — | — |
```

- **덮는 범위 줄을 반드시 적는다.** 기획서는 변경분만 적으므로 회귀 세트로는 구멍이 있다.
  **덮은 척하는 것보다 안 덮었다고 적힌 게 낫다**
- **개수를 손으로 적지 않는다.** 표 줄을 세면 된다 (CLAUDE.md §2.7⑤)
- `name`·`precondition` 을 표에 따로 옮겨 적지 않는다. **코드가 정본이다** (§2.7①)

## 🛑 §3. 내부 게이트 — 표를 승인받는다

표를 쓴 **직후** `AskUserQuestion` 으로 멈춘다. **산문 3지선다 금지.**

선택지 — `이대로 케이스 N건 만든다` / `표를 고쳐 달라` / `중단`

**근거** — 1등급은 게이트 1(계획 승인)이 없어서 파일 N 개를 다 쓴 뒤에야 사람이 본다.
분해가 어긋나 있으면 N 건을 통째로 다시 쓴다. **표는 싸고 케이스는 비싸다.**

승인된 표가 **정본**이다. 이후 단계는 표만 읽는다.

## §4. selector 확정 — 화면을 실제로 연다

**기획서에 없는 단 하나의 정보다.** 추측해 쓰면 문법은 통과하고 실행은 전부 실패한다.

```bash
node -e "
const {chromium}=require('@playwright/test');
(async()=>{
  const b=await chromium.launch();const p=await b.newPage();
  await p.goto('<대상 주소>');
  console.log(await p.locator('body').ariaSnapshot());
  console.log('testid:', await p.locator('[data-testid]').evaluateAll(e=>[...new Set(e.map(x=>x.dataset.testid))]));
  await b.close();
})()"
```

새 파일 0개 · 새 의존성 0개. 상호작용 뒤에 생기는 요소는 가운데에 `fill`/`press`/`click` 을
이어 붙여 **그 상태에서 다시 찍는다.**

| 상황 | 무엇을 쓰나 |
|---|---|
| 주소가 열려 있고 로그인 불필요 | **탐침** (기본) |
| 로그인·사내망 뒤 | 크롬 MCP(`navigate`+`read_page`)로 본 뒤 **탐침으로 재확인** |
| 그 요소가 화면에 없다 | **케이스를 만들지 않는다.** 표에 `보류(<사유>)` 로 남긴다 |

**locator 우선순위** `getByRole` > `getByPlaceholder` > `getByTestId` > `getByText`.
CSS 선택자·`nth()`·XPath 금지 — 화면이 조금만 바뀌어도 깨지고 왜 깨졌는지 검증 문장에 안 남는다.

**「일단 쓰고 실패하면 고친다」가 기본이 아닌 이유** — Playwright 는 「그 locator 를 기다리다
시간 초과」라고만 말한다. **무엇이 있는지는 안 알려 준다.** 탐침 없이 루프를 돌면 3회 규칙에 그냥 걸린다.

### 용어 사전 — 표 아래에 붙인다

```markdown
## 용어 사전

| 도메인 용어 | 화면에서 무엇 | locator |
|---|---|---|
| 할 일 입력칸 | 맨 위 텍스트 상자 | `getByPlaceholder('What needs to be done?')` |
```

**케이스 20건이 이 표 하나만 본다.** 화면이 바뀌면 고칠 자리가 한 곳이다.

> **R14.** **기대값은 「사람이 판정한 것」에서만 온다.** 근거는 기획서일 수도 PO 의 결정일 수도 있다.
> **화면에서 자동으로 오지 않는다** — 화면에서 읽는 것은 selector 와 「무엇이 있나」뿐이다.
> 현재 화면이 버그를 갖고 있으면 그 버그가 기대값으로 박히고, 회귀 세트라 **그 버그를 영원히 지킨다.**

## §5. 케이스 작성

본보기는 `tests/demo/DEMO-011.spec.ts`. 대상 주소는 데모 케이스와 같이 **직접 적는다**
(데모 8건이 전부 그렇다). 실제 서비스는 러너가 실행마다 `PLATFORM_BASE_URL` 로 넘긴다.

**표의 칸이 코드의 어느 자리로 가는지가 정해져 있다.**

| 표 칸 | 코드 자리 | 증적 문서 |
|---|---|---|
| 결과 | `name` · `verify` 첫 인자 | 검증 항목 · 판정 |
| 전제 | `precondition` | 사전조건 |
| 조작 | `test.step` 제목 | 시험 절차 |

> **R16.** 코드의 `name`·`precondition`·`test.step` 제목·`verify` 문장은
> 표의 해당 칸을 **글자 그대로** 옮긴다. 다듬고 싶으면 **표를 고치고 다시 옮긴다.**
> (§6 관문 2 의 비교가 문자열 일치로 끝나게 하려는 것이다)

### 가장 자주 걸리는 K 규칙 둘 — 쓰면서 확인한다

- **K10** `params`·`expected` 의 **모든 칸**에 `.default()` 또는 `.optional()`.
  하나라도 빠지면 정기 실행이 그 케이스를 못 돌린다
- **K9** 이름에 `password`·`passwd`·`pw`·`token`·`secret`·`apiKey`·`credential` 이 들어가면
  `.meta({ secret: true })` 필수

그 밖 — **K7 주석 0줄**(훅이 그 자리에서 막는다) · `expect` 직접 호출 금지 ·
**K6** `test.step` 제목과 `verify` 문장은 **문자열 리터럴** · **K4** `precondition`·`params`·`expected`
생략 불가(없으면 `[]`/`null`/`null`).

## §6. 검증 관문 넷

`package.json` 에 실재하는 이름만 쓴다. **파이프로 넘기지 않는다** — `| tail` 은 종료 코드를
`tail` 것으로 바꾼다.

```bash
npm run typecheck   > /tmp/tc.log 2>&1; echo "EXIT=$?"
npm run check:tests > /tmp/ct.log 2>&1; echo "EXIT=$?"
```

**관문 2 — 표를 따랐나.** 만든 `.spec.ts` 에서 `name`·`precondition`·`step` 제목·`verify` 문장을
뽑아 **표의 칸과 글자로 대조한다.** 실행을 안 하므로 넷 중 제일 싸다.

- 표에 있는데 코드에 없다 → **누락**
- 코드에 있는데 표에 없다 → **지어냈다**
- 문장이 다르다 → **약해졌거나 절차가 바뀌었다**

**약한 어설션을 금지 목록 없이 잡는 자리가 여기다.** 「목록이 비어있지 않다」는 금지어 목록에
없지만 표의 「목록에 「우유 사기」 한 건이 보인다」와 다르므로 걸린다.

```bash
npx playwright test tests/<폴더> --project=desktop --repeat-each=3 --reporter=line > /tmp/pw.log 2>&1; echo "EXIT=$?"
```

**관문 3 — 3회 연속 초록이어야 통과.** 2/3 면 초록이 아니라 **불안정**이고 대개 대기 누락이다.
`mobile` 을 선언한 케이스가 있으면 `--project=mobile` 도 한 번 더.

**★ 인자 없이 돌리지 않는다.** `DEMO-002` 는 일부러 실패하고 `DEMO-009` 는 모바일에서 실패한다
(SPEC §10). 전체를 돌리면 **빨강이 정상값**이라 내 실패가 그 속에 묻힌다.

**관문 4 — 일부러 부러뜨린다.** 케이스가 초록이 된 뒤 기대값을 한 칸 틀리게 바꿔 한 번 돌린다.
빨강이 뜨면 되돌리고 통과. **여전히 초록이면 그 케이스는 아무것도 확인하지 않는 것**이므로 다시 쓴다.
`spec-review` **G8** 이 이미 요구하는 것이고, 그 결과를 PR 에 적는다.

### 종료 조건 (CLAUDE.md §6)

1. 같은 케이스가 **같은 이유로 3회** 빨강 → **그 케이스만 멈춘다.** 파일을 지우고
   표의 상태를 `보류(<에러 첫 줄>)` 로 적고 **나머지는 계속 간다** — 케이스마다 문제가 다르다
2. 끝난 뒤 보류 목록을 CLAUDE.md §6 형식(하려던 것·시도 셋·에러 원문·가설·필요한 것)으로 한 번에 보고
3. **초록을 만들려고 케이스를 느슨하게 고치지 않는다** (CLAUDE.md §5).
   `verify` 를 지우거나 기대값을 실제값에 맞추는 것은 고친 게 아니라 **보류**다

## §7. 표 되채우기와 커밋

1. 표의 `tcId`·`상태` 칸을 채운다. 보류 줄은 **사유와 함께 남긴다** — 지우지 않는다
2. 실재 확인 — `grep -rho "tcId: '[^']*'" tests/<폴더> | sort` 와 표를 맞춘다
3. 커밋은 케이스 묶음이 초록이 될 때마다. `tests/**` 는 WS-C 소유이므로
   `[WS-C] <접두사> 케이스 N건: <무엇>` 형식

> **R12.** 기존 표가 있으면 **먼저 읽는다.** 새 요구사항마다 **더하기·바꾸기·없애기** 중
> 무엇인지 판정하고, **바꾸기면 기존 `tcId` 를 유지한 채** 케이스를 고친다.
> 번호를 새로 따면 「3개월째 초록이었는데 이번에 빨강」이라는 회귀 이력이 끊긴다.
>
> **R13.** **정본은 코드다.** 표와 코드가 어긋나면 **코드가 맞다.**
> 표를 고쳐서 코드를 바꾸는 게 아니라 **코드를 고치고 표를 갱신한다.**
> 표는 「어느 요구사항에서 왔나」를 남기는 기록이지 실행되는 물건이 아니다 —
> 이걸 잊으면 유지보수가 두 벌이 되고, 그게 Gherkin 이 죽은 자리다.
