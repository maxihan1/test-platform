잠금이 사라졌으므로 이 검사가 유일한 방어선이다 — 변경이 없으면 "변경 없음"으로 적고 넘어간다.

### B. 도메인 불변식 — 치명

SPEC §3에 적힌 불변식. 깨지면 데이터가 조용히 거짓이 된다.

### C. 경계 침범 — 중대

| # | 검사 | 통과 조건 |
|---|------|----------|
| C1 | 이번 작업 범위 밖 폴더를 건드렸는가. 건드렸으면 **계획이나 게이트 2 요약에** 이유가 적혀 있는가 | 이유가 있음 (계획이 없는 0·1등급은 게이트 2 요약만 본다) |
| C2 | Catalog / Execution / Reporting이 서로의 모듈을 직접 import 하는가 | 직접 import 없음 |
| C3 | 러너가 공유 볼륨(`artifacts/`) 외 경로에 파일을 쓰는가 | 쓰지 않음 |
| C4 | 주석이 **다른 파일이 막아 준다**를 근거로 위험을 안 막았으면, 그 파일을 열어 확인했는가 | 확인함 (또는 그런 주석 없음) |
| C5 | 계획의 `files` 에 적힌 파일이 **실제 diff 에 전부 있는가.** 없으면 왜 안 끝났는지 게이트 2 요약에 적혀 있는가 | 전부 있음 (또는 이유가 적혀 있음) |
| C6 | `[계약 변경 필요]` 블록의 `상태:` 를 닫았으면, **그 블록을 아직 `대기` 라 부르는 다른 문서**도 같이 닫았는가 (`grep -rn "상태: 대기" docs/` 와 앞 계획들의 「범위 밖」 표) | 같이 닫음 (또는 그렇게 부르는 곳 없음) |

C1은 `git diff --name-only origin/main...HEAD` 로 변경 파일 목록을 뽑아
계획의 `files` 와 대조한다.

**C5 는 C1 의 반대쪽이다.** C1 은 **밖으로 나간 것**만 본다 — 계획이 「고치겠다」고 적고
안 고친 자리는 C1 이 전부 초록으로 넘긴다.

**바뀐 파일 목록을 뽑아 계획의 `files` 와 대조한다.** 빠진 파일마다 이유를 묻는다 —
필요 없어졌으면 계획을 고치고, 잊은 것이면 그 자리에서 드러난다.
**문서는 특히 잘 빠진다** — 코드가 안 돌아 깨지는 것이 아니라 조용히 낡을 뿐이다.

**C6 은 C5 의 그물 밖을 본다.** C5 는 **계획이 「고치겠다」고 적은 자리**만 본다 —
`files` 에 아예 안 올라온 문서(앞 계획의 「범위 밖」 표 같은 것)는 거기서 빠진다.

**그대로 뒀으면 다음 세션이 「아직 대기구나」로 읽고 이미 접은 설계를 다시 집는다.**
`상태:` 를 닫는 것은 한 파일의 일이 아니다 — **그 블록을 가리키는 모든 문서의 일**이다.
`grep -rn "상태: 대기" docs/` 와 앞 계획들의 「범위 밖」·「다음 PR」 표를 같이 훑는다.

**C4 — 주석이 「다른 곳이 이미 막는다」고 하면 그 자리를 연다.** 한 경로에만 걸린 가드를 주석이
「언제나」라고 적는 일이 있다 (LEARNINGS 「문서가 규정한 것이 코드에 안 걸려 있다」).
**같은 파일의 다른 주석이 그렇게 말한다는 것은 근거가 아니다.** 해당 SQL·조건을 눈으로 센다.

**C1 은 기계가 안 본다** — 범위를 막는 훅이 없다 (`CLAUDE.md §1.1`).

그래서 이 항목은 「막았는가」가 아니라 **「범위를 벗어난 이유가 어딘가에 적혀 있는가」**를 본다.
벗어나는 것 자체는 금지가 아니다 (`CLAUDE.md §1.1`).

**어디를 보는지는 등급에 따라 다르다.** 계획 파일은 2등급 이상에만 있다.

| 등급 | 어디를 보나 |
|---|---|
| 0 · 1 | 게이트 2 요약 (계획 파일이 없다) |
| 2 · 3 | 계획의 `files` — 구현 중에 늘었으면 게이트 2 요약 |
| 명세만 바뀐 일(`spec` 차선) | 게이트 2 요약 (계획 파일이 없다 — `/tpx` §차선) |
