# spec-review — 체크리스트 D~F

### D. 용어 — 중대

| # | 검사 | 통과 조건 |
|---|------|----------|
| D1 | `testId`, `caseId`, `test_case_id` 등 `tcId` 외 표기가 있는가 | 없음 |
| D2 | `tcId` 값이 세 꼴 중 하나인가 — `<접두사>-<3자리>`(옛 꼴 · 기능) · `<접두사>-UI-<3자리>` · `<접두사>-FN-<3자리>`. 접두사는 `^[A-Z][A-Z0-9]{0,11}$` (SPEC §2, 2026-09-17 자유 형식 · 2026-10-02 종류 글자) | 일치 |
| D5 | 접두사의 **뜻**을 읽는 코드가 있는가 (앞 3글자를 잘라 기능 영역으로 쓰는 등) | 없음. 플랫폼은 모양과 중복만 본다 |
| D3 | Playwright `projects` 이름이 `desktop` / `mobile`과 철자까지 일치하는가 | 일치 |
| D4 | 화면 표기가 `PC` / `모바일`인가 (`desktop`/`mobile`은 코드 안에서만) | 일치 |

D1은 `grep -rn "testId\|caseId\|test_case_id" --include=*.ts` 로 확인한다.

### E. 테스트 코드 규칙 — 중대

`tests/**` 에만 적용된다.

| # | 검사 | 통과 조건 |
|---|------|----------|
| E1 | `npm run check:tests`가 통과하는가 (주석·expect·명세·describe·문장 — SPEC §4 K표는 기계가 본다) | 통과 |
| E2 | **§10 표에 적힌 케이스가 모두 있는가.** 개수를 여기 적지 않는다 — `docs/spec/공통/7-데모와-완료.md` §10 표가 정본이고, **표의 `tcId` 마다** `tests/demo/<tcId>.spec.ts` 가 있는지 본다. 건수로 대조하지 않는다 | 전부 있음 |
| E3 | `DEMO-008`~`010`이 디바이스 축을 실제로 검증하는가 | 검증함 |
| E4 | `name`·절차 제목·검증 문장이 검수자가 읽을 만한 한국어 문장인가 (기계가 못 보는 품질) | 읽힘 |

**E2 가 건수를 안 쓰는 이유** — `check:tests` 는 `tests/**` 의 **모든** 케이스를 세고, `tests/demo/` 에도
작성 에이전트가 만든 `DEMO-` 케이스가 들어온다. 건수로 대조하면 **멀쩡한 저장소에 중대 위반이 뜬다.**

### F. 화면 규칙 — 경미

| # | 검사 | 통과 조건 |
|---|------|----------|
| F1 | 목록 화면에 JSON 원문이 노출되는가 | 노출 없음 |
| F2 | 결과 목록이 케이스 1행에 디바이스별 판정을 묶어 표시하는가 | 묶음 |
| F3 | 입력 폼 라벨이 `describe()` 값에서 오는가, 하드코딩인가 | describe에서 옴 |
| F4 | 코드 뷰가 기본 접힌 상태인가 | 접힘 |
| F5 | 증적 문서에 코드나 `httpTrace`가 포함되는가 (**§8.4 의 모든 형식에서**) | 미포함 |
| F7 | 증적 엑셀이 **한 행 = 한 검증 문장**인가. 병합 셀을 쓰는가 (SPEC §8.4) | 한 행씩 · 병합 없음 |
| F6 | 판정을 색이나 아이콘만으로 전달하는 곳이 있는가 (글자 없이 색이나 아이콘만 — DESIGN.md 원칙 5) | 없음 |
| F8 | 색을 정해진 자리 밖에서 쓰는가 — ① 판정 색을 **판정 밖**에서 쓰는가(실패 색의 오류 표시만 예외 — DESIGN.md 원칙 1) ② **대표색**을 SPEC §8 「대표색」 목록 밖에서 쓰는가(그래프 금지 포함, 2026-10-07) ③ **껍데기 색(`--chrome`)**을 SPEC §8 껍데기 목록 밖에서 쓰는가(개편 전 코드에 남은 자리 — 로그인 링크 · 입력 포커스 — 는 묶음 1 WEB-F3-02 에서 정리하므로 그 전까지 잡지 않는다). 목록의 정본은 다 **SPEC §8** 이고 개수를 여기 적지 않는다 — §8 을 열어 대조한다. **서비스 색은 2026-09-22 에 화면에서 걷혔다** — 어느 자리에든 있으면 위반이다 (기계 검사는 `styles.test.ts`) | 그 밖에서 쓰지 않음 |
| F11 | 움직임이 DESIGN.md 원칙 4 를 어기는가 — 요소 하나가 0.3초를 넘는다(예외 둘: 숫자 올라가기 0.4초 · 실행 중 맥박 되풀이), 데이터를 그리는 움직임에 넘침 곡선을 쓴다, 처음 열 때 등장이 0.5초 안에 안 끝난다, 실행 중 표시 밖의 되풀이 움직임이 있다, `prefers-reduced-motion` 에서 꺼지지 않는다 (2026-10-07) | 어기는 것 없음 |
| F10 | **「구현이 다 됐다」·「미구현 0건」을 어딘가에 적는가.** 적는다면 근거가 「코드에 미구현 표시(TODO·throw)가 없다」뿐인가. SPEC §8 이 **요구하는 화면 자리**(고르는 상자·버튼)가 실제로 있는지 열어서 봤는가 (2026-09-20 에 형식 고르기가 없는데 「다 됐다」고 적었다) | 명세가 요구하는 자리를 열어서 확인했다 |
| F9 | 화면 파일(`apps/admin/src/web/*.tsx`)을 고쳤는데 같은 이름의 `*.test.tsx` 가 없는가. 있으면 그 화면의 규칙을 단언하는가 (2026-09-19 에 일부만 덮고 나머지는 「그 화면을 건드릴 때」로 넘겼다 — 몇 대 몇인지는 세어서 본다. `ls apps/admin/src/web/*.tsx \| grep -v '\.test\.tsx$' \| wc -l` 와 `ls apps/admin/src/web/*.test.tsx \| wc -l`) | 고친 화면마다 그물이 있다 |
