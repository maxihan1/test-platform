# /tp-spec

체인 [2]. **읽을 장을 좁혀 읽고, 계약 변경 여부를 판정한다.** 0·1등급은 진입하지 않는다.

## 선행 읽기

**없음.** `/tp` 가 `CLAUDE.md` · 색인 · LEARNINGS 발췌를 이미 실었다. **재로드 금지.**

## Step 1. 읽을 장을 좁힌다

`docs/SPEC.md` 색인의 **「갈래를 맡았을 때」 표**에서 이번 갈래 행을 찾아 **그 장만** 읽는다.

- 갈래가 없는 작업이면 **「기능을 더하거나 고칠 때」 라우터 표**에서 찾는다
- 어느 표에도 없으면 하네스 작업이다 — **「읽을 장 없음」으로 판정하고 넘어간다.** 억지로 읽지 않는다
- **전량(12장)을 읽지 않는다.** WS-0 과 integration 만 예외다

읽은 장과 줄 수를 PR 코멘트에 적는다. 이 숫자가 「한 번만 읽었다」의 증거다.

## Step 2. 계약을 건드리는지 판정한다

다음 넷 중 하나라도 바뀌면 **계약 변경**이다 (CLAUDE.md §1.2).

| 계약 | 어디 |
|---|---|
| Shared Kernel 타입 | `packages/kit/src/types.ts` |
| 러너 HTTP 요청·응답 형태 | SPEC §5.2 |
| DB 표·칸 이름 | `db/migrations/` · SPEC §6 |
| Admin API 경로·응답 형태 | SPEC §7 |

**「문서가 잠김·금지라 적어도 강제하는 장치를 먼저 확인한다」**(CLAUDE.md §1.2).
`guard.mjs` 의 `LOCKED` 는 2026-09-17 에 비워졌다. 산문만 보고 「못 바꾼다」고 판단하면
**없는 위반을 보고하게 된다.**

계약을 안 건드리면 `계약 변경: 없음` 을 적고 Step 4 로 간다.

## Step 3. 계약을 건드리면 — 게이트 0

**즉시 멈춘다.** 계획을 쓰지 않는다. CLAUDE.md §1.2 형식으로 `/tp` 에 반환한다.

```
[계약 변경 필요]
대상:    <무엇>
현재:    <지금 형태>
제안:    <바꿀 형태>
이유:    <왜>
영향:    <어느 갈래가 흔들리나>
```

`/tp` 가 🛑 **게이트 0** 을 낸다. 승인 없이 [3] 으로 넘어가지 않는다.

## Step 4. SPEC 을 고치기로 했으면 — §2.7 이 같이 움직인다

**★여기가 가장 잘 빠지는 자리다.**

승인을 받아 SPEC 을 고치는 것으로 끝이 아니다. `CLAUDE.md §2.7` 이 같이 움직일 것을 적어 뒀다.
2026-09-17~18 개정에서 「같은 규칙이 두 곳에서 다른 말을 하는」 일이 **아홉 번** 났고 전부 사후에 찾았다.

**이 단계는 §2.7 을 실행하지 않는다. [3] tp-plan 이 할 일로 만들게 목록을 넘긴다.**
지금 고치면 계획에 안 잡히고, 구현 단계가 빠뜨린 것을 아무도 못 본다.

`/tp` 에 아래 여섯을 **그대로 반환한다.**

### ① 같은 규칙이 적힌 다른 절 찾기

절 번호가 아니라 **고친 문장의 핵심 낱말로 12장을 전부 훑는다.** 같은 규칙이 다른 말로 적혀 있어
절만 보면 못 찾는다.

```bash
grep -rn "<핵심 낱말>" docs/spec/ docs/SPEC.md
```

- 도메인 절(§3.x)과 화면 절(§8.x)이 같은 것을 말하는 일이 잦다. **한 장 안에서도 어긋난다**
- **기계가 보는 규칙(§4 K표)을 특히 확인한다.** 산문이 바뀌어도 K표는 안 따라온다
- 정본을 **한 곳으로 정하고** 나머지는 그 절을 가리키게 한다. 내용을 옮겨 적으면 그게 다음 어긋남이다

### ② 뒤집은 결정을 지울지 남길지

| 어떤 경우 | 어떻게 |
|---|---|
| 판단 기준이 아직 쓸모 있다 | 문단을 **남기고 왜 뒤집었는지 덧붙인다** |
| 근거가 사실이 아니게 됐다 | **뺀다.** 무너진 근거를 남기면 다음 세션이 또 막힌다 |

### ③ 색인(`docs/SPEC.md`)은 표가 아니라 길잡이다

네 곳을 본다. **넷째를 가장 잘 빠뜨린다.**

1. 장 목록
2. 절 번호 → 장 표
3. 표 주인
4. **「기능을 더하거나 고칠 때」 라우터 표** — 새 개념을 만들었으면 *그걸 하려는 사람*이
   여기서 길을 찾아야 한다

절을 새로 만들면 **번호를 뒤에 더한다.** 기존 번호는 영구 주소다.

### ④ SPEC 밖 여섯 곳

| 어디 | 왜 |
|---|---|
| `docs/WORKSTREAMS.md` 킥오프 | **세션이 SPEC 보다 먼저 읽는다.** 여기가 틀리면 SPEC 을 열기 전에 이미 틀린다. **기계가 안 본다 — 눈으로 대조한다** |
| `spec-review` 체크리스트 · `npm run check:*` | 검사가 옛 기준이면 **초록불이 거짓말을 한다** |
| `docs/SETUP.md` · `docs/HOOKS.md` · `docs/DESIGN.md` | 사람이 따라 하는 절차와 화면 기준 |
| `docs/WORKFLOW.md` | 지금이 어느 단계이고 무엇이 남았는가 |
| `docs/design-mockup.html` | 화면 규칙이 바뀌었으면 |
| **코드에 박힌 상수** | SPEC 의 형식·숫자·열거값을 코드가 복사해 둔 자리. 정규식·상한 같은 것 |

**마지막 줄이 가장 늦게 드러난다.** 소유 밖이면 고치지 말고 그 갈래 킥오프에 항목으로 넘긴다.

### ⑤ 숫자를 손으로 적지 않는다

「검색 조건 다섯」·「바꿀 것 여섯」·「221군데」가 전부 조용히 틀려졌다.
**개수는 정본 표를 가리키고, 세는 일은 기계에 맡긴다.**

### ⑥ 검사

`npm run check:spec` → `spec-review` H 절. [6] tp-review 가 돌린다.
**같은 규칙이 두 곳에서 다른 말을 하는 것은 기계가 못 본다** — 사람이 게이트 2 에서 본다.

```

   ├─ 계약 변경: 없음 | 필요 (게이트 0)
   └─ §2.7 동반 수정: 해당 없음 | N곳 → [3] 이 할 일로 만든다
```

## 실패 / 엣지

- **색인 표에 이번 갈래 행이 없다** — 라우터 표를 본다. 거기도 없으면 「읽을 장 없음」
- **읽을 장이 1000줄을 넘는다** — 작업이 여러 갈래를 걸친다. 쪼갤지 `AskUserQuestion`
- **계약인지 애매하다** — 위 표 넷에 이름으로 있는지만 본다. 없으면 계약이 아니다
- **§2.7 ④ 의 파일이 소유 경로 밖이다** — 고치지 말고 할 일에 「그 갈래로 넘김」으로 적는다
