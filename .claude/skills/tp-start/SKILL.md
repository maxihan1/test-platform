# /tp-start

체인 [1]. **파일을 하나라도 고치기 전에** 판을 깐다. 전 등급 호출된다.

## 선행 읽기

**없음.** `/tp` 가 이미 실었다.

## ★ 순서를 어기지 않는다

**2026-09-18 실측.** 같은 세션 안에서 계획을 먼저 쓰고 PR 을 나중에 열었다.
한 세션 안에서도 드리프트가 난다. **기억에 맡기지 않고 여기 박아 둔다.**

```
1. 등급 판정      ← 이게 없으면 어느 단계를 도는지 모른다
2. 작업방 생성    ← 공유 체크아웃에서 고치지 않는다
3. 초안 PR 개설   ← ★ 파일을 하나라도 고치기 전에
4. 반환
```

**Step 3 을 건너뛴 채 다음 단계로 넘어가지 않는다.** 계획 파일도 PR 이 생긴 뒤에 쓴다.
넘어갔다는 것을 알아차리면 그 자리에서 멈추고 PR 부터 만든다.

## Step 0. 낡은 체크아웃으로 돌고 있지 않은지 본다

**가장 먼저 한다.** 뒤처진 체크아웃에서 시작하면 **낡은 스킬로 낡은 절차를 돈다.**

```bash
git fetch -q origin main
git rev-list --count main..origin/main
```

`0` 이 아니면 **멈추고 보고한다.** 여기서 고치려 하지 않는다 — 워크트리 안에서는
main 을 갱신할 방법이 git 에 없다 (`tp-merge` Step 4 에 근거).

```
⚠️ 메인 체크아웃이 <N>커밋 뒤처졌습니다.

   `.claude/skills/` 도 낡았을 수 있습니다 — 지금 도는 절차가 최신이 아닐 수 있습니다.
   먼저 이걸 돌려 주세요.

   ! cd <저장소 루트> && git pull
```

**2026-09-18 실측** — 세 번 병합하고 최신화를 안 해 여덟 커밋이 밀렸고,
새 스킬이 체크아웃에 없어 `/tp` 자체가 안 먹었다. `tp-merge` Step 4 가 이제 막지만,
사람이 직접 병합하거나 다른 기계에서 받아 왔을 때는 여기가 유일한 그물이다.

작업 자체는 `origin/main` 에서 따므로 멀쩡하다. **낡는 것은 사람이 열어 보는 자리와 스킬이다.**

## Step 1. 선언 등급을 잰다

**이번에 건드릴 경로**를 넣는다. 아직 diff 가 없으므로 사람이 아는 경로다.

```bash
node .claude/scripts/detect-tier.mjs <경로> [<경로>...]
```

출력 셋을 전부 받아 적는다 — `등급` · `표면` · `미분류`.

- **미분류가 나오면 조용히 넘기지 않는다.** 1등급으로 두되 그 줄을 PR 본문에 싣고
  게이트 2 요약까지 들고 간다
- 등급이 애매하면 **높은 쪽**을 선언한다. 실측이 낮으면 게이트 2 에서 내리면 된다

**이것은 선언이다.** 실측은 [6] tp-review 가 `git diff --name-only origin/main...HEAD` 로 다시 잰다.
**둘을 나란히 게이트 2 요약에 싣는다** — 자동 승격은 하지 않는다.

## Step 2. 작업방을 만든다

```bash
git status --porcelain          # 미커밋이 있으면 멈춘다
git fetch -q origin main
git worktree list               # 같은 이름이 있으면 -2 접미사
```

이름은 `<종류>-<한두-낱말>` 로 짓는다. 예 `ws-c-runner-3` · `setup-port-fix`.

```bash
git worktree add .claude/worktrees/<이름> -b <이름> origin/main
```

**갈래 작업이면 소유 경로 잠금을 켠다.** `guard.mjs` 의 `ownership` 모드가 이 환경변수를 본다.

```bash
export WORKSTREAM=<A|B|C|D|E|F>
```

갈래가 없는 작업(하네스·계약 반영)이면 **설정하지 않는다.** 설정하면 못 고칠 파일이 생긴다.

### 작업방 함정 둘

- **`node_modules` 는 상위로 올라가 저장소 루트 것을 쓴다.** 워크트리에 따로 만들지 않는다.
  루트에 없는 부품은 `npm run check:deps` 가 잡는다 — **Step 4 에서 먼저 돌린다**
- **`git stash` 를 맨몸으로 쓰지 않는다.** 스택이 모든 워크트리와 공유된다.
  치워 둘 것이 있으면 임시 커밋을 쓴다

## Step 3. ★ 초안 PR 을 연다 — 파일을 고치기 전에

```bash
git commit -q --allow-empty -m "chore: <이름> 시작"
git push -q -u origin <이름>
gh pr create --draft --title "[작업중] <제목>" --body-file <본문파일>
```

**초안(Draft)이라 병합 버튼이 눌리지 않는다.** 이것이 2026-09-17 에 두 번 난 사고
(#4→#5, #6→#7 — 먼저 병합돼서 뒤 커밋이 누락)를 막는 장치다.

**`gh pr ready` 는 이 스킬에서 절대 부르지 않는다.** 체인 전체에서 [7] tp-merge 한 곳뿐이다.
판별식 `pr-draft-guard` 가 이 규칙을 강제한다.

제목 앞의 `[작업중]` 도 [7] 에서 뗀다.

### PR 본문 뼈대

```markdown
## 무엇을 만드나

<한 문단. 왜 하는지까지>

## 확인 방법

<사용자가 직접 눌러볼 명령이나 클릭 경로. 코드를 보여주지 않는다>
```

그다음 진행 상태 블록을 얹는다.

```bash
node .claude/scripts/pr-update.mjs --pr <번호> --tier <등급> --step 1 \
  --next "<다음 멈춤>" --ws "<갈래>" --spec "<읽을 예정>"
node .claude/scripts/pr-update.mjs --pr <번호> --comment "### [1/7] 시작 완료
...
**다음.** <다음 단계>"
```

## Step 4. 판이 성한지 본다

```bash
npm run check:deps
```

누락이 있으면 **내 작업 때문이 아니다.** 고치지 말고 `/tp` 에 그대로 반환한다 —
사용자가 `npm install` 을 돌려야 한다. 이 검사가 2026-09-18 에 도구 호출 다섯 번을 잡아먹은
「내 변경인가 환경인가」 판별을 한 줄로 끝낸다.

## Step 5. 반환

`/tp` 에 돌려준다. 다음 단계는 컨트롤러가 등급으로 정한다 — 2등급 이상은 `/tp-spec`,
0·1등급은 곧장 구현 인라인.

## 출력

```
🔄 [1/7] tp-start
   ├─ 선언 등급: <N> · 표면: <목록> · 미분류: <경로 또는 없음>
   ├─ 작업방: .claude/worktrees/<이름> (브랜치 <이름>)
   ├─ 소유 경로 잠금: WORKSTREAM=<갈래> 또는 없음(하네스)
   ├─ check:deps: 통과 또는 누락 N개
   └─ 📋 초안 PR #<번호> — 파일을 고치기 전에 열었다
```

## 실패 / 엣지

- **미커밋 변경이 있다** — 작업방 생성을 막는다. `AskUserQuestion` 으로 셋 중 하나
  (임시 커밋 / 버리기 / 별도 작업방)
- **같은 이름 작업방이 있다** — `-2` 접미사. 단, A-0 에서 이미 물었어야 한다
- **`gh` 가 실패한다** (인증·한도) — 작업방은 유지하고 사용자에게 보고한다.
  **PR 없이 다음 단계로 넘어가지 않는다** — 상황판이 없으면 재개 지점도 없다
- **푸시 훅이 막는다** — 에러 원문을 읽는다. `npm test` 실패면 `git diff origin/main...HEAD` 로
  내 변경인지 먼저 본다. 환경 문제면 고치지 말고 보고한다
