## 9. 인프라

```yaml
# docker-compose.yml (구조만)
services:
  postgres:
    image: postgres:16
    restart: unless-stopped
    ports: ["127.0.0.1:${POSTGRES_PORT:-5433}:5432"]    # 바깥 포트는 .env로 뺀다. 이 기계 안에만 연다 — 망이 갈린 author 가 게이트웨이로 못 닿게 (2026-09-23)
    volumes: ["pgdata:/var/lib/postgresql/data"]
  admin:
    build:                            # FROM mcr.microsoft.com/playwright:<버전>-jammy (증적 PDF용 브라우저)
      context: .
      dockerfile: apps/admin/Dockerfile
      args:
        VITE_GRAFANA_PORT: "${GRAFANA_PORT:-3001}"   # 「그래프 ↗」 링크 주소. 화면 번들에 구워진다 (§9.2)
    restart: unless-stopped           # 재부팅 뒤 스스로 돌아온다. 기동 시 중단 복구가 돈다 (§3.2)
    ports: ["${ADMIN_PORT:-3000}:3000"]
    depends_on: [postgres]
    environment:
      SESSION_SECRET: "${SESSION_SECRET}"   # 로그인 세션 서명 키 (§3.5). 없으면 기동하지 않는다
      # 서비스 이름·색·저장소·대상 서버 주소는 환경변수가 아니라 DB 에 있다 (§6 service·service_env).
      # 2026-09-17 서비스 통합 전에는 PLATFORM_INSTANCE_* 넷이 여기 있었다 → §9.2
    volumes:
      - "./tests:/tests:ro"           # 스캔과 실패 지점 코드 발췌가 소스를 읽는다. 접두사별 하위 폴더 (§9.2)
      - "artifacts:/artifacts"        # 스크린샷 서빙, 증적 문서 저장
    networks: [default, authoring]    # author 가 admin 에만 닿게 따로 두는 망 (2026-09-23)
  runner:
    build: ./apps/runner              # FROM mcr.microsoft.com/playwright:<버전>-jammy
    restart: unless-stopped
    # 바깥 포트를 열지 않는다. admin이 컨테이너 네트워크 안에서만 부른다.
    # 러너에는 로그인이 없어 포트가 열려 있으면 인증을 건너뛰는 뒷길이 된다 (§3.5)
    volumes:
      - "./tests:/tests:ro"           # 테스트 소스 읽기 전용 마운트
      - "artifacts:/artifacts"        # 스크린샷 공유 볼륨 (admin과 공유)
    mem_limit: 4g                     # 폭주해도 admin을 끌고 내려가지 않게
  author:                             # 작성 에이전트 (2026-09-23). 선택 사항 — 아래 「작성 에이전트 컨테이너 author」
    profiles: [authoring]
    build: { context: ., dockerfile: apps/authoring/Dockerfile }   # playwright 이미지 + gh · pandoc · claude CLI(판 고정)
    restart: on-failure:5             # 토큰이 틀리면 [거부] 로 끝난다. 끝없이 다시 켜지 않는다
    user: "${HOST_UID:-1000}:${HOST_GID:-1000}"
    depends_on: [admin]
    environment:                      # PLATFORM_ADMIN_URL=http://admin:3000 · 토큰 셋 · DISABLE_AUTOUPDATER=1 — 아래 설정값 표
    mem_limit: 4g                     # claude + 관문 3회 Chromium
    shm_size: 1g
    volumes:
      - "./:/repo"                    # 작업방·PR·병합 뒤 당기기가 서버 저장소에서 일어난다
      - "/dev/null:/repo/.env:ro"     # 비밀값 파일을 자식 세션에게서 가린다
      - "author_node_modules:/repo/node_modules"
    networks: [authoring]             # admin 하고만. postgres·runner 에 못 닿는다
  grafana:
    image: grafana/grafana
    restart: unless-stopped
    ports: ["${GRAFANA_PORT:-3001}:3000"]
    depends_on: [postgres]
    volumes: ["./infra/grafana/provisioning:/etc/grafana/provisioning:ro"]   # WS-D가 채운다
volumes:
  pgdata: {}
  artifacts: {}
  author_node_modules: {}             # 리눅스용 부품. 시작 스크립트가 lock 해시로 맞춘다
networks:
  default: {}
  authoring: {}                       # admin · author 만
# 마이그레이션은 한 번 돌고 끝나는 일회성이라 restart를 붙이지 않는다
```

- 대상 서버: 2 vCPU / 16GB EC2 (Ubuntu)
- 동시 실행 2 고정 (Execution 디스패처). CPU가 2코어이므로 그 이상은 느려지기만 한다.
  Playwright 프로세스 하나는 케이스 1건만 돌리므로 `workers: 1`이다
- 러너와 admin 둘 다 Playwright 공식 이미지를 쓴다 (시스템 라이브러리 문제 회피. admin은 PDF용).
  이미지 태그와 `@playwright/test` 버전은 **정확히 같아야** 한다. 다르면 브라우저 바이너리를 못 찾는다
- 러너와 admin은 바깥 인터넷(HTTPS)으로 나갈 수 있어야 한다. 데모 대상이 공개 사이트다 (§10)
- `/tests`는 읽기 전용이라 그 안에 `node_modules`를 둘 수 없다. 러너 이미지가
  `@playwright/test`·`@platform/kit`·`zod`를 `/tests` 밖에서 resolve 되게 갖고 있어야 한다
- 스크린샷은 러너와 어드민이 **공유 볼륨**에 둔다.
  경로 규칙: `artifacts/runs/{runId}/{historyId}/{seq}.png`
  러너가 쓰고 어드민이 `/api/screenshots/...`로 서빙한다. 러너는 DB를 여전히 모른다
- 증적 문서는 `artifacts/evidence/{runId}/{id}.{html|pdf}`에 둔다. `evidence_document.file_path`가 이 경로다
- Grafana는 읽기 전용 DB 계정으로 붙는다. 계정은 Phase 0에서 만든다 (마이그레이션 또는 postgres init 스크립트)
- **바깥 포트는 전부 `.env`(컨테이너에 넘길 설정값을 적어 두는 파일)의 값으로 뺀다.** 기본값은 지금 쓰는 숫자 그대로다.
  숫자가 박혀 있으면 한 서버에서 다른 것과 포트를 다투고, 개발용과 운영용을 같이 띄울 수 없다
- **러너는 바깥 포트를 열지 않는다.** admin만 컨테이너 네트워크 안에서 `http://runner:4000`으로 부르면 된다.
  러너에는 로그인이 없으므로 4000이 열려 있으면 admin의 로그인 화면을 지나지 않고 아무나 테스트를 돌릴 수 있다
- **상시 서비스 넷(postgres·admin·runner·grafana)에 `restart: unless-stopped`를 붙인다.**
  서버가 재부팅돼도 사람이 손대지 않고 돌아온다. DB가 안 뜨면 admin의 재기동 복구(§3.2)도 돌지 못한다.
  마이그레이션은 한 번 돌고 끝나는 일회성이므로 붙이지 않는다 — 붙이면 끝날 때마다 다시 뜬다
- **화면 글꼴을 이미지 안에 담는다** (2026-09-18 결정). 바깥 주소(CDN)에서 받아오지 않는다.
  사내망에서 그 주소가 막히면 글꼴이 시스템 기본으로 조용히 떨어지고, 그러면
  **「숫자는 세로로 맞춘다」 규칙이 같이 깨진다** — TC ID·소요시간·응답 코드가 어긋난다.
  글꼴 파일은 화면 번들에 넣고 아래 빌드 단계가 이미지에 싣는다. 자세한 것은 DESIGN.md
- **이 줄은 화면 번들 이야기다. 증적 문서는 다른 길이다** — PDF·HTML 은 화면 CSS 를 타지 않으므로
  이미지에 글꼴이 있어도 이름으로 부르면 안 떨어진다. 정본은 **도메인/리포팅 §8.4** 다 (2026-09-20)
- **admin 이미지는 안에서 화면을 빌드한다.** `apps/admin/Dockerfile`에 화면 빌드 한 줄이 들어간다.
  `.dockerignore`(이미지를 만들 때 복사하지 않을 파일을 적어 두는 목록)가 `**/dist`를 막고 있어
  호스트에서 빌드한 산출물은 이미지에 들어가지 않는다. 이 단계가 없으면 컨테이너는 API만 내고 화면 주소는 빈 화면이 된다.
  `.dockerignore`는 그대로 둬도 된다 — 이미지 안에서 만든 파일은 복사를 타지 않는다
- **서비스 이름·색·테스트 저장소 주소·대상 서버 주소는 환경변수가 아니라 DB에 있다**
  (§6 `service`·`service_env`, 설정 화면은 §8.8). 2026-09-17에 뒤집은 결정이다.

  | 2026-09-16 | 2026-09-17 |
  |------------|------------|
  | `PLATFORM_INSTANCE_NAME`·`_COLOR`·`PLATFORM_TESTS_REPO` | `service` 표 |
  | `PLATFORM_ENV_URLS` (`dev=주소,qa=주소` 한 줄) | `service_env` 표 |

  **앞 판의 근거는 「인스턴스마다 서버가 두셋뿐이고 바뀌면 재기동하면 된다」였다.**
  한 벌이 서비스 여럿을 감당하면 서비스가 셋일 때 주소가 아홉 개라 한 줄에 안 들어가고,
  주소 하나를 고치려고 **전체를 재기동**하게 된다. 그래서 데이터로 내렸다
- **`SESSION_SECRET`은 환경변수로 남는다.** 로그인 세션을 서명하는 키라 DB에 둘 수 없다 (§3.5).
  값이 없으면 admin이 **기동을 거부한다** — 임시 키를 지어내면 재기동할 때마다 전원 로그아웃되고,
  그 사실을 아무도 모른 채 「가끔 로그인이 풀린다」로 겪는다
- `PLATFORM_BASE_URL`은 **실행마다 러너가 자식 프로세스에 넘기는 값**이라 `.env`에 두지 않는다 (§5.2).
  한 번 정하는 설정과 실행마다 바뀌는 값을 섞지 않는다

### 9.1 기술 스택 (2026-09-16 확정)

| 층 | 선택 | 비고 |
|----|------|------|
| 언어·런타임 | TypeScript, Node 20 이상, npm workspaces 모노레포 | Node 버전은 Playwright 이미지에 든 것을 따른다 |
| admin 서버 | Fastify | 컨텍스트별 `routes.ts`를 플러그인으로 등록한다 (WORKSTREAMS 공용 골격) |
| 화면 | React + Vite | `apps/admin/src/web/**`가 Vite 프로젝트. 빌드 산출물을 admin이 `/`에서 정적 서빙, API는 `/api/**` |
| DB 접근 | `pg` + 순수 SQL | ORM 없음. spec-review가 컬럼명을 grep으로 확인할 수 있어야 한다 |
| 마이그레이션 | SQL 파일 + dbmate | `db/migrations/*.sql`. compose의 일회성 서비스로 적용한다 |
| 명세·검증 | zod (JSON Schema 변환은 zod 내장 `z.toJSONSchema`) | §4. 별도 변환 패키지를 쓰지 않는다 — zod 4에서 동작하지 않아 2026-09-17 의존성에서 지웠다 |
| 단위 테스트 | Vitest | 각 앱 안 `*.test.ts`, 화면은 `*.test.tsx`. `tests/**`는 Playwright 전용 |
| E2E·데모 | Playwright | `tests/**` |
| PDF | Playwright `page.pdf()` | admin 안에서 (§3.3) |
| 엑셀 | exceljs | 증적 문서 XLSX (§8.4). 2026-09-18 승인 |

| 작성 에이전트 이미지 | `@anthropic-ai/claude-code`(판 고정) · `gh` · `pandoc` — **author 이미지에만**, 저장소 `package.json` 에는 안 든다 | 서버에서 케이스를 만들고(claude) PR 을 열고 병합하고(gh) 워드를 글자로 바꾼다(pandoc) | 맥에서 쓰던 도구를 그대로 서버로 옮긴 것이다. pandoc 은 맥 `textutil` 의 자리다 | 2026-09-23 게이트 0·1 |

**`exceljs` 를 고른 이유** — 같은 일을 하는 `xlsx`(SheetJS)는 라이선스와 취약점 이력이 있다.
읽기는 안 하고 **쓰기만** 하므로 기능 차이는 문제가 되지 않는다.

**`@testing-library/user-event` 와 `@testing-library/jest-dom` 은 안 들인다.** 누르기·타이핑은
`@testing-library/react` 에 이미 든 `fireEvent`(요소에 클릭·입력 같은 사건을 직접 쏘는 함수)로 되고,
단언은 `expect(el.textContent)` 처럼 **맨 DOM 값을 그대로 보는 것**으로 된다.
`toBeVisible` 같은 전용 단언이 없어도 같은 것을 본다.

**jsdom 에는 레이아웃 엔진**(요소가 화면 어디에 얼마만 한 크기로 놓이는지를 계산하는 부분)**도
CSS 계산도 없다.** 폭·높이·스크롤 위치가 전부 0 으로 나오고 `scrollIntoView` 는 아예 없으며,
스타일시트가 실제로 무슨 색·무슨 간격을 먹였는지도 물어볼 수 없다.
그래서 여기서 관측할 수 없는 것은 **「화면 밖에 그려졌다」 같은 배치 · 간격 · 색 · 애니메이션**이고,
그건 여전히 사람이 브라우저로 본다. 이 그물이 무는 것은 **거기 있다 · 이런 글자다 · 눌리면
이렇게 된다 · 접근성 꼬리표가 붙어 있다**까지다.
화면에 검사를 더 썼다는 것이 **그 부류를 봤다는 뜻이 아니다** — 이 그물을 치게 만든 사고가
바로 그 부류였다. 임시 비밀번호를 내놓을지 말지는 맞게 판정했는데 그 상자를 화면 밖에 그렸다.
`docs/DESIGN.md` 의 모달 규칙으로 재 보면 이 그물이 단언하는 것은 **행동·접근성 축뿐**이고,
바탕색·테두리·radius · 뒤 덮개 잉크 40%·blur 금지 · 폭 480px·좁은 화면 좌우 16px ·
애니메이션 없음은 **한 줄도 못 본다.**

**2026-09-21 에 그 사각지대가 실제로 물었다.** 모달 안의 진행 막대가 `flex-shrink` 로
높이 0 이 돼 화면에서 통째로 사라졌는데, 색도 비율도 맞아서 검사는 초록이었다.
`getBoundingClientRect()` 가 이 터에서는 늘 0 을 내므로 **높이를 재는 단언 자체가 성립하지 않는다.**

그래서 **못 재는 값 대신 그 값을 만드는 규칙의 존재를 단언한다** —
`apps/admin/src/web/styles.test.ts` 가 `styles.css` 글자를 읽어 그 규칙이 있는지 본다.
크기·겹침·줄바꿈은 여전히 사람이 브라우저로 보되, **본 뒤에는 기계가 볼 수 있는 모양으로 남긴다.**

**비밀번호 해시는 새 부품이 필요 없다.** Node에 이미 들어 있는 `crypto.scrypt`로 되는 것을
이 저장소의 Node로 실제 돌려 확인했다 (2026-09-16). 해시 생성·같은 값 일치·다른 값 불일치·
안전한 비교(`timingSafeEqual`)가 전부 내장으로 된다.

**Slack 알림도 부품이 필요 없다** (§8.9). 웹훅은 HTTPS 로 JSON 을 한 번 보내는 것이고
Node 20 에 `fetch` 가 들어 있다.

### 9.2 운영 (2026-09-16 결정)

#### 정기 실행

§8.5의 성공률 추이 패널은 같은 케이스가 **주기적으로 돌아야** 성립한다.
사람이 누를 때만 돌면 점이 흩어질 뿐이고, 그 점은 품질이 아니라 사람의 근무 시간을 그린다.

**테스트 대상이 아직 데모 사이트여도 켠다.** 지표의 내용보다 **장치가 실제로 도는지 검증**하는 것이 지금 목적이다.
성공률 추이 패널이 그려지는지, 정기 실행 경로가 도는지, 불안정한 케이스가 드러나는지가 여기서 확인된다.

- 매일 **새벽** 활성 케이스 전부를 한 번 돌린다. 사람이 쓰는 시간과 겹치면 동시 실행 2를 나눠 쓰게 된다
- 값은 **케이스 코드에 적힌 기본값**으로 돈다. 사람이 채워야만 도는 케이스가 없도록 §4 K10이 강제한다.
  저장된 입력값 묶음에 이름 약속을 만들지 않는다 — 진실의 원천은 코드다 (§3.1)
- 실행 제목은 `정기 실행 <날짜>`, 대상 서버는 `demo`, 반복 횟수는 1이다.
  반복은 테스트 코드를 검증하는 도구지 추이를 만드는 도구가 아니다 (§8.2)
- **실행자는 `스케줄러`다.** 사람이 아니므로 사람 이름을 받지 않는다 (§3.5)
- **거는 자리는 서버의 `cron`**(정해진 시각에 명령을 자동으로 돌려 주는 리눅스 기본 기능)이다.
  admin 안에 스케줄러를 넣지 않는다 — 컨테이너가 재기동될 때마다 다음 실행 시각이 흔들린다.
  나중에 화면에서 "무엇을 몇 시에"를 고르고 싶어지면 그때 스케줄 표를 만든다
- **하는 일은 HTTP 요청이 아니라 컨테이너 안의 명령이다** (2026-09-17 결정)

  ```
  docker compose exec admin npx tsx scripts/run-scheduled.ts <서비스 접두사>
  ```

  **앞 판은 `POST /api/runs`를 인증 없이 부르게 했다.** 그러려면 admin 바깥에 로그인을 거치지 않는
  문이 하나 열려 있어야 한다. §3.5가 러너 포트를 닫는 이유로 든 「로그인을 거치지 않고 실행을
  시킬 수 있는 뒷길」과 **같은 성질의 구멍**이다. 그래서 문을 내지 않고 안에서 만든다.
  계정 만들기(아래)와 같은 모양이라 **새로 배울 개념이 0개**다. 인증 경계는 §7이 정본이다
- 서비스마다 따로 건다. 접두사를 인자로 받아 그 서비스의 활성 케이스만 돈다
- **정기 실행은 Slack 알림을 항상 보낸다** (웹훅이 설정돼 있으면. §8.9).
  새벽에 진행되는 실행을 볼 사람이 없어 아침에 Slack 에서 보는 것이 유일한 경로다.
  사람이 돌리는 실행은 반대로 기본이 꺼짐이다 — 거기는 화면 앞에 사람이 있다

#### 배포 절차

배포는 한 줄이다.

```
git pull && docker compose up -d --build
```

- 마이그레이션은 compose의 일회성 서비스가 admin보다 먼저 돈다. 사람이 따로 칠 것이 없다
- admin은 기동할 때 카탈로그를 한 번 스캔하므로(§3.1) 배포 직후 케이스 목록이 최신이 된다
- 진행 중인 실행이 있는 중에 배포하면 그 실행은 끊긴다. admin이 부팅 직후 미완 항목을 닫고 `ABORTED`로 바꾼다 (§3.2).
  끊긴 실행이 영원히 `진행 중`으로 남는 것보다 낫다

#### 화면이 Grafana 포트를 아는 법

「그래프 ↗」 자리(§8)는 `GRAFANA_PORT` 를 **admin 이미지의 build arg `VITE_GRAFANA_PORT` 로 받아**
화면 번들에 구워 둔다 — `docker-compose.yml`(admin `build.args`) → `apps/admin/Dockerfile`(`ARG`·`ENV`) →
`apps/admin/src/web/layout.ts`. grafana 서비스의 포트 매핑은 실행 시점 값이라 화면까지 오지 않는다.

- **한계 — 값이 빌드 때 구워진다.** `GRAFANA_PORT` 를 바꾸면 **admin 이미지를 다시 빌드해야 한다.**
  안 하면 아무 오류도 없이 이 링크만 틀린 포트를 가리킨다. 위 배포 한 줄은 `--build` 가 붙어 있어 저절로 맞지만,
  `.env` 만 고치고 `docker compose up -d` 로 올리면 옛 번들이 그대로 뜬다
- **다른 길이 있었다** (2026-09-20 결정). admin 이 `index.html` 을 내줄 때 값을 심으면 실행 시점 값이라
  다시 빌드가 필요 없다. 정적 서빙에 치환 단계를 하나 더 얹어야 해서 이번에는 빌드 시 방식으로 갔다

#### 첫 계정과 첫 서비스 만들기

회원가입 화면은 없다 (§8.6). 계정은 **설정 화면에서 운영자가 만든다** (§8.8).
다만 **처음 한 번은 로그인할 사람이 아직 없으므로** 컨테이너 안에서 명령으로 만든다.

```
docker compose exec admin npx tsx scripts/add-user.ts <아이디> <이름> admin
docker compose exec admin npx tsx scripts/add-service.ts <접두사> <이름> --env <키>=<주소>
```

- **`--env` 를 하나 이상 넣는다** (2026-09-19). 대상 서버가 없으면 실행 설정의 드롭다운이 비고,
  안 고르면 실행 요청이 400 이다 — 서비스를 만들어도 아무것도 못 돌린다 (§8.2).
  여러 번 적을 수 있다. **인자와 그 밖의 절차는 [SETUP.md](../../SETUP.md)가 정본이다**
- **이 명령들이 이미지 안에 있어야 돈다.** `apps/admin/Dockerfile` 이 `scripts/` 를 싣는다 —
  2026-09-19 까지 안 싣고 있어 여기 적힌 첫걸음이 실제로는 `ERR_MODULE_NOT_FOUND` 로 죽었다.
  `apps/admin/src/deploy.test.ts` 가 그 줄이 사라지지 않았는지 본다

- 비밀번호는 이 명령이 무작위로 만들어 화면에 한 번 찍고 다시 보여주지 않는다.
  명령 인자로 비밀번호를 받으면 서버의 명령 이력에 평문으로 남는다
- 첫 계정은 **운영 등급**이어야 한다. 그래야 설정 화면에 들어가 나머지를 만들 수 있다 (§3.5)
- 두 번째부터는 명령을 쓰지 않는다. 설정 화면이 같은 일을 하고, 화면에서 만들면
  서비스 배정까지 한자리에서 끝난다
- 이 스크립트를 admin 안 어느 경로에 둘지는 공용 골격을 맡은 갈래가 정한다.
  **2026-09-18에 저장소 루트의 `scripts/`로 정했고 확장자는 `.ts`다.** 컨테이너가 이미 `tsx`로
  돌고 있어(`CMD ["npx","tsx",…]`) 명령도 같은 것으로 돈다. 순수 JavaScript로 두면 계정 만들기와
  실행 만들기를 **두 번째로 구현하게 된다** — 비밀번호 해시 형식과 `createRun`이 각각 두 벌이 되고,
  한쪽만 고치는 날 조용히 갈라진다

#### 서비스를 하나 더 만들 때 — 화면에서 한다 (2026-09-17 결정)

**이 자리에 「인스턴스를 하나 더 만들 때 바꿀 것 여섯」이 있었다.** 서비스마다 한 벌을 따로 띄우던
때의 절차다. 서비스를 합치면서(§1) **설정 파일 여섯 줄을 고치고 컨테이너를 새로 띄우던 일이
화면에서 항목 하나를 더하는 일이 됐다.** 절차를 지우고 어디로 갔는지만 남긴다.

| 앞 판에서 바꾸던 것 | 지금 |
|-------------------|------|
| 바깥 포트 · DB 주소 | **없어졌다.** 한 벌이라 한 번만 정한다 |
| 인스턴스 이름 (`PLATFORM_INSTANCE_NAME`) | 설정 화면의 서비스 이름 (§8.8 · §6 `service.name`) |
| 인스턴스 색 (`PLATFORM_INSTANCE_COLOR`) | 설정 화면의 서비스 색 (`service.color`) |
| 테스트 저장소 주소 (`PLATFORM_TESTS_REPO`) | 설정 화면의 테스트 저장소 (`service.tests_repo`) |
| 대상 서버 주소 (`.env` 한 줄) | 설정 화면의 대상 서버 표 (`service_env`). 서비스가 셋이면 주소가 아홉 개라 한 줄에 안 들어간다 |
| 테스트 폴더 마운트 | 아래 참조 |

배포 설정으로 남는 것은 한 벌을 띄울 때 한 번 정하는 값들뿐이다 —
`DATABASE_URL`·`RUNNER_URL`·`PLATFORM_TESTS_DIR`·`PLATFORM_ARTIFACTS_DIR`·`EXECUTION_CONCURRENCY`·`PORT`·`PLATFORM_PUBLIC_URL`·**`AUTHORING_AGENT_USER`**·**`PLATFORM_ADMIN_URL`**.

**`PLATFORM_ADMIN_URL` 은 작성 에이전트가 admin 을 부를 주소다** (2026-09-23 신설).
서버의 `author` 컨테이너는 compose 가 `http://admin:3000` 으로 채운다. 맥(대체 경로)은 compose 안의 이름으로 못 닿아
비우면 `http://localhost:3000` 을 본다. 평문 `http://` 는 `localhost` 와 compose 안의 `admin` 만 받는다.

#### 작성 에이전트 컨테이너 `author` (2026-09-23 신설)

**선택 사항이다** — compose profile `authoring`. 켜는 명령은 `docker compose --profile authoring up -d author`.
무엇을 지키고 왜 그런지의 정본은 `도메인/작성` §3.6 「★ 서버 컨테이너가 기본이다」 표다. 여기는 설정값만 적는다.

| 값 | 무엇 |
|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | `claude setup-token` 으로 만든 **구독** 토큰(`sk-ant-oat…`). 시작 스크립트가 모양을 본다. **고객사 서버는 그 회사 계정의 토큰** |
| `GH_TOKEN` | PR 열기·초안 풀기·병합 권한. 자식 세션에는 가짜 값으로 덮어 넘긴다 |
| `AUTHORING_AGENT_TOKEN` | 설정 > 계정 > 작성 계정의 에이전트 토큰. 에이전트만 쓰고 자식 세션에는 안 넘긴다 |
| `HOST_UID` · `HOST_GID` | 컨테이너를 돌릴 uid. 서버 저장소 주인과 같게 둔다. 비우면 `1000` |
| `AUTHORING_GIT_NAME` · `AUTHORING_GIT_EMAIL` | 커밋 작성자. 비우면 `test-platform authoring` |

이미지는 `apps/authoring/Dockerfile` — 러너와 같은 Playwright 태그 · `gh` · `pandoc` · `@anthropic-ai/claude-code` **판 고정**.
`node_modules` 는 `author_node_modules` 볼륨이다. 시작 스크립트가 `package-lock.json` 해시를 대조해 바뀌면 `npm ci` 한다.

**★ 맥(대체 경로)의 열쇠는 설정값으로 만들지 않는다** (2026-09-23 결정 · 같은 날 비밀번호 → 에이전트 토큰).
에이전트는 **처음 켤 때 한 번 에이전트 토큰을 묻고** 홈 폴더의 파일(`~/.test-platform/agent-token`, 본인만 읽기)에 둔다.
맥에서는 환경변수로 받지 않는다 — 셸 기록과 프로세스 목록에 샌다. 서버 컨테이너는 위 표대로 `.env` 에서 받는다.
토큰이 여는 통로·발급·취소의 정본은 `도메인/인증` §7 「인증 적용 범위」, 뒤집은 이유는 `도메인/작성` 결정표 「맥 계정의 비밀값을 어디에 두나」다.

**`AUTHORING_AGENT_USER` 는 작성 에이전트가 쓰는 계정 아이디다** (2026-09-22 신설).
집기·작업 단계 올리기·사진 올리기·끝났다고 알리기 넷은 **그 이름이 아니면 403** 이다.
**비면 아무도 못 집는다** — 열어 두면 그 서비스에 배정된 아무 `operator` 가 맥보다 먼저 집어
병합될 PR 주소를 자기 것으로 바꿔치기할 수 있다 (`도메인/작성` §3.6).
그 계정은 **`operator` 여야 한다** — `admin` 을 주면 맥에 저장된 비밀값 하나가 설정 자리 전부를 연다.
**사진은 새 설정값을 만들지 않는다** — `PLATFORM_ARTIFACTS_DIR` 아래 폴더를 가른다.

**`PLATFORM_PUBLIC_URL` 은 이 플랫폼이 바깥에서 열리는 주소다** (2026-09-18 신설).
Slack 알림의 `결과 보기`·`증적 문서` 링크가 이 값 위에 붙는다 (§8.9).
서버는 자기가 어떤 주소로 열리는지 모른다 — 앞에 프록시가 있으면 컨테이너 안쪽 포트와 다르다.
**비어 있으면 알림에 링크를 넣지 않고 본문만 보낸다.** 틀린 주소를 보내는 것보다 없는 편이 낫다.

#### 테스트 코드 저장소는 서비스마다 설정에서 넣는다 (2026-09-17 결정)

서비스마다 테스트 코드가 **다른 저장소**에 있다. 그래서 두 값을 설정 화면에서 받는다 (§8.8).

| 설정 | 무엇 | 플랫폼이 하는 일 |
|------|------|----------------|
| 테스트 저장소 (`tests_repo`) | 그 서비스의 저장소 주소 | ~~**적어 두기만 한다.**~~ 화면과 증적 문서 머리말에 기재되고, **2026-09-22 부터 판정에도 쓴다** — 작성 에이전트가 올린 PR 주소가 **정말 이 저장소의 것인지** 대조한다 (`도메인/작성` §7). **그래서 비어 있거나 `https://` 로 시작하지 않으면 그 서비스는 작성을 끝낼 수 없다** — 대조할 기준이 없으면 「아무 주소나 좋다」가 되어 다른 저장소의 PR 이 병합된다 |
| 테스트 폴더 (`tests_dir`) | 실제로 읽을 폴더. `PLATFORM_TESTS_DIR` 아래 상대경로 | 스캔과 실패 지점 코드 발췌가 여기를 읽는다 |

```
/tests                 ← PLATFORM_TESTS_DIR. 컨테이너에 마운트하는 뿌리 하나
  pay-e2e/…            ← 결제 서비스의 tests_dir. 저장소 하나가 통째로 들어온다
  member-tests/…       ← 회원 서비스의 tests_dir. 다른 저장소다
```

- **뿌리 마운트는 하나로 둔다.** 서비스가 늘 때마다 `docker-compose.yml`을 고쳐야 하면
  「화면에서 서비스를 만든다」(§8.8)가 반쪽이 된다. 저장소를 뿌리 아래에 받아 두고
  폴더 이름만 설정에 적는다
- **폴더 이름을 접두사와 묶지 않는다.** 저장소 이름은 조직이 이미 정해 둔 것이고,
  플랫폼 규칙에 맞추려고 저장소를 새로 파게 만들지 않는다
- 스캔은 **서비스마다 자기 폴더만** 훑는다. 다른 서비스의 폴더를 보지 않으므로
  접두사가 다른 케이스가 섞여 들어오지 않는다. 섞여 있으면 그 케이스는 스캔이 걸러 낸다 (§3.1)
- **플랫폼이 저장소에서 코드를 직접 받아오지 않는다.** 받아오기 시작하면 이 플랫폼이 배포 서버가 된다.
  폴더를 채우는 것은 배포 절차의 몫이다
