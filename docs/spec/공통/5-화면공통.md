## 8. 화면

### 껍데기 — 사이드바 · 헤더 · 푸터 (2026-09-21 결정)

한 벌이 서비스 여럿을 감당하므로(§1) **지금 어느 서비스를 보고 있는지**가 늘 보여야 한다.
엉뚱한 서비스에서 `실행`을 누르는 사고를 막는 장치가 서비스 고르개 하나다.
**2026-10-13 사용자 결정 — 서비스 고르개는 맨 위 헤더로 옮겼고 앱 대시보드에서도 둔다(PC 헤더 — 휴대폰 위 줄은 계속 숨긴다).** 앞 판(2026-10-07)은 대시보드에서만 고르개를 숨겼다 —
여러 서비스를 함께 보는 화면에서 고르개가 「이 서비스만」으로 읽힌다는 까닭이었다. 사용자가 대시보드에서 칸이 사라지는 것을 되돌려 달라고 했다.
**대시보드의 내용은 지금도 배정 서비스 전체다.** 대시보드의 칸은 내용을 거르지 않고, 다른 메뉴로 갈 때 쓸 서비스를 미리 고르는 용도다.
읽는 사람이 헷갈릴 수 있다는 근거는 남아 있어 탭 제목 · 바닥 글에는 서비스 이름을 계속 걸지 않는다(아래). 그 화면에는 `실행` 단추가 없다.

```
┌──────────────┬────────────────────────────────────────────────┐
│ QA Hub       │ [PAY 결제 서비스 ▾]      🔔2  🌐 한국어 ▾  김철수 ▾ │
├──────────────┼────────────────────────────────────────────────┤
│ 대시보드      │  테스트 스크립트 목록  [다시 스캔]               │
│ PRD 관리      ├────────────────────────────────────────────────┤
│ 테스트 작성   │   본문                                         │
│ 테스트 스크립트│                                                │
│ E2E 시나리오  │                                                │
│ 실행 기록     │                                                │
│ 그래프 ↗      │                                                │
│ 설정          ├────────────────────────────────────────────────┤
│              │ v0.4.0 · pay-e2e · 러너 정상                    │
└──────────────┴────────────────────────────────────────────────┘
```

- **맨 위 헤더 (2026-10-13 사용자 · 시안 A)** — 가로 한 줄이고 사이드바 · 본문과 다른 면에 앉는다. 왼쪽 칸은 사이드바와 같은 폭이고
  접으면 같이 좁아져 체크 마크만 남는다. 위에서부터가 아니라 왼쪽에서 오른쪽으로 읽는다.
  - **「QA Hub」 로고** — 맨 왼쪽. 체크 마크와 글자(`QA` 는 잉크, `Hub` 는 대표색 — 위 대표색 목록 「로고」). 누르면 「집」으로 간다(아래 「집」 줄)
  - **서비스 고르개** — 로고 옆. 접두사 칩과 서비스 이름을 한 상자에 담은 높이 32px 의 작은 칸이다(앞 판은 사이드바 맨 위의 넓은 칸이었다).
    무엇을 고르는 자리인지 적던 이름표(`서비스`)는 없앴다 — 칸 안에 서비스 이름이 그대로 보인다. 읽어 주는 이름은 `서비스 선택`
  - **오른쪽 끝 묶음** — `알림` 버튼(종 아이콘과 안 읽은 수 배지, 읽어 주는 이름은 `알림`) · 언어 고르개(지구본 아이콘 + `한국어` / `English`) · 계정 메뉴
  - **계정 메뉴** — 로그인한 사람 이름(§8.6). 누르면 `비밀번호 변경`과 `로그아웃`이 펼쳐지고 바깥을 누르거나 Esc 를 누르면 닫힌다.
    앞 판은 사이드바 바닥에 이름 · 언어 · `로그아웃` · `비밀번호 변경`을 늘 펼쳐 두었다
  - 사이드바를 접어도 헤더의 칸은 그대로 키보드로 닿는다 — 접히는 것은 로고 글자뿐이다
  - **휴대폰에는 이 헤더가 없다** — 위 줄과 아래 탭이다(아래 「휴대폰 화면」)
- **왼쪽 사이드바** — **자리 목록**만 든다. 진행 · 완료 알림 줄은 사이드바가 아니라 본문 맨 위 줄이다(아래 「알림」, 2026-10-11).
  바탕은 짙은 색(DESIGN.md 의 `--rail`)이고 글자는 밝다
- **사이드바는 접을 수 있다 (2026-09-21 추가).** 접으면 44px 레일만 남고 본문이 그만큼 넓어진다.
  접은 상태는 **브라우저에 남아 새로고침해도 유지된다** — 새로고침마다 다시 접게 하면 그 기능이 짐이 된다.
  - **접어도 자리 목록을 화면에서 지우지 않는다.** 글자만 숨기고 요소는 남긴다 —
    지우면 키보드 탭 대상에서 빠져 **키보드로만 쓰는 사람이 이동을 통째로 잃는다.**
    이것은 「등급이 낮아서 못 하는 것은 보이지 않는다」와 다른 자리다 —
    그쪽은 **영영 못 하는 것**이고, 접기는 **사람이 방금 접었고 언제든 되돌리는 것**이다
  - **지금 있는 자리 표시는 접힌 채로도 보인다.** 어디에 있는지를 잃으면 접기가 길을 잃게 만든다
  - **휴대폰에는 사이드바가 없다** — 위 줄과 아래 탭이다(아래 「휴대폰 화면」, 2026-10-12). 앞 판은 사이드바를 가로 줄로 접어 그려서 거기서는 접지 않았다
- **화면 머리** — 지금 보고 있는 화면의 제목과 **그 화면의 주 행동** 버튼(아래 「화면 머리」 절. 맨 위 헤더와 다른 것이다).
  본문과 **다른 면**에 앉고 경계선이 그어진다. 어느 것이 주 행동인지는 그 화면의 절이 정한다
- **푸터** — 제품 버전 · 테스트 저장소 주소 · 러너 상태
- 서비스 고르개에 **접두사 칩과 서비스 이름**을 적는다(2026-10-13 — 접두사를 칩으로 다시 보인다. 2026-09-22 에 걷은 것은 `DEMO-` 꼴의 접두사 표시와 서비스 색이고, 헤더 칩은 서비스를 구분하는 글자 하나다). **테스트 저장소 주소**는 푸터 몫이다.
  브라우저 탭 제목도 `<서비스 이름> · 테스트 플랫폼`으로 한다. 탭이 여럿일 때는 탭 글자만 보인다.
  **대시보드만 `테스트 플랫폼` 이다 — 바닥 글도 서비스 이름을 걸지 않는다 (2026-10-07 게이트 2 사용자).** 대시보드에도 고르개가 있지만(2026-10-13) 내용은 서비스 하나가 아니다 — 「고른 서비스」 이름이 탭과 바닥 글에 걸리면 여러 서비스를 함께 보는 화면이 「이 서비스만」으로 읽힌다
- **서비스 색을 화면에서 쓰지 않는다 (2026-09-22 결정).**
  **본문이든 껍데기든 어느 자리에도 없다.** 서비스는 **이름과 저장소 주소**로 구분한다.

  **왜 뒤집었나** — 「글자는 읽어야 보이고 색은 안 읽어도 구분된다」가 색을 둔 이유였다.
  그런데 실제로 쓴 사람이 **「이 파란 네모가 뭘 뜻하는지 모르겠다」**고 했다.
  안 읽어도 구분되기는 하는데 **무엇으로 구분되는지를 모르면 구분이 아니다.**
  색은 이름을 대신하지 못하고, 이름 옆에 있으면 더 설명할 것만 는다.

  **막으려던 사고(엉뚱한 서비스에서 실행)는 그대로 막힌다.** 고르개는 맨 위 헤더라
  어느 화면에서든 같은 자리에 걸리고(2026-10-13 부터 대시보드에도 있다), **거기 적힌 서비스 이름을 읽으면 된다.**
  막던 것은 네모가 아니라 **고르개가 늘 같은 자리에 있다는 사실**이었다.

  **자리를 옮겨 온 내력을 남겨 둔다** — 띠 바탕 → 자리 목록 줄의 네모와 3px 경계선 →
  사이드바 고르개의 네모 (전부 2026-09-21). **세 번 옮겨도 「무엇을 뜻하는지」는 안 풀렸다.**
  옮길 자리를 더 찾는 대신 걷은 이유가 이것이다. 색을 다시 쓰고 싶어지면
  **먼저 「색 옆에 이름이 있는데 색이 무엇을 더해 주나」에 답한다.**

- **`service.color` 칸은 DB 에 남는다.** 지우는 것은 마이그레이션이라 되돌릴 수 없고(CLAUDE.md §5),
  서비스가 여럿이 되어 색을 다시 쓸 날이 오면 값이 그대로 있다.
  **화면이 안 읽을 뿐이다.** 새 서비스를 만들 때 화면이 중립 기본값 하나를 보낸다 —
  그 칸이 INSERT 필수라서 그렇고, 그 사실을 코드 주석이 적는다.
- **판정 색은 언제나 판정이다.** DESIGN.md 원칙 1 의 「판정 색은 판정에만」에
  이제 **서비스 색이라는 구멍이 없다.**
- **대표색은 이 자리에만 쓴다 (2026-10-07 사용자 결정 · 코드 반영 끝 — PR #172).**
  누를 수 있는 것, 지금 고른 것, 지금 진행 중인 것을 알리는 색이다.
  - 주 버튼 — 화면 머리의 주 행동처럼 그 화면에서 가장 흔한 다음 행동. 나머지 버튼은 테두리만 쓴다
  - **지금 있는 자리** 표시 — 사이드바의 왼쪽 막대, 화면 안 탭의 밑줄, 고른 카드의 테두리, 설정 안 메뉴의 왼쪽 막대(2026-10-09 · 도메인/인증 §8.8), 휴대폰 아래 탭의 윗막대와 실행 기록 하위 줄의 고른 칩 테두리(2026-10-12 · 아래 「휴대폰 화면」)
  - 링크 — 줄 제목 링크(시나리오 이름 · 결과 칩처럼 줄을 여는 길)는 잉크다. 대표색이 아니다
  - **실행 중** 표시 — 실행이 도는 동안의 맥박 점
  - 알림 개수 배지 — 알림은 판정이 아니라 판정 색(진홍)을 쓰지 않는다. 알림 서랍의 안 읽음 점과 고른 거르기 칩 테두리도 같은 뜻이라 대표색이다(2026-10-11)
  - 로고

  (실행 중 · 알림 배지 · 로고는 2026-10-07 시안 확정 때 더했다)

  **이 목록 밖에서는 쓰지 않는다. 그래프에도 쓰지 않는다** — 그래프 수치는 판정 색과 회색 단계로 그린다
  (시안에서 오렌지를 일곱 자리에 쓰자 흐려졌다는 디자인 리뷰 지적, 2026-10-07).
  판정 색과 색조가 겹치지 않는 값이어야 하고, 값은 DESIGN.md 「토큰」 절이 정본이다.
  **이 목록이 정본이고 DESIGN.md 는 여기를 가리킨다** — 아래 껍데기 목록과 같은 이유다.
  **왜 열었나** — 앞 판은 「본문의 색은 언제나 판정이다」였다. 버튼과 링크가 글자와 같은 잉크라
  누를 것과 읽을 것이 갈리지 않았고, 사용자가 고객사나 포트폴리오에 내놓기에는 「전문성 없는 단순 어드민」 같다고 했다.
  막으려던 일(판정이 아닌 것이 판정처럼 보이는 것)은 판정 색을 판정 밖에 쓰지 않는 것으로 계속 막는다
- **껍데기에도 판정이 아닌 색을 쓴다 (2026-09-21 · 2026-10-07 위 대표색 목록으로 합쳤다).** 지금 코드의 자리는 이렇다.
  - 지금 있는 자리 표시(사이드바의 막대 · 탭 밑줄 · 설정 안 메뉴의 막대 · 휴대폰 아래 탭의 윗막대 · 휴대폰 하위 줄의 고른 칩 테두리) · 고른 카드의 테두리 — 대표색이다. E2E 조립 화면의 고른 카드는 도메인/시나리오 §8.11 · DESIGN.md 원칙 2 예외
  - 표머리 라벨과 구획 제목 라벨 — `--ink-muted` 잉크다
  - 사이드바 — 가장 짙은 면 `--rail` 이다

  **이 목록 밖에서는 쓰지 않는다.** 행 안에서, 배지에서, 본문 글자에서 판정 색을 보면 그것은 여전히 판정이다.
  금지를 통째로 푸는 대신 자리를 못 박아 구멍의 크기를 고정한다.
  **개수를 적지 않는다 (2026-09-21 수정).** 처음에는 「넷뿐이다」라고 적었는데
  DESIGN.md 도 같은 숫자를 손으로 적고 있었다 — 자리가 하나 늘거나 주는 날 한쪽만 고쳐진다.
  **이 목록이 정본이고 DESIGN.md 는 여기를 가리킨다** (CLAUDE.md §2.7 ⑤)
- 서비스 고르개의 목록에는 **배정받은 서비스만** 뜬다 (`GET /api/auth/me`의 `services`, §7)
- **한 번에 한 서비스만 본다. 앱 대시보드만 예외다.** 여러 서비스가 한 목록에 섞이지 않는다.
  세 서비스를 맡은 사람이 「오늘 다 괜찮나」를 보려면 세 번 전환해야 했고, 그 갈증을 처음에는 Grafana(§8.5)에서 풀기로 했다.
  **2026-10-07 사용자 결정** — 앱 안 `대시보드`(도메인/리포팅 §8.12)가 사이드바 맨 위에 서서 **테스트 결과**(통과율 · 신규 실패 · 일별 · 서비스별)로
  이 갈증을 푼다. 그 화면만 배정 서비스를 가로질러 모은다. 서비스 고르개는 2026-10-13 부터 이 화면에도 있다(내용을 거르지 않는다). Grafana 는 실행 · 작성에 걸린 시간 같은 운영 지표를 맡는다
- 서비스 이름·색·저장소 주소는 설정 화면(§8.8)에서 정한다. 화면이 값을 지어내지 않는다

**2026-09-16에는 이 자리가 「인스턴스 띠」였다.** 서비스마다 한 벌을 따로 띄우던 때라
그 자리는 고르는 자리가 아니라 **알리는 자리**였고, 「인스턴스를 고르는 화면은 만들지 않는다」가 규칙이었다.
서비스를 합치면서(§1) 고르는 자리가 됐다. 막으려던 사고(엉뚱한 쪽에서 실행)는 그대로라 고르는 자리는 남는다.
**2026-09-21 에 그 자리가 맨 위 가로 띠에서 사이드바 맨 위로 옮겨 갔다.** 옮긴 것은 위치이고 역할은 그대로다.
**2026-10-13 에 사이드바 맨 위에서 맨 위 헤더로 한 번 더 옮겼다**(로고 · 알림 · 언어 · 계정 메뉴와 같이). 이번에도 위치만 바뀌었고 역할은 그대로다.

### 화면 머리 — 제목 · 부제 · 주 행동 (2026-09-22 결정)

**본문 면 바깥에, 본문과 다른 면으로 선다.** 같은 바탕에 얹으면 처음 지적인
「헤드와 메인이 분리 안 돼 있다」로 되돌아간다.

| 자리 | 무엇 | 없으면 |
|------|------|--------|
| 제목 | 이 화면이 무엇인가. `h1` 하나 | — (늘 있다) |
| 부제 | 지금 무엇을 보여주고 있는가. `모두 42건` · `대상 서버 qa` · **그 화면이 마지막으로 무엇을 했는가** | 줄 자체를 안 만든다 |
| 주 행동 | 이 화면에서 가장 흔한 다음 행동. `다시 스캔` · `전체 실행` | 자리를 안 만든다 |

- **껍데기가 아니라 화면이 그린다.** 부제는 동적이고(`모두 42건`) 행동도 상태를 탄다(`스캔하는 중`) —
  껍데기에 통로를 뚫으면 화면마다 그것을 위로 올려 보내야 해서 배선만 는다.
  **2026-09-21 에 실제로 그 통로를 뚫었는데 부르는 곳이 하나도 없었다** (2026-09-22 에 걷어냈다)
- **빈 자리를 잡아 두지 않는다.** 부제도 행동도 없으면 제목 한 줄이다
- **부제가 「마지막으로 무엇을 했는가」까지 받는다 (2026-09-22 확장).** 케이스 목록의 스캔 결과와
  그 **실패 사유**가 그 예다 ([도메인/카탈로그.md](../도메인/카탈로그.md) §8.1).
  앞 판은 그런 것을 목록 위에 따로 줄로 뒀는데, 표가 창을 채우는 화면에서는 그 줄이 그대로 표에서 빠졌다.
  **부제로 옮기면 자리만 옮기고 적히는 것은 안 줄어든다** — 실패 사유를 빼면 안 된다.
  성공은 `--ink-faint`, 실패는 `--fail` 이다 (DESIGN.md 원칙 1 의 판정 색이 아니라 오류 색이다)
- 좁은 화면에서는 세로로 쌓이고 행동 버튼은 44px 이다. 휴대폰 실행 결과의 `실패 N건 다시 실행` 은 아래 탭 위에 붙는다 (아래 「휴대폰 화면」)
- **제목 칸이 모자라면 행동 버튼 묶음이 아랫줄로 내려간다** (2026-10-09 · 진행판 WEB-F2-10). 앞 판은 버튼 묶음이 줄어들지 않아
  케이스를 골라 버튼이 셋 · 넷으로 늘면 제목이 한 자씩 세로로 서고 목록 높이가 0 이 됐다(700px 창 · 사이드바 폄). 제목에 기준 폭을 두고 버튼은 그 뒤에 줄을 넘는다
- 색값·간격·글자 크기는 `docs/DESIGN.md`, 기계 검사는 `apps/admin/src/web/styles.test.ts`

실행 기록은 **「돌린 뒤」**라 그 뒤에 남는다.
**`테스트 작성` 은 기획서(만들 테스트를 말로 적어 둔 요구사항 문서)를 넣어 테스트를 만들고, 만들어진 것을 보고,
머지(만든 것을 본 저장소에 합치는 일)까지 하는 곳이다.** `테스트 스크립트` 는 **이미 있는 것을 보는 곳**이고
작성은 **아직 없는 것을 만드는 곳**이라 성격이 다르다.

**`PRD 관리` 는 `테스트 작성` 바로 앞이다 (2026-10-10).** 표준 기획서(PRD — 서비스의 요구를 규칙 하나씩 고정 번호로 적은 것)를 보고 고치고 확정하는 곳이고,

  집은 대시보드 → `테스트 스크립트` → `테스트 작성` → `실행 기록` 순으로 남은 자리 중 첫 자리다 — 앞이 `none` 이면 다음이 집이다. 집을 바꾸려면 이 줄과 `route.ts` 의 `집()` 을 같이 고친다.
  **`PRD 관리` 는 집이 되지 않는다** (2026-10-10) — 같은 작성 칸이라 `테스트 작성` 이 집이다.
  케이스 · 작성 · 실행 · 대시보드(사람의 dashboard 칸 — Grafana) 네 칸이 다 `none` 이면 `권한을 받지 않았습니다. 운영자에게 요청하세요` 한 줄만 보인다 — 서비스 0건 안내보다 먼저다
- **하위 메뉴 — 테스트 종류 (2026-10-02 사용자 시안 A · PR #132).** `테스트 스크립트` 와 `실행 기록` 아래에 `UI 테스트` · `기능 테스트` 를 **늘 펼쳐 둔다.**
  영어는 `UI tests` · `Functional tests`. 주소는 `#/cases/ui` · `#/cases/fn` · `#/runs/ui` · `#/runs/fn` 이고 **종류 없는 옛 주소와 묶음 이름은 기능 테스트로 간다** — 지금 케이스가 전부 기능이라서다.
  - 지금 자리가 하위면 **하위가 표시(막대)를 갖고 묶음은 글자만 밝힌다.** 종류를 모르는 상세(실행 결과 · 항목 · 옛 주소 `#/cases/:id/run`)에서는 묶음만 펼친 표시를 받는다 —
    묶음 링크는 기능 목록으로 가므로 「지금 자리」(`aria-current`)라고 하지 않는다. 접힌 레일에서는 펼친 묶음이 막대를 받는다. 묶음은 이름 붙은 묶음(`role="group"`)으로 읽힌다
  - 같은 글자가 두 묶음에 나오므로 하위 링크는 `실행 기록 · UI 테스트` 처럼 묶음 이름을 단 이름(aria-label)으로 읽힌다
  - **접어도 하위를 지우지 않는다** — 위 자리 목록과 같이 글자만 숨겨 탭이 닿게 두고, 접힌 레일에서는 지금 자리를 가진 묶음이 막대를 받는다
  - 휴대폰에는 사이드바가 없어 실행 기록의 하위만 목록 위 고르개 줄로 놓는다(아래 「휴대폰 화면」)
  - **`실행 기록 › E2E` 는 셋째 하위 메뉴다** — 시나리오 실행 화면과 함께 넣었다(PR #165, 2026-10-07). 누를 곳이 없는 메뉴는 두지 않는다(§8.6). `E2E 시나리오` 자리(`#/scenarios`)와는 다른 것이다(만드는 곳 ↔ 돌린 기록)
  - 종류를 바꾸면 목록을 새로 그린다 — 고른 것 · 쪽 · 검색어가 남으면 UI 와 기능을 섞어 골라 실행이 거절된다(도메인/실행 §7 `MIXED_KIND`)
  - **이름 「테스트 케이스」를 「테스트 스크립트」로 바꿨다** (2026-10-02 사용자 「나중에」 → 2026-10-09 반영 — 위 「세 번째로 바뀌었다」 줄)
- **`none` 인 자리의 주소를 직접 치면 집으로 보낸다** (2026-09-28 사용자). 이유 한 줄을 띄우지 않는다 —
  설정 화면(도메인/인증 §8.8)이 머리 없이 이유를 보이는 것과 다르다. 설정은 admin 이 아니면 **영영** 못 여는 자리이고,
  기능 자리는 서비스를 바꾸면 열릴 수 있어 안내보다 옮기는 편이 덜 헷갈린다
  **「자리」는 목록 주소다**(`#/cases` · `#/prd` · `#/authoring` · `#/scenarios` · `#/runs`). 한 건 주소(실행 · 항목 · 옛 주소 `#/cases/:id/run` · 작성 상세)는
  띠가 아니라 **그 건의 서비스**로 화면이 버튼을 가르고 서버가 막는다 — 띠와 다른 서비스의 실행 링크를 열어도 튕기지 않는다 (2026-09-28 코드 검토)
  시나리오 조립 화면은 버튼 · 저장을 열 때의 서비스로 가르고 조립 중 띠를 바꾸면 안내 한 줄만 뜬다(도메인/시나리오 §8.11 「조립」, 2026-10-16 E2E-F1-23).
  자리는 `#/scenarios/:id` 만 한 건 주소이고, `#/scenarios/new` 는 띠 서비스의 실행 칸으로 본다 — 실행 칸이 `none` 인 서비스로 띠를 바꾸면 집으로 옮긴다

#### 알림 — 본문 위 줄 · 「알림」 버튼 · 알림 서랍 (2026-10-11 사용자 · 묶음 3 시안 B · WEB-F3-04)

한 번 돌리면 최악 50분, 작성은 30분 넘게 걸려 자리를 떴다 돌아오는 진입이 흔하다.
본문 맨 위 한 줄로 「지금 무엇이 돌고 얼마나 남았나」와 「아까 그거 끝났나」를 다 받는다.
**앞 판은 진행 중인 실행 하나만 카드로 띄웠다** — 작성과 E2E 실행은 안 보였고, 끝난 소식은 탭을 닫으면 사라졌다.

- **맨 위 헤더 오른쪽에 「알림」 버튼이 늘 있다**(2026-10-13 시안 A — 앞 판은 본문 맨 위 오른쪽이었다. 휴대폰은 아래 탭 `알림` — 아래 「휴대폰 화면」). 버튼은 종 아이콘과 배지만 보이고 읽어 주는 이름은 `알림`이다. 안 읽은 수를 대표색 배지로 단다(위 대표색 목록 「알림 개수 배지」). 0 이면 배지가 없다.
  누르면 오른쪽에서 **알림 서랍**이 열린다 — 하던 일을 가로막지 않는 패널이라 뒤를 어둡게 하지 않는다
- **알릴 것이 있으면 본문 맨 위에 줄을 띄운다.** 하나마다 한 줄, 도는 것 먼저(케이스 실행 → E2E 실행 → 작성) 그다음 끝난 것, 각각 새것 먼저.
  **최대 세 줄**이고 넘으면 셋째 자리를 `외 N건 — 알림 열기` 로 쓴다
  - 도는 실행 — `RUN 2113 이 진행 중입니다 12/40 · 약 6분 남음 · 14:32 종료 예상` + 작은 진행 막대. 누르면 그 실행 결과(§8.3)
  - 도는 실행의 작은 막대는 덧붙임이다 — 색만으로 판정을 말하지 않으려고 실패가 있으면 글에도 `실패 N` 을 적는다
  - 도는 E2E 실행 — `E2E RUN 2114 이 진행 중입니다 · 5단계 · 3분 지남`. 누르면 그 실행 결과(케이스 실행과 같은 주소 — 결과 화면이 E2E 결과로 갈라 그린다).
    **막대 · 끝난 수 · 남은 시간이 없다** — 러너가 끝에 결과를 한꺼번에 돌려줘 도중 진척을 알 길이 없다(도메인/시나리오 §3.7 「실행 묶음의 끝」 · 「남는 한계」).
    앞 판은 이 줄도 없어 E2E 를 돌려 놓고 다른 화면으로 가면 돌고 있는지 알 수 없었다(2026-10-16 E2E-F1-18 사용자 시작 질문)
  - 도는 작성 요청 — `작성 요청 #57 이 진행 중입니다 · 3 / 5 단계 스크립트 작성 · 23분 지남 · 약 18분 남음 · 14:32 종료 예상 · 최근 5건 기준`. 누르면 작성 상세.
    반영 · 고치기처럼 다섯 단계를 안 밟는 요청은 `N / 5 단계` 와 남은 시간 없이 단계 글만 적는다(`fiveSteps`)
  - **작성 · PRD 고리는 그 알림의 서비스로 고르개를 바꾼 뒤 연다** — 알림은 서비스 전체인데 작성 상세 · PRD 관리는 고른 서비스로 읽는다. 실행 결과는 서비스와 상관없이 열린다
  - 남은 시간을 세는 규칙은 실행이 도메인/실행 §8.9 「남은 시간」, 작성이 도메인/작성 §7 「남은 시간」이 정본이다
- **끝나면 같은 줄이 결과를 말한다** — `RUN 2113 이 끝났습니다 · 36 통과 · 4 실패`,
  `작성 요청 #56 이 끝났습니다 · 스크립트 파일 24개 · PRD 확인 필요 3건`(확인 필요가 있으면 「PRD 관리」 고리를 같이 단다 — 작성이 PRD 에 새 요구를 「확인 필요」로 올리므로, 도메인/작성 §3.6 「★ 표준 기획서」).
  누르거나 닫으면 읽음이 되어 줄에서 빠진다. 끝난 지 2시간이 지나면 줄에서는 빠지고 서랍에만 남는다.
  **그 실행의 결과 화면을 보고 있는 사람에게는 줄 대신 모달이 뜬다** (도메인/실행 §8.9) — 모달은 하던 일을
  가로막는 장치라서 그 실행을 보고 있을 때만 막을 자격이 있다. 모달로 알린 실행은 읽음이 된다
- **알림 서랍** — 볼 수 있는 서비스 전체에서 최근 7일 안에 끝난 실행 · 작성 요청. 거르기는 전체 · 실행 · 작성 · 안 읽음, 「모두 읽음으로」 하나.
  실행은 칸 read 인 서비스, 작성 요청은 작성 칸 read 인 서비스만 담는다(도메인/인증 §3.5).
  **끝난 E2E 시나리오 실행은 담지 않는다** — 항목이 없어 집계가 늘 0이라 「0 통과」로 거짓말한다. 판정은 시나리오 결과 화면이 따로 낸다(도메인/시나리오).
  그래서 끝난 소식 줄에도 안 오른다 — 도는 E2E 줄은 끝나면 그냥 빠진다
- **읽음은 이 브라우저에만 남는다** — 다른 기기에서는 다시 안 읽음으로 보인다. 알림 표를 새로 만들지 않으려는 결정이다(2026-10-11 사용자 시작 질문).
  사람이 여럿 같은 서비스를 보거나 휴대폰 화면(WEB-F3-06)에서 읽음이 엇갈려 불편하면 그때 서버로 옮긴다
- 대시보드 자리에서는 줄을 숨기고 버튼만 둔다(위 「대시보드」 줄)
- 알릴 것이 없으면 **줄 자체가 없다** — 빈 자리를 잡아 두지 않는다 — 버튼은 헤더에 있어 본문에는 남는 것이 없다(휴대폰은 버튼이 아래 탭이라 그 자리가 통째로 없다)
- 재료는 통로 하나 `GET /api/notifications` 다(공통/3-공유계약 §7.1). 도는 것이 있으면 3초, 없으면 20초마다 다시 받는다. 도는 것이 E2E 실행뿐이면 20초다 — 도중 진척이 없어 자주 받아도 바뀌는 것이 없다

### 등급이 낮아서 못 하는 것은 보이지 않는다

§3.5의 권한을 화면이 지키는 방법은 하나다 — **없앤다.** 제목의 「등급」은 이름으로 불리는 자리라 그대로 둔다 (2026-09-28 기능별 권한으로 바뀜).
흐리게 두면 사람이 그것이 올 때까지 기다린다 (§8.6).

| 이 권한이 모자라면 | 화면에 없는 것 |
|------|--------------|
| 케이스 `write` | `입력값 묶음 저장` · 지우기 · 다시 스캔 |
| 실행 `write` | `실행` · `실행 멈추기` · **증적 문서 만들기 버튼들**(§8.4 의 `{라벨} 만들기`. 글자를 여기 다시 적지 않는다) · 실패 카드 `버그`(2026-10-11) |
| 작성 `write` | **`새 작성` · `다시 만들기`** · 중단 · 폐기 · 「PRD 관리」의 확인 필요 고르기 · 확정 · `요구 더하기` · 고치기 · 되돌리기 (2026-10-10) · 실패 카드 `화면이 맞음` · `화면이 맞음으로 바꾸기`(2026-10-11) · 「서비스 가이드」의 `저장` · `파일 더하기` · `빼기`(2026-10-17) |
| 기능이 `none` | 그 기능의 사이드바 자리 전체 (위 「자리 목록」) |
| admin 아님 | **`머지`** · `설정` 자리 |

`증적 문서 받기`는 실행 `read` 에게도 보인다. 받는 것은 읽기다 (§3.5).

**★ 어느 할 일이 어느 등급인지는 이 표가 정본이 아니다** (2026-09-22 검토가 잡았다).
**정본은 `도메인/인증` §7 「등급으로 갈리는 자리」 표**이고, 이 표는 그것을 **화면에서 어떻게 지키는가**만 적는다.
**등급 목록을 여기 베껴 적지 않는다** — 베낀 사이에 저쪽 표에 줄이 늘면 **화면만 뒤처지고,
그러면 서버가 403 을 내는 버튼이 화면에 남는다.** 위 「없는 것」이 늘거나 줄 때는 **저쪽 표를 먼저 본다.**

**`머지`가 작성 `write` 에게도 없는 이유** — 저장소를 영구히 바꾸는 일이라 admin 이다
(`도메인/인증` §7). **화면에서 안 보이는 것은 편의가 아니라 §8.6 의 규칙**이고,
막는 것은 서버다 — 화면이 숨겨도 서버 표가 없으면 통로가 열린 채로 남는다.

### 휴대폰 화면 — 결과 확인 · 진행 상황 · 다시 실행 (2026-10-12 사용자 · 묶음 5 시안 A · WEB-F3-06)

휴대폰으로 하는 일은 **「끝났나 보고, 실패면 다시 돌리기」** 다. 슬랙 알림을 눌러 들어오는 길이 흔하다.
**앞 판(2026-09-17 「좁은 화면에서 제대로 되는 것은 둘」)은 「끝났나 보기」 하나로 좁히고 PC 화면을 가로 줄로 접어 그렸다** —
자리 목록이 위를 다 덮었고, 「실패 N건 다시 실행」은 케이스마다 값 칸이 펼쳐진 긴 창이었다(시안 캔버스 「묶음 5」 B 가 그 모양이다).
「확인할 곳을 좁혀야 확인이 실제로 끝난다」는 그때 근거는 그대로다 — 이번에는 다시 실행까지 넣고 나머지는 아예 그리지 않는다.

**휴대폰은 창 폭 620px 미만이다.** 기기를 따로 알아내지 않는다 — PC 창을 좁혀도 같은 화면이 나온다.

| 휴대폰에서 연다 | PC 에서만 연다 |
|---|---|
| 대시보드(도메인/리포팅 §8.12) · 실행 기록(도메인/실행 §8.7, E2E 포함) · 실행 결과(§8.3) · 항목 상세 · 알림 서랍 · 비밀번호 변경 | PRD 관리 · 테스트 작성 · 테스트 스크립트 · E2E 시나리오 · 설정 · 그래프 ↗ |

- **껍데기는 위 줄과 아래 탭이다.** 사이드바는 없다
  - 위 줄 — 서비스 고르개(대시보드에서는 숨긴다. PC 헤더는 2026-10-13 에 대시보드에도 두기로 바꿨고 휴대폰은 손대지 않았다) · 오른쪽 끝 **사람 버튼**.
    누르면 이름 · 언어 고르개 · `비밀번호 변경` · `로그아웃` 이 펼쳐진다
  - 아래 탭 — `대시보드` · `실행 기록` · `알림`. 자리가 없는 탭은 없다(「등급이 낮아서 못 하는 것은 보이지 않는다」).
    `알림` 탭은 PC 의 「알림」 버튼과 같은 것이다 — 안 읽은 수 배지를 달고 알림 서랍을 연다(위 「알림」)
  - 실행 기록의 하위(UI 테스트 · 기능 테스트 · E2E)는 실행 기록 목록 위에 고르개 줄로 놓는다
  - **본문 위 알림 줄은 남는다** — 진행 상황이 바로 그 줄의 일이다. 줄 안 글은 줄을 바꿔 감싸고 가로로 넘치지 않는다
- **PC 전용 화면의 주소로 오면 그 화면을 그리지 않고 안내만 한다** — `「테스트 작성」 화면은 PC 에서 엽니다` ·
  `휴대폰에서는 실행 결과 확인 · 진행 상황 · 다시 실행만 합니다. 같은 주소를 PC 에서 여세요` · `주소 복사` · `실행 기록으로`
  (실행 기록 자리가 없는 사람은 `대시보드로`, 둘 다 없으면 이 버튼이 없다).
  알림 서랍의 작성 요청 고리처럼 PC 전용 화면으로 가는 고리가 휴대폰에도 있다. **집으로 보내지 않는다** — 가려던 주소가 사라지면 PC 에서 다시 찾을 길이 없다
- **실행 결과** — 요약 띠 → 실패 카드 → 통과 · 미실행 줄 차례는 PC 와 같다(도메인/실행 §8.3).
  `실패 N건 다시 실행` 은 **아래 탭 바로 위에 붙어 있다** — 실패 카드를 내려 읽은 자리에서 바로 누른다.
  증적 문서 만들기 · `실행 중단` 은 머리에 남는다 — 증적 버튼은 형식마다 하나라 여럿이 되어 바닥에 붙이면 본문을 덮는다
- **다시 실행** — PC 와 같은 실행 창(도메인/실행 §8.10)이 아래에서 올라온다(DESIGN.md 「모달」).
  여러 건이면 **케이스마다 값 칸을 접어 두고** `값` 을 누르면 편다. 실행을 눌렀는데 틀린 칸이 있으면 그 케이스를 펼친다.
  한 건이면 접지 않는다 — 디바이스 · 저장값까지 한 자리에서 본다
- 손가락으로 누르는 영역 최소 크기(44px)는 **위 휴대폰 화면 전부와 위 줄 · 아래 탭에** 건다.
  **실제로는 46px 로 건다** — 브라우저가 반올림하며 소수점만큼 깎아 실측이 43.9986 로 나왔다.
  기준이 44 라서 46 을 거는 것이지 기준이 46 인 것이 아니다 (2026-09-21)
- 증적 문서는 A4 고정폭이라 휴대폰에서 펴 볼 대상이 아니다. 받기는 된다 — 실행 결과의 증적 칸이 휴대폰에서 증적을 받는 길이다

### 화면 낱말은 하나로 (2026-10-19 사용자 · ⑫ 사용성 개편 · 점검 16)

**같은 일을 화면마다 다른 말로 부르지 않는다.** 앞 판은 반영 · 머지 · 병합 · 합치기가 한 일을 가리켰고, 「성공」과 「통과」가 같은 판정이었다.
화면(`apps/admin/src/web/**`)의 글자는 아래 표의 왼쪽 말만 쓴다. 명세 · 코드 식별자 · 서버 오류 코드는 이 표를 따르지 않는다 — 화면에 보이는 글자의 규칙이다.

| 쓰는 말 | 쓰지 않는 말 | 무엇 |
|---|---|---|
| 반영 | 머지 · 병합 · 합치기 | 작성 요청이 만든 케이스를 저장소 main 에 넣는 일(도메인/작성 §3.6 「★ 머지는 운영 등급이다」) |
| 통과 | 성공 | 판정 `PASS` |
| 값 필요 | 보류 케이스 · 판정 불가 | 사람이 값을 채워야 반영할 수 있는 케이스(도메인/작성 §3.6 「★ 보류 케이스」의 `UNDECIDABLE` · `ON_HOLD`) |
| 빠짐 | 누락 | 원장에서 케이스도 제외도 없는 요구 번호 |

- **메뉴 「테스트 스크립트」와 제품 용어 「케이스」는 그대로다** — 위 「자리 목록」의 결정(2026-10-07 사용자)이고 이 표가 뒤집지 않는다
- 화면 글자는 영어 표(`messages/*.ts`)의 키라 글자를 바꾸면 키와 화면 테스트가 찾는 글자도 같이 바꾼다(아래 「키는 한국어 원문이다」)
- 개발자 말(main 케이스 · CI · 초안 PR · 작성 에이전트 · 모킹 · trace 등)을 무엇으로 바꿀지는 이 표에 아직 없다 — 진행판 WEB-F4-14 가 「지금 → 바꿀 문구」 표를 먼저 보이고 정해 여기에 더한다

### 다국어 — 화면 글자는 한국어와 영어 (2026-09-22 결정)

**언어는 둘이다.** `ko` 가 기본이고 `en` 이 있다. 고르개는 **맨 위 헤더 오른쪽**,
알림 버튼과 계정 메뉴 사이다(2026-10-13 — 앞 판은 사이드바 아래, 로그인한 사람 이름 옆이었다). 고른 언어는 **브라우저에 남아 새로고침해도 유지된다.**

- 언어를 바꾸면 **`<html lang>` 과 탭 제목도 따라간다.** `lang` 이 틀리면
  화면 낭독기가 한국어 목소리로 영어를 읽는다
- **언어 고르개는 헤더에 있어 사이드바를 접어도 그대로다**(2026-10-13). 앞 판은 사이드바 바닥에 있어 접어도 지우지 않는 규칙이 따로 있었다
- 날짜·시각·숫자 형식도 언어를 따른다. 형식을 손으로 짜지 않는다

#### 키는 한국어 원문이다

표를 **영어 한 벌만** 둔다. 한국어는 키 자체가 답이다.

| | 왜 |
|---|---|
| 표가 하나다 | 두 벌이면 같은 글자를 두 곳에 적고 한쪽이 뒤처진다 |
| 코드가 읽힌다 | `t('진행 중')` 은 무엇이 나올지 그 자리에서 보인다 |
| 빠진 번역이 화면을 안 깨뜨린다 | 표에 없으면 **한국어가 그대로 나온다.** 키가 그대로 나오지 않는다 |

대신 **워딩을 고치면 표의 키도 같이 고쳐야 한다.** 이것이 이 선택의 유일한 약점이고,
**기계가 본다** — 소스와 표를 양방향으로 대조한다 (`apps/admin/src/web/messages.test.ts`).

- **값이 박힌 글자는 자리표로 넣는다** — `t('RUN {번호} 이 진행 중입니다', { 번호 })`.
  **키는 언제나 정적 문자열이다.** 템플릿 문자열로 쓰면 대조가 그 줄을 못 보고 지나간다.
  그래서 **못 잡는 대신 금지한다** — 첫 인자가 문자열 리터럴이 아닌 호출이 하나라도 있으면 검사가 빨개진다
- **같은 한국어가 자리마다 다른 영어여야 하면** 키 뒤에 괄호로 자리를 붙인다
  (`실행 (버튼)` · `실행 (집계)`). 괄호는 화면에 나오지 않는다
- **새 자리 `테스트 작성` 의 영어는 `Authoring` 이다 (2026-09-22).** 명세가 여기서 못 박는다 —
  다음 세션이 지어내면 자리 이름만 다른 말이 된다.
  **어느 파일에 적을지는 명세가 지목하지 않는다.** 자리 이름들이 이미 messages 표 두 파일로 갈려 있고,
  옆 자리 `테스트 스크립트` 의 영어는 `messages/shell.ts` 가 아니라 `messages/cases.ts` 쪽에 있다 (실측).
  **어느 쪽에 둘지는 다음 PR 이 정한다.**
  **기계가 이 갈림을 안 잡는다** — 위 대조는 소스와 표를 양방향으로 맞추는 것이라 갈려 있어도 초록이다

#### 옮기지 않는 글자 둘

| 무엇 | 왜 | 어디 |
|---|---|---|
| **케이스가 주는 글자** — 케이스 이름 · 사전조건 · 입력 칸 라벨 | 코드가 진실의 원천이고(§3.1) 폼 라벨은 케이스의 `describe()` 에서 온다([실행.md](../도메인/실행.md) §8.2). 화면이 지어내면 그 순간 둘이 갈린다 | 케이스 파일 |
| **증적 문서** | 검수처에 내는 산출물이다([리포팅.md](../도메인/리포팅.md) §8.4). 화면 언어를 따라가면 **같은 실행의 문서가 둘이 된다** | `reporting/` |

**그래서 영어로 바꿔도 화면의 일부는 한국어로 남는다.** 숨기지 않고 적어 둔다 —
케이스 이름과 입력 칸 라벨은 이 화면에서 사람이 가장 많이 읽는 값이다.

**영어를 쓰는 사람이 실제로 오면 다음 레버는 껍데기가 아니라 케이스다.**
케이스를 영어로 쓰게 하거나 `packages/kit` 의 `describe()` 가 두 언어를 받게 해야 하고,
**뒤엣것은 계약 변경이다** — 그때는 CLAUDE.md §1.2 의 절차로 연다.
여기에 적어 두지 않으면 다음 세션이 껍데기 번역을 더 하는 쪽으로 간다.
