### 3.6 작성 — 기획서를 테스트 코드로 (2026-09-22 신설)

- **책임**: 「이 기획서로 테스트를 만들어 달라」는 요청을 대기줄에 세우고, 작성 에이전트(기본은 서버의 `author` 컨테이너,
  맥은 대체 — 아래 「★ 서버 컨테이너가 기본이다」)가 집어 가 일하는 동안의 상태·작업 단계·결과를 화면에 낸다
- **애그리거트 루트**: `AuthoringRequest` (식별자는 대기줄 행 번호)
- **용어는 [공통/1-제품과-구조.md](../공통/1-제품과-구조.md) §2 가 정본이다** — `작성 요청`·`작성 에이전트`·`작업 단계`.
  여기서 새 이름을 짓지 않는다
- **불변식**
  - **코드는 저장소에만 생긴다.** 이 컨텍스트가 드는 것은 작성 요청과 작업 단계뿐이다.
    테스트 코드는 작성 에이전트가 **초안 PR**(draft pull request, 「아직 병합하지 말라」고 표시해
    올리는 변경 요청)로 저장소에 올리고, 사람이 화면에서 머지를 눌러야 코드가 된다.
    PR 을 여는 것은 **에이전트 스크립트**다 — 흐름은 아래 「작성 에이전트는 전용 체인이다」
    **근거의 정본은 §1 「영구히 하지 않는다」 표의 「화면이 테스트 코드를 직접 들고 편집하는 기능」 행이다** —
    2026-09-22 에 그 행이 **화면이 코드 본문을 들고 있을 때**로 좁혀졌다. 여기 옮겨 적지 않는다
  - **`test_source` 는 그 금지의 예외가 아니다.** 편집 대상이 아니라 화면이 실패한 줄을 발췌하려고
    받아 두는 스냅샷이고, 머지 전 파일이 admin 의 `/tests` 에 없어서 필요하다 (§6)
  - **한 요청은 한 서비스다** — `authoring_request.service_id`. 실행이 `test_run.service_id` 로
    같은 것을 거는 것과 같은 규칙이다 (§1 · §6)
  - **집어 가는 쪽은 작성 에이전트 하나다. 그래서 줄도 하나다.** 작성·재실행·머지가 `kind` 로 갈릴 뿐 한 줄에 선다.
    집는 일은 `PENDING`→`RUNNING` 한 줄 UPDATE 이고 그것이 곧 잠금이다 — **정본은 §6**.
    에이전트는 **서비스마다 따로 집는다** (2026-09-24) — 서비스 A 가 도는 동안 B 가 기다리지 않는다.
    **같은 서비스 안도 나란히 돈다** (2026-10-01) — 작성 · 재실행 · 케이스 고치기는 동시 상한(정본 [공통/6-인프라.md](../공통/6-인프라.md))의 자리만 있으면 가져가고,
    **자리를 먼저 잡고 나서** 가져간다. **반영은 서비스마다 한 줄로 차례로** 돌고, 반영 때 먼저 들어간 케이스와 겹치는지 본다 —
    정본은 아래 「★ 반영 때 겹침 검사」. 보류 없는 반영은 CI 를 기다리기만 해서 상한에 안 센다
  - **진행은 두 층이고 이 컨텍스트는 위층만 든다. 이 구분이 이 장의 핵심이다**
    - **위층 — 작업 단계** (`stage`). 「요구사항 표 만드는 중」·「케이스 2건째」·「관문 3 도는 중」.
      케이스를 **만드는 일**의 진척이고, 이 표가 새로 드는 것은 이것뿐이다
    - **아래층 — 테스트 절차** (`Step`). **이미 kit 과 러너가 든다** (§5.1 · §5.2). 새로 만들지 않는다
    - 아래층을 `stage` 에 또 담으면 같은 것이 두 곳에서 다른 말을 한다. 아래층은 `result` 에 통째로 실려 온다 (§6)
  - **입력은 자료 목록이다** (2026-09-23). 기획서 파일 여럿과 피그마 주소 여럿이 한 세트이고,
    **다 올리기 전에는 줄에 안 선다** (`DRAFT`). 정본은 아래 §7 「자료」
  - **에이전트(서버 `author` 또는 맥)가 꺼져 있으면 줄이 안 준다.** 요청은 `PENDING` 으로 쌓여 있다가 켤 때 처리된다.
    고장이 아니라 구조다 — 없애려면 러너가 브랜치를 보게 해야 하고 그것은 배포 구성과 러너 계약(§5.2)을 건드린다

#### ★ 인증을 뚫지 않는다

작성 에이전트는 서버 컨테이너에서든 맥에서든 **계정으로 로그인해 사람과 같은 문**을 쓴다
(비밀번호 대신 그 계정의 에이전트 토큰으로 — 2026-09-23, [인증.md](인증.md) §7).
전용 경로도, 인증을 건너뛰는 예외도 만들지 않는다. 등급도 사람과 똑같이 걸린다 —
등급이 모자라면 작성 요청을 집어가지 못한다.

**★ 그 계정은 작성 `write` 를 가진 member 다. `admin` 을 주지 않는다** (2026-09-22 검토가 잡았다 · 2026-09-28 전에는 `operator`).

**★ 그리고 서버가 그 계정을 이름으로 안다** (2026-09-22 보안 검토가 잡았다).
**「집어 가는 쪽은 맥 하나다」(당시 문구)는 전제이지 장치가 아니었다** — 서버가 그 지목을 안 보면
그 서비스에 배정된 **아무 작성 `write`** 가 집기를 두드려 맥보다 먼저 집고, 「끝났다」에
**자기가 고른 PR 주소**를 실을 수 있다. 그 행은 정상 완료로 보이고 `admin` 이 머지를 누르면
**그 사람이 고른 PR 이 병합된다** — 이 장이 막으려는 바로 그것이다.
그래서 **에이전트가 행을 바꾸는 통로(집기·단계 올리기·사진 올리기·산출물 올리기·끝내기)는 정해진 계정 이름에만 연다.**
이름이 안 정해져 있으면 **아무도 못 집는다.**
에이전트가 **행을 바꾸는** 일은 이 통로들뿐이고 모두 `(작성, write)` 다.
**산출물 올리기(`outputs`, 2026-09-25)** 는 [인증.md](인증.md) §7 의 등급표(`gate.ts`, `(작성, write)`) · 토큰 통로 · 라우트표(`scope.ts`, `작성요청, 칸:'id'`) 셋에 다 든다.
에이전트는 **기획서 파일도 내려받는다** (2026-09-23) — 그것은 읽기라 `(작성, read)` 로 열려 있고 사람도 상세에서 받는다.
위 통로들처럼 계정 이름을 볼 까닭이 없다. 남의 행을 바꾸는 일이 아니다.
**머지 행을 만드는 것은 사람**이고 에이전트는 그것을 집어 실행할 뿐이다 —
그래서 에이전트에 `admin` 이 필요 없다. 실행이 무엇인지(초안 풀기 · CI 기다리기 · 병합)는 아래 「작성 에이전트는 전용 체인이다」.

**왜 못박나** — 안 적으면 다음 세션이 「편하게 `admin` 으로 두자」를 고른다.
그 순간 **맥에 저장된 비밀값 하나가 `/api/settings/**` 전부를 연다** —
이 장이 세운 「실행할 수 있는 사람 ≠ 저장소를 바꿀 수 있는 사람」이 계정 설정 하나로 사라진다.

- **근거의 정본은 [인증.md](인증.md) §7 「인증 적용 범위」다.** `POST /api/auth/login` 을 뺀
  모든 `/api/**` 는 로그인이 필요하고 **예외는 없다**
- 그 절에 **2026-09-16 에 예외를 만들었다가 2026-09-17 에 지운 이력**이 있다. 그때의 판정이 이것이다 —
  그 예외가 내세운 방어는 **귀속**을 말할 뿐 **접근**을 막지 못한다. 이 길에도 그대로 적용된다
- **「맥에서 도는 거니까 토큰 하나 파자」로 되돌리지 마라.** 로그인 없이 지나가는 자리를 하나 내는 순간,
  §3.5 가 러너 포트를 닫으며 막으려 한 바로 그 뒷길이 admin 에 생긴다.
  **2026-09-23 의 에이전트 토큰은 이것이 아니다** — 계정에 묶여 확인 함수가 같은 사람을 돌려주므로 등급·배정·
  정해진 계정 이름이 그대로 걸린다. 계정 없는 토큰·공용 토큰은 여전히 금지다 ([인증.md](인증.md) §7 「인증 적용 범위」)

**§9.2 정기 실행 선례와 다른 이유** — 그쪽은 HTTP 를 안 쓰고 **컨테이너 안 명령**으로 풀었다.
작성 에이전트는 처음에 컨테이너 밖(맥)에 있어 그 길이 없었다. **서버 컨테이너로 들어온 뒤에도 HTTP·에이전트 토큰을 그대로 쓴다** —
DB 에 직접 닿게 하면 자식 세션(셸 권한, 외부 기획서를 읽는다)이 DB 에도 닿는다. 그래서 author 는 DB 가 없는 망에 둔다.
**설명의 정본은 [공통/1-제품과-구조.md](../공통/1-제품과-구조.md) §3 컨텍스트 지도다** — 여기 옮겨 적지 않는다.

#### ★ 서버 컨테이너가 기본이다 (2026-09-23 · 게이트 0·1)

**화면에서 보내면 서버의 `author` 컨테이너가 5초 안에 집는다.** 맥을 켜 둘 필요가 없고, 누가 어느 기계에서 보내든 같다.
맥에서 같은 스크립트를 돌리는 길은 **개발용 대체**로 남긴다. **둘을 동시에 돌리지 않는다** — 켤 때 멈춘 요청을 닫는 일이
계정 이름으로 가르므로 서로의 진행 중 요청을 닫는다.

**왜 뒤집었나** — 처음 판단은 「`claude` 가 사람의 구독 로그인을 쓰니 맥에서, 그러면 서버에 Claude·GitHub 토큰을 안 심어도 된다」였다.
**그 판단의 값(서버에 비밀값 0)은 지금도 맞다.** 사용성과 맞바꿨다 — 켤 때마다 비밀번호, 맥 터미널 상시 실행, 로그인 시 자동 실행
셋이 모두 「사용성이 너무 떨어진다」로 거절됐다(사용자, 2026-09-23). `claude setup-token` 이 **구독용 장기 토큰**을 주므로 추가 비용 0 은 지킨다.

**누구의 Claude 계정인가 — 고객사 서버는 그 회사 계정이다** (2026-09-23 게이트 1). 우리 서버(개발·시연)는 사용자 구독 토큰을 쓴다.
개인 구독 토큰을 고객사 서버에 심지 않는다 — 개인 구독의 공유·제3자 서비스 사용은 약관 위반 쪽이다. 코드는 같고 `.env` 에 누구 토큰을 넣느냐만 다르다.

**컨테이너가 지키는 것** (구성의 정본은 [공통/6-인프라.md](../공통/6-인프라.md) §9)

| 무엇 | 왜 |
|---|---|
| **선택 사항**(compose profile `authoring`) | 토큰을 넣기 전에 같이 떠 [거부] 로 재시작만 반복하지 않게 |
| 저장소 뿌리를 `/repo` 로 붙이되 **`.env` 는 가린다** | 자식 세션은 셸로 `/repo` 를 읽는다. `.env` 에 모든 비밀값이 있다 |
| **admin 하고만 같은 망** | 자식이 postgres·runner 에 못 닿게 |
| **root 로 켜고 사용자를 가른다** (2026-09-24 게이트 0) — 자식은 자리마다 다른 uid(`AUTHORING_CHILD_UID + k`), 서버 저장소에 쓰는 일은 `HOST_UID` | 자식이 에이전트(root)·다른 자리 자식의 `/proc/<pid>/environ`(GitHub·에이전트·피그마 토큰)을 못 읽고, 서버 저장소·부품에 못 쓴다. 서버 저장소에 root 소유 파일도 안 남는다. 자식 uid 칸이 비거나 겹치면 **켜지지 않는다** — 그냥 돌면 자식이 root 가 된다 |
| **작업마다 별도 사본** — bare git 은 자식 밖, 트리·집만 자식 것 | 자식이 훅·git 설정을 심어도 에이전트가 안 본다(`GIT_DIR` 로만 git 을 친다). 집이 매번 새것이라 앞 건의 설정이 안 이어진다 |
| 자식이 끝나면 **검사 전에** 그 uid 의 프로세스를 전부 거두고 공용 임시의 흔적을 지운다 — 못 거두면 **에이전트를 멈춘다** · 자식은 작업마다 새 임시 자리 · 브라우저 폴더는 읽기 전용 · 링크·일반 파일 아님·트리 밖 파일은 **읽기 전에** 거부 | 남은 자식이 검사 뒤 파일을 바꿔치기하거나 **같은 자리를 받은 다음 건(다른 서비스)** 의 토큰·캐시·브라우저를 건드리지 못하게 · root 가 링크를 따라 토큰 파일을 PR 본문에 싣지 않게 |
| 에이전트 토큰은 **자식 환경에서 뺀다** · Claude 구독 토큰은 넘긴다 | 자식이 들면 남의 줄을 집고 끝낼 수 있다 · 자식 `claude` 는 로그인이 필요하다 |
| 시작 스크립트가 **구독 토큰 모양**(`sk-ant-oat…`)을 본다 | API 키를 넣으면 실비 청구다 |
| 워드는 **pandoc** — 옛 `.doc` 은 실패로 알린다 | 맥의 `textutil` 이 리눅스에 없다. pandoc 은 `.docx` 만 읽는다 |

**남는 한계 — 알고 쓴다**
- **자식은 Claude 구독 토큰을 든다** — 자식 `claude` 가 로그인해야 해서다. 기획서에 숨긴 지시로 그 토큰을 밖으로 보낼 수 있다(망은 admin 뿐이지만 인터넷은 열려 있다)
- **자식은 서버 저장소(`/repo`)를 읽을 수는 있다** — 쓰기는 막혔지만 가린 것은 `.env` 하나다. 원격 주소에 토큰을 박았거나 `.env.*` 같은 다른 비밀 파일을 저장소에 두지 않는다
  (사본의 부품 링크가 `/repo/node_modules` 를 가리켜 막지 않았다. 부품을 저장소 밖으로 옮기면 닫힌다 — 2026-09-24 보안 검토)
- **맥 경로와 맥의 Docker Desktop 에서는 격리가 성립하지 않는다** — 맥 에이전트는 root 가 아니라 자식을 다른 uid 로 못 띄우고,
  Docker Desktop 의 폴더 공유는 uid 권한을 안 지켜 자식이 `/repo` 에 쓴다(2026-09-24 실측). **격리는 리눅스 서버에서만 성립한다** — 맥에서는 믿을 수 있는 기획서만 넣는다
- **예비 모델은 과부하·미제공에만 넘어간다.** 구독 한도에 걸리면 넘어가지 않고 그 건이 「Claude 구독 한도에 걸렸다」로 실패한다. 보조의 예비는 [보조 모델, 메인 예비] 순이라 둘 다 Sonnet 이면 보조는 예비가 없다 — 알고 쓴다(2026-10-04)
- **같은 서비스의 반영은 차례로 돈다.** 반영이 CI 를 최대 17분 기다리는 동안 그 서비스의 다음 반영이 선다. 작성은 2026-10-01 부터 서지 않는다 — 그 전에는 한 서비스 안이 한 건씩이라 작성도 섰다(아래 「★ 반영 때 겹침 검사」)
- 구독 한도를 사람의 대화형 사용과 나눠 쓰고, 동시에 도는 수만큼 빨리 닳는다. 토큰은 1년이면 만료된다 — 만료되면 시작 스크립트가 아니라 첫 `claude` 가 실패한다
- 사본의 부품(`node_modules`)은 서버 저장소 것을 가리킨다 — 서버 저장소가 GitHub main 보다 뒤처졌으면 새 공유 심볼을 쓰는 케이스가 로컬 관문에서 깨질 수 있다
- 대상 서버 주소가 `localhost` 면 컨테이너 안에서 자기 자신이다 — 관문 3회 실행이 실패한다

#### ★ 머지는 운영 등급이다

| 할 일 | 최소 등급 | 왜 |
|---|---|---|
| 작성 · 재실행 | `(작성, write)` | 결과가 **초안 PR** 이라 마음에 안 들면 버리면 된다. 지금 「실행」과 같은 무게다 |
| **머지** | `admin` | **저장소를 영구히 바꾼다.** 되돌리려면 사람이 손으로 해야 한다 |

**둘에 같은 등급을 주면 「실행할 수 있는 사람 = 저장소를 고칠 수 있는 사람」이 된다.**

**★ 2026-09-22 까지 서버는 이것을 표현할 수 없었다.** `apps/admin/src/auth/gate.ts` 가
「설정 자리면 `admin`, 아니면 읽기는 `viewer`, **나머지 전부 `operator`**」로 경로와 방식만 보고 갈랐다.
그대로 두면 머지 통로가 무조건 `operator` 였다. **화면이 버튼을 안 그리는 것은 편의이지 방어가 아니다** —
그대로 만들었으면 실행 등급이면 누구나 머지 통로를 직접 찔렀다. 지금은 경로→권한 표다 ([인증.md](인증.md) §7 「등급으로 갈리는 자리」).

**이 장은 「무엇이 어느 등급인가」만 적는다. 「서버를 어떻게 고치나」는 [인증.md](인증.md) §7
「등급으로 갈리는 자리」가 맡는다.** 여기 중복해 적지 않는다.

**에이전트가 머지를 판단하지 않는다. 손일 뿐이다.** 사람이 화면에서 눌러야만 머지 요청이 생긴다.
사람 게이트가 사라지는 것이 아니라 자리를 옮기는 것이다.
에이전트가 보는 것은 「CI 가 초록인가」 하나이고, 초록이 아니면 병합하지 않고 멈춘다 (아래 절).

#### ★ 작성 에이전트는 전용 체인이다 (2026-09-23) — 정본은 여기다

작성 요청 하나를 처리하는 일은 **`tpx-author` 전용 체인**을 탄다. 일을 둘로 나눈다.
**git 과 GitHub 을 만지는 일은 전부 에이전트 스크립트**가 하고, **자식 Claude**(에이전트 스크립트가 띄우는 `claude -p`)는
케이스를 만드는 일만 한다.

| 누가 | 무엇을 | 하지 않는 것 |
|---|---|---|
| 에이전트 스크립트 — 준비 | GitHub 이 말하는 main SHA(`git ls-remote`)를 묻고 그 판으로 **작업방**(요청마다 따로 만드는 사본 — bare git 은 자식 밖, 2026-09-24)을 연다. 서버 저장소에는 아무것도 안 쓴다 | — |
| 자식 Claude | 자료 → 요구사항 표 → `tpx-cases` 로 케이스(화면 묶음이 여럿이면 서브에이전트 팬아웃 — 아래 「★ 원장」) → 관문 0(원장 대조) · 관문 넷. 끝나면 결과 요약만 남긴다 | **git · gh · push · PR · `/tpx` · 백그라운드(background) 작업** |
| 에이전트 스크립트 — 마무리 | `tests/` · `docs/` 밖에 자식이 **새로** 남긴(추적 안 된) 파일은 지우고 로그 · PR 본문 「작성 요약」 머리에 경고 한 줄로 이름을 남긴다(열 개까지 · 2026-10-03 게이트 0 — 11203 이 실행 로그 파일 하나로 케이스 142개를 못 올렸다. 고친 파일 · `tests/` · `docs/` 안의 엉뚱한 파일은 케이스가 쓰는 것일 수 있어 지우지 않는다) → 요구 지문 파일 쓰기(바뀐 파일 확인 전 — 그래야 바뀐 파일 목록에 들어 커밋된다. 아래 「★ 원장」 「요구 지문」) → 바뀐 파일이 케이스뿐인지 확인 → 원장 대조(빠져도 거절하지 않고 셈에 남긴다 — 아래 「★ 원장」) → commit → push → **초안 PR** 을 연다 → 서버에 끝났다고 보고(`prUrl` 을 싣는다) → 작업방을 치운다 | — |

- **PR 본문에 에이전트의 관문 3(3회 실행) 기록을 싣는다.** 아래 「테스트만 바뀐 PR」 이 그것을 병합 근거로 쓴다.
  **끝의 전체 3회는 에이전트가 결과 파일로 직접 확인한다**(2026-10-03 게이트 0) — 에이전트가 정한 폴더(`AUTHORING_GATE3_DIR`)의 `gate3-final*.json` 을 읽어
  하나씩(`workers` 1) · 폴더의 케이스 파일마다(그 파일이 든 가장 늦은 결과로) 데스크톱 3회 · 실패 0 · 마지막 수정 뒤 실행인지 본다. 어기면 「작성 요약」 머리에 ⚠️ 한 줄을 싣고 **올리기는 막지 않는다**(막으면 다 만든 케이스를 못 쓴다).
  자식 명령 하나는 최대 10분이라 하나씩 차례로 나눠 돌려도 된다 — 덩어리마다 결과 파일을 남긴다. 같은 머리에 품질 숫자(판정 평균 · 전제 확인 · 공용 부품 밖 CSS · 여러 파일에 따로 만든 도우미) 한 줄도 싣는다. 전제 확인은 **준비가 있는 케이스만** 센다 — 전제가 없거나 `비회원이다` · `로그아웃 상태다` 뿐인 케이스는 분모에서 빼고 그 수를 같이 적는다(2026-10-04 게이트 0 — MKT 11211 의 55% 는 이 착시였고 준비 있는 케이스만 세면 91%로 이전과 같았다). 공용으로 옮기지 않은 임시 도우미(`components/draft-*`)가 남아도 ⚠️ 한 줄
  팬아웃했으면 기록은 **묶음별 3회 + 끝의 전체 3회**다. 묶음별 숫자는 서브에이전트가 남긴 실행 결과 파일에서 자식이 읽는다 — 말로 돌려받은 숫자를 옮기지 않는다 (아래 「★ 원장」 팬아웃 · 2026-10-03)
- **머지** — 사람이 누르면 에이전트가 초안을 풀고(Ready), **PR 의 맨 끝 커밋(head)에 대한 최신 `check` 실행이 `success` 일 때만** 병합한다.
  그 밖(`failure` · `cancelled` · `skipped` · `timed_out` · 결과 없음)이면 병합하지 않고 `FAILED` 로 끝낸다.
  **다시 누르면 CI 를 다시 돌린다** — 이미 Ready 인 PR 은 풀어도 새 실행이 안 생기기 때문이다
- **★ 빨간 PR 의 병합을 막는 것은 GitHub 이 아니다.** main 보호가 관리자에게 강제되지 않고(`enforce_admins: false`)
  에이전트는 저장소 주인 계정으로 돈다. 그래서 **막는 것은 에이전트의 판정과 「관리자 우회를 쓰지 않는다」 둘뿐이다.**
  「GitHub 이 막아 준다」고 믿고 이 판정을 느슨하게 만들지 마라
- **테스트만 바뀐 PR 은 CI 가 가벼운 길로 돈다** — 타입 · 케이스 파일 규칙(K 규칙) · 비밀값 이름만 본다.
  **CI 는 새 케이스를 실행하지 않는다.** 사내 대상·비밀값이 필요한 케이스를 CI 러너가 못 돌리기 때문이다.
  그래서 **병합 근거는 PR 본문에 실린 에이전트의 관문 3 기록**이다. 무엇이 「테스트만」이고 무엇이 빠지는지의 정본은
  [`docs/HOOKS.md`](../../HOOKS.md) 「CI 와 병합 차단」이다 — 여기 옮겨 적지 않는다
- **에이전트가 켜질 때 자기 이름으로 잡힌 채 멈춘 `RUNNING` 을 닫는다.** 작성·재실행은 `STOPPED`(멈춤 요청이 있었으면 `USER`, 없으면 `AGENT_RESTART`) —
  아래 「중단 · 폐기 · 진척」. **머지는 지금처럼 `FAILED`** 다(머지는 멈추는 통로가 없다). 머지의 사유는 「작성 에이전트가 꺼져 중단됐다 — 다시 넣어라」, 작성·재실행은 사유 글 대신 중단 이유로 남는다.
  머지는 CI 를 기다리느라 오래 잡혀 있어서, 그사이 에이전트가 꺼지면 그 행이 영원히 `RUNNING` 으로 남는다.
  새 통로는 없다 — 목록(`?status=RUNNING`)과 끝내기만 쓴다
- **케이스를 쓸 폴더는 서비스 설정의 테스트 폴더(`testsDir`)다** (2026-09-25 게이트 0) — `GET /api/auth/me` 의
  `services[].testsDir` 로 받는다([인증.md](인증.md) §7). 케이스가 0건인 새 서비스도 그 폴더를 새로 만들어 쓴다.
  **한 칸 이름(`^[A-Za-z0-9._-]+$`, `.`·`..` 아님)이 아니면 집은 뒤 작업방을 만들기 전에 사유와 함께 `FAILED`** — `a/b` 는 「테스트만」
  판정 모양에서 벗어나 push 가 막히고, `..` 는 사본 밖을 가리킨다.
  **뒤집은 판단** — 앞 판(2026-09-23)은 「그 칸이 응답에 없고 더하면 계약 변경」이라 사본의 기존 케이스로 폴더를 추정했고
  없으면 「첫 케이스는 사람이 `/tpx` 로」 실패시켰다. 계약 변경이 승인돼 근거가 사라졌으므로 추정을 뺐다
- **설정을 바꾸거나 판정 스크립트가 바뀐 배포 뒤에는 에이전트를 다시 켠다.** 서비스 목록·서버·폴더는 켤 때
  `/auth/me` 한 번으로 받고, 판정 스크립트도 켤 때 메모리에 고정한다
- **아직 막지 않는 것** — 서비스의 테스트 저장소(`tests_repo`)가 이 플랫폼 저장소가 아니면 작성은 끝내기에서 거절된다
  (서버의 PR 주소 대조). 집기 전에 거르려면 `/auth/me` 에 저장소 주소를 더 실어야 해서(계약) 이번엔 안 했다 (2026-09-25)

**신뢰 경계 (2026-09-23).** 기획서를 올릴 수 있는 사람(그 서비스의 작성 `write`)의 파일은 자식 Claude 가 **셸 권한으로** 읽는다.
그래서 기획서에 숨긴 지시로 자식이 움직인다고 보고 막는다. 자식은 **GitHub 자격증명을 뺀 환경**으로 떠서 push·PR·병합을 못 하고
(`Bash(git:*)` 같은 이름 막기는 실수 방지일 뿐이다), 에이전트는 올리기 전과 병합 직전에 **GitHub 이 말하는 main SHA** 기준으로,
**켤 때 메모리에 고정한** 판정 스크립트로 「테스트만」을 판정한다.
**commit·push 는 작업마다 만든 사본에서 훅을 끄고(`core.hooksPath=/dev/null`) 한다** (2026-09-24) — 트리의 훅은 자식이 쓸 수 있는 자리다.
그래서 에이전트의 push 에는 pre-push 가 안 돌고, 같은 검사(타입·K 규칙)는 CI 가벼운 길이 한다.
**서버 컨테이너에서는** 자식이 다른 uid 라 사본의 bare git·서버 저장소·에이전트의 토큰에 못 닿는다 (위 「★ 서버 컨테이너가 기본이다」).
**맥에서는 그래도 자식이 맥 계정의 파일을 읽고 쓸 수 있다**(keychain · 사본의 bare git 설정 포함) — 키체인과 함께 전용 macOS 계정으로 푼다 (후속).

**뒤집은 판단 — 「자식이 `/tpx` 를 타고 초안 PR 을 연다」.** 앞 판은 자식 Claude 에게 `/tpx` 일곱 단계를 통째로 맡겨
작업방·초안 PR 까지 자식이 열게 했다. **첫 한 바퀴 실측에서 무너졌다** (PR #62, 닫음).
관문 넷까지는 약 10분에 끝났는데 [6] 독립 검사가 30분을 넘기다 자식이 백그라운드 검사를 남긴 채 먼저 끝났고,
PR 은 [6] 에서 멈췄다. [6] 은 관문 넷과 겹치고 [7] 은 사람이 화면에서 누르니 자식에게 할 일이 없었다.
PR 주소도 자식 출력에서 찾아야 해서 고리가 약했다 — 이제 PR 을 스크립트가 여니 주소를 직접 안다.
**판단 기준이 아직 쓸모 있어 남긴다** — 다음에 「자식에게 `/tpx` 를 통째로 맡기자」가 나오면 이 실측부터 본다 (CLAUDE.md §2.7 ②).

#### ★ 역방향 — 화면과 대조한다 (2026-09-25 · 게이트 0)

**역방향의 정본은 이 절이다.** 다른 장은 이 절을 가리키고 자기 표면만 적는다 —
칸은 [공통/4-데이터모델.md](../공통/4-데이터모델.md) §6, `CaseSpec.unconfirmed` 와 K11 은
[공통/3-공유계약.md](../공통/3-공유계약.md) §5.1 · [공통/2-명세선언.md](../공통/2-명세선언.md) §4,
집계는 [실행.md](실행.md), 대상 서버 줄의 테스트 계정은 [인증.md](인증.md) §8.8, 통로는 아래 §7.

**무엇인가.** 지금까지의 작성(정방향)은 기획서만 읽고 케이스를 만든다. 기획서가 늦거나 화면과 어긋나면
그 어긋남이 작성 도중에 조용히 묻힌다. **역방향은 실제 화면을 같이 본다.** 두 갈래다.

- **대조** — 기획서와 실제 화면을 맞대 본다. 같으면 정식 케이스, 다르면 원본 기획서에 표시해 넘기고 그동안 화면 기준 임시 케이스를 만든다
- **화면만** — 기획서 없이 **시작 주소**만 받는다. 거기서 링크로 갈 수 있는 같은 사이트의 모든 화면을 훑어(아래 「기획서가 없을 때」) 케이스(전부 미확정)와 **워드 역기획서**를 만든다

둘을 합쳐 **역방향**이라 부른다. 요청의 `compare` 가 켜진 것이 역방향이고, 자료가 0 이고 `startUrl` 이 있으면 화면만이다.
`startUrl` 은 **훑기를 시작할 화면**이다. 대조에서는 없어도 된다 — 없으면 기획서가 말하는 화면에서 시작한다.

**정한 것** (2026-09-25 사용자 · 게이트 0 두 번 승인)

| 무엇 | 정한 것 |
|------|------|
| 하는 일 | 기획서와 실제 화면을 **대조**한다 |
| 같을 때 | **정식 케이스.** 기대값은 기획서, 화면에서는 요소 주소(selector)만 읽는다 |
| 다를 때 | 원본 기획서에 표시해 기획자·의사결정자에게 넘기고, 그동안 **화면 기준 임시 케이스**를 만든다 |
| 임시 케이스 | **「미확정」 꼬리표**를 단다. 실행은 하되 통과율·증적에서 따로 묶는다. 수정된 기획서가 다시 오면 확정하거나 지운다 (아래) |
| 화면에만 있을 때 | 다를 때와 같다 — 「문서에 없음」 표시 + 미확정 케이스 |
| 훑는 범위 | 기획서가 말하는 화면 + 거기서 **바로 이어지는 한 칸**. 한 칸은 **그 화면 안에서 여는 것**(팝업·탭·펼치기·그 흐름의 다음 단계)이다 — 머리 메뉴·바닥 링크·다른 기능으로 가는 링크는 한 칸이 아니다 (2026-09-27 · 게이트 0. 홈에서 메뉴 전체를 한 칸으로 읽어 38장을 훑고 60분에 걸렸다) |
| 로그인 | 설정 > 서비스 > **대상 서버 줄마다 테스트 계정** |
| 표시 | 워드는 메모 단 사본 · 피그마는 그 화면에 댓글 · PDF 는 스티커 메모 사본(**새 npm 패키지 승인 뒤** — 그 전엔 차이 목록만) |
| 켜는 자리 | 작성 화면의 「실제 화면과 대조」 체크박스. 켜면 대상 서버(`qa` 등)도 고른다 |
| 기획서가 없을 때 | **된다(화면만).** 자료 대신 시작 주소를 받고 거기서 **링크로 갈 수 있는 같은 사이트의 모든 화면**을 훑는다(2026-10-03 게이트 0 · 사용자 「모든 화면을 봐야지」). 머리 메뉴 · 하위 메뉴 · 바닥 링크 · 화면 안 링크(로그인 화면의 비밀번호 찾기 · 가입 · 약관 등)를 다 넣는다. **같은 틀은 대표 하나만 연다**(게시판 글 · 쪽 번호 · 정렬) — 무엇이 같은 틀인지는 아래 「화면 구조는 크롤러가 먼저 뽑는다」가 정본이다(숫자 · 번호 마디와 쪽 · 정렬 · 돌아갈 주소 인자만 묶고, `?modal=` 처럼 글자 값으로 화면을 가르는 인자는 묶지 않는다 — 2026-10-04 에 「쿼리만 달라도 같은 틀」을 좁혔다. 그 규칙대로면 CDY `?modal=login` 과 비밀번호 찾기 창이 하나로 묶인다). **로그인 전과 뒤 두 상태로 훑는다** — 로그아웃 상태에서 갈 수 있는 화면과 로그인 상태에서 갈 수 있는 화면을 각각 목록에 넣고 줄마다 상태를 적는다. 두 상태에 다 있는 주소는 로그인 상태로 한 번만 열고, 시작 화면만 두 상태 모두 연다(2026-10-03 사용자 「로그인 전 화면도 확인해야」). 다른 사이트 · 파일 내려받기 · 제출해야 열리는 화면 · 로그아웃 버튼은 뺀다(아래 허용 목록). 화면만에만 쓴다 — 대조는 위 「한 칸」 그대로다. 그전에는 메뉴 1단계(2026-09-27 게이트 1)였고 하위 메뉴를 더했다가(2026-10-03 · CDY 26 → 10장) 바닥 링크 · 로그인 화면 링크가 빠져 비밀번호 찾기 · 약관 둘을 놓쳤다(CDY 11209 · 23장). 케이스는 **전부 미확정**, 산출물은 워드 역기획서(pandoc · 항목마다 「확인 필요」 칸) |

**처리 — 차이마다 무엇을 만드나**

| 기획서와 화면 | 케이스 | 기획서에 | `result.diffs[].kind` |
|------|------|------|------|
| 같다 | **정식** — 기대값은 기획서 | 아무것도 안 단다 | 안 싣는다 |
| 다르다 | **미확정** — 화면 기준 | 원본 표시 | `DIFFERENT` |
| 화면에만 있다 | **미확정** — 화면 기준 | 「문서에 없음」 표시 | `SCREEN_ONLY` |
| 문서에만 있다 | **정식** — 기대값은 기획서. 실패할 것이고 **그게 맞는 신호다** | 「화면에 없음」 표시 | `DOC_ONLY` |

화면만은 대조할 기획서가 없어서 표를 안 탄다 — 케이스가 전부 미확정이고 표시 대신 역기획서를 낸다.

**미확정 꼬리표.** 케이스에 `defineCase({ ..., unconfirmed: '<사유 한 문장>' })` 를 단다.
예 `'기획서와 다름 — 차이 D3: 저장 버튼 이름이 「확인」이다 (작성 요청 5870)'`(꼴은 `tpx-cases` `references/wording.md` 「사유 머리」). 사유에 차이 번호를 실어 증적과 표시 사본에서 같은 차이를 찾게 한다.
- **역방향 작성만 단다 — 예외 하나, 정방향이 화면에서 본 기획서에 없는 입력 규칙**(아래 「★ 테스트 두 갈래」, 2026-10-02 사용자). 그 밖의 정방향 작성과 사람이 쓴 케이스는 달지 않는다 (사람이 본다 · spec-review B10 — K11 은 모양만 본다).
  이미 있는 케이스에 꼬리표를 새로 다는 diff 는 spec-review · `check:tests` 가 경고하고 게이트 2 요약에 싣는다 (판정 방식은 [실행.md](실행.md) §3.2)
- 미확정 케이스도 계정 값은 `params` 비밀값 칸으로만 받는다. 글자로 박지 않는다 (K9)
- **확정하는 길은 둘이다** (2026-10-01 게이트 0 — 앞 판은 「정방향 재요청 하나다」).
  ① 기획자가 고친 기획서(화면만이면 고친 역기획서)를 **정방향 요청으로 다시 올리면**
  R9 대조(기존 요구사항 표와 더하기·바꾸기·없애기를 가르는 규칙, `.claude/skills/tpx-cases/references/4-selector.md`)로
  꼬리표를 떼거나 케이스를 지운다 ② **어드민에서 케이스 고치기로 확정한다** — 사람이 지금 기대값을 보고 맞다고 판정하는 것이고,
  필요하면 같은 요청에서 기대값도 고친다. 정본은 아래 「★ 케이스 고치기」.
  ②를 더한 까닭: 기획 답이 말로 오거나(PO 결정) 화면이 맞는 것으로 판명돼 고칠 기획서가 없을 때 길이 없었다 —
  PR #116 이 35건의 꼬리표를 손으로 뗐다. ①의 판단 기준(기획서 · R9)은 그대로 쓸모 있어 남긴다

**왜 기대값 규칙의 예외인가.** 이 저장소는 **기대값을 사람이 판정한 것에서만** 가져온다 (CLAUDE.md 「playwright-cli」).
화면이 버그를 갖고 있으면 그 버그가 기대값으로 박히고 회귀 세트가 영원히 지키기 때문이다.
화면 기준 임시 케이스는 그 규칙의 **예외**다 — 사용자가 위험을 듣고 골랐다(2026-09-25).
**위험은 「답이 안 오면 버그를 지키는 케이스가 초록으로 남는다」이다.** 꼬리표가 그것을 막는다 — 집계·증적·목록에서
따로 묶여 「사람이 판정한 초록」과 섞이지 않는다. **꼬리표 없이 화면 값을 기대값으로 쓰는 것은 여전히 금지다.**

**훑기 규칙 — 허용 목록이다.** 자식 Claude 는 브라우저로 화면을 훑되 **링크 이동 · 탭 · 펼치기 · 팝업 열고 닫기만 한다.** 그 밖은 하지 않는다.
- **폼 제출과 입력 뒤 확정은 로그인 폼 말고는 하지 않는다.** 저장·삭제·결제·발송이 여기 든다. 로그아웃도 누르지 않는다
- **다음 단계가 제출을 요구하면 거기서 멈춘다.** 그 흐름은 케이스로만 만들고 관문 실행에서 돈다 — 정방향과 같다
- 훑는 범위는 위 표의 「훑는 범위」다. 화면만은 시작 주소가 그 출발점이다
- **훑기 예산 30분** (2026-09-27 게이트 1) — 넘으면 더 훑지 않고 본 것까지로 케이스를 만든다. 결과 요약에 「예산으로 멈춤」을 적는다.
  「한 칸」 정의는 자식이 읽는 산문이라 또 넓게 읽힐 수 있다 — 훑기에 묶여 케이스 · 관문이 늦어지지 않게 둔 예산이다(전체 시간 상한은 없다 — §7 「중단」 표의 `TIMEOUT` 은 출력 20분 없음, 2026-10-03)
- **화면 구조는 크롤러가 먼저 뽑는다** (2026-10-04 게이트 0 · 사용자 「페이지 구조를 한번에 파악하는 playwright 기능」) — 자식이 로그인 상태 파일을 만든 뒤 `npx tsx scripts/authoring-crawl.ts` 를 한 번 돌린다.
  크롤러는 AI 없이 로그인 전 · 후 두 번 화면마다 Playwright `ariaSnapshot`(역할 · 이름으로 된 화면 구조) · 보이는 입력칸 속성(필수 · 글자 수 · 형식) · 링크 수를 자료 폴더의 `crawl/` 에 쓴다. 화면만은 같은 사이트 링크를 따라가고(`--follow`), 대조는 기획서가 말하는 화면 주소만 찍는다(따라가면 「한 칸」 범위를 넘는다).
  **허용 목록 안에서만 돈다** — 링크 이동뿐이고 누르기 · 제출이 없다. 링크 글자(로그아웃 · 탈퇴 · 삭제 · 담기 · 결제)나 주소의 동작 낱말(logout · delete · add · cancel · `act=` 등) · 내려받기 · 다른 출처는 따라가지 않는다. 한 장씩 1초 이상 띄우고, 429 · 5xx 가 세 번 이어지면 멈추고, 그림 · 글꼴 · 영상은 받지 않는다. 합계 100장 · 10분이 상한이고 이 시간은 훑기 예산 30분에 든다.
  로그인 판에서 로그인 주소로 돌려보내지거나 아이디 · 비밀번호 칸이 같이 나오면 「로그인 풀림」으로 멈춘다 — 자식이 다시 로그인해 상태 파일을 새로 만든다. 로그인 화면이 아니라 홈으로 돌려보내는 사이트는 못 가른다 — 그때는 서브에이전트의 「로그인으로 튕김」 보고가 그물이다. 판정은 `scripts/authoring-crawl-rules.ts` — **같은 틀**은 숫자 · 번호 마디(주문 번호 꼴 포함) · 쪽 · 정렬 · 돌아갈 주소 인자만 묶는다. `?modal=` 처럼 글자 값으로 화면을 가르는 인자는 묶지 않고, 숫자 값 인자로 가르는 틀(`?board_no=1` · `=4`)은 둘째 장까지 열어 구조 지문(글자 · 숫자를 뺀 요소 짜임)이 다르면 둘 다 남긴다.
  위험 글자는 12자 이하 버튼 글자에만 본다(글 제목의 「추천」은 따라간다). 걸러진 링크는 `index.json` 에 남고 요약에 수가 실린다 — 「결제 내역」 같은 정상 화면이 걸렸으면 자식이 거기서 보고 손으로 연다. 한 폴더 아래 20장이 넘으면 더 열지 않고 그 수도 싣는다. 장수 · 시간은 두 상태가 반씩 나눈다.
  **자식은 `crawl/list.json`(주소 · 이름 · 상태 · 파일 · 틀 · 지문 둘, 저장본이 있으면 `저장본` · `저장기록`)과 아래 저장본 `kept/` 만 읽는다** — `index.json` 과 화면마다의 `.yml` 은 열지 않는다(대화 토큰). 서브에이전트는 맡은 화면의 `.yml` 만 읽고 화면 구조를 다시 찍지 않으며, 팝업 · 탭 · 펼치기 · 다음 단계 · 입력 규칙의 오류 문구처럼 **눌러 봐야 아는 것만** 직접 연다.
  크롤러가 못 찾은 화면(버튼 · 라우터로만 가는 화면)은 서브에이전트가 「더 갈 곳」으로 알린다. 실측 — 데모마켓 22장 82초, CDY(로그아웃) 57장 115초(비밀번호 찾기 · 약관 포함)
- **서비스 설정의 「훑지 않을 경로」는 화면만 작성에서 뺀다** (2026-10-04 게이트 0 · 사용자 — CDY 대전 · 경남 지역 사이트) — 에이전트가 건을 가져갈 때마다 `GET /api/auth/me` 의 `services[].crawlExclude` 를 다시 읽고(못 읽으면 켤 때 읽은 것) 값 규칙으로 한 번 더 거른 뒤, 화면만 역방향 절의 크롤러 명령에 `--exclude '<경로>'` 를 경로마다 붙인다.
  크롤러는 주소 경로(pathname)가 그 경로이거나 그 아래면(마디 경계 — `/daejeon` 은 `/daejeonx` 를 안 뺀다 · 인코딩은 풀어서 · 대소문자는 가른다) 열지 않고(다른 주소에서 그 경로로 넘겨진 화면도), 저장본과 견주기 전에 그 경로의 저장 항목도 뺀다 — 첫 실행에서 「저장본에 있는데 못 본 화면」 수가 부풀지 않게. 그 저장 기록은 「다 봄」 실행의 갈기에서 지워진다(의도 — 나중에 빼기를 풀면 새 화면으로 다시 훑는다).
  서브에이전트는 「더 갈 곳」에도 그 경로를 적지 않는다. 해시 라우트(`#/…`) 안 화면은 경로로 못 뺀다. 시작 주소가 뺄 경로 안이면 크롤러는 아무것도 열지 않고 요약에 경고를 띄운다 — 설정을 고치라는 뜻이다. 대조는 기획서 화면만 보므로 붙이지 않는다. 이어서 작성은 앞 실행의 크롤 목록을 쓴다 — 바뀐 설정은 새 실행부터 먹는다. 값 규칙은 [인증.md](인증.md) §7 계약 변경 블록
- **바뀐 화면만 다시 훑는다 — 화면 기록 저장본** (2026-10-04 게이트 0 · 1 · 사용자 지시 11) — 에이전트가 화면 기록을 작업 바탕(서버 `/work` 볼륨 · `AUTHORING_WORK_DIR`) 아래 `screens/<접두사>/` 에 남긴다(root 소유 · 저장소 밖).
  자식을 띄우기 전에 저장본을 자료 폴더 `kept/` 로 넣고, 크롤러가 `--keep` 으로 견줘 목록에 `저장본: 같음 · 바뀜 · 새 화면` 을 단다. **같음은 저장 기록을 복사해 쓰고 다시 훑지 않는다.**
  같음의 기준은 글자 지문(크롤 파일 전체 — `#` 머리 줄은 숫자까지, 본문 숫자는 0) — 번호로 묶인 상세(틀에 `:n`)는 저장 때와 다른 글을 봤을 수 있어 구조 지문으로 견준다. 훑은 지 30일이 지나면 바뀜으로 본다(지문이 못 잡는 팝업 안 · 오류 문구 변화를 언젠가는 본다).
  올릴 때 에이전트가 자료 폴더의 `crawl/list.json` · `summary.json` · `screens/*.md` 를 읽어 **이번에 본 화면만** 저장본에 간다. 기록 첫 줄 `# <크롤 주소>` 로 목록과 맞추고 안 맞으면 저장하지 않는다. 못 본 화면을 지우는 것은 화면만 · 크롤 「다 봄」일 때만이고, `list.json` 이 없으면 아무것도 안 한다.
  에이전트는 root 라 자료 폴더 파일을 링크 · 하드링크 · 200KB 넘는 것은 읽지 않고, 저장 폴더가 링크면 쓰지 않는다. 크롤 요약에 「저장본에 있는데 이번에 못 본 화면」 수와 가장 오래된 기록의 날수가 실린다.
  **저장소(`docs/screens`)에 두지 않은 까닭** — 같은 서비스 두 건이 같은 기록 파일을 고치면 반영 때 main 합치기가 실패해 작성 전체를 다시 해야 하고, 로그인 상태 화면의 이름 · 이메일 · 계정 아이디가 main 이력에 영구로 남는다(강제 push 금지라 못 지운다 — 게이트 1 검토). 디스크가 비었거나 다른 기계(맥 대체)면 저장본이 없을 뿐이고 전부 훑는다. **맥 대체는 격리가 없다** — 자식과 에이전트가 같은 계정이라 자식이 작업 바탕의 `screens/` (다른 서비스 것까지)를 고칠 수 있다. root 소유 보호는 서버 `author` 에만 맞는다.
  같은 키는 `상태 + 주소`(같은 주소가 두 상태로 목록에 있다) · 재사용한 화면의 훑은 날은 바꾸지 않는다(30일 그물) · 못 본 화면 지우기는 크롤이 예외 없이 다 봤을 때 실제로 돈 상태만 · 이어받기는 앞 실행의 `kept/` 를 그대로 둔다(크롤러를 다시 안 돌린다) · 재사용 수와 가장 오래된 날은 에이전트가 PR 본문 머리에 싣는다
- **훑기를 나눈다** (2026-10-03 게이트 0) — 자식이 훑을 화면 목록(주소 · 이름)을 뽑는다. 첫 목록은 위 크롤러의 `list.json` 이다(두 상태에 다 있는 틀은 로그인 하나 · 시작 화면만 둘 다 — 크롤러가 이미 골랐다). 크롤러를 못 돌렸으면 화면만은 **로그아웃 상태(시작 화면 · 로그인 화면)와 로그인 상태(시작 화면)에서 같은 사이트 링크를 한 번에 모아** 상태가 붙은 첫 목록을 만든다(위 표 「기획서가 없을 때」 — 비밀번호 찾기 · 가입 링크는 로그인 화면에만 있다). 로그아웃 상태 화면은 로그인 상태 파일 없이 연다. 같은 틀은 자식이 목록을 합칠 때 하나로 줄인다.
  목록이 길면 머리 메뉴 직속부터 나눈다. 결과 요약에 `훑은 화면 K장 / 목록 N장` 을 적어 빠진 화면이 드러나게 한다 — N 은 찾아서 같은 틀을 합친 주소 전체(크롤러 목록 + 더 갈 곳)이고, K 는 화면 기록(`screens/*.md`) 수 — 화면 카드의 「훑은 화면」과 같다(크롤 동안은 0). 마감으로 못 연 주소는 결과 요약에 남긴다.
  같은 줄에 `기계로 본 화면 N장 · 직접 연 한 칸 M개 · 더 갈 곳 X · 빈 화면 의심 S` 를 싣는다 — M 은 화면 기록의 「연 한 칸」 줄 수. AI 가 기계 결과만 믿고 눌러 보기를 건너뛰면 M 이 줄어 드러난다(2026-10-04 게이트 1).
  화면이 넷 이상이면 서브에이전트 넷까지 **한 차례**로 나눠 훑는다. **화면만은 예외** — 서브에이전트가 목록에 없는 같은 사이트 주소를 찾으면 화면 기록 끝 「더 갈 곳」에 주소만 적고, 자식이 모아 같은 틀을 합친 뒤 남은 것이 있으면 차례를 더 띄운다(차례마다 넷까지, 셋 이하면 자식 혼자). 마감이 지나면 새 차례를 띄우지 않는다. 서브에이전트는 이 허용 목록 · 아래 출처 규칙을 그대로 지키고 **화면 기록 파일만** 쓴다.
  로그인 상태 파일은 자식이 한 번 만들어 같이 쓰고, 로그인 상태로 연 화면이 로그인 화면으로 튕기면 그 서브에이전트는 멈추고 알린다(로그아웃 상태 화면은 상태 파일 없이 연다) — 그 화면은 자식이 혼자 훑는다.
  예산 30분은 자식이 첫 화면을 연 때부터의 벽시계이고 서브에이전트에게는 **마감 시각**(절대 시각)으로 넘긴다. 표 · 차이 목록은 자식 혼자 쓴다
- **본 것은 화면마다 파일로 적고 대화에는 한 줄만 남긴다** — 페이지 구조 전체를 대화에 붙이면 뒤의 모든 턴이 그것을 다시 읽는다
- **이 규칙은 자식에게 주는 지시라 기획서에 숨긴 지시로 깨질 수 있다.** 기계적 방어는 계정 권한(아래 「로그인」)과 운영 줄 금지뿐이다

**로그인.** 대상 서버 줄(`service_env`)에 적힌 테스트 계정으로 들어간다. 에이전트는 집기 응답의 `target`
(`env` · `baseUrl` · `startUrl` · `loginId` · `loginPassword`)으로 받아 자식 환경에만 넘긴다 — 피그마 토큰과 같은 길이다 (§7 「자료」).
넘기는 방법과 집기 때 다시 대조하는 것은 §7 이 적는다.
- **테스트 계정 비밀번호는 그 서비스의 작성 `write` 전원이 알 수 있는 값으로 본다.** 화면에서 가리는 것은 표시일 뿐 경계가 아니다.
  그들에게 알려도 되는 **권한 낮은 전용 계정만** 넣는다 ([`docs/SETUP.md`](../../SETUP.md) §8)
- **운영 서버 보호** — 역방향은 **테스트 계정을 넣은 대상 서버 줄만** 고를 수 있다(아니면 400 `BAD_ENV`, §7). 운영 줄에는 계정을 넣지 않는다. 「계정을 넣은 줄」은 **아이디와 비밀번호가 둘 다 있는 줄**이다 — 로그인하려면 둘 다 필요하다.
  그러면 역방향이 운영 서버로 가지 못한다
- **출처 규칙** — 다른 출처로 나가는 링크는 따라가지 않는다. 훑는 중 리다이렉트로 출처가 바뀌어도 링크와 같이 보고 따라가지 않는다.
  계정을 입력하기 **직전에** 지금 페이지 출처가 `baseUrl` 출처인지 확인하고, 다르면 입력하지 않고 그 화면을 멈춘다
- `startUrl` 은 그 서버 주소와 **출처가 같아야** 한다(§7 `BAD_START_URL`). **이것은 실수 방지이고 자식을 막는 장치가 아니다**
- **SSO(다른 출처를 거치는 로그인)는 이번 판에서 지원하지 않는다** — 출처 규칙이 그 입력을 막는다 (아래 「아직 알 수 없는 것」)

**표시는 실패해도 요청을 실패시키지 않는다.** 워드 메모·피그마 댓글·PDF 표시가 안 되면 그 차이에
`marked: false` 와 `markError` 를 남기고 요청은 끝까지 돈다. 피그마 토큰에 댓글 쓰기 권한이 없을 때가 그 예다 ([인증.md](인증.md) §8.8).

**산출물.** 표시 사본과 역기획서는 **플랫폼에 올린다** — 새 통로 `outputs` 로 자료 목록에 역할(`MARKED` · `REVERSE_SPEC`)을 달고 선다 (§7).
**저장소에 들어가는 것은 정방향과 같다** — 케이스와 `docs/cases` 표, 글자본 자료가 있으면 요구 지문 파일(위 「★ 원장」 「요구 지문」)뿐이다.

**남는 한계 — 알고 쓴다**
- **자식이 테스트 계정 비밀번호를 든다** — 브라우저로 로그인해야 해서다. 기획서에 숨긴 지시로 밖에 보낼 수 있다(위 「신뢰 경계」).
  그래서 **권한 낮은 전용 테스트 계정**을 쓴다 (위 「로그인」)
- **기획서에 적힌 비밀번호는 받자마자 가린다** (2026-09-29 사용자) — 에이전트가 자료를 받아 글자로 바꾼 뒤, 자식을 띄우기 **전에**
  자료 폴더 전체(글자본 · 차이 · 화면 기록) · 트리에서 앞 실행이 바꾼 케이스 · 요구사항 표 · 옛 행 본문에서 원문을 `••••••` 로 바꾼다.
  작업 폴더에 받은 워드 사본은 글자로 바꾼 뒤 지운다 — **서버에 올린 원본 자료는 그대로 둔다.** 못 가리면 자식을 띄우지 않고 `FAILED`.
  **이어받은 실행도 같다** — 앞 실행이 남긴 파일까지 여기서 가려진다. 케이스에 `••••••` 가 남으면 올리기 거절로 돌려 비밀값 자리로 고치게 한다.
  표시 사본은 워드 글 칸(글 · 지운 글 · 필드 코드 · 차트 글)에서 같은 표시로 가린다 — 여러 칸에 갈려도, 속성은 안 건드린다.
  **못 가리는 것** — PDF · 그림 · 피그마 · 워드 속성이나 문서 정보 칸 · UTF-8 이 아닌 글자 파일 · 20MB 넘는 파일. 그때는 아래 검사가 잡는다
- **올리는 것에서는 에이전트 스크립트가 막는다 — 자식이 아니다.** `outputs` 올리기 전 · `finish` 전 · push 전에
  그 요청의 `loginPassword` 원문이 올릴 파일 · `result`(`diffs` 포함) · `stage` · `testSource` · 케이스 diff · PR 본문에 있는지 찾는다.
  있으면 올리지 않고 **중단(올리기 거절)** 으로 끝내며 사유에 값을 싣지 않는다(§7 이유 표 `REJECTED`). 자식이 인터넷으로 직접 보내는 것은 이것이 못 막는다
- **검토한 대안** — 자식에게 비밀번호 대신 에이전트가 로그인해 만든 세션(`storageState`)만 넘기는 방법.
  새는 것을 수명 짧은 세션으로 줄일 수 있다. 이번엔 안 했다
- **미확정이 오래 남을 수 있다** — 기획 답이 안 오면 끝이 없다. 가장 오래된 미확정의 나이를 서비스 머리에 보인다 ([카탈로그.md](카탈로그.md))

#### ★ 보류 케이스 — 사람이 값을 채운다 (2026-09-29 · 게이트 0·1)

**보류 케이스의 정본은 이 절이다.** 다른 장은 이 절을 가리키고 자기 표면만 적는다 —
꼬리표 `CaseSpec.held` 는 [공통/3-공유계약.md](../공통/3-공유계약.md) §5.1, K10 예외와 K13 은
[공통/2-명세선언.md](../공통/2-명세선언.md) §4, 칸 `held_input` 은 [공통/4-데이터모델.md](../공통/4-데이터모델.md) §6 「작성 보류 입력 칸」,
통로는 아래 §7, 화면은 [`docs/DESIGN.md`](../../DESIGN.md) 「작성 상태」.

**무엇인가.** 5877(데모마켓 대조)에서 요구 15건이 「판정 불가·보류」로 빠졌다. 그 목록은 PR 본문 글로만 남아
누구도 이어받지 못했고 병합되면 사라졌다. 대부분은 기대값 기준이 기획서에 없거나 전제 값(관리자 계정 · 대기 시간)이 없어서다 —
**사람이 값 하나만 주면 케이스가 된다.** 그래서 자식이 그 요구도 **케이스 코드까지** 만들고, 사람은 작성 상세 화면에서
빈 칸에 값을 넣거나 그 케이스를 제거한 뒤 「반영」(머지)을 누른다.

**정한 것** (2026-09-29 사용자 · 게이트 0·1)

| 무엇 | 정한 것 |
|------|------|
| 누가 코드를 쓰나 | **자식이 전부 쓴다** — 판정 불가 · 보류 요구도 절차 · 판정까지. 사람이 채울 칸만 비운다 |
| 비운 칸 | `.describe()` 만 있고 `.default()` 가 없다. 그래서 K10 이 이 케이스에만 예외를 둔다 |
| 사람이 넣은 값이 가는 곳 | **코드의 `params` · `expected` 기본값(`.default(값)`)** — 테스트 본문에 박는 하드코딩이 아니다. 실행 화면에서 지금처럼 바꿔 넣을 수 있다 |
| 사람이 하는 일 | 칸마다 값을 넣거나, 그 케이스를 **제거**한다. 넣은 값은 되돌릴 수 있다 |
| 반영 | 에이전트가 값을 코드에 적고 → **채운 케이스를 3회 실행** → 통과해야 병합. 하나라도 실패하면 병합하지 않는다 |
| 꼬리표 | `defineCase({ ..., held: '<머리> — <사유 한 문장>' })`. 있으면 `test(spec)` 이 **건너뛴다**(skip) — 값이 없어 돌 수 없다 |

**머리 둘 — 판정 불가와 보류**

| 머리 | 언제 | `result.held[].kind` |
|------|------|------|
| `판정 불가 — ` | 기대값 기준이 기획서에 없다. 사람이 판정한 기대값이 필요하다 | `UNDECIDABLE` |
| `보류 — ` | 전제 값(대기 시간 · 특정 데이터 · 관리자 계정 같은)이 없다 | `ON_HOLD` |

예 `held: '판정 불가 — 쿠폰 중복 적용 시 최종 금액 기준이 기획서에 없다'`. 공백뿐이면 키가 없는 것으로 친다(`unconfirmed` 와 같은 규칙).

**코드 모양.** 비운 칸은 `.describe()` 만 단다 — 칸 설명이 화면의 라벨이 되므로 **사람이 무엇을 넣을지 알 수 있는 문장**으로 쓴다.

```ts
export const spec = defineCase({
  tcId: 'MKT-041',
  name: '쿠폰 두 장을 겹쳐 쓰면 최종 금액이 기준대로 나온다',
  held: '판정 불가 — 쿠폰 중복 적용 시 최종 금액 기준이 기획서에 없다',
  params: z.object({ couponA: z.string().describe('첫 쿠폰 코드').default('WELCOME10') }),
  expected: z.object({ total: z.number().describe('두 쿠폰을 적용한 최종 결제 금액(원)') }),
  ...
});
```

**왜 기대값 규칙 안인가.** 이 저장소는 기대값을 **사람이 판정한 것에서만** 가져온다 (CLAUDE.md 「playwright-cli」).
보류 칸의 값은 **사람이 화면에서 넣은 값**이다 — 자식이 화면에서 읽은 값이 아니다. 그래서 역방향의 미확정과 달리 규칙의 예외가 아니다.
**자식이 비운 칸을 제 짐작으로 채우는 것은 금지다** — 그러면 그 케이스는 보류가 아니라 근거 없는 정식 케이스다.

**입력 칸 (`held_input`)**
- **뿌리의 최신 끝난 실행 행**에만 받는다 — 화면이 보는 결과가 그 행 것이다. 아니면 409 `NOT_LATEST`
- **새 실행(이어서 작성 · 다시 작성)이 끝나면 옮긴다** — 끝내기(`finish`) 안에서 앞 행의 입력 가운데 **같은 tcId · 같은 칸 이름**인 것만 새 행으로 옮긴다.
  제거 표시는 그 tcId 가 새 결과에도 보류로 있으면 옮긴다. 칸이 바뀌었거나 없어진 입력은 버린다 — 옛 칸 이름에 값을 적으면 코드가 깨진다
- 머지가 대기 · 도는 중이면 넣기 · 되돌리기가 409 `MERGE_ACTIVE` — 에이전트가 집은 입력과 화면이 달라진다
- 누가 · 언제(`by` · `at`)를 서버가 붙인다. 부르는 쪽이 적지 않는다

**채울 칸 계산 (`fields`).** 어떤 칸을 화면에 보일지는 **에이전트 스크립트가 코드(스키마)에서 계산**해 끝내기의 `result.held[]` 에 싣는다 — 자식의 말을 믿지 않는다.
- **기본값이 있는 칸은 뺀다** — 이미 값이 있다
- **비밀값 칸(`.meta({ secret: true })`)은 뺀다.** 화면에서 받지 않는다 — 반영 때 대상 서버 줄의 테스트 계정으로 채워 돈다(아래 「반영」)
- **타입은 넷만** — `string` · `number` · `boolean` · `enum`(선택지 `options`). 그 밖(배열 · 객체 · 날짜 같은) 칸은 `fields` 에 안 싣고, 그 케이스는 **제거만** 된다
- **채운 것** = 모든 `fields` 에 값이 있다. **남은 보류(`heldOpen`)** = 채우지도 제거하지도 않은 케이스 수. `fields` 가 빈 케이스는 제거해야 0 이 된다

**반영 — 머지 에이전트가 하는 일** (보류 입력이 있는 머지만. 없으면 지금 머지 그대로다)

1. **자리를 잡는다** — 작성과 같은 동시 상한에 센다. 작업방을 열고 케이스를 돌리기 때문이다
2. **작업방** — 작성 에이전트의 관문 환경(작업방 · 자리 uid · 대상 서버 환경 변수)을 그대로 쓴다. `author-<뿌리>` 의 **자식이 끝낸 커밋** 위에서 연다
3. **값 적기** — 채운 칸에 `.default(값)` 을 적는다(이미 기본값이 있으면 바꾼다). 값은 **TypeScript 리터럴로 만들어 적는다**(`ts.factory`) — 글자를 이어 붙이지 않는다(따옴표 · 줄바꿈이 코드를 깬다).
   `held` 속성을 뺀다. `unconfirmed` 는 그대로 둔다(아래)
4. **제거** — 제거한 케이스 파일을 지우고, `docs/cases` 요구사항 표의 그 tcId 칸을 「제거함(<tcId>)」로 바꾼다
5. **검사** — 타입 검사 · `check:tests --no-held`. `held` 가 하나라도 남으면 병합하지 않는다
6. **3회 실행** — 채운 케이스만 `--repeat-each=3`. 대상은 claim 의 `target`(아래 「대상 서버」). 비밀값 칸은 그 줄의 테스트 계정으로 채운다
7. **올리기** — 적을 글(케이스 · 표)과 커밋 메시지에 대상 서버 줄의 **비밀번호 원문**이 있으면 올리지 않고 `FAILED`(「넣은 값에 테스트 계정 비밀번호가 들어 있어 올리지 않았다」 — 값은 안 싣는다. 입력은 남는다).
   지울 파일도 쓸 파일처럼 모양(링크 · 트리 밖)을 본 뒤 지운다. 자기 브랜치 `author-<뿌리>` 에 `--force-with-lease` 로 올린다(CLAUDE.md §5 예외 안 — 자기 브랜치 덮어쓰기).
   원격 머리 커밋이 에이전트 것이 아니면 덮어쓰지 않는다(아래 「실행 기록」 PR 줄과 같은 규칙)
8. **PR 을 다시 읽어 새 head SHA 로 CI 를 기다린다** — push 전에 읽은 head 로 기다리면 옛 커밋의 초록으로 병합한다. 그다음은 지금 머지와 같다(초록일 때만 병합)

- **실패하면** `FAILED` 로 끝내고 사유에 **케이스마다 첫 실패 문장**을 싣는다(`3회 실행에서 실패했다 — <파일> — <문장> · …`). **입력은 남는다** — 사람이 값을 고쳐 다시 누르면
  에이전트가 **자식이 끝낸 커밋 위에 다시 적는다**(앞 반영이 올린 값 커밋을 버리고). 실패한 머지는 최신에서 빠지므로 다시 넣을 수 있다(아래 「실행 기록」)

**대상 서버 — 어디서 3회를 도나**
- **대조 요청** — 원본의 대상 서버(`env`)를 물려받는다. 머지 요청에 `env` 가 오면 400 `BAD_ENV`
- **정방향 요청** — 대상 서버가 없으므로 **반영 때 사람이 고른다.** 채운 보류가 있으면 `env` 가 필수이고 **테스트 계정을 넣은 줄만** 된다(역방향과 같은 규칙 · 운영 줄 보호). 아니면 400 `BAD_ENV`.
  고를 수 있는 줄은 상세의 `mergeEnvs` 다(§7)
- claim(MERGE) 의 `target` 은 그 줄이다 — 넘기는 방법(환경 변수 · 인자 배열, 셸 문자열 금지)은 역방향 「로그인」과 같다

**보류가 main 에 들어가지 않게 — 막는 자리 셋.** 보류 케이스는 값 없이 건너뛰므로 main 에 들어가면 **아무것도 안 지키는 초록**이 된다.
**「GitHub 이 막아 준다」가 아니다** — 위 「작성 에이전트는 전용 체인이다」처럼 main 보호가 관리자에게 강제되지 않는다.
- ⒜ **merges** — 남은 보류가 있으면 409 `HELD_OPEN`. 보류 목록을 못 읽은 실행이면 409 `HELD_UNKNOWN`. 화면도 반영 버튼을 막고 이유를 보이지만 막는 것은 서버다
- ⒝ **에이전트** — 값을 적은 뒤 `held` 가 남았으면 병합하지 않고 `FAILED`
- ⒞ **CI** — 초안이 아닌 PR 에서 `check:tests --no-held` 를 돈다. `held` 가 하나라도 있으면 빨강이다(정본은 [`docs/HOOKS.md`](../../HOOKS.md) 「CI 와 병합 차단」).
  초안 PR 에는 보류가 있어도 된다 — 사람이 채우기 전의 자리다

**보류와 미확정은 같이 달 수 있다.** 역방향에서 화면 기준 임시 케이스인데 값 하나가 없으면 `held` 와 `unconfirmed` 를 둘 다 단다.
**채워도 `unconfirmed` 는 남는다** — 사람이 넣은 것은 빈 칸 하나이고 나머지 기대값은 여전히 화면 기준이다. 확정은 위 「★ 역방향」의 두 길(정방향 재요청 · 케이스 고치기) 가운데 하나다.

**남는 한계 — 알고 쓴다**
- **테스트 계정이 아닌 비밀값은 받을 길이 없다** — 관리자 계정처럼 대상 서버 줄에 없는 비밀값이 필요한 케이스는 제거하고 사람이 `/tpx` 로 만든다
- **관리자가 GitHub 에서 빨간 PR 을 직접 병합하면 보류가 main 에 들어간다** — ⒞ 는 빨강을 보일 뿐 막지 못한다(`enforce_admins: false`). 들어가도 실행은 건너뛸 뿐 깨지지 않는다
- **3회 실행은 반영 때 한 번이다** — 그 뒤 대상 서버 자료가 바뀌어 깨지는 것은 정기 실행이 잡는다
- **머리 두 말은 자식 스킬이 지킨다** — K13 은 비지 않은 리터럴인지(모양)만 본다

```
[계약 변경 필요]
대상:    CaseSpec.held · K10 예외 · K13 · check:tests --no-held · authoring_request.held_input ·
         finish result.held[](name?) · result.heldUnknown · PUT/DELETE …/held/:tcId · 상세 held[] · heldOpen · heldUnknown · mergeEnvs ·
         merges { sourceId, env? } · 409 HELD_OPEN · 409 HELD_UNKNOWN · claim(MERGE) held · target
현재:    판정 불가 · 보류 요구는 케이스를 만들지 않고 PR 본문 글로만 남는다. 병합되면 사라진다
제안:    자식이 held 꼬리표를 단 케이스 코드까지 만들고, 사람이 작성 상세에서 값을 넣거나 제거한 뒤 반영 —
         에이전트가 .default(값) 로 적고 채운 케이스를 3회 돌려 통과해야 병합 (위 절 · 아래 §7)
이유:    5877 에서 요구 15건이 판정 불가 · 보류로 빠져 누구도 이어받지 못했다 (2026-09-29 사용자)
영향:    KIT(타입 · test 건너뛰기) · WS-A(check:tests K10 · K13) · WS-작성(서버 · 에이전트 · 자식 스킬) · WS-E(작성 화면) · CI
상태:    반영 완료 (2026-09-29, PR #108)
```

#### ★ 원장 — 기획서의 요구 번호와 표를 맞댄다 (2026-09-30 · 게이트 0·1)

**원장의 정본은 이 절이다.** 자식이 따르는 절차는 `tpx-cases` `references/2-requirements.md` 「원장」 · `6-gates.md` 관문 0, 코드는 `scripts/authoring-ledger*.ts` 다.

**무엇인가.** 5877(데모마켓 대조)의 기획서 요구 172개 가운데 124개가 케이스가 안 됐고, 그중 3개(REQ-HOME-001 · 003 · REQ-BRD-008)는
요구 줄 · 보류 · 「안 덮는 것」 어디에도 흔적이 없었다. **관문 넷은 전부 표 → 코드 쪽만 본다.** 기획서 → 표는 사람 승인 하나로 막는데
작성 에이전트는 그 승인을 건너뛴다(「작성 에이전트는 전용 체인이다」). PR 본문 숫자도 표 기준이라 빠진 것이 어디에도 안 나왔다.
장째 뺀 사유는 자유 문장이라 「「한 칸」 밖」(규칙 오적용) · 「화면 케이스가 아니다」(플랫폼은 API 케이스를 돈다) 같은 틀린 사유가 그대로 통과했다.
**그래서 요구 번호 목록(원장)을 기계가 뽑고, 표가 그것을 빠짐없이 덮었는지 기계가 본다.**

| 무엇 | 정한 것 |
|------|------|

**셈을 남긴다 (2026-09-30 · 게이트 0 · 1).** 셈이 PR 본문 글뿐이면 요청마다 몇 % 를 덮었는지 화면에서도 대시보드에서도 못 본다.
에이전트가 원장 대조를 한 뒤의 끝내기(DONE · 대조 뒤 올리기 거절)에 `result.coverage` 를 싣고, 서버가 칸 다섯(`coverage_*`, [데이터모델](../공통/4-데이터모델.md) 「작성 커버리지 칸」)에 옮긴다.
모양과 거절은 §7 `finish`, 화면 한 줄은 [DESIGN.md](../../DESIGN.md) 「Status 카드」, 대시보드는 [리포팅.md](리포팅.md) §8.5 「작성 커버리지」가 정본이다.

| 셈 단위 | **실행 하나** · 그 실행이 뽑은 **전체 원장** 기준. 이어서 작성 · 다시 작성도 원장을 다시 뽑아 대조한다 |

> **「빠지면 올리기 거절」을 2026-09-30 게이트 1 에서 뒤집었다.** 앞 판(PR #119)은 빠지면 올리지 않고 중단(올리기 거절)으로 끝내 이어서 작성하면 자식이 빠진 번호부터 채웠다.
> **판단 기준은 아직 쓸모 있다** — 사람 · 자식이 적은 목록을 끝 조건으로 믿지 않고, 기계로 뽑은 목록과 맞댄다. 바뀐 것은 맞댄 결과를 **막는 데** 쓰느냐 **남기는 데** 쓰느냐다.
> 뒤집은 까닭 — 사용자가 「멈추지 말고 기록만 남겨 나중에 확인」을 골랐다. 거절하면 그 실행이 만든 케이스를 통째로 못 쓰고, 남은 요구는 셈에 남아 ③ 으로 이어 채울 수 있다.

**요구 지문 (2026-10-04 · 게이트 0 · 1).** 원장은 실행마다 그때 번호만 뽑고 끝나면 사본을 치워 앞 판이 남지 않는다. 기획서가 새 판으로 와도 **번호는 같은데 내용이 바뀐 요구**를 기계가 모른다.
그래서 요구마다 글의 지문을 표 옆에 남기고 다음 작성 때 앞 판과 견준다 — 「바뀐 부분만 다시 만들기」(2026-10-04 사용자 지시의 8)의 재료다.
**이번에는 PR 본문 머리에 보고만 한다** — 막지 않고, 차이를 자식에게 넘기는 것은 다음 단계다. 코드는 `scripts/authoring-ledger.ts`(지문) · `scripts/authoring-ledger-diff.ts`(파일 · 합치기 · 차이 · 머리 줄) · `scripts/authoring-ledger-io.ts`(읽기 · 쓰기)가 정본이다.

| 무엇 | 정한 것 |
|------|------|
| 지문 단위 | **번호 모드** — **줄 단위로 가른다.** 줄 첫머리에 원장 번호가 있는 줄부터 다음 그런 줄 전까지가 그 번호의 글이다. 첫머리 앞의 표시는 넘긴다 — 표 테두리 · 목록 표시(`-` `*` `•` `■` `◦` 등) · 제목 `#` · 괄호(`[` `(` `【`) · 번호 목록(`1.` · `1)`). 줄 가운데서 언급한 번호(REQ-HOME-004 줄의 REQ-ADM-003)와 번호 바로 뒤에 조사가 붙은 언급(「REQ-001 을 먼저 거친다」)은 주인이 아니다. **머리글은 주인을 끊는다** — md 자료는 `#` 줄(그 뒤 첫머리에 원장 번호가 있으면 주인이다), 변환한 글자본은 「4. 회원」 · 「2.1 공통」처럼 점 번호 뒤 빈칸 **하나**인 40자 이하 줄 가운데 문장으로 끝나지 않는 것이다 — 서버 변환의 본문 번호 목록은 「1.  아이디」(빈칸 둘), 맥 변환은 탭이라 요구 글로 남는다. 표에서 첫 칸이 빈 줄(서버 변환 격자 표의 칸 안 목록)은 그 행 주인에 붙고, 원장 번호 없는 새 행은 주인을 끊는다. 행 번호 칸(「3   REQ-…」 · 「\| 3 \| REQ-…」 · 숫자만 있는 줄)과 테두리 줄은 지문에서 뺀다 — 행 하나를 끼워도 뒤 요구가 안 바뀌게. 첫머리에 한 번도 안 나온 번호(범위의 가운데 · 언급만 됨)는 그 번호가 나온 줄 전부다. **문단 모드** — 그 문단. 둘 다 빈칸을 하나로 모은 글의 SHA-256 앞 16자. 게이트 1 은 문단 · 표 행 단위로 정했으나 구현에서 줄 단위로 바꿨다 — 맥 변환(textutil)은 칸마다 줄을 나누고 빈 줄이 없어 단위로 가르면 장 하나가 덩이 하나가 됐다(2026-10-04 계획 검토 실측 — 한 줄 고치면 14개가 바뀜). 줄 단위는 서버 · 맥 꼴 모두 그 번호 하나만 바뀐다(데모마켓 172개 실측) |
| 파일 | `docs/cases/<접두사>.fingerprint.json` — 표 옆에 두고 표와 같이 커밋한다. 자료 폴더의 원장 사본(`ledger.json`)과 다른 파일이다. 모양 `{ 판: 1, 자료: { <자료 이름>: { 꼴: '<확장자>/<변환 도구 또는 그대로>' } }, 항목: [{ 번호, 지문, 자료 }] }`. 번호 모드 번호는 파일에 한 번만 있다 — 한 실행 안에서는 원장처럼 먼저 나온 자료 것, 합칠 때는 이번 원장이 다시 뽑은 번호를 다른 자료에서 뺀다. 읽을 때 1MiB 를 넘거나 모양이 틀리면 「못 읽음」. 가벼운 길(`cases` 차선)에 든다 — 꼴의 정본은 `.claude/scripts/cases-only.mjs` |
| 쓰기 | 에이전트가 올릴 때 쓴다(순서는 위 「에이전트 스크립트 — 마무리」). **자료마다 합친다** — 앞 판(기준 SHA 의 main 파일)에서 이번 원장 자료의 항목과 이번에 다시 뽑은 번호를 빼고 이번 항목을 넣는다. 다른 자료 항목은 물려받는다 — 개정분만 보낸 요청이 앞 판 전체를 지움으로 만들지 않게. 쓰기 전에 `docs` · `docs/cases` 가 링크 아닌 진짜 폴더이고 실제 경로가 트리 안인지 본다. 파일 자리는 지우고 새로 쓴다(링크를 따라가지 않게). **원장이 없으면** 파일을 앞 판 글로 되돌린다(앞 판에 없으면 지운다) — 자식이 만진 파일이 올라가지 않게. **앞 판을 git 으로 못 읽었거나 폴더 확인 · 쓰기 · 되돌리기에 실패하면** 쓰지 않고 트리의 지문 파일을 커밋에서 뺀다(자식 손을 탔을 수 있다 — 2026-10-04 보안 검토). 바뀐 파일이 지문 파일뿐이면 「바뀐 파일이 없다」로 거절한다 — 케이스 없는 PR 이 지문만 반영해 다음 앞 판을 바꾸지 않게 |
| 차이 | **번호 모드는 번호가 열쇠다** — 이번 원장의 번호마다 앞 판 어느 자료에서든 같은 번호를 찾아 견준다. 더함(앞 판에 없음) · 바뀜(둘 다 있고 지문이 다름) · 지움(다시 보낸 자료 — 앞 판에 같은 이름이 있는 자료 — 에 있던 번호가 이번 원장 어디에도 없음). 그래서 이름을 바꾼 새 판도 바뀐 요구가 나오고 앞 이름의 번호는 지움이 아니다. **글자본 꼴이 다르면 견주지 않는다** — 이번 자료의 꼴이 앞 판 같은 이름의 꼴과 다르거나, 찾은 앞 지문이 다른 꼴로 뽑은 것이면 건너뛴다(같은 기획서도 꼴이 다르면 지문이 전부 다르다). 문단 모드 — 같은 자료 안에서 지문으로 짝짓고 「앞 번호 → 새 번호」 짝을 돌려준다(다음 단계가 출처 칸을 옮길 재료). 고친 문단은 지움 하나 + 더함 하나다. 앞 판에 이름이 없는 자료는 「새 자료」로 따로 알린다 |
| PR 머리 줄 | 원장 셈 줄 다음에 한 줄 — 「기획서 판 차이 — 더함 N · 바뀜 N · 지움 N(번호 앞 10개)」, 있으면 「새 자료 N(이름)」 · 「글자본 꼴이 달라 견주지 않음 — <자료 이름>」을 덧붙인다. 앞 판 파일이 없으면 「기획서 판 차이 — 앞 판 지문 없음(반영하면 저장된다)」, 못 읽으면 「⚠️ 앞 판 지문을 못 읽음」. 원장이 없으면 줄이 없다. **보고만 하고 막지 않는다** |
| 반영 충돌 | main 합치기에서 **main 이 지문 파일을 바꿨으면 충돌이 안 나도** 바탕 · main · 요청 세 판에서 **세 갈래로 다시 계산해** 쓴다 — git 의 줄 합치기는 충돌 없이도 JSON 을 깨뜨릴 수 있다. 요청이 바꾼 항목이 이기고, 요청이 지운 항목은 빠지고, main 이 새로 넣은 다른 자료 항목은 남는다. 자료의 꼴도 같은 규칙으로 고른다(꼴과 항목이 다른 판에서 오면 다음 실행이 전부 거짓 바뀜이 된다). 바탕이 없으면 둘을 합치고 같은 항목은 요청 것. 한쪽이 파일을 지웠으면 남은 쪽. 모양이 틀린 판은 없는 것으로 친다. 표 처리 뒤에 한다 — 순서는 아래 「★ 반영 때 겹침 검사」 「요구사항 표 합치기」 |
| 자식 | **이 파일을 만들거나 고치지 않는다** — 에이전트가 올릴 때 덮어쓰거나 앞 판으로 되돌린다 |

**칸과 번호 (2026-10-04 · 게이트 1 사용자).** 같은 기획서(MKT)를 처음부터 두 번 작성하니 케이스가 148 · 227개로 갈렸다(#137 · #144). 요구 여러 줄을 케이스 하나로 묶는 판단(R15)과 쓴 차례대로 붙는 번호가 실행마다 달랐다 — 같은 번호 같은 요구 148 중 7.
사용자 정의는 「같은 기획서를 100번 돌려도 문장은 달라도 커버리지 · 맥락이 비슷」이다. 그래서 **작성 에이전트의 케이스 경계와 tcId 를 코드가 정한다.** 사람 세션(`/tpx-cases`)은 R15 그대로다.
코드는 `scripts/authoring-slots.ts`(칸 · 번호 · 상수) · `scripts/authoring-ledger-check.ts`(표 읽기 · 채우기 · 대조) · `scripts/ledger.ts`(`npm run ledger:number`)가 정본이다.

**설계 기법 (2026-10-05 · 게이트 1 사용자).** 「칸과 번호」는 케이스 경계와 tcId 를 고정했지만, 요구마다 경계 · 예외 칸을 만들지는 AI 가 골라 실행마다 갈렸다 — 두 실행(#137 · #144)이 어긋난 칸 86 중 경계 · 예외가 34 였다.
사용자 지시는 「예외 · 경계를 채울지 AI 가 고르는 것을 경계값 분석 등 테스트 설계 기법으로 정하라 — 예외 케이스 포함」이다. 그래서 **작성 에이전트의 경계 · 예외 칸을 요구 글의 문구로 코드가 정한다.**
사람 세션(`/tpx-cases`)은 지금처럼 R18 을 읽고 판단한다 — `npm run ledger:design` 목록은 참고로 쓸 수 있다. 코드는 `scripts/authoring-design.ts`(판정 · 목록 글) · `scripts/authoring-design-check.ts`(대조 · PR 머리 줄) · `scripts/ledger.ts`(`npm run ledger:design`)가 정본이다.
기법 낱말 · 단위 목록도 코드가 정본이다 — 여기 옮겨 적지 않는다. 자식이 칸마다 줄을 쓰는 법은 `tpx-cases` `references/test-design.md` 다.

- **비싼 조작(결제 · 가입)을 칸마다 따로 한다** — R15 의 「비싼 조작은 합친다」를 에이전트는 못 쓴다. 출처 칸에 번호를 여럿 적은 줄은 첫 번호 칸으로 모인다
- **축 고르기는 문구로 못 찾는 것만 AI 판단이다** — 경계 · 예외 가운데 요구 글의 문구로 찾는 것은 코드가 정한다(위 「설계 기법」). 문구로 못 찾는 것 — 무작위 시간 · API 표 「로그인 필요」 열 · 다른 요구에 걸친 기준 · 다른 문체 — 과 UI · 정상은 AI 판단이고 실행마다 갈린다. UI · 정상은 낱말 규칙으로 잰 두 실행의 합의 일치가 70% 안팎이라 코드로 못 정한다.
  「축 고르기는 AI 판단이다」만 적던 것을 2026-10-05 에 바꿨다 — 두 실행(#137 · #144)이 어긋난 칸 86 중 경계 · 예외가 34 였다(위 「설계 기법」)
- **이어 작성은 기준 줄만 있는 요구를 안 본다** — 설계 대조는 줄이 전부 기준 줄인 요구를 건너뛴다(위 「설계 기법」 「안 보는 요구」). 앞 요청이 경계 · 예외 칸 없이 반영한 요구는 뒤 요청에서 설계 칸 빠짐으로 안 나온다
- **시간 단위 한도(일 · 시간 · 분 · 초)는 시계를 못 움직여 보류가 늘 수 있다** — 설계가 그 경계 칸을 요구해도 시험 값을 만들 수 없으면 자식이 보류로 쓴다
- **설계 판정은 글자 문구로 짐작한다** — 뜻은 모른다. 오판은 「설계 거절」로 까닭과 함께 빼고 PR 머리에 센다. 놓친 것은 위 「축 고르기」의 AI 판단 몫으로 남는다
- **고정 번호는 고정 범위 끝(기능은 원장 수 × 3)이 999 안일 때만이다** — 넘으면 그 갈래는 칸 차례로 매겨 같은 요구라도 실행마다 번호가 밀릴 수 있다(PR 머리 「번호 상한」). 잡음 가족(화면 ID · 오류 코드)도 원장 수에 든다
- **「설계 거절」 절이 둘 남을 수 있다** — 두 요청이 같은 표에 처음으로 「설계 거절」 절을 더하면 반영 뒤 절이 둘이고 표 읽기는 앞 절만 본다. 뒤 절이 면제한 칸은 다음 실행의 관문 0 에서 설계 칸 빠짐으로 다시 뜬다(말없이 빠지지는 않는다). main 에 남은 거절 줄은 요구 글이 바뀐 뒤에도 같은 칸을 계속 면제한다 — PR 머리 「설계 거절」 셈으로만 보인다
- **3회 빨강으로 정한 보류는 케이스 통째다** — 표를 쓸 때 정한 보류만 출처 표시로 갈라진다. 쓰는 도중 보류가 된 칸은 정식 확인까지 같이 묶인다
- **기준 표의 칸이 이미 꽉 찼으면 넘친다** — 기준 줄은 덩이를 세지 않으므로 기준에 `칸줄상한` 만큼 찬 칸에 새 줄이 오면 같은 번호를 물려받아 한 케이스가 상한을 넘는다
- **빠져도 올린다** — 빠짐은 셈 · PR 본문 머리 · 대시보드 「빠짐」 칸으로만 드러난다. 병합(반영)도 막지 않는다
- **CI 는 원장을 못 본다** — 기획서가 저장소에 없다. 대조는 에이전트(올리기)와 자식 · 사람(관문 0)이 한다
- **서버와 맥은 같은 워드를 다른 글자본으로 푼다** — 그래서 요구 지문은 자료마다 글자본 꼴을 싣고 꼴이 다르면 견주지 않는다(위 「요구 지문」 차이). 한 판은 서버, 다음 판은 맥에서 돌리면 그 자료는 차이가 안 나온다
- **요구 지문 단위는 글자본 모양에 기댄다** — 번호 없는 제목(「부록」 · 「개요」) 뒤의 글은 앞 장 마지막 요구에 붙고, 변환한 글자본에서 빈칸 하나짜리 짧은 번호 단계(「1. 아이디 입력」)는 제목으로 보여 주인을 끊는다. 번호 뒤에 「이」 · 「가」로 시작하는 요구 글(「REQ-001 이 화면은 …」)은 조사 언급으로 보여 주인이 안 된다. 서버 · 맥 꼴의 표 · 번호 목록 · 격자 표는 2026-10-04 에 실측했다
- **사람 세션(`/tpx-cases`)은 요구 지문을 안 쓴다** — 사람이 표를 고쳐 병합해도 main 의 지문 파일은 그대로라 앞 판이 낡는다. 다음 작성의 차이는 마지막으로 에이전트가 올린 판과 견준 것이다
- **같은 기획서의 「더함 0 · 바뀜 0 · 지움 0」은 앞 판이 반영된 뒤에만 나온다** — 지문 파일을 기준 SHA 의 main 에서 읽으므로 첫 요청이 반영되기 전의 다시 작성 · 다른 요청은 「앞 판 지문 없음」이다

**남은 요구로 이어 작성 (2026-09-30 · 게이트 0·1).** 요청 하나는 120분이라 큰 기획서는 한 번에 못 덮는다(5877 은 172개 중 48개). 2026-10-03 에 120분 제한을 없앴지만(§7 TIMEOUT) 「다음 요청」 · 「빠짐」으로 남은 요구를 이어 채우는 길로 그대로 쓴다.
반영(병합)이 끝난 작성 요청의 「다음 요청」 · 「빠짐」 번호를 **새 작성 요청**(새 번호 · 새 브랜치 `author-<새 뿌리>` · 새 PR)이 맡는다. 사람이 작성 화면에서 누른다.
통로는 §7 `POST /api/authoring/requests` 의 `continueFrom`, 칸은 [데이터모델](../공통/4-데이터모델.md) 「작성 이어 작성 칸」, 화면은 [DESIGN.md](../../DESIGN.md) 「작성 상태」, 자식이 할 일은 `tpx-author` `references/continue.md` 가 정본이다.

화면은 **값과 동작만** 보낸다. 코드 본문을 들지 않으므로 [공통/1-제품과-구조.md](../공통/1-제품과-구조.md) §1 「영구히 하지 않는다」의 편집 금지에 걸리지 않는다.

**남는 한계 — 알고 쓴다**

  작성 반영 쪽은 2026-10-01 부터 표가 끝에 줄을 더하기만 했으면 스스로 합친다(아래 「★ 반영 때 겹침 검사」 「요구사항 표 합치기」). 고치기 반영은 main 을 합치지 않는다 — 고친 파일이 겹치면 다시 적용이다
- **폐기는 화면에서 치울 뿐이다** — GitHub 의 PR 은 열린 채 남는다. 관리자가 그 PR 을 GitHub 에서 직접 병합하면 저장값은 안 지워진다
- 객체 · 배열 기본값과 `verify(...)` 안의 글자 값은 못 고친다 — 사람이 `/tpx` 로 고친다
- **Grafana 「작성 커버리지」에 다시 적용 실행이 「재실행 · 원장 없음」 줄로 섞인다** — 패널은 `kind` 만 읽고 대시보드 계정은 `source_id` 를 못 읽어 다시 적용을 못 가른다. 가르려면 대시보드 칸 권한을 넓혀야 해서 다음으로 미뤘다(WORKSTREAMS 「📐 케이스 고치기」)

```

대상:    authoring_request.kind CHECK · 원본 짝 CHECK(이름 authoring_request_source_pair_check) · POST /api/authoring/edits ·
         RERUN 원본에 EDIT · 집기 응답 edits · 반영 끝내기 result.pulled · 409 EDIT_OPEN · 400 BAD_EDIT
현재:    코드를 바꾸는 길은 작성 · 재실행 · 반영(보류 값) 셋뿐. 케이스를 지우거나 기대값을 코드에 적거나 미확정을 확정할 길이 화면에 없다
```

#### ★ 반영 때 겹침 검사 — 같은 서비스 동시 작성 (2026-10-01 · 게이트 0·1)

**이 절이 정본이다.** 다른 장은 이 절을 가리키고 자기 표면만 적는다 — 통로는 아래 §7, 칸 `conflict_input` 은

**무엇인가.** 여러 사람이 같은 서비스에 작성 요청을 넣으면 요청마다 자식이 같은 main 에서 출발해 **같은 다음 번호**를 고른다 —
자식은 다른 열린 PR 을 못 본다. 2026-10-01 전에는 에이전트가 서비스마다 한 건씩만 돌려 이것이 드러나지 않았지만,

**반영할 때 에이전트가 지금 main 과 견줘** 겹친 케이스를 사람에게 고르게 한다. 같은 tc_id 가 main 에 둘 들어가면
카탈로그 스캔이 그 서비스를 아예 갱신하지 않는다(§3.1).

| 동시 실행 | 작성 · 재실행 · 케이스 고치기는 **자리(동시 상한 — 모든 서비스를 합친 수, 정본 [공통/6-인프라.md](../공통/6-인프라.md))** 만 있으면 같은 서비스도 나란히 돈다. 자리가 없으면 「대기 중」으로 남는다 — **에이전트가 자리를 먼저 잡고 나서 가져간다**(가져간 채 자리를 기다리면 단계 글 없이 30분이 지나 「응답 없음」으로 보인다) |
| 반영은 한 줄 | **같은 서비스의 반영은 모두 차례로**(보류가 있든 없든) — main 에 차례로 들어가야 견주기가 맞다(main 보호가 「최신 main 위에서 CI」를 강제하지 않는다). 보류 있는 반영은 케이스를 돌려서 자리도 하나 쓴다. 앞 반영을 기다리는 반영은 단계 글 「앞 반영을 기다리는 중」을 몇 분마다 다시 올린다 |
| 무엇을 견주나 | 이 요청이 **새로 더한** 케이스마다(바꾼 케이스는 안 본다) ⒜ **같은 tc_id** — 지금 main 의 케이스 파일이나 요구사항 표(「제거함(…)」 칸 포함)에 그 tc_id 가 있다 ⒝ **같은 요구 번호** — 이 요청이 작성을 시작한 뒤 main 에 새로 들어온 케이스가 같은 요구 번호를 덮는다(요구사항 표 「출처」 칸의 번호. 문단 번호 `P-001` · `P2-003` 꼴은 요청마다 1부터라 뺀다 — 위 「★ 원장」 문단 모드) ⒞ **같은 이름** — 이 요청이 작성을 시작한 뒤 main 에 새로 들어온 케이스와 이름(`defineCase` 의 `name`)이 같다(앞뒤 공백 · 겹친 빈칸 · 영문 대소문자 무시). **예전부터 있던 케이스는 ⒝ · ⒞ 로 안 잡는다** — 자식이 작성할 때 이미 보고 만들었고, 한 요구에 케이스 여럿은 원래 된다 |
| 걸리면 | 반영하지 않고 **실패로 끝난다** — 「겹치는 케이스 N건 — 케이스마다 고른 뒤 다시 반영한다」. 보류에서 「제거」한 케이스는 겹침으로 안 센다(어차피 빠진다) |
| 고르기 | 케이스마다 **남긴다**(`KEEP`) · **뺀다**(`DROP`). 남기면 tc_id 가 겹칠 때만 새 번호를 받고 안 겹치면 그대로 들어간다. 빼면 이 요청에서 그 케이스 파일과 그 tc_id 를 가진 표 줄이 빠진다(「제거함」으로 남기지 않는다 — main 의 같은 tc_id 줄과 섞인다). 권한은 `(작성, write)`. 다 고르기 전에는 반영이 409 `CONFLICT_OPEN` |
| 새 번호 | **작성 에이전트의 같은 tc_id 는 같은 칸이다**(위 「★ 원장」 「칸과 번호」, 2026-10-04) — 같은 main 에서 출발한 두 요청이 같은 요구를 덮으면 같은 번호가 나온다. 「남긴다」로 새 번호를 받은 줄은 다음 실행부터 기준 줄로 남아 번호 명령이 안 건드린다. 지금 main 의 케이스 파일 · 요구사항 표(「제거함」 포함)와 이 요청의 번호 가운데 가장 큰 것 + 1 부터 차례로 — **지운 번호를 다시 쓰지 않는다**(옛 실행 이력이 새 케이스에 붙는다). 999 를 넘으면 실패한다(파일 이름 규칙이 세 자리다). **번호열은 종류마다다** — `-FN-` 과 옛 꼴이 한 열, `-UI-` 는 따로 001 부터이고 999 상한도 열마다다(2026-10-02 · PR #129 · 아래 「★ 테스트 두 갈래」) |
| 요구사항 표 합치기 | main 이 이 요청이 시작한 뒤 **이 서비스의 표 · 요구 지문 파일이나 테스트 폴더를 바꿨을 때만** main 을 요청 브랜치에 합친다. **표 처리는 표가 충돌했을 때만 탄다** — 지문 파일만 충돌했는데 표 쪽 사유로 되돌리지 않게. **main 이 요구 지문 파일을 바꿨으면 표 처리 뒤에 충돌 여부와 상관없이 세 판에서 다시 계산한다**(위 「★ 원장」 「요구 지문」 반영 충돌). 표에서 **양쪽이 같은 자리에 줄을 더하기만 한 곳**은 main 줄 → 이 요청 줄 순으로 잇고, 「요구」 차례 번호가 겹치면 뒤쪽 줄을 그 표의 가장 큰 번호 뒤로 다시 매긴다. **「덮는 범위」 줄**은 이 요청 것을 남긴다. 그 밖에 양쪽이 같은 곳을 고쳤거나, 새 서비스의 첫 요청 둘이 표를 각자 만들었거나, 케이스 파일이 충돌하면 반영하지 않고 쉬운 문장으로 실패한다 — 「main 과 같은 파일을 고쳐 합치지 못했다 — <경로>. 다시 작성한다」. **요청끼리 같은 Page Object(`pages/` · `components/`)를 고친 충돌도 이 길이다**(2026-10-02 · PR #129 — AI 가 합치는 것은 다음 PR). 합친 표는 원장 형식 검사(위 「★ 원장」)를 돌려 **새로** 깨졌으면 같은 식으로 실패한다 — main 에 원래 있던 문제로는 막지 않는다 |
| 케이스를 돌리나 | 번호 바꾸기 · 빼기 · 합치기는 케이스를 안 돌린다(동작이 안 바뀐다). 타입 · 케이스 규칙은 CI 가 본다. 보류 값을 채운 케이스만 지금처럼 3회 돌린다(위 「★ 보류 케이스」) |
| PR 본문 | 반영 때 「겹침 처리: MKT-042 → MKT-061 · MKT-050 뺌」 줄을 더한다 — 관문 3 기록이 옛 tc_id 를 가리키지 않게 |
| 배포 순서 | 고르는 화면(PR #127)이 들어간 뒤에 author 컨테이너를 이 판으로 다시 켠다 — 그 전에는 겹침이 생겨도 고를 화면이 없다 |

**구현 세부 — 계약 모양**

| 무엇 | 모양 |
|------|------|
| 견주는 기준 | GitHub 의 지금 main · **자식이 끝낸 커밋**(PR 머리에서 에이전트의 반영 커밋 — 보류 값 · 겹침 처리 · main 합침 — 을 첫 부모로 거슬러 간 곳) · 둘의 갈래점. 서버 저장소에서 git 객체만 읽는다 — 작업 폴더를 안 연다. 다시 반영할 때 작업 폴더도 같은 커밋에서 다시 짓는다(한 번 적용한 결정이 CI 빨강 뒤 다시 반영에서 그대로 다시 적용된다) |
| 결과 한 줄 | `{ tcId, name, file, kinds: ('TCID' \| 'REQUIREMENT' \| 'NAME')[], with: [{ tcId, name, file }], requirements?: string[] }` — 한 케이스에 종류가 여럿이면 한 줄에 모은다. `with` 는 겹친 main 쪽 케이스(표에만 남은 tc_id 면 `file` 이 표 경로 · `name` 은 빈 글자) · `requirements` 는 ⒝ 의 겹친 번호. 끝내기는 반영 `FAILED` + `result.conflicts`. 상한 숫자(건수 · `with` · `requirements` 길이 · 글자 수)는 `apps/admin/src/authoring/conflicts.ts` 에만 둔다 |
| 칸 | 원본(작성 실행) 행의 `conflict_input JSONB` = `{ [tcId]: { action: 'KEEP' \| 'DROP', by, at } }` — 보류의 `held_input` 과 같은 자리 |
| 겹침 목록이 사는 곳 | 그 실행을 원본으로 하는 **가장 최근 반영**이 겹침으로 실패했을 때만(`result.conflicts` 가 있다). 그 뒤 반영이 성공 · 다른 까닭으로 실패하면 목록이 없다 — 결정은 원본 행에 남는다 |
| 가져가기 | 반영 행을 가져가면 `conflicts: [{ tcId, action }]` — 원본의 결정 **전부**. 거르기는 에이전트가 새로 찾은 겹침 목록으로 한다(서버가 지금 목록으로 거르면 CI 빨강으로 실패한 반영 뒤에는 목록이 없어 결정이 사라진다) |
| 자리 없는 작업 폴더 | 보류 없는 반영의 작업 폴더(번호 바꾸기 · 빼기 · 합치기)는 트리의 코드를 하나도 돌리지 않는다 — 자식이 쓴 코드가 에이전트 계정으로 돌면 안 된다. 합침 커밋 제목은 에이전트 커밋 모양이라 「실행 기록」 덮어쓰기 검사가 에이전트 것으로 읽는다 |
| 뒤에서 도는 일 | 「서버가 거절했다」를 받으면 지금처럼 모두 멈추고 자식을 거둔다 · 에이전트를 끌 때 도는 일을 다 기다린다 |

**남는 한계 — 알고 쓴다**
- **자리가 다 차면 반영도 기다린다** — 보류 있는 반영은 자리를 쓰고, 에이전트는 자리를 잡은 뒤 가져간다
- **「덮는 범위」 줄은 마지막 반영 것만 남는다** — main 쪽 설명은 사라진다
- **빼기 뒤처리는 안 한다** — 뺀 케이스를 가리키던 합친 줄 · 판정 불가 절의 언급과 그 요청의 셈(`coverage`)은 옛것이다
- **열린 요청끼리는 반영 때에야 드러나고 먼저 반영한 쪽이 기준이다** — 뒤에 반영하는 사람이 고른다
- **main 쪽 케이스를 빼려면** 위 「★ 케이스 고치기」로 지운다 — 이 고르기는 이 요청 쪽만 바꾼다
- **GitHub 에서 직접 병합하면 이 검사를 안 거친다**

- **예외 · 경계는 근거에 적힌 것만** — PRD · 화면 입력 검사 · API 스키마 · 명시된 업무 규칙. 칸끼리 곱하지 않는다(R18).
  **작성 에이전트는 설계 목록(위 「★ 원장」 「설계 기법」)의 칸을 뺄 수 없다** — 오판이면 「설계 거절」로 까닭을 남긴다. **0건**(「없으면 … 보여 준다」)은 R2 의 경계다 —
  빈 상태에서 하나가 생기면 바뀌는 것까지가 기능 경계 칸이고, 처음 화면 모양은 UI 칸이 따로 덮는다(2026-10-05 · 게이트 1 사용자)
- **화면에만 있는 입력 규칙은 정방향에서도 미확정 케이스로 만든다** — 필수 표시 · 글자 수 제한 · 형식 안내만, 기획서가 다루는 화면 안에서만.
  표는 §3 에서 얼지만 이 줄만 §4 탐침 뒤에 더한다. 더하는 것은 메인(자식) 하나이고 같은 규칙은 하나로 합친다. 사람이 「케이스 고치기」로 확정하거나 지운다.
  기획서에 없는 버튼 · 메뉴는 만들지 않는다 — 역방향 「대조」가 맡는다. 「화면만」 요청은 지금처럼 전부 미확정이다
- **입력 칸이 한도를 넘는 글자를 막을 때** (2026-10-03 게이트 0) — 「한도 + 1 글자를 넣으면 한도까지만 들어간다」는 경계 케이스로 쓴다. 기획서가 한도를 넘었을 때의 오류를 말하면 화면과 다른 것이라 차이 · 미확정 케이스로 둔다.
  **케이스를 빼고 「사람 판단」으로 미루지 않는다** — 같은 날 CDY 는 케이스로, MKT 는 빼서 서비스마다 갈렸다
- **커버리지(위 「★ 원장」)는 갈래에 맞는 케이스로 채운다** — 동작을 적은 요구는 Functional 케이스가, 화면 모양만 적은 요구는 UI 케이스가 덮는다.
  UI 케이스 하나로 동작 요구를 덮었다고 치지 않는다(R19). 원장은 그 요구가 동작 요구인지 모르므로 사람이 PR 에서 본다 — 셈이 UI 케이스로만 덮인 번호를 `uiOnly` 로 싣고 PR 본문 머리에 「UI 로만 덮음 N — 번호 …」 줄로 보인다(위 「★ 원장」 「셈을 남긴다」). **보고용이다 — 관문이 아니다**(빠짐으로 안 세고 거절하지 않는다)
- **locator 순서** — testid(이름에 뜻이 있을 때) → role → label → placeholder → text → CSS → XPath. CSS · XPath 는 까닭을 용어 사전에 남긴다. 판정 대상을 `nth()` 로 고르지 않는다 (`4-selector.md`)

## 7. Admin API

**새 통로를 라우트표에 등록한다.** `apps/admin/src/auth/scope.ts` 가 **「모르면 막는다」**로 돌아
등록 안 된 틀은 문이 403 으로 떨어뜨린다. 안 적으면 **모든 요청이 막히고 원인이 권한처럼 안 보인다.**
번호에서 서비스를 찾는 갈래가 하나 필요하다 — `authoring_request.service_id` 다.

**등급의 정본은 `도메인/인증` §7 「등급으로 갈리는 자리」다.** 아래 묶음 머리의 등급 표시는
그 규칙을 이 경로들에 **적용한 결과**이지 새로 정하는 자리가 아니다 — 둘이 어긋나면 인증 장이 이긴다.

  **같은 문을 지난다** (위 ★ 절).
  **단 사진 올리기는 지금 에이전트 코드가 안 부르고, 그래서 에이전트 토큰으로는 안 열린다** (2026-09-23) —

  **`outputs` 는 처음부터 에이전트가 부르므로 그 목록에 든다** — 어느 표에 드는지는 위 「★ 인증을 뚫지 않는다」 (2026-09-25).

- **로그에 계정 비밀번호를 찍지 않는다** (2026-09-25) — 설정 PATCH 본문 · 집기 응답 · 에이전트 로그에 `loginPassword` 를 남기지 않는다.

- **머지만 경로가 갈린 이유** — 같은 경로에 `kind: 'MERGE'` 로 얹으면 등급이 **본문 값**에 따라
  갈려야 하고 그러려면 문이 본문을 읽어야 한다. 경로가 다르면 경로만 보고 가른다
- **★ 경로를 가른 것만으로는 안 닫힌다 — 본문도 가둔다** (2026-09-22 검토가 잡았다).
  문은 **경로**를 보고 `(작성, write)` 를 통과시키는데, 그 뒤 라우트가 본문의 `kind` 를 그대로 받으면

  그러면 **작성 `write` 인 사람이 저장소를 영구히 바꾼다** — 이 장이 막으려는 바로 그것이다.
  **막는 자리를 둘로 겹친다.**
  ⒜ 이 통로가 `AUTHOR`·`RERUN` 밖의 `kind` 를 **`400` 으로 거부한다** (위 §7)
  ⒝ 표가 `kind` 값 자체를 가둔다 (`공통/4-데이터모델` §6 의 `CHECK`)
  **하나만으로는 부족하다** — ⒜ 는 새 라우트가 생기면 빠질 수 있고, ⒝ 만 있으면 `MERGE` 가
  대기줄에 서는 것을 막지 못한다 (`CHECK` 는 값의 모양만 본다)
- **`requestedBy` 는 요청에 싣지 않는다.** 로그인한 세션에서 채운다 —
  실행이 `triggeredBy` 를 그렇게 하는 것과 같은 이유다 (§7.1 · §3.5)
- **사진만 따로 올린다.** 판정과 소스 본문은 `finish` 가 JSON 으로 한 번에 올리지만 사진은 파일이다.

- `result` 의 모양은 **§5.1 이 정본이다.** 맥이 러너와 같은 리포터를 타므로 같은 모양으로 온다
- **★ `?service=` 하나로 판정을 끝내지 않는다** (2026-09-22 검토가 잡았다).
  그 값은 **부르는 쪽이 적는 것**이고 문은 그것을 배정과 대조할 뿐이다 —
  `auth/gate.ts` 가 자기 주석에 그 함정을 적어 뒀다
  (「`/api/runs/<남의번호>?service=<내것>` 이 통과한다」, 2026-09-19 실측).
  **줄을 거르는 것은 라우트다.** 둘을 못박는다.
  ⒜ **`claim` 은 그 서비스의 `PENDING` 행만 집는다.** 자원을 **서버가 고르는** 통로라
  안 거르면 **남의 서비스 행**을 집어 주고, 그 행에는 기획서 자료가 딸려 있다(옛 행은 `spec_text` 본문 통째).

  ⒝ **`sourceId` 가 가리키는 행의 `service_id` 가 `?service=` 와 다르면 `403`.**

#### 토큰 사용량 (2026-09-27 · 게이트 0·1)

작성 요청 5871(데모마켓 대조)이 60분 제한에 걸려 결과 0 으로 끝났는데 얼마를 썼는지 알 길이 없었다.
**자식 claude 가 쓴 토큰을 요청마다 남기고** 대시보드에서 본다 (패널 규칙은 [리포팅.md](리포팅.md) §8.5 「작성 토큰」).

- **받는 법** — 에이전트는 자식을 `--output-format stream-json --verbose` 로 돌려 이벤트를 줄 단위로 읽는다.
  정상 종료면 마지막 `result` 이벤트의 모델별 사용량(`modelUsage`)을 더하고 환산 비용(`total_cost_usd`)을 쓴다 — 하위 에이전트·보조 호출까지 든다.
  **끊기면**(대부분 시간초과 · 결과 없이 죽은 것도) `result` 가 없으니 턴마다 오는 `assistant` 이벤트를 **메시지 id 마다 마지막 사본**으로 더한다.
  그 값은 **하한값이다** — 턴 이벤트의 출력 토큰은 스트리밍 중간값이라 실제보다 적다(2026-09-27 실측 3 → 최종 460). 비용은 비우고 `partial` 을 켠다.
  대시보드는 이 칸으로 「끊김」을 가른다 — 오류 글(`error`)은 대시보드에 열지 않는다(데이터모델 「대시보드 칸 권한」).
  `result` 가 오면 사용량 칸이 없는 판이어도 끊김이 아니다 — `modelUsage` → `result.usage` → 턴 합 순서로 센다
- **claude 가 아예 안 떴으면 알리지 않는다** — 쓴 토큰이 없고, 0 을 보내면 「돌렸는데 0」으로 읽힌다. 그 요청의 칸은 비어 있다
- **모델** — 출력 토큰이 가장 많은 모델 이름 하나를 남긴다. 2026-10-04 부터는 보조(Sonnet) 출력이 가장 많고 메인 예비도 Sonnet 이라 이 칸으로 예비로 넘어간 요청을 가를 수 없다 — 모델별 사용량은 result `modelUsage` 원문을 본다(위 「모델」 줄)
- **보내는 순서가 계약이다** — 자식이 끝나면 **어떤 끝내기(`finish`)보다 먼저** `usage` 를 부른다. 끝난 행에는 409 라 늦게 보내면 버려진다.
  에이전트가 멈추느라 자식을 죽인 경우만 안 보낸다(서버도 그 행을 받아 주지 않는다)
- **보내기 실패가 요청을 실패시키지 않는다** — 관측이 본 작업을 깨면 안 된다. 거절(401·403)만 다른 통로처럼 던진다
- **결과 요약**(PR 본문)은 `result` 이벤트의 글이다. stream 전체를 싣지 않는다 — 훑은 화면 글이 PR 에 들어간다

#### 자료 — 파일과 피그마 (2026-09-23 신설)

**작성 요청의 입력은 자료 목록이다.** 기획서 파일 여럿과 피그마 주소 여럿이 한 세트다.
표 정의와 파일 저장 자리는 [공통/4-데이터모델.md](../공통/4-데이터모델.md) §6 「작성 자료」가 정본이다.
**아래 상한과 종류는 이 절에만 적는다.** 다른 곳은 이 절을 가리킨다.

**본문을 붙여 넣던 방식을 접었다.** 앞 판은 화면이 기획서 본문(`specText`)을 실어 보냈다.
경로를 보내면 **맥은 다른 기계라 그 파일을 못 읽기** 때문이었다. **그 판단 기준은 지금도 맞다** —
그래서 이번에도 경로가 아니라 **파일 자체를 서버에 올린다.** 바뀐 것은 사실 하나다.
기획서는 **PDF·워드 파일로 오고 피그마가 같이 온다.** 글만 붙여 넣으면 표와 그림이 빠진다.
다음에 「그냥 붙여 넣게 하자」가 나오면 이 사실이 아직 맞는지부터 본다 (CLAUDE.md §2.7 ②).

| 무엇 | 정한 것 (2026-09-23 승인) |
|------|------|
| 받는 파일 종류 | `.pdf` · `.docx` · `.doc` · `.md` · `.txt`. 그 밖(`.hwp` · `.pptx` 등)은 400 `{ error: 'BAD_FILE_TYPE' }` 이고 화면은 **이유를 문구로** 보인다 |
| 한 파일 상한 | **20MB.** 넘으면 413 |
| 한 요청의 자료 개수 상한 | 파일과 피그마를 합쳐 **20.** 넘으면 만들 때는 400, 올릴 때는 409 |
| 파일 이름 | 한글이 된다. 제어 문자 · `"` · `/` · `\` · `..` 가 있으면 400 `{ error: 'BAD_NAME' }` |
| 피그마 주소 | `https://` 이고 호스트가 `figma.com`·`www.figma.com`, 경로가 `design`·`file`·`proto` 인 것만 받는다. **통과·거절이 아니라 정규화한다** — 파일 키와 `node-id` 만 뽑아 `https://www.figma.com/design/<키>/?node-id=<숫자-숫자>` 로 **다시 조립해 저장한다.** 파일 전체 링크처럼 `node-id` 가 없으면 `https://www.figma.com/design/<키>/` 로 저장한다. 「Copy link」가 붙이는 `&t=…` 같은 꼬리는 버린다. 저장값에 셸 특수 글자가 원천적으로 없어서 맥이 명령줄에 끼워도 안전하다. **브랜치 링크**(`/design/<키>/branch/<브랜치키>/…`)는 브랜치 키로 조립한다 — 본 파일 키로 줄이면 main 을 읽는다. 브랜치 키도 같은 `[A-Za-z0-9]{1,64}` 로 좁힌다 (2026-09-23) |
| FigJam (`/board`) | **안 받는다.** 화면 디자인이 아니다. 400 `BAD_FIGMA_URL` 과 이유 문구 |

- **산출물(`outputs`, 2026-09-25)도 위 표와 아래 규칙을 따른다** — 한 파일 상한 · 이름 검사(`BAD_NAME`) · 행 먼저 파일 나중 · 내려받기 헤더가 같다.
  다른 것은 종류와 개수다. 종류는 `MARKED` 가 원본과 같은 확장자(`.doc` 원본이면 `.docx` 로 낸다), `REVERSE_SPEC` 은 `.docx` 만이고
  어긋나면 400 `BAD_FILE_TYPE` 이다. **자료 개수 상한에 세지 않는다**

- **순서는 만들기 → 올리기 × 파일 수 → 줄에 세우기다.** 올리는 동안 행은 `DRAFT` 라 맥이 안 집는다.
  줄에 세우기는 `WHERE status='DRAFT'` 한 문장 UPDATE 다
- **중간에 실패한 `DRAFT` 는 안내만 한다.** 「이 요청은 줄에 서지 않았다. 새 요청으로 다시 넣어라」를
  새 요청 폼과 그 요청의 상세에 보인다. 이어 올리기와 지우기는 만들지 않는다
- **올리는 서버는 행 → 파일 순서로 쓴다.** 파일 쓰기가 실패하면 그 행을 지운다 —
  행만 남으면 내려받기가 없는 파일을 찾는다
- **내려받기는 브라우저가 파일을 열지 못하게 준다.** `content-type: application/octet-stream` 고정 ·
  `content-disposition: attachment; filename*=UTF-8''<퍼센트 인코딩한 이름>` · `X-Content-Type-Options: nosniff`.
  확장자로 `text/html` 을 짐작하게 두면 올린 파일이 admin 과 같은 출처에서 열린다
- **피그마 토큰은 서비스 설정에 있다** ([인증.md](인증.md) §8.8). 맥에는 안 둔다.
  집기 응답이 피그마 자료가 있을 때만 싣고, 맥은 그 값을 **claude 자식 프로세스의 환경에만** 넘긴다.
  토큰이 없는데 피그마 자료가 있으면 맥은 claude 를 안 부르고 `FAILED` 로 끝낸다 — 사유는 「설정 화면에 피그마 토큰을 넣어라」
- **피그마를 읽는 도구는 npm 패키지 `figma-reader` 다** (GitHub 저장소 이름은 `figma-reader-cli` — 둘을 헷갈리지 마라).
  부르는 명령과 판 번호의 정본은 `.claude/skills/tpx-cases/references/1-input.md` 다
- **자료도 본문도 없는 행은 돌리지 않는다.** 작성 에이전트는 claude 를 안 부르고 `FAILED` 로 끝낸다. 옛 행은 `spec_text` 로 돈다. 단 화면만(`compare` 이고 `startUrl` 이 있는) 행은 돈다 (2026-09-25 · §3.6 「★ 역방향」)

`테스트 작성` 은 `테스트 케이스` **다음**이다. **여기 옮겨 적지 않는다** — 자리가 늘거나 순서가 바뀌면
그 절만 고친다.

> **2026-09-22 에 정해졌다.** 앞 판이 「위치는 화면 리뉴얼 뒤에 정한다」로 미뤄 뒀는데
> **그 리뉴얼이 끝났고**(PR #51) 같은 날 자리 절이 다섯째를 받았다.
> **미뤄 둔 문장을 그대로 두면 다음 세션이 자리를 다시 고른다** — 그러면 사이드바 순서가
> 정본과 어긋나고, 그 어긋남은 **화면을 눈으로 보기 전까지 아무 검사에도 안 걸린다**
> (2026-09-22 검토가 잡았다).

**왜 자기 자리를 갖나** — 작성은 대기줄·진행·결과·머지를 다 담아 버튼 하나가 아니고,
「케이스」 화면이 **이미 있는 것을 보는 곳**인 데 반해 여기는 **아직 없는 것을 만드는 곳**이다.
