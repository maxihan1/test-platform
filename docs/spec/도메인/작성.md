# 작성

> **이 장이 담는 절** — §3.6 · §7 Authoring API
> 기획서를 넣으면 테스트 코드가 만들어지고 화면에서 머지까지 간다. **코드는 저장소에만 생긴다.**
> **쓰는 표** `authoring_request` — 정의는 [공통/4-데이터모델.md](../공통/4-데이터모델.md) §6 에 있다.

### 3.6 작성 — 기획서를 테스트 코드로 (2026-09-22 신설)

- **책임**: 「이 기획서로 테스트를 만들어 달라」는 요청을 대기줄에 세우고, 맥에서 도는 작성 에이전트가
  집어 가 일하는 동안의 상태·작업 단계·결과를 화면에 낸다
- **애그리거트 루트**: `AuthoringRequest` (식별자는 대기줄 행 번호)
- **용어는 [공통/1-제품과-구조.md](../공통/1-제품과-구조.md) §2 가 정본이다** — `작성 요청`·`작성 에이전트`·`작업 단계`.
  여기서 새 이름을 짓지 않는다
- **불변식**
  - **코드는 저장소에만 생긴다.** 이 컨텍스트가 드는 것은 작성 요청과 작업 단계뿐이다.
    테스트 코드는 작성 에이전트가 **초안 PR**(draft pull request, 「아직 병합하지 말라」고 표시해
    올리는 변경 요청)로 저장소에 올리고, 사람이 병합해야 코드가 된다.
    **근거의 정본은 §1 「영구히 하지 않는다」 표의 「화면이 테스트 코드를 직접 들고 편집하는 기능」 행이다** —
    2026-09-22 에 그 행이 **화면이 코드 본문을 들고 있을 때**로 좁혀졌다. 여기 옮겨 적지 않는다
  - **`test_source` 는 그 금지의 예외가 아니다.** 편집 대상이 아니라 화면이 실패한 줄을 발췌하려고
    받아 두는 스냅샷이고, 머지 전 파일이 admin 의 `/tests` 에 없어서 필요하다 (§6)
  - **한 요청은 한 서비스다** — `authoring_request.service_id`. 실행이 `test_run.service_id` 로
    같은 것을 거는 것과 같은 규칙이다 (§1 · §6)
  - **집어 가는 쪽은 맥 하나다. 그래서 줄도 하나다.** 작성·재실행·머지가 `kind` 로 갈릴 뿐 한 줄에 선다.
    집는 일은 `PENDING`→`RUNNING` 한 줄 UPDATE 이고 그것이 곧 잠금이다 — **정본은 §6**
  - **진행은 두 층이고 이 컨텍스트는 위층만 든다. 이 구분이 이 장의 핵심이다**
    - **위층 — 작업 단계** (`stage`). 「요구사항 표 만드는 중」·「케이스 2건째」·「관문 3 도는 중」.
      케이스를 **만드는 일**의 진척이고, 이 표가 새로 드는 것은 이것뿐이다
    - **아래층 — 테스트 절차** (`Step`). **이미 kit 과 러너가 든다** (§5.1 · §5.2). 새로 만들지 않는다
    - 아래층을 `stage` 에 또 담으면 같은 것이 두 곳에서 다른 말을 한다. 아래층은 `result` 에 통째로 실려 온다 (§6)
  - **맥이 꺼져 있으면 줄이 안 준다.** 요청은 `PENDING` 으로 쌓여 있다가 켤 때 처리된다.
    고장이 아니라 구조다 — 없애려면 러너가 브랜치를 보게 해야 하고 그것은 배포 구성과 러너 계약(§5.2)을 건드린다

#### ★ 인증을 뚫지 않는다

작성 에이전트는 **컨테이너 밖**에서 돌지만 **계정으로 로그인해 사람과 같은 문**을 쓴다.
전용 경로도, 인증을 건너뛰는 예외도 만들지 않는다. 등급도 사람과 똑같이 걸린다 —
등급이 모자라면 작성 요청을 집어가지 못한다.

**★ 그 계정은 `operator` 다. `admin` 을 주지 않는다** (2026-09-22 검토가 잡았다).
맥이 하는 일은 **집기·단계 올리기·사진 올리기·끝났다고 알리기** 넷뿐이고 넷 다 `operator` 다.
**머지 행을 만드는 것은 사람**이고 맥은 그것을 집어 실행할 뿐이다 —
그래서 맥에 `admin` 이 필요 없다.

**왜 못박나** — 안 적으면 다음 세션이 「편하게 `admin` 으로 두자」를 고른다.
그 순간 **맥에 저장된 비밀값 하나가 `/api/settings/**` 전부를 연다** —
이 장이 세운 「실행할 수 있는 사람 ≠ 저장소를 바꿀 수 있는 사람」이 계정 설정 하나로 사라진다.

- **근거의 정본은 [인증.md](인증.md) §7 「인증 적용 범위」다.** `POST /api/auth/login` 을 뺀
  모든 `/api/**` 는 로그인이 필요하고 **예외는 없다**
- 그 절에 **2026-09-16 에 예외를 만들었다가 2026-09-17 에 지운 이력**이 있다. 그때의 판정이 이것이다 —
  그 예외가 내세운 방어는 **귀속**을 말할 뿐 **접근**을 막지 못한다. 이 길에도 그대로 적용된다
- **「맥에서 도는 거니까 토큰 하나 파자」로 되돌리지 마라.** 로그인 없이 지나가는 자리를 하나 내는 순간,
  §3.5 가 러너 포트를 닫으며 막으려 한 바로 그 뒷길이 admin 에 생긴다

**§9.2 정기 실행 선례와 다른 이유** — 그쪽은 HTTP 를 안 쓰고 **컨테이너 안 명령**으로 풀었다.
작성 에이전트는 컨테이너 밖에 있어 그 길이 없다.
**설명의 정본은 [공통/1-제품과-구조.md](../공통/1-제품과-구조.md) §3 컨텍스트 지도다** — 여기 옮겨 적지 않는다.

#### ★ 머지는 운영 등급이다

| 할 일 | 최소 등급 | 왜 |
|---|---|---|
| 작성 · 재실행 | `operator` | 결과가 **초안 PR** 이라 마음에 안 들면 버리면 된다. 지금 「실행」과 같은 무게다 |
| **머지** | `admin` | **저장소를 영구히 바꾼다.** 되돌리려면 사람이 손으로 해야 한다 |

**둘에 같은 등급을 주면 「실행할 수 있는 사람 = 저장소를 고칠 수 있는 사람」이 된다.**

**★ 그런데 지금 서버는 이것을 표현할 수 없다.** `apps/admin/src/auth/gate.ts` 가
「설정 자리면 `admin`, 아니면 읽기는 `viewer`, **나머지 전부 `operator`**」로 경로와 방식만 보고 가른다.
그대로 두면 머지 통로가 무조건 `operator` 다. **화면이 버튼을 안 그리는 것은 편의이지 방어가 아니다** —
이대로 만들면 실행 등급이면 누구나 머지 통로를 직접 찌를 수 있다.

**이 장은 「무엇이 어느 등급인가」만 적는다. 「서버를 어떻게 고치나」는 [인증.md](인증.md) §7
「등급으로 갈리는 자리」가 맡는다.** 여기 중복해 적지 않는다.

**에이전트가 머지를 판단하지 않는다. 손일 뿐이다.** 사람이 화면에서 눌러야만 머지 요청이 생긴다.
사람 게이트가 사라지는 것이 아니라 자리를 옮기는 것이다.

## 7. Admin API

**새 통로를 라우트표에 등록한다.** `apps/admin/src/auth/scope.ts` 가 **「모르면 막는다」**로 돌아
등록 안 된 틀은 문이 403 으로 떨어뜨린다. 안 적으면 **모든 요청이 막히고 원인이 권한처럼 안 보인다.**
번호에서 서비스를 찾는 갈래가 하나 필요하다 — `authoring_request.service_id` 다.

**등급의 정본은 `도메인/인증` §7 「등급으로 갈리는 자리」다.** 아래 묶음 머리의 등급 표시는
그 규칙을 이 경로들에 **적용한 결과**이지 새로 정하는 자리가 아니다 — 둘이 어긋나면 인증 장이 이긴다.

```
# Authoring — 화면이 부른다. 읽기는 보기만(viewer), 넣기는 실행까지(operator)
POST   /api/authoring/requests           작성·재실행 요청을 줄에 세운다
         ?service=    **필수.** 보고 있는 서비스의 접두사. 배정받지 않은 것이면 403
         { kind, sourceId?, specText, params? }
         ★ kind 가 AUTHOR 나 RERUN 이 아니면 400. 이 통로로는 MERGE 가 절대 안 들어온다
       → 201 { id }
GET    /api/authoring/requests           대기줄 한 쪽
         ?service=    **필수**
         ?status=     PENDING | RUNNING | DONE | FAILED. 생략하면 전부
         ?page=
       → { items, total, page, pageSize }
GET    /api/authoring/requests/:id       한 건 상세
       → { stage, stageAt, result, prUrl, testSource, ... }

# Authoring 머지 — 운영(admin) 등급만. 저장소를 영구히 바꾼다
POST   /api/authoring/merges             머지를 줄에 세운다
         ?service=    **필수**
         { sourceId }
       → 201 { id }    kind = MERGE 인 대기줄 한 행

# Authoring — 맥이 부른다. 사람과 같은 문을 지난다 (실행까지 등급)
POST   /api/authoring/requests/claim     줄에서 한 건 집어 간다
         ?service=    **필수**
       → 집은 한 건. 줄이 비었으면 204
PATCH  /api/authoring/requests/:id/stage 작업 단계를 올린다
         { stage }
       → 200
POST   /api/authoring/requests/:id/screenshots   사진 파일을 올린다
       → 200 { dir }
POST   /api/authoring/requests/:id/finish        끝났다고 알린다
         { status, result?, testSource?, prUrl?, error? }
       → 200
```

- **화면이 부르는 것과 맥이 부르는 것이 갈린다.** 넣기·읽기·머지 요청은 화면이 부르고,
  집기·단계 올리기·사진 올리기·끝났다고 알리기는 맥이 부른다. **같은 문을 지난다** (위 ★ 절)
- **머지만 경로가 갈린 이유** — 같은 경로에 `kind: 'MERGE'` 로 얹으면 등급이 **본문 값**에 따라
  갈려야 하고 그러려면 문이 본문을 읽어야 한다. 경로가 다르면 경로만 보고 가른다
- **★ 경로를 가른 것만으로는 안 닫힌다 — 본문도 가둔다** (2026-09-22 검토가 잡았다).
  문은 **경로**를 보고 `operator` 를 통과시키는데, 그 뒤 라우트가 본문의 `kind` 를 그대로 받으면
  `{ kind: 'MERGE', sourceId: <초안 PR 번호> }` 한 줄로 **머지 행이 대기줄에 서고 맥이 집어 간다.**
  그러면 **실행 등급인 사람이 저장소를 영구히 바꾼다** — 이 장이 막으려는 바로 그것이다.
  **막는 자리를 둘로 겹친다.**
  ⒜ 이 통로가 `AUTHOR`·`RERUN` 밖의 `kind` 를 **`400` 으로 거부한다** (위 §7)
  ⒝ 표가 `kind` 값 자체를 가둔다 (`공통/4-데이터모델` §6 의 `CHECK`)
  **하나만으로는 부족하다** — ⒜ 는 새 라우트가 생기면 빠질 수 있고, ⒝ 만 있으면 `MERGE` 가
  대기줄에 서는 것을 막지 못한다 (`CHECK` 는 값의 모양만 본다)
- **`requestedBy` 는 요청에 싣지 않는다.** 로그인한 세션에서 채운다 —
  실행이 `triggeredBy` 를 그렇게 하는 것과 같은 이유다 (§7.1 · §3.5)
- **사진만 따로 올린다.** 판정과 소스 본문은 `finish` 가 JSON 으로 한 번에 올리지만 사진은 파일이다.
  러너는 admin 과 같은 볼륨을 봐서 경로만 주고받으면 되는데 **맥은 다른 기계라 파일 자체를 올려야 한다** (§6)
- `result` 의 모양은 **§5.1 이 정본이다.** 맥이 러너와 같은 리포터를 타므로 같은 모양으로 온다
- **★ `?service=` 하나로 판정을 끝내지 않는다** (2026-09-22 검토가 잡았다).
  그 값은 **부르는 쪽이 적는 것**이고 문은 그것을 배정과 대조할 뿐이다 —
  `auth/gate.ts` 가 자기 주석에 그 함정을 적어 뒀다
  (「`/api/runs/<남의번호>?service=<내것>` 이 통과한다」, 2026-09-19 실측).
  **줄을 거르는 것은 라우트다.** 둘을 못박는다.
  ⒜ **`claim` 은 그 서비스의 `PENDING` 행만 집는다.** 자원을 **서버가 고르는** 통로라
  안 거르면 **남의 서비스 행**을 집어 주고, 그 행에는 `spec_text`(기획서 본문 통째)가 실려 있다
  ⒝ **`sourceId` 가 가리키는 행의 `service_id` 가 `?service=` 와 다르면 `403`.**
  본문에 실린 번호라 경로 검사가 안 닿는다 — 안 막으면 남의 서비스 요청을 가리키는
  `RERUN`·`MERGE` 가 선다
- 경로에 실린 번호(`:id`)는 **열 자리 숫자 글자만** 받는다. 그 밖이면 `400` —
  문(`auth/scope.ts`)과 라우트가 같은 값을 읽어야 한다

### 화면에서 어디에 서나 — **정해졌다**

**정본은 [공통/5-화면공통.md](../공통/5-화면공통.md) §8 「자리 목록」이다.**
`테스트 작성` 은 `테스트 케이스` **다음**이다. **여기 옮겨 적지 않는다** — 자리가 늘거나 순서가 바뀌면
그 절만 고친다.

> **2026-09-22 에 정해졌다.** 앞 판이 「위치는 화면 리뉴얼 뒤에 정한다」로 미뤄 뒀는데
> **그 리뉴얼이 끝났고**(PR #51) 같은 날 자리 절이 다섯째를 받았다.
> **미뤄 둔 문장을 그대로 두면 다음 세션이 자리를 다시 고른다** — 그러면 사이드바 순서가
> 정본과 어긋나고, 그 어긋남은 **화면을 눈으로 보기 전까지 아무 검사에도 안 걸린다**
> (2026-09-22 검토가 잡았다).

**왜 자기 자리를 갖나** — 작성은 대기줄·진행·결과·머지를 다 담아 버튼 하나가 아니고,
「케이스」 화면이 **이미 있는 것을 보는 곳**인 데 반해 여기는 **아직 없는 것을 만드는 곳**이다.
