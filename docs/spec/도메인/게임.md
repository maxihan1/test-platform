### 3.10 게임 테스트 — 기획서에서 디바이스 팜 실행까지 (2026-10-22 사용자)

사용자(2026-10-22) 「altterser로 게임 대상으로 PRD, Test스크립트, 테스트 실행까지 할 수 있는걸 만들고 싶은데 구현을 어떻게 할지 정리하자」 ·
「케이스 작성 하는부분이 취약한거 같은데??」 · 「리니지 라이크 게임을 QA 한다고 하면 어떻게 테스트 스크립트를 작성할껀지 … AI의 역할 웹처럼 지도는 어떻게 만들지」.
아래 결정 표는 같은 날 기획 대화(진행판 GAME-F1-01)에서 주제마다 정했고 시작 질문(GAME-F1-02)에서 명세로 옮기는 것을 승인받았다. 다시 묻지 않는다. 「(내 결정)」이 붙은 줄은 대화에서 알렸고 반대가 없던 것이다.
첫 대상 게임은 사용자의 리니지 라이크 **Ashveil**(`~/Projects/bossroom`, Unity 6000.0.84f1)이다 — 아래 예의 값은 거기서 왔다.

#### 조각 — 무엇을 어디에 만드나

```
[게임 안 SDK] ─TCP(폰 안 127.0.0.1)─┬ [디바이스 팜: 게임 명령 주소 · 명령마다 adb forward] ←HTTP─ [게임 CLI (작성 AI · 창 훑기)] · [kit · 서버 러너 (정식 실행)]
                                    └ [내 컴퓨터: USB adb forward] ←TCP─ [게임 CLI] · [kit · 내 컴퓨터 러너 (테스트 실행)]
```

| 조각 | 하는 일 | 자리 |
|------|---------|------|
| ① 게임 SDK | QA 빌드에서만 폰 안 `127.0.0.1` 에 포트를 연다(adb 로만 닿는다). 트리 읽기 · 찾기 · 누르기 · 끌기 · 글자 넣기 · 읽기 · 속성 읽기 · 가짜 `Input` · 게임 오류 받아 두기 · 배치 확인 | `control_cli`(Unity UPM 패키지) |
| ② 게임 CLI | appium-cli 꼴 — `snapshot`(줄인 트리 + 스크린샷) → ref → 액션. 액션마다 케이스 코드 한 줄(`Ran:`)을 찍는다 · 잡기 · 열기 · 놓기 · 창 훑기 `crawl`. 설치 · 실행은 디바이스 팜 Appium 세션으로 | 같은 `control_cli`(TypeScript). QA Hub 는 appium-cli 처럼 태그로 받는다 |
| ③ kit · 러너 | 몸통 `{ game }` · 보내는 길 둘 · Appium 으로 설치 · 실행한 뒤 게임에 붙기 · 증적 · 케이스가 부른 서버 API 기록 · 확률 검정 도우미 | test_platform |
| ④ QA Hub | 종류 `GAME` · 작성 자료 엑셀 · CSV · 게임 화면 통로 · 게임 지도 · 게임 작성 지침 · 설계 칸 · 관문 3 게임 갈래 · 종류 칩 | test_platform |
| ⑤ 디바이스 팜 | 폰을 잡은 사람만 쓰는 게임 명령 주소 — 명령마다 `adb forward` 를 걸고 답을 받으면 지운다(놓을 때 남는 것이 없다). 지금 입구(`:4723`, 회사 서버는 SSH 터널 하나)로만. 팜 입구를 거친 실기기 확인은 아직(아래 「0단계 결과」) | 사용자의 `~/Projects/Devicefarm` (INT-F13-11 · ADR-048) |
| ⑥ Ashveil | QA 빌드의 AltTester 를 우리 SDK 로 바꾼다 — 둘이 같이 `Input` 을 바꿔치면 부딪친다 | `~/Projects/bossroom` |

- **SDK ↔ CLI 사이 통신 꼴(명령 · 응답 모양)은 `control_cli` 저장소가 정본이다.** 이 명세는 QA Hub 가 그것을 어떻게 쓰는지만 적는다 (내 결정)
- **SDK 는 QA 빌드에만 든다** — QA 빌드 단계가 asmdef 참조 · 정의 심볼을 더하고 Release 빌드에는 빠진다(Ashveil D-29 꼴). 1차 지원은 Unity 6 LTS 하나다

#### 게임 연결 — 디바이스 팜 · USB (결정 12)

| | 정식 실행 · 작성 AI | 테스트 실행 |
|---|---|---|
| 폰 | 디바이스 팜 폰 — 지금처럼 빈 폰 하나를 잡는다(`apps/admin/src/execution/farm.ts`) | 내 컴퓨터 러너에 USB 로 꽂은 폰(`LOCAL_RUNNER_URL` — `apps/admin/src/execution/trialRoutes.ts`) |
| 게임에 닿는 길 | kit · CLI 가 팜의 게임 명령 주소 `POST /api/devices/{serial}/game` 으로 보낸다 — 본문은 게임 명령 JSON 하나, 답은 `{"value": <게임 답 그대로>}`(게임이 `ok:false` 여도 200). 오류도 `value` 에 `{error, message}` 로 와서 성공과 오류는 HTTP 코드로 가른다 — 게임에 못 닿음 · 15초 안에 답 없음 502 · 잡은 사람이 아님 · 폰 다시 켜는 중 409 · 본문이 JSON 객체가 아님 400 · 415 · 501(표는 안내서 7절). 팜이 명령마다 `adb forward` 를 걸고 답을 받으면 지운다 · 잡은 사람만 · 그 사람의 자동 테스트 중에도 받는다. 정본은 Devicefarm 안내서 `docs/guides/test-platform.md` 12절 | 내 컴퓨터 러너가 꽂힌 폰에 직접 `adb forward` 를 걸고 TCP 로 보낸다 |
| 화면 영상 · logcat | 팜이 남긴다(지금 앱과 같다) | 없다(앱과 같다) |

- **설치 · 실행은 Appium 이 한다** — 지금 앱 케이스 길 그대로 앱 파일(대상 서버 줄의 `app_path`)을 깔고 켠 뒤 kit 이 게임 포트에 붙는다. 스크린샷 · 기기 정보(`DeviceInfo`)도 Appium 세션에서 그대로 받는다
- **게임은 실행 하나 동안 폰을 한 번 잡고 한 번 깐다** — 앱은 항목마다 잡고 놓아(놓을 때 정리가 앱을 지운다 — `apps/admin/src/execution/farm.ts`) 항목마다 다시 깐다. 게임은 APK 가 크고 켜는 데 오래 걸려, 항목 사이엔 앱만 다시 켜고 상태는 어드민 API 로 맞춘다. 첫 실행 상태가 필요한 케이스(튜토리얼)만 앱 데이터를 지운다 — **표시할 칸이 아직 없어 1차에는 모든 항목이 데이터를 둔다**(2026-10-23 GAME-F1-09 시작 질문 승인 — 칸은 튜토리얼 케이스가 나올 때 계약으로 더한다).
  **붙인 모양 (2026-10-23 GAME-F1-09)** — admin 이 게임 실행의 android 항목을 한 줄로 모아 디바이스 줄 차례 하나 안에서 빈 폰을 **120분** 잡고, 항목마다 보내기 전에 늘리기(`/hold/extend` — 끝나기 10분 전부터 30분, 그 전이면 팜이 409 로 거절해 그냥 넘긴다)를 부른 뒤 같은 폰 번호로 차례로 보낸다. 다 돌면 한 번 놓는다(`apps/admin/src/execution/dispatcher.ts` · `farm.ts`). 항목마다 Appium 연결만 새로 연다 — kit 이 게임 항목 연결을 `noReset` · `forceAppLaunch` · `shouldTerminateApp` 으로 열어 한 번 깐 앱을 데이터째 두고 다시 켠다(`packages/kit/src/runtime/app.ts`)
  **아직 못 막는 것 (2026-10-25 GAME-F2-15)** — `noReset` 이면 Appium 이 같은 패키지가 깔린 폰에는 넘긴 APK 를 판을 견주지 않고 안 깐다. 잡은 폰에 같은 게임의 다른 판이 남아 있으면(팜에 처음 등록할 때부터 있던 패키지와 그 위에 덮어 깐 빌드는 놓을 때 지우지 않는다 — Devicefarm 안내서 11절 「앱 설치」. 10-24 의 0.1.25 처럼 잡기 밖에서 깐 판도 남아 있었다) 첫 항목도 그 판을 켜고, 실행은 넘긴 빌드가 아닌 그 판을 돈다. 게임 화면 읽기는 `noReset` 을 끄고 `enforceAppInstall` 을 켜서 막았다 — 끄기만 하면 깔린 판이 같거나 높을 때 또 안 깐다([러너.md](러너.md) §5.2 「게임 화면 읽기」). 실행 쪽은 admin 이 첫 항목을 러너에 알려야 해서 러너 요청 칸(계약)이 바뀐다 — 시작 질문(2026-10-25)에서 이번 줄 밖으로 뒀다
  **지금 잡는 규칙(항목마다 — [실행.md](실행.md) §3.2 「디바이스 줄」)이 바뀌는 자리다** — 회귀 실행 하나가 폰을 몇 시간 쥘 수 있어, 그동안 작성의 폰 잡기는 기다리지 않고 「폰이 다른 실행에 쓰이는 중이다」를 받는다(지금 앱 화면 읽기와 같다). 이 거절은 빈 폰만 고르는 QA Hub 쪽이 한다 — 작성은 서버 몫 토큰으로 붙어(`farm.ts` `팜머리` — [러너.md](러너.md) §5.2 「디바이스 팜 접속 방식」 「팜 토큰은 누른 사람 것이 먼저다」 · 2026-10-27. 그 전에는 토큰 없이 붙었다) 팜의 「잡은 사람만」은 토큰을 안 넣은 사람의 정식 실행과 작성을 한 사람으로 본다. 2026-10-29 부터 토큰을 넣은 사람이 누른 실행은 그 사람 것이라 팜이 가른다. 팜 폰이 한 대인 동안의 한계다. 아래 §7 블록이 잡는 단위를 같이 바꾼다
- **작성 중 폰 잡기** — 훑기 · 눌러 보기 · 돌려 보기 단계마다 잡고 놓는다. appium-cli 처럼 한 번에 30분을 넘겨 쥐지 않는다 — 그 사이 정식 실행이 폰을 쓴다.
  놓은 직후 다시 잡으면 팜이 정리하는 2~4초 동안 빈 폰이 아니다 — control-cli `hold`(v0.1.1 · 2026-10-25 GAME-F2-15)는 정리 중(`cleaning`)인 폰이 있을 때만 20초까지 기다리고, 없으면 바로 「다른 실행에 쓰이는 중」으로, 한도를 넘기면 「팜이 정리하는 중」으로 거절한다. QA Hub 폰 잡기(`apps/admin/src/execution/farm.ts`)와 같은 규칙이다
- 게임 포트는 폰 안 `127.0.0.1` 에만 연다 — 같은 와이파이의 다른 기기가 QA 빌드를 조작하지 못한다
- **명령 하나는 15초 안에 끝난다** — 팜이 15초에 502 로 끊고, SDK 는 10초에 스스로 「답하지 않았다」를 준다. 「뜰 때까지 기다리기」는 짧은 명령을 되풀이하는 꼴이어야 두 길(디바이스 팜 · USB)이 같게 돈다 — 게임 드라이버 `waitFor` 가 0.3초마다 `find` 를 보낸다(GAME-F1-06 · kit 도 같은 드라이버를 쓴다 — GAME-F1-09)

#### 케이스 꼴

웹 케이스 꼴(`tests/mku/MKU-FN-240.spec.ts`)과 앱 케이스 꼴(`tests/mda/MDA-FN-001.spec.ts`)을 잇는다 — `defineCase` 하나 · `platforms: ['android']` · 몸통이 `{ game }` 을 받는다. 쓰는 규칙은 작성 지침 `tpx-cases` `references/game.md`(2026-10-23 GAME-F1-11 — 화면을 읽는 `tpx-author` `references/game.md` 와 이름만 같다)가 맡는다.

- **준비** — 어드민 API 또는 GM 명령으로 상태를 만든다(결정 16 — 새 캐릭터 · 골드 · 아이템 · 위치 · 레벨 · 결과 고정 · 확률 설정 · 몬스터 놓기 · 봇 치우기). 걸어가지 않고 순간이동한다
- **확인 수단** — 보이는 글자는 화면, 서버가 정하는 값(재화 · 아이템 · 강화 결과)은 서버 API 와 화면 둘 다, 게임이 폰에서 계산하는 값(이동 속도 · 데미지)은 SDK 로 게임 안 속성을 읽는다. 어드민 API 가 없고 GM 명령만 있는 게임은 화면 값 · GM 조회 명령으로 확인하고 결과 요약에 「서버 값 확인 없음」을 적는다
- **간섭 차단** — 케이스마다 계정 앞머리를 쓰고, 봇과 다른 몬스터는 치운 뒤(Ashveil `/admin/world/reset`) 정해진 자리에 하나만 둔다. 정리는 finally.
  폰이 움직이는 봇처럼 서버가 자리를 못 박으면 읽는 동안 사라졌을 때 보이는 다른 것을 골라 다시 한다(2026-10-25 GAME-F2-13 — `tpx-cases` `5-stable.md` 「게임」)
- **기다림** — 고정 시간 쉬기 금지. 「오브젝트가 뜰 때까지 · 글자가 들 때까지 · 사라질 때까지」는 게임 드라이버 `waitFor` 로 기다린다(SDK 에 기다리기 명령은 없다 — 드라이버가 `find` 를 되풀이한다). 「값이 될 때까지」는 `get` 을 되풀이한다 — kit 이 게임 드라이버에 더한 `waitForValue`(GAME-F1-09 — [공통/3](../공통/3-공유계약.md) 「게임 테스트 타입」), 쓰는 법은 작성 지침 `5-stable.md` 「게임 — 기다림」(2026-10-23 GAME-F1-11)
- **주소** — 오브젝트 이름 → 겹치면 `/` 로 시작하는 경로(같은 이름 형제는 `[순번]`, 0부터 — `/HudCanvas/Inventory/Grid/Slot[2]`). 좌표 금지. 여럿 생기는 것(몬스터 · 드랍)은 정해진 자리에 하나 두고 찾는다
- **기대값** — 표준 기획서에서만 온다. 화면 · 창 기록 · 게임 지도 · API 지도는 근거가 아니다(웹과 같다 — CLAUDE.md 「playwright-cli」 절)
- **어드민 키는 케이스에 글자로 쓰지 않는다** — 대상 서버 줄의 어드민 키 칸(`service_env.admin_key` — 머리 이름 + 값, 설정 화면은 끝 4자리만 — [인증.md](인증.md) §7 「envs[] 한 줄」 `adminKey`)을 kit 이 몸통 `admin` 요청 도구의 머리로 넣고 기록에서 가린다(GAME-F1-09 — [공통/3](../공통/3-공유계약.md) 「게임 테스트 타입」). 작성 중에는 빠른 검사의 「비밀번호 노출 점검」이 케이스 · 표 · 가이드에서 키 값을 찾는다(아래 「작성 — 한 바퀴」 붙인 모양 GAME-F1-12b). Ashveil 은 머리 하나(`X-Admin-Key`)로 열려 OAuth 꼴 API 인증 칸(`api_auths`)에 안 맞는다
- **느린 망 흉내는 1차에 없다** — 게임은 kit 을 거치지 않고 자기 서버와 바로 통신한다

#### 창 훑기 — 게임 화면 지도 (CLI `crawl`)

- **단위** — 창(UI Canvas 아래 켜지고 꺼지는 묶음)과 장소(구역). 웹의 「같은 틀」 자리가 창 루트 경로다 — 같은 창의 목록 줄 · 슬롯은 대표 하나다
- **차례** — ① 로그아웃 상태 창(로그인 · 가입 · 서버 설정) ② 로그인 → 캐릭터 선택 · 생성 창 ③ 월드 HUD 버튼을 하나씩 눌러 열리는 창을 찍고 닫는다(창 안 버튼은 한 단계 더) ④ 장소마다 어드민 API 로 순간이동해 그 자리를 찍는다.
  CLI `crawl` 은 지금 화면에서 ③ 꼴(버튼을 하나씩 눌러 새로 뜬 창을 찍고 닫기 버튼 → 저절로 사라지기 → 폰 뒤로 키로 닫기)만 한다. ①② 로 화면을 맞추고 `crawl` 을 다시 부르는 것은 작성 AI 다 — 상태마다 폴더를 나눠(`game-crawl/<이름>/`) 훑고 훑자마자 견주기 명령(`npx tsx scripts/authoring-game-crawl.ts <폴더> '<상태>'`)을 돌린다(GAME-F1-10 · 자식 지침 `tpx-author` `references/game.md` §4).
  **④ 장소마다 순간이동과 조건이 있어야 열리는 창은 상태 도우미 부르기 명령으로 한다** (2026-10-24 GAME-F1-12b — 위 「작성 — 한 바퀴」 붙인 모양) — 둘 다 작성 중에 상태 도우미(어드민 API · GM 명령)를 불러야 해서 어드민 키를 넘기는 줄로 미뤘다(2026-10-23 GAME-F1-10 시작 질문 승인 · GAME-F1-11 에서 F1-12 로 옮김 → GAME-F1-12 에서 GAME-F1-12b 로 나눔).
  장소는 게임 지도의 `zone:` 요소마다 도우미의 순간이동으로 옮긴 뒤 `crawl --max 1 --out game-crawl/zone-<구역>` 으로 그 자리만 찍고 견주기 명령에 구역을 준다(`… '<상태>' <구역>`) — 시작 화면이 장소 기록 `game:<장면>/zone:<구역>` 이 되고 견주기가 `game.json` 에 구역을 남겨 에이전트가 같은 열쇠로 올린다. 조건부 창은 도우미로 조건(골드 · 아이템 · 레벨)을 만든 뒤 그 창을 연 화면에서 `crawl` 을 다시 부른다(폴더를 나눈다). 구역 이름은 글자 · 숫자 · `_` `-` 64자까지다(`scripts/authoring-game-crawl.ts` `구역꼴`). 어드민 API 가 없고 GM 명령만 있으면 잡은 폰의 채팅 칸에 control-cli 로 넣는다(위 「작성 — 한 바퀴」 붙인 모양 GAME-F1-12b). 둘 다 가이드에 없으면 안 한다. 결과 파일 꼴의 정본은 control_cli README 「창 훑기」
- **위험한 누르기** — 크롤 전용 버림 캐릭터로 돈다(캐릭터 이름 앞머리 `qacrawl` · 끝나면 정리 — 작성 끝에 상태 도우미의 캐릭터 지우기를 부르기 명령으로 부른다. 가이드에 지우는 길이 없으면 남기고 결과 요약에 적는다 · 2026-10-24 GAME-F1-12b). 캐릭터 삭제 · 탈퇴처럼 크롤을 끝내는 버튼은 누르지 않는다(웹 「탈퇴 멈춤」과 같다)
- **상한** — 창 60개 · 10분 안쪽, 작성 30분 예산 안이다. 숫자의 정본은 CLI 코드 상수 `CRAWL`(control_cli `src/crawl.ts`)이다
- **재사용** — 창마다 글자 · 구조 지문을 남긴다. 다음 작성 때 지문이 같으면 다시 안 훑는다(웹 30일 그물). 바뀐 창만 다시 훑는다.
  **붙인 모양 (2026-10-23 GAME-F1-10)** — `crawl` 은 지문을 재려고 창을 다 연다. 다시 안 하는 것은 AI 의 정리와 올리기다. 견주기 명령이 창마다 `같음`(같은 상태 · 같은 열쇠의 저장 기록과 지문 둘 다 같고 훑은 지 30일 안) · `바뀜` · `새 창` 을 찍고(`scripts/authoring-game-crawl.ts`), AI 는 같음이면 `game-kept/` 의 저장 기록을 읽고 바뀜 · 새 창만 기록 파일 끝에 「## 정리」(무엇 하는 창 · 주요 오브젝트 · 이어지는 항목)를 덧붙인다.
  에이전트는 견주기 명령이 남긴 표시(`game.json` — 상태 · list.json 지문 · 창마다 같음)대로 바뀜 · 새 창만 화면 기록으로 올린다(`PUT …/screens` — 열쇠는 아래 「지도」의 `game:<장면>/<창 경로>`(창 경로는 같은 이름 형제 순번을 뗀 틀) · 시작 화면은 `game:<장면>` · 연결은 창을 연 버튼). 자식이 본 판정과 올리는 판정이 같아야 정리를 덧붙이지 않은 창이 정리된 기록을 덮지 않는다(웹이 크롤 목록의 「같음」을 믿는 것과 같다). 견주기 뒤에 같은 폴더를 다시 훑었으면(지문이 다르다) 그 폴더는 안 올린다.
  같음은 안 올려 훑은 날이 그대로라 30일 그물이 돈다 — 다만 같음 창에서 서버가 모르는 창으로 가는 연결이 생겼으면(지난 훑기가 상한에 걸려 못 연 창) 서버의 기록 · 지문 · 훑은 때를 그대로 둔 채 연결만 보태 다시 올린다. 본 창은 전부 찾은 창(`…/screens/done` 의 seen)으로 남긴다.
  **못 본 창의 옛 기록은 지우지 않는다**(done 의 complete 빈 목록) — 한 화면에서 시작한 훑기라 그 상태를 다 봤는지 모른다. 사라진 창의 기록이 남는 한계는 상태 도우미로 다 도는 훑기가 생길 때 다시 본다. 기록 · 이름 · 연결에 테스트 계정 비밀번호가 있으면 하나도 안 올리고 PR 본문 머리 줄에 적는다
- **AI 몫** — 프로그램이 못 연 조건부 창을 연다(GAME-F1-12b — 상태 도우미) · 창 기록에 「무엇 하는 창 · 주요 오브젝트 · 이어지는 기획서 항목」을 적는다 · 창 기록은 기대값 근거가 아니다

#### 지도 — 웹 표를 게임 열쇠로 (결정 9)

새 표를 만들지 않고 웹 지도 표에 게임 꼴 열쇠를 넣는다. 표 정의는 [공통/4-데이터모델.md](../공통/4-데이터모델.md) §6 「표준 기획서 · 지도 · 화면 기록 표」 · 「서비스 지도 표」.

| 웹 표 | 게임에서 담는 것 | 누가 채우나 |
|-------|------------------|-------------|
| `prd_version` | 같다 — 데이터 표 줄은 요구의 입력값 | AI 옮기기 |
| `req_case` | 같다 | 스캔 |
| `case_screen` | 케이스 ↔ 화면 객체(`pages/<창>.page.ts` — 주소 값이 창 열쇠) ↔ **창 열쇠** `game:<장면>/<창 경로>`(예 `game:World/Canvas/InventoryPanel`) | 스캔 |
| `screen_record` | 창 · 장소 기록 — 오브젝트 이름 · 경로 · 종류(버튼 · 글자 · 입력칸 · 월드) · 누를 수 있나 · 글자 지문 · 구조 지문(오브젝트 이름 나무). 장소는 `game:World/zone:Town` 꼴 — 그 자리의 NPC · 몬스터 · 바닥 아이템 | CLI 훑기 + AI 정리 |
| `screen_link` | 창 → 버튼 → 창 · 장소 → 귀환 · 이동 → 장소 | CLI 훑기 |
| `screen_found` | 찾은 창 · 장소 전부 → 「PRD 에 없는 창」(예 GM 콘솔) | CLI 훑기 |
| `service_api` · `service_api_use` | API 목록은 게임 서버 API 문서에서(API 테스트의 문서 읽기). **케이스 → API** 는 kit 이 케이스가 부른 서버 API 를 기록한다(android 는 trace 를 끄므로 게임은 API 기록만 켠다). **창 → API 는 1차에 비운다** — 게임마다 통신(REST · 소켓)이 달라 SDK 가 엿들을 길이 하나가 아니다 | kit · 스캔 |

- `state` 는 웹과 같이 `로그아웃` · `로그인:<역할>` 이다. `screen_found.viewport` 는 게임에서 비운다
- 화면 기록 통로(작성.md §7 `PUT …/screens`)는 주소 꼴을 안 봐서 `game:` 열쇠가 그대로 들어간다(GAME-F1-07 확인 — 코드 변경 없음). 그 통로는 요청의 대상 서버 줄에 저장하는데 게임 작성 요청은 대조가 없어 그 칸이 비어 있다 —
  **게임 애플리케이션 요청의 화면 기록 셋(`GET` · `PUT …/screens` · `POST …/screens/done`)은 앱 줄에 둔다**(2026-10-23 GAME-F1-10 시작 질문 승인 — `apps/admin/src/prd/agentRoutes.ts` `화면줄`). 앱 줄은 게임 첫 화면을 읽는 줄과 같다(요청에 대상 서버가 있으면 그 줄, 없으면 앱 파일 경로가 있는 첫 줄 · 운영 줄은 건너뛴다). 창 훑기는 그 줄의 앱 파일로 켠 게임을 본 것이다. 앱 줄이 없으면 웹처럼 빈 목록 · 400 `BAD_SCREEN` `env` 다
- **지도는 화면에 보이지 않는다** — 웹 지도처럼 AI 가 다음 작성 때 읽는 내부 기록이다. 새 화면 · 카드 · 탭을 더하지 않는다(2026-10-22 사용자 「이 지도를 보여주지 않는데」). 웹에서 지도에서 뽑아 보이는 것은 「케이스가 안 거친 API」 카드 수 하나뿐이다(2026-10-26 — 그 카드는 테스트 작성 결정 목록 「미검증 API」로 옮긴다 · 도메인/작성 §3.6 「★ 결정 목록」)

#### 게임에만 있는 지도 넷 (결정 9)

| 지도 | 담는 것 (Ashveil 예) | 어디서 오나 | 무엇에 쓰나 |
|------|---------------------|-------------|-------------|
| 게임 데이터 | 아이템 · 몬스터 · 스킬 · 상점 · 드랍표 · 확률표 줄마다 기획서 값 · 게임 서버 값 · 거친 케이스(`sword_long` 공격력 +14 · 1,200골드) | 표준 기획서의 데이터 표 + 게임 서버 데이터 API(`/admin/item-templates`) | 기획서와 서버 값이 다른 줄 · 한 번도 안 거친 아이템 · 몬스터. 확률표 줄에는 세 겹 상태와 마지막 검정 결과 |

- **채우는 때** — 표준 기획서로 옮긴 바로 뒤의 「게임 지도 만들기」 단계(위 「작성 — 한 바퀴」 1b). AI 가 파일로 써서 서버에 올린다(화면 기록 올리기 꼴). 기획서를 고치면(PRD 「반영」) 그 요구에 붙은 요소만 다시 만든다.
  **붙인 모양 (2026-10-23 GAME-F1-10)** — AI 가 자료 폴더 `game-elements.json` 에 §7 `PUT …/game-elements` 본문을 그대로 쓰고(지난 지도는 `game-map.txt` 로 받는다), 에이전트가 자식 뒤에 그대로 올린다 — 모양 검사는 서버가 하고 틀린 자리를 PR 본문 머리 줄에 싣는다. 비밀번호가 든 파일은 안 올린다. 「스폰 API 읽기」는 AI 가 서비스 가이드의 스폰 목록을 옮기는 것으로 시작했고, 2026-10-24 GAME-F1-12b 부터 도우미에 스폰 목록 읽기(가이드에 경로가 있을 때)가 있으면 부르기 명령으로 서버 목록을 읽어 `spawn:<번호>` 요소를 채운다(위 「작성 — 한 바퀴」 붙인 모양 GAME-F1-12b)
- **열쇠** — 데이터 `item:sword_short` · 월드 `zone:Town` · `spawn:<번호>` · `npc:<이름>` · 상태 `state:성향=보라` · 바뀜 `move:성향 선량→보라` · 재화 `flow:골드-강화`
- **담는 법** (내 결정) — 지도마다 표를 만들지 않고 표 둘에 종류만 나눈다: 게임 요소(종류 · 열쇠 · 이름 · 값 · 근거 요구 번호)와 요소를 거친 케이스. 케이스는 선언에 닿는 요소를 적는다(`defineCase` 의 `elements` — `techniques` 처럼 AI 가 쓰고 빠른 검사가 지도에 있는지 본다)
- **서버 값** — 데이터 대조 케이스(API 로 표 전 줄 대조)가 kit 도우미로 줄마다 결과를 남기고, 실행 결과(`elementChecks` — 공통/3-공유계약 「게임 테스트 타입」)로 admin 이 요소에 쓴다(열쇠마다 마지막 값 하나 — 항목마다 받은 줄은 `run_item.element_checks` 에 따로 남아 실패 카드 「오브젝트」 탭이 된다, 2026-10-31 WEB-F7-24). 지도가 「기획서 값 · 서버 값 · 같음 / 다름」으로 보인다(AI 가 읽는다)
- **덮음** — 재화 흐름은 케이스 선언 + 통과로 센다. 실행 뒤 서버 원장 기록 종류로 자동으로 맞추는 것은 나중이다
- AI 는 작성 전에 지도를 파일로 받는다(웹 `api-map.txt` 꼴). 지도는 기대값 근거가 아니다 — 근거는 표준 기획서 항목뿐이다

#### 설계 칸 — 게임 관점 넷 (결정 8)

웹 기법 다섯(경계값 · 동등 분할 · 결정 테이블 · 상태 전이 · 오류 추정 — [작성.md](작성.md) §3.6 「★ 테스트 두 갈래」)은 그대로다. 설계 명령이 게임 낱말로 칸을 더 뽑는다.
**기법 이름 목록(`TECHNIQUES`)은 늘리지 않는다** — 게임 관점은 칸을 뽑는 낱말일 뿐 케이스 선언의 기법 칸 값이 아니다 (내 결정 — 늘리면 계약이 바뀌고 웹 화면의 기법 표시가 같이 바뀐다).

| 관점 | 기획서 낱말(예 — 판정이 보는 낱말의 정본은 `scripts/authoring-design.ts`, 아래 「붙인 모양」) | 뽑는 칸 · 확인 |
|------|----------------------|----------------|
| 확률 세 겹 | 「%」 · 「확률」 · 「무작위」 | 위 「확률 세 겹」 ① · ② · ③ |
| 재화 · 아이템 흐름 | 골드 · 경험치 · 획득 · 소모 · 구매 · 판매 · 드랍 | 늘고 준 양 = 서버 원장 = 화면 값. 모자랄 때(정확히 비용 · 1 모자람) |
| 게임 상태 바뀜 | 사망 · 부활 · 성향 · PK · 장착 · 해제 · 파괴 | 허용된 바뀜 하나씩 + 막혀야 할 바뀜(마을 안 PK · 죽은 채 상점) |
| 시간 · 공간 | 초 · 리젠 · 쿨다운 · 반경 · m · 구역 · 좌표 | 시간 경계(19초 · 20초) · 거리 경계(24m · 25m) · 구역 경계(Z 199 · 200) — 걸어가지 않고 순간이동 |
| 끊김 · 연타 | 저장 · 유지 · 재접속 · 구매 · 강화 · 결제 | 앱을 끄고 다시 켜도 위치 · 진행 유지 · 버튼 연타 · 동시 요청에 한 번만 |
| 데이터 표 | 표 하나가 요구 하나 | 표 전 줄은 API 로 한 번에 대조, 화면은 대표 줄(가장 싼 · 비싼 · 판매 불가) |

- **통신 끊기(요청 중 와이파이 끊기)도 1차에 넣는다** — 0단계에서 디바이스 팜 Appium 의 `mobile: setConnectivity { wifi: false }` 가 됐다(되돌리기도 됐다). 모바일 데이터는 팜 폰에 SIM 이 없어 못 봤다 — 와이파이만 끊는다
- **붙인 모양 (2026-10-23 GAME-F1-11 시작 질문 승인)** — 설계 판정(`scripts/authoring-design.ts`)이 **종류 「게임」 애플리케이션 요구에만** 게임 낱말 칸을 더한다 — 「구매」 · 「저장」은 웹 기획서에도 있어 웹 판정을 흔들지 않게. 게임 여부는 에이전트가 원장을 지을 때(원장 준비 · 원본 원장과 옮기기 대조 · 올리기 판정 · 반영 계획)와 자식이 원장을 다시 지을 재료(`ledger-base.json` 의 `게임`)로 넘긴다.
  칸은 웹과 같은 경계 · 예외이고 기법도 웹 다섯 안이라 빠진 칸 막기 · 「설계 거절」 · 기법 대조가 그대로 돈다 — 확률 「성공 40%」 → 경계 0% · 100%(②) + 예외 결정 테이블(①) · 정상 칸은 ③ · 재화 쓰는 곳 「1,000골드」 → 경계 999 · 1,000골드(금액이 없으면 「비용 − 1 · 비용」) · 재화 모자람 → 예외 동등 분할 · 상태 바뀜(사망 · 성향 · PK · 장착 · 해제) → 예외 상태 전이 · 「리젠 20초」 · 「반경 25m」 · 「Z 200 부터」 → 경계 바로 앞 · 그 값(한도 낱말이 붙으면 웹과 같은 2값 — 「25m 이내」 → 25m · 26m. 좌표는 「좌표」가 앞에 오거나 한도 낱말이 뒤에 올 때만) · 끊김 뒤를 적은 문장(재접속 · 저장된다 · 유지된다) → 예외 상태 전이.
  **데이터 표는 칸을 뽑지 않는다** — 정상 케이스 하나에 API 전 줄 대조 · 화면 대표 줄 절차 둘이다. **기획서가 적지 않은 연타 · 끊김은 오류 추정 줄이다** — 두 번 누르기에 구매 · 강화 · 판매를 더하고 게임만 항목 둘(통신 끊기 · 다시 켜기)을 더한다([작성.md](작성.md) §3.6 「설계 기법」 「오류 추정」). 줄 쓰는 법은 `tpx-cases` `test-design.md` 「게임 애플리케이션」.
  「PRD 관리」의 「설계 미리보기」는 화면이 애플리케이션 종류를 몰라 웹 칸만 보인다

#### 실행 결과 (결정 11)

새 화면은 없다. 앱 케이스 결과 화면을 그대로 쓴다 — 단계별 판정 · 캡처 스크린샷 · 기기 정보 · 통과 못 한 항목의 팜 화면 영상 · logcat(`apps/admin/src/web/FarmEvidence.tsx`) · 실패 유형과 한 줄([리포팅.md](리포팅.md) §8.12 「실패 유형」).

- **실패 유형** — 게임 드라이버 오류 문구를 실패 유형 분류(`apps/admin/src/reporting/failureType.ts`)가 알아보게 맞춘다: 오브젝트 못 찾음 → 요소 미검출 · 기다림 초과 → 타임아웃 · 게임 연결 끊김 → 환경 오류(이름은 화면 · [리포팅.md](리포팅.md) §8.12 「실패 유형」 것. 맞춘 문구는 그 절 차례 ③ ~ ⑤ — 2026-10-23 GAME-F1-09)
- **통과 못 한 항목에 둘을 더 남긴다** — ① 실패 순간 화면에 있던 오브젝트 목록(트리 파일 `game-tree.txt` — 「이름이 바뀌었나 · 창이 안 열렸나」) ② 케이스 동안 게임에서 난 오류 로그(`game-errors.txt` — Unity 예외 · 에러 — SDK 가 받아 둔다. 웹 「콘솔 오류」 자리. 없으면 파일이 없다). 자리는 화면 영상 · logcat 옆 「받기」 줄이다 — kit 이 팜 증적 폴더에 두어 지금 목록이 그대로 낸다(GAME-F1-09 — 꼴은 [공통/3](../공통/3-공유계약.md) 「게임 테스트 타입」). 실행 결과 실패 카드에서는 ① 이 「받기」 줄 대신 증거 칸 「오브젝트」 탭에 그 항목의 게임 요소 대조 표와 같이 펼쳐 보인다(2026-10-31 WEB-F7-24 · [DESIGN.md](../../DESIGN.md) 「증거 칸은 종류마다 탭만 다르다」). 항목 상세 · E2E 결과는 「받기」 줄 그대로다
- **통과한 항목의 「영상 보기」** — 누르면 디바이스 팜에서 받아 온다(팜 보관 30일 안). 같은 화면이라 앱 케이스에도 붙는다. 30일이 지났거나 팜이 꺼져 있으면 까닭 한 줄을 보인다.
  **첫 조각(3분)만 보인다** — 팜이 3분마다 파일을 나누는데 항목 하나는 길어야 5분이라 대부분 한 조각이다(2026-10-23 GAME-F1-09 시작 질문 승인). 러너는 통과 항목의 Appium 연결 번호 파일을 남기고, admin 이 그 번호로 팜에 묻는다(받아 저장하지 않고 흘려보낸다 — 우리 저장 공간이 그대로다)
- 추적표 · 정기 실행 · 흔들림 표시는 그대로다

#### 빌드마다 돌리기 (결정 13)

**정본은 [실행.md](실행.md) §3.11 이다** (2026-10-24 GAME-F1-13 — 웹 · Android 앱 · API 도 같은 CI 토큰 · 같은 통로로 받게 넓혀 옮겼다. 사용자 「웹이나 모바일 ci도 필요 한데 같이 쓸수 있는 거야?」).
게임에서만 다른 것은 셋이다.

- **스모크 핵심 경로** — 로그인 → 캐릭터 → 월드 입장 → 사냥 한 번 → 상점 한 번. 작성 지침이 정상 기능 케이스에만 · 다 해서 5~10건 단다(2026-10-23 GAME-F1-11 — `tpx-cases` `5-writing.md` · `game.md` §5).
  게임 화면을 거치는 케이스로 고른다 — 어드민 API 만 부르고 끝나는 케이스는 빌드가 깨져도 초록이다(1차 작성 PR #442 의 6건이 모두 그랬다). 메인 AI 가 합친 뒤 고르고, 0건이면 빠른 검사가 짚는다(2026-10-25 GAME-F2-13 — 위 「작성 — 한 바퀴」 5 · 6)
- **폰은 실행 하나에 한 번 잡는다**(위 「게임 연결」) — 서명 주소가 같은 시간대에 같아 Appium 이 받아 둔 APK 를 다시 쓴다. 120분 잡기를 항목마다 늘린다
- **CI 가 빌드에 박는 서버와 빌드를 알릴 때 고르는 대상 서버는 같은 서버다**(2026-10-25 GAME-F2-18) — 어긋나면 스모크가 어드민 API 로 만든 상태를 게임이 못 봐 모두 빨갛다. 까닭은 아래 「게임 쪽이 준비할 것」

#### 게임 쪽이 준비할 것 (결정 16)

Ashveil 은 QA Hub 를 염두에 두고 만들어 어드민 API(상태 만들기 · 결과 고정 · 확률 설정 · 정리)가 있다. 고객사 게임에는 없을 수 있다. 이 목록은 납품 문서(고객사 요청 목록)로 쓴다.

- **꼭** — ① QA 빌드에 우리 SDK ② 상태를 만드는 길(어드민 API 또는 GM 명령) — 캐릭터 · 재화 · 아이템 · 위치 · 결과 고정 · 확률 설정 · 정리 ③ 테스트 계정 만들기(아이디 · 비밀번호, 또는 QA 빌드의 게스트 · 개발용 로그인 — 소셜 로그인만 있는 게임) ④ QA 빌드에 QA 서버 주소를 박는다(아래 「서버 주소는 QA 빌드에 박는다」)
- **있으면 좋은 것** — 시도마다 적용 확률 · 뽑은 숫자 기록(확률 ③ 을 서버 쪽에서도 본다) · QA 환경 요청 기록(창 → API 지도를 채운다)
- GM 명령은 SDK 가 채팅 창에 대신 친다 — UI 조작이라 SDK 에 새 기능이 없다(글자 넣기 · 보내기). 둘 다 없으면 그 케이스는 보류다(사냥으로 준비하지 않는다)
- **서버 주소는 QA 빌드에 박는다** (2026-10-25 GAME-F2-18 시작 질문 승인) — QA Hub 는 게임에 서버 주소를 넘기지 않는다. 대상 서버 줄 주소는 게임에 가지 않고 케이스의 어드민 · 서버 API 와 작성 · 부하 쪽이 쓴다.
  폰에 넣는 설정 파일(Ashveil `server-config.json`)은 디바이스 팜이 폰을 놓을 때 앱 데이터와 함께 지우고, 로그인 화면의 서버 설정 버튼은 게임마다 화면이 달라 케이스마다 주소를 넣는 조작이 따로 든다. GAME-F1-14 의 빌드 39 는 주소를 비워 만들어 폰 안 `127.0.0.1:8080` 으로 갔다.
  Ashveil 에서는 빌드 단계의 기본 서버 주소 칸(저장소 변수 `GAME_SERVER_URL` · 수동 실행 입력 `serverUrl`)을 채우면 된다 — 빌드 39 까지는 비어 있었고, 채우는 것은 Ashveil 쪽 일이다.
  **박은 서버와 대상 서버 줄 주소는 같은 서버여야 한다** — 케이스가 어드민 API 로 만든 캐릭터 · 아이템을 게임이 봐야 한다. QA Hub 는 둘이 같은지 보지 않는다 — 어긋나면 준비한 상태가 게임에 안 보여 케이스가 빨개진다.
  한 빌드로 여러 서버를 돌리는 길은 아래 「1차 밖 · 나중」이다
