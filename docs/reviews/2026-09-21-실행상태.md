### ② 회차 접기가 화면과 서버에서 같은 말을 하는가 — **통과**

`reporting/insights.ts` 의 `접기` SQL 과 `web/group.ts:51` 의 `회차요약()` 을 세 조합으로 눈으로 대조했다.
**갈래가 둘 다 셋이다.** 판정하는 순서만 다르고(SQL 은 FAIL 먼저, JS 는 PASS 먼저) 결과가 같다.

| 한 (케이스, 디바이스)의 회차들 | `접기` SQL | `회차요약()` |
|---|---|---|
| 전부 PASS | `bool_or(FAIL)` 거짓 → `bool_and(PASS)` 참 → **PASS** | `통과 === 길이` → **PASS** |
| 하나라도 FAIL (PASS·NA 가 섞여도) | `bool_or(FAIL)` 참 → **FAIL** | `통과 ≠ 길이` · `실패있나` 참 → **FAIL** |
| 전부 NA, 또는 PASS+NA | 둘 다 거짓 → **NA** | `통과 ≠ 길이` · `실패있나` 거짓 → **NA** |

정본 둘(도메인/실행 §8.3 「회차 요약」 · 도메인/리포팅 §8.5)과도 맞는다.
§8.5 가 경고한 「`bool_and(status = 'PASS')` 만 쓰면 NA 가 실패로 둔갑한다」를 **SQL 이 실제로 피했다.**

그물도 있다 — `insights.test.ts` 가 `XDG-005` 를 5회 중 3PASS·2FAIL 로 넣고 `계속깨짐` 을 단언하고(계획 BLOCKER 3),
`XDG-008`(앞 PASS → 이번 NA 2회)과 `XDG-009`(앞 NA → 이번 PASS)로 NA 양쪽 방향을 둘 다 민다.

**화면과 서버가 같은 접기를 본다는 것도 코드로 확인했다** — `RunInsights.이번판정들()` 이
`회차요약()` 을 그대로 부른다. 낱말(서버가 준 `판정`)과 색(화면이 접은 `status`)이 같은 결과 위에 선다.

### ③ 비밀값이 새는가 (§4.1) — **통과**

`대표문장뽑기` SQL 을 직접 읽었다. 뽑는 것은 둘뿐이다.

- `a.value->>'statement'` — 케이스 작성자가 `verify('...')` 에 직접 쓴 **문장 리터럴**이다
  (`packages/kit/src/runtime/verify.ts:37` 이 인자를 그대로 넣는다). 실행값이 안 섞인다
- `i.error->>'message'` — 이미 `ItemDetail.tsx:48` 이 화면에 그대로 그리고 있는 값이다
