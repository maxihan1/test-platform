## 기타

### 1. 화면이 서버 모듈(`execution/validate.ts`)을 직접 import 한다
어디:    `apps/admin/src/web/validation.ts:5`
무엇:    `import { validate } from '../execution/validate.js'` — 화면 번들에 서버의 검증 함수가 들어간다
왜 이렇게: `POST /api/runs`는 입력값을 스키마로 검증하지 않는다(title·platforms·케이스 존재만 본다).
         그런데 SPEC §8.2는 "검증 실패 시 칸 아래에 이유를 표시"를 요구한다. 검증기를 화면에 또 쓰면
         '실행하기'와 '입력값 세트로 저장'(서버가 검증)이 같은 값에 다른 사유를 낸다
위험:    WS-B가 그 파일에 DB나 fastify를 import 하면 화면 빌드가 조용히 깨진다
대안:    admin에 검증 전용(저장하지 않는) 엔드포인트를 두면 경계가 깔끔해진다. SPEC §7 변경이 필요하다
체크리스트 제안: C 절에 `C4 — 화면이 서버 모듈을 직접 import 하는가`를 넣을 만하다. 지금 C2는
         Catalog·Execution·Reporting 셋 사이만 본다

### 2. JSX 렌더링에는 자동 테스트가 없다
무엇:    테스트한 것은 순수 함수 4종(스키마→칸, 검증, 환경 묶기, 주소)이다. 화면이 실제로 그려지는지는
         브라우저에서 손으로 눌러 확인했다 (진행 기록에 확인 목록)
왜:      vitest include가 `apps/**/*.test.ts`라 `.test.tsx`를 집지 않고, DOM 환경(jsdom)도 깔려 있지 않다.
         새 패키지는 CLAUDE.md §3대로 물어야 한다
판단 필요: jsdom을 깔아 컴포넌트 테스트를 넣을지, 화면은 사람이 보는 것으로 둘지

### 3. 컨테이너가 화면을 서빙하지 못한다 — 내 소유 경로 밖
무엇:    `.dockerignore`의 `**/dist`와 `apps/admin/Dockerfile`에 vite 빌드 단계가 없는 것
왜 문제: `docker compose up` 만으로는 3000번에서 화면이 안 열린다. 지금은 개발 서버(5173)로만 열린다
고칠 곳: 병합 담당. Dockerfile에 `RUN npx vite build --config apps/admin/src/web/vite.config.ts` 한 줄
