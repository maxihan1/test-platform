## 중대

### 실측이 3등급인데 3등급 렌즈를 안 돌렸다

어디: 절차 (`.claude/skills/tpx/SKILL.md` 등급별 절차 표)
무엇: `docs/spec/**` 를 고쳐 `SPEC` 표면이 붙었고 `detect-tier` 가 **3등급**을 낸다.
선언은 2등급이었다. 3등급이 요구하는 것 중 **코드 검사 렌즈 하나**가 빠졌다.

| 3등급이 요구하는 것 | 돌았나 |
|---|---|
| 게이트 0 (계약 변경) | ✅ 돌았다 — `/auth/me` 응답 변경을 승인받았다 |
| 계획 1장 + §1.2 절차 | ✅ |
| 계획 검토 `/plan-eng-review` + `/plan-ceo-review` | ⚠️ eng·design 관점만. **ceo 렌즈는 안 돌았다** |
| 코드 검사 + **`/security-review`** 또는 `ponytail-review` | ❌ **안 돌았다** |

왜 문제: **이번 변경이 인증 표면을 건드렸다.** `GET /api/auth/me` 의 응답에
`envs[].baseUrl`(대상 서버 **내부 주소**)을 실었고 이 값은 **보기만 등급에게도 간다.**

「실행 결과 화면(§8.3 RUN 머리)에서 이미 보이는 값이라 새 노출이 아니다」로 판단했지만
**그 판단을 자기검사가 했다.** 노출 면이 「그 실행을 볼 수 있는 사람」에서
「로그인한 모든 사람」으로 넓어진 것은 맞고, 그것이 괜찮은지는 바깥 렌즈가 볼 일이다.

고칠 곳: 게이트 2 전에 `/security-review` 를 돌린다. 등급 판정은 게이트 2 에서 사람이 정한다.

**왜 선언이 2였나** — 착수 시점에는 SPEC 을 고칠지 몰랐다. 게이트 0 에서 확정됐는데
**그때 선언을 3으로 올리지 않았다.** 체인이 「실측이 높아도 자동 승격하지 않는다」고 하지만,
**게이트 0 통과 시점은 선언을 다시 잴 자리**다 — 거기서 SPEC 변경이 확정되기 때문이다.
`.claude/skills/tpx/SKILL.md` 에 그 한 줄을 더할 것을 제안한다 (아래 「기타」).
