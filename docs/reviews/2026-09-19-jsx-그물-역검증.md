# JSX 그물 역검증 — 여섯 자리를 부숴 봤다

2026-09-19 · 대상 `apps/admin/src/web/` 의 화면 조각 셋 (`Modal.tsx` · `SettingsPassword.tsx` · `Form.tsx`)

---

## 왜 했나

이 PR 이 화면 조각 셋에 자동 검사(그물)를 씌웠다. **셋 다 처음부터 초록이었다** — 코드가 이미 규칙을 지키고 있었기 때문이다.

**그런데 초록인 것과 무는 것은 다르다.** 검사가 아무것도 안 보고 있어도 초록이다.
앞선 작업에서 「열두 경로를 표로 돌렸는데 축을 하나 빼먹어 전부 통과」한 일이 실제로 있었다.

그래서 **일부러 코드를 망가뜨려 검사가 빨개지는지** 봤다. 이것을 mutation testing(멀쩡한 코드에 일부러 흠을 내서, 검사가 그 흠을 잡아내는지 보는 방식)이라고 부른다.
잡아내면 그 검사는 그 축을 실제로 보고 있다는 뜻이고, 못 잡아내면 초록불이 거짓말을 하고 있다는 뜻이다.

**한 번에 한 자리만 망가뜨렸다.** 부수고 → 검사를 돌려 빨간 것을 확인하고 → 편집으로 되돌리고 → 초록을 확인하고 → 원본과 똑같은지 확인했다. 그다음 자리로 갔다.

되돌릴 때 `git checkout` · `git restore` · `git stash` 는 쓰지 않았다. 부수기 전에 원본을 따로 복사해 두고 그것을 그대로 붙여 넣었다.

**같이 빨개진 7건 전부**

| 검사 이름 | 왜 |
|----------|-----|
| 라벨이 for 로 칸에 묶여 있다 | **직접 문 것.** `getAttribute('for')` 가 `null` |
| enum 은 드롭다운이고 선택 칸이면 고르지 않음이 맨 앞이다 | `칸찾기` 가 터짐 |
| boolean 은 예·아니오 두 낱말짜리 드롭다운이고 코드 낱말은 안 보인다 | `칸찾기` 가 터짐 |
| 글자를 치면 그 키와 값으로 onChange 가 불린다 | `칸찾기` 가 터짐 |
| 비밀값 칸은 타이핑할 때 글자가 점으로 보이는 칸이다 (SPEC §8.2) | `칸찾기` 가 터짐 |
| 꼬리표가 없어도 이름이 비밀값이면 가려서 받는다 (K9 2차 방어) | `칸찾기` 가 터짐 |
| 오류는 그 칸 아래에 뜨고 아무것도 비활성화하지 않는다 (SPEC §8.2) | `칸찾기` 가 터짐 |

## 우려 — 자리 6 의 진단 메시지

자리 6 에서 7건이 빨개지는 것 자체는 옳다. 그런데 그중 6건이 뱉는 메시지가 `SyntaxError: Invalid selector #` 다.
**「라벨이 칸에 안 묶여 있다」는 말이 어디에도 없다.** 앞으로 누가 실수로 `htmlFor` 를 지우면, 로그를 열고 7건 중 맨 위 하나를 찾아 읽어야 원인을 안다.

`칸찾기` 가 빈 `id` 를 먼저 보고 사람이 읽는 말로 던지게 하면 이 진단이 또렷해진다. 다만 **이것은 검사 코드를 고치는 일이라 판단이 필요하다.** 여기서는 제안만 적고 정하지 않았다.

지금 그물이 무는 것 자체는 증명됐으므로 급한 일은 아니다.
