## 치명

### B-3.5 — 실행자가 아직도 요청 본문에서 온다

어디:   `apps/admin/src/execution/routes.ts:28` · `apps/admin/src/execution/store.ts:177`
무엇:   `POST /api/runs` 가 `triggeredBy` 를 **요청 본문에서 받고**(없으면 `'admin'`),
        `test_run` INSERT 는 `triggered_by_name` 칸을 **아예 쓰지 않는다.**
왜 문제: §3.5 가 이름 붙여 금지한 것이다 — 「보내는 쪽이 정할 수 있으면 아무 이름이나 적을 수 있어
        증적이 증적이 아니게 된다」. 로그인을 붙여 놨는데 실행자는 여전히 화면이 적어 보내는 자유
        문자열이다. 게다가 이름 칸이 비어 있으므로 **앞으로 만드는 모든 실행이** 화면과 증적에서
        `실행자 미상 (인증 도입 이전)` 으로 나온다 (§8.6). 인증을 붙인 의미가 여기서 새 나간다.
        실제로 확인했다 — 정기 실행으로 만든 `test_run` 행의 `triggered_by_name` 이 비어 있다.
고칠 곳: **WS-B**. 세 줄이다.
  1. `execution/routes.ts` 의 `runBody` 에서 `triggeredBy` 줄을 **뺀다**
  2. 핸들러가 `req.user` 에서 가져온다 — 문(`auth/gate.ts`)이 모든 `/api` 앞에 서므로 여기 닿았으면 사람이 있다
  3. `CreateRunInput` 에 `triggeredByName` 을 더하고 `test_run` INSERT 의 컬럼 목록에 `triggered_by_name` 을 넣는다
  `req.user` 는 `{ username, displayName, role, services }` 다. 타입은 이미 전역에 실려 있어 import 가 필요 없다.
  같이 고칠 검사 둘 — `runs.test.ts:121`(본문에 실행자를 싣는다) · `runs.test.ts:164`(기본값 `'admin'` 을 단언한다)

**이 갈래가 고치지 않은 이유** — `apps/admin/src/execution/**` 는 WS-B 소유다 (CLAUDE.md §1.1).
킥오프의 «실행자는 로그인한 사람에게서 온다» 를 WS-F 가 할 수 있는 데까지는 했다 —
문이 `req.user` 를 실어 준다. 그것을 **읽는** 쪽이 남았다.

## 기타

### 1. SPEC 을 한 곳 고쳤다 — 판단이 필요하다

§9.2 가 «이 스크립트를 admin 안 어느 경로에 둘지는 공용 골격을 맡은 갈래가 정한다» 고 맡겨 둔 자리를
`scripts/*.ts` 로 채우고, 명령 줄 셋을 `node …js` 에서 `npx tsx …ts` 로 맞췄다.

**순수 JavaScript 로 두면 계정 만들기와 실행 만들기를 두 번째로 구현하게 된다.**
`run-scheduled` 는 `createRun` 과 `dispatch` 를 그대로 써야 하고, `add-user` 는 비밀번호 해시 형식을
그대로 써야 한다. 컨테이너는 이미 `npx tsx` 로 돈다(`Dockerfile` 의 `CMD`). SETUP 과 WORKSTREAMS 의
같은 줄도 맞췄다 (§2.7 ④).

### 2. SPEC 이 정하지 않은 자리를 셋 판단했다

1. **스캔(`POST /api/catalog/scan`)의 등급** — §7 의 등급 표에 이름으로 없다. 방식으로 갈라 `operator` 로 뒀다
2. **등급 부족의 오류 이름** — §7 은 403 만 정하고 이름을 안 준다. `{ error: 'FORBIDDEN', need: '<등급>' }` 으로 뒀다
3. **아이디 중복의 오류 이름** — §7 은 접두사 중복만 이름을 준다. `USERNAME_TAKEN` 으로 맞췄다

셋 다 LEARNINGS 에 적었다.

### 3. 닿지 못한 서비스 경계가 하나 있다

문은 `?service=` 와 실행 요청의 `tcId` 접두사로 서비스를 알아낸다. **`GET /api/runs/:runId` 처럼
번호만 들고 오는 요청은 걸러지지 않는다** — 그 자원이 어느 서비스 것인지는 실행 갈래만 안다.
문이 그것을 알려면 경로마다 자원→서비스 대응을 들고 있어야 하고, 그러면 갈아 끼울 자리가 하나가 아니게 된다.
병합 단계에서 각 갈래가 자기 조회에 `req.user.services` 를 한 줄 걸어 닫는 것이 맞다.
