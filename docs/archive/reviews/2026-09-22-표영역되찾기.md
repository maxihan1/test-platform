어디:    `docs/WORKSTREAMS.md:443` · `:458`
무엇:    계획 할 일 10 의 `files` 가 `docs/WORKSTREAMS.md` 를 적어 뒀는데 diff 에 없다.
         그리고 **실제로 낡은 줄이 있다** —

```
> ④ `DESIGN.md` 모달 규칙 일곱 중 다섯은 **아무 검사도 안 본다** (덮개·애니메이션·폭·색)
> 지금도 열려 있는 것은 … ④ 모달 규칙 다섯 …
```

         이번 PR 이 `styles.test.ts` 에 **폭과 높이 검사를 더했다.** 「아무 검사도 안 본다」가
         더 이상 참이 아니고, 열려 있는 것은 다섯이 아니라 넷이다.
왜 문제: 킥오프는 **세션이 SPEC 보다 먼저 읽는 자리**다 (`CLAUDE.md §2.7 ④`).
         여기가 틀리면 다음 사람이 「폭은 아무도 안 보니 내가 검사를 만들어야겠다」로 읽고
         **이미 있는 검사를 또 만든다.** 반대로 「다섯이 열려 있다」를 보고 남은 일의 크기를 잘못 센다.
         C5 가 생긴 이유가 정확히 이것이다 — 계획이 「고치겠다」고 적은 자리를 아무도 안 고쳤는데
         검사가 전부 초록이었다.
고칠 곳: 이 PR. **자기검사가 찾아 그 자리에서 닫았다** — 아래 「검사자가 고친 것」 절 참조.

### H2 — `DESIGN.md` 는 넓은 상자가 **셋**이라는데 코드는 **둘**이다 [재발 아님, 이번에 처음 잰다]

어디:    `docs/DESIGN.md:326` vs `apps/admin/src/web/RunPickModal.tsx:150`
무엇:    `DESIGN.md` — 「넓은 것 셋은 1400px 이다 — **여러 건 실행 모달**(2026-09-21, 값을 접지 않고
         다 펴야 해서), 그리고 ②의 상자 둘(2026-09-22)」.
         그런데 `넓게` 프롭을 실제로 주는 곳은 **둘뿐**이다 —

```
grep -rln "넓게" apps/admin/src/web/*.tsx | grep -v test
→ CaseDetail.tsx · RunResultModal.tsx · Modal.tsx(프롭 정의)
```

         `RunPickModal.tsx:150` 은 `<Modal 제목=… onClose=… 버튼=…>` 로 부르고 **`넓게` 를 안 준다.**
         여러 건 실행 모달은 지금 480px 이다.
왜 문제: 「값을 접지 않고 다 펴야 해서」가 그 상자를 넓게 만든 근거인데 **그 근거가 코드에 안 걸려 있다.**
         케이스를 여러 건 고르고 실행을 누르면 입력값이 480px 안에 다 들어가야 하는데,
         DESIGN.md 만 읽은 사람은 그게 이미 넓다고 믿는다.
         다음에 이 상자가 좁다는 지적이 오면 **문서가 「이미 고쳤다」고 거짓말한다.**
**★ 이 PR 이 그 틀린 말을 되풀이했다.** `styles.css` 의 `.modal.wide` 주석에
         「상자 셋 — 케이스 상세 · 실행 결과 · **여러 건 실행 확인**」 이라고 적었고
         커밋 메시지도 「셋 다 넓어진다」라고 적었다. **재 보지 않고 문서를 믿었다** —
         `docs/LEARNINGS.md` 220줄의 「잰 것과 짚은 것」 그대로다.
고칠 곳: **이 PR 은 사실을 적는 데까지만 한다.** `RunPickModal` 에 `넓게` 를 주는 것은
         화면 동작 변경이고 이번 범위(표 영역 되찾기) 밖이다 — 게이트 2 에서 사람이 정한다.
         둘 중 하나여야 한다. ① `RunPickModal` 에 `넓게` 를 준다 ② `DESIGN.md` 를 「둘」로 고친다.

`reporting/generate.test.ts` 가 쓰는 중인 `test_run` 을 다른 검사 파일의 정리 구문이 지웠다.

## 기타 — 계획에서 뺀 것 하나 (F10 과 맞물린다)

계획 할 일 1 의 「좁은 화면에서 실행 기록 표머리 살리기」를 **안 했다.**

`docs/spec/도메인/실행.md:302` 는 「좁은 화면에서 표머리를 감추지 않는다」에 이어
「줄이 세로로 접히면 **표머리 대신 줄마다 라벨을 붙인다**」고 적는다.
좁은 화면에서 줄은 이미 세로로 접히므로(`styles.css` 620px 블록) **머리를 격자로 되살리면
칸이 안 맞아 오히려 오해를 준다.** 명세가 요구하는 것은 줄마다 라벨이고,
그것은 `RunList.tsx` 와 다국어 표까지 걸려 계획이 CSS 한 줄로 잡은 것보다 크다.

**잘못된 고침을 조용히 넣지 않았고 범위도 조용히 안 늘렸다.** 게이트 2 에 싣는다.
그 자리는 **이 PR 이 만든 것이 아니라 원래 어긋나 있던 것**이다.
