### 기타(결정 6 · §8.11 「화면 글자」 표) — 결과 화면이 모킹 구간 안의 API 호출 단계를 「모킹된 채 실행했다」고 적는다
어디: apps/admin/src/web/ScenarioResultPart.tsx:49 · 68~70 (`part.mocks.length > 0 && part.kind !== 'mock'`)
무엇: 러너는 단계마다 그때 걸려 있던 모킹 무늬를 `mocks` 에 싣는다. API 단계도 예외가 아니다(apps/runner/scenario/parts.ts:222). 화면은 모킹 켜기 단계만 빼고 전부에 「모킹이 적용된 상태로 실행했습니다 — 무늬」를 붙인다. 그런데 API 호출 단계는 `지금창.fetch` 로 진짜 서버에 간다(같은 파일 162줄)
왜 문제: 결정 6 은 「API 호출 부품만 모킹을 안 거친다」고 했고, §8.11 표는 그 단계의 표시를 `모킹되지 않음` 으로 정했다. 지금 화면은 정반대로 적는다. 진짜 서버에 상태를 심은 단계가 모킹된 것으로 읽힌다. 결정 6 이 「가장 나쁜 실패」로 꼽은 바로 그 착각이다. 검사 fixture 의 API 단계는 `mocks: []` 라서(ScenarioResult.test.tsx 「안돈」) 이 경로를 아예 안 밟는다. A7 과 같은 꼴로, fixture 에 늘 이상적인 값만 넣었다
고칠 곳: WS-E(ScenarioResultPart.tsx). API 단계에는 세로선과 함께 `모킹되지 않음` 칩과 `이 단계의 API 호출은 모킹되지 않습니다` 를 쓴다. 검사에 `mocks` 가 찬 API 단계를 더한다. 증적의 「모킹 구간」 표시(리포팅 §8.4)에도 같은 구분이 필요한지는 할 일 21 의 같은 규칙 찾기에서 본다
체크리스트 제안: F 절에 「모킹 구간 안의 API 호출 단계를 모킹된 것처럼 적지 않는가」 한 줄

### 기타(§8.11 「서버 · 러너가 만들어 화면에 그대로 뜨는 문장」 · §7 「실행 결과를 적는 규칙」) — 결과 화면이 실패가 아닌 단계의 오류 문장을 버린다
어디: apps/admin/src/web/ScenarioResultPart.tsx:111~113 (`part.status !== 'FAIL' || …`)
무엇: 오류 문장은 `FAIL` 단계에만 나온다. `NA` 로 닫힌 단계의 사유는 이 화면 어디에도 안 뜬다. 시간 초과(`TIMEOUT`) · 재기동 복구(`ABORTED`) · 「러너가 거절했다: …」 · 「러너에 닿지 못했습니다」 · 「러너가 이 부품 결과를 돌려주지 않았다」 · 「결과를 저장하지 못했다: …」가 모두 그렇다. 글자로 바뀌어 보이는 것은 `NOT_RUN` → `– 실행 안 됨` 하나뿐이다
왜 문제: 러너가 거절하면 모든 단계가 사유 없이 「미실행」 배지만 단 결과가 된다. 판정이 왜 없는지 화면에서 알 길이 없다. §8.11 은 이 문장들(`러너가 이 부품 결과를 돌려주지 않았다` 등)을 「화면이 받은 글자를 그대로 보인다」고 적었다. 케이스 쪽 항목 상세(ItemDetail.tsx 50~55줄)는 판정과 상관없이 `실행이 멈춘 사유` 로 보여 준다. 계약 ②(줄 `verdict`)를 더한 까닭이 「실패와 시간 초과를 가른다」였는데, 결과 화면에서는 시간 초과라는 말이 사라진다
고칠 곳: WS-E(ScenarioResultPart.tsx). `NOT_RUN` 이 아닌 `NA` 의 `error.message` 도 보인다. `TIMEOUT` · `ABORTED` 같은 코드 글자를 사람 말로 바꿀지는 §8.11 「화면 글자」 표에 줄이 없다. 「명세 승인 필요」로 게이트 2 에서 정한다
