## ★ 치명 1 — 실행 등급 아무나 「맥인 척」 집어 병합될 PR 을 바꿔치기할 수 있었다

**이 PR 이 지키려던 단 하나의 불변식이 그대로 깨져 있었다.**

내가 만든 방어(`claimed_by` 대조)는 **「A 가 집은 행에 B 가 쓰는 것」**만 막았다.
**B 는 그냥 먼저 집으면 됐다 — 경계가 아니라 경주였다.**

```
평범한 operator 가  →  맥보다 먼저 집는다 (줄은 서비스마다 하나, 가장 오래된 것부터)
                    →  finish 에 자기가 고른 pr_url 을 싣는다
admin 이 「머지할까」  →  그 사람이 고른 PR 이 병합된다
```

사람 게이트는 **「이 요청을 머지할까」만 묻고 「이 주소가 그 요청이 만든 것 맞나」는 아무도 안 본다.**

**왜 생겼나** — 명세가 「집어 가는 쪽은 맥 하나다」를 **전제로만** 적었고 서버가 그 전제를 안 지켰다.
맥은 일반 `operator` 계정이라 다른 `operator` 와 구분되지 않았다.

**막은 것 — 겹치는 셋**

| | 무엇 |
|---|---|
| ⒜ | **집기·단계·사진·끝내기 넷을 정해진 계정 이름에만 연다** (`AUTHORING_AGENT_USER`). **비면 아무도 못 집는다** (`scope.ts` 의 「모르면 막는다」) |
| ⒝ | `pr_url` 이 **그 서비스의 저장소 주소 + `/pull/<숫자>`** 모양인지 본다. 다른 저장소도, 명령줄에 위험한 글자도 막힌다 |
| ⒞ | `claimed_by` 대조는 그대로 둔다 — 셋이 겹쳐야 한 겹이 빠져도 나머지가 문다 |

## ★ 치명 2 — 사진이 서버를 다시 띄우면 사라졌다

`SCREENSHOT_ROOT` 라는 **새 설정값을 만들었는데 볼륨에 안 묶여 있었다.**
배포에서 살아남는 자리는 `PLATFORM_ARTIFACTS_DIR`(`/artifacts`) 하나뿐이다.

**안 고쳤으면** — 운영에서 맥이 올린 사진이 컨테이너 안 임시 공간에 떨어져 **재배포마다 통째로 사라지고**,
다음 PR 의 화면은 원래 자리에서 찾으므로 **처음부터 한 장도 못 띄운다.**
그 세션은 「사진이 왜 안 뜨지」로 시간을 쓰는데 원인이 자기 코드가 아니다.

**게다가 바로 위 주석이 반대로 말하고 있었다** — 「러너 스크린샷과 **같은 볼륨**을 쓴다」. 아니었다.
**검사는 초록인데 운영만 틀리는 모양**이었다 (검사가 임시 폴더를 따로 지정한다).

→ **새 설정값을 없애고** `PLATFORM_ARTIFACTS_DIR` 아래로 폴더만 갈랐다.

## ★ 치명 3 — 검사가 1회는 통과하고 2회부터 깨졌다

**연속 3회 규칙(`spec-review` G3)이 잡으라는 바로 그 경우다. 1회만 돌렸으면 못 봤다.**

**원인은 내 검사였다** — 만든 서비스 넷(`XWA`·`XWAX`·`XWAR`·`XWARX`)을 **안 치웠다.**
다른 검사들이 「지금 살아 있는 서비스」를 훑기 때문에 **2회차부터 다른 세상을 본다.**

```
1회차  서비스 넷을 만든다        → 통과
2회차  그 넷이 이미 있는 채 시작  → 7건 실패
```

→ 정리 구문에 **서비스 삭제**를 더했다. **`LIKE` 로 넓히지 않고 자기 번호로만 지운다** —
`XWAR` 이 `XWA` 로 시작하므로 넓히면 남의 fixture 를 실행 도중에 지운다 (`XBR` 선례).

## ★ 남은 판단 하나 — CI 가 빨간불로 뜰 수 있다

DB 를 붙인 순간 **그동안 건너뛰던 검사 19개 파일이 한꺼번에 돌기 시작한다.**
검토 시점에 그중 일부가 흔들렸는데, **그 흔들림의 주된 원인(치명 3, 내가 남긴 서비스)은 닫았다.**
**다만 CI 는 같은 명령을 세 번 치므로 한 번만 흔들려도 전체가 빨간불**이고,
빨간불이면 이 PR 뿐 아니라 **그 뒤 모든 PR 이 못 들어간다.**

게이트 1 에서 사용자가 정한 조건이 이것이다 —
**「남의 검사가 빨개지면 고치려 들지 말고 그 자리에서 멈추고 보고한다.」**
그래서 **게이트 2 요약에 싣는다.**
