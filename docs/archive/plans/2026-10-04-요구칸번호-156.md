# 요구 칸 · 케이스 번호를 코드로 (8·9번 4단계)

등급: 3 · 갈래: WS-작성 · 2026-10-04

## 도메인 정리

작성 에이전트의 자식이 쓰는 요구사항 표(`docs/cases/<접두사>.md`)에서 **케이스 경계와 tcId 를 AI 대신 코드가 정한다.** 계약(공유 타입 · 러너 HTTP · DB 칸 · Admin API)은 그대로다. tcId 꼴(`<접두사>-(UI|FN)-NNN`)도 그대로다.

| 무엇 | 지금 | 바꾼 뒤 |
|---|---|---|
| 케이스 경계 | AI 가 「같이 확인하면 좋겠다」 싶은 줄을 묶는다(R15) | **칸 = 요구(그 줄 출처의 원장 번호 가운데 원장 차례가 가장 앞) × 갈래(축 `UI` → UI, 정상 · 경계 · 예외 → 기능) × 축.** 같은 칸 줄은 한 케이스다 |
| 번호 | AI 가 쓴 차례대로 | UI = 원장 차례 `i`, 기능 = `(i−1)×3 + {정상 1 · 경계 2 · 예외 3}`. 기준(main) 표에 같은 칸이 있으면 그 번호를 물려받는다. 겹치거나 999 를 넘거나 한 칸이 10줄을 넘는 둘째 덩이 · 원장 번호 없는 줄은 뒤로 이어 매긴다 |
| 「다음 요청」 제외 | 자식이 마음대로 쓴다 | 작성 에이전트의 자식은 **새로 못 쓴다** — 기준 표에 이미 있던 줄만 인정(「사람이 뺌」과 같은 장치) |
| 원장 없음(화면만 · PDF · 피그마) | AI 번호 | 그대로 — 칸을 정할 원장이 없다 |
| 사람 세션(`/tpx-cases`) | R15 | 그대로 — 명령은 쓸 수 있지만 강제하지 않는다 |

재사용 — `scripts/authoring-ledger-check.ts` 의 `표읽기` · `원장대조` · `사람이뺀번호`, `scripts/authoring-ledger.ts` 의 `번호찾기`, `scripts/authoring-conflicts-apply.ts` 의 `다음번호` · `번호열머리`, `apps/admin/src/catalog/rules.ts` 의 `TCID` · `tcId종류`, `scripts/authoring-ledger-io.ts` 의 `기준읽기` · 원장 사본 쓰기.

## 왜

같은 기획서(MKT)로 처음부터 두 번 작성하니(1차 #137 · 2차 #144) 케이스가 148 · 227개로 갈렸고 측정(#154)은 「같은 번호 같은 요구 148 중 7 · 묶인 짝 겹침 27.9% · 한쪽만 덮은 번호 0 · 18」이었다.
사용자 정의(2026-10-04) — 같은 기획서를 100번 돌려도 **문장은 달라도 커버리지 · 맥락이 비슷**해야 한다.

**실측 — 두 표의 실제 줄에 이 규칙을 적용했다**(임시 스크립트, 원장 차례는 2차 표에 처음 나온 차례로 근사).

| 숫자 | 지금 | 이 규칙 |
|---|---|---|
| 케이스 수(1차 · 2차) | 148 · 227 | 233 · 305 |
| 같은 번호 같은 요구(#154 정의) | 148 중 7 | 두 실행에 다 있는 번호 212 중 212 — 번호를 요구에서 계산하므로 정의상 100% |
| 두 실행이 다 덮은 요구의 칸 겹침(요구 · 갈래 · 축 자카드) | 70.9% | 70.9% — 표 줄에서 나오므로 번호 규칙과 상관없이 같다 |
| 가장 큰 번호 · 10줄 넘는 칸 | — | 514 · 0 |

- **AI 가 「전제 · 조작이 같은 줄」끼리 묶지 않는다** — 1차 케이스 148 중 89개가 서로 다른 조작 여럿을 한 흐름으로 이었다. R15 글자 그대로를 코드로 옮기면 312개로 쪼개져 오히려 흔들린다. 그래서 칸을 원장 번호로 잡는다
- **UI · 기능은 따로 나오는 게 맞다**(사용자 확인 요청) — 두 표 모두 축 칸과 갈래(tcId)가 어긋난 줄 0. 한 요구에 둘 다 있는 경우 44 · 73개, 결과 문장이 80% 넘게 닮은 UI-기능 짝 2 · 3개였고 그마저 「처음에는 눌리지 않는다」(UI) ↔ 「약관 하나만 동의하면 눌리지 않는다」(기능)처럼 다른 확인이다
- **1차가 뺀 18개는 AI 가 정한 범위다** — 「관리자 비밀번호 없음」 9(지금 규칙은 보류 케이스) · 「선택 요구 — 필수를 먼저 덮었다」 9. 2차는 0
- **남는 흔들림 70.9% 는 축 고르기다** — 요구마다 예외 · 경계를 만들지 말지(R18)는 여전히 AI 판단이다. 이 PR 은 그것을 줄이지 않는다. 측정에 「칸 겹침」을 더해 다음 단계 재료로 남긴다

**대가 — 사용자에게 알렸다(2026-10-04).** 케이스 +34~57% · 비싼 조작(결제 · 가입)을 칸마다 따로 함(출처 칸에 번호 여럿을 적으면 첫 번호 칸으로 모이는 길은 남는다) · 기능 칸 번호는 요구 333개까지 · 화면만 작성(CDY)은 안 바뀜 · 한 칸 10줄 넘으면 둘째 덩이는 뒤 번호.
