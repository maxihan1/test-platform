### 주의 1 — 칸은 아홉이 아니라 열이다 (두 렌즈 공통)
계약 블록 칸은 test_case 2 · run_item 1 · service_env 2 · authoring_request 3 · authoring_asset 2 = 10. 숫자를 믿고 검사를 쓰면 한 칸이 빠져도 초록이다. 검사는 계약 블록 칸 목록을 배열로 그대로 옮기고, 계획의 「아홉」은 지운다.

### 주의 2 — CHECK 검사 빈 곳 (두 렌즈 공통)
`compare=false` 인데 `start_url` 만 찬 경우, `kind='MERGE'` 인데 `compare=true` 인 경우가 없다. SQL 에서 조건 하나를 빠뜨려도 통과한다. 두 경우를 더하고 새 CHECK 에 이름을 붙인다(20260923 되돌리기 선례).

### 주의 3 — migrate:down 이 에이전트 산출물을 입력처럼 남긴다 (eng)
`role` 칸을 지우면 `MARKED`·`REVERSE_SPEC` 행이 사람이 넣은 자료로 보이고, 에이전트가 자기 역기획서를 기획서로 다시 읽는다. 칸을 지우기 전에 `DELETE FROM authoring_asset WHERE role <> 'INPUT'`.

### 주의 4 — 빈 글자 `unconfirmed: ''` 처리 미정 (eng)
명세는 「비면 확정」. 빈 글자도 키를 빼고 검사 하나로 고정한다(K11 이 빈 글자를 위반으로 잡는 것은 WS-A 몫).

### 주의 5 — WORKSTREAMS 에 적을 PR 번호는 실제로 확인 (ceo, 참고)
#74 로 확인됐다.

### 참고 (범위 밖)
`apps/admin/src/settings/store.ts:71` 이 저장마다 service_env 줄을 지우고 다시 넣어 계정 칸이 지워진다. 지금은 쓰는 곳이 없어 해가 없고 WS-F 후속 항목에 이미 있다.

### 통과한 것
- 범위 — 계약 둘만, 쓰는 코드는 후속
- CHECK 조건·칸 타입·기본값이 계약 블록 제안 그대로
- 기존 RERUN·MERGE 행은 `compare` 기본 false 라 새 CHECK 에 안 걸린다
- `login_password` 는 grafana_ro 권한 없는 표, `run_item.unconfirmed` 는 기존 권한을 따른다
- 자기 참조 FK 와 CASCADE 충돌 없음 · fixture `XRC` 새것 · `skipIf` 관례 · K11 은 WS-A 로 남김
