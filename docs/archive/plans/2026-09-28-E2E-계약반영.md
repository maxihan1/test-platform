등급: 3 · 갈래: 없음(계약 반영 단위) · 2026-09-28

## 도메인 정리

- 계약 둘. Shared Kernel 타입(`packages/kit/src/types.ts`)과 DB 표(`db/migrations/`)
- 정본은 [공통/3-공유계약 「E2E 시나리오 타입」](../spec/공통/3-공유계약.md)과 [공통/4-데이터모델 「E2E 시나리오 표」](../spec/공통/4-데이터모델.md) 계약 블록이다. 둘 다 PR #97 게이트에서 승인됐고 지금은 `상태: 대기` 다
- **kit 블록은 타입과 런타임(시나리오 모드 — 본체 꺼내기 · `RunScope` 꿰기 · 제목으로 건너뛰기)을 한데 묶었다.** 런타임은 WORKSTREAMS 📐 E2E 2번(KIT + WS-C 러너) 몫이다. 이번에는 타입만 넣고 블록을 둘로 나눈다
- 표를 **읽고 채우는 코드는 이번 범위가 아니다.** 서버(WS-B) · 증적(WS-D) · 화면(WS-E)은 갈래별 후속이다

## 왜

뒤 갈래가 전부 이 두 계약을 읽는다. 타입과 표가 먼저 서야 러너와 서버가 주고받을 수 있다(WORKSTREAMS 📐 E2E 권장 순서 1번).

옛 코드가 새 칸에 깨지지 않는지 실측했다 — `apps/admin/src` 운영 코드에 `SELECT *` 와 zod `.strict()` 가 없다. `test_run.kind` 는 기본값 `'CASE'` 라 기존 INSERT 는 그대로 선다.

### 주의 1 — 디바이스(`platform`)를 어느 표도 박제하지 않는다 (ceo · 계약)
`platform` 은 `scenario` 에만 있고 `PUT /api/scenarios/:id` 가 바꿀 수 있다. 버전·실행 어디에도 없어 바꾼 뒤에는 옛 실행이 어느 디바이스였는지 모르고, 「이 버전으로 되돌리기」가 디바이스를 안 되돌린다(리포팅 「그날 모양」). 고칠 것 — `platform` 을 `scenario_version` 으로 옮긴다. 승인된 계약을 바꾸는 일이라 게이트에서 사용자가 정한다.

### 주의 2 — 계약 블록 나누기에 문구 배분이 비었다 (ceo · eng)
「한 글자도 안 바꾼다」는 불가능하다 — 대상·현재·영향 줄이 섞여 있다. 문장 단위로 나눠 담고 이유는 두 벌. 「`ScenarioPart` 넷」은 「타입 넷」의 오기.

### 주의 3 — `migrate:down` 이 `evidence_document` 를 빠뜨렸다 (ceo · eng)
WS-D 가 시나리오 증적을 만든 뒤에는 `DELETE test_run` 이 FK 로 막힌다. 순서 — `evidence_document`(시나리오 몫) → 부품·절차 표 DROP → `test_run` SCENARIO 행 → 칸 셋 → `scenario_version` → `scenario`.

### 주의 4 — fixture 정리 순서와 상태 (eng)
`scenario_run_part.run_id` 에 CASCADE 가 없다 — 부품 → `test_run` → `scenario_version` → `scenario` → `service` 순. `test_run` 은 자기 `service_id` 로 지우고 `status='FINISHED'` 로 넣는다(`recoverRunning()` 이 표 전체를 훑는다).

### 주의 5 — 칸 검사가 이름만 본다 (eng)
`NOT NULL`·기본값·타입이 틀려도 초록. 칸마다 `(이름, data_type, is_nullable, column_default)` 를 정본에서 옮겨 견준다.

### 주의 6 — 빠진 제약 검사 (eng)
`platform` CHECK · 부품 `kind` CHECK · `scenario_version` 기본 키 · 절차 `UNIQUE` · FK 다섯 · `ON DELETE CASCADE` · 박제 넷 중 나머지 셋. ⑨ 도 제약 이름으로 맞춘다. `pg_constraint` 목록을 통째로 견주는 편이 짧다.

### 주의 7 — ⑥ 은 제약 둘이 동시에 걸린다 (eng)
기본값이 「올바른 case 부품」인 넣기 도우미로 한 칸만 망가뜨린다.

### 주의 8 — 타입 검사 파일이 `noUnusedLocals` 에 걸린다 (eng)
값을 배열에 모아 `it` 하나에서 쓴다. RED 는 typecheck 기준.

### 주의 9 — Grafana 권한 반대쪽 (eng)
새 표 넷은 `has_any_column_privilege = false`, `test_run.kind` 는 `has_column_privilege = true`.

### 주의 10 — 제약 이름은 정본 SQL 과 글자가 다르다 (eng)
마이그레이션 머리 주석에 「표 단위 CHECK 둘에만 검사용 이름을 붙였다」 한 줄.
