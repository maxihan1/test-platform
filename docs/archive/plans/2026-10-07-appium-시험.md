## 사용자 결정 (2026-10-07)

- 첫 대상은 **Android**. iOS 는 Android 길이 뚫린 뒤
- 시험은 에뮬레이터가 아니라 **USB 로 연결한 실기기**

## 구조 — 9/23 Q9 의 모양 그대로 됐다

Playwright Test 를 실행기로 두고 WebdriverIO 연결을 fixture 로 넘긴다. 케이스가 `page` 를 안 받으면 Playwright 는 브라우저를 띄우지 않는다.

```ts
const test = base.extend<{ driver: WebdriverIO.Browser }>({
  driver: async ({}, use, testInfo) => {
    const driver = await remote({ hostname: '127.0.0.1', port: 4723, capabilities: {
      platformName: 'Android', 'appium:automationName': 'UiAutomator2',
      'appium:udid': 'R3CR10TCVCD', 'appium:app': '<apk 경로>',
      'appium:appPackage': 'com.saucelabs.mydemoapp.rn', 'appium:appActivity': '.MainActivity',
    } });
    try { await use(driver); }
    finally {
      const png = Buffer.from(await driver.takeScreenshot(), 'base64');
      await testInfo.attach('screenshot', { body: png, contentType: 'image/png' });
      await driver.deleteSession();
    }
  },
});

test('장바구니 담기 — 상품 하나를 담으면 장바구니 수가 1', async ({ driver }) => {
  await (await driver.$$('~store item'))[0].click();
  await driver.$('~Add To Cart button').click();
  expect(await driver.$('~cart badge').$('android.widget.TextView').getText()).toBe('1');
});
```

`~` 는 accessibility id(Android 에서는 `content-desc`)로 찾는다는 뜻이다. 이 앱은 화면마다 이름표가 달려 있어 좌표나 화면 글자를 쓰지 않았다.

### d. 강제 종료 — 러너 방식 그대로 흉내 냈다

러너는 중단할 때 프로세스 그룹 전체에 SIGKILL 을 보낸다(`apps/runner/src/kill.ts:10`). fixture 의 연결 닫기가 돌 틈이 없다.

| 경우 | 결과 |
|------|------|
| 끄고 그대로 둔다 | 연결이 남았다가 **마지막 명령에서 60초 뒤** 저절로 닫힌다(Appium `newCommandTimeout` 기본값). 실측 — 마지막 명령 00:21:24 → 닫힘 00:22:24 |
| 끄자마자 다음 실행 | **막히지 않는다.** 새 연결이 「이 기기는 다른 연결이 쓰는 중」 경고 한 줄을 남기고 기기를 가로챈다. 먼저 연결은 기록 없이 사라진다(그 번호로 닫으면 404) |
| 정상으로 끝남(비교) | fixture 가 연결을 닫는 그 자리에서 풀린다 |

- 로컬 한 대에서는 중단이 해롭지 않다
- **위험은 겹침이다.** 같은 기기에 연결 둘이 겹치면 뒤 것이 앞의 것을 경고 한 줄로 가로채고, 앞 실행은 이유를 모르는 실패로 끝난다.
  지금 「동시 실행 2」는 전역이라(`apps/admin/src/execution/dispatcher.ts`) 기기를 구분하지 않는다
- 디바이스 팜에서는 끊긴 연결이 60초 동안 기기를 잡고 있을 수 있다. 러너가 연결 번호를 쥐고 있다가 중단 때 직접 닫으면 기다릴 이유가 없다 — **중단 경로에서 직접 닫는 것은 이번에 재지 않았다**

### e. 화면 읽기 — 같은 첫 화면(상품 목록)을 두 도구로

| | Appium `getPageSource` | mobilecli `dump ui` (기본) | mobilecli `dump ui --format raw` |
|---|---|---|---|
| 크기 | **78,545자** | 13,686자 · 공백 빼면 **6,960자** | 45,060자 |
| 요소 | 111개 | 62개 | Android 기본 구조 그대로 |
| 담긴 것 | 전부 | 종류 · 이름표 · 글자 · 위치 | 전부(resource-id 포함) |
| 시간 | 연결이 열려 있어야 한다 | 2.6초, Appium 연결 없이 | 2.7초 |

- 이름표(content-desc)는 두 도구가 **완전히 같다** — 한쪽에만 있는 것 0개
- 토큰을 글자 수 ÷ 4 로 어림하면 Appium 약 2만, mobilecli 기본 약 1,700. **약 11분의 1**
- mobilecli 는 폰에 앱을 따로 깔지 않았고 상주 프로세스도 남기지 않았다
- 9/23 Q13 의 판단(mobilecli)이 실측으로 맞았다. **조건이 하나 붙는다** — 기본 형식에는 resource-id 가 없다.
  이름표 없이 resource-id 만 쓰는 앱은 raw 를 걸러 읽어야 한다

## 시험하다 걸린 것 — 2단계 구현이 같은 데서 안 막히게

- **Appium 3 은 열린 연결 목록을 기본으로 안 준다.** `GET /appium/sessions` 는 보안 기능 `session_discovery` 를 켜야 답한다. 이번엔 서버 로그로 판단했다
- **연결이 닫힐 때 남는 로그가 경로마다 다르다** — 정상 닫기 `Removing session <번호>`, 시간 초과 `Removing session '<번호>'`(따옴표), 가로채기는 아무 줄도 안 남는다.
  처음에 따옴표 경로를 놓쳐 「3분 넘게 안 풀린다」고 잘못 읽었다. 로그로 감시하면 셋을 다 봐야 한다
- adb 는 `~/Library/Android/sdk/platform-tools` 에 있는데 PATH 에 없다. mobilecli 는 adb 가 PATH 에 있어야 한다

## 1단계(계약)에 넘길 것

1. **기기 잠금** — 기기마다 한 번에 연결 하나. 전역 「동시 실행 2」와 따로 기기 단위로 기다리게 한다
2. **실행 위치** — 로컬(맥에 USB) / 디바이스 팜(접속 방식 확인 필요). 케이스에는 기기 「종류」만 적고, 어느 기기 · 어느 위치인지는 실행 때 고르는 쪽을 1단계 의견으로 낼 예정
3. **중단 처리** — 러너가 연결 번호를 쥐고 중단 때 닫는다. 안 하면 기기가 60초 묶인다
4. **제한 시간** — 로컬은 지금 기본 30초로 충분. 팜에서 다시 잰다
5. **화면 읽기 도구** — mobilecli 기본 형식. 새 도구라 저장소에 들일 때 승인(CLAUDE.md §3)
6. **증적 스크린샷** — `capture()` 를 driver 스크린샷으로 바꾼다. 한 장에 약 0.5MB
7. **앱 파일 자리** — apk 를 어디 두고 실행에 어떻게 넘길지. 9/23 Q9 「환경마다 다른 앱 파일을 둘 자리가 없다」가 그대로 남아 있다
8. **코드에 박힌 값** — 「desktop/mobile」이 34줄 · 23파일에 박혀 있다(9/23 의 약 20곳에서 늘었다). 정의는 `packages/kit/src/types.ts:4`.
   시나리오 표는 DB 가 두 값만 받는다(`db/migrations/20260928000004_scenario.sql:21`)
