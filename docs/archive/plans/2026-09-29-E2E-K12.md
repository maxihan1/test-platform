## 왜

시나리오는 건너뛸 절차를 **제목으로** 지목한다(러너 PR #100). 제목이 겹치면 하나를 풀다 둘을 건너뛰고,
둘째가 「확인」이면 막는 판정까지 사라진다. K12 가 CI 에 서야 서버(4번)가 제목을 열쇠로 믿을 수 있다.
판별 함수는 서버가 조립 때 `skippable` 이 아닌 건너뛰기를 400 으로 막는 근거다.

**판별 기준 (명세 글자 그대로)**
- 절차 = 소스 순서대로 만나는 `test.step(...)` 호출. 제목은 첫 인자가 문자열 리터럴일 때만(아니면 K6 이 잡는다)
- 판정 = 그 절차 본문 안의 `verify(...)`. **중첩 절차 안의 판정은 가장 안쪽 절차 것**이다
- `blocker` 판정 = `verify` 넷째 인자가 객체 리터럴이고 `blocker: true`
- `skippable` = 판정 0개 **그리고** 바로 다음 절차가 `blocker` 판정을 가진다
- `usesRequest` = `test(spec, async ({ request, ... }) => …)` 의 첫 매개변수 구조 분해에 `request` 가 있다.
  `page.request` 는 따지지 않는다 — 명세가 「케이스의 API 직접 호출(`request`)」이라 적었다
- K12 비교는 **글자 그대로** — 러너가 제목을 글자 그대로 맞춘다

### 주의 1 — 같은 절차가 반복문 안에 있으면 K12 가 못 본다
글자로 제목이 하나여도 `for` 안의 `test.step('담는다', …)` 는 실행 때 여러 번 돈다. 러너는 `skip.has(title)` 로 맞추므로(`packages/kit/src/runtime/step.ts:94`) 하나를 풀면 전부 건너뛴다.
지금 케이스 중에 그런 모양은 없다. **고칠 것** — 반복문·함수 안의 `test.step` 은 「만들기」로 치지 않는다(`skippable: false`). K12 를 넓히지는 않는다 — 반복은 정당한 쓰임이다

### 주의 2 — 도우미 함수 안의 `verify` 는 판정 0개로 보인다
절차 본문이 도우미를 부르고 그 안에서 `verify` 하면 소스상 판정 0개라 「만들기」로 잘못 잡힌다. 건너뛰면 그 판정이 사라진다.
지금 케이스에 도우미 함수는 없다(`grep` 0건). **고칠 것** — 판정 0개 판단을 「본문에 `verify` 도 없고, 식별자가 아닌 멤버 호출(`page.x()`) 밖의 맨 함수 호출도 없다」로 좁히거나, 한계를 판별 함수 머리 주석에 적는다. 앞쪽이 안전하다(틀리면 건너뛰기를 못 할 뿐)

### 주의 3 — `blocker` 를 변수로 넘기면 못 알아본다
`verify(…, opts)` 처럼 넷째 인자가 객체 리터럴이 아니면 blocker 가 아닌 것으로 본다. **안전한 쪽으로 틀린다**(건너뛰기를 못 할 뿐) — 고칠 것 없음, 검사 하나로 그 방향을 못 박는다
