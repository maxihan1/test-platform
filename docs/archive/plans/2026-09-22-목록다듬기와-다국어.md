## 왜

화면을 실제로 쓰면서 나온 지적 12건이다. 셋으로 갈린다.

**① 목록이 표로 안 읽힌다** — 컬럼 이름이 없어 각 칸이 무엇인지 모른다. 케이스 목록·실행 기록 둘 다 그렇다.
파라미터 입력칸이 케이스명 *아래* 붙어 있어 한 줄이 두 덩어리로 보인다.

**② 「열렸다」가 안 느껴진다** — `상세` 는 줄 아래로 펼쳐질 뿐이고, `결과 보기` 는 반대로
화면을 통째로 갈아타 보던 자리와 검색 조건을 잃는다.

**③ 글자가 만든 사람의 말이다** — 「도는 중」·「끝남」·「실패 섞임」·「기록 없음」.

여기에 **사이드바의 파란 네모와 `DEMO-` 가 무엇을 뜻하는지 화면만 봐서는 모른다**는 지적이 붙었다.
둘 다 걷고 남는 서비스 고르개를 제대로 만든다.

**다국어는 이 참에 같이 한다.** 어차피 화면 글자 대부분을 건드리므로 나중에 하면 같은 파일을 두 번 고친다.
사용자가 「전 화면 한 번에」를 골랐다.

### 다국어 설계 — 키를 한국어 원문으로 쓴다

**표를 한 벌만 둔다.** `en` 표가 `한국어 원문 → English` 를 담고, `ko` 는 키 자체가 답이다.

```
t('진행 중')  →  ko: '진행 중' (키 그대로)  ·  en: 'Running' (표에서)
```

- 표가 **둘이 아니라 하나**다. 322 × 2 = 644 가 아니라 322 개다
- 코드가 읽힌다. `t('cases.status.running')` 은 무엇이 나올지 파일을 열어야 안다
- **빠진 번역이 화면을 깨지 않는다.** 표에 없으면 한국어가 그대로 나온다

대신 **조용히 빠지는 것**을 기계가 잡아야 한다. 검사 **셋**을 같이 만든다 (할 일 1).

| 검사 | 무엇을 막나 |
|---|---|
| 소스의 `t('…')` 키가 전부 `en` 표에 있다 | 번역을 빠뜨린 채 초록불이 뜨는 것 |
| `en` 표의 키가 전부 소스에 있다 | 워딩을 고친 뒤 옛 키가 표에 남는 것 |
| **첫 인자가 문자열 리터럴이 아닌 `t(` 호출이 하나도 없다** | 아래 참조 |

#### 값이 박힌 글자 — 키는 언제나 정적 문자열이다 (게이트 1 반영)

화면에는 값이 끼워진 글자가 이미 많다.
`RUN ${runId} 이 도는 중입니다 ${끝난수}/${총}`(`layout.ts:172`) · `모두 N건` · `끝난 N회 기준`.

**이것을 템플릿 문자열로 쓰면 정규식이 못 잡고 검사가 초록으로 통과한다.**
영어로 바꿔도 그 줄만 한국어로 남는다. 그래서 둘을 못 박는다.

```
✅  t('RUN {번호} 이 진행 중입니다 {끝난}/{전체}', { 번호, 끝난, 전체 })
❌  t(`RUN ${번호} 이 진행 중입니다`)
```

**정규식의 한계를 「탐지 못 함」이 아니라 「금지」로 푼다.** 위 표의 셋째 검사가
비-리터럴 `t(` 호출을 하나라도 보면 빨개진다 — **새는 길이 검사 실패가 된다.**

#### 같은 한국어가 다른 영어여야 할 때 (게이트 1 반영)

`실행` 은 버튼에서 `Run`, 집계 라벨에서 `Runs`, 「실행 기록」에서 `Run history` 다.
키 하나에 값 하나뿐이므로 **탈출구를 미리 정한다** — 키 뒤에 괄호로 자리를 붙인다.

```
t('실행 (버튼)')   t('실행 (집계)')
```

괄호 부분은 **표에 없을 때 화면에 나오면 안 되므로**, 한국어를 낼 때 ` (…)` 꼬리를 떼고 낸다.
구현 중에 처음 부딪히면 이미 옮긴 파일을 다시 열어야 한다.

#### 표를 영역별로 가른다 (게이트 1 반영)

`messages.ts` 하나에 322개를 넣으면 **① 할 일 여섯이 같은 파일을 건드려 병렬이 깨지고
② 300줄 규칙(CLAUDE.md §3)을 어긴다.**

```
messages/shell.ts     껍데기·공통   (할 일 5)
messages/cases.ts     케이스        (할 일 6)
messages/runs.ts      실행          (할 일 7)
messages/settings.ts  설정·로그인   (할 일 8)
messages.ts           넷을 합치기만 한다 (할 일 1 이 만들고 그 뒤 아무도 안 고친다)
```

### BLOCKER 2 — 보간(값을 끼워 넣는 글자) 설계가 아예 없다. 그래서 검사에 구멍이 남는다

**무엇이** — 화면에는 값이 박힌 글자가 이미 많다.
`RUN ${runId} 이 도는 중입니다 ${끝난수}/${총}`(`layout.ts:172`) · `모두 N건` · `끝난 N회 기준`.
계획은 `t('…')` 만 말하고 **이런 글자를 어떻게 다루는지 한 줄도 없다.**

**왜 문제** — 적어 두지 않으면 구현자가 자연스럽게 템플릿 문자열로 쓴다.

```
t(`RUN ${id} 이 진행 중입니다`)   ← 정규식이 못 잡는다. 표에 없어도 검사가 초록이다
```

**영어로 바꿔도 그 줄만 한국어로 남고 아무도 모른다.**

**고칠 것** — 둘을 같이 박는다.

1. **키는 언제나 정적 문자열이다.** 값은 자리표로 넣는다 —
   `t('RUN {번호} 이 진행 중입니다 {끝난}/{전체}', { 번호, 끝난, 전체 })`
2. **검사가 「못 잡는다」가 아니라 「거부한다」로 바뀐다.** 소스를 훑어
   **첫 인자가 문자열 리터럴이 아닌 `t(` 호출이 하나라도 있으면 빨갛게 만든다.**
   그러면 구멍이 닫힌다 — 새는 길이 검사 실패가 된다.

지적 ① 에 대한 답이다. **정규식의 한계는 「탐지 못 함」이 아니라 「금지」로 푼다.**

`ui.tsx` 의 `when()` · `seconds()` 가 시각을 그린다. 한국어와 영어는 형식이 다르다
(`2026. 9. 22. 오후 3:04` / `Sep 22, 2026, 3:04 PM`).
`Intl.DateTimeFormat` 에 언어를 넘기면 된다 — **새 부품이 필요 없다.**
i18n 에서 가장 흔히 빠뜨리는 자리다.

### 주의 3 — `<html lang>` 과 탭 제목이 언어를 안 따라간다

`index.html` 의 `lang` 은 고정이고 `Shell.tsx` 가 `document.title` 을 한국어로 적는다.
`lang` 이 틀리면 **화면 낭독기가 한국어 목소리로 영어를 읽는다.** DESIGN.md 접근성 기준에 걸린다.
