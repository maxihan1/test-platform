# WS-E 화면 ① 뼈대 — 로그인 · 서비스 띠 · 자리 넷 · 등급

등급: 2 · 갈래: E · 2026-09-19

## 도메인 정리

**바운디드 컨텍스트** — 없다. 화면은 세 컨텍스트(Catalog · Execution · Reporting)를 **보여주기만** 한다.
도메인 규칙을 새로 만들지 않고 `/api/**` 가 주는 값을 그린다.

| 영향 | 무엇 |
|---|---|
| 소유 경로 | `apps/admin/src/web/**` |
| **소유 밖에서 고치는 것** | `apps/admin/src/execution/queries.ts` — 아래 「왜」 참조 |
| 부르는 API | `/auth/me` · `/auth/login` · `/auth/logout` · `/catalog/cases` · `/runs` · `/runs/:runId` · `/runs/:runId/items/:historyId` |
| 관련 절 | §8(화면 공통) · §8.1 · §8.3 · §8.6 · §3.5 · §4.1 · DESIGN.md |

**계약 변경이 아니다.** SPEC §7 이 `GET /api/runs/:runId` 를
`{ ...run, counts, items: [...], evidence: [{ id, format, status, filePath, error, generatedAt }] }` 로 적으면서
`evidence` · `last-by-case` · `settings` 는 필드를 **전부 나열**했고 `run` 과 `items` 만 **열어 뒀다**.
그리고 §6 표가 「`param_schema` 가 없으면 입력 칸의 라벨을 카탈로그에서 읽게 된다」고 이 통로를 요구한다.

## 왜

**지금 main 의 화면은 아예 안 뜬다.** 화면이 마지막으로 손을 탄 것은 2026-09-17 이고
그 뒤 `WS-F`(인증)와 `WS-A`(카탈로그)가 전제를 바꿨다.

| 무엇이 막나 | 어디 | 화면은 |
|---|---|---|
| 모든 `/api/**` 에 로그인 문 | `auth/gate.ts:62` | 로그인 화면이 **없다.** 401 을 받고 전부 빈 화면 |
| `GET /api/catalog/cases` 가 `?service=` 필수 | `catalog/routes.ts:122` | `api.cases()` 가 안 보낸다 → 400 `SERVICE_REQUIRED` |
| `GET /api/runs` 가 `?service=` 필수 | `execution/routes.ts:138` | `api.runs()` 가 안 보낸다 → 400 |

**그래서 이 덩이가 먼저다.** 로그인과 서비스 띠가 서야 나머지 열아홉 항목을 눌러볼 수 있다.

같은 덩이에 **버그 둘**을 넣는다. 둘 다 이미 사람에게 해를 끼치는 것이고 뼈대와 같은 파일을 만진다.

- `RunResult.tsx:28` 의 정지 조건이 `status !== 'FINISHED'` 다. WS-C 가 중단 기능을 넣었으므로
  **중단된 실행은 2 초마다 영원히 다시 묻는다** (SPEC §8.3)
- `ItemDetail.tsx:37` 이 `Object.entries(item.params)` 를 그대로 그린다.
  `20260917000001` 이 과거 `run_item` 을 `param_schema = '{}'` 로 메워서 **그 행의 비밀번호가 평문으로 뜬다.**
  WS-D 가 증적 쪽(`reporting/collect.ts:141`)만 고치고 화면은 킥오프로 넘겼다 (LEARNINGS 2026-09-19)

### BLOCKER 2 — 로그인은 만드는데 「도중에 끊기면」이 없다

`grep -n "401" apps/admin/src/web/` 이 0 줄이다. `api.ts` 의 `call()` 은 `res.ok` 가 아니면
`ApiError` 를 던질 뿐이고 401 을 따로 보지 않는다.

**나중에 무엇이 잘못되나** — `auth/identify.ts:18` 이 **세션이 살아 있어도 계정이 비활성이면

그때 화면은 `Failed` 컴포넌트로 빨간 글자 한 줄(`요청이 실패했다 (401)`)을 띄우고 멈춘다.
**로그인 화면으로 돌아가지 않는다.** 사람은 새로고침해도 같은 화면을 보고 도구가 고장난 줄 안다.

「열 때」만이 아니라 「도중에 끊길 때」도 같은 자리다 — 사람이 보는 결과가 같다.

**고칠 것** — `call()` 이 401 을 받으면 지금 자리를 기억하고 `#/login` 으로 보낸다.
할 일 6 에 그 사이클을 넣는다. 화면 다섯 곳에 각각 넣지 않는다 — `call()` 하나가 모든 요청의 길목이다.
