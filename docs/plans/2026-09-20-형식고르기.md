## 왜

직전 PR #32 의 검사가 **치명 1** 로 냈다. SPEC §8.4 의 「내는 형식」 표가
**「이 표가 형식의 정본이다. 결과 화면에서 골라 만든다」**고 못 박았는데
`RunResult.tsx:127` 이 `api.makeEvidence(data.runId, 'PDF')` 로 **PDF 를 박아 놨다.**

**서버는 처음부터 셋을 다 받고 있었다.** 화면만 안 물어봤다.
그래서 완료 기준 상자 넷이 **누를 버튼이 없어서** 못 채워진 채였다.

같이 **비밀값 꼬리표를 단 데모 케이스**를 만든다. 지금 `tests/demo/` 열 건 어디에도
비밀값 칸이 없다(꼬리표 0건 · 이름으로 걸리는 것 0건) — **가리기가 되는지 화면에서 볼 방법 자체가 없다.**
상자 하나가 더 열린다.

## ★ 화면 설계 — 계획이 정한다 (게이트 1 에서 확정)

**버튼 셋을 RUN 머리에 나란히 둔다.** `PDF 만들기` · `엑셀 만들기` · `HTML 만들기`.

**자리 근거를 바로잡는다.** 초판이 `evidence.ts:2` 주석을 인용한 것은 **과하게 읽은 것이었다**
(그 문장은 「항목 상세 화면 vs 실행 결과 화면」을 골랐다). **진짜 근거는 명세 원문이다** —
`docs/spec/도메인/리포팅.md:118` 「증적은 실행 단위 1부이므로 버튼은 항목 상세가 아니라
**실행 결과 목록(§8.3)의 RUN 머리**에 둔다」.

**목업이 명세와 어긋나 있다.** `docs/design-mockup.html:576~605` 이 `.tally` 에 숫자만 두고
형식 고르기를 `증적 문서` 구획 안 드롭다운으로 그렸다. **게이트 1 이 「명세를 따른다」로 정했으므로
목업을 명세에 맞춘다** (할 일 6).

**모달 탈락** — `DESIGN.md:169` 가 「두 자리에만 쓴다」로 못 박았다.
**드롭다운 탈락** — 부분 유일 인덱스가 `(run_id, format) WHERE status='PENDING'` 이라
형식마다 상태가 **실제로** 갈리는데 드롭다운은 고른 하나만 보여준다.

### 버튼 글자와 상태 — `title` 에 기대지 않는다

**`title`(말풍선)은 터치에 안 뜨고 `disabled` 버튼은 키보드 탭에서도 빠진다.**
지금 코드는 버튼 **글자 자체**로 「실행이 끝나면 만들 수 있습니다」를 화면에 쓴다(`evidence.ts:28`).
그 정보를 말풍선으로 내리면 **휴대폰에서 영영 못 읽는다** — 완료 기준 상자 「휴대폰으로 …볼 수 있다」가 죽는다.

| 그 형식의 상태 | 버튼 글 | 누를 수 있나 | 이유를 어디에 |
|---|---|---|---|
| 실행이 도는 중 | — **버튼을 아예 안 그린다** | — | `.tally` 아래 **보이는 줄** 하나 — 「실행이 끝나면 증적 문서를 만들 수 있습니다」 |
| 그 형식이 `PENDING` | `PDF 만드는 중` | ✗ | 버튼 글자가 곧 이유다 |
| 그 형식의 마지막이 `FAILED` | `PDF 다시 만들기` | ✓ | **보이는 줄** — 「PDF 를 만들지 못했습니다 — {사유}」 |
| 이미 만들었다 | `PDF 다시 만들기` | ✓ | 없음 |
| 없다 | `PDF 만들기` | ✓ | 없음 |

- **도는 중에는 버튼 셋을 안 그린다.** 넷(멈추기 + 형식 셋)을 다 그려 놓고 하나도 못 누르게 하면
  좁은 화면에서 **판정 숫자 셋이 셋째 줄로 밀린다.** `DESIGN.md:232` 가 휴대폰의 일을
  「끝났나 보기」로 좁힌 것과 정면으로 어긋난다
- **`PDF 만드는 중입니다` 가 아니라 `PDF 만드는 중`** — `DESIGN.md:118` 「버튼은 동사로 끝난다」.
  선례가 `RunResult.tsx:345` 의 `멈추는 중` 이다. 그리고 긴 글자는 **2초마다 줄바꿈 위치를 흔들어**
  누르려던 버튼이 손가락 밑에서 움직인다
- **실패 사유는 형식별로 가른다.** 지금 `.scan-error` 띠 하나(`RunResult.tsx:151`)와
  `증적오류` 문자열 하나(`:37`)뿐이라 「PDF 는 됐는데 엑셀만 실패」를 화면이 말하지 못한다
- **클래스는 `btn ghost` 로 못 박는다.** `.btn` 은 잉크색을 꽉 채워서 머리 띠에 **검은 덩어리 셋**이 생기고
  판정 숫자가 밀린다 — `DESIGN.md:23~25` 「색은 판정만 갖는다」의 취지가 시각적으로 뒤집힌다
- **이름은 `엑셀` 로 통일한다.** 아래 목록이 `{it.format}` 을 날것으로 찍어 `XLSX` 가 뜬다 —
  한 화면에 같은 물건이 두 이름이 된다. `DESIGN.md:140` 의 `PC`/`모바일` 선례를 따른다

### 좁은 화면 — `flex-wrap` 한 줄로는 모자란다

- `.tally` 에 `flex-wrap: wrap` (지금 없다)
- **620px 미디어 쿼리에 `.tally .btn { min-height: 44px }`** — `DESIGN.md:232` 가 실행 결과 화면에
  44px 을 걸었는데 `styles.css:727~731` 은 `.right .btn` 에만 건다. 실측 `.btn` 은 약 **41.6px** 이다.
  **지금은 버튼이 하나라 오눌러도 결과가 같았다. 셋이 되는 순간 오눌림이 의미를 갖는다**
- 좁은 화면에서 `.tally` 의 `gap` 을 줄인다(지금 18px 이라 접히면 줄 간격도 18px 이 된다).
  목업이 `:268` 에서 `gap:14px` 을 쓰는데 코드에 안 옮겨져 있다
- **같은 `.tally` 를 완료 모달(`RunResult.tsx:291`)도 쓴다** — 안 깨지는지 같이 본다

빠진 그 하나가 **기댓값이 바뀌는 바로 그 건**이다 — 단언값이 `글: '증적 문서 만들기'` 다.

**이것이 「검사를 지워서 초록을 만들지 않는다」가 실제로 뚫리는 방식이다** — 서약은 남고 개수가 틀린다.
`받는법` 5건도 서약 밖이다(모르는 형식 → `받기` · 대소문자 무시 두 축).

### BLOCKER 4 — `증적버튼모양` 의 새 모양을 안 정해서, 지금 설계대로면 **도는 중인 모든 실행에 빨간 오류 띠**가 뜬다

`RunResult.tsx:122` 가 `title={증적.사유}` 이고 **`:151` 이 `사유` 가 `null` 이 아니면
`.scan-error` 빨간 띠를 그린다**(「만들지 못했습니다 — {사유}」).

계획의 상태 표는 도는 중 안내(「실행이 끝나면 만들 수 있습니다」)를 `title` 에 넣는다.
그걸 `사유` 에 실으면 **아무것도 실패 안 했는데 실패로 보인다.**
새 칸에 실으면 지금 **글자로 보이던** 안내가 **말풍선으로 숨는다** —
`title` 은 터치에 안 뜨고, 완료 기준 상자 「휴대폰으로 …볼 수 있다」가 여기서 반쯤 죽는다.
§8.4 도 「**옆에** `실행이 끝나면 만들 수 있습니다`를 적는다」이다.

### BLOCKER 5 — `DEMO-011` 이 비밀값을 화면에 타이핑하면 **증적 스크린샷에 평문으로 박힌다**

`.meta({ secret: true })` 가림은 `params`·`expected` **칸**에만 걸린다. **스크린샷 픽셀에는 안 걸린다** —
그리고 §8.4 가 스크린샷을 PDF·HTML 문서 **안에 심는다**.

게다가 §10 이 정한 브라우저 대상 `demo.playwright.dev/todomvc` 에는 **비밀번호 칸이 없다.**
입력 칸은 「What needs to be done?」 하나뿐이고 친 글자가 **할 일 항목으로 화면에 남는다.**

계획이 `DEMO-003` 길을 물리친 이유(「비밀값이 증적에 실린다」)가 **타이핑 길로도 그대로 재현된다.**
상자 「비밀값이 화면과 증적 문서에서 가려져 나온다」를 확인하러 온 사람이 **정확히 반대 장면**을 본다.

### BLOCKER 6 — 계획이 할 일 4 ④ 에서 고칠 대상을 **반대로 짚었다**

계획은 「상자가 **목록**에서, §8.4 가 **결과 화면**에서 → **상자**를 고친다」로 판정했다.

**§11 상자는 그 문장과 일치한다.** 어긋난 것은 **§8.4 의 두 문장끼리**(`:118` ↔ `:154`)다.

상자만 고치면 **어긋남이 닫히는 게 아니라 자리를 옮긴다.**

### BLOCKER 7 — 사용자에게 「상자 다섯이 열린다」고만 하고 **무엇을 눌러야 하는지 한 줄도 없다**

**병합하고 화면을 열면 버튼이 하나 그대로다. 「PR 이 실패했다」로 읽는다.**

### BLOCKER 8 — 목업이 이 화면을 이미 그렸는데 계획이 그 파일을 안 열었다

`DESIGN.md` **셋째 줄**이 「`design-mockup.html` 이 시각적 기준이다. WS-E는 목업을 먼저 열어보고 시작한다」다.

게다가 순서가 나쁘다. 할 일 1·2 가 코드를 박은 **뒤에** 목업을 연다.

### BLOCKER 9 — 휴대폰 손가락 44px 이 `.tally` 에 안 걸려 있다

`DESIGN.md:232` 가 「손가락 최소 44px 은 **실행 기록 목록과 실행 결과** 두 화면에 건다」인데
