## 도메인 정리

- **계약**(게이트 0 승인 2026-10-05) — 공유 타입 `CaseSpec.techniques?` · DB `test_case.techniques` · `GET /api/catalog/cases` 항목과 `?technique=` · `GET /api/catalog/export` 열
- **흐름** — 「미확정」 꼬리표와 같은 길: 케이스 파일 `defineCase({ techniques })` → 스캐너(고칠 것 없음 — `mod.spec` 통째) → `test_case` UPSERT → 목록 API · 엑셀 → 화면 목록(시안 A). 실행 기록 · 증적은 **안 바뀐다**(기법은 판정 셈에 안 들어가는 설명 정보 · 증적은 `test_case` 를 안 읽는다)
- **누가 채우나** — 작성 에이전트(자식)가 케이스 파일에 적고, 관문 0(`--agent`) · 올리기 판정이 「그 칸이면 그 기법」과 견준다(#157 의 칸 · 설계 재료). 사람 세션은 적어도 되고 안 적어도 된다(K14 가 꼴만 본다)
- 정본 절 — 공통/2-명세선언 필드 표 · K 표 · 공통/4-데이터모델 · 도메인/카탈로그 §3.1 · §7 · §8.1 · 도메인/작성 §3.6 「설계 기법」

## 왜

사용자 지시(2026-10-05) — 「만들어진 테스트가 어떤 기법으로 만들어졌는지 표시되고 필터도 되었으면」 · 「UI 테스트에는 안 들어가고 FN 에만」.
