## 도메인 정리

- Catalog BC. 명세 정본 — [도메인/카탈로그 §3.1 「미확정 꼬리표」 · §7 목록 응답](../spec/도메인/카탈로그.md), [공통/2-명세선언 §4 K11](../spec/공통/2-명세선언.md), 경고 규칙 [도메인/실행 §3.2](../spec/도메인/실행.md)
- 계약(목록 응답 모양)은 PR #73 게이트 0 에서 승인, 칸은 PR #74 가 세웠다. 이 PR 은 반영이다
- 화면(`apps/admin/src/web/**` 의 배지·머리 알림·`api.ts` 타입)은 WS-E 후속 — 이번에 안 건드린다

## 왜

타입과 칸만 서 있고 채우는 쪽이 없다. 스캐너가 꼬리표를 DB 에 옮겨야 실행 박제(WS-B)·증적(WS-D)·화면(WS-E)이 읽을 값이 생긴다.
K11 이 없으면 빈 사유·변수 사유가 조용히 확정 케이스로 섞인다.

## Plan

- **RED** — `store.test.ts`(DB, 접두사 `ZZA` 그대로) 에 넷. ① 사유 있는 명세를 저장하면 `unconfirmed` 가 그 글, `unconfirmed_since` 가 채워진다 ② 사유 글자만 바꿔 다시 저장하면 `unconfirmed` 는 새 글, `unconfirmed_since` 는 **그대로** ③ 사유를 빼고 저장하면 둘 다 `NULL` ④ 다시 달면 새 시각. 지금은 UPSERT 가 칸을 안 쓴다

- **RED** — `rules.test.ts` 에 순수 함수 `newlyUnconfirmed(before: string | null, after: string): boolean` 넷. 전에 없던 파일(before `null`) → false(새 케이스는 역방향이 원래 단다) · 전에 꼬리표 없고 지금 있음 → true · 전에도 있음 → false · 지금 없음 → false
