# Grafana 작성 현황 — 가장 오래된 미확정 · 작성에 걸린 시간

등급: 3 · 갈래: D · 2026-09-26

## 도메인 정리

- BC: Reporting (대시보드). 읽기만 한다 — 카탈로그(`test_case`)·작성(`authoring_request`)·설정(`service`)의 칸을 **칸 단위 권한**으로 빌려 본다
- 영향: DB 권한(`grafana_ro`) · Grafana 대시보드 JSON · 명세 리포팅 §8.5·§8.4·§7 · 데이터모델 §6
- 화면·Admin API·러너·Kit 타입은 그대로다

| 패널 | 읽는 칸 | 규칙 |
|---|---|---|
| 가장 오래된 미확정 | `test_case(tc_id, is_active, unconfirmed_since)` · `service(id, prefix, name)` | 케이스 목록 머리(`catalog/store.ts`)와 같다 — 활성 케이스 · `tc_id LIKE prefix || '-%'` · `min(unconfirmed_since)` |
| 작성에 걸린 시간 (최근 30일) | `authoring_request(id, service_id, kind, status, compare, created_at, finished_at)` · `service(id, name)` | `kind='AUTHOR' AND status='DONE'` · 걸린 시간 = `finished_at - created_at` · 서비스 × 방식(보통 / 화면과 대조)으로 묶어 건수·중간값·최대 |

## 왜

사용자 2026-09-26 — 미확정 케이스가 기획 답을 며칠째 못 받는지, 기획서를 넣고 초안 PR 이 나오기까지 얼마나 걸리는지를 Grafana 에서 본다.
대시보드 계정은 `test_run`·`run_item` 만 읽는다(§8.5). 표를 통째로 열면 **기획서 본문(`spec_text`)·테스트 소스·`slack_webhook`·`figma_token`** 이 대시보드로 샌다 — 그래서 칸 단위로만 연다 (게이트 0 승인 2026-09-26).

대조 요청은 화면을 훑느라 훨씬 오래 걸린다 — 섞으면 보통 요청이 느려진 것처럼 보여 방식으로 가른다.

### 주의 1 — 「걸린 시간」의 시작이 제출이 아니다 (두 렌즈)
`created_at` 은 DRAFT 행이 생긴 때다(`assetStore.ts:83`). 자료 올리는 시간과 한 줄 대기줄의 대기가 섞여, 긴 값이 사람 탓인지 에이전트 탓인지 못 가른다.
대조 요청은 PR 뒤 역기획서·표시까지 마치고 DONE 이다(`authoring-upload.ts:278`). 고칠 것: `started_at` 을 열어 「대기」(started−created)와 「작업」(finished−started)을 가르거나, 정의를 명세에 그대로 적는다
