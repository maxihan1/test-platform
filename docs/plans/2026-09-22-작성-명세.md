# 테스트 작성 기능의 명세를 세운다 — 잠금 셋과 새 도메인 장

등급: 3 · 갈래: 없음 (**새 갈래를 만드는 것이 이번 일의 일부**) · 2026-09-22

## 도메인 정리

**새 바운디드 컨텍스트를 하나 만든다 — `작성`.**

| BC | 무엇을 맡나 | 이번에 흔들리나 |
|---|---|---|
| **작성 (신설)** | 기획서 → 케이스 → 테스트 코드 → PR. 대기줄과 작업 단계 | **새로 생긴다** |
| 카탈로그 | 만들어진 케이스를 훑어 목록에 올린다 | 안 흔들린다 — 작성이 PR 을 올리면 기존 `scan()` 이 그대로 집는다 |
| 실행 | 케이스를 돌린다 | 안 흔들린다 |
| 리포팅 | 증적 문서 | 안 흔들린다 |
| 인증 | 누가 무엇을 할 수 있나 | **흔들린다** — 갈리는 자리가 셋에서 넷이 된다 |

**관련 절** — `공통/1` §1·§2·§3 · `공통/4` §6 · `공통/5` §8 · `도메인/인증` §7.
**`packages/kit` 은 안 흔들린다** — 작성 에이전트가 kit 을 import 하지 않는다 (PR #41 판정, 2026-09-22 재확인).

## 왜

**엔진과 에이전트는 이미 병합이 끝났고 화면만 남았다.** 그런데 착수하면 **세 곳에서 막힌다.**

| | 실측 (2026-09-22, 최신 `main` 병합 뒤) |
|---|---|
| ① | `공통/1-제품과-구조.md` 의 「영구히 하지 않는다」 표에 **「화면에서 테스트 코드를 작성·편집하는 기능」 행이 살아 있다.** 우리 설계는 화면이 코드를 담지 않는데(코드는 PR 로 저장소에만 생긴다) **그 구분이 명세 어디에도 없다** |
| ② | **「자리 넷」이 여섯 파일에 글자로 박혀 있다.** 자리를 하나 더하는 것이 화면 코드 변경이 아니라 명세 변경이다 |
| ③ | `apps/admin/src/auth/gate.ts` 의 `필요등급()` 이 **설정 자리면 admin, 읽기면 viewer, 나머지 전부 operator.** `/api/authoring/merge` 를 admin 으로 만들 길이 **없다** |

**③ 이 가장 위험하다.** 그대로 만들면 **실행 등급이면 누구나 저장소를 영구히 바꿀 수 있다.**
화면이 버튼을 안 그리는 것은 **편의이지 방어가 아니다.**

**게이트 0 에서 사용자가 「그려 넣어라」를 골랐고**, ③ 의 푸는 방법도 **「경로→등급 표를 서버에 둔다」**로
같이 골랐다. 화면(`apps/admin/src/web/role.ts`)이 이미 표라서 서버가 같은 모양이 된다.

### 다국어가 방금 새 제약을 만들었다 (2026-09-22)

착수 뒤 `main` 이 **18커밋** 움직였다 (PR #53 「목록 다듬기와 다국어」). `origin/main` 을 **병합**했다
(리베이스는 강제 푸시가 필요해 `CLAUDE.md §5` 가 금지한다). **충돌 0건.**

| | 새 사실 | 누가 보나 |
|---|---|---|
| 1 | 자리 이름이 `테스트케이스 목록` → **`테스트 케이스`** 로 줄었다 | — |
| 2 | 자리 이름은 **영어 이름도** 있어야 한다 (`ko`·`en`, 키가 한국어 원문) | **기계** — `apps/admin/src/web/messages.test.ts` 가 소스와 표를 양방향 대조 |
| 3 | 자리 이름은 다른 것들과 **길이가 비슷해야** 한다 | 사람 |
| 4 | 자리 이름과 그 화면 제목이 **같은 말을 두 번** 하면 안 된다 | 사람 |

**→ 새 자리 이름은 `테스트 작성` / `Authoring` 이다.** 길이가 `테스트 케이스`·`실행 기록` 과 비슷하고,
그 화면의 제목(작성 대기줄 등)과 말이 겹치지 않는다.

### 「자리 다섯」이라고 적지 않는 이유

**숫자를 절 제목에서 뺀다.** 여섯째가 생기는 날 같은 일을 또 하지 않으려는 것이다.

- 고칠 자리 수가 **두 길 모두 같다** — 숫자가 글자 안에 있어서 어느 쪽이든 같은 줄을 만진다.
  그런데 숫자를 빼면 **다음엔 0곳**이다
- `CLAUDE.md §2.7 ⑤` — 「개수는 정본 표를 가리키고 세는 일은 기계에 맡긴다」
- **`공통/5-화면공통.md` 가 같은 병을 자기 안에 적어 뒀다** — 「DESIGN.md 도 같은 숫자를 손으로
  적고 있었다 — 자리가 하나 늘거나 주는 날 한쪽만 고쳐진다」

**목록은 이미 정본이다** — 그 절이 「이 목록이 정본이다」라고 적었다. 문제는 목록이 아니라 **제목의 숫자**다.

### 할 일 6. 등급 갈리는 자리를 셋에서 넷으로

- **RED** — `docs/spec/도메인/인증.md` 가 「**등급으로 갈리는 자리는 셋이다**」라고 적고 표에
  `viewer`·`operator`·`/api/settings/** = admin` 세 줄만 둔다. **머지를 admin 으로 만들 자리가 없다.**
  코드도 같다 — `gate.ts` 의 `필요등급()` 이 설정 자리면 admin, 아니면 읽기는 viewer, **나머지 전부 operator**
- **GREEN** — 「셋이다」를 **넷**으로 하고 표에 줄을 더한다 —
  **「저장소를 영구히 바꾸는 일 (머지)」 = `admin`**. 이유를 같이 적는다: 되돌리려면 사람이 손으로 해야 하고,
  둘에 같은 등급을 주면 「실행할 수 있는 사람 = 저장소를 고칠 수 있는 사람」이 된다.
  그리고 **푸는 방법을 명세에 박는다** — **경로→등급 표를 서버에 둔다**(게이트 0 결정).
  화면(`apps/admin/src/web/role.ts`)이 이미 표라서 둘이 같은 모양이 된다.
  **새 통로는 `scope.ts` 라우트표에 등록해야 한다**도 적는다 — 「모르면 막는다」라서
  안 적으면 전부 403 이고 **원인이 권한처럼 안 보인다**
- **REFACTOR** — 없음. **`gate.ts`·`scope.ts` 구현은 다음 PR 이다**
