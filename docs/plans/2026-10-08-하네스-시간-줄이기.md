## 왜

**① 판별식 검사가 1분~10분으로 흔들린 원인 — 검사 둘이 진짜 단위 테스트를 한 번씩 더 돌았다.**
CI 「판별식 검사」 단계가 #176 78초 · #177 492초 · #175 604초였다. #177 로그의 검사별 `duration_ms` 를 뽑으니
492초 중 491초가 `hook-contract.test.mjs` 의 둘이었다 — 「삭제와 코드 push 가 섞이면 검사로 간다」 246초 · 「입력이 비면 검사로 간다」 244초.
둘이 쓰는 `run()` 은 진짜 훅을 **진짜 저장소에서 진짜 npm 으로** 부른다. 가짜 커밋 번호라 차선이 `full` 이 되고 훅이 `test:changed` + `test:always` 를 끝까지 돈다.
그래서 그 PR 의 단위 테스트 양(같은 CI 의 단위 테스트 단계 34초 · 243초 · 301초)을 그대로 따라 흔들렸다. 검사가 보는 것은 출력의 「검사 시작」 글자 하나다.
작업 폴더에서 빈 입력으로 훅을 돌려 보니 vitest 가 떠서 `Test Files 18 passed` 를 찍었다(2026-10-08 실측). 같은 파일 79줄은 「진짜 npm test 를 돌리면 이 검사가 수 분 걸린다」고 적고 가짜 npm 을 쓰는데, `run()` 만 그것을 안 탔다.
조용한 맥에서는 `check:workflow` 3회가 모두 219건 통과 · 46~50초라 결과는 안 흔들렸다 — 흔들린 것은 시간이다.

**② 같은 커밋에 같은 검사를 되풀이한다.** `tpx-impl` Step 4 와 `tpx-review` Step 4 가 같은 일곱 명령을 같은 커밋에 돌고, 이어지는 push 에서 훅이 단위 테스트를 또 돈다.
PR #177 은 기계를 기다린 시간이 약 40분(로컬 검사 2번 · 훅 2번 · CI)이었다.

**③ 기록만 더한 push 도 단위 테스트를 다시 돈다.** 차선은 PR 전체(origin/main 대비)를 본다. 코드가 섞인 PR 이면 검사 기록 · 진행 기록만 더한 push 도 `full` 이라
단위 테스트를 다시 돌고 「오늘 날짜 기록」을 다시 요구한다. PR #176 은 게이트 2 승인이 자정을 넘겨 기록 push 가 막혔다.
LEARNINGS [환경] 2026-10-08 이 「다시 나면 훅이 『검사 기록 커밋 이후 차이가 docs 뿐이면 통과』를 보도록 옮긴다」고 예고했다.
(착수 때 「문서만 push 건너뛰기는 09-25 차선으로 이미 된다」고 한 것은 틀렸다 — 그건 PR 전체가 문서뿐일 때만이다.)

**④ 1등급에 spec-review 기록을 강제한다.** `/tpx` 등급표는 1등급(화면 · 테스트 · 하네스) 렌즈를 `/code-review`(+ 화면이면 `/qa-only`)로 정했는데,
훅은 `full` 차선이면 등급과 상관없이 `docs/reviews/<오늘>-*.md` 를 요구하고 응답 끝 경고도 매번 spec-review 를 돌리라고 한다.

### BLOCKER 1 — `local` 표지를 기계가 아니라 세션이 판정해서 찍는다
Step 4 일곱 명령은 줄마다 `EXIT=$?` 를 찍고 세션이 눈으로 읽는다(tpx-impl 이 「Tests N passed 와 EXIT=1 이 동시에 참」을 경고할 만큼 잘못 읽은 적이 있다). migration·package 면 전체 규칙도 스킬에서는 산문이다.
계획대로면 impl 이 찍은 표지 하나로 review 와 훅이 둘 다 건너뛰어, 유일한 기계 판정이던 훅이 빠진다. 잘못 찍히면 깨진 코드가 CI 에서야 걸린다.
고칠 것: `check-stamp.mjs run local` 이 일곱 명령과 전체 규칙을 스스로 돌리고, 전부 0 이고 시작 때 HEAD · 작업 폴더가 그대로일 때만 찍는다. 스킬은 이 명령 하나만 부른다. `put` 은 훅만 쓴다.

### BLOCKER 2 — HEAD 가 아닌 커밋에도 `push` 표지가 붙는다
훅은 올리는 ref 가 무엇이든 작업 폴더를 검사하는데 계획은 「올린 커밋마다 put push」다. `git push origin 다른브랜치` · `HEAD~1:refs/heads/x` · 여러 ref 면 검사 안 한 트리에 「통과」가 찍히고, 표지는 공용 폴더라 다른 작업 폴더도 믿는다.
고칠 것: `put` 은 대상이 `git rev-parse HEAD` 와 같을 때만 남기고 아니면 이유를 찍는다. RED 에 「다른 ref 를 push 한 뒤 그 ref 에 표지가 없다」를 더한다.

### 주의 1 — 1등급 면제가 일부 경로만 보고 내려질 수 있다
pre-push 는 diff 가 실패하면 `lane=full; break` 로 남은 ref 를 안 읽어 `changed_all` 에 앞 ref 경로만 남는다 — diff 가 한 번이라도 실패하면 면제하지 않는 표시를 둔다.
surfaces 의 DOC(`docs/**` · `**/*.html`)은 0등급이라 `docs/x.mjs` · `apps/admin/public/x.html` 도 면제된다(lane.mjs 17~19줄이 경고한 자리) — 면제 조건을 「1등급 표면이거나 lane 의 문서자리」로 좁힌다.

### 주의 2 — `set -e` 에서 새 node 호출이 실패할 때
detect-tier 는 경로가 비면 exit 3 이라 `$(…)` 로 부르면 훅이 [차단] 문구 없이 죽는다. `if out=$(…); then` 으로 감싸고 경로는 stdin 으로.
reuse 를 모을 때 초기값은 none(REFS 비었을 때 · 삭제 줄 · find 출력이 빔). 「HEAD 에 push 표지가 있는 저장소 + 빈 stdin → 그래도 기록 요구」 RED 를 더한다.

### 주의 3 — porcelain 의 이름 바꾸기 줄 · 따옴표 친 경로
` -> ` 새 경로만 쓰면 `execution/b.ts -> web/b.ts` 가 1등급으로 내려간다. `git -c core.quotePath=false status --porcelain --no-renames` 를 쓰고 못 읽는 줄은 더러움 · 미분류로 친다. 이름 바꾸기 줄과 한글 경로를 RED 에 더한다.
