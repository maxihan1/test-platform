## 왜

기획서는 붙여넣는 본문이 아니라 **PDF·워드 파일**로 온다. 피그마도 같이 온다. 문서도 피그마도 **여럿이 한 세트**다
(사용자가 세 번에 걸쳐 못박았다 — PR #61 인계 코멘트 §1).

**`DRAFT` 가 핵심이다.** 요청을 만들고 파일을 하나씩 올리는 동안 줄에 서 있으면 맥이 집어 가 빈 것을 보고 실패한다.
다 올린 뒤 「줄에 세우기」가 `DRAFT → PENDING` 으로 바꾼다.

### 흐름

```
화면  POST /requests {kind:AUTHOR, figma:[주소…]}  → DRAFT 행 + FIGMA 자료 행   → 201 {id}
화면  POST /requests/:id/assets?name=기획서.pdf  (원시 바이트)  × 파일 수     → FILE 자료 행
화면  POST /requests/:id/submit                    → DRAFT → PENDING (자료 0 이면 409)
맥    POST /requests/claim                          → 집은 한 건 (+ assets)
맥    GET  /requests/:id/assets/:assetId            → 파일 받아 임시 폴더에
맥    docx 는 textutil 로 글자만 · pdf 는 그대로 · 피그마 주소는 프롬프트에
맥    claude -p --add-dir <임시 폴더>               → tpx-cases 가 npx figma-reader-cli 로 피그마를 읽는다
```

- **`RERUN` 은 `DRAFT` 를 안 거친다.** 자료를 새로 안 받고 원본 행의 자료를 맥이 읽는다 — 곧장 `PENDING`
- **`MERGE` 는 지금 그대로다** (자료 없음 · 바로 `PENDING`)
- **파일 저장 자리는 `authoring-assets/<요청번호>/`** — 사진 폴더 `authoring/<번호>/` 안에 두면
  사진 장수 상한(`readdir` 200)이 자료까지 센다. 뿌리는 사진과 같은 `PLATFORM_ARTIFACTS_DIR` (볼륨으로 묶인 유일한 자리)

### 실측 — 파일이 이미 크다 (CLAUDE.md §3 300줄)

| 파일 | 줄 | 이번에 |
|---|---|---|
| `authoring/routes.ts` | 379 | 자료 통로 셋을 **새 파일 `authoring/assets.ts`** 로 뗀다 — 파서 상한도 따로 가져야 해서 어차피 갈라야 한다 |

**Fastify 파서 상한은 파서 쪽이 이긴다.** `routes.ts:165` 의 `octet-stream` 파서가 `bodyLimit: 4MB`(사진)로 걸려 있어
같은 플러그인 안에서는 라우트 `bodyLimit` 으로 못 넓힌다. 자료 통로는 **다른 플러그인**에서 자기 파서를 등록한다.

### 게이트 1 에서 정할 것 (명세에 없는 값 — CLAUDE.md §1.4)

| 무엇 | 제안 |
|---|---|
| 받는 파일 종류 | `.pdf` · `.docx` · `.md` · `.txt` |
| 한 파일 상한 | 20MB |
| 한 요청의 자료 개수 상한 | 파일 + 피그마 합쳐 20 |
| 피그마 토큰 자리 | **맥 비밀번호와 같은 방식** — 켤 때 묻고 메모리에만. 빈 입력이면 피그마 없이 돌고, 피그마 자료가 든 요청만 `FAILED`(「피그마 토큰 없이 켰다」) |
| `spec_text` 를 맥이 채우나 | **칸만 풀고 채우는 일은 미룬다.** 지금 그 값을 만드는 쪽도 읽는 쪽도 없다 |
| `figma-reader-cli` 스킬 설치 | **안 한다.** `tpx-cases` 가 `npx figma-reader-cli@<고정 판> inspect` 를 직접 부른다. 벤더 폴더가 안 생기므로 CLAUDE.md 벤더 경계 절을 안 고친다 |

## LEARNINGS 근거

- 넓은 `DELETE ... LIKE` 가 남의 fixture 를 지운 일 (CLAUDE.md §3) — 자료 표 검사도 **`XWA`·`XWAR` 의 자기 `service_id` 로만** 지운다. `authoring_asset` 은 `ON DELETE CASCADE` 로 부모와 함께 간다
- 경로 번호를 느슨하게 읽어 문과 라우트가 다른 값을 본 일 — `:assetId` 도 `번호()` 로 읽는다
- 폴더 거슬러 오르기 — 파일 이름은 모양을 좁히고 저장 이름은 **자료 행 번호**로 짓는다
- 맥이 보낸 값을 명령줄에 끼운 일(`pr_url`) — 피그마 주소도 **모양을 좁혀 받는다**. 자식이 그 값을 `npx` 인자로 쓴다
