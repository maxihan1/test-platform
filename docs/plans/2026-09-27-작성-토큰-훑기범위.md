# 역방향 「한 칸」 정의 · 작성 토큰 사용량 저장 · Grafana 토큰 패널

등급: 3 · 갈래: 작성 (+ D 대시보드) · 2026-09-27

## 도메인 정리

- BC: Authoring(에이전트 · 통로 · 표) · Reporting(대시보드). 인증은 에이전트 토큰 통로 목록에 한 줄
- 게이트 0 (2026-09-27 사용자) — ① 사용량 계약 변경 승인 ② 훑는 범위는 **A: 명세 범위 그대로, 「한 칸」을 좁게 정의**(두 단계 넓히기는 안 한다)

| 무엇 | 어디 |
|---|---|
| 사용량 칸 다섯 | `authoring_request.tokens_input · tokens_output · tokens_cache_read · tokens_cache_write`(BIGINT) · `cost_usd`(NUMERIC) |
| 보고 통로 | `POST /api/authoring/requests/:id/usage` — 집은 에이전트만 · RUNNING 일 때 · 한 번(이미 있으면 409) |
| 받는 법 | `claude -p --output-format stream-json --verbose`. 턴마다 `assistant` 이벤트의 `message.usage` 를 **메시지 id 로 한 번씩** 더한다 → 시간초과로 끊겨도 센다. 끝에 `result` 이벤트가 오면 그 합계·`total_cost_usd` 를 쓴다(비용은 정상 종료 때만) |
| 결과 요약 | 올리기(PR 본문)에 넘기던 자식 출력 → `result` 이벤트의 `result` 글. 없으면(끊김) assistant 글을 이어 붙인 것 |
| 패널 | 「작성 토큰」 — 최근 30일(끝난 시각) 처음 작성 요청, 서비스 × 결과(성공/실패) · 요청 수 · 요청당 토큰 중간값 · 토큰 합계 · 환산 비용 합계. 토큰 = 네 칸 합 |
| 「한 칸」 | 그 화면 **안에서** 여는 것 — 팝업 · 탭 · 펼치기 · 그 흐름의 다음 단계. **머리 메뉴 · 바닥 링크 · 다른 기능으로 가는 링크는 한 칸이 아니다.** 본 내용은 화면별 파일에 적고 대화엔 한 줄 |
