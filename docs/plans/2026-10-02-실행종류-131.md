# 실행 하나에 한 종류 — test_run.kind UI · FN · SCENARIO

등급: 3 · 갈래: contracts · WS-B · WS-D · 2026-10-02 · PR #131 · 진행판 AUT-F3-20(서버 몫. 화면은 #132)

## 도메인 정리

- 실행(도메인/실행 §3.2 · §7 · §8.7) · 시나리오 결정 10(시나리오 §3.7) · 리포팅 §8.4 증적 · §8.5 Grafana · 데이터모델(공통/4) · 작성 §3.6 「★ 테스트 두 갈래」 대기 블록
- 「케이스 실행」 = `kind IN ('UI','FN')`. E2E = `SCENARIO`. tcId 종류 판정은 `catalog/rules.ts` `tcId종류`

| 영향 | 무엇 |
|---|---|
| DB | `test_run.kind` CHECK `UI · FN · SCENARIO` · 기본값 없음 · 옛 `CASE` 행 삭제(증적 문서 → 실행 항목(절차 행 CASCADE) → 실행) |
| `POST /api/runs` | 종류를 tcId 로 정한다. 섞이면 400 `MIXED_KIND` |
| `GET /api/runs` | `?kind=ui\|fn\|case\|scenario`, 기본 `case`(UI+FN). 줄에 `kind` |
| 단건 · 증적 · 견주기 | 케이스 실행만(`UI · FN`). 견주기는 같은 종류의 직전 실행 |
| 증적 머리 | 「종류」 칸(HTML · 엑셀) |
| 정해진 시간 실행 | 종류별로 실행 둘. 빈 쪽은 안 만든다 |
| Grafana | 네 패널 `kind IN ('UI','FN')` · 최근 실행 목록에 종류 칸 |

**계약 변경: 게이트 0 승인(2026-10-02)** — 위 표 그대로.
