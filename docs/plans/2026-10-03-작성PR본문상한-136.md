# 작성 PR 본문이 GitHub 상한을 넘지 않게

등급: 2 · 갈래: WS-작성 · 2026-10-03 · PR #136

## 도메인 정리

작성 에이전트의 PR 본문 조립(`scripts/authoring-chain.ts` `PR본문`)만 바꾼다. 계약(DB · Admin API · kit 타입 · 러너)은 그대로다.
명세가 PR 본문에 꼭 실으라는 것은 관문 3 기록(작성 §3.6 164행)과 셈 머리 줄(445행)이다 — 둘 다 「작성 요약」 절 안에 있다(머리 = 셈 · 꼬리 = 자식 결과 요약의 관문 줄).
요구사항 표를 본문에 싣는 것은 명세에 없다 → 긴 표를 경로 한 줄로 바꿔도 명세와 안 어긋난다. 명세는 안 고친다.

## 왜

2026-10-03 MKT 다시 작성(#11201)이 93분 동안 케이스 133개(UI 29 · FN 104)를 다 만들고도 `gh pr create` 가 「Body is too long (maximum is 65536 characters)」로 거절돼 중단(REJECTED)됐다.
요구사항 표가 117,745자였다. 요구 172개짜리 기획서면 늘 넘는다.

### BLOCKER 1 — ② 「단계 시각 절을 뺀다」는 명세(작성 §7 1048행 「PR 본문에 단계 시각 절로 싣는다」)와 어긋난다
상한을 넘는 실행은 오래 걸린 실행이라 단계표가 가장 필요한 때 사라진다. 단계표는 수 KB 를 안 넘으니 ② 를 빼고 표 → 요약 줄이기로 간다.

### 주의 1 — UTF-16 `length` 60,000 은 Linux 명령 인자 상한(131,072바이트)을 한글 본문에서 넘을 수 있다
`--body` 인자로 넘어가 한글 3바이트면 약 180KB → E2BIG. UTF-8 바이트로 60,000 을 센다(GitHub 상한도 같이 지켜진다).

### 주의 2 — ③ 줄이기는 머리글(셈 · 빠짐 · UI 로만 덮음 줄) 통째 + 자식 출력은 줄 단위로 가운데를 줄인다
글자로 자르면 셈 줄 · 관문 줄이 가운데서 잘린다. 긴 한 줄만 그 줄 안을 자른다.

### 주의 3 — 옮길 기존 테스트는 다섯이다(55~80행). `PR본문고치기인자` 는 chain 에 둔다

### 통과한 것
- 표를 본문에서 빼는 것은 명세에 없어 안 어긋난다 · 짧으면 글자까지 같게 · 비밀 검사 순서 · held-merge 처리 줄은 여유 안 · 새 파일로 떼기

## 게이트 1 결정 (2026-10-03 · 지적 반영하고 진행)

- ② 단계 시각 절 빼기를 지운다. 줄이는 순서는 표 → 요약 가운데뿐
- 상한은 UTF-8 바이트 60,000 (`Buffer.byteLength`)
- 요약 줄이기: 머리글(첫 빈 줄 앞)은 통째, 그 뒤 자식 출력은 줄 단위로 가운데를 「…(줄임)…」으로. 그래도 넘으면 가장 긴 줄 안을 자른다
- 기존 PR본문 테스트 다섯을 옮기고 `PR본문고치기인자` 는 chain 에 둔다
