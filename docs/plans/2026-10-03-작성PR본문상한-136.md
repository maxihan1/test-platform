# 작성 PR 본문이 GitHub 상한을 넘지 않게

등급: 2 · 갈래: WS-작성 · 2026-10-03 · PR #136

## 도메인 정리

작성 에이전트의 PR 본문 조립(`scripts/authoring-chain.ts` `PR본문`)만 바꾼다. 계약(DB · Admin API · kit 타입 · 러너)은 그대로다.
명세가 PR 본문에 꼭 실으라는 것은 관문 3 기록(작성 §3.6 164행)과 셈 머리 줄(445행)이다 — 둘 다 「작성 요약」 절 안에 있다(머리 = 셈 · 꼬리 = 자식 결과 요약의 관문 줄).
요구사항 표를 본문에 싣는 것은 명세에 없다 → 긴 표를 경로 한 줄로 바꿔도 명세와 안 어긋난다. 명세는 안 고친다.

## 왜

2026-10-03 MKT 다시 작성(#11201)이 93분 동안 케이스 133개(UI 29 · FN 104)를 다 만들고도 `gh pr create` 가 「Body is too long (maximum is 65536 characters)」로 거절돼 중단(REJECTED)됐다.
요구사항 표가 117,745자였다. 요구 172개짜리 기획서면 늘 넘는다.
