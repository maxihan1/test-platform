# E2E 시나리오 계약 반영 — kit 타입 · DB 표

등급: 3 · 갈래: 없음(계약 반영 단위) · 2026-09-28

## 도메인 정리

- 계약 둘. Shared Kernel 타입(`packages/kit/src/types.ts`)과 DB 표(`db/migrations/`)
- 정본은 [공통/3-공유계약 「E2E 시나리오 타입」](../spec/공통/3-공유계약.md)과 [공통/4-데이터모델 「E2E 시나리오 표」](../spec/공통/4-데이터모델.md) 계약 블록이다. 둘 다 PR #97 게이트에서 승인됐고 지금은 `상태: 대기` 다
- **kit 블록은 타입과 런타임(시나리오 모드 — 본체 꺼내기 · `RunScope` 꿰기 · 제목으로 건너뛰기)을 한데 묶었다.** 런타임은 WORKSTREAMS 📐 E2E 2번(KIT + WS-C 러너) 몫이다. 이번에는 타입만 넣고 블록을 둘로 나눈다
- 표를 **읽고 채우는 코드는 이번 범위가 아니다.** 서버(WS-B) · 증적(WS-D) · 화면(WS-E)은 갈래별 후속이다

## 왜

뒤 갈래가 전부 이 두 계약을 읽는다. 타입과 표가 먼저 서야 러너와 서버가 주고받을 수 있다(WORKSTREAMS 📐 E2E 권장 순서 1번).

옛 코드가 새 칸에 깨지지 않는지 실측했다 — `apps/admin/src` 운영 코드에 `SELECT *` 와 zod `.strict()` 가 없다. `test_run.kind` 는 기본값 `'CASE'` 라 기존 INSERT 는 그대로 선다.
