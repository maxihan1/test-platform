## 왜

PR #161 · #162 로 러너는 이어 주기 · 꽂은 값 · 미룬 뒷정리를 돌려주는데, admin 은 하나도 안 받는다.
- `validate.ts` `부품모양` 의 case 갈래에 `carryOver` · `links` 가 없다 — `z.object` 가 모르는 칸을 오류 없이 버려 **저장하는 순간 이어 주기가 사라진다**(WORKSTREAMS ⓒ 인계)
- 결과의 `bound` · `cleanup` 을 안 적고, 실행 만들기가 저장값을 안 채워 부품 열 개면 비밀번호를 열 번 적어야 한다(시나리오 §3.7 「부품 입력값을 채우는 순서」)
- 미확정 부품이 섞인 통과가 정식 통과로 세진다(§7 「판정 접기」)

**코드 실측 (2026-10-06)**
- 러너는 꽂은 값을 조립 값 위에 덮는다 — `apps/runner/scenario/links.ts:246` `{ ...part.params, ...bound }`. 그래서 admin 이 꽂기 칸을 저장값으로 채워도 실행에는 꽂은 값이 간다
- `callScenarioRunner` 는 러너 응답을 거르지 않고 넘긴다(`execution/runner.ts:158`) — `bound` · `cleanup` 은 이미 admin 까지 온다
- `저장값을채운다`(`execution/savedInput.ts`)는 `RunItemInput`(케이스 실행 모양)과 트랜잭션 연결만 받는다. 시나리오 부품은 `{ tcId, params, expected }` 를 가진 다른 모양이다
- 시험 보관소(`execution/trial.ts` `시작한다`)는 **시작할 때 받은 비밀값 목록**으로 결과가 도착할 때 가린다. `bound` 는 러너가 돌아와야 알 수 있어 그 목록에 못 든다
- 내 `platform` DB 에는 `20261006000001_scenario_relink` 가 안 걸려 있다(마지막 `20261005000001`). DB 검사는 SETUP §13 임시 DB `tp_e2e14` 에서 돈다
