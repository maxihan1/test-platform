# 작성 요청 진척 표시 · 중단 · 폐기

등급: 3 · 갈래: 작성 (+ E 화면 · D 대시보드) · 2026-09-27

## 도메인 정리

- 이어하기를 둘로 나눈 앞쪽(사용자 2026-09-27). 뒤쪽(보관·이어하기)은 다음 PR — 여기서 세운 「중단됨」 위에 선다
- 게이트 0 (2026-09-27 사용자) — 계약 승인 · 멈추고 버리는 사람은 **요청한 사람 + 운영(admin)** · 시스템이 멈춘 것도 「중단됨 + 이유」로 · **누가 멈췄는지도 남긴다** · Grafana 는 중단을 따로 센다

| 무엇 | 정한 것 |
|---|---|
| 상태 | `DRAFT · PENDING · RUNNING · DONE · FAILED` + **`STOPPED`**(중단됨) |
| 칸 | `stop_requested_at`(사람이 멈춰 달라고 한 때) · `stopped_by`(아이디 또는 `system`) · `stop_reason`(`USER`·`TIMEOUT`·`LIMIT`·`AGENT_RESTART`) · `discarded_at` · `progress`(JSONB) |
| 중단 | `POST …/:id/stop` — `PENDING` 이면 곧장 `STOPPED`(USER) · `RUNNING` 이면 `stop_requested_at`·`stopped_by` 만 적는다 · 그 밖 409. `AUTHOR`·`RERUN` 만(머지는 409) |
| 에이전트가 아는 길 | `PATCH …/:id/stage` 가 `{ stage, progress? }` 를 받고 `{ ok, stop }` 을 돌려준다. 자식이 도는 동안 **30초마다** 부른다 |
| 끝내기 | `finish` 가 `status: 'STOPPED'` + `stopReason` 을 받는다. `USER` 면 `stopped_by` 는 멈춰 달라고 한 사람 그대로, 그 밖이면 `system` |
| 시스템 중단 | 시간초과 → `TIMEOUT` · 구독 한도 → `LIMIT` · 에이전트가 켜질 때 남은 `RUNNING` → `AGENT_RESTART`. 전부 지금은 `FAILED` 다 |
| 폐기 | `POST …/:id/discard` — `FAILED`·`STOPPED`·`DRAFT` 만. 행은 남기고 `discarded_at` 을 적는다. 목록은 폐기된 것을 안 보인다(`?discarded=1` 이면 보인다). 통계·토큰은 남는다 |
| 누가 | 요청한 사람 + `admin` (자료 올리기·줄 세우기와 같은 `NOT_REQUESTER` 403) |
| 진척 | `{ elapsedSec, screens, cases, tokens, lastAction, at }` — 에이전트가 계산해 올린다. 화면은 60분 한도 대비 경과와 함께 그린다 |
| Grafana | 「작성에 걸린 시간」에 중단 수 칸 · 「작성 토큰」 결과에 「중단」 줄(STOPPED — 쓴 토큰이 빠지지 않는다) |

## 왜

5871 은 「케이스를 만드는 중」 한 줄로 45분을 보냈고 멈출 길도 치울 길도 없었다. 명세 「아직 알 수 없는 것」의 「실패한 작성 요청을 어떻게 치우나」가 열려 있었다.
