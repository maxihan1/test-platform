## 왜
사용자가 Devicefarm 진행판(https://claude.ai/artifact/WCojLAwpcRvL7pv67hfwY7)과 **같은 형식**을 test_platform 에도 원했다 —
영역 → 기능 → 태스크 체크박스를 원본으로 두고, 병합할 때마다 완료가 반영된 페이지를 같은 URL 로 다시 게시한다.
**WORKSTREAMS.md 와 동기화**도 요구했다(게이트 없는 사용자 답, 2026-09-29). 지금 진척은 WORKSTREAMS 산문의 `✅`·`반영 완료` 에만 있어
기계가 셀 수 없다. 두 문서가 같은 사실을 따로 적으면 한쪽만 갱신된다 — 그래서 **어긋나면 검사가 빨개지게** 한다.

동기화 규칙 (검사 `check:wbs`)
- ① WORKSTREAMS 에서 `✅` 또는 `반영 완료` 가 붙은 줄의 PR 번호는 전부 wbs 에서 `[x]` 태스크의 근거로 있어야 한다
- ② wbs 의 추적 영역(WORKSTREAMS 가 묶음으로 관리하는 역방향·E2E·인증 개편)에서 `[x]` 태스크의 PR 은 WORKSTREAMS 완료 줄에 있어야 한다
- ③ `[x]` 는 근거 줄(`근거 PR #N · YYYY-MM-DD`)이 있어야 한다 — 날짜는 git 에서 캐지 않고 적는다(Devicefarm 은 git log -S 로 캤다. 결정적이고 테스트하기 쉬운 쪽)

### 주의 1 — `check:wbs` 가 문서 차선에서 안 돌 수 있다
wbs.md 체크만 바꾸는 PR 은 `docs` 차선이다. CI 는 그 차선에서 `check:workflow` 를 건너뛰므로 `check:wbs` 를 그 옆에 두면
**어긋난 채로 병합된다.** 고칠 것 — `check:spec` 옆(설치 전)에 두고, `wbs.mjs` 는 node 표준 모듈만 쓴다.

### 주의 2 — 재게시 시점
할 일 5 가 「기록 단계」라고만 적었다. 체크는 Step 1(기록, 같은 PR 커밋)에, **재게시는 Step 4 의 main 최신화가 성공한 뒤**여야 한다.
Devicefarm 도 리뷰에서 같은 것을 고쳤다(옛 진행률이 게시된다).

### 주의 3 — 규칙 ① 이 지나가는 언급까지 줍는다
WORKSTREAMS 147행처럼 완료 줄 안에서 앞 PR 을 언급하면(`위 PR #79 의 …`) 그 번호도 「완료」로 잡힌다.
지금은 언급되는 PR 이 전부 실제로 끝난 것이라 해가 없다. 한계를 스크립트 주석에 적어 둔다.
