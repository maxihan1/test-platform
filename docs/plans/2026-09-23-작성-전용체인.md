## 왜

첫 한 바퀴(PR #61 의 #1623 → PR #62, 닫음) 실측.

```
10:08:59 보내기 → 10:11:29 작업방·PR → 10:13:13 요구사항 표 → 10:15:38 케이스 3건
→ 10:19:07 관문 넷 통과          ← 여기까지 약 10분
10:19 ~ [6] 독립 검사 30분 넘게 → 자식이 background 검사를 남기고 먼저 끝남 → 멈춤
```

- 자식 Claude 가 `/tpx` 7단계를 다 탄다. [6] 은 관문 넷과 겹치고 [7] 은 사람이 화면에서 누르니 할 일이 없다
- 초안 PR 은 병합이 안 된다 — 지금 맥의 머지는 `gh pr merge` 만 쳐서 **머지 클릭이 실패할 공산**이 크다
- CI 가 테스트만 바뀐 PR 에도 전부(단위 1319 × 3 · DB · 판별식) 돌리고, `tests/demo` 는 아예 안 돌린다
- pre-push 훅이 오늘 날짜의 검사 기록을 요구해 **맥이 테스트 PR 을 push 하면 막힌다**

**목표 — 올리기부터 main 병합까지 약 13분.**

### 흐름 (바뀐 뒤)

```
화면  보내기 → DRAFT → 자료 올리기 → 줄에 세우기                       (그대로)
맥    집기 · 자료 받기 · 변환                                          (그대로)
맥    git worktree add --detach <폴더> origin/main                     ← 새로. 로컬 브랜치를 안 만든다
자식  claude -p (그 폴더에서) → tpx-author: 자료 → 요구사항 표 → tpx-cases 케이스 → 관문 넷
      background 금지 · git 금지 · 끝나면 결과 요약만 찍는다
맥    바뀐 파일이 tests/** · docs/cases/** 뿐인지 확인 → commit → push HEAD:refs/heads/author-<번호>
      → gh pr create --draft (본문 = 요구사항 표 + 자식 요약) → finish(DONE, prUrl) → 폴더 치우기
화면  끝남 + 머지 버튼 → 사람이 누름 → MERGE 행
맥    gh pr ready → 새 CI 실행을 기다림(실행 번호가 바뀌는 것) → 초록이면 gh pr merge → finish
CI    바뀐 파일이 tests/** · docs/cases/** 뿐 → 가벼운 길 (타입 · K1~K10 · 비밀값 이름 · 바뀐 케이스만 실행)
```

### 게이트 1 에서 정할 것

| 무엇 | 제안 |
|---|---|
| 머지 방식 | **맥이 CI 를 기다렸다 병합** (tpx-merge Step 2 와 같은 「실행 번호」 방식). `gh pr merge --auto` 는 저장소 설정 `allow_auto_merge` 를 켜야 해서(지금 꺼짐) 밖으로 나가는 변경이 생긴다 |
| pre-push 훅의 가벼운 길 | 바뀐 파일이 `tests/**`·`docs/cases/**` 뿐이면 **전체 단위 테스트와 검사 기록 요구를 건너뛰고** `typecheck`·`check:tests` 만. 코드는 한 줄도 안 바뀌어 단위 테스트가 볼 것이 없다 |
| 「테스트만」의 정의 | `tests/**` 와 `docs/cases/**`. 하나라도 섞이면 지금처럼 전부 |
| CI 가벼운 길이 도는 케이스 | **이번 PR 에서 바뀐 `.spec.ts` 만** `--project=desktop`. `tests/demo` 도 바뀐 것은 돈다 |
| 맥의 브랜치 | 로컬 브랜치를 안 만든다(`--detach` + `push HEAD:refs/heads/author-<번호>`) — 쌓이지 않고 `-D` 가 필요 없다 |

## LEARNINGS 근거

- 자식 `claude -p` 가 background 를 남기고 턴을 끝내면 곧 종료다 (2026-09-23) — 프롬프트와 체인에서 막는다
- 보고 한 번을 잃으면 영원히 RUNNING (2026-09-23, 재시도는 PR #61 이 고쳤다) — 새 단계(push·PR·머지)도 같은 재시도 규율
- `gh pr checks --watch` 는 묵은 `skipping` 을 통과로 읽는다 (tpx-merge Step 2) — 머지 대기는 실행 번호로
- 순수 함수 검사는 경계 밖 값을 못 본다 — git·gh 인자는 순수 함수로, 실제 흐름은 병합 뒤 한 바퀴로 본다
