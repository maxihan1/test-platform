## 왜

0단계 시험(`docs/plans/2026-10-07-appium-시험.md`, PR #170)이 「Playwright Test 실행기 + WebdriverIO 연결 fixture」로 실기기 케이스 1건이 8~9초에 통과하고 스크린샷이 남는 것을 확인했다. 디바이스 팜은 사용자가 개발 중이라 이번에는 **맥에 USB 로 연결한 폰(로컬)** 만 한다 (2026-10-07 사용자).

코드 사실 — `packages/kit/src/runtime/test.ts:154` 가 모든 케이스를 `({ page, request })` 로 등록한다. `page` 를 받는 순간 브라우저가 뜨므로 앱 케이스는 이 자리에서 갈라야 한다. 러너는 자식에게 `...process.env` 를 그대로 넘긴다(`apps/runner/src/execute.ts:124`) — 앱 연결 환경값은 러너 코드 변경 없이 내려간다. K8 은 제목 가짓수로 세서(`rules.ts:214`) 프로젝트를 더해도 셈이 안 바뀐다. CI 는 `tests/todo --project=desktop` 만 돌린다 — 앱 케이스는 CI 에서 안 돈다. `webdriverio` 9 는 `require` 입구(`build/index.cjs`)가 있어 러너 이미지의 `require` 쪽에서도 불린다(LEARNINGS 309 걱정 없음). 그래도 **동적 import** 로 둔다 — 브라우저 케이스가 쓰지도 않는 부품을 싣지 않게.

### 명세가 안 정한 것 — 제안 (게이트 1 승인 뒤 할 일 8 이 명세에 옮긴다)

| 무엇 | 정한 것 |
|------|--------|
| 앱 연결 설정 자리 | 러너 환경값. `PLATFORM_APPIUM_URL`(필수) · `PLATFORM_APP`(apk 경로, 필수) · `PLATFORM_DEVICE_UDID`(선택 — 없으면 Appium 이 연결된 한 대를 고른다). `npm run runner:local` 이 `PLATFORM_APPIUM_URL=http://127.0.0.1:4723` 을 싣는다. 대상 서버마다 다른 앱 파일은 admin PR 에서 정한다 |
| 필수 값이 없을 때 | 연결을 열기 전에 던진다 — `Android 앱 케이스를 돌리려면 PLATFORM_APPIUM_URL 이 필요하다`(APP 도 같은 꼴). 컨테이너 러너는 Appium 이 없어 이 문장으로 끝난다 |
| 섞기 오류 문장 | `defineCase` 가 던진다 — `<tcId>: android 는 다른 디바이스와 함께 선언하지 않는다`. 스캐너가 이 문장을 그대로 실패 사유로 싣는다(`scanner.ts:81`) |
| 없는 인자를 쓰면 | 앱 케이스의 `page` · 브라우저 케이스의 `driver` 는 꺼내는 순간 던진다 — `<tcId>은 Android 앱 케이스라 page 가 없다 — driver 를 쓴다` · `<tcId>은 브라우저 케이스라 driver 가 없다` |
| 사람이 읽는 라벨 | `android` → `Android 앱` (kit `platformLabel`) |
| 케이스끼리 섞이지 않게 | Appium 기본(연결마다 앱 데이터 초기화)을 그대로 쓴다 — 0단계에서 두 번째 실행도 빈 장바구니로 시작했다 |
| 연결 닫기 | 케이스가 끝나면(통과 · 실패 · 예외) kit 이 닫는다. **러너가 끊으면(중단 · 제한 시간) 못 닫는다** — Appium 기본 60초 뒤 풀리거나 다음 연결이 가로챈다(0단계 실측). 고치는 것은 다음 PR |
| 제한 시간 | 기본 30초 그대로. 0단계 최대 13초(앱 설치 포함) |
