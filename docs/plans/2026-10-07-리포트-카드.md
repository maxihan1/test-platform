## 왜

사용자가 「리포트 가독성 — 상단 요약, 실패 먼저」를 UI 개편 열 가지 중 하나로 들었고(2026-10-07), 시안 B-report(증거 카드형)를 고른 뒤 C판으로 다듬었다.
지금 결과 화면은 케이스 줄만 받고 사전조건 · 절차 · 확인은 「상세」를 눌러 **한 건씩** 받는다. 실패 30건이면 30번 따로 묻고, 케이스별 「이 실행 기준 최근 판정」은 어디서도 주지 않는다 — 그래서 통로를 하나 낸다.

**실제 자료에 먼저 돌려 봤다** (§1 규칙 7, 로컬 compose DB · 읽기만).
- 실행은 2건뿐이다. RUN 20799(데모마켓 · qa · FN) 확정 2 · 통과 2 → 통과율 100%. RUN 20397(코디세이 · prod · FN) **확정 0 · 미확정 1 → 통과율 분모가 0** 이다
  → 분모 0 은 실제로 있는 경우다. 「—」와 「확정 항목 없음」으로 그린다(아래 제안 3)
- 실패 항목 · 최근 흐름을 그릴 실제 자료가 없다 → 카드 · 최근 흐름 · 연속 실패 수는 DB 검사 자료와 가짜 응답 화면 실측으로만 확인한다. 실기기 확인은 게이트 2 의 확인 방법에 「데모마켓에서 일부러 깨진 케이스 하나를 돌려 본다」로 싣는다
