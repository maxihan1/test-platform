# 테스트 작성 화면 — 결정 다섯

등급: 0 (이 문서 자체) · 갈래: 없음 · 2026-09-21

> **이건 할 일 계획서가 아니다. 보류 중인 설계 기록이다.**
> `docs/plans/` 의 다른 파일과 달리 「할 일 N개」 서식을 쓰지 않는다.
> 만들 때가 되면 그때 `/tpx` 가 계획서를 따로 쓴다 — 이 문서는 **그 계획서의 입력**이다.

**무엇을 기다리나** — 어드민 화면 전면 리뉴얼 (2026-09-21 기준 PR #45 · 작업방 `web-redesign`).
화면 자리·부품이 그 결과에 달려 있어 리뉴얼이 끝난 뒤에 착수한다.

**어디서 왔나** — 2026-09-19 대화에서 승인된 4단계 계획의 **3단계(화면)**.
1단계(`tpx-cases` 스킬, PR #37·#38)와 2단계(작성 에이전트, PR #41)는 병합이 끝났다.
**그 계획서 원본은 이 저장소에 없다** (세션 계획 파일이다). 1·2단계의 결정 근거를 되짚어야 하면
PR #37·#41 의 코멘트가 저장소 안에 남은 정본이다.

---

## 왜 적어 두나

구조를 **건바이건으로 다섯 건** 정했는데 그 결정이 **대화에만 있었다.**
리뉴얼이 끝날 때쯤이면 그 대화가 없다. 적어 두지 않으면 같은 논의를 처음부터 다시 한다.

**결정보다 근거가 중요하다.** 무엇을 정했는지만 남기면 다음 사람이 뒤집을지 말지를 판단할 수 없다.
그래서 건마다 「왜」와 「무엇을 재서 그렇게 판단했는지」를 같이 적는다.

## 만들려는 것 — 한 그림

```
[화면]  테스트 작성  (최상위 자리 하나 — 몇째인지는 리뉴얼 뒤에 정한다)
   │
   ├ 기획서 넣기 ──────→ 대기줄: 작성 요청
   │                         ↓ 맥이 집는다
   │                   [맥 터미널 — 눈에 보이게 돈다]
   │                     ├ 케이스와 테스트 코드 생성
   │                     ├ 관문 넷 (3회 연속 실행 포함)
   │                     ├ 진행을 단계마다 대기줄에 보고
   │                     └ 초안 PR 생성
   │                         ↓
   ├ 결과 ✅/❌ · 실패한 줄 · 실패 화면 사진 · PR 링크
   │
   ├ 「다시 돌려보기」 ─→ 대기줄: 재실행 요청 (값을 바꿔서)
   │
   └ 「머지」 ─────────→ 대기줄: 머지 요청
                             ↓ 맥이 집는다
                       초안 해제 → GitHub 검사 → 초록이면 머지
                             ↓
                       머지 완료 · 그 뒤로도 GitHub 이 매번 지킨다
```

**사람 게이트는 없어지지 않는다. 터미널에서 버튼으로 자리만 옮긴다.**

## 건 1 — 머지 전 테스트를 **맥에서** 돌린다

### 무엇을 정했나

맥이 **러너와 똑같은 명령**으로 돌리고, 결과를 화면으로 올린다.

### 왜 러너가 아니라 맥인가

러너와 어드민이 테스트 파일을 **체크아웃된 폴더 통째로 읽기 전용 마운트**해서 본다
(`docker-compose.yml` 의 `./tests:/tests:ro`, admin·runner 둘 다). **브랜치를 고르는 자리가 없다.**
그래서 **아직 머지 안 된 코드는 지금 화면에서 못 돌린다.**

러너가 브랜치를 보게 하려면 러너가 git 을 알아야 하고 마운트가 바뀐다 — 도커 구성과 러너 계약이
흔들리는 3등급 변경이다. **맥은 이미 그 코드를 들고 있으므로 거기서는 아무것도 안 바꿔도 된다.**

### 어떻게 되나 — 러너가 하는 일이 그게 전부다

러너는 `apps/runner/src/execute.ts` 에서 자식 프로세스 하나를 띄우는 것이 전부다.
맥도 같은 명령·같은 환경변수를 쓰면 **같은 판정 배관을 탄다.**

| 필요한 것 | 지금 어떻게 되나 |
|---|---|
| 결과 (통과·실패, 문장별 판정) | kit 리포터가 **stdout 한 줄**로 낸다 (`packages/kit/src/runtime/reporter.ts`) |
| **실패한 줄 번호** | kit 이 스택에서 뽑아 **결과에 이미 실려 온다** (`runtime/callsite.ts` → `types.ts` 의 `StepResult.line`) |
| **실패 지점 코드** | 발췌가 **이미 본문을 인자로 받는 순수 함수**다 (`apps/admin/src/catalog/source.ts` 의 `excerpt`) |
| **스크린샷** | 실패하면 **자동으로 찍힌다** (`runtime/step.ts`) |

### 이 건에서 새로 만드는 것 — 셋

**① 스크린샷 파일을 서버로 보낸다.** 러너와 어드민은 같은 볼륨을 봐서 경로만 주고받으면 되는데,
맥은 다른 기계다. 파일 자체를 올려야 한다.

**② 테스트 소스 본문을 같이 보낸다.** 어드민이 지금 발췌를 만들 때 **자기 `/tests` 폴더에서
파일을 읽는데**(`source.ts` 의 `readExcerpt`), **머지 전 파일은 거기 없다.**
본문을 받아 위의 순수 함수에 그대로 넣으면 된다.

**③ 스크린샷이 어느 폴더로 갈지 정한다.** `runtime/artifacts.ts` 가 경로를
`runs/{runId}/{historyId}/{seq}.png` 로 가르는데, 그 둘이 없으면 **`0`/`0` 으로 떨어진다.**
지금 그 번호는 **DB 실행 기록의 행 번호**인데 머지 전 실행에는 그 행이 없다.
**정하지 않으면 모든 작성 요청이 `runs/0/0/` 에 겹쳐 쓰고 직전 요청의 사진을 덮는다.**
대기줄 행 번호를 쓰는 것이 가장 가깝지만 **아직 안 정했다.**

> **러너도 `docker-compose.yml` 도 안 건드린다.**

### 「같은 결과」라고까지는 말하지 않는다

같은 명령·같은 리포터를 타므로 **판정 배관은 같다.** 다만 **브라우저가 같지 않다** —
러너는 리눅스 이미지의 Chromium 을 쓰고(`apps/runner/Dockerfile`) 맥은 macOS 쪽이다.
`docker-compose.yml` 머리주석이 「이미지 태그와 `@playwright/test` 버전은 정확히 같아야 한다」고
적어 둔 그 자리다. **크기·겹침·줄바꿈에 걸리는 판정은 갈릴 수 있다.**
그리고 맥에서 처음 돌리려면 브라우저 바이너리를 한 번 받아야 한다.

### 남겨 둔 아쉬움

**맥이 꺼져 있으면 아무것도 안 된다.** 요청은 대기줄에 쌓였다가 켤 때 처리된다.
없애려면 러너가 브랜치를 보게 해야 하고 그건 위에 적은 3등급 변경이다.
**지금은 그 값이 그 비용만큼 크지 않다고 판단했다.**

## 건 2 — 머지는 **사람이 결정하고 맥이 실행**한다

### 무엇을 정했나

화면의 머지 버튼이 대기줄에 **「머지 요청」**을 넣는다. 맥이 집어서 친다.

```
초안 해제 → 검사가 새로 도는 것을 확인 → 초록이면 머지
```

절차는 **새로 설계하지 않는다.** `tpx-merge` 스킬의 Step 2·3 에 실측으로 박혀 있는 것을 옮긴다.

> ★ **검사 결과를 「지금 초록인가」로 읽으면 안 된다.** 초안일 때 남은 묵은 「건너뜀」 딱지를
> 통과로 읽어 **검사가 한 번도 안 돈 채 병합된다.** 실행 **번호가 바뀌는 것**을 봐야 한다.
> 2026-09-18 실측이고 `tpx-merge` 에 로그까지 그대로 적혀 있다.

### 왜 서버가 아니라 맥인가

서버가 직접 치려면 **서버에 GitHub 토큰을 심어야 한다.** 그 토큰은 **저장소를 고칠 수 있는 열쇠**다.
2단계에서 「서버에 GitHub 배관과 토큰이 아예 불필요」를 이득으로 골라 맥을 택했는데,
여기서 토큰을 심으면 **그 결정을 되돌리는 것**이다.

맥에는 `gh` 가 **이미 로그인돼 있다.** 새로 관리할 비밀값이 0개다.

### 오해하기 쉬운 자리

**에이전트가 머지를 판단하지 않는다. 손일 뿐이다.**
사람이 화면에서 눌러야만 요청이 생긴다. 게이트가 사라지는 것이 아니라 **자리를 옮기는 것**이다.
그 게이트는 2026-09-17 에 두 번 난 사고(먼저 병합돼서 뒤 커밋이 누락)를 막으려고 생겼다.

## 건 3 — 대기줄은 **DB 표**, 진행은 **두 층**

### 왜 DB 표인가

1. 제품의 나머지가 전부 DB 에 있어 **화면이 읽는 길이 이미 깔려 있다**
2. 진행을 화면이 주기적으로 읽어 그리는 패턴이 **이미 돌고 있다**
   (`apps/admin/src/web/RunResult.tsx` 가 2초마다 진행을 읽어 모달에 그린다)
3. 파일로 하면 상태 갱신과 동시 접근을 **손으로 만들게 된다**

### 대기줄이 실어 나르는 것

| 방향 | 무엇 |
|---|---|
| 화면 → 맥 | 작성 요청 · 재실행 요청 (값을 바꿔서) · 머지 요청 |
| 맥 → 화면 | 상태 · 결과 JSON · 스크린샷 파일 · 테스트 소스 본문 |

### 맥 스크립트는 터미널에서 눈에 보이게 돈다

**숨은 데몬으로 두지 않는다.** 한도를 얼마나 쓰는지와 지금 무엇을 하는지가 사람 눈에 보여야 한다.

### 진행이 두 층인 것을 놓치지 않는다

| 층 | 무엇 | 지금 |
|---|---|---|
| 아래 — **테스트 절차** | 「할 일을 한 건 만든다」 2/2 | **이미 있다.** kit 이 절차마다 한 줄을 흘리고(`runtime/progress.ts` 의 `알린다`) 러너가 모은다(`execute.ts` 의 `진행을_모은다`) |
| 위 — **작업 단계** | 「요구사항 표 만드는 중」 → 「케이스 2건째」 → 「관문 3 도는 중」 | **없다. 새로 만든다** |

아래층은 공짜로 따라오고, **위층만 만들면 된다.**

## 건 4 — **GitHub 이 생성된 테스트를 매번 돌린다**

### 지금 무엇이 비어 있나

`.github/workflows/ci.yml` 에 **`tests/**` 를 실행하는 단계가 없다.**

> **오해하기 쉬운 자리** — 「테스트 단계가 없다」가 아니다. 단위 테스트 단계는 **있고**
> 세 번 돈다. 없는 것은 **생성된 테스트(`tests/**`)를 실제로 돌리는 단계**다.
> 이걸 구분 안 하면 이미 있는 단계를 중복으로 또 만든다.

그리고 `vitest.config.ts` 가 `tests/**` 를 **안 담는다.** `exclude` 로 뺀 것이 아니라
`include` **허용목록**(`apps/**`·`packages/**`·`scripts/**`)에 애초에 없다 — 지우러 오면 지울 줄이 없다.
그 파일 주석이 이유를 적어 뒀다. 「`tests/**` 는 Playwright 전용이라 Vitest가 집어가면 안 된다」.

**결과적으로 생성된 테스트 코드는 모양만 검사받고 한 번도 실행되지 않은 채 `main` 에 들어간다.**

### 실측

`TODO-003` 의 기대값을 뒤집어 「할 일이 하나도 없는데 남은 개수가 보인다」고 주장하게 만들었다.

| | 결과 |
|---|---|
| 검사 단계 전부 | **EXIT=0 (초록)** |
| 실제로 돌려 보면 | **EXIT=1 — 검증 실패** |

**전부 초록이라 머지가 막히지 않는다.**

### 머지 시점보다 **그 뒤**가 더 중요하다

케이스가 `main` 에 들어가면 그때부터 **회귀 테스트**다.
누가 화면을 고쳐 그 케이스가 깨지는 날, **지금 구조로는 아무도 모른다.**
검사가 테스트를 돌리면 그 수정을 올리는 순간 빨간불이 떠서 머지가 막힌다.

**맥이 돌린 것으로 갈음하지 않는다** — 자기가 쓴 코드를 자기가 돌린 것이라 독립이 아니고,
무엇보다 **만든 그날 한 번**일 뿐이다.

### 이 건이 실제로 필요로 하는 것 — 망 도달성만이 아니다

| 무엇 | 왜 |
|---|---|
| **대상 주소** | `playwright.config.ts` 가 `PLATFORM_BASE_URL` 에서 받는다. 안 주면 케이스가 갈 곳이 없다 |
| **입력값** | `runtime/inputs.ts` 가 `PLATFORM_PARAMS` 를 읽고, 기본값 없는 필수 칸에서 **던진다.** 케이스별 입력값은 DB 에 있는데 검사기는 DB 를 모른다 |
| **브라우저** | 검사 기계에는 바이너리가 없다. 한 번 받아야 한다 |
| **망 도달성** | 지금 대상은 **인터넷에 열린 연습용 주소**라 닿는다. **사내망 화면이 대상이 되면 못 들어간다** — 그때 다시 정한다 |

### ★ 등급이 튈 수 있다

`.github/workflows/**` 만 고치면 **2등급**이다. 그런데 위의 「대상 주소」 때문에
`playwright.config.ts` 를 **한 줄이라도** 건드리면 그 파일은 **3등급(COMPOSE)** 이라
게이트 0 이 붙는다. **먼저 재 보고 시작한다.**

### 이 건은 따로 먼저 한다

화면을 안 만들어도 혼자 값어치가 있고 이 문서의 나머지와 독립이므로 별도 작업으로 뺀다.

## 건 5 — **권한으로 제어**한다

### 정한 것

| 새 할 일 | 최소 등급 | 왜 |
|---|---|---|
| 테스트 작성 · 재실행 | **operator** | 결과가 **초안 PR** 이다. 마음에 안 들면 버리면 그만이라 되돌리기 쉽다. 지금 「실행」과 같은 무게 |
| **머지** | **admin** | **저장소를 영구히 바꾼다.** 되돌리려면 사람이 손으로 해야 한다 |

**둘에 같은 등급을 주면 「실행할 수 있는 사람 = 저장소를 고칠 수 있는 사람」이 된다.**

### ★ 그런데 지금 서버는 이걸 표현할 수 없다 — 이게 이 건의 진짜 일이다

화면과 서버가 **같은 모양이 아니다.**

- **화면은 표다.** `apps/admin/src/web/role.ts` 가 `할일` 마다 최소 등급을 적는다.
  여기에 두 줄 더하는 것은 그대로 된다
- **서버는 표가 없다.** `apps/admin/src/auth/gate.ts` 는 **경로와 방식으로만** 가른다 —
  `/api/settings` 로 시작하면 admin, 나머지는 읽기면 viewer, 그 밖은 **전부 operator** 다

그래서 **`/api/authoring/merge` 같은 경로는 무조건 operator 가 된다. admin 으로 만들 길이 없다.**

**오늘 둘이 맞아 보이는 것은 우연이다.** 기존 할 일 여섯은 등급 배정이
「읽기=viewer / 그 밖=operator / 설정=admin」과 우연히 일치한다.
**머지가 그 우연이 깨지는 첫 사례다.**

> 화면이 버튼을 안 그리는 것은 **편의이지 방어가 아니다.** 이대로 만들면
> **실행 등급이면 누구나 머지 통로를 직접 찌를 수 있는 저장소**가 된다 —
> 이 표가 막으려고 쓴 바로 그 상태다.

**어떻게 풀지는 아직 안 정했다.** 서버에 경로→등급 표를 두는 길과, 갈리는 자리를 하나 더 만드는 길이 있다.
**착수할 때 정한다.** 그리고 서버 권한 장(`docs/spec/도메인/인증.md` 계열)이 「갈리는 자리는 셋」이라고
적어 뒀으므로 **명세도 같이 움직인다.**

### 그리고 새 통로는 등록해야 한다

`apps/admin/src/auth/scope.ts` 의 라우트표에 **없는 경로는 「모르면 막는다」로 떨어져 거부**된다.
새 작성 통로를 전부 등록하지 않으면 **모든 요청이 막히고 원인이 권한처럼 안 보인다.**

### 화면 자리

작성은 버튼 하나가 아니라 **대기줄·진행·결과·머지를 다 담는 화면**이라 **자기 자리를 갖는다.**
그리고 「케이스」 화면은 **이미 있는 것을 보는 곳**이고 작성은 **아직 없는 것을 만드는 곳**이라 성격이 다르다.

**몇째 자리인지는 정하지 않는다** — 아래 「아직 안 정한 것」 참조.
지금 자리는 `apps/admin/src/web/layout.ts` 의 `자리목록()` 이 만드는데
**기본이 셋**(케이스·실행 기록·그래프)이고 **설정은 admin 에게만** 붙는다.
그래서 operator 가 보는 자리는 셋이다. 그리고 「그래프」는 Grafana 로 나가는 **바깥 링크**라
성격이 다르다. **최상위 자리 아래에 이차 탭을 두지는 않는다** (지금 그런 구조가 없다).

## ★ 시작 전에 풀어야 할 것 — **셋이다. 하나가 아니다**

「막힌 것은 하나」로 읽고 출발하면 화면을 만들다 **선언 안 한 계약 변경**이 튀어나온다.

### ① 명세가 「안 만든다」고 적어 둔 행

`docs/spec/공통/1-제품과-구조.md` 의 영구 제외 표에 이 행이 있다.

> 화면에서 테스트 코드를 작성·편집하는 기능 |
> §3.1의 "코드가 진실의 원천"과 정면으로 충돌한다.
> 화면에서 고친 코드와 저장소의 코드가 갈리는 순간 무엇이 진실인지 아무도 모르게 된다

**행의 글자가 이 설계를 금지로 읽는다.** 그런데 **적힌 이유는 이 설계에 안 맞는다** —
이 설계에서는 **화면이 코드를 들고 있지 않다.** 화면은 요청만 넣고, 코드는 맥이 만들어
**PR 로 저장소에 올린다.** 저장소가 계속 유일한 진실이다.

**기준은 남기고 범위만 좁힌다** (`CLAUDE.md` §2.7 ②). 금지되는 것은 **화면이 코드를 직접 들고 고치는 것**이다.

### ② 「자리 넷」이 명세에 글자로 박혀 있다

`docs/spec/공통/5-화면공통.md` 가 **「자리 넷」을 여러 군데에 글자로** 적어 뒀고
현재 상단 띠의 그림까지 들어 있다. 코드 주석도 같은 말을 한다
(`apps/admin/src/web/layout.ts`).

**자리를 하나 더하는 것은 화면 코드 변경이 아니라 명세 변경이다.**
§2.7 ④ 대로 `docs/DESIGN.md` 와 `docs/design-mockup.html` 도 같이 움직인다.

### ③ 서버 권한 모델 (건 5 참조)

「머지 = admin」을 표현할 수 없다. 서버 권한 장도 같이 움직인다.

### 그리고 2단계에서 넘긴 명세 작업이 이 작업으로 와 있다

목록의 **정본은 PR #41 의 `[2/7]` 코멘트**다. 새 도메인 장 · 데이터 모델의 새 표 ·
색인 네 곳(특히 **라우터 표**) · 컨텍스트 지도 · 유비쿼터스 언어 · 인증 장의 최소 등급 행 ·
`WORKSTREAMS` 킥오프 · `WORKFLOW` · 표면 판정 스크립트의 미분류.
**개수를 여기 손으로 적지 않는다** (`CLAUDE.md` §2.7 ⑤) — 세는 일은 그 코멘트를 열어서 한다.
그 표의 첫 행(영구 제외 표)은 위 ①에서 따로 다뤘다.

### ⚠ 리뉴얼과 겹치는 파일이 있다

**「명세는 리뉴얼과 안 겹치니 미리 해 두자」고 판단하면 안 된다.**

2026-09-21 기준 PR #45 는 **빈 시작 커밋 하나뿐이라 무엇을 건드릴지 아직 알 수 없다.**
그리고 제목이 「**사이드바·헤더·푸터**를 갖춘 새 디자인」이다 —
`docs/spec/공통/5-화면공통.md` 가 바로 **맨 위 띠·자리·좁은 화면** 장이므로
**상단 띠가 사이드바가 되면 그 장은 반드시 다시 쓰인다.**

| 먼저 해도 되나 | 파일 |

| ✅ 된다 | ③ 서버 권한 — `apps/admin/src/auth/**` · 인증 명세 |

## 아직 안 정한 것

다음 사람이 정해야 하는 것들이다. **지금 정하지 않은 것은 판단 재료가 부족해서이지 잊어서가 아니다.**

- **화면에서 몇째 자리인가.** 리뉴얼이 상단 띠를 사이드바로 바꾸면 「몇째」라는 말 자체가
  성립하지 않을 수 있다. **자기 자리를 갖는다는 것만 결정이고 위치는 리뉴얼 뒤에 정한다**
- **서버 권한을 어떻게 표현하나** (건 5). 경로→등급 표를 두는 길과 갈리는 자리를 하나 더 만드는 길
- **스크린샷 폴더의 번호를 무엇으로 하나** (건 1 ③). 안 정하면 사진이 서로를 덮는다
- **상태를 몇 개로 두나.** 실제로 화면에 무엇을 보여야 충분한지는 **화면을 그려 봐야 안다**
- **재실행에서 무엇을 바꿀 수 있게 하나.** 지금 실행 화면의 입력값 부품을 쓸 수 있는지는 리뉴얼 뒤에 본다
- **한 번에 몇 건까지 대기줄에 넣게 하나.** 맥이 한 번에 하나씩 처리하므로 상한이 필요할 수 있다
- **실패한 작성 요청을 어떻게 치우나.** 다시 시도인지, 버리는 것인지, 둘 다인지

## 이 문서를 어디서 가리키나

**적어 두기만 하면 못 찾는다.** 수 주 뒤 세션이 읽는 자리에 한 줄씩 걸어 뒀다.

- `docs/WORKFLOW.md` — 지금이 어느 단계이고 무엇이 남았는가
- `docs/WORKSTREAMS.md` — **세션이 명세보다 먼저 읽는 자리** (`CLAUDE.md` §2.7 ④)

**리뉴얼이 끝나 이 작업을 시작하면 그 두 줄을 「진행 중」으로 고치고, 끝나면 뗀다.**
