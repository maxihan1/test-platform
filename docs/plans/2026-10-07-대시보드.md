## 왜

사용자가 「대시보드 페이지가 필요하다 · 사이드바에 넣어 달라」고 했고, 대시보드 = 테스트 결과 · Grafana = 운영 시간으로 갈랐다(2026-10-07).
서비스마다 `/api/runs` 를 부르면 서비스 수만큼 요청이 늘고 회차 접기를 화면이 다시 짜게 돼 통로 하나로 모은다.

**실제 자료에 먼저 돌려 봤다** (§1 규칙 7, 로컬 compose DB · 읽기만, `/tmp` 아닌 작업 임시 폴더의 시험 질의).
- 실행이 2건뿐(UI · FN, 2026-10-03 · 10-06)이고 접은 판정은 통과 2 — 신규 실패 0 · 히트맵 0. **자료가 적은 상태가 흔하다** → 빈 칸 화면을 시안만큼 다듬는 할 일을 넣었다(할 일 7 · 8)
- **시간대가 결과를 바꾼다** — 10-06(UTC) 에 시작한 실행이 `Asia/Seoul` 로 자르면 10-07 칸에 든다. 하루 경계를 서버 시간대로 두면 화면의 「오늘」과 어긋난다
- 작성 커버리지는 한 서비스 99.4%(171/172, 2026-10-05 재실행) — 0% 나 100% 에 붙지 않는다
- 경계값(신규 실패 · 히트맵 상위 · 빈 창)은 실제 자료로 못 덮어 DB 검사의 가짜 자료(접두사 `XDQ`)로 덮는다
