# 화면 리뉴얼 ① — 명세 개정과 디자인 언어

등급: 3 · 갈래: WS-E · 2026-09-21

## 도메인 정리

바운디드 컨텍스트를 건드리지 않는다. **화면(WS-E)의 껍데기와 시각 언어만** 바꾼다.

| 영향 | 무엇이 흔들리나 |
|------|---------------|
| WS-E 화면 | 전 화면의 껍데기와 토큰 |
| WS-D 리포팅 | 증적 문서가 화면 토큰을 복사해 둔다 (`reporting/html.ts`). `styles.test.ts` 가 13개를 대조한다 |
| WS-A 카탈로그 | 이번 PR 에서는 안 건드린다. 상세·이력은 ② 로 미룬다 |

관련 절 — `공통/5-화면공통` §8 · `공통/1-제품과-구조` §2 · `공통/7-데모와-완료` · `DESIGN.md`.

**두 PR 로 쪼갰다.** 이 PR 은 「화면이 같은 일을 다르게 보이게」, 다음 PR 은 「화면이 새 일을 하게」다.
경계가 여기인 이유 — 껍데기와 토큰은 전 화면을 한 번에 훑고, 파라미터·상세·이력은 카탈로그와
실행 컨텍스트를 새로 잇는다. 섞으면 게이트 2 에서 무엇 때문에 깨졌는지 못 가른다.

## 왜

지금 화면은 좌우 여백이 통째로 비고, 아래가 끊기고, 맨 위 띠와 본문이 같은 면 위에 붙어
어디까지가 껍데기인지 눈으로 안 갈린다. 사용자가 전면 리뉴얼을 요청했고
목업 다섯 판을 주고받아 게이트 0 에서 계약 변경을 승인받았다.

**밝은 베이지 한 톤이 「사내에서 대충 만든 어드민」으로 읽히던 원인이었다** — 껍데기와 내용이
같은 밝기라 경계가 1px 선뿐이었다. 사이드바를 짙게 눌러 대비를 만든다.

목업은 `deep.html` 로 확정했고 디자인 리뷰 지적 여덟을 전부 반영해 실측으로 재검증했다.
명암비 24짝 미달 0건 (어두운 면 위 글자 셋 13.14 · 6.38 · 7.85 포함).
