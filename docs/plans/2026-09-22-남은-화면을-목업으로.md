# 어드민 화면 전면 리뉴얼 ③ — 헤더 자리를 채우고 남은 화면 넷

등급: 3 · 갈래: WS-E · 2026-09-22

## 도메인 정리

| BC | 무엇을 건드리나 | 관련 절 |
|---|---|---|
| Execution | `GET /api/runs` 가 `q`·`state`·`env` 를 받고 응답에 `summary` 를 더한다 | 실행 §7 · §8.7 · 공유계약 §7.1 |
| Catalog | 건드리지 않는다 | — |
| Reporting | 건드리지 않는다 | — |

**경계를 넘지 않는다.** 실행 목록과 그 집계는 둘 다 `test_run`·`run_item` 에서 오므로 **실행 쪽이 낸다.**

## 왜

PR① 이 껍데기를 만들면서 `Shell` 에 「화면이 제목과 주 행동을 넘기는 통로」(`header`)를 뚫었다.
**그런데 부르는 곳이 하나도 없다** — `main.tsx:144` 가 `header` 를 안 준다.
그래서 화면마다 제목을 **자기 본문 안**에서 그리고, 처음 지적하신
「헤드와 메인이 분리 안 돼 있다」가 **절반만 해결된 채로** 남아 있다.

PR② 는 케이스 목록만 손봤다. 화면 파일 24개 중 **7개**만 바뀌었다.
확정 목업(`docs/design-mockup.html`)은 **일곱 화면**을 그려 뒀는데 그중 **둘**만 옮겨졌다.

### 세어 본 것

| 무엇 | 실제 |
|---|---|
| `집계띠` 를 쓰는 화면 | `CaseList` 하나 |
| `Shell` 의 `header` 를 넘기는 곳 | **0** |
| 목업이 그린 화면 | 7 (케이스 목록 · 실행 기록 · 실행 결과 · 모달 · 설정 · 로그인 · 375px) |
| 그중 옮겨진 것 | 2 (케이스 목록 · 모달) |

### 헤더는 통로를 뚫지 말고 **화면이 직접 그린다**

`Shell` 의 `header` prop 을 채우려면 화면마다 제목·부제·행동을 **위로 올려 보내야** 한다.
부제는 동적이고(`모두 42건`) 행동도 상태를 탄다(`스캔하는 중`) — 올려 보내려면 배선이 늘어난다.

**그럴 필요가 없다.** 목업의 `.main` 은 `.head` 와 `.body` 를 세로로 쌓은 것뿐이다.
화면이 자기 첫 자식으로 `<화면머리>` 를 그리면 같은 결과가 나오고 배선이 0이다.

- `Shell` 은 `.main` 을 세로 flex 로 두기만 한다
- **쓰는 곳이 없는 `header` prop 은 뺀다.** 죽은 통로를 남기면 다음 사람이 「왜 아무도 안 쓰지」를 또 판단한다

### BLOCKER 1 — 집계 띠를 「일반화」하면 **판정 색 보호가 풀린다** (eng)

지금 `Summary.tsx` 는 칸 이름이 타입에 박혀 있고 색이 라벨과 1:1로 묶여 있다.

```
type 칸이름 = '전체' | '통과' | '실패' | '미실행';
{ 라벨: '전체', 색: '' } · { 라벨: '통과', 색: 'p' } · { 라벨: '실패', 색: 'f' } · { 라벨: '미실행', 색: 'n' }
```

**그 묶음이 「판정 색은 판정에만」을 타입으로 강제하고 있다** (DESIGN.md 원칙 1 · spec-review F8).
할 일 5 의 REFACTOR 가 「칸 목록을 받도록 푼다」고만 적었다 — 그대로 풀면
`실행 횟수`·`평균 소요` 같은 **판정이 아닌 칸에 판정 색을 칠할 수 있게 된다.**

**고칠 것** — 칸을 `{ 라벨, 값, 판정?: ItemStatus, 부제? }` 로 두고 **색은 `판정` 이 있을 때만** 나오게 한다.
그러면 판정 아닌 칸에 판정 색이 **타입에서 막힌다.** (9/10)

### 주의 1 — `state=failed` 가 총건수를 거짓으로 만들 수 있다 (eng)

`failed` 는 「실패 항목이 하나라도 있는 실행」이라 **집계 조건**이고 `HAVING` 이 필요하다.
그런데 지금 질의는 `count(*) OVER ()` 로 총건수를 같은 줄에서 뽑는다.

**`HAVING` 뒤에 `OVER ()` 가 무엇을 세는지 실측해야 한다.** 틀리면 `total` 이 거짓이 되고
**빈 쪽이 생긴다** — §8.7 「고칠 것 5」가 이름 붙여 막아 둔 바로 그 함정이다.
할 일 1 의 RED 에 「거른 뒤 `total` 이 실제 걸린 수와 같다」를 넣는다. (8/10)

### 주의 2 — 평균 소요가 **도는 실행**을 어떻게 세는지 안 정했다 (eng)

`finished_at` 이 `null` 인 실행은 소요가 없다. 빼야 하는데, 빼면 「42회 중 41회의 평균」이 된다.
**부제에 그 사실을 적지 않으면 숫자가 미묘하게 틀린 채로 읽힌다.** (9/10)

### 주의 3 — 그물이 없는 화면을 통째로 다시 그린다 (eng)

### 주의 4 — `.head` 의 조상이 바뀐다 (eng)

### 주의 6 — 목업의 「증적 문서 받기」 버튼이 **명세에 없는 행동**이다 (design)

목업의 실행 기록 머리에 `증적 문서 받기` 버튼이 있다 (`design-mockup.html:672`).
그런데 **증적은 실행 하나마다 만든다** (§8.4 · §8.3 의 RUN 머리).
목록 화면에서 무엇을 받는다는 건지 명세에 없다 — **목업이 답한 적 없는 자리다.**

그대로 옮기면 누르면 아무 일도 안 하는 버튼이 생기거나, 없는 기능을 만들게 된다.
**빼거나 명세에 있는 행동으로 바꾼다.** (9/10)

### 주의 7 — 빈 상태가 한 갈래뿐이다 (design)

검색·거르개가 생기면 「비었다」가 **세 갈래**가 된다 — 아직 안 돌렸다 / 검색에 안 걸렸다 / 거르개에 안 걸렸다.
지금 문장은 하나뿐이라 검색한 사람에게 「아직 실행한 기록이 없습니다」라고 말하게 된다.
**케이스 목록이 §8.1 에서 이미 세 갈래로 가른 그 문제다.** (9/10)
