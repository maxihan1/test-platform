## 왜

사용자 요청 (2026-09-24). ① 여러 사람이 쓰면 한 줄에 서서 기다린다 — 서비스별로 따로 돌린다
② 모델을 Opus 로 정하고 속도·정확성 균형으로 effort `high` ③ 장애 때 Sonnet 으로 자동 전환
④ 새 모델을 쓰려면 CLI 가 최신이어야 한다 — `opus` 별칭이 가리키는 모델은 CLI 판이 정한다
⑤ PR #68 게이트 2 가 넘긴 격리 후속(고객사 설치 전 필수)과 finish prUrl 좁히기를 합친다.

**격리가 병렬의 전제이기도 하다** — 지금 작업방은 `/repo` 의 git worktree 라 두 건이 동시에 `/repo/.git` 에
`worktree add`·`fetch` 하면 잠금이 겹친다. 사본으로 가면 `/repo` 에 쓰는 일은 병합 뒤 당기기 하나만 남고 그것은 직렬로 묶는다.

**새로 찾은 구멍 (계획 중)** — 에이전트가 root 가 되면 자식이 만든 파일을 **링크를 따라** 읽는 순간이 위험해진다.
자식이 `docs/cases/<서비스>.md` 를 `/proc/1/environ` 으로 링크하면 PR 본문에 토큰이 실린다. 링크는 거부한다(할 일 5).
