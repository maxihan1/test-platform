## 도메인 정리

작성 BC. 바뀌는 곳은 에이전트 스크립트(`scripts/authoring-run.ts` · `scripts/authoring-progress.ts`)와 명세 산문(도메인/작성 §3.6 · §7).

화면은 `limitSec`·`tokens` 를 progress 에서 그대로 읽으므로 코드가 안 바뀐다(주석 한 줄만).

## 왜

- 5872 가 훑기 25분 → 케이스 → 관문 1·3 을 90/90 까지 통과한 23:29 에 관문 2 를 시작했고 23:30:48 에 60분 제한에 걸렸다. 결과 0, 작업방은 안 남는다(이어하기 없음).
  사용자가 한도를 **120분**으로 정했다(2026-09-28 `/tpx` 인자).
- 상세 화면의 「만든 케이스 파일」이 늘 0. `authoring-rules.ts:165` 가 자식에게 `tests/<폴더>` 에 쓰라고 하고 `authoring-run.ts:248` 은 `<트리>/<폴더>` 를 센다.
- 진척 토큰이 715 로 보였는데 같은 요청의 캐시 읽기는 1,570만. 명세가 `tokens` 를 「입력+출력」으로 정했기 때문이다 — 사용자가 캐시 읽기를 넣기로 했다.
  캐시 쓰기는 요청에 없어서 뺀다(게이트 1 에서 볼 것).
