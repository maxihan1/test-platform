## 왜

요청 하나는 120분이라 큰 기획서는 한 번에 못 덮는다. 5877(데모마켓)은 172개 중 48개만 케이스가 됐고 124개가 `다음 요청` 으로 표에 남았다(`docs/cases/MKT.md`).
원장 대조(PR #119)와 셈(PR #120)이 남은 것을 보이게 했지만 그것을 다음 요청으로 넘길 길이 없다 — 지금은 같은 기획서를 새로 넣어 처음부터 돌리는 수밖에 없다.

LEARNINGS 근거:
- 2026-09-28 「재실행은 자기 자료가 없는데 요청 번호 = 자료 주인으로 쓴 자리가 셋 더 있었다」 — 자료를 **참조**하면 같은 사고가 난다. 그래서 **복사**한다(아래 제안 표)
- 2026-09-30 「셈 줄을 최신 실행에 붙여 반영하면 사라질 뻔했다」 — 남은 수는 「머지를 뺀 최신 작성 실행」이 아니라 **반영된 그 실행**(MERGE 의 원본)의 셈을 본다
- 2026-09-30 「셈 거절로 PR · 이어하기를 잃을 뻔했다」 — 이어 작성의 남은 번호 계산이 실패해도 끝내기 몸을 막지 않는다(자식 전 FAILED 는 설정 · 자료 문제만)

| 옛 본문 · params | `spec_text` · `params` 도 원본 것을 복사한다 |
| 세우는 순서 | **뿌리 잠금 안에서** 한 묶음으로 DRAFT 행 + 자료 행 → (잠금 밖) 파일 복사 → 실패하면 행 · 폴더를 지우고 500 → DRAFT→PENDING. ~~자료 수를 안 보는 UPDATE~~ **구현에서 `제출` 을 그대로 썼다** — 입력 자료가 없는 원본은 `NOTHING_LEFT` 가 먼저 거르므로 `제출` 이 거짓일 수 없고, 거짓이면 초안을 지우고 500 이라 DRAFT 가 남지 않는다(검토 주의 1 의 걱정을 다른 자리에서 막았다 · 2-C 검증이 잡은 차이). 유일 색인 위반은 409 `ALREADY_CONTINUED` 로 바꾼다 |
| 판정 순서 | 같이 온 칸 400 → 원본 확인(400 · 404 · 403) → `BAD_SOURCE`(AUTHOR 아님 · DRAFT · 폐기) → **뿌리 잠금 안에서** `NOT_MERGED` → `ALREADY_CONTINUED` → `NOTHING_LEFT`(셈 · **입력 자료가 없는 원본**도 — 본문만 있는 옛 행 · 화면만은 원장을 못 만든다) → 대조 재판정(`BAD_ENV` · `BAD_START_URL`) |
| 같이 온 칸 | `continueFrom` 과 `figma`(빈 배열 아님) → 400 `BAD_FIGMA_URL` · `compare` · `env` · `startUrl` → 400 `BAD_ENV`. 재실행이 역방향 칸을 거절하는 것과 같은 코드다 |
| `continueFrom` 모양 | 양의 정수가 아니면 400 `SOURCE_ID_REQUIRED` · RERUN · MERGE 번호면 409 `BAD_SOURCE` — 화면은 `rootId` 를 보낸다 |
| 병합됨 | 뿌리의 최신 실행(실패한 머지는 뺀다 — `최신실행`)이 `DONE` 인 `MERGE`(게이트 0). **GitHub 에서 직접 병합한 요청은 「반영」을 한 번 누르면 된다** — 에이전트가 이미 병합된 PR 의 반영을 DONE 으로 닫는다(`scripts/authoring-merge.ts:84`). MKT(5873)가 이 길이다 — 화면 반영 항목 설명 · 명세에 싣는다(검토 BLOCKER 2) |
| `NOTHING_LEFT` 재료 | 그 MERGE 의 원본(반영된 작성 실행)의 `result.coverage`. 번호 셈인데 `later` · `missing` 이 둘 다 비었거나 `{ none }` 이면 409. **셈이 없으면(옛 요청) 받는다** — 에이전트가 main 표로 다시 센다 |
| 한 번만 | 뿌리 잠금 안에서 폐기 안 된 이어 작성이 있으면 409 `ALREADY_CONTINUED`. 유일 색인 `authoring_request_continue_from_once`(`WHERE continue_from IS NOT NULL AND discarded_at IS NULL`)가 동시 누름을 한 번 더 막는다. 이어 작성한 요청을 폐기하면 다시 누를 수 있다 |
| `canContinue` | **뿌리 기준**(어느 실행 번호로 읽어도 같다) — 병합됨 ∧ 폐기 안 된 이어 작성 없음 ∧ 셈이 「남은 것 없음」이 아님. 권한은 화면이 본다(`canResume` 과 같다) |
| `continuedBy` | 폐기 안 된 이어 작성 요청의 번호. 없으면 null |
| 목록 `continueFrom` | 줄의 **뿌리** 것. 줄의 다른 칸은 최신 실행 것이지만 이 칸은 최신 실행(재실행 · 머지)에 없다 |
| 에이전트 남은 번호 | 집을 때 원장을 다시 뽑고(지금도 한다) **기준 SHA 의 main 표 · 케이스**와 맞대 `빠짐` ∪ `다음 요청` 제외. 저장된 `later` · `missing` 은 안 쓴다(사본이라 사람이 표를 고치면 낡는다 — WORKSTREAMS ② 「③ 에 넘길 것」). 표는 `ls-tree` 로 있는지 먼저 보고 없으면 빈 표, **그 밖의 git 실패는 FAILED 와 까닭**(뭉개면 덮은 번호까지 다시 맡긴다 — 검토 주의 9) |
| 「사람이 뺌」 (게이트 1 사용자) | **기준 SHA 의 main 표에 이미 있던 「사람이 뺌」 줄은 에이전트 대조에서도 인정한다** — 올리기 판정 · 셈 · 관문 0(`check:ledger --agent`) · 남은 번호가 한 규칙. 자식이 새로 쓴 「사람이 뺌」은 지금처럼 형식 오류. 이어 작성만이 아니라 모든 작성 실행에 적용된다(지금은 사람이 적은 줄이 다음 실행에서 「빠짐」이 된다 — 검토 BLOCKER 1). 에이전트가 기준 표에서 그 번호를 뽑아 메모리에 들고, 원장 사본(`ledger.json`)에도 실어 자식의 관문 0 이 같은 목록을 쓴다 |
| 남은 게 없거나 원장 없음 (게이트 1 사용자 — 실패로 닫고 안내) | 자식을 띄우지 않고 `FAILED` — 「남은 요구가 없다 — 앞 요청들이 기획서 요구를 모두 케이스로 만들었거나 제외했다. 이 요청은 폐기해도 된다」 · 「원장이 없어 남은 요구를 모른다 — <까닭>. 이 요청은 폐기해도 된다」. 폐기하면 원본이 풀린다. 서버가 셈으로 먼저 거르므로 드물다(셈이 없는 옛 요청 · 사람이 표를 고친 뒤) |
| DONE 인 이어 작성은 원본을 잠근다 | 폐기는 FAILED · STOPPED · DRAFT 만이다(`stop.ts:95`). 이어 작성이 PR 을 열었으면 그 요청을 반영하거나 다시 작성한다 — 원본에서 또 누를 길은 없다. 명세 「남는 한계」와 화면(원본 쪽 「남은 요구는 #M 요청이 맡았습니다」)에 적는다(검토 주의 2) |
| 자식에게 | 줄 프롬프트에 `--- 이어 작성 ---` 절(원본 번호 · 남은 수 · 앞 20개 · 전체는 `<자료>/continue.json`). 절차는 `tpx-author` `references/continue.md` — 남은 번호만 맡고 표의 다른 줄은 손대지 않는다 |
| 셈 | 이어 작성 실행도 **전체 원장** 기준(지금 규칙 그대로). 앞 요청이 덮은 것까지 들어 누적 진척이 보인다 |
| 다시 작성 · 이어서 작성 | 이어 작성 요청의 재실행 · 이어서 작성도 이어 작성 모드다 — 에이전트가 원본 상세(재실행이면 지금도 읽는다)의 `continueFrom` 을 본다 |
| 화면 버튼 | 「다음 단계」의 반영 끝(DONE MERGE) 상태에 항목 「남은 요구로 이어 작성」(검은 `btn` · 확인 창 없음 — DESIGN.md 모달 ① 밖). 설명은 **머지를 뺀 최신 작성 실행의 셈**(`AuthoringDetail` 의 `작성.coverage` 를 따로 넘긴다 — MERGE 행에는 셈이 없다, 검토 BLOCKER 3)으로 「반영한 실행 기준으로 다음 요청 a · 빠짐 b 개가 남았습니다. 이것을 새 요청으로 작성하고 새 번호로 넘어갑니다. 남은 요구는 에이전트가 시작할 때 다시 셉니다.」 · 셈이 없으면 앞 문장을 뺀다. 화면 문구에 `main` · `표` 같은 안쪽 말을 쓰지 않는다. 누르면 **새 번호** 상세로 간다 — 실행 기록 규칙(같은 쪽에 머문다)의 예외다. 409 를 받으면 오류 한 줄 뒤 다시 읽는다 |
| 못 누를 때 까닭 | 권한 없음 「이어 작성은 작성 요청 권한이 있는 사람만 할 수 있습니다.」 · 이미 넘김 「남은 요구는 #M 요청이 맡았습니다」 + 「#M 요청 보기」 링크 · 남은 것 없음(셈) 「이어 작성할 요구가 없습니다. 모두 케이스로 만들었거나 제외했습니다.」 · 원장 없음 「기획서 요구를 세지 못해 이어 작성할 수 없습니다.」 — 버튼이 사라지면 왜 없는지 말한다(검토 주의 1 · 화면 주의 3) |
| GitHub 직접 병합 안내 | 끝난 작성 실행(DONE · PR 있음)의 반영 항목 설명에 셈에 남은 요구가 있으면 「GitHub 에서 이미 병합했어도 여기서 반영을 눌러야 남은 요구를 이어 작성할 수 있습니다.」 |
| 이어받음 표시 | 낱말은 늘 「남은 요구」 — 「이어서 작성」(같은 번호 · 재개)과 부딪히지 않게(검토 주의 3). 이어 작성 요청은 상세 머리 부제 `#N 의 남은 요구`(뿌리의 `continueFrom` 에서 — 재실행 뒤 최신 실행에는 없다 · `#N` 은 링크) · 목록 줄은 평문 `#N 의 남은 요구`(줄 전체가 링크라 안에 링크를 못 둔다) — 첫 실행(차 1)이면 종류 라벨 자리에. 영어는 follow-up(`Follow-up of #N`) — continue 는 이어서 작성에만 |
| Grafana | `continue_from` 칸 권한은 이번에 안 더한다 — 기획서 하나의 누적을 대시보드로 볼 때 후속(WORKSTREAMS) |

### 통과한 것
- 흐름이 처음부터 끝까지 닫힌다 — 반영 → 버튼 → 새 요청 → 기준 SHA 의 main 표로 남은 번호 → 자식은 그 번호만 → 전체 원장 셈
- 자료 **복사**가 타당하다 — 요청 번호를 자료 주인으로 쓰는 자리(집기 피그마 토큰 · outputs 자료주인 · `자료출처` 의 브랜치 · 커밋 · 표시 원본 · 상세 입력)가 모두 새 번호로 풀린다(LEARNINGS 2026-09-28)
- 새 요청이 자기 뿌리 — `source_id` NULL 이라 사슬 · 브랜치 · 머지 뿌리 · 보류 입력 옮기기가 섞이지 않는다
- 부분 유일 색인이 폐기와 맞는다 — 폐기가 사슬 전부(AUTHOR 뿌리 포함)에 `discarded_at` 을 찍는다
- `NOTHING_LEFT` 재료(반영된 MERGE 의 원본 셈) · 실패한 머지를 최신에서 빼는 규칙 · 확인 모달이 필요 없다(DESIGN.md 모달 ①) · 버튼 자리 · 권한 판정 · 목업에 작성 상세가 없다
