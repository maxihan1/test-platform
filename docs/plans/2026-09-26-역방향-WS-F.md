# 역방향 WS-F — 대상 서버 줄의 테스트 계정

등급: 3 · 갈래: F · 2026-09-26

## 도메인 정리

- BC: 인증·설정. 칸은 PR #74 가 만든 `service_env.login_id` · `login_password`
- 정본: 도메인/인증 §7 설정 API 「envs[] 한 줄」 · 같은 자리 계약 블록 · §8.8 「대상 서버」
- 영향

| 자리 | 바뀌는 것 |
|---|---|
| `settings/routes.ts` 입력 스키마 | `envs[]` 줄에 `loginId?` · `loginPassword?` (문자열 또는 null) |
| `settings/store.ts` `대상서버넣기` · 목록 질의 | 비밀번호 유지 규칙 · 응답 `loginId` · `hasLoginPassword` (비밀번호 원문은 안 싣는다) |
| `/api/auth/me` envs | 안 바뀐다 — 계정을 싣지 않는다(인증 §7 101줄) · `hasLogin` 도 안 넣는다(사용자 결정) |
| `auth/gate.ts` · `auth/scope.ts` | **이번에 안 고친다** — `outputs` 세 줄은 WS-작성으로 넘긴다(사용자 결정) |
| 화면(WS-E) | 설정 > 서비스의 계정 칸. 이번에 안 고친다 |

## 왜

역방향 에이전트가 대상 서버 화면에 로그인하려면 계정이 필요하다. 저장은 대상 서버 줄을 **전부 지우고 다시 넣기** 때문에,
화면이 받은 적 없는 비밀번호를 되돌려 보내지 못하면 주소 하나만 고쳐도 모든 줄의 비밀번호가 사라진다 — 그래서 「키 없음 = 유지」다.

사용자 결정 (2026-09-26, [2])
- `outputs` 를 등급표·토큰 통로·라우트표에 넣는 일은 통로를 만드는 WS-작성으로 넘긴다. 표만 먼저 넣으면 `gate.test.ts` 「표에 있는데 소스에 없는 자리」 검사가 빨강이다
- `/api/auth/me` 에 `hasLogin` 을 넣지 않는다. 계정 없는 줄은 서버가 400 `BAD_ENV` 로 거절한다(작성 §3.6)

**게이트 1 에서 확인할 빈칸** — 명세는 `loginPassword` 만 「키 없음 = 유지」로 정했다. `loginId` 키가 없을 때는 적혀 있지 않다.
지금 설정 화면(WS-E 전)은 `loginId` 를 모르니 서비스를 저장할 때마다 아이디가 지워진다. **제안: `loginId` 도 같은 규칙(키 없음 = 유지, null·빈 글자 = 지움)**
