| 통로 | 바뀌는 것 |
|---|---|
| `POST /api/authoring/requests` | AUTHOR 에 `compare?·env?·startUrl?` · 400 `BAD_ENV`·`BAD_START_URL` · RERUN 에 오면 `BAD_ENV` |
| `POST …/:id/submit` | `compare` + `startUrl` 이면 자료 0 허용 |
| `GET …requests` · `GET …/:id` | `compare·env·startUrl` (계정 없음) · `assets[].role·sourceAssetId` |

| `POST …/:id/finish` | `result.diffs[]` 가 상세까지 그대로 온다 |

## 왜

역방향의 화면(WS-E ②)과 에이전트(WS-작성 ③)가 부를 서버 자리가 아직 없다. 사용자가 셋으로 나눈 첫 PR 이다 (2026-09-26).
`routes.ts` 가 이미 437줄이라(300줄 규칙) 통로를 더하기 전에 에이전트 통로를 떼어 낸다.

## 결정할 것 (게이트 1)

- **`finish` 의 `diffs` 모양이 틀리면 거절하나.** 명세는 모양만 적고 오류 코드를 안 정했다. 지금 `result` 는 모양 검사 없이 저장한다.
  추천 — **검사하지 않는다**(지금과 같게). 보내는 쪽이 에이전트 하나뿐이고, 화면은 React 가 글자를 이스케이프하며 없는 칸을 방어해 그린다.
  검사하려면 새 오류 코드를 명세에 더해야 한다(계약 추가)
- **다시 돌리기(RERUN)가 원본의 산출물까지 읽는 문제.** 원본 자료 목록에 MARKED·REVERSE_SPEC 이 섞인다. 거르는 것은 에이전트(③)가 `role === 'INPUT'` 으로 한다 — 이 PR 은 역할만 싣는다
