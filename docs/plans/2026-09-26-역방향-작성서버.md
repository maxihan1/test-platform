## 결정할 것 (게이트 1)

- **`finish` 의 `diffs` 모양이 틀리면 거절하나.** 명세는 모양만 적고 오류 코드를 안 정했다. 지금 `result` 는 모양 검사 없이 저장한다.
  추천 — **검사하지 않는다**(지금과 같게). 보내는 쪽이 에이전트 하나뿐이고, 화면은 React 가 글자를 이스케이프하며 없는 칸을 방어해 그린다.
  검사하려면 새 오류 코드를 명세에 더해야 한다(계약 추가)
- **다시 돌리기(RERUN)가 원본의 산출물까지 읽는 문제.** 원본 자료 목록에 MARKED·REVERSE_SPEC 이 섞인다. 거르는 것은 에이전트(③)가 `role === 'INPUT'` 으로 한다 — 이 PR 은 역할만 싣는다

### BLOCKER 1 — 역방향 요청을 다시 돌리면(RERUN) 조용히 깨진다 (eng · ceo 둘 다)
DB CHECK 가 `compare` 를 AUTHOR 에만 허락하므로 RERUN 행은 늘 `compare=false` 이고 집기에 `target` 이 없다.
그런데 라우트는 원본이 compare 여도 RERUN 을 받는다. 화면만 원본은 입력 자료 0 이라 에이전트가 늘 FAILED, 대조 원본은 정방향으로 돌아 역방향이 사라진다.
고칠 것 — 사용자 결정(§1.4). ⒜ 원본이 compare 면 409 `BAD_SOURCE` ⒝ 집기가 원본의 target 을 대신 싣고 `outputs` 의 source 도 원본 자료까지 받는다.
