## 왜

Grafana 가 자기 로그인(`admin`/`admin`)을 따로 쓰고 3001 을 밖으로 연다 — 플랫폼 권한이 대시보드에 안 걸리고, 설치마다 기본 비밀번호가 열려 있다 (인증 §7 「Grafana 통로」).

근거 — PR #95 보안 검토 인계: **`/grafana/**` 에도 변경 강제 403 과 세션 도장 대조가 걸려야 한다** (지금 문은 `/api` 에만 걸린다)

## 게이트 1 에서 정할 것 (명세에 없는 세부)

1. **실시간 연결(websocket)** — 권장: **끈다**(`GF_LIVE_MAX_CONNECTIONS=0`, proxy 도 websocket 안 넘김). 대시보드는 새로고침 주기로 다시 그린다. 켜면 proxy 가 연결마다 문을 거치게 해야 해서 코드가 는다
2. **Grafana 가 만드는 주소의 기준** — 권장: **`PLATFORM_PUBLIC_URL` + `/grafana/`**(Slack 링크가 이미 쓰는 값). 비어 있으면 `http://localhost:3000/grafana/`. 명세 인프라 §9.2 표의 `GF_SERVER_ROOT_URL` 줄을 이 값으로 고친다

### BLOCKER — 플랫폼 `admin` 이 Grafana 최고 관리자로 들어간다
Grafana 가 처음 켜질 때 자기 `admin` 을 만들고, auth proxy 는 같은 이름의 기존 계정으로 들인다. `Viewer` 자동 배정은 새 계정에만 걸린다.
요청의 `Authorization: Basic admin:admin` 이 넘어가면 다른 로그인 방식으로도 먹는다 → `GF_SECURITY_DISABLE_INITIAL_ADMIN_CREATION=true` · `GF_AUTH_BASIC_ENABLED=false` · proxy 가 `Authorization`·플랫폼 쿠키를 지운다 · 브라우저에서 `/grafana/api/user` 역할이 Viewer

### 주의 (반영)
1. 할 일 1 이 2 의 `req.user` 에 기댄다 → **1·2 를 한 작업으로**
2. 판정은 등록된 경로 틀로 · `/%67rafana/`·HEAD·`/grafana`(끝 `/` 없음) 검사
3. 302 는 화면 `GET` 만 · `/grafana/api/**`·`GET` 아닌 요청은 401 · `next` 는 `encodeURIComponent`
4. websocket 끄기를 명세에 · upgrade 요청이 문을 비켜 가지 않는지(끄면 proxy 가 안 받는다) 검사
5. 할 일 3 검사가 명세 표 전부(AUTO_SIGN_UP · AUTO_ASSIGN_ORG_ROLE · ROOT_URL · 새 셋)를 본다
6. `GF_SERVER_ROOT_URL` 은 **명세 값 그대로**(`PLATFORM_PUBLIC_URL` 은 끝 `/` 로 `//grafana/` 위험) — 게이트 1 의 2번은 검토 권고로 닫음
7. Grafana 로그아웃 → 플랫폼 첫 화면(`GF_AUTH_SIGNOUT_REDIRECT_URL=/`)
8. 브라우저 확인에 `POST /grafana/api/ds/query` 200 (Host·Origin 검사)
