## 왜

데모마켓(자료 3757) 요구 172개 가운데 124개가 케이스가 안 됐고 3개(REQ-HOME-001 · 003 · REQ-BRD-008)는 표 어디에도 흔적이 없었다.
관문 넷은 모두 **표 → 코드** 쪽만 보고, **기획서 → 표** 는 사람 승인 하나로 막는데 작성 에이전트는 그 승인을 건너뛴다
(`scripts/authoring-rules.ts:176`). PR 본문 숫자도 표 기준이라 빠진 것이 어디에도 안 나왔다. 제외 사유는 자유 문장이라
「한 칸 밖」(규칙 오적용) · 「화면 케이스가 아니다」(플랫폼은 API 케이스를 돈다) 같은 틀린 사유가 그대로 통과했다.
분석 전문은 PR #119 대화와 아래 LEARNINGS 항목.

케이스 작성이 한 줄로 돌아 오래 걸린다 — 사용자 결정(2026-09-30): **서브에이전트 A안(화면 묶음별 팬아웃) · 동시 3.**

## 명세가 안 정한 것 — 제안 (게이트 1 에서 승인받는다)

| 무엇 | 제안 |
|---|---|
| 번호 모드 판정 | 글자본에서 `^[A-Z][A-Z0-9]*(-[A-Z][A-Z0-9]*)*-\d{2,}$` 꼴 낱말을 모아 **맨 끝 `-숫자` 앞(가족)** 으로 묶는다. 서로 다른 번호가 **3개 이상**인 가족이 하나라도 있으면 번호 모드 — 그 가족들의 번호가 원장이다(처음 나온 순서). `UTF-8` · `ISO-9001` 같은 외톨이는 가족이 3이 안 돼 빠진다 |
| 문단 모드 (번호 없음 · 사용자 결정) | 빈 줄로 가른 덩이마다, 목록 항목(`-`·`*`·`•`·`1.`)은 항목마다 하나. **빈칸 뺀 15자 미만 · 표 테두리 줄(`-`·`=`·`+`·`|` 만)은 뺀다.** 번호는 나온 순서대로 `P-001`… 같은 글자본이면 같은 번호다. 문단 모드는 표의 출처 칸에 `P-012` 를 적고, 요구가 아닌 문단(개요 · 목차 · 변경 이력)은 제외 종류 「요구 아님」으로 뺀다 |
| 원장이 없는 자료 | PDF · 피그마 · 화면만(자료 0) — 글자본이 없다. **대조를 건너뛰고 PR 본문에 「원장 없음 — <까닭>」을 싣는다.** 글자본 자료가 하나라도 있으면 그것들로 원장을 만들고 나머지 자료는 까닭에 적는다 |
| 자료가 여럿 | 자료마다 따로 뽑아 합친다. 번호가 겹치면 하나로 친다. 문단 모드 번호는 자료가 둘 이상일 때 `P<자료 순번>-001` |
| 대조 규칙 | 원장의 모든 번호가 ⒜ 「요구사항」 표 어느 줄의 출처 칸에 있거나 ⒝ 「제외」 표에 **한 줄에 하나** 있어야 한다. 「제외」 종류는 닫힌 다섯 — `다음 요청` · `되돌릴 수 없음` · `자료 없음` · `요구 아님` · `사람이 뺌`. 모르는 종류 · 한 줄에 번호 둘 이상 · 범위(`~`) 는 형식 오류. 원장에 없는 번호가 표에 있으면 경고만 |
| 대조 실패 | 에이전트가 **올리기 거절(`REJECTED`)** 로 끝낸다 — 까닭 「원장 대조: 빠진 요구 N개 — <번호 앞 20개>」. 이어서 작성하면 자식이 그것부터 채운다(이미 있는 흐름) |
| `사람이 뺌` | 자식(작성 에이전트)은 못 쓴다 — 사람 세션만. 에이전트 대조에서 자식이 쓴 것은 형식 오류로 친다 |
| 팬아웃 발동 | 표가 확정되고 tcId 를 다 매긴 뒤, **화면 묶음 2개 이상 · 케이스 8건 이상**일 때. 아니면 지금처럼 혼자 한다 |
| 팬아웃 규칙 | 서브에이전트는 **동시 3 · 앞에서 끝까지 기다린다**(백그라운드 금지 — 2026-09-23 자식이 백그라운드를 남기고 먼저 끝나 멈췄다). 자기 tcId 파일만 쓰고 `docs/cases/<접두사>.md` 는 **손대지 않는다** — 용어 조각은 `<산출물 폴더>/glossary/<묶음>.md` 에. 관문 1 · 3 을 자기 파일만. 자식이 조각을 합치고 관문 0 · 2 · 3(전체) · 4 를 한 번 |
