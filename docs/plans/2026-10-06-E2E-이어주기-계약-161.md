## 왜

PR #160 이 명세에 `상태: 대기` 블록 다섯을 남겼다. 러너(ⓑ)와 서버(ⓒ)가 같은 모양을 주고받으려면 타입과 표가 먼저 서야 한다 — #97 → #98 과 같은 순서다.

실측 — `scenario_run_part` 를 만지는 마이그레이션은 `20260928000004_scenario.sql` 하나다(LEARNINGS [E2E] 2026-09-22 「한 파일만 보고 단정」 — 전부 grep 했다).
칸 검사(`scenario-columns.test.ts`)는 `information_schema.columns` 를 **칸 순서(ordinal_position)대로** 대조한다. `ALTER TABLE ... ADD COLUMN` 은 끝에 붙으므로 새 칸 셋은 `finished_at` 뒤에 온다.
그런데 명세(데이터모델)는 세 칸을 `CREATE TABLE` 가운데(`mocks` 뒤)에 적었다 — 명세 SQL 과 실제 칸 순서가 갈린다. 할 일 3 이 명세를 실제와 같게 「끝에 붙이는 ALTER」로 옮긴다(뜻은 같다).
