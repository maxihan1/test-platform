## 도메인 정리

작성 에이전트(`scripts/authoring-*`)와 자식 절차(`tpx-author`)만 건드린다. 계약(DB · Admin API · kit 타입 · 러너)은 그대로다.
작성 PR 본문은 계약이 아니다. 관련 절은 도메인/작성 §3.6 「서브에이전트 팬아웃」, §7 「중단 · 폐기 · 진척」이다.

| 무엇 | 어디 |
|---|---|
| 표지 줄 감지 · 단계표 | `scripts/authoring-progress.ts` 의 `진척누적기` — 이미 자식의 모든 흐름 줄을 먹는다 |
| 로그 · PR 본문에 싣기 | `scripts/authoring-run.ts`(298줄 — 300줄 안에 두려고 두 줄만 더한다) · `scripts/authoring-upload.ts` · `scripts/authoring-chain.ts` `PR본문` |
| 자식이 표지를 말하게 | `.claude/skills/tpx-author/SKILL.md` 절차 · `references/fanout.md` |

## 왜

서버 실측 전에 어느 단계가 가장 오래 걸리는지 알아야 다음에 무엇을 서브에이전트로 나눌지 정한다(WORKSTREAMS 「실측 뒤 가장 긴 단계부터」).
지금은 `elapsedSec` 하나뿐이다. 5872 가 시간초과로 결과를 잃었을 때도 어디서 시간을 썼는지 몰랐다 — 그래서 시간초과 · 멈춤으로 끝나도 로그에 남긴다.

결정(사용자, 2026-10-03) — 기록은 **에이전트 로그 + 성공 시 작성 PR 본문**. DB · 화면은 안 한다.
시각은 자식이 아니라 **에이전트가 표지 줄을 본 순간의 시계**로 찍는다.

LEARNINGS #128(2026-10-02) — 지침이 만들라는 것을 기계가 받는지 먼저 본다. `흘릴줄` 은 첫 글 블록의 첫 줄만 보므로
표지가 둘째 줄에 오면 놓친다 → 감지는 글 블록의 **모든 줄**에서 찾는다(할 일 1 의 RED).

### BLOCKER 1 — `parent_tool_use_id` 「있으면」으로 거르면 자식 줄까지 다 버린다
stream-json 은 자식 본인 줄에도 `"parent_tool_use_id": null` 을 붙인다(`scripts/fixtures/stream-json-sample.jsonl`). 칸이 있는지로 거르면 운영에서 표지가 늘 0 이 되고 테스트만 초록이다.
고칠 것 — 값이 문자열일 때만 서브에이전트로 본다. RED 에 「null 인 줄의 표지는 센다」, 테스트 줄은 표본 모양으로.

### 주의 1 — 표지 줄을 `먹기` 반환값으로 내면 `lastAction` 이 명세(작성 §7 「도구 이름·글 첫 줄」)와 어긋난다
반환값 · `lastAction` 은 그대로 두고 표지는 단계 목록에만 쌓아 로그에 따로 찍는다.

### 주의 2 — 로그 자리를 `if (멈춤.까닭 !== null) return;` **앞**(자식동안 끝난 직후)으로 못박는다
거절로 멈추는 길은 끝내기를 안 부른다. `사용량보고`(네트워크) 보다도 앞이어야 마지막 단계 끝이 안 밀린다.

### 주의 3 — 역방향 단계 이름(화면 훑기 · 차이 목록 · 역기획서 원고 · 비밀번호 점검)이 없다
대조 요청에서 가장 길 구간이 다른 이름에 묻힌다. `references/reverse.md` 를 files 에 더한다.

### 주의 4 — 이어하기는 같은 PR 본문을 갈아 써서 앞 실행 단계표가 PR 에서 사라진다
절 제목을 「단계 시각 (이번 실행)」으로 하거나 한계를 적는다. 앞 실행 것은 로그에 남는다.

### 주의 5 — `authoring-chain.ts` 도 298줄이다
할 일 3 검증에 `wc -l scripts/authoring-chain.ts`. run.ts 는 정확히 두 줄만 더한다.
