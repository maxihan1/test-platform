# 증적 · 항목 상세에 기대결과가 「없음」으로 나오는 버그

등급: 3 · 갈래: WS-D(리포팅) · WS-E(화면) · 2026-10-01 · PR #123 (여섯 요청 중 묶음 ①)

## 도메인 정리

- BC: 리포팅(§3.3 증적 재현 · §8.4 항목 상세) · 실행(§3.2 스냅샷 · §8.3 값 한 줄). **계약 변경 없음** — kit 타입 · 러너 HTTP · DB 칸 · Admin API 응답 모양이 그대로다
- 이 PR 이 바꾸는 표면: 서버 증적 수집(`reporting/collect.ts`) · 화면 칸 만들기(`web/mask.ts`) · 항목 상세 화면(`web/ItemDetail.tsx`) · 명세 문장 세 곳

| 누가 | 무엇이 바뀌나 |
|---|---|
| 증적(PDF · 엑셀 · HTML) | 값이 빈 칸을 박제된 스키마의 기본값으로 채운다 → 「기대 결과 없음」 · 「입력 없음」이 기본값으로 돈 케이스에서 사라진다 |
| 결과 목록의 값 한 줄 | 같은 규칙. 기본값으로 돈 항목도 「어떤 값으로 돌렸나」가 보인다 |
| 항목 상세 화면 | 위 규칙 + **기대결과 칸을 더한다**(§8.4 「블록 모양은 같다」 — HTML 증적에는 이미 있다) |

## 왜

케이스 값을 안 고치고 실행하면 그 칸은 요청에 `{}` 로 실리고(`web/pickRun.ts` · `scripts/run-scheduled.ts` 등) 그대로 `run_item.expected` · `params` 에 박제된다.
케이스는 kit 안(`packages/kit/src/runtime/inputs.ts`)에서 코드 기본값으로 돌지만 그 값은 기록에 안 돌아온다.
`collect.ts` `toFields()` 와 `mask.ts` `fieldsOf()` 가 **값 쪽만** 훑어 빈 목록을 만들고, HTML 증적은 그것을 「기대 결과 없음」으로 그린다.

박제된 스키마(`run_item.expected_schema` · `param_schema`)에는 그 실행 때의 `default` 가 들어 있다 — kit 이 `z.toJSONSchema(..., { io: 'input' })` 로 기본값을 남긴다.
그 실행이 쓴 기본값과 같은 값이고 박제 값만 읽으므로 §3.3 「리포팅은 test_case 를 읽지 않는다」가 그대로 지켜진다. 지난 실행도 증적을 새로 뽑으면 바르게 나온다(스키마를 박제하기 시작한 2026-09-17 이후 실행).

**실행을 만들 때 기본값을 채워 박제하는 길(쓰는 쪽)은 이번에 안 한다.** 지난 실행을 못 고치고, 러너에 가는 값이 바뀌는 일이라 범위가 넓다.
읽는 쪽 한 곳씩(서버 · 화면)이면 지난 실행과 앞으로의 실행이 같이 고쳐진다.

## 명세가 안 정한 것 — 제안

| 무엇 | 정한 것 |
|---|---|
| 칸 순서 | **박제된 스키마의 칸 순서로 걷는다** — 값이 있으면 값, 없으면 기본값. 스키마에 없는 값 칸은 맨 뒤에 붙인다. 값과 스키마가 같은 JSONB 키 순서라 값이 다 차 있던 행은 지금과 글자 하나 다르지 않다(§3.3) (게이트 1 — 검토 주의 1) |
| 기본값도 값도 없는 칸 | 만들지 않는다(지어내지 않는다). 선택 칸이 이 경우다 |
| 비밀값 칸의 기본값 | 다른 칸과 같이 `********` 로 가린다 |
| 기본값에서 온 칸 표시 | 따로 표시하지 않는다. 그 실행이 실제로 쓴 값이기 때문이다 |
| 값 글자 | 증적은 지금처럼 `String(value)`(참거짓은 `true` — §8.4 견본 「기대 true」), 화면은 지금처럼 `예` / `아니오`. 두 테스트에 같은 입력 · 같은 순서를 넣어 맞춘다 (게이트 1 — 주의 3) |
| 이미 만든 증적 | 저장된 문서 파일은 안 바뀐다 — 새로 뽑아야 기본값이 보인다. 스키마가 `'{}'` 인 박제 이전 행은 그대로 「없음」이다. 명세 문장과 끝 보고에 적는다 (게이트 1 — 주의 2) |

### 주의 1 — 칸 순서가 실행마다 바뀐다
`params` 와 스키마가 둘 다 JSONB 라 키가 길이 순으로 다시 늘어선다. 「차 있던 칸 먼저, 기본값 칸은 뒤」로 하면 같은 케이스도 어느 칸을 고쳐 돌렸느냐에 따라 순서가 달라져 실행끼리 비교하기 어렵다.
고칠 것: **스키마 칸 순서대로** 걸으며 값이 있으면 값, 없으면 기본값을 넣고, 스키마에 없는 값 칸은 맨 뒤에 붙인다. 값이 다 차 있던 행은 값과 스키마가 같은 JSONB 순서라 지금과 글자 하나 다르지 않다(§3.3).

### 주의 2 — 이미 만든 증적 파일은 그대로 틀린다
지금 사람들이 여는 PDF · 엑셀 · HTML 은 `evidence_document` 에 저장된 파일이라 코드를 고쳐도 안 바뀐다. 2026-09-17 마이그레이션 이전 실행은 스키마가 `'{}'` 라 다시 만들어도 「없음」이다.
고칠 것: 명세 문장과 끝 보고에 「이전에 만든 문서는 새로 뽑아야 기본값이 보인다 · 박제 이전 행은 그대로」를 적는다. 계획의 「지난 실행도 다시 뽑으면 바르게 나온다」를 이 범위로 좁힌다.

### 주의 3 — 같은 규칙이 두 곳인데 맞춰 보는 검사가 없다
`collect.ts` 는 `String(value)`, `mask.ts` 는 `보일값()` 으로 그려서 참거짓 기본값이 증적은 `true`, 화면은 `예` 다. 한쪽만 고쳐지면 조용히 갈라진다.
고칠 것: 같은 입력 · 같은 기대 순서를 두 테스트에 똑같이 넣는다. 증적이 `true` 로 적는 것은 §8.4 견본 「기대 true」와 맞으므로 명세에 정한 것으로 한 줄 적는다.

### 주의 4 — `collect.ts` 가 300줄 한도에 가깝다 (지금 279줄)
고칠 것: 넘으면 `toFields` 를 따로 떼어 낸다고 REFACTOR 칸에 미리 적는다.

### 주의 5 — 화면 문구 띄어쓰기가 섞인다
머리 `기대결과` 와 빈 상태 `기대 결과 없음` 이 같은 칸 안에서 다르다. `입력값` / `입력 없음` 은 짝이 맞다.
고칠 것: 화면은 `기대결과` / `기대결과 없음` 으로 맞추고 영어 표에 키를 더한다. 명세 견본은 증적(`html.ts`)과 같은 `기대 결과` 로 쓴다.

### 통과한 것
- 저장값은 박제 전에 `저장값을채운다()` 가 채우므로 값이 빈 칸은 실제로 코드 기본값으로 돈 칸이다 — 지어낸 값이 들어갈 틈이 없다
- `.default().meta({ secret: true })` 꼴에서도 `secret` 과 `default` 가 같은 칸에 남는다(zod 로 직접 뽑아 확인)
- `fieldsOf` · `한줄로` 를 쓰는 곳은 항목 상세와 결과 목록 줄뿐이다. insights · 대시보드 · 결과 상자 · 케이스 상세는 `run_item` 값을 안 읽는다
- `html.test` · `xlsx.test` 는 자기 자료를 따로 만들어 영향이 없다 · 접두사 `XDC` 규칙도 맞다
