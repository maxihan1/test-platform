# 화면 기록 저장 — 바뀐 화면만 다시 훑는다

등급: 3 · 갈래: WS-작성 · 2026-10-04

## 도메인 정리

작성 BC §3.6 「★ 역방향」 크롤러 절과 올리기 허용 목록(`cases-only.mjs` — CI 차선과 작성 올리기가 같이 쓴다). 계약(타입 · API · DB) 변경 없음.
저장 자리는 저장소 `docs/screens/<접두사>/` — 작성 PR 에 실려 병합되면 main 에 남고, 다음 작성의 작업 트리(main 사본)에 그대로 있다.

## 왜

사용자 지시 11. 크롤러(#150)가 구조는 1~3분에 뽑지만, 보조가 화면마다 쓰는 기록(요소 · 규칙 · 오류 문구 · 연 한 칸)은 매번 새로 쓴다. 바뀌지 않은 화면의 기록을 다시 쓰면 다시 작성 · 이어 작성마다 훑기 20분 안팎을 쓴다.
#150 이 남긴 「지난번보다 화면이 줄면 보이게」도 저장본이 있어야 견줄 수 있다.

게이트 0 승인 여섯 문장.
1. `docs/screens/<접두사>/` 에 화면 기록 `.md` 와 `index.json`(주소 · 상태 · 틀 · 구조 지문 · 글자 지문 · 기록 이름)
2. 옮기는 쪽은 에이전트(스크립트) — 작성이 끝나면 자료 폴더의 기록 · 크롤 목록을 이 자리로 복사
3. 지문 둘 — 글자 지문까지 같을 때만 저장 기록을 그대로 쓴다
4. 다음 작성 — 크롤러가 저장본과 견줘 목록에 같음 · 바뀜 · 새 화면. 같음은 저장 기록을 가져다 쓰고 나머지만 보조가 훑는다
5. 크롤 요약에 「저장본에 있는데 이번에 못 본 화면 K장」
6. 올리기 허용 목록에 `docs/screens/<접두사>/` 의 기록 · `index.json`(이름 꼴 좁게)

## 이름 맞추기 (설계)

보조는 화면 기록을 **크롤 파일 이름으로** 쓴다 — 크롤 `로그아웃/012.yml` → 기록 `out-012.md`, `로그인/007.yml` → `in-007.md`(저장소 파일 이름은 영문 소문자 · 숫자만).
크롤에 없는 화면(더 갈 곳)은 `extra-<영문 이름>.md` — 지문이 없어 저장하지 않고 다음에도 훑는다.
저장본은 `상태 + 틀` 로 맞춘다(번호는 실행마다 바뀐다).
