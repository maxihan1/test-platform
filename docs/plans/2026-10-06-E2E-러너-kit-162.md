## 왜

지금 고정 spec 은 창(`page`) 하나와 `request` 하나를 모든 케이스 부품에 같이 넘기고, kit 은 `traced` 로만 감싼다.
그래서 앞 케이스의 시계 고정 · 주입 스크립트가 뒤로 새고, `finally` 의 API 삭제가 앞 부품 데이터를 지우고, 케이스 API 요청에는 모킹이 안 걸린다(10-04~06 실측 — 시나리오 §3.7 결정 12 표).

**코드 실측 (2026-10-06, Playwright 1.63)** — 감싸는 자리를 정하려고 번들을 읽었다.
- `Page` 는 만들 때 `this.request = this._browserContext.request` 로 받는다 → 러너가 창의 `request` 를 바꿔 끼운 뒤 `newPage()` 하면 `page.request` 도 감싼 것이다
- `Browser.newPage()` 는 안에서 `this.newContext()` 를 부른다 → `browser.newContext` 하나만 감싸면 둘 다 잡힌다
- `@playwright/test` 의 ESM 입구(`index.mjs` → `playwright/test.mjs`)는 CJS `test.js` 의 `playwright.request` 객체를 그대로 다시 내보낸다 → 케이스(`require`)와 고정 spec(`import`)이 **같은 객체**를 볼 가능성이 크다. 러너 이미지에서 잰다(할 일 7, LEARNINGS [WS-C] 2026-09-28)
- 무늬 맞추기는 공개 함수가 없다(`globToRegexPattern` · `resolveGlobBase` 는 번들 내부). glob 변환만 옮긴다 — 아래 결정 7

**LEARNINGS 근거** — [WS-C] 2026-09-28 「로컬 · CI 초록인 러너가 이미지에서만 죽었다 — kit 이 require 와 import 로 섞여 불렸다」.
그래서 `window.ts` · `links.ts` · `parts.ts` 는 kit 을 **타입으로만** 가져오고(값은 `wire.ts` 사본), 이미지 실측(할 일 7)을 완료 조건에 둔다.

|---|---|---|---|

| 3 | 바꿔 보내기 주소 | `baseUrl` 끝 `/` 를 떼고 `path` 의 `{}` 를 `encodeURIComponent(값)` 으로 바꿔 잇는다 | API 부품과 같은 잇기(`new URL` 이 경로를 날린다). 값에 `/` · `..` 가 섞여 다른 경로로 새지 않게 |
| 4 | 시간 초과 부품의 절차 | 창을 닫고 5초까지 기다려 kit 이 모은 절차를 싣는다. 못 받으면 `steps: []` | 창이 닫히면 Playwright 동작이 바로 실패해 kit 이 절차를 돌려준다. 끝없는 기다림(Playwright 밖)만 못 받는다 |
| 5 | 뒷정리 줄 | 미룬 삭제가 없어도 `[]` 로 흘린다 | 응답 `cleanup` 이 「없었다(`[]`)」와 「끊겨서 모른다(칸 없음)」를 가른다 |
| 6 | 미룬 삭제를 보낼 때 실을 것 | 모을 때의 쿠키(그 도구의 `storageState()`) + 그 호출에 직접 붙인 `headers` | 「모을 때의 로그인 상태」에 Bearer 머리도 든다. 연결을 만들 때 준 `extraHTTPHeaders` 는 꺼낼 길이 없어 못 옮긴다 |
| 7 | 이어 주기 · API 쪽 모킹의 무늬 맞추기 | Playwright glob 변환(`*` · `**` · `{a,b}` · `\` 이스케이프)을 옮긴다. `*` 로 시작하는 무늬와 절대 주소는 브라우저 `route` 와 같다. `/` 로 시작하는 상대 무늬는 `baseUrl` 의 origin 을 붙인다 | `ponytail:` Playwright 의 상대 무늬 풀기(대소문자 · `..` · `?`)를 다 옮기지 않았다 — 어긋나면 시험 실행이 빨강으로 보여 준다 |
| 8 | API 쪽 가짜 응답 | 막기 · 돌려주기 · 미룸 · 모킹은 `APIResponse` 와 같은 메서드(`status` · `ok` · `headers` · `body` · `text` · `json` · `url` · `dispose`)를 가진 객체로 준다 | Playwright 의 `APIResponse` 는 밖에서 못 만든다. 케이스는 판정을 `verify` 로만 한다(K표) |
| 9 | 감싸지 않는 것 | `fetch(Request 객체)` 처럼 주소 대신 요청 객체를 넘기는 호출 · `browser.newBrowserCDPSession` 같은 다른 길 | 표본 0. 필요해지면 그때 |
| 10 | 직접 만든 창 · 연결의 수명 | 러너가 닫지 않는다(케이스가 닫는다). 거기 거는 이어 주기 · 미룸은 그때 도는 부품 것을 따른다 | 부품 창은 러너가 닫는다(결정 3). 직접 만든 것은 케이스 몫이다 |
