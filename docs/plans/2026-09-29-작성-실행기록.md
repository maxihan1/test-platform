# 작성 요청 번호는 하나로 — 이어서 작성 · 다시 작성은 실행 기록으로

등급: 3 · 갈래: WS-작성 · 2026-09-29

## 도메인 정리

작성 요청(애그리거트)의 **보이는 번호 = 뿌리 번호**(맨 처음 AUTHOR 행). DB 는 그대로 — 실행마다 행이 서고(RERUN · 이어받기 · MERGE),
뿌리는 `AUTHOR` 면 자기, `RERUN` 이면 `source_id`(이미 맨 처음), `MERGE` 면 원본 행의 뿌리다.
바뀌는 것: Admin API 목록 · 상세 응답(계약 — 게이트 0 승인 2026-09-29), 에이전트 브랜치 · PR 규칙, 화면(시안 A 표 — 사용자 선택).
Grafana · 토큰 · 통계는 실행(행)마다 그대로 센다.

## 왜

5873 한 작업이 5873 → 5874 → 5875 → 5876 → 5877 로 흩어져 보였다. 사용자 「번호를 하나로 하고 히스토리 항목」,
DB 를 나누는 B 안(2~3일) 대신 화면에서 묶는 A 안(반나절) · 다시 작성도 같은 번호 · 이어서 작성은 같은 PR 갱신.
