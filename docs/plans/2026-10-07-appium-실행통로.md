## 도메인 정리

| 무엇 | 지금 | 이번 뒤 |
|------|------|--------|
| 정식 실행 `POST /api/runs` | android 항목이면 400. 전부 컨테이너 러너(`RUNNER_URL`) | android 를 받는다. 최상위 `location`(기본 `local`). android 항목은 내 컴퓨터 러너(`LOCAL_RUNNER_URL`), 브라우저 항목은 그대로 |
| 케이스 테스트 실행 | desktop · mobile | android 도. 폰이 쓰이는 중이면 409 `DEVICE_BUSY` |
| 동시성 | 전역 2 줄 하나 | 브라우저는 전역 2 그대로 · android 는 **폰 줄** 따로 한 번에 하나 (테스트 실행도 같은 잠금) |

| 정기 실행 | android 를 검사 없이 컨테이너 러너로 보낸다 | android 케이스를 뺀다(뺀 수를 한 줄 알림) |
| 스크린샷 | 맥 러너는 `./artifacts`, admin 컨테이너는 이름 붙은 볼륨 — 404 | compose 의 artifacts 자리를 `.env` 한 줄로 `./artifacts` 에 걸 수 있다(기본은 지금 볼륨 그대로) |
| 화면 | android 를 보내지만 서버가 400 · 결과 칸은 PC · 모바일뿐 | 실행 위치 고르개(android 케이스가 섞였을 때) · 결과 칸 「Android 앱」 · 안내 문구 셋 |

- **사용자 결정 (2026-10-07)**
  - 「고르개를 지금 만든다」 — 로컬 / 디바이스 팜, 팜은 꺼진 채

  - PR 하나에 화면까지 넣는다 (할 일 14)

- 0단계 실측(`docs/plans/2026-10-07-appium-시험.md` §d) — 같은 폰에 연결 둘이 겹치면 뒤 것이 가로채고, SIGKILL 이면 정리가 안 돌아 60초 남는다

## 명세가 안 정한 것 — 제안 (게이트 1 에서 승인받는다)

| 무엇 | 제안 |
|------|------|
| `location` | **android 항목이 있으면 필수**(없으면 400 `INVALID_REQUEST`) — 기본값을 두면 팜이 붙을 때 뜻이 조용히 바뀐다(게이트 1 반영). 브라우저만 고른 요청은 이 칸을 안 본다 |
| 거절 순서 | android 항목이 있을 때만 — 칸 없음 400 → `farm` 이면 409 `FARM_OFF` → `LOCAL_RUNNER_URL` 이 비면 409 `LOCAL_OFF`. **실행을 만들기 전에** 거절한다(기록이 안 생긴다) |
| 오류 글자(화면) | `LOCAL_OFF` 는 원인이 같은 `TRIAL_OFF` 와 한 문장 꼴로 맞추고 「다」로 끝낸다 — 납품 서버 사용자가 따라 할 수 없는 「SETUP」 안내는 뺀다 · `FARM_OFF` 「디바이스 팜은 아직 준비 중입니다」 · `DEVICE_BUSY` 「디바이스가 다른 실행에 쓰이고 있습니다」. 최종 글자는 humanize 점검 뒤 할 일 12 에서 정한다 |
| 고르개 | 이름 **「로컬 / 디바이스 팜」**(사용자가 부른 이름 — 「내 컴퓨터」는 다른 자리의 팀원이 자기 PC 로 읽는다). 고른 케이스에 android 가 하나라도 있을 때만 그린다. 「준비 중」은 라벨 글자로 보인다. 「실행」 버튼은 늘 눌린다. 고르개는 「실행」에만 걸리고 「▶ 테스트 실행」은 늘 로컬이다 |
| 중단을 보낼 곳 | **맡은 러너 하나** — `run_item.platform` 으로 고른다(android → 로컬, 그 밖 → 컨테이너). 공통/3 §5.3 「맡은 러너에게만」 그대로. 진행만 두 러너에 묻는다 |
| 폰 잠금 범위 | admin 메모리에 하나(폰 한 대 = 로컬 러너 하나). 여러 대는 디바이스 팜 때. admin 이 다시 뜨면 잠금이 사라지는데 러너 자식은 폰을 쥔 채일 수 있다 — 한계로 적는다 |
| 결과 칸 | **그 실행에 든 디바이스로** 정한다 — 웹만 → PC · 모바일(지금과 같다), 앱만 → Android 앱, 섞이면 셋. 디바이스 거르개 칩도 같은 목록 |
| 정기 실행 | android 케이스를 빼고 「android 케이스 N건은 정기 실행에서 뺐다」 한 줄을 남긴다. 케이스가 전부 android 면 실행을 안 만들고 0 으로 끝난다(오류가 아니다) |
| 연결 번호 파일 | `artifacts/runs/<runId>/<historyId>/appium-session` (글자 한 줄 = sessionId). 이름 상수와 폴더 함수는 kit 것을 러너가 같이 쓴다 — 경로를 따로 계산하면 어긋날 때 조용히 못 닫는다 |
| 러너의 연결 닫기 | android 항목이면 **끝난 방식과 상관없이** 시도한다(파일이 없으면 아무것도 안 함). DELETE 제한 10초 — admin 유예 30초 안에 답한다 |
| 실행 위치 저장 | 안 한다. 팜이 붙으면 정식 실행 = 팜, 로컬 = 테스트 실행으로 바뀌어 저장할 까닭이 없다(게이트 0 사용자). **팜이 붙으면 걷을 것** — `location` 의 `'local'` 값 · `LOCAL_OFF` · runner.ts 의 android → 로컬 분기 · 고르개 「로컬」 · 정기 실행 android 제외(되살린다). 러너 §5.2 에 적는다 |

### BLOCKER 1 — 「결과가 기록된다」가 어느 서버 이야기인지 확인이 없다 (ceo)
android 정식 실행은 admin 이 `LOCAL_RUNNER_URL` 로 맥 러너를 부를 때만 돈다. 운영 서버(EC2 · 고객 서버)는 이 값을 비우므로 늘 409 `LOCAL_OFF` — 결과는 **맥에 admin · DB · 러너 · 폰을 같이 띄운 판**에만 쌓인다.
사용자 말이 운영 서버 기록을 뜻했다면 이 계획으로는 못 한다(맥 러너 등록 · 터널 같은 다른 길). 「왜」 · 실행 §7 한계에 적고 게이트 1 맨 위에서 확인받는다.

### BLOCKER 2 — 앱만 도는 실행의 결과 칸이 빈 칸투성이다 (design)
「android 항목이 있으면 Android 앱 칸을 붙인다」면 MDA 처럼 앱 케이스만 있는 실행은 모든 줄이 「PC — · 모바일 —」 이고 칩도 0건이다. 칸은 **그 실행에 든 디바이스로** 정한다(웹만 → PC · 모바일, 앱만 → Android 앱, 섞이면 셋). 칩도 같은 목록. §8.3 문장과 RunResult 검사에 「앱만」 경우.
