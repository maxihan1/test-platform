# Appium 실행 통로 — android 정식 실행 · 실행 위치 · 폰마다 하나 · 끊을 때 연결 닫기 (APP-F1-02)

등급: 3 · 갈래: WS-B (+ WS-C 러너 · kit · WS-E 화면 · 배포) · 2026-10-07 · PR #174

## 도메인 정리

| 무엇 | 지금 | 이번 뒤 |
|------|------|--------|
| 정식 실행 `POST /api/runs` | android 항목이면 400. 전부 컨테이너 러너(`RUNNER_URL`) | android 를 받는다. 최상위 `location`(기본 `local`). android 항목은 내 컴퓨터 러너(`LOCAL_RUNNER_URL`), 브라우저 항목은 그대로 |
| 케이스 테스트 실행 | desktop · mobile | android 도. 폰이 쓰이는 중이면 409 `DEVICE_BUSY` |
| 동시성 | 전역 2 줄 하나 | 브라우저는 전역 2 그대로 · android 는 **폰 줄** 따로 한 번에 하나 (테스트 실행도 같은 잠금) |
| 중단 · 진행 | `RUNNER_URL` 한 곳 | 두 러너 모두에 묻는다 — 모르는 historyId 는 러너가 false · 진행은 DB 교집합으로 거른다 |
| 러너가 끊을 때 | SIGKILL 뿐 — Appium 연결이 60초 남는다 | kit 이 연결 번호를 artifacts 에 적고, 러너가 끊은 뒤 그 번호로 Appium 연결을 지우고 나서 답한다 |
| 정기 실행 | android 를 검사 없이 컨테이너 러너로 보낸다 | android 케이스를 뺀다(뺀 수를 한 줄 알림) |
| 스크린샷 | 맥 러너는 `./artifacts`, admin 컨테이너는 이름 붙은 볼륨 — 404 | compose 의 artifacts 자리를 `.env` 한 줄로 `./artifacts` 에 걸 수 있다(기본은 지금 볼륨 그대로) |
| 화면 | android 를 보내지만 서버가 400 · 결과 칸은 PC · 모바일뿐 | 실행 위치 고르개(android 케이스가 섞였을 때) · 결과 칸 「Android 앱」 · 안내 문구 셋 |

관련 절 — 도메인/실행 §3.2 · §7 · §8.2 · §8.3 · §8.10, 도메인/러너 §5.2 「앱 실행」 · 「내 컴퓨터 러너」, 공통/6-인프라 §9 · §9.2, 공통/3-공유계약 §5.3.

## 왜

- 컨테이너 러너에는 Appium 이 없다. 폰은 사람 맥에 꽂혀 있다 → 실행 위치를 고르는 길이 있어야 android 가 정식 실행에 들어간다
- **사용자 결정 (2026-10-07)**
  - 「고르개를 지금 만든다」 — 로컬 / 디바이스 팜, 팜은 꺼진 채
  - 게이트 0 — 「디바이스 팜을 정식 테스트로 둘 건데 아직 개발 중이니 로컬에서도 우선 결과가 기록되게. 차후에 (로컬은) 테스트 실행으로 바꿀 것」 → **로컬 정식 실행은 팜이 붙기 전까지의 임시 길**이라 명세에 그렇게 적는다
  - PR 하나에 화면까지 넣는다 (할 일 14)
- 0단계 실측(`docs/plans/2026-10-07-appium-시험.md` §d) — 같은 폰에 연결 둘이 겹치면 뒤 것이 가로채고, SIGKILL 이면 정리가 안 돌아 60초 남는다
- LEARNINGS
  - 2026-09-29 PR #109 — Node fetch 는 응답 머리를 300초까지만 기다린다 → 긴 호출은 `러너에보낸다`(node:http) 그대로 쓴다
  - 2026-10-06 zod `z.object` 는 모르는 칸을 버린다 → `location` 을 runBody 에 꼭 넣고 검사로 지킨다
  - 2026-10-07 PR #171 — 연결을 「열린 결과」로 쥐면 연결 도중 끊김에 세션을 버린다 → 번호 파일은 **열린 직후** 적는다. 열리는 도중 끊기면 못 닫는 한계는 남긴다
  - 2026-10-07 PR #170 — Appium 로그 「닫힘」 문구는 꼴이 여럿이다 → 실기기 확인은 Appium 의 `GET /sessions` 로 남은 연결 수를 센다

## 명세가 안 정한 것 — 제안 (게이트 1 에서 승인받는다)

| 무엇 | 제안 |
|------|------|
| `location` 기본값 | `'local'`. 브라우저만 고른 요청은 이 칸을 안 본다 |
| 거절 순서 | android 항목이 있을 때만 — `farm` 이면 409 `FARM_OFF`, `LOCAL_RUNNER_URL` 이 비면 409 `LOCAL_OFF`. **실행을 만들기 전에** 거절한다(기록이 안 생긴다) |
| 오류 글자(화면) | `LOCAL_OFF` 「이 서버에는 내 컴퓨터 러너가 켜져 있지 않습니다. 켜는 법은 SETUP」 · `FARM_OFF` 「디바이스 팜은 아직 준비 중입니다」 · `DEVICE_BUSY` 「폰이 다른 실행에 쓰이고 있습니다」 |
| 고르개를 보이는 때 | 고른 케이스에 android 가 하나라도 있을 때만. 브라우저만이면 칸이 없다 |
| 중단을 보낼 곳 | **두 러너 모두** — 공통/3 §5.3 「맡은 러너에게만」과 다르다. 어느 러너가 맡았는지 저장하지 않아도 되고, 모르는 historyId 는 러너가 false 를 돌려줘 안전하다. §5.3 표에 한 줄 덧붙인다 |
| 폰 잠금 범위 | admin 메모리에 하나(폰 한 대 = 내 컴퓨터 러너 하나). 여러 대는 디바이스 팜 때 |
| 결과 칸 | 웹 실행은 지금과 같다(PC · 모바일). android 항목이 있는 실행만 「Android 앱」 칸이 붙는다. 디바이스 거르개 칩도 같다 |
| 정기 실행 | android 케이스를 빼고 「android 케이스 N건은 정기 실행에서 뺐다」 한 줄을 남긴다 |
| 연결 번호 파일 | `artifacts/runs/<runId>/<historyId>/appium-session` (글자 한 줄 = sessionId). 이름은 kit `protocol.ts` 상수를 러너가 같이 쓴다 |
| 실행 위치 저장 | 안 한다. 팜이 붙으면 정식 실행 = 팜, 로컬 = 테스트 실행으로 바뀌어 저장할 까닭이 없다(게이트 0 사용자) |
