## 왜

사용자 판단은 「기능은 됐는데 어드민 페이지처럼 보인다」였다. 실물을 뜯어 본 원인은 셋이다.

1. **방안지 격자 배경** — `styles.css` 의 `body` 가 28px 격자를 두 겹 깐다.
   완성된 제품이 아니라 아직 안 그린 와이어프레임으로 읽힌다. 이것이 가장 크다
2. **글자가 전부 12~14px** — 크기 위계가 없어서 무엇부터 볼지 눈이 못 고른다
3. **조건이 테두리 칩 여덟 개 줄** — `조건칩들` 이 같은 모양 버튼을 한 줄에 늘어놓는다.
   도구 모음이 아니라 실험실 스위치판으로 보인다

**컨셉은 그대로 둔다.** 「대시보드가 아니라 검사 기록지」도, 「색은 판정만」도, 「카드 대신 괘선」도
그대로다. 바꾸는 것은 표현이다 — 바탕색, 글자 크기, 컨트롤 모양, 버튼 문구.

## 고른 스킨 — 제도 청사진

차가운 청회색 바탕에 검정 잉크, 껍데기(띠·탭·표머리)에만 청색 잉크.
계측기와 도면의 어법이다. 판정 세 색은 지금 것을 색조만 차갑게 맞춰 그대로 쓴다.

### 글꼴 — 시안에서 한 곳 물러선다

시안은 본문에 IBM Plex Sans KR 을 썼다. **본문 글꼴은 Pretendard 로 둔다.** 실측 근거다.

- `apps/admin/src/reporting/html.ts:128` 이 글꼴 파일을 **base64 로 증적 문서 안에 심는다.**
  지금 `PretendardVariable.woff2` 가 **2.0MB** 이고, base64 로 부풀어 약 2.7MB 가 문서마다 들어간다
- Pretendard 는 가변(variable, 파일 하나로 굵기 여러 단을 내는) 글꼴이라 한 벌로 끝난다.
  **IBM Plex Sans KR 은 가변이 아니다** — 400·500·600 세 벌을 따로 실어야 하고
  한국어 글꼴은 벌마다 1MB 를 넘는다. **증적 문서 한 부가 세 배로 불어난다**
- 스킨 4 의 정체성은 한국어 획이 아니라 **차가운 바탕 · 청색 껍데기 · 등폭 숫자**다.
  본문 서체를 바꿔서 얻는 것이 적고 잃는 것이 크다

대신 **IBM Plex Mono 를 더한다.** TC ID · 소요시간 · 응답 코드 · RUN 번호 · 입력값 이름과 값에만 쓴다.
라틴 글자만 필요해서 굵기 둘(400·500)을 합쳐 50KB 안쪽이다. 증적 문서에 심어도 부담이 없다.
**CDN 은 쓰지 않는다** — 제품 안에 파일로 넣는다 (DESIGN.md 2026-09-18 결정 그대로).

> npm 패키지가 아니라 글꼴 파일 하나를 받아 `apps/admin/src/web/fonts/` 에 넣는 일이다.
> 라이선스는 OFL 이라 재배포에 걸림이 없다. 받는 것은 사람이 한 번 한다 (SETUP.md 에 절차를 적는다).

### 껍데기와 본문을 가르는 선 — 이 개정의 핵심

「판정 외의 색 금지」에 구멍을 내는 것이라 **어디까지가 껍데기인지를 숫자로 못 박는다.**
껍데기는 다음 넷뿐이다.

1. 맨 위 띠
2. 자리 넷의 밑줄
3. 표머리의 라벨과 그 바로 아래 괘선
4. 구획 제목 라벨

**이 넷 밖에서는 `--chrome` 을 쓰지 않는다.** 행 안에서, 배지에서, 본문 글자에서 색을 보면
그것은 여전히 판정이다. 이 문장이 SPEC 의 「본문의 색은 언제나 판정이다」와 짝이 되어야 한다 —
그래서 아래 §1.2 블록 둘째가 필요하다.

## 계약 변경 필요 (CLAUDE.md §1.2) — 승인 없이 진행하지 않는다

```

대상:    SPEC 공통/5-화면공통 §8 「맨 위 띠」

         ① 띠 위쪽 전폭 3px 선과 ② 서비스 이름 왼쪽 8px 네모, 두 자리로 옮긴다
```

## 할 일

### 1단계 — 글꼴을 들인다 (WS-E)

- `IBM Plex Mono` 400·500 을 라틴 부분집합 woff2 로 받아 `apps/admin/src/web/fonts/` 에 넣는다
- `styles.css` 에 `@font-face` 둘을 더한다. `font-display: swap`, `format('woff2')` — 지금 규칙 그대로
- `docs/SETUP.md` 에 「글꼴 파일 받는 법」 절을 더한다
- **검증** — `npm run build` 뒤 번들에 woff2 가 실렸는지. 파일 크기 합이 60KB 미만인지

### 2단계 — 토큰과 배경 (WS-E)

- `styles.css` 의 `:root` 를 위 표대로 갈아끼운다. `--chrome` 을 더한다
- `body` 의 `background-image` 두 줄(방안지 격자)을 **지운다**
- 숫자·ID 자리에 `font-family: 'IBM Plex Mono'` 를 건다

## 이번 범위 밖

시안 캔버스에 있지만 **이번에 만들지 않는다.** 스킨만 바꾸는 일과 섞으면 되돌리기가 어려워진다.

| 무엇 | 왜 미루나 | 어디로 |
|------|----------|--------|
| 실행 진행 모달 | 러너가 스텝 단위 진행을 내보내야 한다 — 러너 계약 변경이 먼저 (§1.2) | 별도 계획 |
| 리포트의 직전 실행 비교 · 실패 사유 묶기 | Admin API 조회가 새로 필요하다 | WS-D 별도 계획 |
| 케이스 목록의 값 인라인 편집 | 화면 구조 변경이라 스킨과 성격이 다르다 | WS-E 별도 계획 |
| 키보드 이동 · production 경고 | 스킨과 무관 | 킥오프 항목으로 넘긴다 |

**단, 4단계의 `값 고치기` 버튼 삭제는 여기 남는다** — 문구 대조표에 들어 있고,
버튼을 지우는 대신 `RunPickModal` 의 접개를 항상 펴 두면 되는 한 줄짜리 변경이기 때문이다.
값 편집 화면을 다시 짜는 일은 위 표의 셋째 줄이다.
