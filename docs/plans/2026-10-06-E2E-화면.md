## 왜

서버 · 러너 · 계약(PR #160~#163)이 끝나 E2E 를 화면에서 만들고 돌릴 일만 남았다. 지금은 시나리오를 API 로만 만들 수 있다.
결과 머리의 「언제 · 누가 · 어느 서버」는 케이스 단건 조회가 시나리오 번호에 404 라(시나리오 §7) 결과 응답에 실어야 한다.
E2E 줄은 판정이 없어 시간 초과도 「멈춤」 빨강이 되고 위 집계와 어긋난다 — 서버가 이미 가진 판정 식(`scenario/verdict.ts` 접은판정SQL)을 줄에 싣는다.
케이스를 지우면 그 케이스를 쓰는 시나리오가 소리 없이 「실행 불가」가 된다 — 지우기 전에 어느 시나리오인지 보여 주고, 지운 뒤에는 조립 화면에서 다른 케이스로 바꿔 끼울 길을 준다(사용자).

## 구현 규칙 — 할 일마다 지킨다 (하위 작업자에게 붙여 보낸다)

- **화면 한국어는 전부 영어 표의 키다** — `apps/admin/src/web/messages.test.ts` 가 양방향으로 센다(코드의 한국어 문자열 → 표에 키, 표의 키 → 코드에 있음). 새 화면 글자는 **새 파일 `web/messages/scenario.ts`** 에 넣고 `web/messages.ts` 가 합친다(할 일 6 이 파일을 만든다). 한국어를 템플릿 문자열(백틱)에 쓰지 않는다 — 값은 자리표 `t('{번호}번에서 멈춤', { 번호 })`
- **있는 키는 다시 넣지 않는다** — `messages.ts` 는 표를 펼쳐 합쳐 뒤가 이긴다. 뜻이 다르면 꼬리를 단다: 단계 종류는 `케이스§단계`('Case') · `대기§단계`('Wait')(이미 `대기`='Waiting' · `케이스`='Cases'). 넣기 전에 `grep -n "'<키>'" apps/admin/src/web/messages/*.ts`
- **글자는 아래 「화면 글자」 절에서 고른다.** 없는 글자를 새로 지으면 CLAUDE.md §3 「화면 한글 문구」(im-not-ai 패턴 · 「~합니다」체 마침표 없음 · 명령형 금지)를 지키고 할 일 끝 보고에 적는다
- **색은 아래 「색 표」만 쓴다.** 판정이 아닌 표시에 `--pass` · `--fail` · `--na` 와 그 바탕색을 쓰지 않는다(DESIGN 원칙 1). 토큰 밖 색(`#6B2A20` 따위) 금지. 새 CSS 는 `web/styles.css` 끝에 `/* E2E 시나리오 */` 구획으로
- 새 소스 파일 첫 줄은 한국어 한 줄 머리 주석. 파일 300줄 상한 — 넘으면 나눈다. `any` 금지. 주석은 「왜」만
- 화면 검사는 `*.test.tsx` 첫 줄 `// @vitest-environment jsdom`. `fetch` 는 `vi.spyOn(api…)` 또는 `vi.stubGlobal('fetch', …)` 로 막는다(기존 `RunList.test.tsx` 본보기). 서버 검사는 SETUP §13 임시 DB(`tp_e2e06`)
- 쓰기 버튼(저장 · 시험 실행 · 실행 · 되돌리기 · 케이스 바꾸기)은 `할수('실행')`(실행 쓰기) 일 때만 그린다 — 못 하면 안 보이게(흐리게 아님, `role.ts` 머리 주석)
- 상자(Modal)는 DESIGN 「모달」 목록 자리에만 쓴다. 이번에 더하는 자리는 할 일 11 의 「떠나기 확인」 하나뿐이다
- 비밀 칸은 `web/mask.ts` 로 가린다(서버도 가려 주지만 화면도 한 번 더)
- 접근성 — 탭은 `role="tablist"` · `tab`(`aria-selected` · `aria-controls`) · `tabpanel` + 왼쪽 · 오른쪽 화살표, 스위치는 `role="switch"` + 설명 `aria-describedby`, 진행 · 저장 결과 알림은 `role="status"`, 단추 이름에 번호(`3번 위로`), 누르는 자리는 좁은 창에서 46px(DESIGN 접근성)
