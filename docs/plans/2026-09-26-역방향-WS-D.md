## 왜

역방향 미확정 케이스는 화면 값을 기대값으로 삼았다. 증적·그래프가 확정과 섞어 세면 **버그를 지키는 초록이 통과율에 들어간다** — 실행 화면(WS-E ①)·Slack(WS-B)은 이미 가른다. 증적·대시보드만 남았다.

### BLOCKER 1 — insights 에서 미확정을 빼면 「빠진건수」가 틀어진다
`접기` 는 이번·직전 실행이 같이 쓰는 질의다. 직전 확정 → 이번 미확정인 케이스가 이번 칸에서 사라져 `빠진건수` +1 로 잡힌다(insights.ts 177~182). 명세는 판정·실패덩어리에서만 빼라 했다.
고칠 것 — 이번 미확정 키는 빠진건수에서도 건너뛴다 · 직전만 미확정이면 새 케이스처럼 · RED 에 「빠진건수 그대로」.

### 주의 1 — Grafana 조건 자리
`unconfirmed` 는 실행을 만들 때 케이스 단위로 박제돼 같은 실행·케이스·디바이스 회차는 값이 같다 → 접기 전 CTE `WHERE` 에 넣는다(접은 뒤 FILTER 면 미확정만 있는 날 0 나누기). RED 를 글자 확인이 아니라 기존 `XDD` fixture 행동 검사로.

### 주의 2 — 판정 줄 세는 단위를 적는다
회차를 접지 않고 run_item 한 행 = 하나(실행 화면 `counts` 와 같다). `NOT_RUN`(finished_at 빈 행)은 증적이 미실행, 화면은 running — 도는 중 실행은 증적이 막혀 ABORTED·저장 실패 행만 갈린다. RED 에 적는다.

### 주의 3 — 미확정 글자를 만드는 곳이 둘(`summary.ts` · `web/unconfirmed.ts`) — 가져다 쓰거나 같은 입력 같은 글자 검사
