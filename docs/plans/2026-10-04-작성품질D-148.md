등급: 3 · 갈래: WS-작성 · 2026-10-04

## 도메인 정리

작성 BC(도메인/작성 §3.6 「서브에이전트 팬아웃」)의 케이스 작성 팬아웃만 바꾼다. 훑기 팬아웃(#146 의 화면만 추가 차례)은 그대로다.
계약(타입 · API · DB) 변경 없음. 훅은 작성 자식에서만 켠다(`AUTHORING_GATE3_DIR` 이 있을 때 — 에이전트가 자식에게만 준다).

## 왜

MKT 재측정 #11211(180분 · 케이스 227) 조사 — 자식이 화면 부품 다섯만 공용으로 만들고 준비 · 정리 도우미(API 로그인 · 장바구니 되돌리기 · 지난 글 치우기)를 빠뜨렸다.
보조는 「components 고치지 않는다」 때문에 파일마다 복사했다(`기본장바구니로되돌리기` 29 파일 · 도우미 19개). 「한 차례」 규칙인데 케이스 팬아웃을 세 차례 돌렸다(2차만 98분).
「전제 확인 55%」는 측정 착시 — 확인 안 한 102건 중 95건이 전제가 「비회원이다」뿐이다. 준비가 있는 케이스만 세면 94%(예전 95%).

게이트 0 승인(2026-10-04) 네 문장.
1. 표의 전제 칸에서 두 케이스 이상에 나오는 준비 · 정리마다 공용 도우미를 먼저 만든다
2. 보조는 모자란 도우미를 `components/draft-<묶음>.component.ts` 한 파일에만 적고 요약으로 알린다. 자식이 합칠 때 같은 일을 하나로 합쳐 공용으로 옮기고 draft 를 지운다. 남으면 끝 검사 ⚠️
3. 작성 자식에서만 켜지는 훅 — 케이스 작성 보조는 묶음 넷까지, 같은 묶음 다시 띄우기는 한 번까지. 넘으면 거절. 훑기 보조는 세지 않는다
4. 전제 확인 비율의 분모는 비회원 · 로그아웃 상태 말고 준비가 있는 케이스. 품질 줄에 「준비 없는 케이스 N」
