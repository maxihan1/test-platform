**새로 설치한 서버에서 작성 에이전트가 처음부터 멈춘다.** `POST /api/auth/password` 는 토큰 통로 밖이다. 명세에 없는 경우 → 게이트 1 결정

### 주의
1. **비밀번호를 바꿔도 다른 세션이 안 끊긴다** (ceo) — 설치 직후 누가 먼저 `admin/admin` 으로 들어와 있으면 바꾼 뒤에도 그 쿠키가 운영 계정으로 통한다 → 게이트 1 결정
2. **preHandler 도 가입을 로그인 없이 통과시켜야 한다** (eng) — 지금은 login 만 건너뛴다. 두 훅이 같은 목록 하나를 보게 한다
3. **기존 fixture 가 `is_approved` 를 안 적어 기본값 false** (eng) — `agentToken`·`gate`·`routes`·`identify`·`authoring/stop` 검사. 할 일 1 files 에 더하고 두 칸을 직접 적는다
4. **아이디 모양 규칙** (eng · ceo · design) — 소문자 권장, 설정 화면 만들기·`add-user.ts` 도 같은 상수
5. **가입 남용** (eng · ceo) — 모양 → 길이 → 중복 → 해시 순서 · 아이디·이름·비밀번호 길이 상한 · 요청 수 제한은 새 부품이라 이번엔 없음을 명시
6. **동시 처리** (ceo · eng) — 수락·거절 `WHERE is_approved = false` · 기본 계정 `ON CONFLICT DO NOTHING` · 함수가 client 를 받아 `pg_temp` 로 시험
7. **변경 뒤 화면이 강제 상태를 못 벗어난다** (design) — 성공하면 `api.me()` 다시 읽기 · 평소 변경 뒤 갈 곳
8. **변경 화면의 틀** (design) — 짙은 바탕 상자인지 Shell 안인지
9. **입력 오류 문구** (design) — 불일치 · 8자 미만 · 빈 칸 · `USERNAME_SHAPE` 안내 · `autocomplete`
10. **승인 충돌** (design) — 409·404 문구와 목록 다시 읽기 · 서비스 0개로 수락 가능한가 · 거절 확인 줄은 `AgentToken.tsx` 모양
11. **주소 갈래** (design) — 로그인한 사람의 `#/signup`, 안 한 사람의 `#/password`
12. **④ 인계** (eng · ceo) — `/grafana/**` 에도 변경 강제 403
13. 작은 것 — 승인 대기 문구를 오류 빨강이 아니라 안내 모양 · `Login.tsx` 머리 주석 · 허용 셋은 `METHOD 틀`·HEAD=GET

### 통과한 것
- 문(승인 대기·변경 강제)을 가입보다 앞에 · 변경 강제를 권한 판정보다 먼저 · 승인 대기 판정을 비밀번호 확인 뒤에(계정 존재가 안 샌다)
- 가입 본문의 role·권한 무시 검사 · 기본 계정을 listen 전에, 한 문장 `NOT EXISTS`
- 수락이 권한 고르개를 재사용 · 로그인 상자 모양 재사용 · 새 계약 변경 없음
