## 도메인 정리

- BC: 작성(§3.6 · §7) · 배포(공통/6 §9) · 컨텍스트 지도(공통/1 §3) · 인증(§7 에이전트 토큰)
- 계약 변경(게이트 0 승인, 2026-09-23): compose 새 서비스 `author` · `.env` 새 값 셋(`CLAUDE_CODE_OAUTH_TOKEN`·`GH_TOKEN`·`AUTHORING_AGENT_TOKEN`) ·
  「맥에서 돈다」 → 「서버 컨테이너가 기본, 맥은 같은 스크립트의 대체 경로」 · 이미지에 claude CLI·gh
- DB·API 계약은 안 바뀐다. 에이전트는 지금처럼 admin 을 HTTP 로 부르고 에이전트 토큰으로 붙는다

## 왜

「맥 에이전트를 켜 두는 방식은 사용성이 너무 떨어진다」(사용자, 2026-09-23). 브라우저는 맥의 프로그램을 못 켜고,
로그인 시 자동 실행도 거절됐다. 서버 안에서 돌면 보내기 → 5초 안에 작성이 시작되고, 누가 어느 기계에서 보내든 같다.
`claude setup-token` 이 구독용 장기 토큰을 준다(`claude setup-token --help`: "requires Claude subscription") — 추가 비용 0 을 지킨다.

부수 효과: 서버와 에이전트가 같은 저장소 폴더를 보므로 병합 뒤 당기기가 서버에서도 먹는다 (PR #67 후속 하나가 닫힌다).

재검토 없이 아래로 고쳐 구현한다. 이 절이 위 할 일을 이긴다.

- **비밀값 가림** — `./:/repo` 위에 `/dev/null:/repo/.env:ro` · author 는 `authoring` 망(admin 만 같이)에만 — postgres·runner 에 못 닿는다
- **uid** — `user: "${HOST_UID:-1000}:${HOST_GID:-1000}"` · `HOME=/tmp/author-home`(start.sh 가 만든다) · 맥 Docker Desktop 은 소유권을 바꿔 주므로 리눅스 실측은 후속
- **node_modules** — 볼륨 + start.sh 가 `package-lock.json` 해시를 볼륨 안 파일과 대조해 다르면 `npm ci`
- **자식 env** — `AUTHORING_AGENT_TOKEN` 은 빼고 `CLAUDE_CODE_OAUTH_TOKEN` 은 넘긴다(둘 다 테스트로 고정) · `/proc/<부모>/environ` 으로 GH_TOKEN 이 읽히는 것은 한계로 SPEC 에 적는다
- **주소** — 정확히 `admin` 만 허용(`http://qaserver` 는 거부)
- **첫 설치** — compose `profiles: [authoring]` · SETUP 에 번호 순서(admin 띄우기 → 토큰 발급 → `.env` 세 값 → `--profile authoring up -d author`)
- **git** — start.sh: `core.hooksPath` 가 절대경로면 경고 후 계속(훅이 꺼질 뿐 작성은 된다) · SETUP 에 「호스트에서 `git worktree prune` 을 author 가 도는 중에 치지 마라」
