# 화면 크롤러 — ariaSnapshot 으로 사이트 구조를 먼저 뽑는다

등급: 3 · 갈래: WS-작성 · 2026-10-04

## 도메인 정리

작성 BC §3.6 「★ 역방향」 훑기 규칙(대조 · 화면만 둘 다). 계약(타입 · API · DB) 변경 없음.
새 스크립트는 작성 자식이 작업 트리에서 명령 한 번으로 돌린다 — 에이전트 쪽 흐름은 그대로이고, 줄 프롬프트 역방향 절에 크롤 폴더 · 명령 한 줄이 는다.

## 왜

사용자 지시 10(2026-10-04 · 「페이지 구조를 한번에 파악하는 playwright 기능」). 지금 훑기는 AI 가 화면마다 열기 → `playwright-cli snapshot`(속은 `ariaSnapshot`) → 요약을 대화로 한 장씩 해 CDY 23장 24분 · MKT 24장 약 30분, 그 내용이 대화에 쌓여 한도를 쓴다.
열기 · 구조 읽기는 기계가 같은 결과를 낸다. 눌러 봐야 아는 것(팝업 · 탭 · 펼치기 · 다음 단계 · 입력 규칙의 오류 문구)만 AI 몫으로 남긴다. 로그인은 사이트마다 폼이 달라 지금처럼 AI 가 스크립트로 하고, 크롤러는 그 상태 파일을 받는다.

게이트 0 승인 다섯 문장.
1. 자식이 로그인 상태 파일을 만든 뒤 `npx tsx scripts/authoring-crawl.ts` 를 한 번 — 로그인 전 · 후 두 번 같은 사이트 링크를 따라 화면마다 `ariaSnapshot` · 입력칸 속성(필수 · 글자 수 · 형식) · 링크를 파일로
2. 링크 이동만(누르기 · 제출 없음) · 로그아웃 · 내려받기 · 다른 사이트 제외 · 같은 틀은 하나 · 최대 100장 · 10분
3. 첫 화면 목록은 크롤러 결과로(#146 의 링크 모으기를 대신)
4. 보조는 크롤러 파일을 읽고 「한 칸」만 직접 연다. 크롤러가 못 찾은 화면은 「더 갈 곳」
5. PR 에 「기계로 본 화면 N장 · AI 가 직접 연 한 칸 M개」
