# WS-D 리포팅 — 진행 기록

## 2026-09-19

- 완료:
  - **증적 문서 세 형식** — HTML · PDF(Playwright `page.pdf()`) · 엑셀(exceljs). 셋 다 같은 표시용 모델에서 나온다
  - **증적 API 둘** — `POST /api/runs/:runId/evidence`(PENDING 을 먼저 돌려준다) · `GET /api/evidence/:id`(영구 주소)
  - **Grafana 대시보드** — 데이터소스 + 패널 넷(성공률 추이 · 평균 소요시간 · 실패 TOP 10 · 최근 실행 목록)
  - **부팅 복구** — 만드는 도중 죽어 `PENDING` 으로 굳은 행을 열 때 한 번 닫는다
  - 검사 386건 · 검사기 5종 EXIT=0 · 전체 테스트 연속 3회 EXIT=0
- 미완: 없음. 다만 아래 「더 고칠 수 있는 것」 다섯이 남았다
- 막힌 것: 없음. 치명 2건을 검사 단계에서 잡아 고쳤다(스크린샷 미표시 · 비밀값 평문 노출)
- 다음 세션이 알아야 할 것:
  - **진입점은 `collect.ts` 의 `collectRun()` 이다.** 실행 한 부를 읽어 「표시용 모델」을 만든다
  - **라벨 · 비밀값 가리기 · 빈 값 처리가 전부 `collect.ts` 한 자리에서 끝난다.**
    `html.ts` · `xlsx.ts` 는 그 모델만 본다 — 원본 JSON 에 못 닿는다.
    **렌더러에서 마스킹을 다시 하지 마라.** 형식이 늘 때마다 새는 자리가 하나씩 는다
  - 판정 글자는 `html.ts` 의 `판정글자` 상수가 정본이다 — `PASS→통과` `FAIL→실패` `NA·NOT_RUN→미실행`.
    **`NA` 와 `NOT_RUN` 이 같은 배지를 다는 것은 겹침이 아니라 설계다** (SPEC §8.3 218줄).
    둘을 가르는 것은 배지가 아니라 옆에 붙는 사유 한 문장이다
  - **스크린샷은 `generate.ts` 의 `스크린샷을심는다()` 가 `data:` URI 로 문서 안에 넣는다.**
    경로로 두면 HTML 은 404, PDF 는 `setContent` 라 요청조차 안 나간다. 엑셀만 경로 글자를 쓴다
  - DB fixture 접두사 — `XDC`(수집) · `XDR`(상태·라우트) · `XDD`(대시보드) · `XDG`(생성)
  - **병합 뒤 `docker compose restart grafana` 를 한 번 돌려야 대시보드가 뜬다.**
    도는 Grafana 는 프로비저닝 폴더를 기동 때 읽는다

### 더 고칠 수 있는 것 (이 갈래 안)

1. **대시보드가 Grafana 기간 선택을 무시한다** — 30일이 SQL 에 박혀 있다.
   고칠 때 `dashboard.test.ts` 가 같이 움직여야 한다 — 지금 그 테스트가 `rawSql` 을 **그대로 실행**해서
   `$__timeFilter` 같은 매크로를 넣으면 문법 오류로 깨진다
2. **`GET /api/evidence/:id` 에 `Content-Disposition` 이 없다** — 엑셀이 확장자 없는 이름으로 떨어져
   더블클릭으로 안 열린다. SPEC §8.4 가 엑셀을 「받기」로 정의한 동작이 성립하지 않는다
3. **admin 컨테이너에 한글 글꼴이 없다** — 저장소에 글꼴 파일이 0개인데
   `apps/admin/Dockerfile:22` 주석은 「번들에 담겨 같이 실린다」고 적고 있다. **주석이 사실과 다르다.**
   PDF 한글이 대체 글꼴로 그려진다
4. **PDF 가 실행 대기줄을 공유한다** (`execution/dispatcher.ts` 의 `enqueue`).
   큰 실행이 도는 동안 「만드는 중」이 굳고 취소 통로가 서버 재시작뿐이다
5. **`routes.ts` 의 `정수()` 가 `1e21` 을 통과시킨다** — Postgres 가 `22003` 을 던져 잡히지 않은 500 이 난다

`store.ts` 의 `recoverPending()` 은 조건 없는 전역 UPDATE 다. 기존 `recoverRunning()` 과 같은 모양이라
새로 들인 위험은 아니지만, admin 을 여러 개 띄우면 서로의 진행 중 문서를 닫는다.

### 다른 갈래로 넘긴 것

**WS-E(화면)** — `apps/admin/src/web/ItemDetail.tsx:37` 이 입력값을 가리지 않고 그대로 그린다.
SPEC §4.1 은 화면과 증적 문서 **둘 다**에 `********` 를 요구한다. 킥오프에 항목으로 적어 뒀다.

### SPEC 안에서 두 문장이 다른 말을 하는 것 (§1.2 승인 필요, 미해결 셋)

- §8.4 엑셀 칸 목록에 「사유」가 없는데 같은 절이 「미실행과 사유로 문서에 남는다」고 한다 —
  HTML 은 사유를 그리고 엑셀은 안 그려서 **한 실행의 두 형식이 다른 말을 한다**
- 실행 중(`RUNNING`)에 증적을 뽑을 수 있는데, 끝난 뒤 다시 뽑으면 내용이 달라져
  §8.4 의 「다시 만들어도 내용이 달라지지 않는다」가 거짓이 된다
- §8.5 소제목은 「반복 실행이 **성공률**을 오염시키지 않게」로 좁은데 본문은 일반 규칙이다.
  「실패 TOP 10」이 회차를 안 접어 불안정한 케이스 하나가 순위를 독차지한다

### 같은 날 뒤에 더 닫힌 것 (마무리 PR)

- **§8.5 소제목이 좁은데 본문은 일반 규칙이다** (「SPEC 안에서 두 문장이 다른 말을 하는 것」 셋째) — 닫혔다.
  소제목을 「반복 실행이 **성공률**을 오염시키지 않게」에서 「반복 실행이 **지표**를 오염시키지 않게」로 넓히고,
  본문에 **어느 패널이 회차를 접고 어느 패널이 안 접는지**를 적었다.
  「실패 TOP 10」도 이제 회차를 접는다 — `bool_or(status = 'FAIL')` 이라 **미실행은 실패로 세지 않는다**
- **엑셀 칸 목록에 「사유」가 없다** (같은 목록 첫째) — 닫혔다. `xlsx.ts` 에 `미실행·판정불가 사유` 칸이 생겼다
- **실행 중에 증적을 뽑을 수 있다** (같은 목록 둘째) — 닫혔다. 서버가 409 `RUN_NOT_FINISHED` 로 막는다 (SPEC §7)
- **`GET /api/evidence/:id` 에 `Content-Disposition` 이 없다** (「더 고칠 수 있는 것」 2) — 닫혔다
- **`정수()` 가 `1e21` 을 통과시킨다** (「더 고칠 수 있는 것」 5) — 닫혔다. `routeParams.ts` 가 상한까지 본다
- **admin 컨테이너에 한글 글꼴이 없다** (「더 고칠 수 있는 것」 3) — **이제 다 닫혔다.**
  위에서 「절반 닫혔다」고 적은 증적 문서 경로도 `html.ts` 가 `@font-face` 로 글꼴을 문서 안에 심는다
- **PDF 가 실행 대기줄을 공유한다** (「더 고칠 수 있는 것」 4) — **안 닫혔다.**
  고치려면 게이트 0 이 필요하고 `execution/**` 은 다른 갈래 소유 경로다.
  잊히지 않게 `docs/WORKSTREAMS.md` WS-E 킥오프의 **「넘긴 것 ⑦」**로 올려 뒀다
