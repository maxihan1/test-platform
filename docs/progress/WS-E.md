### 컨테이너가 화면을 서빙하지 못한다 — 내 소유 경로 밖이라 고치지 않았다

`app.ts`는 `src/web/dist`가 있으면 서빙하도록 이미 돼 있다. 그런데

- `.dockerignore`에 `**/dist`가 있어 호스트에서 빌드한 산출물이 이미지에 안 들어간다
- `apps/admin/Dockerfile`에 vite 빌드 단계가 없다

둘 다 `apps/admin/src/web/**` 밖이다 (CLAUDE.md §1.1). **병합 담당이 Dockerfile에
`RUN npx vite build --config apps/admin/src/web/vite.config.ts` 한 줄을 넣으면 된다.**
`.dockerignore`는 `**/dist`를 그대로 둬도 된다 — 이미지 안에서 빌드하면 COPY를 타지 않는다.

지금 확인하는 방법은 개발 서버다. API는 진짜 admin(3000)이 받는다.

```
docker compose up -d
npx vite --config apps/admin/src/web/vite.config.ts
# → http://localhost:5173
```

### 다음 세션이 알아야 할 것

- **진입점**: 폼 자동 생성은 `schema.ts`의 `schemaToFields`/`toValues`,
  실행 전 검증은 `validation.ts`, 환경별 묶기는 `group.ts`, 주소 해시는 `route.ts`.
  화면은 `CaseList`·`RunSetup`·`RunList`·`RunResult`·`ItemDetail` 다섯 개, 공용 조각은 `ui.tsx`
- **`validation.ts`는 서버의 `../execution/validate.ts`를 그대로 부른다.** 검증기를 두 벌 두면
  '실행하기'와 '입력값 세트로 저장'이 같은 값에 다른 사유를 낸다. WS-B가 그 파일에
  DB나 fastify를 import 하면 화면 빌드가 깨진다 — 순수 함수로 남겨 둬야 한다
- **Vite 프록시 규칙은 `'^/api/'`다.** `'/api'`로 적으면 소스 파일 `/api.ts` 요청까지
  admin으로 넘어가 화면이 통째로 빈다 (LEARNINGS)
- **개발 서버 명령에 `--config`가 꼭 필요하다.** 화면 폴더에 package.json을 만들지 않았다 —
  루트·admin의 package.json은 Phase 0 공용 골격이라 스크립트를 넣을 수 없다
- **단위 테스트는 `*.test.ts`만이다.** vitest include가 `apps/**/*.test.ts`라 `.test.tsx`는 안 잡힌다.
  그래서 JSX가 아니라 순수 함수(스키마→칸, 묶기, 주소)를 테스트했다. DB를 쓰지 않으므로 fixture 접두사도 없다
- **좁은 창(620px 미만) 레이아웃은 눈으로 확인하지 못했다.** 목업의 미디어 쿼리를 그대로 옮기고
  `.err`·`.after-assert` 두 개를 더했다. 브라우저 창을 620px 아래로 줄이지 못했다
- `docs/LEARNINGS.md`가 202줄이다. 자체 규칙(100줄)을 넘었으니 정리 대상이다 — 내 갈래 소유가 아니라 건드리지 않았다

- **`group.ts` 의 칸이 배열이다.** 회차가 여럿이면 `회차요약()` 이 `3/5 통과` 를 만든다.
  하나라도 통과가 아니면 통과 색으로 칠하지 않는다
- **총건수로 페이지를 세지 않는다.** `paging.ts` 의 인자에 `total` 자리가 아예 없다
- ③ 이 이어받을 것 — 설정 화면(§8.8)이 서비스·계정·대상 서버·Slack 웹훅을 다 받는다.
  그때 `add-service.ts` 의 `--env` 와 `SETUP.md` 의 배정 SQL 은 첫 서비스용으로 남긴다.
  **서비스 색을 만들 때 흰 글자 대비 4.5:1 을 재는 장치**도 그 화면 몫이다 (① 에서 넘겼다)

## 2026-09-19 — ③ 마감 (PR #27)

킥오프 마지막 넷 — 15 설정 화면 · 18 좁은 화면 · 20 글꼴 번들 · 23 Slack 웹훅 칸.
**23개가 전부 끝났고 WS-E(화면)가 닫혔다.**

### 왜 1등급이었나 — 서버를 안 건드렸다

①②는 화면이 읽을 통로가 없어 각각 2·3등급이었다. 이번엔 `settings/routes.ts` 에
필요한 API 가 전부 있었다 — 서비스·계정·대상 서버·Slack 웹훅·비밀번호 다시 만들기.
접두사 불변(`PREFIX_IMMUTABLE`)도 서버가 이미 막는다. **화면만 만들면 됐다.**

### 브라우저로 눌러 보다가 찾은 것 셋

| 무엇 | 안 고쳤으면 |
|---|---|
| **배정이 없으면 설정 화면까지 덮였다** | 안내가 「설정에서 자기 자신을 배정하세요」로 보내 놓고 그 자리를 막았다. **서비스가 0개인 첫 운영자는 영영 못 빠져나온다** |
| **자기 자신을 배정해도 띠가 그대로** | 시킨 대로 했는데 아무 일도 안 일어난다. 새로고침하면 되지만 그러라고 알려 주는 것이 없다 |
| **기본 서비스 색이 명암비 미달** | `add-service.ts` 의 `#5B7FDE` 가 3.79 였다. DEMO 하나가 아니라 **새로 만드는 모든 서비스**가 미달 색을 받고 있었다 |

앞의 둘은 **검사 셋과 타입 검사를 다 통과한 채로** 있었다. 눌러 보지 않으면 안 나온다.
세 번째는 이번에 만든 명암비 함수가 잡았다 — 장치를 만들자마자 그 장치가 기존 값을 걸렀다.

### SPEC 이 정한 것 그대로

- 설정 화면은 **좁은 화면 대응을 하지 않는다** (§8.8 「책상에서만 쓰는 화면」).
  킥오프 18 이 고를 둘(실행 기록 목록·실행 결과)과도 맞는다
- 임시 비밀번호는 **모달이 아니라 화면 안의 줄**이다. 모달은 두 자리뿐이다 (DESIGN.md)
- 마지막 운영 계정은 등급 드롭다운과 내리기 버튼을 **아예 안 그린다** (§3.5)

### 다음 세션이 알아야 할 것

- **설정 화면의 판단은 `settingsView.ts` 에 있다** — 접두사 모양 · 명암비 · 웹훅 칸 ·
  마지막 운영 계정 · 서버 오류를 사람 말로. 화면(`Settings.tsx`)은 그리기만 한다
- **`빈띠사유()` 가 지금 자리를 받는다.** 설정만 예외로 두는 자리다 — 새 화면을 더할 때
  「배정이 없어도 열려야 하는가」를 물어본다
- **접두사 정규식이 두 곳에 있다** — 서버 `settings/routes.ts` 와 화면 `settingsView.ts`.
  화면은 서버 모듈을 import 할 수 없다(fastify 를 끌고 와 번들이 깨진다). SPEC §2 를 고치면 둘 다 고친다
- **글꼴은 `web/fonts/PretendardVariable.woff2` 하나다.** 굵기 셋을 한 파일로 낸다.
  `font-feature-settings` 대신 `font-variant-numeric` 을 쓴다 — 앞엣것은 폴백에서 조용히 무효다
- **`scripts/` 가 admin 이미지에 안 들어간다** (아래 「넘기는 것」)

### 넘기는 것

| 무엇 | 어디로 | 왜 |
|---|---|---|
| `apps/admin/Dockerfile` 에 `COPY scripts` 가 없다 | **배포(§9.2)** | `docker compose exec admin npx tsx scripts/add-user.ts` 가 `ERR_MODULE_NOT_FOUND` 로 죽는다. **SETUP.md 가 안내하는 첫 계정 만들기가 실제로는 안 된다.** Dockerfile 은 3등급(COMPOSE) 표면이라 이번 범위에서 고치면 등급이 올라간다 (CLAUDE.md §1.1 — 보고만 한다) |
| `gate.ts` 의 IDOR | **WS-F(인증)** | 로그인한 사람이 실행 번호만 바꿔 남의 서비스 기록을 읽는다. `origin/main` 의 기존 문제다 |
| JSX 단위 테스트 | 별도 작업 | 사용자가 ③ 게이트에서 「지금처럼 간다」를 골랐다. 그물을 씌우려면 ①②의 화면까지 한꺼번에 덮는 작업이 맞다 |

### 검사 렌즈 셋 — 자기검사가 혼자서는 못 잡았을 것들

실측 2등급이라 렌즈 셋을 병렬로 돌렸다. **셋이 독립적으로 겹쳐 지적한 것이 다섯**이었다.

| 렌즈 | 결과 |
|---|---|
| `spec-review` [자기검사] | 치명 0 · 중대 1 · 경미 2 |
| 코드 리뷰 | 심각 4 · 보통 9 · 경미 7 |
| 화면 QA | 심각 3 · 보통 7 · 경미 7 |

**전부 검사 일곱과 타입 검사를 통과한 채로 있었다.** 대표적인 것 셋 —

- **계정 목록이 실패하면 영영 「불러오는 중입니다」** (`users.error` 를 보는 자리가 없었다)
- **임시 비밀번호가 화면 밖에 떴다.** 계정이 열 명만 돼도 안 보이는데 **그 사이 옛 비밀번호는
  이미 죽어 있다** — 본인은 영문도 모르고 로그인이 막힌다
- **입력칸 아홉 개가 브라우저 기본 모양이었다.** 스타일이 `input[type='text']` 에 걸려 있는데
  React 는 기본 `type` 을 DOM 에 안 써 준다. **속성 선택자는 속성이 실제로 있어야 맞는다**

전말과 고친 목록은 `docs/reviews/2026-09-19-WS-E-3.md`.

**남은 판단 하나** — SPEC §8.8(「색을 언제든 고친다」)과 §8(「서비스 색은 띠에서만 쓴다」)이
부딪힌다. 색을 안 보여주고 색을 고르게 할 수 없다. 두 렌즈가 §8 에 예외 한 줄을 더하자고 제안했고
그건 SPEC 변경이라 게이트 0 이 필요하다.
