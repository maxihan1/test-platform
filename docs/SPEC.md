# 테스트 자동화 플랫폼 — 스펙

> 이 문서는 구현의 **단일 진실 원천(Single Source of Truth)** 이다.
> 여기 적힌 타입·계약·스키마와 다르게 구현하면 병렬 작업이 충돌한다.
> 변경이 필요하면 **구현하지 말고 먼저 이 문서를 고칠 것.**

**스펙은 여러 장으로 나뉘어 있다. 이 문서는 색인이다.**
**몇 장인지 여기 적지 않는다** — 장이 늘면 이 줄만 뒤처진다 (`CLAUDE.md §2.7 ⑤`).
세는 일은 아래 장 목록과 `npm run check:spec` 이 한다.
전문을 통째로 읽지 않는다. 아래에서 하려는 일을 찾아 그 줄의 장만 읽는다.

### 이 판이 뒤집은 것

앞 판을 기억하는 세션이 **옛 전제로 일하지 않게** 여기 모아 둔다. 판단 근거는 각 절에 남겨 뒀다.

| 앞 판 | 지금 | 어디 |
|-------|------|------|
| 서비스마다 인스턴스를 따로 띄운다. DB도 따로다 | **한 벌이 서비스 여럿을 감당한다.** 충돌은 케이스 번호 접두사 배정으로 막는다 | §1 · §2 |
| 접두사는 기능 영역을 뜻한다 | **자유 형식이다. 플랫폼은 뜻을 모른다** — 모양과 중복만 본다 | §2 |
| 권한 칸을 만들지 않는다 | **등급 셋** — 보기만 · 실행까지 · 운영 | §3.5 · §6 |
| 인증 없이 부를 수 있는 API 가 하나 있다 (정기 실행) | **없다.** 정기 실행은 컨테이너 안 명령으로 만든다 | §7 · §9.2 |
| 반복 실행에 상한을 두지 않는다 | **한 번에 만들어질 실행 항목 1000건까지** | §8.2 |
| 실행 항목 수는 케이스 수 × 디바이스 수 × 반복 횟수 | **Σ(케이스마다의 디바이스 수) × 반복 횟수다** (2026-09-21 수정). 케이스마다 선언한 디바이스가 달라 곱셈이 성립하지 않는다 | §8.2 |
| 케이스 목록 검색 조건에 「기능 영역」이 있다 | **없다.** 서비스는 사이드바 서비스 고르개에서 고른다 | §8.1 · §8 |
| 증적은 PDF 하나 | **골라서 만든다** — PDF · 엑셀 · HTML | §8.4 |
| 계정·서비스를 서버 명령으로 만든다 | **설정 화면에서 만든다.** 첫 계정·첫 서비스만 명령이다 | §8.8 · §9.2 |
| 껍데기는 맨 위 가로 띠 + 그 아래 가로 탭 넷이다 | **왼쪽 사이드바 + 상단 헤더 + 푸터다** (2026-09-21). 자리 목록은 그대로고 배치만 세로로 갔다 | §8 |
| 실행이 끝나도 알리지 않는다 | **완료 모달 · 알림 줄 · Slack** (2026-09-18 신설). **진행 중의 진행도 같은 상자가 그린다** (2026-09-21) | §8.9 |
| 진행 중인 항목은 **근사치**다. 항목 안에서 절차가 어디까지 갔는지는 알 길이 없다 | **러너에게 물어**(`GET /progress`) 도는 것을 전부, **절차와 머문 시간까지** 그린다 (2026-09-21) | §5.2 · §8.9 |

결정의 전말은 [reviews/2026-09-17-eng-review.md](reviews/2026-09-17-eng-review.md)(기술)와
[reviews/2026-09-17-design-review.md](reviews/2026-09-17-design-review.md)(화면)에 있고,

| **작성 입력(파일·피그마)을 바꿀 때** | 도메인/작성 §7 「자료」가 **정본이다** — 받는 종류·상한·피그마 주소 정규화·`DRAFT` 순서가 거기 있고 **상한 숫자는 그 절에만 적는다.** 표와 파일 저장 자리는 공통/4-데이터모델 §6 「작성 자료」, 피그마 토큰 칸은 도메인/인증 §8.8 → 새 통로는 아래 줄처럼 `auth/gate.ts`·`auth/scope.ts` 두 표에 같이 든다. 피그마를 읽는 명령은 `.claude/skills/tpx-cases/SKILL.md` |
| **작성 에이전트가 로그인하는 방법(에이전트 토큰)을 바꿀 때** | 도메인/인증 §7 「인증 적용 범위」가 **정본이다** — 토큰이 여는 통로 목록·발급 대상·해시가 거기 있다. 코드의 목록은 `auth/gate.ts` 의 `토큰통로`, 칸은 공통/4-데이터모델 §6 `app_user.agent_token_hash`, 화면은 도메인/인증 §8.8 계정 표, 에이전트가 토큰을 두는 자리는 `docs/SETUP.md` §8 |
| **작성한 것을 머지하는 자리를 건드린다** | 도메인/인증 §7 「등급으로 갈리는 자리」 표가 **정본이다** — 머지는 `admin` 이고 **표에 없는 경로의 기본값도 `admin`** 이다. 어느 통로가 어느 쪽인지는 도메인/작성 §7 이 경로마다 적는다. **화면이 버튼을 안 그리는 것은 편의이지 방어가 아니다** → **새 통로는 코드의 표 둘에 같이 든다** — `auth/gate.ts` 의 등급표(무슨 등급인가)와 `auth/scope.ts` 의 라우트표(어느 서비스인가). **다른 표다** |
| **작성 에이전트가 도는 자리(서버 `author` 컨테이너 · 맥 대체)를 바꿀 때** | 도메인/작성 §3.6 「★ 서버 컨테이너가 기본이다」가 **정본이다** — 무엇을 가리고 어느 망에 두는지와 남는 한계가 거기 있다. 설정값·이미지는 공통/6-인프라 §9 「작성 에이전트 컨테이너 author」, 구성의 기계 검사는 `apps/admin/src/deploy.test.ts`, 시작 검사는 `apps/authoring/start.sh`. 사람이 따라 하는 설치 순서는 `docs/SETUP.md` §8. **모델·effort·예비 모델·CLI 최신화**는 `scripts/authoring-model.ts`, **동시 상한·자식 격리(작업마다 사본·자리 uid)** 는 `scripts/authoring-copy.ts` (2026-09-24) |
| **작성 에이전트 경로(전용 체인·머지·CI 가벼운 길)를 바꿀 때** | 도메인/작성 §3.6 「작성 에이전트는 전용 체인이다」가 **정본이다** — 에이전트가 무엇을 어떤 순서로 하는지, 머지를 누르면 CI 를 기다렸다 병합하는 것이 거기 있다. **테스트만 바뀐 PR·push 가 무엇을 건너뛰는지(가벼운 길)의 정본은 docs/HOOKS.md 「CI 와 병합 차단」** → 자식 세션이 타는 스킬은 `.claude/skills/tpx-author/SKILL.md`, 에이전트 스크립트가 git·gh 를 부르는 인자와 판정은 `scripts/authoring-chain.ts`, 작업마다 만드는 사본의 자리·git 환경은 `scripts/authoring-copy.ts`, 사본 만들기·자식 거두기는 `scripts/authoring-child.ts` |
| 표에 칸을 더한다 | 공통/4-데이터모델 §6 — **계약이다.** CLAUDE.md §1.2 절차를 먼저 밟는다 |
| 러너가 주고받는 모양을 바꾼다 | 도메인/러너 §5.2 — **계약이다.** 같은 절차 |
| 포트·컨테이너·배포를 건드린다 | 공통/6-인프라 §9 — **한 벌에 한 번 정하는 값만 여기 있다.** 서비스마다 다른 값은 위 줄 |

## 절 번호 → 어느 장에 있는가

## 표 → 주인과 정의 위치

표마다 주인 도메인이 하나씩 있다. 정의는 전부 **공통/4-데이터모델 §6** 한 곳에 모여 있다.
스키마를 쪼개지 않는 이유는 그 장 머리에 적어 뒀다.

| 표 | 주인 | 그 도메인 장 |
|----|------|------------|
| `service` · `service_env` · `user_service` | 인증 (설정 화면이 쓴다) | [도메인/인증](spec/도메인/인증.md) |
| `test_case` | 카탈로그 | [도메인/카탈로그](spec/도메인/카탈로그.md) |
| `param_set` · `test_run` · `run_item` · `run_item_step` | 실행 | [도메인/실행](spec/도메인/실행.md) |
| `evidence_document` | 리포팅 | [도메인/리포팅](spec/도메인/리포팅.md) |
| `app_user` | 인증 | [도메인/인증](spec/도메인/인증.md) |
