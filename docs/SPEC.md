# 테스트 자동화 플랫폼 — 스펙

> 이 문서는 구현의 **단일 진실 원천(Single Source of Truth)** 이다.
> 여기 적힌 타입·계약·스키마와 다르게 구현하면 병렬 작업이 충돌한다.
> 변경이 필요하면 **구현하지 말고 먼저 이 문서를 고칠 것.**

**스펙은 12장으로 나뉘어 있다. 이 문서는 색인이다.**
전문을 통째로 읽지 않는다. 아래에서 하려는 일을 찾아 그 줄의 장만 읽는다.

## 무엇을 하려는가 → 무엇을 읽는가

### 갈래를 맡았을 때

| **WS-B 실행** | 공통 1 · 공통 3 · 공통 5 · **도메인/실행** · 공통 4 | 737줄 |

| **WS-D 리포팅** | 공통 1 · 공통 5 · **도메인/리포팅** · 공통 4 | 537줄 |
| **WS-E 화면** | 공통 1 · 공통 5 · **도메인 5장의 §8 절** · `DESIGN.md` | 824줄 |

`공통 1`은 어느 갈래든 읽는다. 용어를 다르게 쓰면 나머지가 전부 어긋난다.

### 기능을 더하거나 고칠 때

| 하려는 일 | 읽을 곳 |
|----------|--------|
| 케이스 선언에 칸을 더한다 | 공통/2-명세선언 §4 → 공통/4-데이터모델 §6 |
| 실행에 옵션을 더한다 (반복·중단 같은) | 도메인/실행 → 공통/3-공유계약 §5.1 |
| 증적 문서 모양을 바꾼다 | 도메인/리포팅 §8.4 |
| 화면을 하나 더한다 | 공통/5-화면공통 → 그 화면이 속한 도메인 장 |
| 표에 칸을 더한다 | 공통/4-데이터모델 §6 — **계약이다.** CLAUDE.md §1.2 절차를 먼저 밟는다 |
| 러너가 주고받는 모양을 바꾼다 | 도메인/러너 §5.2 — **계약이다.** 같은 절차 |
| 설정값·포트·컨테이너를 건드린다 | 공통/6-인프라 §9 |

## 표 → 주인과 정의 위치

표마다 주인 도메인이 하나씩 있다. 정의는 전부 **공통/4-데이터모델 §6** 한 곳에 모여 있다.
스키마를 쪼개지 않는 이유는 그 장 머리에 적어 뒀다.

| 표 | 주인 | 그 도메인 장 |
|----|------|------------|
| `test_case` | 카탈로그 | [도메인/카탈로그](spec/도메인/카탈로그.md) |
| `param_set` · `test_run` · `run_item` · `run_item_step` | 실행 | [도메인/실행](spec/도메인/실행.md) |
| `evidence_document` | 리포팅 | [도메인/리포팅](spec/도메인/리포팅.md) |
| `app_user` | 인증 | [도메인/인증](spec/도메인/인증.md) |

## 이 문서를 고칠 때

- **절 번호를 바꾸지 않는다.** 코드 주석·훅·스킬 221군데가 번호로 이 문서를 가리킨다.
  새 내용은 뒤에 번호를 더한다 (§8.7, §9.3 처럼)
- **계약**(§5 타입 · §5.2 러너 · §6 표 · §7 API)을 바꾸려면 CLAUDE.md §1.2 절차를 먼저 밟는다
- 장을 더하거나 절을 옮기면 **위의 세 표(장 목록 · 절 번호 · 표)를 같이 고친다**
- 검사 — `npm run check:spec` 을 돌리면 문서가 가리키는 절 번호가 실제로 있는지 본다
