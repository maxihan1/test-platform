# 테스트 자동화 플랫폼 — 스펙

> 이 문서는 구현의 **단일 진실 원천(Single Source of Truth)** 이다.
> 여기 적힌 타입·계약·스키마와 다르게 구현하면 병렬 작업이 충돌한다.
> 변경이 필요하면 **구현하지 말고 먼저 이 문서를 고칠 것.**

**스펙은 여러 장으로 나뉘어 있다. 이 문서는 색인이다.**
**몇 장인지 여기 적지 않는다** — 장이 늘면 이 줄만 뒤처진다 (`CLAUDE.md §2.7 ⑤`).
세는 일은 아래 장 목록과 `npm run check:spec` 이 한다.
전문을 통째로 읽지 않는다. 아래에서 하려는 일을 찾아 그 줄의 장만 읽는다.

### 이 판이 뒤집은 것

앞 판을 기억하는 세션이 **옛 전제로 일하지 않게** 여기 모아 둔다. 판단 근거는 각 절에 남겨 뒀다.

| 앞 판 | 지금 | 어디 |
|-------|------|------|
| 서비스마다 인스턴스를 따로 띄운다. DB도 따로다 | **한 벌이 서비스 여럿을 감당한다.** 충돌은 케이스 번호 접두사 배정으로 막는다 | §1 · §2 |
| 접두사는 기능 영역을 뜻한다 | **자유 형식이다. 플랫폼은 뜻을 모른다** — 모양과 중복만 본다 | §2 |
| 권한 칸을 만들지 않는다 → 등급 셋 (2026-09-17) | **운영 여부 + 프로젝트마다 기능 셋 × 세 칸 + 대시보드 한 칸** — 프로젝트마다 케이스 · 실행 · 작성을 안 씀 · read · write (2026-09-28 · 주는 단위는 2026-10-19 에 서비스에서 프로젝트로) | §3.5 · §6 |
| 인증 없이 부를 수 있는 API 가 하나 있다 (정기 실행) | **없다.** 정기 실행은 admin 이 안에서 만든다 — 설정 화면에서 켜고 admin 이 1분마다 DB 를 본다(2026-10-12. 그 앞은 서버 cron 이 컨테이너 안 명령을 불렀다) | §7 · §9.2 |
| 반복 실행에 상한을 두지 않는다 | **한 번에 만들어질 실행 항목 5000건까지** (2026-10-13 PRD-F9-22 — 앞은 1000) | §8.2 |
| 실행 항목 수는 케이스 수 × 디바이스 수 × 반복 횟수 | **Σ(케이스마다의 디바이스 수) × 반복 횟수다** (2026-09-21 수정). 케이스마다 선언한 디바이스가 달라 곱셈이 성립하지 않는다 | §8.2 |
| 케이스 목록 검색 조건에 「기능 영역」이 있다 | **없다.** 서비스는 왼쪽 줄의 애플리케이션 칸(앞 이름 헤더 서비스 고르개)에서 고른다 | §8.1 · §8 |
| 증적은 PDF 하나 | **골라서 만든다** — PDF · 엑셀 · HTML | §8.4 |
| 계정·서비스를 서버 명령으로 만든다 | **설정 화면에서 만든다.** 계정은 회원가입 → admin 수락으로도 생긴다. 첫 계정은 빈 서버가 만드는 기본 계정 `admin` 이다 (2026-09-28) | §3.5 · §8.8 · §9.2 |
| 껍데기는 맨 위 가로 띠 + 그 아래 가로 탭 넷이다 | **왼쪽 사이드바 + 상단 헤더 + 푸터다** (2026-09-21). 자리 목록은 그대로고 배치만 세로로 갔다 | §8 |
| 껍데기는 왼쪽 사이드바 + 상단 헤더 + 푸터다 · 휴대폰은 결과 확인만 · 색은 어두운 한 벌 | **왼쪽 줄 + 사이드바 + 푸터다 — 헤더를 걷었다 · 휴대폰에서도 모든 메뉴 · 밝게 · 어둡게 두 벌** (2026-10-30 화면 개편 2 · 시안 11판) | §8 · DESIGN.md |
| 케이스 한 건을 실행해도 실행 기록에 새 RUN 한 줄이 생긴다 | **새 RUN 을 만들지 않는다** — 같은 대상 서버에서 가장 늦게 시작한 끝난 실행에 「다시 실행」으로 붙어 그 결과를 고치고(원래 결과는 남긴다), 붙일 곳이 없으면 케이스 이력에만 남는다 (2026-10-30 WEB-F7-02 · 시안 11판) | 도메인/실행 §3.2 |
| 실행이 끝나도 알리지 않는다 | **완료 모달 · 알림 줄 · Slack** (2026-09-18 신설). **진행 중의 진행도 같은 상자가 그린다** (2026-09-21). 알림 서랍 · 작성 완료 · 남은 시간은 2026-10-11 | §8.9 |
| 케이스 1건 = Playwright 프로세스 1개. 케이스끼리 이어 돌리는 길은 없다 | **E2E 시나리오** — 케이스와 부품을 조립해 한 브라우저에서 이어 돈다. 시나리오 1개 = 프로세스 1개. 결과는 케이스 이력에 안 섞는다 (2026-09-28) | §3.7 · §5.2 |
| 진행 중인 항목은 **근사치**다. 항목 안에서 절차가 어디까지 갔는지는 알 길이 없다 | **러너에게 물어**(`GET /progress`) 도는 것을 전부, **절차와 머문 시간까지** 그린다 (2026-09-21) | §5.2 · §8.9 |
| 미확정은 케이스 파일의 `unconfirmed` 꼬리표가 정하고 집계 · 증적에서 따로 묶는다. 확정은 기획 답을 받아 케이스 고치기로 | **표준 기획서 항목 상태에서 계산하고 그대로 센다** — 꼬리표와 「그중 미확정 N건」만 단다. QA 가 「PRD 관리」 메뉴에서 PR 없이 확정한다 (2026-10-10 · 계산 · 집계는 2026-10-11 PR #206, 꼬리표 빼기는 PR #219 반영) | §3.6 · §3.2 |
| E2E 조립에서 도구가 후보를 내지 않는다 | **중요도는 사람이, 이어지는 후보는 도구가 정한다** — 다음 단계 추천 (2026-10-10 · 2026-10-11 PR #218 반영). **2026-10-23 부터 AI 도 흐름 후보 2~3개를 내고 사람이 고른다** — E2E 마법사(결정 15 · 앞 판은 「AI 가 흐름 초안을 만들지 않는다」) | §3.7 · §8.11 |
| 크롤러는 링크만 따라가고 누르지 않는다. 대조는 기획서 화면만 찍는다 | **사이트 전체를 훑고 버튼도 누른다**(위험 이름 포함) · 로그아웃 뒤 다시 로그인 · 탈퇴와 되돌릴 수 없다고 경고하는 확인 창은 마지막 확인 직전에 멈춘다 · 화면 연결 (2026-10-10 · PR #214 반영 · 경고 창은 2026-10-13 PRD-F9-23) | §3.6 |
| 증적에 요청 · 응답 원문을 넣지 않는다 | **종류 「API」 애플리케이션 케이스만 절차마다 원문을 가려 접어 넣는다** (2026-10-20 API-F1-01). 화면 케이스는 그대로다 | §3.8 · §8.4 |
| 인증 · 결제 같은 뒤쪽 프로그램은 애플리케이션이 아니다(꼬리표) | **꼬리표는 그대로고, 화면 없는 API 를 직접 시험하면 그 API 서버를 종류 「API」 애플리케이션으로 등록한다** (2026-10-20 API-F1-01) | §2 · §3.8 |
| 바깥에서 실행을 거는 문이 없다 (정기 실행도 admin 안에서 만든다) | **CI 의 빌드 올리기가 첫 바깥 문이다.** 로그인 대신 CI 토큰을 거치고 그 애플리케이션의 빌드 올리기 하나만 연다(2026-10-22 GAME-F1-02 · 2026-10-24 GAME-F1-13 반영 — 웹 · 앱 · 게임 · API 공통) | §7 · §9.2 · §3.11 |

| 실패가 버그인지는 QA Hub 「결정 필요」에서 판정한다 | **BTS 를 이은 프로젝트는 BTS 에서만 판정한다** — 실패는 BTS 「QA 검토」 이슈로 가고 결정 필요 ② 실패 판정이 빠진다. 잇지 않은 프로젝트는 그대로다 (2026-10-28 기획 · 2026-10-31 BTS-F1-01 명세 · 반영은 진행판 BTS) | §3.12 |

## 절 번호 → 어느 장에 있는가

## 이 문서를 고칠 때

**절차는 [CLAUDE.md](../CLAUDE.md) §2.7 「SPEC을 고치면 같이 움직이는 것」이 정본이다.**
여기에 옮겨 적지 않는다 — 두 곳에 적히면 한쪽이 반드시 뒤처진다.

- **절 번호를 바꾸지 않는다.** 코드 주석·훅·스킬 수백 군데가 번호로 이 문서를 가리킨다.
  새 내용은 뒤에 번호를 더한다 (8.7 · 9.3 처럼. 여기서는 없는 절을 예로 들어야 하므로 `§`를 붙이지 않는다)
- **계약**(§5 타입 · §5.2 러너 · §6 표 · §7 API)을 바꾸려면 CLAUDE.md §1.2 절차를 먼저 밟는다
