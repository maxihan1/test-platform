### 이 화면에서 걸린 것

- 로그인 「로그인」 버튼은 누른 직후 안쪽이 돌림 표시로 바뀌어 역할 이름 「로그인」으로는 못 찾는다. 막힘 여부는 `#login-form button[type="submit"]` 로 본다
- 점검 화면은 저장하면 폼을 통째로 다시 그린다. 토스트가 뜬 뒤에 칩 · 마지막 변경 글을 읽으면 이미 다시 그려진 뒤다
- 점검 켜기 스위치를 바꾼 저장은 확인 창이 먼저 뜬다. 이미 켜진 상태에서 켜기를 다시 켜면 창 없이 바로 저장되므로 스위치가 바뀌는 케이스는 꺼진 상태에서 시작한다
- `/users` 같은 보호 화면은 쿠키가 없거나 깨져 있으면 화면이 먼저 열리고 API 401 을 받은 뒤 `/login?next=…` 로 간다(쿠키 없을 때는 서버가 바로 302). 로그인 화면 제목이 뜰 때까지 기다리면 두 경우가 같다

### 이 화면에서 걸린 것
- 검색은 0.3초 뒤 거르고 `/api/ops/users?q=` 로 부른다. `waitForResponse` 로 응답을 받은 뒤 표 줄 수가 응답과 같아질 때까지 기다린다(`검색()`).
- 상세 패널의 「닫기」는 `hidden` 속성만 켠다. 패널에 `display:flex` 가 걸려 있어 화면에는 그대로 보인다 — 닫힘을 `hidden` 속성으로 기다리는 `상세닫힘기다리기()` 를 따로 둔다.
- 정지 창 「정지」를 사유 없이 누르면 창이 먼저 닫히고 서버 응답의 오류 문구가 토스트로 뜬다. 토스트는 3초 뒤 사라지므로 같은 문구가 바로 이어지는 단계는 사이에 새로 고친다.
- `/users?id=<없는 번호>` 는 화면 모듈이 실패해 제목까지 사라진다(`.error-text` 한 줄과 토스트만). `열기()` 대신 `없는유저열기()` 를 쓴다.
- 끝 시각이 지난 제재는 서버의 `suspended` / `chatMuted` 가 꺼지지만 이력에는 `releasedAt` 없이 남는다 — 「끝남」 칩.
