#### 이 화면들에서 걸린 것

- 머리글은 세션 응답 뒤에 그려진다 — 화면 Page Object 의 `열기` 는 `머리글.그려질때까지()` 를 부른다
- 목록은 불러오는 동안 같은 머리의 빈 표(로딩 줄)를 먼저 그린다 — 표 머리나 표 유무로 기다리지 말고 글 링크(또는 빈 상태 한 줄)가 붙기를 기다린다
- 상세의 `#post[aria-busy]` 는 글이 그려지면 사라지고, 「댓글 N」 제목은 댓글 응답 뒤에 바뀐다 — 댓글을 읽는 케이스는 `댓글불러올때까지()` 를 쓴다
- 좋아요 · 로그인 · 비밀번호 찾기 버튼은 요청 중 이름이 「처리 중」으로 바뀐다 — 같은 이름의 버튼이 다시 붙을 때까지가 요청이 끝난 뜻이다
- 대상 서버 주소가 http 라 브라우저에 `navigator.clipboard` 가 없다 — 「링크 복사」는 화면이 오류를 삼켜 아무 일도 안 한다. 케이스는 클립보드가 없을 때만 가짜를 세운다(`클립보드권한주기`)
- webkit(모바일)은 `grantPermissions(['clipboard-…'])` 를 알지 못한다 — 권한 주기는 chromium 에서만 한다
- 틀린 비밀번호로 5번 틀리면 계정이 10분 잠기고 로그인으로 지울 수도 없다 — 잠금 케이스는 일회용 회원이어도 그 회원이 남는다
- 같은 머리글이 이동 전 화면에도 있다 — 링크를 누른 뒤 `머리글.그려질때까지()` 만 기다리면 아직 옛 화면이다. 도착한 화면에만 있는 요소(로그인 버튼 · 가입하기 버튼 · 임시 비밀번호 받기 버튼)를 기다린다

- 목록 2쪽의 첫 글은 같이 도는 케이스가 글을 만들고 지울 때마다 바뀐다 — 서버에서 11번째 글을 누르기 전과 읽은 뒤 두 번 구해 둘 중 화면과 맞는 쪽을 쓴다

#### 이 화면에서 걸린 것

- `.or()` 로 두 자리를 기다릴 때 `.first()` 만 쓰면 문서에 먼저 있는 숨은 글(「장바구니가 비어 있습니다」 · 「주문할 상품이 없습니다」)을 집어 끝내 기다린다. `.filter({ visible: true })` 를 붙인다
- 최대 가격 슬라이더는 `fill` 이 범위 밖 값(500,001)을 형식 오류로 거절한다 — 값을 넣고 `input` · `change` 를 직접 일으킨다
- 읽기 전용 우편번호 · 주소 칸은 준비 단계에서 값을 직접 넣고, 주소 검색 새 창을 거치는 흐름은 주소 검색 케이스가 맡는다
- 화면의 칸 id 는 그릴 때마다 무작위(`f-xxxx`)다 — 라벨 · 역할로 집는다
- 실제로 결제하는 케이스는 재고가 영구히 줄어든다(2번 상품이 3회 반복 몇 번에 20개에서 7개가 됐다). 결제 케이스는 재고가 큰 상품(FN-308 은 27번 · FN-309 는 26번 · FN-535 는 24번 · FN-310 은 22 · 30번)을 쓰고, 수량 10 경계를 보는 케이스(UI-182 · FN-236 · FN-241)는 결제하지 않는 8번을 쓴다
- 선택 삭제 「확인」 뒤 화면이 삭제 요청을 보내지 않는다 — 화면 스크립트 `busy(e.currentTarget, …)` 가 확인 창을 기다린 뒤라 `currentTarget` 이 null 이다(콘솔 `Cannot read properties of null (reading 'innerHTML')`). FN-259 가 이 때문에 빨갛다

#### 이 화면에서 걸린 것

- 머리글은 세션 응답 뒤에 그려진다. 화면 `열기` 는 `머리글.그려질때까지()` 를 부른다
- 마이페이지 왼쪽 메뉴는 폭 768 미만에서 본문 위로 쌓인다 (왼쪽이 아니라 위). 위치 판정은 `메뉴가본문앞에있는가()` 로 폭에 따라 가른다
- 주문 내역 기간을 누르면 표가 「불러오는 중」 틀로 바뀌었다가 다시 그려진다. `목록그려질때까지()` 가 그 틀이 사라지기를 기다린다
- 프로필 사진 미리보기는 파일을 읽는 동안 옛 그림이 남는다. `미리보기바뀔때까지()` 로 기다린 뒤 본다
- 머리글의 「<이름>님」은 처음 그릴 때 한 번만 쓰고 회원정보 저장으로는 바뀌지 않는다 (새로 고침 전까지)
- 상담 메시지의 자동 답변은 1초 뒤다. `page.clock.install()` → 화면 열기 → `pauseAt` → `runFor` 로 시각을 움직인다
- 로그인 5번 실패로 잠긴 계정은 10분 동안 로그인이 안 되어 케이스가 만든 회원을 지울 수 없다 (MKT-FN-384)

### CSS 를 쓴 까닭 — 조각에 빠진 것

| 도메인 용어 | 화면에서 무엇 | locator |
|---|---|---|
| 게시판 빈 목록 | 글이 없을 때 표 대신 나오는 안내 | `#board .empty-state` — 까닭: 역할 · 이름이 없는 안내 틀이다 |
| 현재 쪽 | 쪽 번호 가운데 지금 쪽 | `[aria-current="page"]` — 까닭: 쪽 번호 링크가 이름만으로는 지금 쪽을 못 가른다 |
| 글 버튼 묶음 | 게시글 상세의 수정 · 삭제 · 좋아요 · 공유 버튼 묶음 | `.post-actions` — 까닭: 묶음에 영역 역할이 없다 |
| 글 메타 | 분류 · 작성자 · 작성일 · 조회수 줄 | `.post-meta` — 까닭: 이름표 없는 글자 묶음이다 |
| 댓글 내용 | 댓글 한 줄의 본문 글 | `p.text` — 까닭: 작성자 · 날짜와 같은 줄에 있어 역할로 못 가른다 |
| 질문 칸 빈 목록 | 고객센터 FAQ 가 비었을 때 안내 | `.empty-state` — 까닭: 역할도 글자도 없는 빈 목록 틀이다 |

### 관문에서 걸린 것 — 이어받은 실행

- 로그인 화면: 틀린 비밀번호로 부수면 「로그아웃」을 기다리다 시간초과로 죽었다. `login.page.ts` 의 `로그인결과나올때까지`(로그아웃 버튼 또는 로그인 오류 글)를 기다린 뒤 판정한다(MKT-FN-101 · 112)
- 로그아웃 확인 창: 「취소」면 로그아웃 요청이 안 나간다. 요청이 나갔을 때만 「로그인」 링크를 기다린다(MKT-FN-114)
- 장바구니 「선택 삭제」: 확인을 눌러도 삭제 요청이 안 나가는 화면 결함이 있다. 요청이 나갔을 때만 줄이 사라지길 기다린다(MKT-FN-259)
- 상품 상세 「장바구니 담기」: 응답이 늦으면 화면 스크립트 오류(`Cannot read properties of null (reading 'innerHTML')`)로 요청이 안 나갈 때가 있다. 로딩 표시나 화면 오류 가운데 먼저 오는 것을 기다린다(MKT-FN-378)
- 머리글 · 바닥글 링크 이동: 느린 모바일에서 5초 안에 도착 화면이 안 보일 때가 있어 확인 상한을 10초로 둔다(MKT-UI-381)
- 게시판 2쪽 첫 글: 다른 케이스가 같은 때 글을 만들면 11번째 글이 밀린다(MKT-FN-125 — 혼자 3회는 통과)
