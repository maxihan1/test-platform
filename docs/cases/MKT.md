- 서버 `unstable` 설정 — API 응답이 0.1~1.5초 늦고 리뷰 조회가 가끔 500 이다. 읽기 전에 늘 앵커를 둔다
- 홈은 공지 팝업 · 쿠키 띠 · 만족도 설문(5~15초)이 화면을 덮는다 — 그것을 보는 케이스가 아니면 `안내창끄기` 로 먼저 끈다
- 장바구니 「선택 삭제」 → 「확인」 뒤 `Cannot read properties of null (reading 'innerHTML')` 로 삭제 요청이 안 나간다(`cart.js` 가 확인 창 뒤 `e.currentTarget` 을 읽는다) — MKT-FN-301 · 311 은 이 버그를 잡아 실패한다(2026-10-07 보류를 풀고 되살림 — 케이스가 맞다), 차이 D29
- 상품 상세 「장바구니 담기」도 같은 종류의 오류가 있다 — 세션 확인이 끝나기 전에 누르면 `e.currentTarget` 이 비어 요청이 안 나간다. 상세를 연 뒤 머리글 「로그아웃」이 그려질 때까지 기다리고 누른다(MKT-FN-272)
- 대상 서버가 http 라 `navigator.clipboard` 가 없다 — 「링크 복사」 토스트가 안 뜬다(MKT-FN-175 는 이 환경에서 실패한다 — 2026-10-07 보류를 풀고 되살림. https 나 localhost 대상에서는 돈다)
- 상품 상세 응답에 이미지 칸이 없다(이미지는 `/img/p/{id}/{n}` 로 따로 받는다) — MKT-FN-457 은 기획서(REQ-API-031)대로 이미지 칸을 기대해 실패한다, 차이 D28
- 관리자 케이스 15건(MKT-FN-517 · 519 · 520 · 522 · 526 · 527 · 542~546 · 548 · 549 · MKT-UI-181 · 182)은 실행 저장값 `adminPassword` 가 있어야 돈다 — 테스트 계정 칸은 회원 하나라서. 저장값이 없으면 첫 단계에서 「관리자 계정 값이 없다」로 끝난다. 관리자 화면 칸은 소스로만 확인했다(아래 「관리자 화면」) — 저장값을 넣은 뒤 첫 실패는 제품 버그인지 셀렉터인지 먼저 가린다
- 정확히 5개가 맞는 자동완성 검색어가 상품 이름에 없다 — 화면은 모킹(MKT-FN-550), API 는 MKT-FN-554 를 뺐다(2026-10-07 — 상한은 FN-254 · 464 가 지키고, 딱 5개 맞는 상품이 생기면 되살린다)
- 결제 금액 경계(49,999 · 50,000)는 상품 금액 46,999 · 47,000 원 가짜 장바구니로 만든다 — 배송비 3,000원이 붙는다

#### 이 화면들에서 걸린 것

- 화면에 `data-testid` 가 없고 입력칸 id 는 그릴 때마다 무작위다. 이름 · 라벨 · 역할로 잡는다
- 홈 · 쇼핑 · 고객센터는 머리글이 먼저 그려지고 나머지는 응답을 받은 뒤 그려진다. `머리글 로고` → `바닥글` → `상담 버튼` 순으로 기다리면 부팅이 끝난 것이다
- 모달 · 토스트 · 슬라이드는 CSS 전환이 0.3~0.5초라 위치를 읽기 전에 멈출 때까지 기다린다(위치가 두 번 연속 같을 때까지 재 본다)
- 응답 본문을 읽는 케이스(로그인 응답)는 화면이 곧바로 이동해 본문을 잃으므로 `route.fetch()` 로 받아 두고 그대로 `fulfill` 한다
- 홈 설문(5~15초) · 15초 대기 케이스는 `context.clock.install()` 과 `fastForward` 로 당긴다. 대기 상한은 한 케이스 30초(Playwright 기본)라서다

#### 이 화면에서 걸린 것

- 입력칸 id 는 그릴 때마다 무작위다. 이름은 `getByRole` 의 접근 가능한 이름(「제목 *」 꼴)으로 잡는다
- 분류 · 정렬 · 탭을 바꾸면 표가 곧바로 로딩 줄로 바뀐다. 글 줄(링크가 든 줄)이 다시 보이는 것을 앵커로 쓰면 새 목록을 기다린 것이 된다

- 좋아요를 누르는 동안 버튼이 로딩 표시로 바뀌어 이름이 「처리 중」이 된다. 눌림(`pressed`) 상태가 바뀐 「좋아요 N」 버튼을 앵커로 쓴다
- 글쓰기 화면에서 한 글자라도 적으면 다른 주소로 가려 할 때 나가기 확인 창이 뜬다. 같은 화면을 다시 열 때는 그 창을 받아야 한다
- 임시 저장본이 있으면 글쓰기 화면이 `confirm` 으로 묻는다. 창을 붙잡았다가 「확인」을 눌러야 폼 준비가 끝난다
- 서버 주소가 `http` 라 보안 연결이 아니다 — 브라우저에 클립보드(`navigator.clipboard`)가 없다. 「링크 복사」를 눌러도 화면이 복사에 실패하고 토스트를 띄우지 않는다
- 토스트는 3초 뒤 사라진다. 앞 절차의 토스트가 남아 있을 수 있어 「토스트 없음」을 보기 전에 앞 토스트가 사라지기를 기다린다
- 글 · 댓글은 임시 회원 것만 만든다. 목록의 시드 글은 읽기 전용으로만 쓴다

#### 이 화면들에서 걸린 것

- 입력칸 id 가 그릴 때마다 무작위(`f-xxxx`)라 라벨 · 역할로만 잡는다. 필수 칸 라벨 끝에 ` *` 가 붙어 `getByLabel` 은 앞 글자 정규식으로 쓴다
- 가격 슬라이더는 `fill` 이 범위 밖 값(500,001)을 「Malformed value」로 거절한다 — 범위 밖 값은 `evaluate` 로 값을 넣고 `input` · `change` 를 보낸다
- 주문서 우편번호 · 주소 칸은 읽기 전용이라 `fill` 이 안 된다 — 준비 단계는 `evaluate` 로 값을 넣고, 새 창 흐름은 FN-319 가 따로 본다
- 날짜 경계(REQ-ORD-004)는 `page.clock.setFixedTime` 으로 오늘을 2026-10-05(월)에 고정한다. 고정 뒤에 연 화면부터 적용된다
- 목록은 센티널이 보이는 만큼만 이어 붙는다. 끝까지 내리는 일은 카드 수가 늘거나 「마지막 상품입니다」가 보일 때까지 반복한다
- 서버는 자동완성을 최대 5개만 돌려준다. 이름에 정확히 5개가 맞는 검색어는 현재 상품 40개에 없다
