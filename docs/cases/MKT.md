| 로그인 버튼 | 로그인 폼 제출 | `getByRole('button', { name: '로그인' })` — **처리 중에는 이름이 「처리 중」으로 바뀐다** |
| 로그인 오류 문구 | 버튼 위 빨간 글자 | `getByRole('alert')` — 빈 채로 먼저 있으니 `getByLabel('처리 중')` 이 사라진 뒤 읽는다 |
| 분류 탭 | 목록 위 탭 | `getByRole('tab', { name: '질문', exact: true })` |
| 검색 조건·검색어·정렬 | 목록 위 | `getByLabel('검색 조건')`(`title`·`content`·`author`) · `getByLabel('검색어')` · `getByLabel('정렬')`(`latest`·`views`·`likes`) |
| 목록 표 칸 제목 | 표 머리 | `getByRole('columnheader')` |
| 목록 줄 | 표 줄 | `getByRole('row')` — **공지/일반은 첫 칸 글자가 「공지」인지로 가른다.** 칸 값은 `evaluateAll` 로 `r.cells[N]` 을 읽는다 |
| 목록 뼈대 줄 | 불러오는 동안의 회색 줄 | `locator('#board .skel-row')` — **앵커 전용** |
| 목록 빈 안내 | 표 대신 나오는 글 | `getByRole('main').getByText('검색 결과가 없습니다')` |
| 쪽 넘김 이전·다음 | 목록 아래 | `getByRole('button', { name: '이전', exact: true })` |
| 토스트 | 화면 아래 가운데 알림 | `getByRole('status')` |
| 상세 조회수 | 제목 아래 한 줄 안 | `getByText(/^조회수 \d+$/)` · 작성자는 `getByText(/^작성자 /)` |
| 좋아요 버튼 | 상세 본문 아래 | `getByRole('button', { name: /좋아요/ })` · 눌린 상태는 `{ pressed: true }` — **♡/♥ 는 `aria-hidden` 이라 이름에 없다** |
| 상세 수정·삭제 | 본문 아래 단추 줄 | `locator('.post-actions').getByRole('link', { name: '수정' })` · `...getByRole('button', { name: '삭제' })` — **댓글에도 같은 이름의 단추가 있어 단추 줄로 좁힌다.** 기획서는 둘 다 버튼이라 적었다(차이 D2) |
| 목록으로 돌아가기 | 상세 맨 아래 | `getByRole('main').getByRole('link', { name: '목록' })` (기획서는 버튼 — 차이 D3) |

## 이 화면에서 걸린 것

- **★ 기대값을 selector 이름에 넣으면 그 판정은 못 부러진다.** MKT-001 이 로고를
  `getByRole('link', { name: expected.logo })` 로 읽었다 — **찾는 조건이 곧 기대값**이라
  글자가 달라도 「다르다」가 아니라 **30초 시간 초과**로 죽는다. 관문 4 에서 기대값을 「데모장터」로
  주입했더니 `firstFailure` 가 판정 문장이 아니라 `locator.innerText` 시간 초과였다.
  `.first()` 로 **자리로 잡고 글자는 읽어서 비교**하도록 고쳤다 (2026-09-29).
  같은 꼴을 `grep -n "name: expected\." tests/mkt` 로 찾는다
- **`npx playwright cli` 탐침이 이 컨테이너에서 안 뜬다.** `Chromium distribution 'chrome' is not found at
  /opt/google/chrome/chrome` 로 죽는다 — 그 도구는 **상표 붙은 Chrome** 을 찾는데 이 컨테이너에는 없다.
  대신 `node --input-type=module < <스크립트>` 로 `@playwright/test` 의 번들 chromium 을 직접 몰았다.
  **`open` 이 종료 코드 1 을 내도 그다음 `snapshot` 은 조용히 무언가를 뱉는다** — 그걸 해시하면
  빈 화면 해시(`9c1c32919101`)를 참값으로 적게 된다. 탐침을 쓸 때는 `open` 의 종료 코드를 먼저 본다
- **목록은 뼈대 줄(`.skel-row`)이 먼저 그려진다.** `#board table` 이 보이기를 기다리면 뼈대에서 바로 통과한다 —
  첫 훑기에서 「질문 분류에는 공지가 0줄」이라는 **거짓 차이**를 그렇게 얻었다.
  앵커는 `locator('#board .skel-row').first().waitFor({ state: 'detached' })` 다
- **바닥글 `<footer id="site-footer">` 는 빈 채로 먼저 있고 `layout.js` 가 나중에 채운다.**
  `getByRole('contentinfo').waitFor()` 는 **빈 껍데기에서 바로 통과**해서 링크가 0개로 읽힌다.
  앵커는 **맨 끝에 붙는 상담 버튼** `getByRole('button', { name: '상담하기' })` 을 쓴다 (`boot()` 가 바닥글 뒤에 붙인다)
- **머리글도 비동기다.** `header()` 가 `await session()` 뒤에 `innerHTML` 을 넣으므로, 본문(표·상세)이 먼저 그려질 수 있다.
  본문만 기다린 뒤 머리글을 재면 `clientHeight` 가 **0** 으로 읽힌다 (MKT-008 이 6회 중 1회 그렇게 깨졌다).
  머리글을 보는 케이스는 **머리글 안의 것**을 앵커로 쓴다 — 주 메뉴 링크나 `알림` 버튼
- **머리글 높이는 0.2초 전환(`transition: height .2s`)이 있다.** `#site-header.stuck` 만 기다리고 재면 **63px** 같은 중간값이 나온다.
  `transitionend` 를 듣는 것도 못 믿는다(이미 끝났으면 안 온다). `el.getAnimations({ subtree: true })` 의
  `finished` 를 전부 기다리면 6회 연속 48px 로 가라앉았다
- **`맨 위로` 버튼은 앵커로 못 쓴다.** `hidden` 속성이 달려 있어 접근성 트리에 없고
  `getByRole('button', { name: '맨 위로' })` 는 `state: 'attached'` 로도 안 잡힌다 — 30초를 기다리다 죽는다
- **입력칸 `id` 는 그릴 때마다 무작위로 바뀐다** (`common.js` 의 `shuffleIds`). `#id` 로 잡으면 깨진다.
  `label[for]` 은 같이 고쳐 주므로 `getByLabel` 은 안전하다
- **홈은 팝업 둘이 순서 없이 뜬다** — 공지 팝업(바로)과 만족도 설문(5~15초). 홈에서 무언가를 누르기 전에
  `modal-backdrop` 이 클릭을 가로채므로 **먼저 팝업을 닫는다**. 안 닫으면
  `<div class="modal-backdrop open">…</div> intercepts pointer events` 로 시간 초과가 난다
- **로그인이 필요한 케이스는 `params` 로 계정을 받는다.** 케이스 파일에 계정 값을 적지 않으므로
  `PLATFORM_PARAMS` 없이 그냥 돌리면 로그인 단계에서 멈춘다. 관문 3 은 값을 실어 돌렸다
