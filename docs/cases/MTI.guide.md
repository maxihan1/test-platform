# MTI 서비스 가이드 요약

## 서비스
Mastodon v4.7.5 REST API 다. 우리 포크를 띄운 대상 서버 qa(https://mastodon.maxihan.com)를 시험한다.
API 문서 판 1 은 커뮤니티 OpenAPI 에 관리자 API 를 더한 것이다.

## 테스트할 때 지킬 것
- 관리자 API(/api/v1/admin/* · /api/v2/admin/*)는 어드민 키(몸통 `admin`)로 부른다
- 앱 토큰으로 되는 API(인스턴스 정보 · 공개 타임라인 · 앱 확인)는 API 인증 「Mastodon 앱」으로 부른다
- 사용자 API 는 계정 줄의 비밀번호 칸 값이 그 사용자의 액세스 토큰이다 — 비밀번호 칸(이름에 password)으로 받아 `Authorization: Bearer` 머리에 넣는다. /oauth/token 으로 사용자 토큰을 받지 않는다
- 일반 회원은 qa_user1, 두 번째 사용자는 qa_user2 다 — 두 사람이 필요한 케이스(팔로우 · 차단 · 멘션 · 다이렉트)에 쓴다
- 테스트가 만든 글 · 미디어 · 목록 · 필터 · 앱은 케이스 끝에서 지운다. 같은 서버를 웹 · 앱 · 운영툴 · API 테스트가 같이 쓴다
- 관리자 API 로 계정 상태를 바꾸는 일(정지 · 침묵 · 역할 변경 · 삭제)은 qa_user2 에게만 하고 끝에서 되돌린다. qa_admin · qa_mod · qa_user1 은 건드리지 않는다
- 토큰을 무효화하는 API(/oauth/revoke 등)를 계정 줄의 토큰에 부르지 않는다
- 숫자 ID 를 케이스에 넣지 않는다 — 시드는 이름으로 찾는다(계정은 /api/v1/accounts/lookup?acct=<이름>)
- 개수는 「n개 이상」으로 확인한다. 시드는 바꾸지 않는다(신고 해결 · 승인 · 정지 · 삭제) — 바꾸는 요구는 같은 꼴의 데이터를 직접 만들고 끝에서 지운다
- 암호 · 이메일 · 2단계 인증 · 계정 삭제 · 계정 이동은 API 에 없고 웹 설정 화면에서만 된다. 일회용 계정은 등록돼 있지 않다
- 케이스가 만든 앱(POST /api/v1/apps)은 API 로 지울 수 없어 쌓인다 — 앱 등록 요구를 확인할 때만 만든다. 만든 컬렉션은 끝에서 지운다
- 시험 동영상 · 큰 그림은 케이스가 만든다 — 1초짜리 mp4 를 base64 로 도우미에 두고, 해상도 곱이 큰 그림은 zlib 로 단색 PNG 를 만들고, 99MiB 넘는 동영상은 작은 mp4 뒤에 바이트를 채운다
- 이어 작성 때 요구 표에서 tcId 칸이 빈 줄은 모두 케이스로 쓴다(같은 요구의 다른 응답 케이스가 있어도 따로)

## 배운 것
- 요령 · 데이터 — 새로 가입한 계정은 이메일 확인 전이라 쓰기 · 읽기 API 가 403 이다 — 동작하는 계정은 일반 회원 · 두 번째 사용자 · 어드민 키만 쓰고 가입 계정은 가입 자체와 이메일 미확인 확인에만 쓴다
- 요령 · 데이터 — 「Mastodon 앱」 앱 토큰은 read 범위뿐이다 — 가입처럼 write 가 드는 앱 토큰은 시험 앱을 만들어 client_credentials 로 받는다
- 요령 · 데이터 — 관계를 바꾸는 케이스는 시드 관계가 없는 대상을 쓴다(일반 회원 → 팔로우 promo_lee · 차단 spam_shop · 메모 news_bot, 두 번째 사용자 → 뮤트 troll_kim · noisy_cho) — 일반 회원 ↔ 두 번째 사용자의 맞팔로우를 끊지 않는다
- 요령 · 공용 서버 — 이 서버는 글 삭제 · 상태 목록의 인용 · 푸시 구독 · 관리 계정 응답이 API 문서 모양과 다르다 — 준비 · 정리 요청은 test.step 밖에서 불러 시험 대상이 아닌 응답이 케이스를 빨갛게 하지 않게 한다
- 요령 · 되돌리기 — 가입으로 만든 계정은 관리 API 로 정지(suspend)한 뒤 DELETE 로 지운다 — 정지하지 않으면 지워지지 않는다
- 요령 · 데이터 — 컬렉션 만들기는 sensitive 를 꼭 보내야 하고 응답은 {"collection": {...}} 으로 한 번 감싸 온다
- 요령 · 되돌리기 — 두 번째 사용자 프로필을 고치는 케이스는 표시 이름 · 자기소개 · 추가 정보 · 사진 설명을 먼저 읽어 두고 finally 에서 같은 값으로 돌린다 — fields_attributes 를 빈 배열로 보내면 추가 정보가 지워진다
- 요령 · 데이터 — 가입계정지우기는 이름으로 지우므로 시드 이름(qa_user1 · admin)으로 가입을 시도한 케이스에서는 부르지 않는다
- 요령 · 데이터 — 경로 번호가 든 API 를 토큰 없이 부를 때는 있는 번호를 넣는다 — 없는 번호는 인증보다 먼저 404 다
- 요령 · 데이터 — 남의 팔로워 공개 글은 팔로워도 인용할 수 없다 — 비공개 글 인용은 두 번째 사용자가 자기 private 글로 한다
- 요령 · 기다리기 — 알림 · 대화는 새 글을 만든 뒤 0.5초 간격으로 다시 조회해 찾는다(최대 10초)
- 요령 · 되돌리기 — 읽은 위치(마커)는 지울 API 가 없다 — 처음 값이 있을 때만 그 값으로 돌린다
- 요령 · 공용 서버 — 공지 이모지 반응은 시드 반응(👍)을 건드리지 않게 다른 이모지로 달고 뺀다
- 요령 · 데이터 — 승인 대기 계정은 가입 이메일 도메인에 allow_with_approval 차단을 잠깐 걸고 가입한 뒤 바로 지워 만든다 — 시드 newbie_wait 는 건드리지 않는다
- 요령 · 데이터 — 팔로우 요청은 두 번째 사용자를 잠깐 잠그고 일반 회원이 언팔로우 · 다시 팔로우해 만든다 — finally 에서 잠금을 풀고 다시 팔로우한다
- 요령 · 데이터 — 하루 25개 예약 한도 케이스는 다른 케이스가 안 쓰는 70일 뒤 날짜를 쓰고 끝에서 모두 지운다
- 요령 · 공용 서버 — 글쓰기 한도(계정당 3시간 300회)가 켜져 있다 — 세 번 돌려 보기에서 일반 회원이 한도를 다 써 글을 만드는 케이스가 429 로 막혔다 — 글을 여러 개 만드는 케이스는 두 번째 사용자에게 나눈다
- 요령 · 데이터 — 시험 동영상은 소리 트랙을 넣어 만든다 — 소리 없는 짧은 mp4 는 서버가 움짤(gifv)로 받아 동영상으로 치지 않는다
- 요령 · 데이터 — 컬렉션에 넣을 계정 후보에서 qa_user2 · spam_shop 은 뺀다 — 일반 회원 컬렉션에 넣을 수 없다
- 요령 · 데이터 — 컬렉션에서 스스로 빠지기는 일반 회원이 만든 컬렉션에 남의 컬렉션에 든 계정을 넣고 시험한다 — 시드 컬렉션은 한 번 빠지면 다음 준비 때까지 비어 있다
