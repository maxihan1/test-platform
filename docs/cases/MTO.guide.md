# MTO 서비스 가이드 요약

## 서비스
Mastodon v4.7.5 의 운영 화면(/admin, 「환경설정 › 관리」)이다. 신고 처리 · 계정 관리 · 서버 규칙 · 공지 · 차단 도메인 · 대시보드를 웹에서 한다.
웹(MTW) · 앱 · API 테스트와 같은 서버(https://mastodon.maxihan.com)를 쓴다. 시연 · 시험용 서버라 실서비스 데이터가 없다.

## 테스트할 때 지킬 것
- 계정은 qa_admin(Owner) · qa_mod(Moderator) · qa_user1(운영 화면이 막혀야 하는 쪽)이다
- 계정 상태를 바꾸는 조치(정지 · 침묵 · 역할 변경 · 삭제)는 qa_user2 에게만 하고 케이스 끝에서 되돌린다. qa_admin · qa_mod · qa_user1 은 건드리지 않는다
- 서버 설정(사이트 이름 · 가입 방식 · 규칙)을 바꾼 케이스는 끝에서 원래 값으로 되돌린다. 가입은 열어 둔 상태가 기본이다
- 케이스가 만든 글 · 미디어 · 목록 · 필터는 케이스 끝에서 지운다
- 메일은 서버 안 Mailpit 에만 쌓인다 — 메일 속 링크를 눌러야 하는 흐름은 못 돈다
- 시드는 이름으로 찾고 숫자 ID 를 케이스에 넣지 않는다. 개수는 「n개 이상」으로 본다
- 시드는 바꾸지 않는다(신고 해결 · 승인 · 정지 · 삭제). 바꾸는 요구는 같은 꼴의 데이터를 케이스가 만들고 끝에서 지운다
- 이 앱에는 일회용 계정이 없다
- 이메일 도메인 차단을 가입으로 확인할 때는 MX 나 A 레코드가 있는 도메인(mastodon.maxihan.com)을 차단한다 — 지어낸 도메인은 차단 전에 「닿을 수 없는 도메인」으로 막힌다. maxihan.com 은 모든 테스트 계정이 쓰므로 차단하지 않는다. 만든 차단과 가입한 계정은 끝에서 지운다
- 유행 검토 대기 글(jiho_cafe 의 #가을 글)은 실행 시작 때 준비가 다시 만든다 — 「대기 중 유행 게시물이 있다」 전제는 이 시드로 채우고 보류하지 않는다

## 테스트 데이터
- 시드 · 대시보드 — 대기 중인 신고 · 승인 대기 사용자 · 검토 대기 해시태그(#가을) · 이의제기가 하나 이상씩 있다
- 시드 · 계정 — promo_lee 제한(silence) · scam_park 정지(suspend) · newbie_wait 승인 대기(가입 이유 있음) · spam_shop 참고사항 있음 · troll_kim 이전 처벌 기록 있음
- 시드 · 신고 — 미해결 3건은 모두 spam_shop 건이라 한 카드에 묶인다(1건은 qa_mod 배정 · 참고사항) · 해결된 신고 3건(경고 · 제한 · 정지)
- 시드 · 이의제기 — troll_kim 1건 대기
- 시드 · 유행 검토 — 글(승인 2 · 대기 1) · 해시태그(승인 2 · 대기 #가을) · 링크(승인 1)
- 시드 · 공지 2(게시 1 · 초안 1) · 커스텀 에모지 :seed_coffee: · :seed_heart: · :seed_mastodon: · 경고 프리셋 2 · 초대 1 · 감사 로그
- 시드 · 계정 이름 — hana_photo · minjun_dev · seoyeon_books · jiho_cafe · yuna_locked · news_bot · noisy_cho · troll_kim · spam_shop · promo_lee · scam_park · newbie_wait
- 시드 · 비워 둔 것 — 서버 규칙 · 이용 약관 · 도메인 차단 · 이메일 도메인 차단 · IP 규칙 · 사용자명 규칙 · 릴레이 · 웹훅 · 연합 서버
- 시드 · 가입 방식 — 「누구나 가입」. 새로 가입한 계정은 승인 대기가 되지 않는다
- 위 시드(신고 · 이의제기 · newbie_wait · 유행 대기 · 공지)를 처리하는 케이스는 시드 대신 직접 만든 데이터로 쓴다

## 배운 것
- 요령 · 기다리기 — 관리 화면은 브라우저 언어를 따라 영어로 뜬다. 기기 흉내가 언어 머리글을 덮으므로 요청마다 accept-language 를 ko 로 바꿔 끼운다(로그인 도우미 `한국어로`)
- 요령 · 공용 서버 — 로그인은 이메일마다 1시간에 25번(정시 UTC 에 풀림) · IP 마다 5분에 25번을 넘으면 429 로 막힌다. 케이스마다 새로 로그인하지 말고 로그인 도우미가 한 실행 안에서 보관한 쿠키를 다시 쓴다. 케이스가 빨개지면 워커가 다시 떠서 보관한 쿠키를 잃고 또 로그인한다 — 빨강이 많은 묶음은 한도를 금방 먹으니 정시마다 「[로그인] 새로 함」 수를 세어 나눠 돈다
- 요령 · 데이터 — 가입은 양식을 연 뒤 3초가 지나야 받고 이메일 도메인은 MX 가 있는 maxihan.com 이어야 한다. 승인 필요 방식에서는 버튼이 「가입 요청하기」다
- 요령 · 되돌리기 — 케이스가 30초 한도에 걸려 끊기면 finally 가 못 돈다. 가입 방식 같은 서버 설정은 바꾼 직후 할 일만 하고 바로 되돌린다
- 요령 · 데이터 — 일회용 계정은 끝에서 정지 뒤 「데이터 삭제」로 지운다. 「신원 확인」 · 「허가」는 상세가 아니라 계정 목록으로 돌아가니 상세를 다시 연다
- 요령 · 기다리기 — 일괄 동작(계정 목록 「허가」 · 「거부」 · 「정지」 · 커스텀 에모지 일괄 버튼) 뒤에는 목록 문서가 다시 오고 행 글자(「비활성」 · 「목록에 없음」 등)가 바뀔 때까지 기다린 다음 읽는다 — 바로 읽으면 묵은 목록이다
- 요령 · 데이터 — 신고 목록 「해결」은 새것부터 쪽으로 나뉘어 시드 신고가 뒤쪽 쪽에 있다 — 「다음」을 눌러 가며 찾는다
- 요령 · 데이터 — 정지된 qa_user2 는 신고 API 가 못 찾는다 — 신고를 먼저 만들고 정지한다. 「제한」 · 「정지」 확정은 그 계정의 열린 신고를 모두 닫는다
- 요령 · 데이터 — 해시태그 목록은 케이스가 만든 태그가 쌓여 시드 「#가을」이 첫 쪽에서 밀린다 — 목록 첫 쪽에서 고르지 말고 이름으로 찾아서 연다
- 요령 · 기다리기 — 공개 정보 화면(/about)의 서버 규칙은 만든 뒤 몇 분 늦게 바뀐다 — 한 실행에서 규칙을 연달아 만들고 바로 보면 뒤 회차가 빨개진다
- 요령 · 데이터 — 계정 게시물이 20건 넘는 시드 계정이 없다 — qa_user1 로 글을 써서 채우고 끝에 지운다
- 요령 · 되돌리기 — 「정지 해제」 · 「제한 해제」 · 「동결 해제」는 확인 창 없이 바로 돌고 「데이터 삭제」 · 「허가」 · 「거부」 · 「암호 초기화」 · 「고인의 계정으로 전환」은 「확실합니까?」 확인 창이 뜬다
- 요령 · 기다리기 — 대시보드 · 해시태그 상세의 타일 숫자는 API 뒤에 그려진다 — 링크가 없는지 · 타일이 안 보이는지는 숫자가 그려지거나 화면 스크립트를 다 불러온 뒤 본다
- 요령 · 데이터 — 가입이 막힌 뒤 주소는 /auth 라 주소로 가입 성공을 가르지 않는다 — 가입 화면 오류 안내와 계정 목록의 그 아이디 줄로 본다
- 요령 · 기다리기 — 「승인을 통한 가입 허용」 가입은 이메일 확인 안내가 뜬 뒤에 「대기 중」 계정 목록을 연다 — 먼저 열면 아직 없다
- 요령 · 공용 서버 — 이메일 도메인 차단으로 가입을 보는 케이스는 MX 가 있는 도메인으로만 가를 수 있고(`.example` 같은 가짜 도메인은 차단과 상관없이 막힌다) 케이스끼리 차단 도메인을 나눈다(mastodon.maxihan.com · www.maxihan.com 둘 다 A 레코드가 있다) — 같은 도메인이면 나란히 돌 때 서로의 차단을 지운다
- 요령 · 공용 서버 — 「커스텀 에모지 화면만 볼 수 있는 역할」로 에모지를 업로드하면 뒤따르는 목록 응답이 400 이라 성공 알림이 안 뜬다 — 목록을 다시 열어 확인한다
- 요령 · 되돌리기 — 저장이 막혀야 하는 권한 케이스(역할 변경 · 역할 추가)도 저장돼 버렸을 때를 대비해 finally 에서 Owner 새 창으로 되돌린다
- 요령 · 데이터 — qa_user2 로는 로그인할 수 없어 그 계정의 글 · 컬렉션을 케이스가 못 만든다 — 컬렉션이 있어야 하는 화면은 컬렉션이 있는 qa_user1 을 쓰고, 게시물 상세는 계정 게시물 목록 첫 줄(부스트한 남의 글일 수 있다) 말고 API 로 고른 글 번호로 연다
- 요령 · 데이터 — 리모트 계정은 계정 목록 「위치」 「리모트」에 연합으로 들어온 계정이 있다 — 숫자 ID 를 박지 말고 목록에서 고르고, 도메인 차단 여부는 그 도메인 서버 상세의 차단 수정 · 취소 링크로 가른다
