# CDY — 코디세이 요구사항 표 (화면만 · 역방향)

**덮는 범위** — 원장 없음 — 화면만이라 기획서 글자본이 없다(작성 요청 10779). 시작 주소 <https://codyssey.kr/> 에서 링크로 갈 수 있는 같은 사이트 화면을 로그인 전 · 뒤 두 상태로 훑어 만들었다. 뺄 경로 `/daejeon` · `/gyeongnam` 은 열지 않았다

- 대상 화면: <https://codyssey.kr/> (prod)
- 케이스: `tests/codyssey/` — 전부 미확정(`unconfirmed: '화면만 — 기획서 없음 (작성 요청 10779)'`)
- 출처 칸은 화면 주소와 화면 기록 이름(`out-001` · `in-034` 등)이다. 기대값은 전부 화면에서 읽은 값이라 사람이 확인해야 한다
- 역기획서 원고는 산출물 폴더의 `reverse-spec.md` 다

> 표의 **요구 번호는 `1`·`2`** 이고 규칙 번호(「규칙 R3」)와 다른 이름 공간이다.
> 화면 한 장의 UI 줄은 UI 케이스 하나로 묶었다 — 같은 `tcId` 가 여러 줄에 있으면 그 줄들이 한 케이스다.

## 이 화면에서 걸린 것

- 지역 · 약관 · 기본 정보 팝업의 dialog 에는 접근성 이름이 없다 — 제목 heading 으로 `filter({ has })` 해 고른다
- 회원가입 기본 정보 단계의 이름 · 휴대전화 · 생년월일 칸은 본인인증 전에 꺼져 있어 적을 수 없다
- 「닫기」(지역 팝업) · 「취소하기」(비밀번호 변경)를 누르면 주소가 `?modal=` 없는 꼴로 돌아가며 팝업이 사라진다
- 헤드리스 크롬은 PDF 를 화면에 열지 않고 내려받기로 돌려 새 탭의 `url()` 이 빈 글자로 남는다. 새 탭의 첫 이동 요청 주소(`context.waitForEvent('request')`)로 `.pdf` 끝을 본다
- 체험 앱은 iframe 안에 늦게 그려지므로 `제목.waitFor()` 가 앵커다. 「STEP 1 / 6」은 1단계에서만 보이는 요소라 「학습 START」 버튼을 먼저 기다린 뒤 판정한다
- 비회원 홈(`/`)은 공지 팝업 둘(「OST2026」 · 「대전 코디세이 AI 올인원 모집」)이 머리글 · 바닥글 클릭을 가린다 — `home-popup.component.ts` 의 `모두닫는다()` 로 닫고 누른다
- 좁은 화면 「전체메뉴」 서랍은 닫혀 있어도 화면 오른쪽 밖에 붙어 있어 `isVisible()` 이 늘 참이다 — 링크가 화면 폭 안에 들어왔는지 위치로 본다(`viewport.component.ts`)
- 공지 · FAQ 목록에서 검색 뒤 결과 없음 문구를 바로 읽으면 묵은 화면을 읽는다 — 앞 목록 줄이 사라지기(`detached`)를 먼저 기다린다
- FAQ 답변은 문단(`p`)일 때도 맨글자일 때도 있다 — 답변 영역(`.post-content`)으로 잡는다

## 케이스로 만들지 않은 것 (화면만 — 원장 번호가 없어 제외 표 대신 여기 적는다)

- 「회원가입」 마지막 단계 제출 · 「본인인증 하기」 · 「이메일 인증 확인」 — 계정을 만들거나 인증 문자 · 메일이 나간다
