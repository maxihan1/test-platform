# CDY — 코디세이 (https://codyssey.kr) 요구사항

**덮는 범위** — 원장 없음 — 글자본이 있는 자료가 없다(화면만). 시작 주소 `https://codyssey.kr/` 의 홈과 머리 메뉴 1단계가 여는 화면, 로그인 화면과 회원가입 창(본인인증 앞까지), 비밀번호 찾기 화면, 로그인 뒤 메인·내 정보 화면을 덮는다.
덮지 않은 것: 회원가입 완료(본인인증이 외부 서비스) · 회원탈퇴 · 내정보 변경 저장 · 비밀번호 변경 완료 · 인증 메일 발송 · 틀린 비밀번호로 로그인(계정 잠금 위험) · 대전·경남 지역 홈과 로그인 · 교육 콘텐츠 체험 · 첨부파일과 공고문 내려받기 · 모바일 화면.

- 대상 화면: <https://codyssey.kr/>
- 케이스: `tests/codyssey/`
- 요청: 작성 요청 10779 (화면만 · 기획서 없음 — 케이스는 전부 미확정이다. 기대값은 화면에서 읽었다)
- 같은 계정으로 다시 로그인하면 앞 로그인이 풀린다. 로그인이 필요한 케이스는 동시에 돌리면 서로를 쫓아낸다

## 분해 근거

- 기획서가 없어 기대값을 모두 화면에서 읽었다. 그래서 케이스는 전부 미확정이다. 사람이 「케이스 고치기」로 확정하거나 지운다
- 화면 하나는 케이스 하나다. 같은 화면을 같은 조작으로 여는 UI 줄은 합쳤다(규칙 R15). 합친 케이스의 `name` 은 게이트가 따로 보지 않는다
- 경계·예외는 화면에서 확인한 입력 규칙에만 걸었다. 아이디 칸 글자 수 상한 200(`maxlength`), 아이디·비밀번호 필수(`required`), 검색 결과 없음 문구. 기획서가 없으므로 이 셋이 근거의 전부다
- 틀린 비밀번호 로그인, 인증 메일 발송, 가입 완료는 서버 쪽 효과가 있어 훑지 않았고 케이스도 만들지 않았다

- 기본 정보 단계의 이름 칸 접근 이름은 「이름 (필수)」, 비밀번호 칸은 「비밀번호 입력」(재입력 칸은 「비밀번호 재입력 (필수)」)이다
- 비밀번호 칸이 글자를 보이는지는 칸의 `type` 이 `text` 인지로 본다(`inputValue()` 는 가려도 같은 값이다)
- 로그인 화면은 머리(banner)가 없고 바닥만 있다

#### 이 화면에서 걸린 것

- 알림마당 목록은 서버가 그리지 않고 화면이 나중에 채운다(주소만 받으면 목록이 비어 있다). 읽기 전에 첫 항목을 기다린다. 쓰는 곳: `공지사항화면.첫공지제목` · `FAQ화면.첫질문제목` · 코디세이 사람들은 쪽 이동 「다음」.
- 코디세이 사람들 화면은 제목 · 입력칸이 먼저 뜨고 약 50ms 뒤에 목록과 쪽 이동이 뜬다. 처음 보이는 목록 항목 하나는 자리표시라 앵커로 못 쓴다(곧 9건으로 바뀐다). 쪽 이동 「다음」을 앵커로 쓴다. 그 버튼은 처음부터 꺼져 있다.
- 코디세이 사람들 목록은 제목이 h3 가 아니라 `strong` 이다. 이 묶음은 그 목록을 판정하지 않는다.
- 검색을 누르면 목록이 먼저 비었다가 약 20ms 뒤에 결과가 채워진다(검색 결과가 없으면 문구가 그때 뜬다). 비는 순간에 읽으면 0건이다. 그래서 검색 전 목록에 있던 제목이 사라지기를 기다리고, 이어 새 결과의 항목(또는 문구)이 붙기를 기다린 뒤 읽는다. 검색 전 목록에 있던 항목은 이미 결과에 들어 있을 수 있으므로 앞의 기다림 하나만으로는 모자란다.
- 앵커로 쓸 제목은 데이터에서 읽는다(`공지사항화면.검색어가없는첫제목(검색어)` · `FAQ화면.카테고리가다른첫질문제목(카테고리)`). 공지 · 질문이 늘고 줄어도 앵커가 안 낡는다. 검색 전 목록에 검색어가 없는 항목이 하나도 없으면 오류를 던진다.
- 공지사항 상세의 맨 위 「공지사항」은 h2 이고 목록 화면의 h1 과 다르다. 이동을 기다릴 때 `제목.중제목('공지사항')` 이 목록 화면에서는 안 잡혀 앵커로 쓸 수 있다.
- FAQ 질문의 답은 평소 DOM 에 없고 질문을 누르면 그 항목 안에 문단으로 생긴다. 붙기를 `attached` 로 기다리고 보임은 따로 읽는다.
- FAQ 카테고리 선택 상자의 항목(`option`)은 `isVisible()` 이 늘 거짓이다. 골라진 항목은 `getByRole('option', { selected: true })` 의 `count()` 로 본다. 선택 상자 항목 여덟 개는 목록과 같이 뒤늦게 채워진다.
- FAQ 에서 구분 버튼(「AI 네이티브」)을 바꾸면 앞에서 고른 카테고리가 남아 「검색 결과가 없습니다.」(띄어쓰기 있음)가 뜬다 — 공지사항 문구와 띄어쓰기가 다르다. 이 묶음은 구분 버튼을 누르지 않는다.
- 약관 두 화면은 제목(h1)과 「현재 위치」 이동 경로가 한꺼번에 뜬다. 제목 판정의 앵커로 이동 경로를 쓴다.

#### 이 화면에서 걸린 것

- 같은 계정으로 다시 로그인하면 앞 로그인이 풀린다. 케이스는 각자 로그인하고 한 번에 하나만 돌린다. 탐침이 로그인해 둔 채로 케이스를 돌리면 탐침 쪽이 풀린다
- 로그인 직후 어디까지 기다릴지는 머리의 사용자 이름이다(주소 `/main/` 은 앵커로 안 쓴다). 로그인 뒤 `/main/` 과 `/main/myinfo/ams/list` 는 열린 순간에 머리 · 본문 요소가 한꺼번에 붙는다
- 로그인 뒤 머리의 「서울」은 버튼이 아니라 글자다. 로그인 전 머리의 지역 버튼 「서울」과 다르다. 내 정보 화면 머리에는 「서울」이 없다
- 설정 버튼은 접근 이름이 없어 머리(banner) 안의 버튼으로 집는다. 메뉴를 열면 머리 안 버튼이 셋(설정 · 「내 정보」 · 「로그아웃」)이 되므로 메뉴를 열기 전에 한 번만 누른다
- 「로그아웃」을 누르면 `/main/` 머리에서 사용자 이름이 먼저 사라지고 약 0.05초 뒤에 홈 `/` 으로 이동한다. 사용자 이름이 사라진 것만으로는 이동이 끝났다고 못 한다
- 로그아웃 뒤 홈은 서버가 그려 준 화면이 약 0.2초 보이다가 한 번 비워지고(글자 0) 0.25초쯤 뒤 다시 그려진다. 머리의 「로그인」 링크를 그 사이에 읽으면 보이지 않는다고 나온다. 홈의 팝업은 다시 그려진 뒤에야 뜨므로 `홈화면.팝업이뜨면기다린다()` 를 앵커로 쓴다(팝업이 없으면 4초 뒤 그냥 넘어간다)
- 비밀번호 변경 창은 입력칸에 글자를 넣지 않고 「변경하기」도 누르지 않는다. 열고 「취소하기」로 닫기만 한다
- 타일 「회원가입」 · 「로그인」은 링크가 아니라 글자(`strong`)다. 「WARM UP」 글자와 「CLEAR」 버튼이 같이 붙는다. 머리의 「로그인」 링크와 다르다
