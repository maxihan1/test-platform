#### 이 화면에서 걸린 것

- 공지 팝업은 「닫기」를 누른 뒤 0.3초쯤 사라지는 움직임이 있다. 누른 바로 뒤 `isVisible()` 은 아직 true 다 — 사라질 때까지 기다린 결과로 본다
- 이벤트 띠는 홈을 연 뒤 늦게 붙는다. 보이는지 보기 전에 `waitFor()` 한다
- 커뮤니티 목록의 쪽 · 분류 탭 · 정렬 · 검색은 눌러도 주소만 바뀌고 표는 `/api/posts` 응답 뒤에 다시 그려진다. 응답을 기다린 뒤 두 프레임 더 기다려야 묵은 줄을 읽지 않는다
- 글쓰기 「등록」 오류는 서버가 400 으로 거절하고(`{"code":"VALIDATION","message":"..."}`) 화면 아래 알림에 같은 문구가 뜬다. 빈 칸이면 「분류를 선택하세요」, 제목 공백만이면 「제목은 2~50자입니다」

#### 이 화면에서 걸린 것

- 주문서의 입력 안내는 칸을 벗어날 때가 아니라 「다음」을 눌러야 뜬다. 「다음」 뒤에는 안내가 뜨거나 결제 수단 단계(쿠폰 칸)가 열리니 둘 중 먼저 나오는 것을 기다린다
- 「다음」이 통과하면 안내 칸이 숨은 단계로 넘어가 비어 보이므로, 같은 케이스에서 다시 시험하려면 주문서를 다시 연다
- 배송 희망일이 일요일이면 「일요일은 배송하지 않습니다」가 같은 안내 칸에 뜬다. 2일 뒤 · 14일 뒤가 일요일일 수 있어 「안내가 보이지 않는다」는 범위 안내 글만 본다
- 결제 수단 라디오는 처음에 아무것도 켜져 있지 않다. 최종 확인 단계로 가려면 먼저 고른다
- 상품 목록은 정렬 · 필터를 바꾸면 카드가 다시 그려진다. 첫 카드가 바뀌기를 기다린 뒤 읽는다

## 이 화면에서 걸린 것

- 장바구니 수량 칸 — 칸을 벗어나면 `PATCH /api/cart/<번호>` 로 저장하고 그 응답 뒤에 「수량 늘리기」 · 「수량 줄이기」 버튼 상태가 바뀐다. 끝의 전체 3회에서 MKS-FN-366 이 2/3 빨강이었다 → `장바구니화면.수량적고저장기다리기` 로 저장 응답과 두 프레임을 기다린 뒤 읽는다
- 글쓰기 「등록」 — 성공하면 `/board/<번호>` 로 옮기고 「등록되었습니다」 알림이 뜬다. 응답 본문은 옮긴 뒤 못 읽는다 → 만든 글은 `열린글지우기(page)` 로 주소의 번호를 보고 지운다
- 홈 — 「공지사항」 팝업을 닫으면 「만족도 설문」 팝업이 이어 뜰 수 있다. 화면을 가리므로 `방해막기` 로 막는다
- 주문서 배송 희망일 — 범위 안이라도 일요일이면 「일요일은 배송하지 않습니다」가 뜬다. 정상 값은 `일요일아닌배송일()` 로 고른다
