#### CSS · XPath 를 쓴 까닭 (locator 는 Page Object · 공용 부품에 있다)

- `#site-header` · `#site-header.stuck` · `#site-header .header-inner` — 머리글 통째와 줄어드는 안쪽 상자에 역할 · 이름이 없다. 높이는 안쪽 상자를 재야 64 → 48 이 나온다
- `.bell-count` · `.bell-list` · `.cart-count` · `.hello` — 머리글 숫자 배지 · 알림 목록 · 인사말에 역할 · 라벨이 없다
- `.post-meta` · `.post-body` · `.post-actions` · `.new-comment` — 상세의 글 정보 줄 · 본문 · 단추 묶음 · 새 댓글 칸에 이름이 없는 단락이다
- `form[aria-busy="true"]` — 글쓰기 · 수정 화면이 준비되는 동안만 붙는 속성이라 속성 선택자로 기다린다
- `#toast-box .toast` · `.modal-backdrop` · `.modal-body` · `.modal-x` — 토스트 상자와 모달 배경 · 본문 · 오른쪽 위 X 에 역할이 없다
- 케이스 `MKF-FN-015` 의 `'.modal-backdrop'` — 공지 팝업이 나타나는 0.3초 동안 불투명도를 읽으려고 페이지 안에서 요소가 생기기 전부터 재야 해서 선택자 글자를 넘긴다

#### 이 화면에서 걸린 것

- 로그인 응답을 늦추면 「로그인」 버튼은 글자 대신 `aria-label="처리 중"` 맴돌이만 남고 `disabled` + `aria-busy` 가 된다. 이름이 사라지므로 폼 안 `getByRole('button')` 으로 집는다
- 로그인 응답 본문은 화면이 이동하면 `response.text()` 가 끝나지 않는다. `context.route` 로 가로채 `route.fetch()` 본문을 담는다
- 머리글은 80px 가 아니라 81px 부터 줄어든다(80px 에서는 높이 64px · `stuck` 없음) — `MKF-FN-014` 가 빨간 까닭
- 글쓰기 빈 칸 · 짧은 제목 · 짧은 본문은 등록 요청이 서버까지 가고 서버 오류 토스트가 뜬다(「분류를 선택하세요」 · 「제목은 2~50자입니다」 · 「본문은 10~2000자입니다」). 화면에서 먼저 막지 않는다
- 스크롤 뒤에는 두 프레임을 기다려야 `scroll` 이벤트 처리가 끝난다(`내리기`)
- 목록 마지막 쪽은 `/api/posts?size=10` 의 `total` 로 센다 — 다른 묶음이 임시 글을 만들고 지우는 동안에도 마지막 쪽을 맞게 연다
- 탐침 `npx playwright cli` 는 `open --browser=chromium` 으로 열어야 이 기계에서 뜬다(기본 chrome 이 없다)

#### 이 화면에서 걸린 것

- 홈의 이벤트 띠는 창 `load` 뒤에 따로 받아 들어온다. 띠가 오기 전 자리를 재려면 `/api/event-strip` 응답을 붙잡아 둔다(`응답붙잡기`).
- 배너 자동 넘김은 4초 `setInterval` 이고 마우스를 올리면 멈췄다가 뗄 때 새로 시작한다. `page.clock.install()` 뒤 `runFor` 로 당긴다.
- 회원가입 「중복 확인」 결과 글은 응답 뒤에 뜨므로 눌러 놓고 곧바로 읽으면 빈 글이다. 안내 글이 보일 때까지 기다린 뒤 읽는다(`중복확인하고기다리기`).
- 로그인 안내 글은 다음 시도 때도 그대로 남는다. 같은 글이 남은 것을 새 결과로 읽지 않도록 시도마다 로그인 화면을 새로 연다(`새로열어틀리게로그인하기`).
- 「가입하기」가 꺼져 있을 때 누르는 시험은 `click({ force: true })` 로 누르고 0.5초 지켜본다(`꺼진가입하기눌러보기`).
- 추천 상품 순서 섞임은 `/api/settings` 의 `unstable` 이 참일 때만 일어난다. 지금 서버는 거짓이라 「홈을 다섯 번 열면 순서가 바뀐다」는 빨갛다.
- 관심 분야 넷째를 눌렀을 때 토스트는 화면에 뜨지 않는다(문서에만 있음).

#### 이 묶음에서 늘어난 것

- 상품 상세: `보고있는수갱신기록하기` · `보고있는수갱신간격들` (「N명이 보고 있어요」가 바뀐 시각을 MutationObserver 로 모은다)

#### 이 화면에서 걸린 것

- 「품절」 덮개는 `::after` 라서 DOM 글자가 없다 — 계산된 스타일의 `content` 와 배경색으로 본다.
- 상품 목록 응답은 `/api/products?maxPrice=…&sort=…&page=…&size=12` 꼴이고 자동완성은 `/api/products/suggest?q=…` 다. 목록 응답을 붙잡을 때 글롭 `**/api/products?*` 는 자동완성을 잡지 않는다.
- 연락처 칸은 12자를 넣으면 11자에서 잘린다 — 오류 문구는 뜨지 않고 2단계로 넘어간다.
- 「선택 삭제」 확인 창에서 「확인」을 눌러도 삭제 요청이 나가지 않는다 (콘솔 오류 `Cannot read properties of null (reading 'innerHTML')`, 2026-10-12).
- 리뷰 목록 응답은 서버가 가끔 500 으로 실패한다 — 리뷰를 기다리는 부분은 「다시 시도」를 눌러 가며 기다린다.
- 상품 1번(데모 니트 가디건)은 재고가 0 이 됐다 — 케이스는 상품 번호를 박지 않고 API 로 상품을 고른다.

- 공유 테스트 계정은 3개월보다 오래된 주문 · 배송중 주문이 있어야 하는 두 케이스(MKF-FN-199 · MKF-FN-203)에서만 읽는다. 주문 취소 · 탈퇴 · 비밀번호 변경은 하지 않는다.
- 관리자 화면을 다루는 케이스는 관리자 계정이 없어 `held` 다. 소스 모듈에서 읽은 요소 이름으로 절차와 판정을 다 써 두었고 실제 화면에서는 한 번도 돌리지 못했다.

## 이 화면에서 걸린 것

- 홈에 처음 들어오면 공지 팝업 · 설문 팝업 · 쿠키 띠가 같이 떠 머리글 링크를 가린다 — 그 셋을 보는 케이스가 아니면 미리 막는다(로컬 저장소 값)
- 틀린 비밀번호를 테스트 계정으로 넣지 않는다 — 5번 틀리면 10분 잠겨 다른 케이스가 다 깨진다. 새로 가입한 임시 회원으로 한다
- 관문 3 을 돌릴 때 `PLATFORM_BASE_URL` 에 대상 서버 주소를 같이 넘긴다 — playwright.config 가 그 값만 읽는다
- 서버 자료(상품 재고 · 남은 임시 회원)가 흔들리면 초기화 케이스 MKF-FN-248 을 먼저 혼자 돌린 뒤 전체를 돈다
