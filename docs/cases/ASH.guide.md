# ASH 서비스 가이드 요약

## 서비스
Ashveil(애쉬베일)은 안드로이드 폰에서 도는 Unity 게임이고 ASP.NET Core 서버가 재화 · 드랍 · 강화 · 인벤토리 · 성향치를 정한다(서버 권위).
전투 연출 · 데미지 계산 · 몬스터와 봇 이동은 폰(클라이언트)이 하고 처치 · 사망 · 선공 결과만 서버 API 로 보고한다.
화면은 코드가 만들어 오브젝트 이름이 코드와 같다. 장면은 로그인 · 캐릭터 선택(Boot)과 월드(World) 둘이다.

## 테스트할 때 지킬 것
- 케이스 준비(캐릭터 · 골드 · 아이템 · 위치 · 결과 고정 · 확률 설정 · 정리)는 api.md 「어드민」 절의 어드민 API 로 한다
- 작성용 로그인 계정(qh 로 시작)은 지우지 않는다 — `/admin/cleanup` 의 앞머리에 qh 를 쓰지 않는다
- 결과 고정 큐는 서버 전체가 같이 쓴다 — 고정을 쓰는 케이스를 나란히 돌리면 서로 가져갈 수 있다
- 확률 · 결과 고정은 서버 메모리에만 있다(다시 켜면 사라진다). 바꾼 확률표는 케이스 끝에 되돌린다. 스폰 표는 DB 에 남으니 바꾸면 `/admin/spawns/reset` 으로 되돌린다
- 골드는 음수가 될 수 없고 모든 골드 변동은 원장에 남는다 — 어드민 골드 변경도 원장에 `ADMIN_ADJUST` 로 남는다
- GM API 는 QA 환경에서만 열리고 `X-Character-Id` 머리로 대상 캐릭터를 고른다

## 배운 것
- 요령 · 데이터 — 케이스마다 일회용 계정(앞머리 qa…)으로 캐릭터를 만들고 끝에 /admin/cleanup 으로 그 아이디만 지운다 — 작성용 계정은 쓰지 않는다
- 요령 · 기다리기 — 게임은 월드에 들어갈 때 가방 · 골드를 서버에서 받아 온다 — 어드민 준비는 게임 입장 앞에 둔다
- 요령 · 기다리기 — 월드에 들어간 직후 구역 이름 글이 잠깐 비어 있다 — 채워질 때까지 기다린 뒤 읽는다
- 요령 · 데이터 — PK 공격 대상은 봇이다 — 캐릭터끼리 pk-attack 은 서버가 막는다
- 요령 · 데이터 — 봇 처치 보고 좌표는 그 봇이 있는 구역 자리로 준다 — 다른 구역 좌표면 거리 오류가 난다
- 요령 · 데이터 — 가방을 꽉 채우는 케이스는 같은 템플릿 스택(빨간 물약)을 먼저 지운다 — 남으면 전리품 · 바닥 아이템이 그 스택에 합쳐진다
- 요령 · 기다리기 — 봇 · 몬스터 이름표는 화면 가까이 있는 것만 뜬다 — 서버 목록에서 고른 봇 대신 이름표가 보이는 봇을 골라 쓴다
- 요령 · 데이터 — 강화 창 장비 목록 · GM 콘솔 아래쪽 버튼은 화면 밖이면 눌러도 반응이 없다 — 장비는 다섯 개 안쪽으로 준다
- 요령 · 공용 서버 — 결과 고정 큐 · 강화 확률 · 드랍 확률 · 스폰 표는 서버 전체가 같이 쓴다 — 시작할 때 고정을 비우고 finally 에서 되돌린다
- 요령 · 데이터 — 같은 초 안에 다시 받은 액세스 토큰은 앞과 같은 글자일 수 있다 — 리프레시는 refreshToken 이 바뀌는지로 본다
