# DEMO — 완료한 할 일 지우기

자료 둘을 표 하나로 합쳤다.

- `기획서-완료지우기.pdf` — 요구사항 R1·R2

**덮는 범위** — 「Clear completed」 버튼이 **언제 보이는지**와 **누르면 무엇이 남는지**만 덮는다.
완료 표시를 다시 풀었을 때 버튼이 사라지는지, 보기(All·Active·Completed)를 바꾼 상태에서 지우는 것은 자료에 없어서 **안 덮는다.**
`DEMO-001`~`011` 은 이 표보다 먼저 있던 플랫폼 데모 케이스라 이 표에 싣지 않는다.

**대상 주소** — 자료 둘 다 `https://demo.playwright.dev/todomvc` 를 적었다. 작성 요청의 대상 서버 `qa — https://qa.demo.test` 는
2026-09-23 에 주소 해석이 안 됐다(`Could not resolve host`). 그래서 탐침과 케이스는 자료의 주소로 했다.

**예외 축은 없다** — 자료 어디에도 실패·오류 화면이 없다 (규칙 R4).

**덮는 범위** — 원장: 요구 28 → 케이스 28 · 제외 0 · 빠짐 0 · 번호 가족 DEMO-NEW 28

## 이 화면에서 걸린 것

- **「Clear completed」를 누른 뒤 남은 개수 문구는 안 바뀐다.** 안 끝낸 수는 누르기 전에도 뒤에도 「1 item left」다.
  그래서 **누른 뒤의 앵커로 `todo-count` 를 못 쓴다** — 묵은 화면에서 바로 통과한다.
  **버튼이 사라지는 것**을 앵커로 쓴다 — `getByRole('button', { name: 'Clear completed' }).waitFor({ state: 'hidden' })`.
  탐침에서 누른 뒤 버튼이 DOM 에서 빠지는 것(0개)을 확인했다
- **할 일이 둘이면 완료 표시가 둘이다.** 도구는 `getByRole('listitem').filter(...)` 를 뱉는데,
  사전의 `todo-item` 으로 줄을 고르고 그 안의 완료 표시를 잡는다
