**합친 줄 (규칙 R15)** — 요구 2 · 3 · 4경계는 전제와 조작이 같고 조작이 **삭제**라 한 케이스로 합친다.
합친 이름: 「Clear completed」 를 누르면 완료한 할 일만 사라지고 완료하지 않은 할 일은 남으며 버튼도 사라진다.
새로 만드는 케이스라 **저장된 입력값 묶음이 없다** — 기대값 칸이 늘어나 다시 볼 묶음이 없다.

**요구 4 정상의 조작이 「할 일 추가」인 이유** — 빈 목록에서는 목록 아래 영역이 통째로 안 그려져
버튼이 **언제나** 안 보인다. 할 일이 한 건 있어 그 영역이 그려진 상태에서 버튼이 없어야 P1 을 확인한 것이다.

## 용어 사전

- 화면 스냅샷 해시: `4735b99cebbb` (빈 화면 · 2026-09-23) — **`docs/cases/TODO.md` 사전과 같은 값이다.**
  같은 화면이므로 빈 화면 해석을 건너뛰고 그쪽 표의 locator 를 그대로 썼다.
  내는 방법은 `.claude/skills/tpx-cases/SKILL.md` §4 의 명령이 정본이다

| 도메인 용어 | 화면에서 무엇 | locator |
|---|---|---|
| 할 일 입력칸 | 제목 아래 텍스트 상자 | `getByPlaceholder('What needs to be done?')` |
| 할 일 항목 | 목록의 한 줄 | `getByTestId('todo-item')` |
| 할 일 글자 | 그 줄에 보이는 글자 | `getByTestId('todo-title')` |
| 남은 개수 | 목록 아래 문구 | `getByTestId('todo-count')` |
| 「Clear completed」 버튼 | 완료한 것이 있을 때만 나오는 버튼 | `getByRole('button', { name: 'Clear completed' })` |

### 이번에 늘어난 것

**사전에 없던 상태 둘을 따로 탐침했다** — 두 건 중 첫째만 완료한 상태, 그리고 「Clear completed」 를 누른 뒤.

| 도메인 용어 | 화면에서 무엇 | locator |
|---|---|---|
| 특정 할 일의 완료 표시 | 그 글자가 든 줄의 동그란 칸 | `getByTestId('todo-item').filter({ hasText: '<할 일>' }).getByRole('checkbox', { name: 'Toggle Todo' })` |

- **할 일이 한 건 있고 완료한 것이 없으면 목록 아래 영역은 그려지지만 버튼만 없다.** 빈 목록에서는 영역 자체가 없다 —
  그래서 요구 4 정상은 할 일을 한 건 넣은 뒤에 판정한다
- **지운 뒤에는 남은 할 일만 목록에 있고 버튼이 사라지며 「1 item left」 는 그대로다**
- 탐침 CLI 가 `getByRole('listitem').filter(...).getByLabel('Toggle Todo')` 를 뱉었다. 사전의 `todo-item` 으로 맞춰 썼다

## 이 화면에서 걸린 것

- **「Clear completed」 를 누른 뒤의 앵커는 「둘째 줄이 사라짐」이다** — `getByTestId('todo-item').nth(1).waitFor({ state: 'detached' })`.
  남은 개수(`1 item left`)는 누르기 전후가 같아 앵커로 못 쓴다. 판정은 **글자 내용**(무엇이 남았나)을 봐서
  앵커가 보장한 개수와 겹치지 않는다. 지우기 대신 「Completed」 보기를 누르는 부수기에서 앵커는 통과하고
  **「완료한 할 일이 목록에서 사라진다」가 원인 자리에서 빨개졌다**
- **준비 확인 절차는 앵커가 「둘째 줄이 붙음」이라, 할 일이 한 건만 생기는 고장에서는 판정 문장이 아니라
  locator 시간 초과로 죽는다** (DEMO-012 부수기). 멈추는 절차는 맞는 자리다
- **전제 판정 문장이 다른 표의 결과 문장과 겹쳤다** — 「목록에 할 일이 한 건도 보이지 않는다」는 `TODO-012` 의 `name` 이다.
  DEMO-014 쪽을 「처음 연 목록에 할 일이 한 건도 없다」로 바꿨다
