# ARO 서비스 가이드 요약

## 서비스
Boss Room 게임 운영툴 웹이다. 메뉴는 대시보드 · 유저/제재 · 지급/회수 · 공지 · 점검 · 기록 여섯이다.
화면 뒤에서 API 서버(ARI)의 /opsapi 를 부르고, 주소는 https://bossroom-ops.maxihan.com 이다.

## 테스트할 때 지킬 것
- 시연 · 시험용 서버라 실서비스 데이터가 없다. 계정은 모두 테스트 계정이다
- 운영자 계정은 qa_ops 하나다
- 게임 서버 · API 서버 · 운영툴이 한 서버를 같이 쓴다. 한 쪽 테스트가 바꾼 상태가 다른 쪽에 그대로 보인다
- 점검을 켠 케이스는 끝에서 반드시 끈다. 켜 둔 채 끝나면 게임 로그인이 모두 막힌다
- 제재(정지 · 채팅 금지)는 qa_player2 에만 걸고 끝에서 해제한다. qa_player1 은 건드리지 않는다
- 테스트가 쓴 공지는 제목을 [QA] 로 시작하고 끝에서 지운다
- 지급 · 회수 시험은 qa_player2 로 하고 재화는 골드(Gold)다. 아이템 이름은 게임 안 이름(예: 체력 물약 · 사슬 갑옷)을 그대로 쓴다

## 배운 것
- 요령 · 되돌리기 — 점검은 서비스 전체에 하나라 케이스 앞에서 점검 상태를 읽어 두고 finally 에서 되돌린다. 「점검 중」을 봐야 하는 케이스만 바로 켜고 나머지는 시작을 내일로 정한 예약으로 저장한다
- 요령 · 데이터 — 점검 저장 API 의 허용 계정은 쉼표 글이 아니라 숫자 배열로 보낸다(글로 보내면 400)
- 요령 · 되돌리기 — 제재 케이스는 첫 절차에서 qa_player2 의 적용 중 제재를 풀고 finally 에서 다시 푼다. 끝 시각이 지난 제재는 풀 수 없으니 적용 중 판정에 끝 시각을 같이 본다
- 요령 · 데이터 — 지급 · 공지 · 제재 사유는 「[QA] <tcId> <시각>」 꼴 고유 글로 만들어 자기 것을 집는다. 지급 기록은 지워지지 않아 회수만 하고, 지난 실행 것은 첫 절차에서 같은 머리글로 찾아 회수한다
- 요령 · 기다리기 — 토스트는 3초 뒤 사라진다. 같은 문구를 이어 기다릴 때는 토스트 대신 표 줄 · 버튼이 바뀌기를 기다린다
- 요령 · 기다리기 — 유저 검색은 /api/ops/users 응답을 받은 뒤 표 줄 수가 응답 건수와 같아질 때까지 기다린다. 기록 탭을 바꾼 직후 쪽 표시는 앞 탭 것이라 새 탭의 표 머리를 기다린다
- 요령 · 공용 서버 — 대시보드 · 기록의 개수 비교는 다른 케이스가 같은 서버에서 제재 · 지급 · 공지를 바꾸면 어긋날 수 있다. 같은 서버 API 의 값과 그 자리에서 견준다
- 요령 · 데이터 — 지급 기록은 케이스가 돌 때마다 쌓여 조건에 맞는 옛 지급이 첫 100건 밖으로 밀린다. 지급 목록 API 를 쪽마다 끝까지 넘기며 찾는다
- 요령 · 기다리기 — 「몇 초 뒤」 시각은 정해 둔 시간을 쉬지 않고 브라우저 시계가 목표 시각을 지날 때까지 기다린 뒤 API 로 바뀐 상태를 확인한다
