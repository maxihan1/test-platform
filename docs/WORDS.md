# 표준 낱말

같은 뜻을 화면마다 다른 말로 부르지 않게 정한 말이다. 사용자가 고른 말만 적는다 — 여기 없는 말을 새로 정해야 하면 사용자에게 묻고 줄을 더한다.

| 어디 | 무엇을 따르나 | 막는 장치 |
|------|---------------|-----------|
| 화면 문구 (`apps/admin/src/web/messages/*.ts` 의 한글 키) | §1 · §2 | `apps/admin/src/web/words.test.ts` — 늘 도는 검사(`test:always`)라 문서만 고친 push 를 빼고 매번 돈다 |
| Grafana 대시보드 (`infra/grafana/provisioning/dashboards/*.json` 의 패널 제목 · 설명 · 표 칸 이름 · 표에 찍히는 값) | §1 · §2 | 같은 `words.test.ts` |
| 리포트(PDF · 엑셀 · HTML) · 워드 · 엑셀 내보내기 · 알림 글 (서버 코드) | §1 · §2 | 없음 — 서버 글자는 로그와 섞여 기계로 못 가른다 |
| AI 에이전트 글 — 단발 AI(수정 AI · PRD 초안 · 노트 · 성능 AI · E2E 흐름 후보. Page Object 합치기는 코드만 내서 뺀다) | §1 · §2 | 없음 — 지시문을 만들 때마다 이 표에서 무늬가 있는 줄을 읽어 싣는다(`scripts/authoring-prompt-common.ts` 「낱말」). 무늬가 없는 줄(「근거」처럼 뜻에 따라 갈리는 말)은 싣지 않는다 |
| AI 에이전트 글 — 작성 에이전트 자식(케이스 · PRD 문장 · 결과 요약) | §1 · §2 | 없음 — 처음 여는 `korean-ai-tells.md` 가 이 표를 가리킨다 |
| 명세 · 문서 · 시안 | §1 · §2. 결정 기록에 남은 옛 말은 그대로 둔다 | 없음 |
| 대화 · 커밋 · PR | §2 + CLAUDE.md §4 「저장소에서만 쓰는 말은 흔한 말로」 | 없음 |

### 안정화 지표 화면에서만 쓰는 말 (도메인/안정화 §3.15 결정 6 · 2026-11-12 사용자)

오류 종류의 상태와 지표 이름이다. 「기존」 · 「해결」은 위 표의 판정 비교(회귀 실패 · 기존 실패 · 해결)와 글자가 같지만 여기서는 **오류 종류**의 상태다 — 안정화 지표 화면 밖에서 섞어 쓰지 않는다.

| 뜻 | 쓰는 말 | 쓰지 않는 말 |
|----|---------|--------------|
| 처음 보는 오류 종류 | 신규 | 새로 (위 표 「처음 생기는 것」) |
| 이전 실행보다 발생 케이스가 는 종류 | 증가 | 급증 (시안 3판 후보) |
| 해결 처리했는데 다시 나온 종류 | 재발 | — |
| 해결 처리 없이 계속 나오는 종류 | 기존 | — |
| 사람이 해결 처리했고 다음 실행 확인 전 | 해결 | — |
| 해결 처리 뒤 다음 정기 실행에서 안 나온 종류 | 해결 확인 | 검증 대기 · 재테스트 대기 · 검증 완료 |
| 그 실행에 남은 오류 종류 수 | 잔여 오류 | 미해결 오류 |
| 그 종류가 처음 나온 실행 | 최초 발생 | — |

「미해결 오류」 · 「검증 대기」 · 「재테스트 대기」는 사용자가 「이상하다」고 거절한 말이다(2026-11-12). 「검증 완료」 · 「급증」은 기획 초안의 후보였다가 「해결 확인」 · 「증가」로 정했다.

### 정기 실행 화면에서만 쓰는 말 (도메인/정기실행 §3.16 · 2026-11-13 사용자)

「세트」는 호환성 화면에도 있다(「호환성 세트」). 정기 실행 화면에서 그냥 「세트」는 정기 실행 세트이고, 호환성 세트를 담을 때는 늘 「호환성 세트」라고 다 쓴다.

| 뜻 | 쓰는 말 | 쓰지 않는 말 |
|----|---------|--------------|
| 정해진 날 · 시각에 돌릴 테스트 묶음 | 세트 | 스위트 · 테스트 묶음 |
| 아직 돌지 않은 차례 | 예정 | 스케줄됨 · 예약됨 |
| 앞 세트가 끝나길 기다려 늦게 시작한 것 | 대기 | 지연 · 밀림 |
| 담은 케이스가 지워지거나 비활성이 된 것 | 빠진 케이스 | 누락 케이스 · 삭제된 케이스 |
| 세트를 멈춰 둔 상태 | 꺼짐 | 일시정지 · 비활성 |
| 안정화 지표가 세는 세트 | 안정화 기준 | 기준선 · 베이스라인 |
| 세트에 넣는 테스트 (마법사 2단계 · 확인) | 테스트 선택 · 선택한 테스트 | 담을 테스트 · 담은 테스트 |
| 언제 돌지 (마법사 4단계) | 실행 주기 · 매일 · 요일 선택 · 1회 | 언제 · 한 번만 |
| 정한 날 · 시각에 프로젝트 QA 리포트를 만드는 줄 (2026-11-15 사용자 — 시안 A 「+ 리포트 일정」) | 리포트 일정 | 리포트 세트 · 리포트 예약 · 예약 리포트 |

세트가 그날 한 번 도는 것을 명세 · 코드는 「회차」(`sched_occurrence`)라 부르지만 화면에는 쓰지 않는다 — 화면은 날짜 칸과 「예정」 · 「대기」로 말한다.

「함께 실행」 · 「이 실패로 실행하지 못한 케이스」는 시안 1판에 썼다가 사용자가 「영어번역체」라고 짚은 말이다(2026-11-23). 「Blocked」는 「진행 불가」 · 「차단」과 나란히 놓고 봤는데, 판정을 영어로 통일하면서 그대로 정해졌다.
판정값을 영어로 적는 자리와 한글로 두는 자리는 TP-F3-34 가 화면 · 리포트 · 알림을 훑어 사용자에게 보이고 확정했다(2026-11-24 · [목록](https://claude.ai/artifact/Ve2NmkneR1sfsa8s7EF1vj)). 기준은 「배지로 바꿔 놓아도 말이 되는 자리만 영어」다 — 위 표의 「한글 그대로 둔다」 네 줄이 그 밖이다.

성능 화면의 업계 말(가상 사용자 · TPS · 램프업 시간 …)은 도메인/성능 §3.9 「화면 낱말 — 성능 업계 말」 표가 정본이다.

「휴대폰」은 테스트 장비가 아니라 일상 말이라 둔다(「휴대폰 메뉴」 · 「휴대폰에 설치해서 쓰는 앱」). 호환성의 모양 칩도 「디바이스 · 폴더블 · 태블릿」이다(2026-11-08 사용자 — 「스마트폰」 말고 디바이스로 통일). 「쿠폰」 · 「옮기기」 · 「생기기」는 낱말 안에 든 글자라 무늬가 비켜 간다. GitHub 의 「PR 병합」 · gRPC 의 「패키지.서비스/메서드」는 그 도구의 말이라 둔다. 「근거」는 「PRD 관리」의 출처 목록에서만 「출처」로 쓰고 「추천 근거」처럼 이유를 뜻하면 둔다.
API 가 주는 값은 바꾸지 않는다(CLAUDE.md §3) — 그런 키는 검사 파일의 예외 목록에 까닭과 같이 적는다.
